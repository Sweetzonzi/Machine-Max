# Machine-Max 武器 HUD 组件原型 02

入口为本目录 `index.html`，使用随附资源的本地静态页面。页面包含组合效果、组件目录、数据与模板三个视图。场景为用户提供的 Minecraft 截图，背景缩放选取截图中的场景区域；所有武器数据均由浏览器模拟。

## 信息粒度与作者组合

| 粒度 | 内容 | 使用方式 |
| --- | --- | --- |
| L0 弹量 | 名称、库存、简短准备状态 | 机枪等需要紧凑常驻显示的控制器 |
| L1 逐管 | 可选标识和库存、每管的弹药标签、准备进度、剩余时间 | 主炮与多管发射器 |
| L2 弹链 | L1 的逐管能力，加上可选弹链的标签、余量与选中态 | 需要观察或选择供弹的控制器 |

L2 单管模式可以把准备进度合入实际对应的弹链行；启用合并时独立逐管行由弹链行承担显示职责。固定箭头表示选择，行下缘填充表示该管准备进度，行尾为就绪标记或剩余时间。切换供弹后，膛内弹和进行中的装填保留各自的真实来源；来源与选择不一致时附一行情境说明。多管模式使用独立逐管列表，弹链列表作为同级区域，页面没有嵌套重复。

“主炮、同轴机枪、车体机枪、高射机枪”是示例的作者命名。模拟控制器各自持有弹链与发射管，显示粒度及位置由 `app.js` 的 `configs`、`positions` 与 `applyPreset` 定义。页面没有按业务角色自动聚合、排序或避让。勾选“拖动调整布局”后可移动组合中的控制器读数；模块变化或大量增加发射管时可能发生重叠或超出画面，布局由操作者安排。

## 模板与数据绑定

`index.html` 的 `patterns` 容器保存作者定义的组件结构。`app.js#clonePattern` 复制组件；`app.js#Binder` 演示同一 Document 内按身份维护重复项、安装本次求值下标、更新文本/类名/CSS 变量。JavaScript 不拼接武器 HTML 字符串。

目标契约来自 `../../docs/plan/进行中/界面-HUD样式挂载与布局设计.md` §8.5、§8.6 和 `../../docs/plan/计划中/武器系统-武器控制器HUD样式与布局设计.md` §二、§三、§4.1：

- `data-mm-repeat="weapon.tubes"` / `"weapon.belts"` 提供集合。
- `data-mm-index="tube"` / `"belt"` 提供条目作用域中的当前快照下标。
- `weapon.tube_fill(variable.tube)` 使用 0～100 百分比。
- `weapon.tube_round_label(variable.tube)` 和 `weapon.tube_reload_text(variable.tube)` 提供逐管标签及时间。
- `weapon.belt_label`、`weapon.belt_remaining`、`weapon.belt_selected` 提供弹链行数据。

浏览器绑定器只识别本页使用的查询，不是完整的 MoLang 或游戏绑定器。循环项保留 DOM 节点，按 `mock-data.js#create` 中管的 key 和弹链 key 对齐；游戏的实际身份契约是上述武器文档中的 `TubeKey` 和完整有序弹链序列。

`demo.*` 表示原型适配器派生值，不是已经确定的游戏查询名。特别是 `demo.belt_fill`、`demo.belt_status` 按单管的真实膛弹／装填来源与弹链匹配，用于演示行内合并；游戏接入需要暴露可匹配的逐管来源身份或提供等价查询。该能力按用户提出的逐管目标信息设计，没有假设选择状态等于实际装填来源。

## 模拟口径

`mock-data.js#snapshot` 的库存读数不含膛内弹药，界面以 `STORE` 标记。有可选弹链时，紧凑及逐管组件同时注明这份库存所属的选中弹链，避免把选中库存误认为膛内弹种的库存。多管导弹可以库存为 0，同时有已上膛的管；逐管满格继续表达就绪。容量数字是供给库存的容量，不表示发射管数。L0 使用作者定义的简短名称，如 `DT / COAX` 与 `DT / HULL`，有限宽度下也能区分同型号的不同安装位。

主炮射击消耗膛内弹并自动开始准备下一发，装填完成时从实际来源弹链扣一发。机枪点射按一次 18 发演示，附带一个用于观察界面的准备周期。导弹自动准备属于再生示例。具体耗时、射速与供给行为只服务于视觉验证，不代表游戏武器标定。

每次“复位本控制器”恢复该控制器的数据；暂停模拟时间可以固定准备进度。多管控制器允许 1、2、4、6、8 根有效管，通过同一条目模板显示。组件目录同步读取组合预览中的控制器数据。

## 资源与适配边界

`assets/mm-field.ttf` 是本次风格探索自绘的 5×7 拉丁字模字体，生成源为 `../weapon-hud-retro/build_font.py#PATTERNS`。网页中文使用系统字体。浏览器分数缩放会影响像素边缘，游戏中的 GUI scale 和中文像素字体需要专项检查。

`assets/minecraft-reference.png` 来自用户的第二张参考截图。页面没有武器图标依赖、虚构故障枚举或车体装甲模块。浏览器中的 CSS 和节点操作未作为 AUI 运行期验证结果；完整绑定器、特殊标签初始化和游戏内透明合成按框架设计验收。

## 校验记录

- `node --check app.js` 与 `node --check mock-data.js` 通过；HTML 中本地资源引用均解析到实际文件。
- Node 断言验证：选择 HE 时膛内 APHE 保持；HE 装填过程中选择烟幕，完成后膛内为 HE，库存只从 HE 扣除；导弹库存为 0 时可以有两根就绪管。
- 浏览器检查覆盖三种组合、组件目录的 L0/L1/L2、切弹差异提示、4 根扩为 8 根、独立组件拖动和退出纯 HUD 预览。
- 文档自包含检查：触发词机械扫描零命中；模板、查询和库存语义均有本文内说明或可定位的交叉引用。
