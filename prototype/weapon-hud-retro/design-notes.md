# Machine-Max：像素化军用火控终端 HUD 风格探索

## 风格名称与参考图

本探索把目标方向称为「像素化军用火控终端」（Pixel Military FCS），也可以用「单色 CRT 战术 HUD」「复古军用仪表界面」描述。这些是用于沟通设计方向的组合名称，并非某一种有严格边界的历史流派。

参考图一的主要特征是象牙色单色、位图字、细线边框、反白信息条、武器轮廓图、分段弹药指示与编号。它同时借用了字符终端与仪器绘图的语言：武器线稿和任意位置的图形意味着它不属于纯命令行界面。参考图二体现 Minecraft 的方块场景和像素字环境；其中长名称截断、列表选择条与大弹量数字也是本原型需要检视的内容。

「电子管／晶体管时代」可以描述联想，但不能单凭绿色屏幕判定硬件年代。1958 年的 SAGE 武器指挥控制台可作为军用 CRT 显示的历史参照，1978 年的 VT100 可作为字符终端的参照。本探索将这两类视觉语言混合用于游戏 HUD，不复刻具体设备。历史参照：[Computer History Museum：SAGE 控制台](https://www.computerhistory.org/revolution/real-time-computing/6/120/505)、[Computer History Museum：VT100](https://www.computerhistory.org/revolution/input-output/14/349/1697)。

「Cassette futurism／盒带未来主义」可作寻找复古科幻视觉的宽泛关键词，但通常还会涉及物理按键、机壳、磁带等设备形态；本探索针对的是屏幕内的火控显示。「军用」的感觉主要来自任务导向的信息秩序、操作反馈、功能缩写与仪表图形。

## 现有 builtin 原型的视觉判断

观察源是 `src/main/resources/spark_modules/machine_max.builtin/machine_max/documents/weapon_hud_element/hud.css` 的 `:root`、`.el-ammo`、`.ammo-num` 与 `.belt` 规则，以及同目录的 `index.html` 与 `preview_third.html`。现有原型采用平滑系统等宽字、青白文字层级、渐变底板、大字号数字和规则列表块。这些选择清楚易读，但组合起来偏向现代软件面板。

本探索用自绘 5×7 拉丁字模、硬边单色块、局部 1px 边框、反白选中条与可数的供弹格建立视觉语法。HUD 使用拉丁缩写，网页说明使用系统中文字体；中文像素字体与本地化宽度需要在游戏接入阶段单独验证。

## 三种原型

| 方向 | 结构与用途 | 重点 |
| --- | --- | --- |
| 01 野战仪表 | 左上装甲、右下武器与烟幕；第三人称组合 | 武器线稿、弹量大字、分段供弹，最接近参考图一 |
| 02 火控终端 | 右下字符表，弹链按列对齐 | 选中行、固定字段位置、短状态回执，突出专用计算机感 |
| 03 观瞄分划 | 中心细分划，下缘武器条，侧面测距与俯仰 | 战斗视野、紧凑读数与外围信息 |

默认配色为荧光绿 `#a4ff80`，另提供象牙白、琥珀、冰蓝与自定义色。颜色由 `style.css` 的 `--accent` 控制，底板由 `--panel-opacity` 控制。状态依靠文字和图形区分：就绪为反白条，装填为斜纹与倒计时，耗尽为 `! FEED EMPTY`，故障为 `X BREECH FAULT`。玩家换色后仍能通过这些标记识别状态。

扫描线和辉光作为可选效果，初始关闭。单色显示、扫描线、位图字是三个独立选择；强扫描线与持续闪烁会影响小字号识读。本原型没有持续闪烁。

## 使用与模拟契约

入口为本目录 `index.html`。所有资源均使用相对路径，可直接在浏览器中打开；本目录也可使用静态 HTTP 服务。`app.js` 的 `directions` 保存方向说明；`render` 把同一份模拟状态投影到三种结构；`startReload` 以 3.2 秒完成一次模拟装填。

可交互功能包括三种方向、五种配色入口、场景亮度、底板浓度、暗色背景、扫描线、辉光、长名称压力测试、四种武器状态、射击、装填、弹链选择与纯 HUD 预览。快捷键为 Space 射击、R 装填、B 切换弹链、Escape 退出纯 HUD 预览。输入框与下拉框持有焦点时由浏览器原生处理键盘输入；按钮与链接持有焦点时 Space 执行其原生激活动作。

三条弹链初始库存分别为 24、12、6 发；模拟装填把当前弹链补到 30 发，不消耗备弹。这一规则只用于观察状态与版面。烟幕、装甲、车速、方位、测距和俯仰均为静态示例，页面未连接游戏。

HUD 设计画布为 1440×810，页面按可用宽度等比缩放。字模轮廓由整格方块构成，画布整数比例下最清晰；浏览器分数缩放可能产生抗锯齿。游戏接入时需要单独校验 GUI scale、实际像素落点、中文字体、透明叠加和 AUI 对 CSS 的支持。

## 资源与边界

- `assets/mm-field.ttf` 是本原型的自绘 5×7 字模字体，生成源为 `build_font.py` 的 `PATTERNS`，离线浏览无需 Python 或字体库。重新生成字体需要本地 Python 与 fontTools。
- `assets/minecraft-reference.png` 是用户提供的第二张参考截图的原样副本。页面通过背景缩放与定位选取左上场景区域，避开截图中原有 HUD；原图像素未被重绘。
- 线框炮图与分划为本地 SVG 几何，位于 `index.html` 的 `.weapon-diagram` 与 `.reticle`。
- 页面未修改 builtin 资源，也未验证为 AUI 文档。原生浏览器中的 SVG、CSS 变量与布局需要在选定视觉方向后按 AUI 能力适配。
- 车体完整性、烟幕模块、方位与分划属于组合展示。将来挂载到游戏时，应遵循现有独立元素边界：分划归观瞄系统，武器控制器元素负责武器身份、弹链、弹量、装填与逐管状态；可参照 builtin 的 `weapon_identity.html`、`weapon_ammo.html`、`weapon_belts.html`、`weapon_tubes.html` 与 `scope_reticle.html`。
