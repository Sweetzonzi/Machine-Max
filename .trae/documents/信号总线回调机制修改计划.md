# 信号总线回调机制修改计划

## 一、问题分析

### 核心缺陷

`sendSignalToTarget()` 中调用 `collectTerminalTargets(signalReceiver, ...)` 时，`signalReceiver` 是 `SubsystemController`（总线）。由于 `collectTerminalTargets` 只识别 `SignalPort` 类型的转发节点，不识别 `ISignalBus`，因此：

- 终端目标收集结果 = `[SubsystemController]`（只有一个总线自身）
- 回调路径：`SubsystemController.sendCallbackToListener("callback", originalSender, value)`
- **期望结果**：终端目标收集结果 = `[EngineSubsystem, WheelDriverSubsystem, ...]`（所有实际收到广播的订阅者）
- **期望回调**：每个订阅者各自发送 `sendCallbackToListener("callback", originalSender, value)` 给发送者

### 典型受影响流程

```
CarControllerSubsystem
  └─ sendSignalToTarget("callback", "vehicle", "engine", requiresImmediateCallback=true)
       └─ SubsystemController.onSignalUpdated("callback", carController)
            └─ broadcast(channel, value, sender, false, false)   ← 无法传递回调需求
                 ├─ EngineSubsystem.onSignalUpdated("callback", carController)    ← 收到了但无法回复
                 ├─ WheelDriverSubsystem.onSignalUpdated("callback", carController)
                 └─ ...
       └─ collectTerminalTargets(SubsystemController, "callback")
            └─ 结果: [SubsystemController]  ← 错误！应该是 [EngineSubsystem, WheelDriverSubsystem, ...]
       └─ SubsystemController.sendCallbackToListener("callback", carController, "callback")
            └─ 仅总线回复，各订阅者未回复  ← 缺陷
```

## 二、修改方案 — 两处改动

### 修改 1：`ISignalSender.java` — `collectTerminalTargets()` 识别 ISignalBus

**文件**: `d:\Files\Project_MinecraftMods\Machine-Max\src\main\java\io\github\sweetzonzi\machine_max\common\mech\signal\ISignalSender.java`

**修改内容**：在 `collectTerminalTargets()` 增加 `ISignalBus` 分支。遇到 ISignalBus 时不将其自身作为终端，而是递归收集其所有订阅者作为终端目标。

```java
// 在 SignalPort 判断分支之后增加：
if (receiver instanceof ISignalBus bus) {
    for (ISignalReceiver subscriber : bus.getAllSubscribers()) {
        collectTerminalTargets(subscriber, channel, terminals, visited);
    }
    return; // 不将总线自身加入终端集合
}
```

**效果**：`sendSignalToTarget()` 的回调逻辑自动收集总线订阅者，每个订阅者向原始发送者发起 `sendCallbackToListener("callback", ...)`。

### 修改 2：`ISignalBus.java` — `broadcast()` 改为 5 参数统一签名

**文件**: `d:\Files\Project_MinecraftMods\Machine-Max\src\main\java\io\github\sweetzonzi\machine_max\common\mech\signal\ISignalBus.java`

**修改内容**：去掉 3 参数重载，只保留 5 参数版本（含 `requiresImmediateCallback` 和 `callbackReturnsSignalValue`）。广播后若回调启用，每个订阅者立即回传 callback 给 `originalSender`。

```java
/**
 * 将信号广播给所有接受此频道的订阅者。
 * 若 requiresImmediateCallback=true，每个订阅者在 onSignalUpdated 后立即
 * 通过 sendCallbackToListener("callback", originalSender, value/channel) 回传。
 */
default void broadcast(String channel, Object value, ISignalSender originalSender,
                       boolean requiresImmediateCallback, boolean callbackReturnsSignalValue) {
    for (ISignalReceiver sub : getAllSubscribers()) {
        if (sub.acceptAllBroadcastInput() || sub.getAcceptedChannels().contains(channel)) {
            sub.getSignalInputChannels()
                    .computeIfAbsent(channel, k -> new SignalChannel())
                    .put(originalSender, value);
            sub.onSignalUpdated(channel, originalSender);
            
            if (requiresImmediateCallback
                    && originalSender instanceof ISignalReceiver
                    && sub instanceof ISignalSender callbackSender) {
                if (callbackReturnsSignalValue)
                    callbackSender.sendCallbackToListener("callback", (ISignalReceiver) originalSender, value);
                else
                    callbackSender.sendCallbackToListener("callback", (ISignalReceiver) originalSender, channel);
            }
        }
    }
}
```

### 修改 3：`SubsystemController.java` — 更新 `broadcast()` 调用

**文件**: `d:\Files\Project_MinecraftMods\Machine-Max\src\main\java\io\github\sweetzonzi\machine_max\common\mech\subsystem\SubsystemController.java`

**修改内容**：`onSignalUpdated()` 中的 `broadcast()` 调用补充 `false, false` 参数。回调由修改 1 的 `collectTerminalTargets` 在 `sendSignalToTarget()` 层处理，不需要在 `SubsystemController` 层触发。

```java
broadcast(channelName, entry.getValue(), entry.getKey(), false, false);
```

## 三、验证标准

1. **编译通过**：`./gradlew build` 无错误
2. **回调正确性**：
   - `CarControllerSubsystem.sendSignalToAllTargetsWithCallback(...)` 后，各引擎/车轮等订阅者都通过 `sendCallbackToListener` 回复，发送者能正确收到以订阅者为 sender 的 "callback" 信号
   - `WeaponControllerSubsystem` 发送发现信号后，能收到各炮塔/发射器的回调
   - 弹药链子系统发送发现信号后，能收到各弹药消费者的回调
3. **无回归**：
   - 点对点路由（非总线路径）的回调行为不变
   - `SubsystemController.broadcast(..., false, false)` 的无声无回调广播行为不变
   - 无死循环或栈溢出
