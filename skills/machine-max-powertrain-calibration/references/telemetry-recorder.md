# 行车记录仪

地面控制器自带一个服务端 CSV 记录仪，每个物理步写一行（名义 100 Hz），不需要额外 mod。
它记录的是控制律与物理体在同一时刻的读数，用来解释静态脚本覆盖不到的过程：起步打滑、
换挡断流、档位振荡，以及周期在一秒量级的车体抖动。

采样点在子系统步的入口，所以 `throttle` / `gear` / `t*_cmd` 这些指令列与 `rpm` /
`t*_spd` 这些反馈列属于同一个物理步，可以直接相减。

## 开录与落盘

```text
/mm debug telemetry start      # 坐在车上执行
/mm debug telemetry stop       # 结束，聊天栏回显文件与行数
```

文件落在 `<gamedir>/logs/machine_max/<载具名>-<控制器名>-<时间戳>.csv`，首行列名，一次
录制一个文件。写盘只在服务端发生：客户端不采样、不建文件。采样在物理线程入口处完成，
只把格式化好的行塞进无锁队列，主线程排空写盘，磁盘慢不会拖住物理步进。

## 列

| 列 | 含义 |
|---|---|
| `t_s` / `wall_ms` | 仿真时间（物理步数 × 0.01 s）与真实毫秒 |
| `speed_mps` / `speed_kmh` | 车体局部前向速度 |
| `accel_mps2` | 相邻两步的车速差 ÷ 0.01 s |
| `throttle` / `brake` / `handbrake` / `steering` | 平滑后的执行器指令（0~1，转向 −1~1） |
| `rpm` | 引擎与电机的平均转速 |
| `gear` / `clutched` | 首个变速箱的挡位索引与离合；`clutched = 0` 即换挡断流中 |
| `active` | 控制器是否在接管（`0` 时 `throttle` 停在最后一次的值，读的时候先看这一列） |
| `mass_kg` | 装配体总质量 |
| `b_vx` / `b_vy` / `b_vz` | 同一物理步从刚体读到的实时机身速度（横向 / 垂向 / 前向）。`speed_mps` 取的是 20 Hz 同步快照，每 5 个物理步才变一次；分辨一步一秒以下的抖动要用这三列 |
| `pitch` / `roll` | 车体姿态（°，抬头为正、右侧下沉为正） |
| `pitch_rate` / `roll_rate` | 机身角速度绕车身横轴 / 纵轴（°/s） |
| `aero_fwd` / `aero_up` | 整车气动合力投影到机身前向 / 上向（N，正值表示推着车往前、往上） |
| `tension_n` | 各条履带张力大小的合计（N） |
| `base_mps` / `yaw_cmd` / `yaw_act` | 履带：单流基准带速、横摆率指令、车体实际横摆率（rad/s） |
| `t{i}_cmd` | 本步下发给该侧履带的带速指令（m/s）；`NaN` = 该侧锚定到 `_in`、不做比例限速 |
| `t{i}_in` | 传动箱给出的伺服目标带速 = 动力链折算到主动轮的转速 + 驱动偏置 `LOCK_DRIVE_BIAS`（30 rad/s，见 `TransmissionSubsystem`） |
| `t{i}_spd` | 履带实际带速 |
| `t{i}_trq` / `t{i}_r` | 下发给滚动轴电机的驱动扭矩（N·m）与主动轮半径 |

`t0` / `t1` 按车体局部 x 从小到大排序，不是按左右命名。

三组力学列（`aero_fwd` / `aero_up` / `tension_n`）取的是上一物理步的合计，比同一行的
其它列晚一步：气动与张力在物理步中由各子零件与各对履带成员分别施加，装配体的累加器
要到下一步开头才是完整合计。

## 先看这四个量

1. **`wall_ms` 与 `t_s` 是否同步。** 物理欠载时 `PhysicsLevel.dynamicRepeat` 从 5 步降到 1~4 步，仿真时间慢于真实时间；两者对不上时，手感上的加速与 `accel_mps2` 不是同一个量，先按 `t_s` 读。
2. **两条履带是不是同时在驱动。** 伺服目标是 `min(_cmd, _in)`（同向时），`_trq` 为 0 表示这一步该侧走的是制动分支、没有推力。单流控制器只要算出非零的转向比，就把一侧判成「内侧」并按住它的转速；两侧 `_trq` 交替为 0 时，整车推力只有一侧的份额。统计 `(t0_trq>0) + (t1_trq>0)` 的分布，全油门直线应当是 2。
3. **接触面的力是否等于模型算的。** `F = Σ t{i}_trq / t{i}_r`，再用 `mass_kg` 与 `accel_mps2` 反算 `F − m·a` 即当步阻力。与档位表的牵引力对照，差得多说明差在阻力项或质量；制动段可以反过来标定这条换算（实测减速度与 `2·max_brake_torque/r` 对得上，说明力→加速度本身没问题）。
4. **引擎转速是否与车速同相。** 理论上 `rpm = speed_mps·i_gear·60/(2π·r)`。实测 `rpm` 明显低于这个值，说明引擎被拖住（转子惯量、`couple_torque` 或换挡断流）。`inertia` 与这条的关系见[工程模型 §十二](engineering-model.md)。

## 换挡

直接读 `gear` 的跳变与 `clutched` 的行数：`clutched = 0` 的行数 × 0.01 s 就是该次断流时长，明显超过 `switch_time` 说明自动换挡在振荡。

## 一步一秒量级的抖动要换列读

`speed_mps` 与由它折算的 `accel_mps2` 都来自 20 Hz 的同步快照，每 5 个物理步里有 4 个读到同一个值（`accel_mps2` 因此是 4 个 0 夹 1 个尖峰），按一秒分箱只剩包络。要判断这类抖动的来源，用 `b_vz` 逐物理步求加速度，再拿另外三组量对照：

- **`aero_fwd` 自己就在台阶式跳。** 子零件的遮挡按 `hydrodynamics.effective_range` 做一次射线检测，车身姿态变化会让射线命中与否翻转，整个子零件的气动力随之开或关。判据是 `aero_fwd` 的变化幅度足以解释 `b_vz` 斜率的变化，且与 `pitch` 同相。
- **`tension_n` 周期性涨落。** 履带张力是相邻成员之间的单边弹簧-阻尼力，`rest` 在装配时按当时轮距固定；悬挂行程改变轮距，张力随之起伏，带一松一紧就把推力调制成脉冲。判据是 `tension_n` 的峰谷与 `b_vz` 斜率的峰谷同相。
- **两者都平、只剩姿态在动。** 说明推力本身平稳，抖动来自俯仰/侧倾模态在给纵向加速度做功，看 `pitch_rate` / `roll_rate` 与控制指令的相位差。进一步的做法是对 `b_vz` 与 `pitch` 做频谱：三者落在同一个频率上时，那个频率就是悬挂的垂向/俯仰固有频率 `ω_n/(2π)`，用 `suspension.py` 的 `ω_n` 对照即可确认。悬挂参数与 `ω_n` 的关系见[工程模型 §十一](engineering-model.md)。

这三组量都是诊断列：不参与物理计算，读取也不改变任何状态。

## 不在这份数据里的

- **客户端侧的量**：渲染帧时间、音效触发时机、HUD 显示值都不可见，这里只有服务端物理读数。
- **多于一个变速箱 / 一个传动箱的细节**：`gear` 与 `rpm` 只取首个变速箱与动力源平均值，各输出端的分化要另看 `t*_in`。
- **静态包线本身**：极速、牵引力与钳位余量由 `calibrate.py` / `suspension.py` 给出，见[工程模型](engineering-model.md)。
