# Machine-Max 动力系统标定

标定做两件事：把需求换成参数，确认这组参数没有互相打架。

判断标准只有一条：**发动机（或电机）曲线上写着的功率，能在轮胎接地点上真的用出来**。额定值写得再高，只要链条上某一环先到上限，多出来的部分就是纸面数字。

本技能只处理**静态包线**——给定参数下最多能输出多少力、能跑多快、能爬多陡。动态手感（换挡冲击、断流顿挫、档位振荡、油门跟随）由控制逻辑决定，标定阶段用观测量记录，不建模。

## 何时使用

- 新载具首次配动力链，或从别的载具复制参数后调整。
- 症状：极速明显低于预期、起步或加速发肉、爬坡无力、驱动轮空转、刹车感远强于加速感、HUD 标称马力与实际观感不符。
- 内容包改动了 `*_engine.json`、`*_motor.json`、`*_gearbox.json`、`*_transmission.json`、`*_wheel_driver.json`、部件质量或轮胎材质之后。

不适用：换挡顿挫、高低档来回跳、松油门拖拽感异常、油门响应迟滞。这些是控制逻辑问题，改 JSON 只会把症状挪到别处。

## 需求：极速必给，其余按粒度叠加

作者手上的输入差别很大，但它们不是几条互斥的路，而是同一组约束里给多给少：

| 输入 | 地位 | 钉住什么 | 没给时怎么补 |
|---|---|---|---|
| 期望极速 `v*` | **必给** | 最高档总传动比 `i_top`（配红线转速） | — |
| 额定功率 `P_rated` @ `n_p` | 可选 | `max_power`，以及极速可达性的下界 | 由 `v*` 处阻力反推 |
| 最大扭矩 `τ_max` @ `n_τ` | 可选 | 一档传动比与档数 | 由 `P_rated` 与转速形状反推 |
| 怠速 / 红线转速 | 可选 | 曲线转速轴与 `i_top` 的取值 | 按发动机族取 |
| `0→x` 加速时间 | 可选 | 比功率下界 | 由 `P_rated` 反算得到时间 |
| 最大爬坡度 | 可选 | 一档总传动比 `i_1` | 按附着利用率 0.85~0.95 反推 |
| 档数 / 巡航转速 | 可选 | 级比与换挡收益 | 按换挡收益 ≥15% 反推 |
| 制动距离或减速度 | 可选 | `max_brake_force` | 按 0.8 g 反推 |

**极速是唯一必给的约束**，它钉住最高档总传动比。其余每一项都把一个未知量从「按默认值取」变成「按给定值取」，同时产生一条可检验的不等式。作者确实给不出极速时，先把功率平衡反解出的 `v_power` 当锚点，方程形式不变。

三种典型粒度，中间的任意子集同样成立：

- **只给极速**：自由度最大，传动比、功率、档数全部由极速推出来。
- **极速 + 实车硬件**（还原向：功率、扭矩、转速，乃至档数）：硬件固定，极速退化成一条要校验的不等式。
- **全部都给**：约束数超过未知数，先判可行性，再谈怎么填。

可行性是这一节唯一要回答的问题：所有不等式同时成立才算可行。有一条破了就是不可行——报出破的是哪条、差多少、放松哪个代价最小，不允许悄悄挪动参数把残差吃掉。残差的算法见 [工程模型 §七](references/engineering-model.md)。

## 求解前先量出来的量

需求之外还有一组量。它们不是作者的选择，而是装配体与模型的事实，必须先从内容包里量出来：

| 量 | 来源 | 影响 |
|---|---|---|
| 质量 `M` | 各部件 `mass` 之和 | 加速、爬坡、附着极限 |
| 轮半径 `r` | **模型**：`type: "wheel"` 的 cube 在 y 向尺寸的一半 | `i_top`、牵引力换算、`max_drive_force` 折成牛顿 |
| 驱动轮数 `N` | 接在传动上的轮 | 单轮力矩分配 |
| 传动箱减速比 `r_trans` | 传动箱 `power_outputs` 里该端的分值 | `i_top`；漏算会把极速算低 |
| 迎风面积 `A` | 包围盒三轴投影，或 `projected_area` 的显式值 | 极速处的气动阻力 |
| `C_rr` | 轮胎材质的 `rolling_friction` | 滚阻、滑行减速 |
| `μ` | 轮胎材质 `friction` × 地面方块 `friction` | 附着上限 `μg` |

`r` 没有对应的 JSON 字段，只能从模型读：轮子的碰撞球半径就是模型 cube 的 y 尺寸一半。轮子画大一圈，`i_top` 与 `max_drive_force` 的换算会一起变，所以改模型之后必须重算 `i_top`，并把新的 `r` 记进卡片。

`r_trans` 同样不在变速箱里：它在部件的 `subsystem_data` 下，是传动箱子系统自己的一张「输出端 → 减速比」表，键是子系统名，值是减速比。单速车（只有电机、没有变速箱）全靠这张表，`r_trans = 1` 时动力源转速就等于轮速换算值。

## 求解顺序

1. **极速 → `i_top`**：`i_top = ω_red·r / v_red`，`v_red` 取 `v*` 的 1.03~1.05 倍，让目标车速落在红线之内。`i_top` 是 `挡位传动比 × final_ratio × r_trans` 三段的乘积，缺口通常落在前两段上。
2. **极速处阻力 → 功率下界**：`P_rated ≥ F_res(v*)·v* / 0.85`。给了功率就校验这一条，没给就按等号取值。
3. **功率与转速 → 扭矩曲线**：定端点 `(n_idle, τ_max·r_idle)`、`(n_τ, τ_max)`、`(n_red, τ_max·r_red)`，`max_power` 取曲线峰值。作者给的功率在 `n_p` 处，峰值就必须落在 `n_p`。
4. **一档 → `i_1`**：`i_1 = F_1·r / τ_max`，`F_1` 由爬坡反推；没给爬坡就按 `0.9·μMg` 取。再用附着 `F_1 ≤ μMg` 与轮端夹紧 `τ_max·i_1/N ≤ max_drive_force` 双向校验。
5. **档数 → 级比**：`q = (i_1/i_top)^(1/(n-1))`。`q ≥ 1.176` 才保住 15% 换挡收益；档数给得太多、跨度又不够时，这一条会破——那是频繁换挡的来源，不是加速能力的来源。
6. **回填验算**：逐档算 `τ_w`、`F`、绑定约束；极速由红线与功率两条条件分别求，取较小者。

## 发动机：曲线定形状，`max_power` 封顶

扭矩曲线由三个转速、两个比例和一个扭矩峰值确定，都是引擎 JSON 的字段：

```
n ≤ n_idle        τ = (n / n_idle) · τ_max · r_idle
n_idle < n ≤ n_τ  τ 由 τ_max·r_idle 线性升到 τ_max
n_τ < n ≤ n_red   τ 由 τ_max 线性降到 τ_max · r_red
n > n_red         τ = 5^(−10(n−n_red)/n_red) · min(τ_max·r_red, P_max/ω)
```

功率由曲线求值：`P(n) = τ(n)·ω`，`ω = n·2π/60`。

`max_power` 是**硬上限**，每个转速都按 `τ ≤ P_max/ω` 再夹一次。因此：

- 取在曲线峰值处，它不额外生效。
- 取小了，它真的削掉高转扭矩，输出由曲线与 `max_power` 共同决定。
- 取大了不参与物理，但会进 HUD 和 tooltip，制造「额定功率高但用不出来」的假象。

作者给的是「额定功率 @ rpm」时，`max_power` 直接取该功率，曲线峰值要调到同一个转速上。

功率峰值永远落在 `n_τ` 与 `n_red` 之间。`r_red·n_red ≥ n_τ` 时峰值就在红线上；否则峰值在 `clamp((n_red − r_red·n_τ)/(2(1−r_red)), n_τ, n_red)`。所以「额定功率 @ `n_p`」里的 `n_p` 必须 ≥ `n_τ`，否则这组参数自相矛盾。

红线以上按 `5^(−10Δ/ω_red)` 衰减，超速 10% 只剩两成，等效于一堵墙——极速因此基本由 `v_red` 决定。

**判定**：`max_power` 与 `max(P(n))` 的偏差超过 1% 即视为参数错误。

### 电机

电机的曲线只有两个参数：峰值扭矩 `max_torque`、峰值功率 `max_power`，外加红线与红线功率比。基速 `ω_base = P_max / τ_max` 是转折点：

```
ω ≤ ω_base        τ = τ_max                    恒扭矩区
ω_base < ω ≤ ω_red  P = P_max·(1 − k·(1 − r_p))  功率线性衰减，τ = P/ω
ω > ω_red         τ 按 0.5^((ω−ω_red)/(0.1·ω_red)) 快速衰减
```

`r_p`（`red_line_power_ratio`）取 1 时就是理想恒功率，换挡毫无收益；取小则高转掉功率、换挡有意义。真机多在 0.7~0.85。功率上限已经内建在曲线里，没有 `max_power` 那层额外夹紧；内阻在代码的阈值换算下实际够不到，按 0 计。

## 单位约定

单位错一次，整张平衡图就废了。下表全部来自代码，不要凭字段名推断。

| 参数 | 所在文件 | 真实单位 | 说明 |
|---|---|---|---|
| `max_power` | 引擎 | W | 必填。功率硬上限，取曲线峰值 |
| `max_torque` | 引擎 | N·m | 必填。曲线峰值扭矩 |
| `idle_rpm` / `max_torque_rpm` / `red_line_rpm` | 引擎 | rpm | 曲线三个转折点 |
| `idle_rpm_torque_ratio` / `red_line_torque_ratio` | 引擎 | 无量纲 | 两端扭矩相对 `max_torque` 的比例 |
| `max_torque` / `red_line_rpm` / `red_line_power_ratio` | 电机 | N·m / rpm / 无量纲 | 恒扭矩上限、红线、红线处功率占比 |
| `damping_factors` | 引擎 / 电机 | N·m/(rad/s)ⁿ | 依次为常数项、一次项、二次项 |
| `gear_ratios[i]` / `final_ratio` | 变速箱 | 无量纲 | 二者相乘得该档传动比 |
| `switch_time` | 变速箱 | s | 断流时长 |
| `power_outputs` | 传动箱（写在部件 JSON） | 无量纲 | 各输出端的固定减速比，与挡位串联 |
| `max_drive_force` | 车轮 | **N·m（轮端力矩）** | 绑定到旋转轴的 `MaxMotorForce`，不是牛顿 |
| `max_brake_force` / `max_hand_brake_force` | 车轮 | N·m（轮端力矩） | 同上 |
| `abs_wheel_radius` | 车轮 | m | 只进滑移率估算（ABS/防滑判定），不参与滚阻与牵引力换算 |
| `rolling_friction` | 材质 | 无量纲 `C_rr` | 只有轮面接触生效，阻力为 `C_rr × 法向载荷` |
| `friction` | 材质 | 无量纲三元组 | 各轴各向异性系数 |
| `projected_area` | 部件 | m² | `≤0` 表示按碰撞形状 AABB 自动计算 |

`max_drive_force` 的命名是历史遗留。它限制的是**轮端力矩**，牵引力还要除以轮半径。

## 驱动力链

```
τ_e ──×i_total──> τ_in ──÷N──> τ_w ──÷r_wheel──> F_traction
```

- 变速箱不改变功率，只把转速除以 `i_total = gear_ratios[i] × final_ratio × r_trans`，扭矩乘以同一比值。
- `r_trans` 是传动箱子系统 `power_outputs` 里分配给该驱动轮那一端的减速比；整车没有传动箱时 `r_trans = 1`，没有变速箱时挡位固定 1.00。**只算挡位不算传动箱，会把单速电车的极速算低到真值的三分之一以下。**
- 传动在开放差速下把扭矩均分给 N 个驱动轮：`τ_w = τ_e · i_total / N`。
- 轮端电机再夹一次：`τ_w ← clamp(τ_w, ±max_drive_force)`，然后减去刹车力矩。

于是单轮牵引力的三个上限依次是：

```
F_engine = τ_e · i_total / (N · r)
F_motor  = max_drive_force / r
F_grip   = μ · N_wheel / 1
```

实际可用的是三者最小值。**每一次标定都要指出当前档位被哪一个绑定**，绑定点不同，要改的参数完全不同。

约束清单里的附着与爬坡用整车量：`F_total = N · F = τ_e · i_total / r`，与驱动轮数无关；`N` 只决定单轮分担多少扭矩。

## 行驶阻力

阻力不是一条统一的「风阻 + 滚阻」曲线，而是三项物理性质完全不同的力：

| 项 | 来源 | 形式 |
|---|---|---|
| 气动 | 每个子部件默认带一条气动配置，三个轴按 AABB 自动取面积 | `½·ρ·C_d·v²·A` + 粘性一阶项 |
| 滚动 | 轮胎材质 `rolling_friction` 声明无量纲 `C_rr`，地面方块再乘一个倍数 | `C_rr·N`，正比于载荷，与速度、步长无关 |
| 内阻 | 引擎 `damping_factors` 多项式 | `c₀ + c₁ω + c₂ω²` |

三项的自变量不同，不能合并成一个系数。详细公式、默认值与代码位置见 [工程模型](references/engineering-model.md)。

极速处的总阻力 `F_res(v*) = ½·ρ·C_d·A·v*² + C_rr·M·g + τ_res·i_top/(r)` 是功率下界的来源，也是判断「功率够不够」的唯一依据。

## 验收阈值

下表既是验收线，也是缺省值的来源：作者没给的约束，按这里取值补。

| 指标 | 阈值 | 不达标时的第一嫌疑 |
|---|---|---|
| 功率利用率 `P_wheel,peak / P_rated` | ≥ 0.85 | 某档 `max_drive_force` 或红线提前绑定 |
| 一档附着利用率 `F / (μG)` | 0.85 ~ 0.95 | 传动比过大，或轮胎摩擦过低 |
| 相邻档换档收益 | ≥ 15% | 档位过密，`max_drive_force` 在该档已绑定 |
| `max_power` 与曲线偏差 | ≤ 1% | 参数填错 |
| 驱动加速度 / 制动减速度 | 0.7 ~ 1.0 | 两者严重不对称时查 `max_drive_force` |
| 极速 | 相对目标 ±5% | 最高档总传动比，其次气动面积 |
| `0→x` 加速时间 | 相对目标 ±10% | 比功率不足，或一档之后的级比过大 |

加速度本身有上限：`a ≤ μ·g`（约 1.0 g，气动下压力之外无法突破）。标一个 1.2 g 的加速目标，无论怎么调功率都到不了。

## 动态项的处理

静态方法覆盖不了的只有三类：起步扭矩爬升过程、换挡断流、档位振荡。它们不进标定模型，只在游戏内观测记录：

- 换挡延迟按常数记账即可：`t_0→X = t_静态 + n_次换挡 × switch_time`。
- 其余三项在游戏内记录，不写入静态结论。记录前按工程模型 §十 的口径：以物理步计时、先确认轮子在滚而不是在滑。

不要为动态性能另写一套积分模型：一旦脚本与游戏物理不一致，排查成本会超过收益，而且无法判断哪一方错。

## 完成后的自检

- 需求表列出了哪些约束是给定的、哪些是按默认值补的。
- 每个上限都写清了它绑定在哪一档、哪个速度点。
- 残差表没有负项；有负项时写明了放松的是哪条软约束。
- 标定卡片里的面积、质量、传动比与实际 JSON 一致。
- `max_power` 等于曲线峰值：它是硬上限，不是一个独立数字。
- 结论中的阻力三项各自有来源，没有合并成单一系数。

## 脚本

`scripts/` 下的工具直接读内容包 JSON，把上面这些量算出来。只要 Python 3.9+，无第三方依赖，不需要游戏。

四个入口各管一个侧面，公共逻辑在 `scripts/mmcal/`。按需只跑其中一个即可，不必为了看曲线而跑整车标定：

| 入口 | 回答什么 | 什么时候用 |
|---|---|---|
| `calibrate.py` | 档位表、极速、功率利用率、约束残差 | 配动力链、判定需求可行性 |
| `curve.py` | 扭矩/功率曲线的形状：峰值落点、功率带宽度、`max_power` 削不削扭矩 | 只调引擎或电机，不看车 |
| `drag.py` | 逐子零件气动面积、各速度点的阻力与所需功率 | 极速不够、判断哪块最吃风 |
| `gears.py` | 挡位 × 终传比 × 传动箱减速比，以及各档红线车速 | 只调传动，动力源还没定 |

```bash
python scripts/calibrate.py --list                          # 有哪些包与模板
python scripts/calibrate.py --pack Machine-Max_K17          # 整车标定，输出 Markdown
python scripts/curve.py --pack Machine-Max_K17              # 该车动力源的曲线
python scripts/curve.py --pack Machine-Max_K17 --csv        # 逐 rpm 全表，可直接画图
python scripts/drag.py --pack Machine-Max_K17 --speeds 30,60,90
python scripts/gears.py --pack Machine-Max_Civilian --template mini_ev
```

Windows 上 `python` 有时是应用商店的占位程序（直接退出、无输出），改用 `py -3` 或 `python3`。

`curve.py` 也能不经过整车，直接点名一个定义：`--subsystem machine_max:k17_engine`。它给出两个值得单看的形状指标：

- **功率带**：功率不低于峰值 90% 的转速区间。区间窄说明换挡落差必须小，否则换完档掉出功率带——这是「换挡有收益」之外的另一个判据。
- **`max_power` 削扭矩起点**：功率上限真的开始压制折线扭矩的转速。有起点就说明高转段调 `max_torque` 已经无效，只有 `max_power` 管用。

`calibrate.py` 带需求时追加参数，会多输出一张残差表：

```bash
python scripts/calibrate.py --pack Machine-Max_K17 \
    --top-speed 60 --power "500 PS" --accel 50:3.0 --grade 33 --gears 7
```

| 参数 | 含义 |
|---|---|
| `--pack` / `--pack-root` | 包目录名或包 id；包根目录缺省按脚本位置推断 |
| `--template` | 模板名；包内有多个模板时必填（`--list` 可见） |
| `--top-speed` | 目标极速 km/h，给出推荐 `i_top` 与极速处功率下界 |
| `--power` | 给定功率，`500 PS` / `368 kW` / `500hp` 都认 |
| `--accel` | `50:3.0` 表示 0→50 km/h 用 3 秒 |
| `--grade` / `--gears` | 最大爬坡度（度）、给定档位数 |
| `--area` | 覆盖气动面积，`10` 或 `5,8,10` |
| `--json` / `--strict` | 输出 JSON；有残差为负时退出码 1（可进 CI） |

`drag.py` 的 `--area` 只覆盖迎风面积（Z），`--speeds` 给速度点；`curve.py` 的 `--points` 控制采样点数、`--step` 控制 CSV 的转速步长。四个入口都认 `--json` 与 `--list`。

脚本算与不算的边界：

| 会算 | 不会算 |
|---|---|
| 整车质量、驱动轮数、轮半径、轮胎材质 | 动态手感（换挡、油门跟随） |
| 三轴气动面积（模型包围盒投影）、逐零件分解 | 遮挡折减：给「轮廓」与「逐零件相加」两个面积，极速因此是两个值 |
| 逐档 `τ_w`、牵引力、加速度、绑定约束 | 游戏内实测 |
| 极速（红线 + 功率平衡）、功率利用率 | |
| 内燃机与电机两种曲线、功率带、削扭矩起点 | 混动：两者同时存在时只取内燃机 |
| 变速箱挡位 × 终传比 × 传动箱减速比，以及没有变速箱的单速车 | 各输出端减速比不一致时的转速/扭矩分化：按均值折算并点名 |

```python
from mmcal import Registry, default_pack_root, resolve_vehicle, solve, Engine
```
