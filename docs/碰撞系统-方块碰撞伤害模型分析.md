# 碰撞系统 — 方块碰撞伤害模型分析

**状态**：分析提案，尚未实现。
**代码范围**：`common/mech/vehicle/collision/CollisionHandler.java` 的方块碰撞伤害路径（`handleTerrainCollision` → `applyBlockDamage`），以及它调用的 `util/mechanic/` 三个公式类、Spark-Core 的物理步进与方块物理数据。
**结论一句话**：当前模型把"整车动能"当成"轮胎局部耗散的能量"，并且让弹道穿甲判定意外地充当了碰撞伤害的开关。修法不是调护甲，而是改**接触能量 $E_c$ 的构造**与**伤害的门槛形式**。
**已核实的外部事实**（读 Spark-Core 源码得到，非推测）：物理步长、步进语义、`appliedImpulse` 的可用条件、方块恢复系数取值、回调频率——见 §1.3 与 §1.1。

## 0. 摘要

| 现象 | 根因 |
| --- | --- |
| 轻型车（400~1000 kg）手感正常 | 伤害门槛恰好落在它们日常速度之上 |
| SDKFZ234（≈6 t）、K17（≈14 t）轮胎异常易损 | 伤害门槛在速度空间按 $m_{\text{eq}}^{-1/2}$ 下降，同时单次伤害按 $m_{\text{eq}}$ 线性上升，两个效应叠加 |
| 提高轮胎等效护甲能缓解 | 两条路径同时变弱：$E_p \propto A_b/(A_p+A_b)$ 直接压低部件侧能量（软地面上尤其明显）；抬到 $A_p > D_{\text{raw}}$ 之后，`resolvePenetration` 的硬门槛（`unpen_power = 0` 时未击穿 → 伤害恒为 0）把伤害一票否决，属于"把开关关掉"，不是"把曲线调平" |
| 提高护甲后更容易撞坏方块 | 这是"较硬吸能更少"的**有意后果**：$E_b/E_c = A_p/(A_p+A_b)$ 随 $A_p$ 上升。问题不在方向，而在幅度——$E_b$ 被放大 4~9 倍，而 §1.5 是纯阈值判定，于是行为跳变 |
| 提高护甲后影响正常伤害 | `getRHA()` 同时是投射物穿甲判定的输入。这是同一份数据服务两种用途的正常代价，本提案的做法是**不去动它**，而不是拆开它 |
| 数值整体难调、存在悬崖 | 每物理步（100 Hz）每接触点独立结算，且串了四道不同量纲的门槛 |

**建议**：保留护甲分配比与弹道穿甲管线两条既有结构，把改动集中在**接触能量 $E_c$ 的构造**与**伤害的门槛形式**上：以求解器给出的接触冲量为物理输入，用**接触力与额定载荷的比较**产生 `baseDamage`，经 `BFDamageApi.hurt` 走完整管线。见 §6。

**两条硬约束**（贯穿全文）：

- **C1 护甲水平保留。** "较硬的接触件吸收更少碰撞能量"是设计意图，$E_p = E_c A_b/(A_p+A_b)$ 保留。碰撞手感的调参面在 $E_c$ 与伤害换算，不在 `rha` / `thickness`。
- **C2 伤害统一走弹道穿甲管线。** 不建立平行的部件伤害通道。碰撞产生的 `baseDamage` 与投射物一样经 `resolvePenetration` → `calculateFinalDamage` → `modifyDamage`。

**已评估并否决的替代方案**：用恢复系数 $e$ 承担能量分配（§5.3）。分配由接触柔度主导，$e$ 对分配的调节上限只有 1.52 倍；更关键的是现有材质把 $e$ 配成了"回弹感"（装甲 $e$=0.07、轮胎 $e$=0.60），与 $e$ 的能量语义（低 $e$ = 耗散多）冲突，于是三种自然写法全部反号——给装甲车体加 $e$ 修正会把它的吸能占比从 52.9% 推到 85.5%。$e$ 的正职是**总耗散量** $\Delta E = \tfrac12\mu v^2(1-e^2)$，保持在这个位置。

**一条贯穿两侧的时序约束**（§1.3、§5.2）：物理回调发生在**求解之前**，而 `getAppliedImpulse` 返回的是**上一步**求解的结果，新接触点读到 0。因此方块侧的摧毁判定**只能用求解前量**（当前相对速度、当前侵入深度），否则摧毁会被推迟一步，而这一步里求解器已经施加了完整刚性冲量——树叶也会像墙一样挡车。部件侧不受影响：损伤是累积量，10 ms 滞后无害，而 $J_{\text{ap}}$ 含求解器算出的真实有效质量。

## 1. 当前模型的完整链路

这一节把现行实现完整复述一遍，后面各节都只引用这里定义过的量。

### 1.1 输入

物理引擎在每个物理步对每个存活接触点回调一次 `onContactProcessed`（Bullet 的 `gContactProcessedCallback`，由 `world.update(fixedStep, 0, false, true, false, true)` 的 `doProcessed = true` 打开；两侧同时触发 `Collide.Processed` 事件）。每个接触点提供：

| 记号 | 来源 | 含义 |
| --- | --- | --- |
| $\vec v_{\text{rel}}$ | `MMMath.relPointWorldVel`，减掉对方对应量 | 接触点相对速度（世界系） |
| $\vec n$ | `point2.getNormalWorld` | 接触法线 |
| $\vec p$ | `point1.getPositionWorld` | 接触点世界坐标 |
| $J_{\text{ap}}$ | `ManifoldPoints.getAppliedImpulse(id)` | 本步该接触点被求解器施加的法向约束冲量 |

法向速度 $v_n = \left|\vec v_{\text{rel}} \cdot \vec n\right|$。

### 1.2 等效质量

`MassUtil.getEquivalentMass`：

$$
m_{\text{eq}} = m_{\text{part}} + 0.3\sum_{c \in \text{已连连接点}} m_c + 0.05\left(M_{\text{装配体}} - m_{\text{part}}\right)
$$

这是手工标定的"惯性参与度"启发式：一个用固定关节螺栓在车体上的轮子，不能按自由刚体的 50 kg 处理。

### 1.3 能量

```java
double contactNormalSpeed = Math.abs(contactVel.dot(normal))
                          + ManifoldPoints.getAppliedImpulse(id) / subPart.body.getMass();
float  restitution = clamp(body.getRestitution() * blockRestitution, 0, 1);
double contactEnergy = 0.5 * partMass * contactNormalSpeed² * (1 - restitution);   // partMass = m_eq
```

$$
E_c = \tfrac12\, m_{\text{eq}}\, v_{\text{eff}}^2\,(1-e),
\qquad
v_{\text{eff}} = v_n + \frac{J_{\text{ap}}}{m_{\text{part}}},
\qquad
e = \mathrm{clamp}\!\left(e_{\text{part}} \times e_{\text{block}},\, 0,\, 1\right)
$$

注意两处质量不一致：$v_{\text{eff}}$ 的冲量项除以**零件自身质量** $m_{\text{part}}$，而 $E_c$ 用的是 $m_{\text{eq}}$。

#### 两个物理步参数（已核实 Spark-Core 源码）

| 事实 | 出处 |
| --- | --- |
| 服务端 `baseStep = 5` → `tps = baseStep × 20 = 100` → $\Delta t = 0.01\ \mathrm{s}$ | `PhysicsLevelApplier.kt:30` 构造 `ServerPhysicsLevel(level, 5, …)`；`PhysicsLevel.kt:62` `val tps = baseStep * 20` |
| 客户端 `baseStep = 3` → `tps = 60` → $\Delta t = 1/60\ \mathrm{s}$ | `ClientPhysicsLevelApplier.kt:21` 构造 `ClientPhysicsLevel(level, 3, …)` |
| 步进是**固定步长单步**：`world.update(fixedStep, 0, …)`，`maxSteps = 0` 的语义是"一次大小为 timeInterval 的单步" | `PhysicsLevel.kt:159`；`PhysicsSpace.java:757` |
| 负载降频只改 `dynamicRepeat`（每游戏 tick 跑几步，5 → 1），**不改 $\Delta t$** | `PhysicsLevel.kt:157` `repeat(dynamicRepeat) { world.update(fixedStep, …) }` |
| `getAppliedImpulse` 返回**上一仿真步**求解器施加的冲量；**求解器需开启 WarmStart 才有值** | `ManifoldPoints.java:72-81`；`PhysicsWorld.kt:38` 已含 `SolverMode.WarmStart` |

三个直接结论：$\Delta t$ 是常量（服务端 0.01 s），$F = J/\Delta t$ 定义良好；两端步长不同，所以 $\Delta t$ 必须从 `getPhysicsLevel().getTps()` 取而不能硬编码；$J_{\text{ap}}$ 的可用性依赖 WarmStart 位。

#### 回调在单个物理步内的位置（已核实 Libbulletjme C++ 源码）

`btDiscreteDynamicsWorld::internalSingleStepSimulation` 的相位顺序（`BulletDynamics/Dynamics/btDiscreteDynamicsWorld.cpp:462-492`）：

```
① predictUnconstraintMotion(timeStep)     重力与速度预测，位置未变
② performDiscreteCollisionDetection()     ← onContactConceived / onContactProcessed 在这里
③ calculateSimulationIslands()
④ solveConstraints(getSolverInfo())       ← m_appliedImpulse 在这里被写
⑤ integrateTransforms(timeStep)           ← 位置在这里更新
⑥ updateActions / updateActivationState
```

三个由此推出的事实，**每一条都直接影响模型设计**：

| 事实 | 依据 |
| --- | --- |
| `onContactProcessed` 由 `btPersistentManifold::refreshContactPoints()` 逐点触发 | `NarrowPhaseCollision/btPersistentManifold.cpp:293-296` |
| `refreshContactPoints()` 在每个碰撞算法的 `processCollision()` **末尾**调用，即已经在 `addContactPoint()` 之后 | `btBoxBoxCollisionAlgorithm.cpp:67-73`（`m_ownManifold` 恒为真）、`btConvexConvexAlgorithm.cpp:311/333/355` |
| **新接触的第一步也会触发 `onContactProcessed`**，但该点刚由 `btManifoldPoint()` 构造，`m_appliedImpulse = 0` | `NarrowPhaseCollision/btManifoldPoint.h:56-62` |

于是：**任何只读 $J_{\text{ap}}$ 的判据，在接触的第一步必然读到 0。** 而求解在 ④、位置更新在 ⑤，都晚于 ②——如果在 ② 不做任何处置，这一步的完整刚性冲量一定会被施加。

#### 同步抑制是可行的，现有代码正在用

在 ② 里写 `ManifoldPoints.setDistance1(id, 大值)`，会让 ④ 中和该接触点，两条路径任一条都成立：

- **建约束前就被跳过**：`btSequentialImpulseConstraintSolver::convertContact` 只在 `cp.getDistance() <= manifold->getContactProcessingThreshold()` 时建接触约束（`BulletDynamics/ConstraintSolver/btSequentialImpulseConstraintSolver.cpp:1024`）。
- **即使建了约束也不出力**：`setupContactConstraint` 里 `penetration = cp.getDistance() + linearSlop`，`penetration > 0` 时走 `velocityError -= penetration * invTimeStep`（同文件 949-954 行），`rhs` 变成极大负值；接触约束是单边的（下限 0），迭代后被夹回 0。

所以 `setDistance1(id, 500)` 是**同一步内生效**的。现有实现的三处——无效接触点、攀爬辅助的"尚未接触高度场"、方块被摧毁——依赖的都是这条机制。

**结论**：能不能"不让车被方块挡一下"，取决于判据能否在 ② 用**求解前量**做出决定。② 可用的量是 `contactVel`（当前相对速度，代码自己算的）、`distance1`（当前侵入深度）、位置与法线；$J_{\text{ap}}$ 是上一步的值，新接触点为 0。

方块侧 $e_{\text{block}}$ 来自 Spark-Core 的数据映射 `data/spark_core/data_maps/block/block_physics.json`，按原版挖掘标签给出：

| 方块类别 | $e_{\text{block}}$ |
| --- | --- |
| `#minecraft:mineable_with_pickaxe`（石头、矿石…） | **0.9** |
| `#minecraft:concrete` | 0.9 |
| `#minecraft:mineable_with_axe`（原木、木板…） | 0.8 |
| `#minecraft:mineable_with_shovel`（泥土、沙、砂砾…） | 0.3 |
| `#minecraft:concrete_powder` / `packed_ice` | 0.3 |
| `blue_ice` | 0.4 |
| `#minecraft:snow` | 0.1 |
| `#minecraft:sand` | 0.2 / `minecraft:ice` 0.2 |
| `#minecraft:mineable_with_hoe`（树叶、作物…） | **0.0** |

所以石头地面上的轮胎：$e = \mathrm{clamp}(0.6 \times 0.9) = \mathbf{0.54}$，$(1-e) = 0.46$、$(1-e^2) = 0.7084$。（$e_{\text{block}} > 1$ 的史莱姆块会被 clamp 到 1。）

### 1.4 能量分配

$$
A_p = \texttt{hitBox.getRHA(subPart)} = \texttt{thickness} \times \Big[\texttt{decay\_rha} + (\texttt{rha} - \texttt{decay\_rha})\cdot r^{\texttt{decay\_power}}\Big]
$$

$$
A_b = \texttt{ArmorUtil.getBlockArmor} = 100\log_{10}(R_{\text{blast}}+1)\cdot\log_{10}(1.001+H)
$$

$$
E_b = E_c\cdot\frac{A_p}{A_p+A_b},
\qquad
E_p = E_c - E_b = E_c\cdot\frac{A_b}{A_p+A_b}
$$

### 1.5 方块侧

$$
\text{摧毁} \iff k_{\text{block}}\cdot E_b > 250\,D_b'
$$

其中 $k_{\text{block}}$ 是材质的 `block_damage_factor`，$D_b' = D_b + 0.5 D_{\text{support}}$ 是方块（含支撑）耐久。

### 1.6 部件侧

$$
D_{\text{raw}} =
\begin{cases}
0.2\,E_p\cdot\dfrac{250D_b'}{E_b} \Big/ 250 & \text{方块被摧毁}\\
\dfrac{0.2 \times 0.33\,E_p}{250} = 2.64\times10^{-4}E_p & \text{方块未被摧毁}
\end{cases}
$$

然后经过两道**串联的硬门槛**才真正落到耐久：

1. **交付门槛**：`if (hitBox.modifyDamage(source, D_raw) > 1)`。`modifyDamage` 顺序应用 `damage_modifiers` → 减 `dmg_resist` → 乘 `dmg_mult`。
2. **弹道穿甲门槛**：`BFDamageApi.hurt` 走 `resolvePenetration` → `calculateFinalDamage`。碰撞路径把 $\texttt{penetration} = \texttt{modifyPiercing}(D_{\text{raw}}) = D_{\text{raw}}$ 写进上下文，于是

$$
\text{击穿} \iff D_{\text{raw}} > A_p
$$

而未击穿时，若 `unpen_power == 0`（轮胎即如此）则 `calculateFinalDamage` 返回 **0**。

最终伤害 = `hitBox.modifyDamage(D_raw)`，即 `modifyDamage` 在门槛里算一次、在下游再算一次（门槛不改写 `baseDamage`，所以只生效一次，但门槛用的是同一个函数）。

### 2.2 轮胎的伤害门槛

对石头（$H=1.5$、$R_{\text{blast}}=6$）：$A_b = 33.65$，$A_p \ll A_b$，故 $E_p \approx 0.98 E_c$（SDKFZ234）。

轮胎的修饰链为 $\times 0.1 \to -2.0 \to -1.0 \to \times 0.95$，交付门槛要求

$$
(0.1 D_{\text{raw}} - 3.0)\times 0.95 > 1
\;\Longrightarrow\;
D_{\text{raw}} > 40.53
\;\Longrightarrow\;
E_p > 1.54\times10^5\ \mathrm{J}
$$

由 $E_p = \tfrac12 m_{\text{eq}} v_{\text{eff}}^2 (1-e)\cdot\frac{A_b}{A_p+A_b}$，门槛法向速度为

$$
v_{\text{eff}}^\star = \sqrt{\frac{2\,E_p^\star}{m_{\text{eq}}\,(1-e)}\cdot\frac{A_p+A_b}{A_b}}
\;\approx\; \sqrt{\frac{3.08\times10^5}{m_{\text{eq}}\,(1-e)}}
$$

取石头地面（$A_b = 33.65$，$e_{\text{block}} = 0.9$，故轮胎 $e = 0.54$、$1-e = 0.46$；kluo 用 `normal_tire` 的 $e=0.65$）：

| 载具 | $A_p$ | $m_{\text{eq}}$ | $e$ | $v_{\text{eff}}^\star$ | 折合 |
| --- | --- | --- | --- | --- | --- |
| kluo / wine_fox | 0.04 | 175 kg | 0.585 | 65.1 m/s | **234 km/h** |
| jeep | 0.06 | 393 kg | 0.54 | 41.3 m/s | 148 km/h |
| SDKFZ234 | 0.60 | 2073 kg | 0.54 | 18.1 m/s | **65 km/h** |
| K17 | 1.20 | 3698 kg | 0.54 | 13.7 m/s | **49 km/h** |

（$e$ 是两侧恢复系数的乘积，见 §1.3。它作为公因子出现在根号里，把四辆车的门槛一起抬高约 1.47 倍，不改变车辆之间的相对关系。）

#### 为什么这个门槛对重车形同虚设

$v_{\text{eff}}$ 由两部分相加：真实法向接近速度 $v_n$，以及 §1.3 的冲量伪速度 $J_{\text{ap}}/m_{\text{part}}$。后者的系数是 $M_{\text{车}}/m_{\text{part}}$——**整车动量变化被当作轮胎自身的速度变化**，SDKFZ234 放大 118 倍，kluo 放大 53 倍，再平方进能量。

把它换算成车辆层面的量更直观。若整车法向速度在单步内变化 $\Delta v$，冲量分散到 $N$ 个接触点，则

$$
v_{\text{eff}} \approx \frac{M}{N\,m_{\text{part}}}\,\Delta v
\qquad\Longrightarrow\qquad
\Delta v^\star = v^\star_{\text{eff}}\cdot\frac{N\,m_{\text{part}}}{M}
$$

| 载具 | 接触点总数 | 冲击集中于单轮时 $\Delta v^\star$ | 折合等效减速度 | 全部接地轮均摊时 $\Delta v^\star$ | 折合等效减速度 |
| --- | --- | --- | --- | --- | --- |
| kluo / wine_fox（700 kg，4 轮） | 16 | 5.58 m/s·步⁻¹ | 558 m/s²（57 g） | 22.3 m/s·步⁻¹ | 2231 m/s² |
| jeep（1280 kg，4 轮） | 16 | 5.80 m/s·步⁻¹ | 580 m/s²（59 g） | 23.2 m/s·步⁻¹ | 2320 m/s² |
| SDKFZ234（7500 kg，8 轮） | 32 | 0.48 m/s·步⁻¹ | 48 m/s²（**4.9 g**） | 3.86 m/s·步⁻¹ | 386 m/s² |
| K17（13000 kg，8 轮） | 32 | 0.21 m/s·步⁻¹ | 21 m/s²（**2.1 g**） | 1.68 m/s·步⁻¹ | **168 m/s²（17 g）** |

也就是说：**同一个物理事件，只要在车辆层面表现为约 2.1 g 的法向减速度（K17）、4.9 g（SDKFZ234），该轮胎就开始掉耐久；而 kluo 级需要约 57 g。** K17 的门槛落在越野行驶的常规载荷范围内，kluo 的门槛只有撞车才会出现。这就是"轻型车表现良好，稍重的军用载具开始显著增加轮胎受损几率"的直接来源，也是它表现为"几率上升"而不是"确定性损坏"的原因——门槛卡在日常载荷分布的尾巴上，于是越重的车越频繁地越线。

门槛之上，单次伤害随 $m_{\text{eq}}$ 线性增长（$D_{\text{raw}} \propto m_{\text{eq}} v^2$），重车再吃一次放大。两个效应方向相同。

> 需要说明的是，"地面接触"并不总是走到这条伤害路径上：`block_collision: ground` 的零件会把低于自身最低点的方块登记进 `climbableBlocks`，命中这些方块时 `handleTerrainCollision` 走高度场修正分支并提前返回。只有两种情况落入伤害路径——平地接触（高度场法线为竖直向上，不满足提前返回条件）与非攀爬面的正面撞击。前一情况正是"静止/巡航时载荷是否越线"的判据来源，后一情况则是撞墙、撞崖面、硬着陆。

### 2.3 护甲为什么"能改善"，代价又是什么

$E_p/E_c = A_b/(A_p+A_b)$，$E_b/E_c = A_p/(A_p+A_b)$。把轮胎 `thickness` 抬 10 倍（$A_p: 0.6 \to 6$）：

| | 石头（$A_b=33.65$） | 泥土（$A_b=3.11$） |
| --- | --- | --- |
| 部件侧能量 | ×0.86 | ×0.41 |
| 方块侧能量 | ×8.6 | ×4.1 |

于是：

- 部件侧只是温和下降，所以"提高护甲"看起来有效，主要靠的是另一条路径——当 $A_p > D_{\text{raw}}$ 时 §1.6 的**弹道穿甲门槛**把伤害一票否决为 0。$A_p$ 从 0.6 抬到 41 以上（`thickness` ≈ 690）就再也吃不到碰撞伤害。这是"关掉"，不是"调平"。
- 方块侧能量被放大 4~9 倍，而 §1.5 是纯阈值判定，一旦越过就出现行为跳变——即"更加容易撞坏方块"。
- `getRHA()` 同时是投射物穿甲的输入，轮胎的抗弹表现随之改变——即"影响正常伤害的表现"。

#### 分配比本身是对的，错的是承载它的量纲

"较硬的接触件吸收更少的碰撞能量"是一条正确的物理直觉，$E_p = E_c\cdot A_b/(A_p+A_b)$ 的表达形式也是标准的两体串联柔度分配。**轮胎吸走大约 98% 的 $E_c$ 并没有问题**——软胎在接触点确实承担绝大部分耗散，这正是它该做的事。§3 的 D1~D4 针对的是 $E_c$ 本身怎么算出来的，与分配比无关。

真正的问题是：$A_p$ 用**绝对毫米尺度**表达一个本质上属于**相对份额**的量，于是份额被钉死在饱和区。轮胎 $A_p = 0.6$、石头方块 $A_b = 33.65$，比值 1 : 56，份额 98.2%，**几乎没有调参空间**：把 $A_p$ 翻 10 倍只换来份额降 14%（石头）／59%（泥土）。想让它真正可调，就得把 $A_p$ 抬到与 $A_b$ 同量级（记住 §1.6 还要 $A_p > D_{\text{raw}}$），而那正好是抗弹所需的 50 倍以上。这才是"调护甲既必要又有害"的成因。

所以本提案的态度是：**分配比保留，但不把它当调参旋钮**。要调碰撞手感，调 §6 里 $E_c$ 的构造与伤害换算，不要动 `rha` / `thickness`。这样 §1.6 的穿甲门槛也就不会被推到"一票否决"的区间。

## 3. 结构性缺陷清单

**D1 — 能量归属错误。** $E_c$ 用的是整车动能尺度（$m_{\text{eq}}$ 主要由车体质量贡献），却把它当作"接触点局部耗散的能量"。轮子撞上障碍时，整车的 $\tfrac12 Mv^2$ 绝大部分仍是整车的动能，并没有在接触点转成热和塑性变形。把它按 $A_b/(A_p+A_b)$ 几乎全额记到轮胎账上，等于凭空发了一笔能量。

**D2 — 等效质量不守恒。** 每只轮胎独立取 $0.3\times m_{\text{车体}}$。SDKFZ234 有 8 只轮子，$\sum 0.3\,m_{\text{车体}} = 2.4\,M_{\text{车}}$。整车能提供的碰撞能量被复制了 2.4 份给轮胎侧。K17 同样是 8 只轮子对 10000 kg 车体。

**D3 — 一个公式里两个质量。** $v_{\text{eff}}$ 的冲量项除以 $m_{\text{part}}$（50 kg），$E_c$ 用 $m_{\text{eq}}$（2073 kg）。前者被放大 $M/m_{\text{part}} \approx 118$ 倍。这是重车轮胎受损的**主因**，而不是护甲配置。

**D4 — 判据是二次量，门槛是绝对量。** $E \propto m v^2$，而"1 HP"是个与质量无关的常数。于是门槛速度 $\propto m^{-1/2}$、单次伤害 $\propto m$。重车受到**双向**惩罚：更容易触发，且触发后掉得更多。任何"质量跨度大"的载具阵容都会踩到这个坑，这不是 SDKFZ/K17 的特例。

**D5 — 护甲量在碰撞路径上承担了三个职责。** `getRHA()` 同时是能量分配比、**伤害开关**、抗弹厚度。前两个职责里，"分配比"是设计意图（§2.3），问题在于它被绝对毫米尺度钉在饱和区；第三个职责是纯粹的越权——`A_p` 一旦大于 $D_{\text{raw}}$，碰撞伤害归零，这是 §1.6 把伤害数值当穿深写进上下文的副产品，不是任何人的设计选择。要拆的是第三项，不是第一项。

**D6 — 逐点逐步结算，没有事件化。** 接触点在其存续期内每物理步回调一次，100 Hz 独立判定。没有接触事件、没有去抖、没有对接触点数量的归一化。同一段刮擦过程会产生成百次微小结算，而每次都要各自越过绝对值门槛。

**D7 — 两条路径的耗散因子不一致。** 方块路径用 $(1-e)$，实体路径用 $(1-e^2)$（`processEntityCollision`）。同一物理含义（碰撞耗散比例）在两处相差最多 1.7 倍。部件互撞路径的常数又是第三个值（`0.0005` 对 `1/250 = 0.004`）。

**D8 — 碰撞伤害落进跳弹判定。** 碰撞走的是 `resolvePenetration`，它会用 $\vec v_{\text{rel}}$ 与 $\vec n$ 算入射角并调 `ArmorUtil.shouldRicochet`，其中含 `Math.random()`。当材料不满足碾压条件时，一次碰撞是否掉血带有随机性，且这个随机性每物理步重掷一次。轮胎与其它低 $A_p$ 零件因为 `effectivePen > 1.5 A_p` 恒成立而免疫跳弹，所以这一条**不影响本次要解决的问题**；厚装甲件在斜向碰撞中是否应当跳弹，是一个可以单独评估的语义问题。

## 4. 需求清单

选定模型前先固定约束，本节即后续一切取舍的依据。

### 游戏性

- **G1** 轻型车（400~1000 kg）现有手感不退化。
- **G2** 重型军用载具在正常越野、过路缘、上下坡时不掉轮胎耐久；只有真正的硬碰（高速撞墙、被炮弹震、跳台落地）才伤胎。
- **G3** 破障能力由"用哪一块去撞"决定，不被轮胎参数牵连。
- **G4** 内容包作者能独立调三个量：轮胎耐撞 / 轮胎抗弹 / 车辆破障能力。
- **G5** 管理员有全局旋钮（已有 `should_destroy_blocks`，可加伤害倍率）。
- **G6** 响应可读、可预测：玩家能学到"什么速度撞什么会坏什么"。
- **G7** 不增加物理线程热点开销。

### 物理可信性

- **P1** 量纲自洽。同一公式里不出现两个互相矛盾的质量。
- **P2** 静载不损伤。轮胎有额定载荷，长久承受车重不是损伤来源。
- **P3** 重车确实更容易压碎方块、也更容易在硬碰中受损——但通过力自然体现，而不是通过虚构质量。
- **P4** 有正确的时间尺度。同样的冲量，10 ms 内交付与 1 s 内交付对轮胎的后果不同。
- **P5** 不发生"凭空给某个零件发能量"（对照 D2）。

## 5. 判据形态对比

| 判据 | 形式 | 优点 | 致命问题 |
| --- | --- | --- | --- |
| **能量** | $\tfrac12 m v^2$ | 直观、与爆炸/穿甲系统共用语言 | 是**状态量**不是**载荷**；必须回答"哪份质量、耗散在哪"，而这两个问题在局部接触上都没有干净答案（D1/D2/D3/D4） |
| **冲量** | $J = m_{\text{eff}}(1+e)v_n$ | 求解器直接给出，且**已经包含真实的约束惯量**（车体、关节、其他轮子、方块刚性全部由求解器算进去了），不需要任何手工系数 | 线性于质量，仍无法区分"一步硬碰"与"一秒慢推"；缺时间维度 |
| **力** | $F = J/\Delta t$ | 与"轮胎额定载荷"量纲一致，可直接数据驱动；同时含质量与时间；静载有正确行为（$F = Mg/N$ 是常数，不是损伤） | $\Delta t$ 固定（§1.3 已核实：固定步长单步、负载降频不改步长），故无变步长风险；剩余工作是平滑/包络以抵抗求解器抖动 |
| **压强** | $F/A_{\text{contact}}$ | 轮胎物理上最贴切（接地压力） | 接地面积难以可靠获取；轮胎形状与地形接触面积每步都在变 |

**冲量是输入，力是判据，损伤是过载的泛函。** 这三句话是本提案的全部结构。

冲量成为首选输入的关键理由，正好回应 D3：$J_{\text{ap}}$ 是求解器为满足非穿透约束而施加的冲量，它本身等于"接触点有效质量 × 该步的法向速度变化"。当轮子用固定关节螺栓在 6 t 车体上时，求解器算出的有效质量**自动**包含车体与关节的贡献；当轮子几乎悬空时，它自动退化为轮子自身。`getEquivalentMass` 的 0.3/0.05 手工系数正是在手工逼近这个量——而求解器已经在同一个物理步里精确算出了它。

### 5.1 护甲水平在载荷模型里的位置

护甲没有从模型里消失，它换了一个更好的位置。在能量式里，$A_p$ 的作用被钉在饱和区（§2.3）；在载荷判定里，它进入**额定载荷**：

$$
F_{\text{rated}} \;\propto\; \text{厚度} \times \text{材料强度}
$$

"较硬的吸收能量更小"在这里表现为"较硬的在同一接触力下过载更少"，是**线性、连续、可全程调节**的。两种表达在物理上指向同一件事（接触柔度），但后者没有饱和问题：软胎 $F_{\text{rated}}$ 低、装甲板 $F_{\text{rated}}$ 高，两端都留出调节余地。

同时，$A_p$ 作为"伤害开关"的那一半职责消失——因为伤害的落地与 §1.6 的 $D_{\text{raw}} > A_p$ 判定无关。

### 5.2 两侧分工：方块侧只能看求解前量，部件侧可以看求解后量

§1.3 的相位顺序决定了这条分工。它是**硬约束**，不是风格选择。

| | 可用输入 | 为什么 |
| --- | --- | --- |
| 方块侧 | **只用求解前量**：`contactVel`（当前）、`distance1`（当前） | 摧毁必须在 ② 完成并同步 `setDistance1(id, 500)`，才能让 ④ 不施加这一步的刚性冲量。若等到 $J_{\text{ap}}$ 可用（已经是下一步），车已经被完整挡了一下——对树叶、作物这类脆弱方块，那等于撞墙 |
| 部件侧 | 可用求解后量：$J_{\text{ap}}$（上一步） | 部件损伤是累积过程，10 ms 滞后不影响手感；而 $J_{\text{ap}}$ 含求解器算出的真实有效质量，正是部件侧想要的输入 |

**这不等于"部件侧要滤波、方块侧不要"那种按时间尺度的划分**，而是按"信息在求解前是否可得"的划分。两者恰好都落在同一条线上，但理由不同：

- 方块侧：**必须**在求解前决定（否则动作太晚）。
- 部件侧：**可以**在求解后决定（滞后无害），而求解后的量更准。

附带结论：方块侧的判据**不能只由 $J_{\text{ap}}$ 导出**。§6.4 给出在求解前可得的替代量；一并给出"质量信息怎么进方块侧判据"的三种做法与取舍。

> **现有实现为什么能工作。** §1.3 的 $v_{\text{eff}} = v_n + J_{\text{ap}}/m_{\text{part}}$ 把两项相加，在时序上恰好覆盖了两种情形：
> - **首接触步**：$J_{\text{ap}} = 0$，但 $v_n$ 是当前真实接近速度 → 判据非零 → 可以立刻 `markRemoved` + `setDistance1(500)`，求解器这一步就不响应，车直接穿过去。
> - **持续接触**：$v_n$ 已被求解器压到 ≈0，但 $J_{\text{ap}}$ 是上一步的大值 → 判据仍非零。
>
> 也就是说，这个看似量纲混搭的伪速度，实际上承担了"首步可用"这个时序职责。**D3 说它放大 $M/m_{\text{part}}$ 倍是对的，但直接删掉它会让方块侧在首步失去判据。** 改造时必须把这份职责显式交给一个求解前量（§6.4），而不是简单删除。

#### 时间常数的归属

P4 要求的时间尺度**只施加于部件损伤**，方块破坏不做任何时间处理：

| | 判据量 | 时间处理 |
| --- | --- | --- |
| 部件侧 | 过载泛函 | 峰值保持 + 慢速基线（§6.2），因为损伤是累积过程，有疲劳/热的时间尺度 |
| 方块侧 | **求解前的瞬时量** | **不做任何滤波**，单步即判 |

方块破坏是"碎或不碎"的二值事件，本来就该看峰值；给它套时间常数会让"高速扫过树叶/作物"这类**单步、低能量**的接触来不及建立判据而丢失破坏。§6.2 的 $F_{\text{fast}}$ 用 $\max$ 保持而非低通，第一步就取到瞬时值，因此它本身也没有上升时间；即便如此，§6.4 的方块侧判据也不读它——不是因为滤波，而是因为它的来源 $J_{\text{ap}}$ 在时序上太晚。

### 5.3 恢复系数能不能承担能量分配

一个自然的设想是：$e$ 是碰撞里唯一真正描述"这次撞击有多不弹性"的量，用它来分配能量，软的东西（$e$ 低）多吸能、硬的东西少吸能。结论是：**$e$ 管的是总量，管不了分配；而且它现在的取值方向恰好与意图相反。**

#### $e$ 的物理含义：只说总量

$$
e = -\frac{v_{\text{分离}}}{v_{\text{接近}}}
\qquad\Longrightarrow\qquad
\Delta E_{\text{总耗散}} = \tfrac12\,\mu\,v_{\text{rel}}^2\,(1-e^2)
$$

$\mu$ 是约化质量。这条式子唯一确定的是**两侧合计耗散了多少**。至于这份耗散发生在哪一侧，它一个字都没说——因为 $e$ 是两侧串联之后的**联合**属性，单个 $e$ 无法反解出两侧各自的贡献。

串联接触里两侧共享同一个力与同一个冲量 $J$，各自的耗散是

$$
E_i \;\approx\; \tfrac12 J^2\, c_i\,(1-e_i^2)
\qquad\Longrightarrow\qquad
\boxed{\;E_i \;\propto\; c_i\,(1-e_i^2)\;}
$$

$c$ 是接触柔度。**分配由柔度主导，$e$ 只是乘在上面的修正项。** 这个式子也解释了现有模型的直觉为什么"方向对"：柔度小（硬、厚、结实）的一侧吸能少，这正是 $E_p = E_c A_b/(A_p+A_b)$ 想表达的东西——它一直是个粗糙的柔度代理。

#### 动态范围：$e$ 比护甲小两个数量级

拿实际数据实测两个因子的可调范围。石头地面上 $e = \mathrm{clamp}(0.9\,e_{\text{part}})$（§1.3）：

| 量 | 取值域 | 单侧权重的最大变化 |
| --- | --- | --- |
| $A$（现有护甲，含方块） | 0.01 ~ 525.9 | **5×10⁴ 倍** |
| $(1-e^2)$ | 0.658（`normal_tire`，$e$=0.585）~ 0.99992（`paper`，$e$=0.009） | **1.52 倍** |

把 $e$ 按 $\propto c_i(1-e_i^2)$ 正确地并进现有分配（取 $c \propto 1/A$）：

| | 轮胎（`off_road_tire`，$A_p$=0.6，$e$=0.54） | 装甲车体（`rha`，$A_p$=30，$e$=0.063） |
| --- | --- | --- |
| 现状 $A_b/(A_p+A_b)$ | 98.25% | 52.87% |
| 加 $e$ 修正后 | **99.52%** | **85.47%** |

两行都朝**错误方向**动，而且装甲那一行动得很多。原因见下一小节。

要把轮胎的 $E_p/E_c$ 拉到 50%，在 $\propto c(1-e^2)$ 下需要

$$
A_p = A_b\cdot\frac{1-e_p^2}{1-e_b^2} = 33.65 \times \frac{0.7084}{0.19} = 125.4
\quad\Longrightarrow\quad \texttt{thickness} \approx 2090
$$

也就是说 $e$ 不但没帮上忙，反而把目标从 $A_b = 33.65$ **抬高到 125.4**（3.7 倍）。$e$ 不是这个旋钮，而且方向是反的。

#### 符号为什么是反的

现有材质数据里，"硬"与"低 $e$"是绑在一起的——这是有意的配平（装甲板不该把撞上来的车弹开）：

| 材质 | $e_{\text{part}}$ | 石头上 $e$ | rha |
| --- | --- | --- | --- |
| `rha`（装甲钢） | **0.07** | 0.063 | 1.00 |
| `structural_steel` | 0.12 | 0.108 | 0.85 |
| `depleted_uranium_armor` | 0.20 | 0.180 | 1.65 |
| `hardwood` | 0.20 | 0.180 | 0.10 |
| `5083_aluminum_alloy` | 0.40 | 0.360 | 0.40 |
| `7035_aluminum_alloy` | 0.55 | 0.495 | 0.45 |
| `pvc` | 0.55 | 0.495 | 0.06 |
| `glass` | 0.60 | 0.540 | 0.12 |
| `off_road_tire` | **0.60** | 0.540 | 0.06 |
| `normal_tire` | **0.65** | 0.585 | 0.04 |
| `ice` | 0.05 | 0.045 | 0.02 |
| `paper` | 0.01 | 0.009 | 0.01 |

$e$ 的**能量语义**是"耗散比例"（$e$ 低 = 耗散多 = 该多吸能）；而数据把 $e$ 的**玩法语义**配成了"回弹感"（装甲 $e$ 低 = 车撞上去不弹开）。两者在这个数据集里冲突。于是任何"低 $e$ 多吸能"的公式，都会得出"装甲板吸能最多"。

"吸能权重"的三种自然写法全部与设计意图反号：

| 写法 | 装甲钢 | 轮胎 | 谁吸能多 |
| --- | --- | --- | --- |
| $\propto (1-e)$ | 0.937 | 0.46 | **装甲吸 67%**（与"硬吸能少"相反） |
| $\propto (1-e^2)$ | 0.996 | 0.708 | **装甲吸 58%**（同样相反） |
| $\propto e$ | 0.063 | 0.54 | 轮胎吸 90%（数值符合意图，但理由是"越弹越吸能"，说不通） |

顺带注意 `paper`（rha 0.01，$e$ 0.01）与 `ice`（rha 0.02，$e$ 0.05）：最软的两个材料 $e$ 最低。$e$ 与硬度只在金属族内部单调，全局不成立。**所以把 $e$ 当作硬度的代理量，严格劣于直接用 `rha` / `thickness`**——同一件事，动态范围小两个数量级，还会被纸和冰破坏掉。

#### $e$ 该待在哪里

1. **总量耗散**：$\Delta E = \tfrac12\mu v^2(1-e^2)$。这是 $e$ 的正职，也是它唯一有物理依据的用法。§1.3 的方块路径用 $(1-e)$、实体路径用 $(1-e^2)$，应当统一到后者（D7）。
2. **分离判据**：$e$ 决定碰撞后是否弹开。这已经由 `ManifoldPoints.setCombinedRestitution` 交给求解器，是 $e$ 的本职。
3. **在载荷模型里 $e$ 是免费的**：接触刚度与阻尼（$e$ 的物理来源）已经体现在求解器逐步给出的 $J_{\text{ap}}$ 分布里，§6.3 不需要再乘一个 $e$ 因子。

同时记下两条 $e$ 的既有不一致（与 D7 同族，但独立于本次问题）：

- **合成规则**：方块路径用 $e_{\text{part}} \times e_{\text{block}}$，部件互撞路径用 $\sqrt{e_{\text{part}} \times e_{\text{other}}}$。串联迟滞元件的能量留存比是相乘的，所以前者符合模型，后者是第三种规则。
- **耗散因子**：$(1-e)$ 对 $(1-e^2)$。石头上的轮胎两者相差 $0.46/0.7084 = 1.54$ 倍，不是小数目。

> **已核实**：方块恢复系数**不是 0**。Spark-Core 的数据映射按原版挖掘标签给出 0.0 ~ 0.9 的值，代码兜底默认 0.3，取值表见 §1.3。所以 $(1-e)$ 因子在方块碰撞路径上实际生效（石头上轮胎 $e = 0.54$，因子 0.46），既不是恒等于 1，也不会因为方块侧为 0 而退化。

## 6. 建议模型：接触载荷判定

### 6.1 物理量

每个物理步、每个接触点：

$$
F_n = \frac{\left|J_{\text{ap}}\right|}{\Delta t},
\qquad
F_t = \frac{\sqrt{J_{\text{lat1}}^2 + J_{\text{lat2}}^2}}{\Delta t},
\qquad \Delta t = 1/\texttt{PhysicsLevel.tps}
$$

$\Delta t$ 服务端为 $0.01\ \mathrm{s}$、客户端为 $1/60\ \mathrm{s}$（§1.3），必须运行时读取，不能硬编码。

**这两个量只供部件侧使用。** 它们来自 `getAppliedImpulse`，而该值在相位 ② 读到的是**上一步**的求解结果（新接触点为 0），因此不能满足方块侧"必须在同一步内决断"的要求。方块侧用 §6.4 的求解前量。

$F_n$ 是法向接触力，$F_t$ 是切向摩擦/刮擦力（对应 `ManifoldPoints.setAppliedImpulseLateral1/2` 写入的两个切向分量）。$J_{\text{ap}}$ 由求解器给出，其含义是"该接触点的有效质量 × 本步为满足非穿透约束所需消除的法向相对速度"，因此**车体惯性、关节耦合、同轴其他接触点、方块的刚性全部已经包含在里面**。

### 6.2 载荷包络（部件侧专用）

对每个 `(subPart, manifoldPointId)` 维护两个状态量：

$$
F_{\text{fast}} \leftarrow \max\!\left(F_n,\; F_{\text{fast}}\,e^{-\Delta t/\tau_f}\right),
\qquad
F_{\text{slow}} \leftarrow F_{\text{slow}} + \left(F_n - F_{\text{slow}}\right)\left(1 - e^{-\Delta t/\tau_s}\right)
$$

$\tau_f \approx 0.05\ \mathrm{s}$（冲击保持时间），$\tau_s \approx 0.5\ \mathrm{s}$（准静态基线）。接触脱离即复位。

关于"上升时间"，需要区分这两个式子：

- $F_{\text{fast}}$ 是**峰值保持**，不是低通。$\max$ 的第一个参数就是本步瞬时值，因此**第一个物理步即取到峰值，不存在上升时间**。$\tau_f$ 只控制"峰过去之后多久回落"，作用是把同一段接触过程中稀疏出现的尖峰粘成一个包络，避免相邻两步之间被判据跳进跳出。
- $F_{\text{slow}}$ 是真正的一阶滞后，有 $\tau_s$ 量级的上升时间。它**只**用于给出 $F_{\text{rated}}$ 的缺省基线（"这辆车平时压着多大载荷"），不参与任何峰值判据。

因此"撞树叶丢破坏"这类担心不成立——但前提是方块侧根本不读这个包络，见 §5.2 与 §6.4。

$F_{\text{slow}}$ 需要一个初值策略：若从 0 开始爬升，接触建立后的前 $\tau_s$ 内基线偏低，$F_{\text{rated}}$ 会被压到下限，可能造成开局的误伤。可行做法是首次接触时直接以 $F_n$ 初始化（或按 $M_{\text{装配体}}\,g/N_{\text{接触点}}$ 估一个理论静载）。

### 6.3 部件侧：载荷与额定值比较

$$
F_{\text{rated}} = \texttt{hitBox.load\_rating} \;\;\text{（内容包可选，单位 N）}
$$

$$
\text{缺省}：F_{\text{rated}} = \max\!\left(\kappa\,F_{\text{slow}},\; \kappa_0\, m_{\text{part}}\,g\right),
\qquad \kappa \approx 3,\ \kappa_0 \approx 5
$$

$$
\text{过载}_{\perp} = \max(0,\; F_{\text{fast}} - F_{\text{rated}}),
\qquad
\text{过载}_{\parallel} = \max(0,\; F_t - \mu_{\text{rated}} F_{\text{rated}})
$$

$$
\mathrm{d}D = k_\perp \cdot \text{过载}_\perp^{\,\gamma} \cdot \Delta t
\;+\; k_\parallel \cdot \text{过载}_{\parallel}^{\,\gamma} \cdot \Delta t
\qquad (\gamma = 1\ \text{起步})
$$

要点：

- **静载自动免疫**。停车、平路巡航时 $F_{\text{fast}} \approx F_{\text{slow}}$，过载恒为 0，与车重无关（满足 G2、P2）。
- **重车的硬碰更伤**（满足 P3）。车重决定 $F_n$ 的量级，$F_{\text{rated}}$ 缺省按同一条静载定标，因此"相对自己体重的冲击"被惩罚，绝对尺度自动跟随车型。
- **没有悬崖**。线性（或 $\gamma=1.5$）响应取代了"绝对值门槛 + 一票否决"，响应曲线连续可导（满足 G6、P1、P4）。
- **切向单独成项**。轮胎侧壁被刮破、斜向顶路缘，都是切向载荷主导的真实损伤渠道；当前模型完全落在法向项里。
- **数值保护**取代 `modifyDamage(...) > 1`：只丢弃 $\mathrm{d}D < 10^{-4}$ 的噪声。
- **护甲在这里的角色是 $F_{\text{rated}}$**（§5.1）；$E_p = E_c A_b/(A_p+A_b)$ 的分配比原样保留，用在由 §6.7 给出的能量口径上。

交付口径（保持 C2：不建立平行伤害通路）：

- 每物理步把 $\mathrm{d}D$ 累积到 `per-(subPart, hitBox)` 的 double；
- **每游戏 tick（20 tps）主线程结算一次**，构造一个 `BFDamageContext` 调一次 `BFDamageApi.hurt`，与投射物走的是同一条管线。这与爆炸系统已经确立的"每个去重键每 tick 至多施加一次"纪律一致（`docs/武器系统-爆炸系统详细设计.md` §9.5），把调用次数从 100 Hz × 接触点数压到 20 Hz × HitBox 数。
- **碰撞伤害在语义上是钝击**，因此正确的落点是 `unpen_power` 这条既有分支，而不是给碰撞单开一条通路。§1.6 的开关问题来自"把伤害数值当作穿深写进上下文"这一口径错误，修法是给碰撞一个**语义正确的 penetration**，并把承接钝伤的材料的 `unpen_power` 设为大于 0：

$$
\text{BLOCKED} \;\Longrightarrow\; D_{\text{final}} = \texttt{modifyDamage}\!\left(D_{\text{base}} \cdot \left(\frac{\text{penetration}}{A_p}\right)^{\texttt{unpen\_power}}\right)
$$

  这需要两个决定，都不动管线结构：
  1. **碰撞写什么 penetration。** 最自洽的是"接触压入深度"——`getDistance1()` 的侵入量（JME 约定负值为侵入）换算成 mm。它天然随撞击强度增长，且与 $A_p$ 同量纲：软胎 $A_p$ 低，同样的压入深度直接吃满 `baseDamage`；厚装甲 $A_p$ 高，钝伤按 `ratio = clamp(penetration/A_p, 0, 1)` 折减。物理图像正确，而且让 $A_p$ 在碰撞路径上获得一个**新**的、合理的作用位置。需要注意的是侵入深度受求解器 ERP 与穿透容差影响、噪声较大，落地前应先在 §8 的响应面工具上观察其分布；若抖动不可接受，退路是写一个由接触力换算的等效压入深度。
  2. **哪些材料承接钝伤。** 轮胎、装饰件这类"本该被撞凹而不是被穿透"的材料设 `unpen_power ≥ 1`。`normal_tire` / `off_road_tire` 当前是 `0.0`，这是碰撞伤害必须先把 $A_p$ 抬到 40+ 才能落地的根本原因。

  替代做法（工作量更大，仅在 1、2 两条都不可接受时考虑）：给碰撞一个独立伤害类型并在 `resolvePenetration` 短路。它换来的是"不用选 penetration 口径"，代价是一条并行通路——与 C2 冲突，故不作为首选。

### 6.4 方块侧：强度判定（不引用部件护甲，只用求解前量）

$$
F_c = \hat m_c \cdot \frac{v_n}{\Delta t} \cdot k_{\text{block}}(\text{材质}),
\qquad \text{摧毁} \iff F_c > S
\;\Longrightarrow\;
\texttt{markRemoved}(pos) + \texttt{setDistance1}(id, 500)
$$

**第一步：判据量必须是求解前量。** §1.3 的相位顺序决定了这一点：只有在 ② 决定并同步禁用接触，④ 才不会施加这一步的刚性冲量。若用 $J_{\text{ap}}$，新接触点读到的是 0，摧毁只能推迟到下一步——而那时车已经被完整挡了一下。

$\hat m_c$ 的构造取决于**该接触点是否有历史**：

| 情形 | $\hat m_c$ | 说明 |
| --- | --- | --- |
| 新接触点（无历史） | $m_{\text{fallback}}$ | 用当前法向接近速度 $v_n$（由 `contactVel` 与法线点乘得到，现有代码已经这么算） |
| 已有历史 | $\mathrm{EMA}\!\left(\dfrac{J_{\text{ap}}}{(1+e)\,v_{n,\text{prev}}}\right)$ | 求解器直接告诉了我们"这个接触点的有效质量是多少" |

$\hat m_c$ 的第二种取法不需要 0.3/0.05 之类的手工系数——车体惯性、关节耦合、同侧其他接触点全在 $J_{\text{ap}}$ 里。EMA 时间常数取 $\tau_s$ 量级（§6.2），以抑制单步噪声。

$m_{\text{fallback}}$ 有三种取法：

| 取法 | 效果 | 代价 |
| --- | --- | --- |
| 零件自身质量 $m_{\text{part}}$ | 最保守 | 6 t 车的 50 kg 轮子严重低估，首次撞石头碎不掉，要等第二步 |
| 现有 `m_eq` 原样 | 首击即有正确量级 | 8 只轮子各自领取 $0.3M$，破坏阈值被高估约 2.4 倍 |
| 整车质量按接地零件数分摊（守恒） | 物理上最直白 | 需要接地零件计数，多一处状态 |

**推荐第三种**，因为"首次撞上去能不能碎"正是玩家最敏感的那一下；随后由 $J_{\text{ap}}$ 学得的 $\hat m_c$ 接手。

#### $S$ 的标定：不要从现阈值平移

现阈值是能量（$k\,E_b > 250 D_b'$），换成力需要除以一个特征位移 $\delta_c$。问题在于**这个位移在现模型里不是常数**：由 $E_c \approx \tfrac12 m v^2$ 与 $F \approx m v/\Delta t$ 反推，$\delta \approx v\,\Delta t/2$，随速度线性增长。所以"令 $S = 250D_b'/\delta_c$ 且取 $\delta_c = 0.05\ \mathrm{m}$"会把破坏门槛在速度空间压低一个数量级。

正确做法是**先定行为目标再反解**：

$$
S = \hat m_c \cdot \frac{v^\star_{\text{block}}}{\Delta t}\cdot\frac{1}{k_{\text{block}}}
\quad\Longleftarrow\quad v^\star_{\text{block}} = \text{该类载具撞碎该方块所需的法向速度}
$$

标定表按（载具级别 × 方块类别）给目标速度，例如"6 t 级以 15 m/s 撞碎石头、以 3 m/s 撞碎泥土、以 0.5 m/s 扫掉树叶"，再逐格反解。这比从旧阈值换算可靠得多，也正好是爆炸系统 `k_armor` 采用的方式。

$k_{\text{block}}$ 沿用 `block_damage_factor`，语义收窄为**接触压强/形状集中系数**（轮胎面积大 → 低值；履带板、撞角、推土刃 → 高值）。

关键性质：

- 判据量在**同一步内**可得，因此摧毁与 `setDistance1` 同步生效，车不会先被挡一下。方块破坏是二值事件，脆弱方块（树叶 $D_b \approx 2.1$）的破坏由单步峰值决定，不做任何时间处理。
- 方块侧**完全不含** $A_p$，抬高轮胎护甲不改变破障能力（满足 G3）。
- "重车更容易压碎方块"由 $\hat m_c$ 随车重增长自然出现；"较硬的接触件更容易压碎方块"这一半由 $k_{\text{block}}$ 承担——它正是"硬撞角 vs 软轮胎"的差别所在，与 C1 一致。
- 掉落率沿用现有形式 $e^{1 - F_c/S}$：压得越狠碎得越彻底。
- 标定时要留意 $k_{\text{block}}$ 的取值范围。现有值是为**压能量**而设的（轮胎 0.05，把阈值推到了不可能达到的量级）；在力判据下 0.05 会把轮胎的破障能力压得过低，它应当重新按"接触压强集中系数"标定，量级大概在 0.2~1.0。

> **离散检测本身的残留顿挫。** 即使方块在同一步被摧毁，位置更新在 ⑤，而车在 ② 之前已经按上一帧的速度侵入了方块。摧毁 + `setDistance1` 阻止的是**冲量**，不是**穿透**；穿透要等下一帧 narrowphase 重新求解。所以"高速穿树叶"可能仍有极轻微的触感，但不会掉速度。是否可接受应当在 §8 的 T8 里实测。

### 6.5 伪代码

```java
// 示意：省略了与现状一致的参数、坐标变换与边界检查
// 物理线程，每物理步、每接触点一次（相位 ②：求解之前）
void onContactProcessed(..., long id) {
    float dt = 1f / subPart.getPhysicsLevel().getTps();   // 服务端 0.01 s，客户端 1/60 s（§1.3）

    HitBox hitBox = subPart.getHitBox(point1.getTriangleIndex());

    // 求解前量：当前接触点法向接近速度（负值表示接近）
    float vn = contactVel.dot(normal);

    // ——— 方块侧：只用求解前量，必须在相位 ② 决定 ———
    if (MMServerConfig.shouldDestroyBlocks() && hitBox.attr.blockDamageFactor() > 0) {
        BlockPos   pos = terrain.getBlockPosFromContactPoint(point, normal, 0);
        BlockState st  = terrain.getBlockSnapshot(pos).getState();
        // 质量估计：有历史就用求解器学到的 m_c，没有就用守恒化的接触参与质量
        float mh = momentumMassFor(id, subPart, vn);           // §6.4，量纲 kg
        float fc = mh * (-vn) / dt * hitBox.attr.blockDamageFactor();  // 法向接触力 N（vn 负值为接近）
        float S  = BlockStrength.of(terrain, pos, st);         // N
        if (st.getDestroySpeed(level, BlockPos.ZERO) >= 0 && fc > S) {
            terrain.markRemoved(pos);
            SparkLevel.submitDeduplicatedTask(level, pos.toShortString(), PPhase.PRE,
                () -> level.destroyBlock(pos, Math.random() < Math.exp(1 - fc / S)));
            ManifoldPoints.setDistance1(id, 500f);            // 同一步内禁用该接触点
        }
    }

    // ——— 部件侧：可用求解后量，滞后 10 ms 无害 ———
    float fn = Math.abs(ManifoldPoints.getAppliedImpulse(id)) / dt;   // 上一步的冲量 → 力
    float ft = (float) Math.hypot(
                   ManifoldPoints.getAppliedImpulseLateral1(id),
                   ManifoldPoints.getAppliedImpulseLateral2(id)) / dt;

    LoadEnvelope env = envelopeFor(id);                       // §6.2，仅部件侧使用
    env.integrate(fn, dt);
    float rated     = hitBox.effectiveLoadRating(subPart, env.slow());   // N，§5.1
    float overloadN = Math.max(0f, env.fast() - rated);
    float overloadT = Math.max(0f, ft - hitBox.shearRatio() * rated);
    float dmg       = (hitBox.loadDamageN() * overloadN
                     + hitBox.loadDamageT() * overloadT) * dt;           // HP
    if (dmg > 1e-4f) pendingDamage.accumulate(subPart, hitBox, dmg, contactVel, normal, point);
}
```

两点注意：

- 方块侧在部件侧**之前**执行。这不是风格问题：它在被摧毁时写 `setDistance1`，而该写入必须在同一次回调里、同一个接触点上完成。
- `momentumMassFor` 在首次接触时用回退质量，之后用 $\hat m_c$（由 $J_{\text{ap}}$ 学得）——两者的切换对判据是连续的。

命中判定被摧毁的方块时（`terrain.isRemoved(pos)`）的提前返回、攀爬辅助分支、Create 地形分支全部保持现状——它们与伤害口径无关。

| 常数 | 含义 | 建议起点 |
| --- | --- | --- |
| $\tau_f$ | 冲击峰值保持时间 | 0.05 s |
| $\tau_s$ | 准静态基线时间常数 | 0.5 s |
| $\tau_m$ | 接触有效质量估计 $\hat m_c$ 的 EMA 时间常数 | $\tau_s$ 量级 |
| $\kappa$ | 缺省额定载荷 = κ × 静载 | 3.0 |
| $\kappa_0$ | 额定载荷下限 = κ₀ × 零件自重 | 5.0 |
| $\mu_{\text{rated}}$ | 切向额定比例 | 0.6 |
| $\gamma$ | 过载指数 | 1.0 |
| $k_\perp, k_\parallel$ | 单位过载的伤害率 | 由 §8 目标反解 |
| $S$ | 方块强度（N） | 由 §6.4 的（载具级别 × 方块类别）目标速度反解，可从石头/泥土/树叶三格起步 |
| $k_{\text{block}}$ 取值域 | 接触压强集中系数 | 重新标定到 0.2~1.0 |

### 6.7 保留护甲分配比时的能量口径

若决定连 §6.3 的载荷判据也暂缓、先只修 $E_c$（阶段 2 的范围），分配比保持不变；$E_c$ 则采用一个**不虚构质量**的写法。标准形式是这一步接触点真正耗散掉的功：

$$
E_{\text{diss}} = \tfrac12\, J_{\text{ap}}\,\Delta v_n,
\qquad
\Delta v_n = v_n^{\text{(prev)}} - v_n^{\text{(now)}}
$$

$J_{\text{ap}}$ 含正确的有效质量，$\Delta v_n$ 是这一步被求解器消除掉的法向相对速度，量纲为 J。

> **$J$ 与 $v_n$ 必须来自同一步。** §1.3 的时序意味着 $J_{\text{ap}}$ 读到的是**上一步**的冲量，所以 $\Delta v_n$ 也要用上一步缓存的 $v_n$ 来算（每个接触点缓存一个 float 即可）。若图省事写成"上一步的 $J$ × 当前的 $v_n$"，在持续接触里当前的 $v_n$ 已被求解器压到接近 0，结果会趋近 0；而在首接触步 $J = 0$，也同样为 0——两头都错。
>
> 近似形式 $\tfrac12 J_{\text{ap}} v_n^{\text{(prev)}}$ 在接近速度远大于分离速度时可用，省掉一次缓存差分。

它与 §1.3 的差别不是系数，而是**量级**——两个算例（$v_n = 12\ \mathrm{m/s}$ 撞墙）：

| 载具 | 现在 $v_{\text{eff}}$ | 现在 $E_c$/点 | $E_{\text{diss}}$/点 | 比值 |
| --- | --- | --- | --- | --- |
| kluo / wine_fox | 57.5 m/s | 120 kJ | 4.1 kJ | **29×** |
| SDKFZ234 | 85.1 m/s | 3.45 MJ | 21.9 kJ | **157×** |

（$J_{\text{ap}}$ 取整车总冲量 $M(1+e)v_n$ 按接触点数均摊：kluo $700\times1.3\times12/16 = 683$ N·s，SDKFZ234 $7500\times1.3\times12/32 = 3656$ N·s；$E_c$ 已含 $(1-e)$ 因子，$e$ 分别取 0.585 与 0.54。）

**所以这一步不是"调参"，是"重新标定"**：$E_c$ 会掉 29~157 倍（1.5~2.2 个数量级），`0.2×0.33/250` 这个换算系数与 `modifyDamage(...) > 1` 的绝对门槛都必须同步重解，否则修完之后会变成"怎么撞都不坏"。这也正好是 D4 的解法：把绝对门槛换成按零件规模缩放的相对门槛（例如 `0.5% × maxDurability`，轮胎 100 耐久 → 0.5 HP，装甲板 2000 耐久 → 10 HP），门槛随零件规格走，质量的单边依赖就消失了。

## 7. 数据字段

`MaterialAttr.PhysicsAttr` 引入（JSON 字段名沿用现有 snake_case 风格）：

```json
"physics": {
  "load_rating": null,            // N，可选；null = 按 κ×静载自动定标
  "load_damage_normal": 0.0,      // HP/(N·s)，法向过载损伤系数
  "load_damage_shear": 0.0,       // HP/(N·s)，切向过载损伤系数
  "shear_ratio": 0.6              // 切向额定比例
}
```

`HitBoxAttr` 增加可选的部位级覆盖 `load_rating_multiplier`。

**职责重新划分**：

| 字段 | 职责 |
| --- | --- |
| `rha` / `thickness` / `decay_rha` | 抗弹（投射物穿甲）；在碰撞路径上作为能量分配比 $A_p$ 与额定载荷 $F_{\text{rated}}$ 的来源，不接受"为改碰撞手感而调它" |
| `dmg_resist` / `dmg_mult` / `damage_modifiers` | 对所有伤害源生效的最终减伤；碰撞仍走这条（内容包继续可用） |
| `unpen_power` | 未击穿钝伤指数。碰撞在语义上是钝击，因此**这是碰撞伤害的落点**：设为 ≥ 1 的材料才能吃到碰撞伤害，设为 0 则被 `resolvePenetration` 一票否决（§6.3） |
| `block_damage_factor` | 接触压强/形状集中系数，只作用方块侧 |
| `load_rating` / `load_damage_*` / `shear_ratio` | 碰撞载荷判定 |

`off_road_tire` 与 `normal_tire` 的 `damage_modifiers` 对 `c:is_impact` 施加 `×0.1 / −2.0`，作用是把碰撞类伤害压到接近零。改走载荷判定后，这组修饰符与 `load_rating` 职责重叠，保留与否属于配平选择。

## 9. 分阶段落地

模型替换不必一次到位。下表按"改动局部性"排序，每步独立可验证，且**每一步都不触碰 C1、C2 两条约束**：

| 阶段 | 内容 | 收益 | 是否需重新标定 |
| --- | --- | --- | --- |
| **0** | 把 `applyBlockDamage` 的公式抽成纯函数 + 调试命令 | 获得可测的响应面，后续每一步都能对比 | — |
| **1** | 给碰撞一个语义正确的 `penetration`，并把 `normal_tire` / `off_road_tire` 的 `unpen_power` 设为 ≥ 1 | 消除 D5 的"伤害开关"那一半：碰撞伤害的落地与 `rha` 无关，修轮胎问题因此不必抬护甲，§2.3 的连带副作用随之消失 | 需要（伤害口径变了） |
| **2** | $E_c$ 采用 §6.7 的 $E_{\text{diss}} = \tfrac12 J_{\text{ap}}\Delta v_n$（同步缓存上一步的 $v_n$）；绝对门槛改为按 `maxDurability` 缩放的相对门槛；统一 $(1-e)\to(1-e^2)$ | 消除 D1、D3、D4、D7。**这是解决"重车轮胎异常易损"的核心一步** | 必须，见 §6.7 |
| **3** | $m_{\text{eq}}$ 与 $J/m_{\text{part}}$ 全部下线，改由 §6.2 的载荷包络给出判据；引入 $F_{\text{rated}}$ | 消除 D2、D6，护甲从"吸能份额"迁移到"额定载荷"（§5.1） | 必须 |
| **4** | 方块侧改为"求解前量 + 强度阈值"判定（§6.4） | 方块破坏与部件护甲彻底脱钩，满足 G3；摧毁与禁用接触同步生效，脆弱方块不挡车 | 必须（$S$ 与 $k_{\text{block}}$ 重标） |
| **5** | 每 tick 聚合结算，对齐爆炸系统的施加纪律 | 性能与一致性；调用次数降两个数量级 | 否 |

两点顺序上的提醒：

- **阶段 1 应当先于阶段 2。** 它本身就会改变伤害口径，但它同时把"伤害开关"拆掉；如果先做阶段 2，$E_c$ 掉 1.5~2.2 个数量级后 $D_{\text{raw}} > A_p$ 会立刻不成立，所有碰撞伤害被穿甲门槛吃掉，看起来像"修坏了"。
- **阶段 2 不是调参，是重新标定。** 它会让碰撞伤害整体下移 1.5~2.2 个数量级（§6.7），换算系数与门槛必须一起重解。建议在阶段 0 的响应面工具上先离线跑完，再进游戏。
- 阶段 3、4 可以互换或并行；它们互不依赖。
