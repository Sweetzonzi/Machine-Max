# 动画系统-事件触发动画设计

> **状态**：已落地第一版接口 + 备忘  
> **日期**：2026-09-02  
> **范围**：载具零件（SubPart）的事件触发动画，聚焦"为零件播放一次指定名称的动画"。  
> **源码依赖**：Spark-Core（动画/状态机底层）、Machine-Max（SubPart 动画接口）。

---

## 1. 动机

载具火炮开火时，早期做法是让炮管作为**独立零件刚体**自行后座。对大口径主炮这是有意义的物理行为（会带动平台、需要后座机构），但对机炮/机枪等小口径武器属于**过度设计**——物理冲量极小的同时，却引入了关节扰动、瞄准抖动，以及"多线程物理 + 关节 = 崩溃"的既有红线。

业界通常做法是用**骨骼动画**表现后座。问题在于：如何让动画与现有系统结合、并支持 UGC（一个零件可能包含多种武器，如 k17 炮塔的 2A42 机炮 + MG 机枪两门发射器共用 `sub_part.machine_max.gun`）。

## 2. 目标与非目标

**目标**：为 SubPart 提供"按名称播放一次性动画"的接口，供事件（开火、受击、落地等）触发；并厘清 Spark-Core 动画体系如何承载"持续动画"与"事件动画"。

**非目标（本期）**：接入发射器触发位；服务端→客户端动画事件网络包；通用"事件→动画"总线；`.animation_controllers.json` 在内容包中的落地。

## 3. 核心结论（源自 Spark-Core 源码）

### 3.1 循环与否由动画自身的 `loop` 设置决定

`Loop`（[Loop.kt](../Spark-Core/src/main/kotlin/cn/solarmoon/spark_core/animation/anim/origin/Loop.kt)）为三态：

```kotlin
enum Loop { ONCE, HOLD_ON_LAST_FRAME, TRUE }
```

- `loop:false` → `ONCE`。在 [AnimInstance.physTick](../Spark-Core/src/main/kotlin/cn/solarmoon/spark_core/animation/anim/AnimInstance.kt#L241-L261) 中：推进到 `maxLength` 后触发 `Finish → exit → idle`，再由 [AnimLayer.physicsTick](../Spark-Core/src/main/kotlin/cn/solarmoon/spark_core/animation/anim/AnimLayer.kt#L89-L98) 的 `removeIf { it.state == IDLE }` **移除**。即：一次性动画播完自停，无需引擎代码管理。
- **重要**：动画若未写 `loop` 字段，[CODEC 缺省即 `Loop.ONCE`](../Spark-Core/src/main/kotlin/cn/solarmoon/spark_core/animation/anim/origin/OAnimation.kt#L51)——内容包作者不写 `loop` 就是一次性动画。

### 3.2 分层混合，事件动画可与 parallel 共存

[AnimController.layers](../Spark-Core/src/main/kotlin/cn/solarmoon/spark_core/animation/anim/AnimController.kt#L37) 是 `SortedMap<Int, AnimLayer>`，每层有 `blendMode`（OVERRIDE / ADDITIVE），按骨混合。

[AnimGroups](../Spark-Core/src/main/kotlin/cn/solarmoon/spark_core/animation/anim/AnimGroups.kt#L12-L26) 层优先级（按 key 升序遍历，值越大优先级越高）：

```
AMBIENT(1) → LOCOMOTION(2) → POSTURE(4) → ACTION(8) → OVERRIDE(16)
```

parallel 常驻动画默认落在 `POSTURE` 层；事件动画应落到更高优先级层（如 `ACTION`），从而与常态动画按骨混合、互不干扰。

### 3.3 动画控制器（`animation_controllers`）为原生能力

- `AnimController.stateMachines`（[AnimController.kt#L39](../Spark-Core/src/main/kotlin/cn/solarmoon/spark_core/animation/anim/AnimController.kt#L39)）由 `OAnimStateMachineSet` 构建，`tick()` 每帧 `progress()`。
- 状态转移条件用 `MoLangCondition`（[MoLangCondition.kt](../Spark-Core/src/main/kotlin/cn/solarmoon/spark_core/state_machine/graph/conditions/MoLangCondition.kt)）——即 **Molang 表达式**（可读 `subpart.get(...)`、`q.anim_time`）。
- 进入状态动作 `PlayAnimAction`（[PlayAnimAction.kt](../Spark-Core/src/main/kotlin/cn/solarmoon/spark_core/state_machine/graph/actions/PlayAnimAction.kt)）播放指定 clip；另有 `StopAnimAction` / `SoundAction` / `ParticleAction` / `MoLangAction`。
- 事件机制：`StateGraphController` 提供 `triggerEvent(String)` 与父级优先递归的 **`broadcastEvent(String)`**（见 [sub_state_machine_event_broadcast_plan.md](../Spark-Core/docs/sub_state_machine_event_broadcast_plan.md)）。

> **约定**：Machine-Max 内容包当前**尚未**使用 `.animation_controllers.json`（已确认无）。控制器能力在，但未接通。

## 4. 动画分类与触发方式

事件动画按"持续性"分为两类，对应不同触发机制：

```mermaid
flowchart TB
  subgraph 持续/条件型["持续 / 条件型（信号系统擅长：持续的变化量）"]
    A1[连射抖动 loop:true]
    A2[装填过程 loop:true]
    A3[舱门/起落架开启]
    A4[触发方式: 动画控制器 `animation_controllers` + MoLang 条件<br/>读 `subpart.get('state.*')` 这类 level 信号]
  end
  subgraph 瞬发一次性["瞬发一次性（命令式播放）"]
    B1[单发后座 kick loop:false]
    B2[受击硬直 loop:false]
    B3[落地震动 loop:false]
    B4[触发方式: SubPart.playAnim(animName)<br/>loop:false 播完自停，无需信号/状态机/衰减]
  end
```

### 4.1 关键取舍

- **瞬发事件 ≠ 放进信号系统**。早期考虑过"把事件写成 `signalStorage` 置 1 再衰减"的 hack，被否决。原因：信号系统（`subpart.get(...)`）语义上是**持续的量**（如 `engine_speed`、`connector_offset`），把离散事件伪装成衰减标量会把"发生了什么事"与"当前标量多大"混为一谈，还需自建衰减器。瞬发事件应走**命令式触发**。
- **"parallel"不是 Spark-Core 硬分类**，而是内容作者的命名/意图约定（`parallel0/1...` 代表常态持续集）。真正的分界是 `loop` + 是否走状态机。

## 5. 已落地的接口

### 5.1 `SubPart.playAnim(String animName)`

文件：[SubPart.java](../Machine-Max/src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/SubPart.java)（位于 `getBones()` 之后）。

```java
/**
 * 播放指定名称的动画（仅客户端）。
 * 动画取自零件变体自身的动画集（{@code part.variant.getAnimations()}），按名称查找。
 * 循环行为由动画自身的 loop 设置决定：缺省（未写 loop）为 ONCE 一次性，播完自停；写 loop:true 则持续循环。
 * 播放于 AnimGroups.ACTION 动作覆盖层，位于 parallel 常驻的 POSTURE 层之上，可与常态动画按骨混合、互不干扰；
 * 连发重触发时先停本层再进入，确保从 0 重启不叠堆。
 * 调用线程：客户端主线程（20tps）。
 *
 * @param animName 动画名（对应 variant 动画集中的键，例如 "recoil_2a42"）
 */
public void playAnim(String animName) {
    if (!level.isClientSide()) return;
    ModelIndex index = new ModelIndex("part", part.variant.getAnimations());
    OAnimationSet set = OAnimationSet.getOrEmpty(index);
    if (!set.hasAnimation(animName)) {
        MachineMax.LOGGER.warn("[SubPart {}-{}] 未找到动画 {}", part.name, name, animName);
        return;
    }
    AnimInstance instance = new AnimInstance(this, new AnimIndex(index, animName));
    instance.setGroup(AnimGroups.ACTION);
    instance.independentEnter();
}
```

要点：
- 动画路径不传参，直接用 `part.variant.getAnimations()`（变体自带）。
- 播放层 `AnimGroups.ACTION`（"动作覆盖"，语义贴合开火/后座；优先级高于 parallel 的 POSTURE）。
- `independentEnter()` = 先 `stopAnimation(group)` 再 `enter()`，保证连发同名动画从 0 重启、不叠堆。
- 仅客户端；未知名 `warn` 后静默返回，便于内容包排错。

### 5.2 `postTick` 只自动播放 `loop:true`

文件：[SubPart.java](../Machine-Max/src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/SubPart.java) `postTick()`。

原有逻辑在空闲时会把动画集**全部** `enter()` 一次。现只自动播放持续动画（`loop:true`），一次性事件动画交由 `playAnim` 按名触发，避免零件刚出现就被预播一次（意外后座）。

```java
for (Map.Entry<String, OAnimation> entry : animSet.getAnimations().entrySet()) {
    if (entry.getValue().getLoop() != Loop.TRUE) continue;   // 仅自动播放持续动画
    ...
}
```

### 5.3 验证

`.\gradlew.bat compileJava` → `BUILD SUCCESSFUL`。`AnimGroups.ACTION`、`OAnimationSet.getOrEmpty/hasAnimation`、`AnimInstance.setGroup/independentEnter`、`OAnimation.getLoop()`、`Loop.TRUE` 均编译通过。

## 6. 后续待办（未实现）

1. **发射器触发位**：在 `LauncherSubsystem` 客户端开火路径（`onTick` 客户端分支，已有 `firedTypes`/burst 快照）调用 `getSubPart().playAnim(animName)`，`animName` 由发射器静态属性数据驱动（如 `fire_animation: "机器:clip名"`）。
2. **服务端→客户端事件包**：受击、落地等服务端观测事件需一条轻量客户端包（`subpartId + animName`），客户端调用 `playAnim`。开火客户端已知，无需包。
3. **重触发粒度**：当前 `independentEnter()` 停整层（ACTION）。若同一 subpart 需同时播放两个不同事件动画（后座 + 炮口焰），需改为"按名称精确退出旧实例"或按事件拆分图层。
4. **内容包升级到动画控制器**：如需"持续/条件性"动画（装填、舱门），可接入 `.animation_controllers.json`（Spark-Core 原生，含 MoLang 条件、事件广播）；届时再定义 `state.*` 语义约定。
