# Machine-Max 武器系统 — 数据驱动投射物设计文档

> 状态：计划阶段（尚未实现）
> 创建时间：2026-05-14，最后修订 2026-05-14
> 相关项目：BallisticsFramework（终点弹道协议依赖）

## 一、项目定位与设计目标

Machine-Max 现有的载具系统已具备完善的零件定义、子系统集成和物理模拟能力，但缺乏武器发射能力。当前 `LauncherSubsystem` 仅能发射原版 Arrow 实体，无法满足载具间弹道对抗的需求。

本设计的核心目标是为 Machine-Max 引入一套**数据驱动的投射物系统**，使得内容包创作者可以通过 JSON 定义投射物的全部弹道参数，而无需编写任何 Java 代码。投射物与 BallisticsFramework 的终点弹道协议深度集成，使用幂函数（德马尔式）速度-伤害模型计算穿深和伤害。

### 设计原则

1. **数据驱动优先**：类似现有的零件定义系统（`PartType` + `SparkPackModule`），投射物参数完全通过 JSON 定义，由 `ProjectileModule` 加载至 `MMDynamicRes` 全局存储
2. **质点/刚体双轨制**：轻小的高速投射物采用无物理刚体的质点模型（配合 SoA 数据布局追求高缓存命中率）；大型低速投射物采用有实际碰撞体积的刚体模型（`PhysicsRigidBody`），可被拦截
3. **复用现有基础设施**：继承 `DestroyableObject` / `DestroyableRigidObject`，并覆写摧毁倒计时相关方法（投射物命中即消失）；融入 `ObjectManager` 的生命周期管理
4. **协议化伤害**：通过构造 `BFDamageContext` 发起 BallisticsFramework 协议伤害，穿透护甲判定管线和回调
5. **阶段一聚焦纯动能**：暂不引入引信、战斗部等概念，投射物命中即消失（调用 `dealDamage` 后 `destroy`）

### 3.1 继承与接口关系

```

├── ✔ 覆写 setDestroyed() — 跳过摧毁倒计时
├── ✔ 覆写 tickDestroyTimer() — 空操作
├── ✔ 覆写 handleAccumulatedDamage() — 空操作
├── ✔ 覆写 postTick() — 跳过 syncToClient（仅关键事件同步）
```

### 3.2 DestroyableObject 继承的覆写策略

投射物继承 `DestroyableObject` / `DestroyableRigidObject` 主要复用其：
- 位置/速度/旋转的 `SynchedEntityData` 网络同步字段
- `addToLevel()` / `destroy()` 生命周期（自动注册/注销于 `ObjectManager.levelDestroyableObjects`）
- `getPosition()` / `setPosition()` / `getVelocity()` 等状态存取方法

**需要覆写的摧毁倒计时相关方法**：

| 方法 | 父类行为 | 覆写后行为 |
|------|---------|-----------|
| `checkDestroyed()` | `!DATA_DESTROYED && durability <= 0` | `!isDestroyed && (hasHit \|\| lifetime <= 0)` |
| `setDestroyed()` | 设置 `DESTROY_TIME` 倒计时 → `DATA_DESTROYED = true` | 仅 `DATA_DESTROYED = true`，不启动倒计时 |
| `tickDestroyTimer(int)` | 递减 `DESTROY_TIME` | 空操作（无倒计时） |
| `handleAccumulatedDamage()` | 由子类实现 | 空操作（投射物不被攻击，无耐久度消耗） |
| `accumulateDamage(float, ctx)` | 累积到伤害队列 | 空操作（同上，或保留记录但不响应） |

对刚性投射物额外需覆写：

| `postTick()` | 从刚体同步数据 + `syncToClient` | 不逐 tick 同步；仅检查 `isDestroyed()` → `destroy()` |

### 3.3 IProjectile 接口设计

```java
/**
 * 投射物公共接口。
 * <p>
 * 定义质点投射物(PointProjectile)和刚体投射物(RigidProjectile)共有的
 * 物理状态协议、弹道参数协议和速度-伤害模型。
 */
public interface IProjectile {

    // ========== 物理状态协议 ==========

    Vector3f getPosition();
    Vector3f getVelocity();
    Vector3f getFrontVector();

    default float getSpeed() {
        return getVelocity().length();
    }

    default Vector3f getDirection() {
        Vector3f vel = getVelocity();
        if (vel.lengthSquared() < 1e-12f) return getFrontVector();
        return vel.normalize();
    }

    // ========== 弹道参数协议 ==========

    ProjectileType getProjectileType();

    default float getMass()            { return getProjectileType().getMass(); }
    default float getGravityFactor()   { return getProjectileType().getGravityFactor(); }
    default float getDragFactor()      { return getProjectileType().getDragFactor(); }
    default float getBaseVelocity()    { return getProjectileType().getBaseVelocity(); }
    default float getBasePenetration() { return getProjectileType().getBasePenetration(); }
    default float getBaseDamage()      { return getProjectileType().getBaseDamage(); }
    default float getBaseAccuracyMil() { return getProjectileType().getBaseAccuracyMil(); }
    default float getPenetrationVelocityCoefficient() {
        return getProjectileType().getPenetrationVelocityCoefficient();
    }
    default float getDamageVelocityCoefficient() {
        return getProjectileType().getDamageVelocityCoefficient();
    }
    default float getRadius()          { return getProjectileType().getRadius(); }

    // ========== 生命周期 ==========

    boolean isAlive();
    int getLifetime();
    int getMaxLifetime();
    void markHit();

    // ========== 速度-伤害模型 ==========

    /**
     * 计算当前速度下的有效穿深 (mm RHA)。
     * 公式: effective = basePenetration × (speed / baseVelocity)^coefficient
     */
    default float calculateCurrentPenetration() {
        float coeff = getPenetrationVelocityCoefficient();
        if (Math.abs(coeff) < 1e-6f) return getBasePenetration();
        float baseV = Math.max(getBaseVelocity(), 1e-6f);
        return getBasePenetration() * (float) Math.pow(getSpeed() / baseV, coeff);
    }

    /**
     * 计算当前速度下的有效伤害值。
     * 公式: effective = baseDamage × (speed / baseVelocity)^coefficient
     */
    default float calculateCurrentDamage() {
        float coeff = getDamageVelocityCoefficient();
        if (Math.abs(coeff) < 1e-6f) return getBaseDamage();
        float baseV = Math.max(getBaseVelocity(), 1e-6f);
        return getBaseDamage() * (float) Math.pow(getSpeed() / baseV, coeff);
    }

    // ========== 便捷方法（阶段一） ==========

    /**
     * 向 BFHurtTarget 直接发起协议伤害。
     * <p>
     * 由于 DestroyableObject 自身实现了 BFHurtTarget，
     * 命中 SubPart 时可直接以 subPart 作为 target 调用 BFDamageApi.hurt()，
     * BallisticsFramework 将自动走 SubPart → getArmorLevel/getRHA/resolvePenetration 管线。
     * <p>
     * 使用 generic() DamageSource，阶段一暂不追踪发射者。
     *
     * @param target    协议伤害目标（SubPart / Entity 等 BFHurtTarget 实现）
     * @param hitPoint  命中点世界坐标 (MC Vec3)
     * @param hitNormal 命中面法线 (MC Vec3)
     * @return 实际造成的伤害量
     */
    default float dealDamage(BFHurtTarget target, Vec3 hitPoint, Vec3 hitNormal) {
        BFDamageContext ctx = BFDamageContext.builder()
            .source(target.getBFEntity() != null
                ? target.getBFEntity().damageSources().generic()
                : new DamageSource(...))  // 阶段一暂用 generic
            .baseDamage(calculateCurrentDamage())
            .penetration(calculateCurrentPenetration())
            .hitVelocity(PhysicsHelperKt.toVec3(getVelocity()))
            .hitPoint(hitPoint)
            .hitNormal(hitNormal)
            .build();
        return BFDamageApi.hurt(target, ctx);
    }
}
```

### 4.1 完整字段

```java
/**
 * 投射物类型数据定义。
 * 对应一个 projectiles/*.json 文件，使用 Mojang Codec 从 JSON 反序列化。
 */
public class ProjectileType {

    private final String type;       // "point" 或 "rigid"
    private final float mass;        // 质量 (kg)
    private final float gravityFactor;  // 重力系数，默认 1.0
    private final float dragFactor;  // 空气阻力系数（速度平方阻力），默认 0
    private final float radius;      // 碰撞半径 (m)，默认 0.05

    private final float baseVelocity;       // 参考速度 (m/s)
    private final float basePenetration;    // 参考速度下穿深 (mm RHA)
    private final float baseDamage;         // 参考速度下伤害值
    private final float baseAccuracyMil;    // 基础精度（密位/千分弧度），默认 5.0

    private final float penetrationVelocityCoefficient; // 默认 0
    private final float damageVelocityCoefficient;      // 默认 0

    private final int maxLifetimeTicks;     // 默认 200

    @Setter
    private ResourceLocation registryKey;   // 加载时赋值，作为全局查询 key

    public static final Codec<ProjectileType> CODEC = RecordCodecBuilder.create(instance -> instance.group(
        Codec.STRING.fieldOf("type").forGetter(ProjectileType::getType),
        Codec.FLOAT.fieldOf("mass").forGetter(ProjectileType::getMass),
        Codec.FLOAT.optionalFieldOf("gravity_factor", 1.0f).forGetter(ProjectileType::getGravityFactor),
        Codec.FLOAT.optionalFieldOf("drag_factor", 0f).forGetter(ProjectileType::getDragFactor),
        Codec.FLOAT.optionalFieldOf("radius", 0.05f).forGetter(ProjectileType::getRadius),
        Codec.FLOAT.fieldOf("base_velocity").forGetter(ProjectileType::getBaseVelocity),
        Codec.FLOAT.fieldOf("base_penetration").forGetter(ProjectileType::getBasePenetration),
        Codec.FLOAT.fieldOf("base_damage").forGetter(ProjectileType::getBaseDamage),
        Codec.FLOAT.optionalFieldOf("base_accuracy_mil", 5.0f)
            .forGetter(ProjectileType::getBaseAccuracyMil),
        Codec.FLOAT.optionalFieldOf("penetration_velocity_coefficient", 0f)
            .forGetter(ProjectileType::getPenetrationVelocityCoefficient),
        Codec.FLOAT.optionalFieldOf("damage_velocity_coefficient", 0f)
            .forGetter(ProjectileType::getDamageVelocityCoefficient),
        Codec.INT.optionalFieldOf("max_lifetime_ticks", 200)
            .forGetter(ProjectileType::getMaxLifetimeTicks)
    ).apply(instance, ProjectileType::new));

    public static ProjectileType get(Level level, ResourceLocation key) {
        return level.isClientSide
            ? MMDynamicRes.PROJECTILE_TYPES.get(key)
            : MMDynamicRes.SERVER_PROJECTILE_TYPES.get(key);
    }
}
```

## 五、速度-伤害模型

### 5.1 公式

```
effective_penetration = base_penetration × (current_speed / base_velocity)^penetration_velocity_coefficient
effective_damage      = base_damage      × (current_speed / base_velocity)^damage_velocity_coefficient
```

### 5.2 系数语义

| 系数值 | 语义 | 物理含义 |
|--------|------|---------|
| 0 | 与速度无关 | 恒为基准值（如定型装药破甲弹） |
| > 0 | 正相关 | 速度越高穿深/伤害越大（动能穿甲弹） |
| < 0 | 负相关 | 速度越快反而越低（存在最佳速度窗口） |
| ~1.43 | 经典德马尔 | 穿深 ∝ v^1.43 |

### 5.3 注意事项

- 穿深计算在构造 `BFDamageContext` 前完成
- 角度效应（斜穿）暂不纳入阶段一
- 速度趋近 0 时有效穿深/伤害趋近 0

## 六、质点投射物 (PointProjectile)

### 6.1 设计动机

适用于小口径穿甲弹、APFSDS 长杆弹等极快速、现实中无法被拦截的投射物。不需要 `PhysicsRigidBody`，避免了 Bullet 碰撞体管理和约束解算开销。

### 6.2 SoA 数据布局（在 ProjectileManager 中）

虽然 `PointProjectile` 也注册在 `ObjectManager.levelDestroyableObjects` 中（复用生命周期和网络同步基础），但其物理更新的核心数据以 SoA 方式存放在 `ProjectileManager`：

```
float[] pointPosX[i]       ← 世界坐标 X (JME)
float[] pointPosY[i]       ← 世界坐标 Y
float[] pointPosZ[i]       ← 世界坐标 Z
float[] pointVelX[i]       ← 速度 X (m/s)
float[] pointVelY[i]       ← 速度 Y
float[] pointVelZ[i]       ← 速度 Z
int[]   pointLifetime[i]   ← 剩余存活 tick
int[]   pointTypeIndex[i]  ← 投射物类型索引（查 ProjectileType 表）
int[]   pointObjId[i]      ← 对应的 DestroyableObject ID（用于回写命中状态）
boolean[] pointAlive[i]    ← 活跃标志
int     pointCount         ← 当前活跃总数
```

- 初始分配 256 容量，动态扩容时 ×2
- 移除时使用 swap-with-last 策略（O(1)）

### 6.3 碰撞检测：使用 JME PhysicsWorld.rayTest

**不使用 Minecraft 的 `ClipContext`**。参照 [LivingEntityEyesightAttachment](file:///d:/Files/Project_MinecraftMods/Machine-Max/src/main/java/io/github/sweetzonzi/machine_max/common/attachment/LivingEntityEyesightAttachment.java) 的模式，使用 JME 物理引擎的射线检测：

```java
// 在 ProjectileManager.updatePointProjectiles() 中，每个物理步对每个活跃质点：
PhysicsLevel physicsLevel = SparkLevel.getPhysicsLevel(level);
PhysicsWorld world = physicsLevel.getWorld();

Vector3f prevPos = new Vector3f(pointPosX[i], pointPosY[i], pointPosZ[i]);
Vector3f currPos = prevPos.add(
    new Vector3f(pointVelX[i], pointVelY[i], pointVelZ[i]).multLocal(timeStep));

// JME 物理射线检测
List<PhysicsRayTestResult> results = world.rayTest(prevPos, currPos);

for (PhysicsRayTestResult result : results) {
    PhysicsCollisionObject obj = result.getCollisionObject();
    if (!(obj instanceof PhysicsRigidBody body)) continue;

    Object owner = PhysicsBodyExtensionKt.getOwner(body);
    if (owner == null) {
        // 命中地形碰撞体 → 仅视觉特效（火花粒子）
        spawnTerrainHitEffect(hitPoint);
        pointAlive[i] = false;
        break;
    }

    // 判断命中类型：
    //   1) owner instanceof BFHurtTarget（如 SubPart 自身即是）
    //      → 获取 HitBox，检查是否活跃
    //      → 直接 dealDamage((BFHurtTarget) owner, ...)
    //   2) owner instanceof Entity（实现了 BFHurtTarget 的原版实体）
    //      → 直接 dealDamage((BFHurtTarget) entity, ...)

    // 获取命中点坐标（参照 Eyesight: startPos + view * hitFraction）
    Vector3f hitPoint = prevPos.add(currPos.subtract(prevPos).mult(result.getHitFraction()));
    Vector3f hitNormal = result.getHitNormalLocal(); // 或从 body 获取面法线

    // 发起协议伤害（传入 Entity 引用）
    // ...
    pointAlive[i] = false;
    break; // 命中第一个目标后停止
}
```

**命中后的处理流程**：

1. 通过 JME rayTest 检测到命中 → 获取 `physicsBody.getOwner()`
2. 判断 owner 类型并直接发起协议伤害：
   - `owner instanceof BFHurtTarget`（如 SubPart）→ 直接调用 `dealDamage((BFHurtTarget) owner, hitPoint, hitNormal)`，BallisticsFramework 自动走穿甲管线
   - `owner instanceof Entity`（实现了 BFHurtTarget 的实体）→ 同理直接传入
   - `owner == null` → 命中地形碰撞体，仅产生视觉特效（火花粒子），不造成伤害
3. 触发命中视觉效果（见第十一节）
4. 服务端标记投射物已命中 → 广播命中包
5. 投射物 self-destruct

### 6.4 每物理步更新流程

```
for i in 0..pointCount:
    if !pointAlive[i]: continue

    // 1) 半隐式 Euler 积分
    speed = |vel[i]|
    gravityAcc = (0, -gravityFactor × 9.81, 0)
    dragForce = dragFactor × speed²
    dragAcc = dragForce / mass × normalize(-vel[i])
    vel[i] += (gravityAcc + dragAcc) × dt
    prevPos = pos[i]
    pos[i] += vel[i] × dt

    // 2) JME rayTest 碰撞检测（见 6.3）
    results = world.rayTest(prevPos, pos[i])
    if hit:
        → 触发命中视觉特效（服务端广播命中事件，客户端播放粒子/音效）
        → dealDamage → markHit → pointAlive[i] = false
        → 发送命中同步包

    // 3) 寿命检查
    pointLifetime[i]--
    if pointLifetime[i] <= 0:
        pointAlive[i] = false
        → 发送超时同步包

    // 4) （可选）末段效应：若未命中任何目标但击中方块，仅生成地形命中特效
```

### 6.5 网络同步策略

**不每 tick 同步**，仅关键事件时广播：

| 事件 | 同步内容 | 方向 |
|------|---------|------|
| 投射物创建 | 类型ID、初始位置、初始速度、寿命 | S→C |
| 投射物命中 | 投射物ID、命中点、命中目标 | S→C |
| 投射物超时 | 投射物ID | S→C |

客户端收到创建包后本地构造 `PointProjectile`，之后**完全由客户端自主外推仿真**，直到收到服务端的命中/超时包。

### 7.4 运动驱动

运动由 Bullet 引擎管理，空气阻力在 `prePhysicsTick()` 中手动施加：

```java
@Override
public void prePhysicsTick() {
    super.prePhysicsTick();
    if (isRemoved) return;

    float speed = body.getLinearVelocity(null).length();
    float dragForce = getDragFactor() * speed * speed;
    if (dragForce > 1e-6f) {
        Vector3f dragDir = body.getLinearVelocity(null).normalize().mult(-1);
        Vector3f dragAcc = dragDir.mult(dragForce / getMass());
        body.setLinearVelocity(body.getLinearVelocity(null)
            .add(dragAcc.mult(physicsTimeStep)));
    }
}
```

```java
        for (int i = 0; i < count; i++) {
            if (!alive[i]) continue;

            // 1. 积分
            // 2. rayTest 碰撞
            // 3. 寿命检查 → alive[i] = false → swapRemove(i)
        }
    }

    private void swapRemove(int index) {
        int last = count - 1;
        if (index != last) {
            // swap all arrays
        }
        count--;
    }

    private void ensureCapacity(int required) {
        if (required <= capacity) return;
```

### 8.3 tick 调度关系

```
LevelTickEvent.Pre
  → ObjectManager.onPreTick()
      → DestroyableObject.preTick() （含 Point/Rigid 的 lifetime -= 1）

PhysicsLevelTickEvent.Pre
  → ObjectManager.onPrePhysicsTick()
      → levelProjectileManagers[level].updatePointProjectiles(physicsLevel)

      → RigidProjectile.prePhysicsTick()  → 施加空气阻力
      → DestroyableObject.prePhysicsTick()

PhysicsLevelTickEvent.Post
  → ObjectManager.onPostPhysicsTick()
      → RigidProjectile 碰撞事件处理（通过 PhysicsCollisionListener）

LevelTickEvent.Post
  → ObjectManager.onPostTick()
      → 刚体投射物 postTick → isDestroyed ? destroy()
      → 关键事件网络同步
```

## 十、与 BallisticsFramework 的集成

### 10.1 伤害发起路径

```
投射物命中
  │
  ├─ 1. JME rayTest / 刚体碰撞 → 获取 owner
  │      ↓
  │   owner instanceof BFHurtTarget（SubPart / Entity 等）
  │      → 直接以此作为 target，无需二次映射
  │
  ├─ 2. 计算有效穿深/伤害
  │     pen = calculateCurrentPenetration()
  │     dmg = calculateCurrentDamage()
  │
  ├─ 3. 构造 BFDamageContext
  │     .source(DamageSources.generic())
  │     .baseDamage(dmg) .penetration(pen)
  │     .hitVelocity(vel) .hitPoint(hitPos) .hitNormal(hitNormal)
  │
  ├─ 4. BFDamageApi.hurt(target, ctx)
  │      │
  │      ├─ target 是 SubPart（继承 DestroyableObject 实现 BFHurtTarget）
  │      │    → getRHA / modifyPenetration / resolvePenetration
  │      │    → calculateFinalDamage → hurt → 伤害传递至 VehicleCore
  │      │
  │      ├─ target 是普通 Entity（实现了 BFHurtTarget）
  │      │    → 同上，走协议穿甲管线
  │      │
  │      └─ target 是普通 Entity（未实现 BFHurtTarget）
  │           → entity.hurt(source, baseDamage) 原版回退
  │
  └─ 5. 触发命中视觉效果（火花粒子 + 音效）
```

### 10.2 BFDamageContext 字段映射

| 字段 | 来源 |
|------|------|
| `source` | `target.getBFEntity().damageSources().generic()`（阶段一） |
| `baseDamage` | `calculateCurrentDamage()` |
| `penetration` | `calculateCurrentPenetration()` |
| `hitVelocity` | 当前速度（JME → MC Vec3，使用 PhysicsHelperKt） |
| `hitPoint` | rayTest.hitPoint / 刚体碰撞点（JME → MC Vec3） |
| `hitNormal` | rayTest.hitNormal / 碰撞接触法线 |
| `extensions` | 阶段一为空 |
| `handler` | 阶段一为 null |

### 10.3 目标类型与管线分发

| 命中目标 owner | target 参数 | BFDamageApi 路径 |
|---------------|------------|-----------------|
| `SubPart` | `subPart` 自身 | 分支1：BFHurtTarget → 穿甲管线（HitBox RHA 判定） |
| `Entity` (implements BFHurtTarget) | `entity` 自身 | 分支1：BFHurtTarget → 穿甲管线 |
| `Entity` (普通实体) | `entity` 自身 | 分支3：原版 `entity.hurt()` 回退 |
| `null` (地形碰撞体) | — | 仅视觉特效，不调用 hurt |

## 十三、设计决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 数据定义 | Spark Module 包机制 | 与 Part 系统一致 |
| 质点碰撞 | JME PhysicsWorld.rayTest | 与 `LivingEntityEyesightAttachment` 同模式，可命中物理刚体及其 owner |

## 十四、未决问题（后续讨论）

1. **发射者追踪**：当前使用 `target.getBFEntity().damageSources().generic()` 丢失了发射者信息。后续集成 `LauncherSubsystem` 时，需传递发射者（玩家或载具）到投射物构造时保存，用于击杀归属、仇恨系统和正确的 DamageSource 构建。

2. **BFHurtTarget 非 Entity 场景**：如果 `BFHurtTarget` 的 `getBFEntity()` 返回 null，无法构造 `DamageSource`。阶段一可以先 fallback 到某个全局静态 `DamageSource`，或要求所有投射物可命中目标必有有效 Entity 引用。

3. **视觉特效网络包**：`ProjectileHitEffectPayload` 需要定义并注册。命中位置/法线/类型（装甲 vs 地形）作为 payload 字段。

4. **精度系统的发射器叠加**：`base_accuracy_mil` 定义了投射物自身的 1σ 散步角。发射器（`LauncherSubsystem`）的 `horizontal_accuracy_multiplier` / `vertical_accuracy_multiplier` 需要与此叠加计算出最终散布椭圆。叠加公式待定（乘性？加性？）。
