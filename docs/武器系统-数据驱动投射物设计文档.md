# Machine-Max 武器系统 — 数据驱动投射物设计文档

> 状态：设计阶段（SOA 核心已实现，Entity 兼容层设计完成）
> 创建时间：2026-05-14，最后修订 2026-05-30
> 相关项目：BallisticsFramework（终点弹道协议依赖）

## 一、项目定位与设计目标

Machine-Max 现有的载具系统已具备完善的零件定义、子系统集成和物理模拟能力，但缺乏武器发射能力。当前 `LauncherSubsystem` 仅能发射原版 Snowball 实体（临时代码），无法满足载具间弹道对抗的需求。

本设计的核心目标是为 Machine-Max 引入一套**数据驱动的投射物系统**，使得内容包创作者可以通过 JSON 定义投射物的全部弹道参数，而无需编写任何 Java 代码。投射物与 BallisticsFramework 的终点弹道协议深度集成，使用幂函数（德马尔式）速度-伤害模型计算穿深和伤害。

### 设计原则

1. **数据驱动优先**：类似现有的零件定义系统（`PartType` + `SparkPackModule`），投射物参数完全通过 JSON 定义，由 `ProjectileModule` 加载至 `MMDynamicRes` 全局存储
2. **质点/刚体双轨制**：轻小的高速投射物采用无物理刚体的质点模型（配合 SoA 数据布局追求高缓存命中率）；大型低速投射物采用有实际碰撞体积的刚体模型（`PhysicsRigidBody`），可被拦截
3. **SOA 为主，Entity 为辅**：物理核心运行在 JME 物理世界（SoA 数组），不受 Minecraft 区块加载影响；同时创建轻量 `ProjectileEntity` 作为兼容层，使其他模组可识别为原版投射物，且支持按需创建/销毁以应对区块穿越
4. **复用现有基础设施**：继承 `DestroyableObject` / `DestroyableRigidObject`，并覆写摧毁倒计时相关方法（投射物命中即消失）；融入 `ObjectManager` 的生命周期管理
5. **协议化伤害**：通过构造 `BFDamageContext` 发起 BallisticsFramework 协议伤害，穿透护甲判定管线和回调
6. **阶段一聚焦纯动能**：暂不引入引信、战斗部等概念，投射物命中即消失（调用 `dealDamage` 后 `destroy`）

### 3.2 DestroyableObject 继承的覆写策略

投射物继承 `DestroyableObject` / `DestroyableRigidObject` 主要复用其：

- 位置/速度/旋转的 `SynchedEntityData` 网络同步字段
- `addToLevel()` / `destroy()` 生命周期（自动注册/注销于 `ObjectManager.levelDestroyableObjects`）
- `getPosition()` / `setPosition()` / `getVelocity()` 等状态存取方法

**需要覆写的摧毁倒计时相关方法**：

| 方法                             | 父类行为                                            | 覆写后行为                                         |
| ------------------------------ | ----------------------------------------------- | --------------------------------------------- |
| `checkDestroyed()`             | `!DATA_DESTROYED && durability <= 0`            | `!isDestroyed && (hasHit \|\| lifetime <= 0)` |
| `setDestroyed()`               | 设置 `DESTROY_TIME` 倒计时 → `DATA_DESTROYED = true` | 仅 `DATA_DESTROYED = true`，不启动倒计时              |
| `tickDestroyTimer(int)`        | 递减 `DESTROY_TIME`                               | 空操作（无倒计时）                                     |
| `handleAccumulatedDamage()`    | 由子类实现                                           | 空操作（投射物不被攻击，无耐久度消耗）                           |
| `accumulateDamage(float, ctx)` | 累积到伤害队列                                         | 空操作（同上，或保留记录但不响应）                             |

对刚性投射物额外需覆写：

\| `postTick()` | 从刚体同步数据 + `syncToClient` | 不逐 tick 同步；仅检查 `isDestroyed()` → `destroy()` |

### 3.3 IProjectile 接口设计

```java
/**
 * 投射物公共接口。
 * <p>
 * 定义质点投射物(PointProjectile)和刚体投射物(RigidProjectile)共有的
 * 物理状态协议、弹道参数协议和速度-伤害模型。
 */
public interface IProjectile {

    // ========== 物理状态协议 ==========

    Vector3f getPosition();
    Vector3f getVelocity();
    Vector3f getFrontVector();

    default float getSpeed() {
        return getVelocity().length();
    }

    default Vector3f getDirection() {
        Vector3f vel = getVelocity();
        if (vel.lengthSquared() < 1e-12f) return getFrontVector();
        return vel.normalize();
    }

    // ========== 弹道参数协议 ==========

    ProjectileType getProjectileType();

    default float getMass()            { return getProjectileType().getMass(); }
    default float getGravityFactor()   { return getProjectileType().getGravityFactor(); }
    default float getDragFactor()      { return getProjectileType().getDragFactor(); }
    default float getBaseVelocity()    { return getProjectileType().getBaseVelocity(); }
    default float getBasePenetration() { return getProjectileType().getBasePenetration(); }
    default float getBaseDamage()      { return getProjectileType().getBaseDamage(); }
    default float getBaseAccuracyMil() { return getProjectileType().getBaseAccuracyMil(); }
    default float getPenetrationVelocityCoefficient() {
        return getProjectileType().getPenetrationVelocityCoefficient();
    }
    default float getDamageVelocityCoefficient() {
        return getProjectileType().getDamageVelocityCoefficient();
    }
    default float getRadius()          { return getProjectileType().getRadius(); }

    // ========== 生命周期 ==========

    boolean isAlive();
    int getLifetime();
    int getMaxLifetime();
    void markHit();

    // ========== 速度-伤害模型 ==========

    /**
     * 计算当前速度下的有效穿深 (mm RHA)。
     * 公式: effective = basePenetration × (speed / baseVelocity)^coefficient
     */
    default float calculateCurrentPenetration() {
        float coeff = getPenetrationVelocityCoefficient();
        if (Math.abs(coeff) < 1e-6f) return getBasePenetration();
        float baseV = Math.max(getBaseVelocity(), 1e-6f);
        return getBasePenetration() * (float) Math.pow(getSpeed() / baseV, coeff);
    }

    /**
     * 计算当前速度下的有效伤害值。
     * 公式: effective = baseDamage × (speed / baseVelocity)^coefficient
     */
    default float calculateCurrentDamage() {
        float coeff = getDamageVelocityCoefficient();
        if (Math.abs(coeff) < 1e-6f) return getBaseDamage();
        float baseV = Math.max(getBaseVelocity(), 1e-6f);
        return getBaseDamage() * (float) Math.pow(getSpeed() / baseV, coeff);
    }

    // ========== 便捷方法（阶段一） ==========

    /**
     * 向 BFHurtTarget 直接发起协议伤害。
     * <p>
     * 由于 DestroyableObject 自身实现了 BFHurtTarget，
     * 命中 SubPart 时可直接以 subPart 作为 target 调用 BFDamageApi.hurt()，
     * BallisticsFramework 将自动走 SubPart → getArmorLevel/getRHA/resolvePenetration 管线。
     * <p>
     * 使用 generic() DamageSource，阶段一暂不追踪发射者。
     *
     * @param target    协议伤害目标（SubPart / Entity 等 BFHurtTarget 实现）
     * @param hitPoint  命中点世界坐标 (MC Vec3)
     * @param hitNormal 命中面法线 (MC Vec3)
     * @return 实际造成的伤害量
     */
    default float dealDamage(BFHurtTarget target, Vec3 hitPoint, Vec3 hitNormal) {
        BFDamageContext ctx = BFDamageContext.builder()
            .source(target.getBFEntity() != null
                ? target.getBFEntity().damageSources().generic()
                : new DamageSource(...))  // 阶段一暂用 generic
            .baseDamage(calculateCurrentDamage())
            .penetration(calculateCurrentPenetration())
            .hitVelocity(PhysicsHelperKt.toVec3(getVelocity()))
            .hitPoint(hitPoint)
            .hitNormal(hitNormal)
            .build();
        return BFDamageApi.hurt(target, ctx);
    }
}
```

### 4.1 完整字段

```java
/**
 * 投射物类型数据定义。
 * 对应一个 projectiles/*.json 文件，使用 Mojang Codec 从 JSON 反序列化。
 */
public class ProjectileType {

    private final String type;       // "point" 或 "rigid"
    private final float mass;        // 质量 (kg)
    private final float gravityFactor;  // 重力系数，默认 1.0
    private final float dragFactor;  // 空气阻力系数（速度平方阻力），默认 0
    private final float radius;      // 碰撞半径 (m)，默认 0.05

    private final float baseVelocity;       // 参考速度 (m/s)
    private final float basePenetration;    // 参考速度下穿深 (mm RHA)
    private final float baseDamage;         // 参考速度下伤害值
    private final float baseAccuracyMil;    // 基础精度（密位/千分弧度），默认 5.0

    private final float penetrationVelocityCoefficient; // 默认 0
    private final float damageVelocityCoefficient;      // 默认 0

    private final int maxLifetimeTicks;     // 默认 200

    @Setter
    private ResourceLocation registryKey;   // 加载时赋值，作为全局查询 key

    public static final Codec<ProjectileType> CODEC = RecordCodecBuilder.create(instance -> instance.group(
        Codec.STRING.fieldOf("type").forGetter(ProjectileType::getType),
        Codec.FLOAT.fieldOf("mass").forGetter(ProjectileType::getMass),
        Codec.FLOAT.optionalFieldOf("gravity_factor", 1.0f).forGetter(ProjectileType::getGravityFactor),
        Codec.FLOAT.optionalFieldOf("drag_factor", 0f).forGetter(ProjectileType::getDragFactor),
        Codec.FLOAT.optionalFieldOf("radius", 0.05f).forGetter(ProjectileType::getRadius),
        Codec.FLOAT.fieldOf("base_velocity").forGetter(ProjectileType::getBaseVelocity),
        Codec.FLOAT.fieldOf("base_penetration").forGetter(ProjectileType::getBasePenetration),
        Codec.FLOAT.fieldOf("base_damage").forGetter(ProjectileType::getBaseDamage),
        Codec.FLOAT.optionalFieldOf("base_accuracy_mil", 5.0f)
            .forGetter(ProjectileType::getBaseAccuracyMil),
        Codec.FLOAT.optionalFieldOf("penetration_velocity_coefficient", 0f)
            .forGetter(ProjectileType::getPenetrationVelocityCoefficient),
        Codec.FLOAT.optionalFieldOf("damage_velocity_coefficient", 0f)
            .forGetter(ProjectileType::getDamageVelocityCoefficient),
        Codec.INT.optionalFieldOf("max_lifetime_ticks", 200)
            .forGetter(ProjectileType::getMaxLifetimeTicks)
    ).apply(instance, ProjectileType::new));

    public static ProjectileType get(Level level, ResourceLocation key) {
        return level.isClientSide
            ? MMDynamicRes.PROJECTILE_TYPES.get(key)
            : MMDynamicRes.SERVER_PROJECTILE_TYPES.get(key);
    }
}
```

## 五、速度-伤害模型

### 5.1 公式

```
effective_penetration = base_penetration × (current_speed / base_velocity)^penetration_velocity_coefficient
effective_damage      = base_damage      × (current_speed / base_velocity)^damage_velocity_coefficient
```

### 5.2 系数语义

| 系数值    | 语义    | 物理含义               |
| ------ | ----- | ------------------ |
| 0      | 与速度无关 | 恒为基准值（如定型装药破甲弹）    |
| > 0    | 正相关   | 速度越高穿深/伤害越大（动能穿甲弹） |
| < 0    | 负相关   | 速度越快反而越低（存在最佳速度窗口） |
| \~1.43 | 经典德马尔 | 穿深 ∝ v^1.43        |

### 5.3 注意事项

- 穿深计算在构造 `BFDamageContext` 前完成
- 角度效应（斜穿）暂不纳入阶段一
- 速度趋近 0 时有效穿深/伤害趋近 0

## 六、质点投射物 (PointProjectile)

### 6.1 设计动机

适用于小口径穿甲弹、APFSDS 长杆弹等极快速、现实中无法被拦截的投射物。不需要 `PhysicsRigidBody`，避免了 Bullet 碰撞体管理和约束解算开销。

### 6.2 SoA 数据布局（在 ProjectileManager 中）

虽然 `PointProjectile` 也注册在 `ObjectManager.levelDestroyableObjects` 中（复用生命周期和网络同步基础），但其物理更新的核心数据以 SoA 方式存放在 `ProjectileManager`：

```
float[] pointPosX[i]       ← 世界坐标 X (JME)
float[] pointPosY[i]       ← 世界坐标 Y
float[] pointPosZ[i]       ← 世界坐标 Z
float[] pointVelX[i]       ← 速度 X (m/s)
float[] pointVelY[i]       ← 速度 Y
float[] pointVelZ[i]       ← 速度 Z
int[]   pointLifetime[i]   ← 剩余存活 tick
int[]   pointTypeIndex[i]  ← 投射物类型索引（查 ProjectileType 表）
int[]   pointObjId[i]      ← 对应的 DestroyableObject ID（用于回写命中状态）
boolean[] pointAlive[i]    ← 活跃标志
int     pointCount         ← 当前活跃总数
```

- 初始分配 256 容量，动态扩容时 ×2
- 移除时使用 swap-with-last 策略（O(1)）

### 6.3 碰撞检测：使用 JME PhysicsWorld.rayTest

**不使用 Minecraft 的** **`ClipContext`**。参照 [LivingEntityEyesightAttachment](file:///d:/Files/Project_MinecraftMods/Machine-Max/src/main/java/io/github/sweetzonzi/machine_max/common/attachment/LivingEntityEyesightAttachment.java) 的模式，使用 JME 物理引擎的射线检测：

```java
// 在 ProjectileManager.updatePointProjectiles() 中，每个物理步对每个活跃质点：
PhysicsLevel physicsLevel = SparkLevel.getPhysicsLevel(level);
PhysicsWorld world = physicsLevel.getWorld();

Vector3f prevPos = new Vector3f(pointPosX[i], pointPosY[i], pointPosZ[i]);
Vector3f currPos = prevPos.add(
    new Vector3f(pointVelX[i], pointVelY[i], pointVelZ[i]).multLocal(timeStep));

// JME 物理射线检测
List<PhysicsRayTestResult> results = world.rayTest(prevPos, currPos);

for (PhysicsRayTestResult result : results) {
    PhysicsCollisionObject obj = result.getCollisionObject();
    if (!(obj instanceof PhysicsRigidBody body)) continue;

    Object owner = PhysicsBodyExtensionKt.getOwner(body);
    if (owner == null) {
        // 命中地形碰撞体 → 仅视觉特效（火花粒子）
        spawnTerrainHitEffect(hitPoint);
        pointAlive[i] = false;
        break;
    }

    // 判断命中类型：
    //   1) owner instanceof BFHurtTarget（如 SubPart 自身即是）
    //      → 获取 HitBox，检查是否活跃
    //      → 直接 dealDamage((BFHurtTarget) owner, ...)
    //   2) owner instanceof Entity（实现了 BFHurtTarget 的原版实体）
    //      → 直接 dealDamage((BFHurtTarget) entity, ...)

    // 获取命中点坐标（参照 Eyesight: startPos + view * hitFraction）
    Vector3f hitPoint = prevPos.add(currPos.subtract(prevPos).mult(result.getHitFraction()));
    Vector3f hitNormal = result.getHitNormalLocal(); // 或从 body 获取面法线

    // 发起协议伤害（传入 Entity 引用）
    // ...
    pointAlive[i] = false;
    break; // 命中第一个目标后停止
}
```

**命中后的处理流程**：

1. 通过 JME rayTest 检测到命中 → 获取 `physicsBody.getOwner()`
2. 判断 owner 类型并直接发起协议伤害：
   - `owner instanceof BFHurtTarget`（如 SubPart）→ 直接调用 `dealDamage((BFHurtTarget) owner, hitPoint, hitNormal)`，BallisticsFramework 自动走穿甲管线
   - `owner instanceof Entity`（实现了 BFHurtTarget 的实体）→ 同理直接传入
   - `owner == null` → 命中地形碰撞体，仅产生视觉特效（火花粒子），不造成伤害
3. 触发命中视觉效果（见第十一节）
4. 服务端标记投射物已命中 → 广播命中包
5. 投射物 self-destruct

### 6.4 每物理步更新流程

```
for i in 0..pointCount:
    if !pointAlive[i]: continue

    // 1) 半隐式 Euler 积分
    speed = |vel[i]|
    gravityAcc = (0, -gravityFactor × 9.81, 0)
    dragForce = dragFactor × speed²
    dragAcc = dragForce / mass × normalize(-vel[i])
    vel[i] += (gravityAcc + dragAcc) × dt
    prevPos = pos[i]
    pos[i] += vel[i] × dt

    // 2) JME rayTest 碰撞检测（见 6.3）
    results = world.rayTest(prevPos, pos[i])
    if hit:
        → 触发命中视觉特效（服务端广播命中事件，客户端播放粒子/音效）
        → dealDamage → markHit → pointAlive[i] = false
        → 发送命中同步包

    // 3) 寿命检查
    pointLifetime[i]--
    if pointLifetime[i] <= 0:
        pointAlive[i] = false
        → 发送超时同步包

    // 4) （可选）末段效应：若未命中任何目标但击中方块，仅生成地形命中特效
```

### 6.5 网络同步策略

**不每 tick 同步**，仅关键事件时广播：

| 事件    | 同步内容              | 方向  |
| ----- | ----------------- | --- |
| 投射物创建 | 类型ID、初始位置、初始速度、寿命 | S→C |
| 投射物命中 | 投射物ID、命中点、命中目标    | S→C |
| 投射物超时 | 投射物ID             | S→C |

客户端收到创建包后本地构造 `PointProjectile`，之后**完全由客户端自主外推仿真**，直到收到服务端的命中/超时包。

### 8.2 ProjectileManager 关键方法

```java
public class ProjectileManager {
    private final Level level;

    // ===== SoA 数组：统一存放质点 & 刚体投射物数据 =====
    float[] posX, posY, posZ;     // 世界坐标 (JME)
    float[] velX, velY, velZ;     // 速度 (m/s)
    int[]   lifetime;             // 剩余存活 tick（主线程权威）
    int[]   typeIndex;            // 投射物类型索引
    int[]   objId;                // 对应的 DestroyableObject ID
    boolean[] alive;              // 活跃标志
    int count;                    // 当前活跃总数（volatile）
    int capacity = 256;           // 初始容量

    // ===== Entity 兼容层 —— 新增 =====
    boolean[] needsEntityRecreate; // Entity 因区块卸载丢失，待重建
    ProjectileEntity[] entities;   // 关联的 Entity 引用（下标对应 SoA 索引，可为 null）

    // ===== 类型缓存 =====
    private ProjectileType[] typeCache; // 该维度所有已加载的投射物类型

    // ===== 热路径复用对象 =====
    private final Vector3f rayFrom = new Vector3f();
    private final Vector3f rayTo = new Vector3f();
    private final Vector3f hitPointJme = new Vector3f();
    private final Vector3f hitNormalJme = new Vector3f();

    /**
     * 统一创建入口：创建 SOA 条目 + 配套 ProjectileEntity。
     * 自动按 ProjectileType 的 type 字段分派 PointProjectile / RigidProjectile。
     *
     * @param type     投射物类型
     * @param position 初始世界坐标（JME）
     * @param velocity 初始速度（JME，m/s）
     * @return 分配的 DestroyableObject ID
     */
    public int spawnProjectile(ProjectileType type, Vector3f position, Vector3f velocity) {
        int typeIdx = getOrAddType(type);
        ensureCapacity(count + 1);

        IProjectile projectile;
        if (type.getProjectileTypeEnum() == ProjectileTypeEnum.POINT) {
            projectile = new PointProjectile(level, type, position, velocity);
        } else {
            projectile = new RigidProjectile(level, type, position, velocity);
        }
        projectile.addToLevel();
        int objId = ((DestroyableObject) projectile).getId();

        int idx = count++;
        setSoaFields(idx, position, velocity, typeIdx, objId, type.getMaxLifetimeTicks());
        projectileObjIds.add(objId);

        // 仅当发射位置区块已加载时才创建 Entity；否则标记延迟创建
        if (!level.isClientSide && isChunkLoadedAt(position)) {
            createProjectileEntity(idx);
        } else if (!level.isClientSide) {
            needsEntityRecreate[idx] = true;
        }

        return objId;
    }

    // ===== Entity 生命周期管理 —— 新增 =====

    /**
     * 为 SoA 中索引为 idx 的投射物创建配套的 ProjectileEntity。
     * 直接传入 IProjectile 对象引用，避免 baseTick 中 O(n) 扫描和线程安全问题。
     * objMap 从 ObjectManager.levelDestroyableObjects 实时获取。
     */
    private void createProjectileEntity(int idx) {
        var objMap = ObjectManager.levelDestroyableObjects.get(level);
        if (objMap == null) return;
        DestroyableObject obj = objMap.get(objId[idx]);
        if (!(obj instanceof IProjectile projectile)) return;

        ProjectileEntity entity = new ProjectileEntity(
            MMEntities.PROJECTILE_ENTITY.get(), level);
        entity.bindToProjectile(projectile);   // 传对象引用，非 objId
        entity.setPos(posX[idx], posY[idx], posZ[idx]);
        entities[idx] = entity;
        level.addFreshEntity(entity);
    }

    /**
     * 按 objId 查找 SoA 数组中的索引（O(n) 线性扫描）。
     * 仅在 Entity 端调用（非热路径）。
     */
    public int findIndexByObjId(int targetObjId) {
        for (int i = 0; i < count; i++) {
            if (objId[i] == targetObjId) return i;
        }
        return -1;
    }

    /**
     * 遍历所有 needsEntityRecreate=true 的条目，检查区块是否已加载。
     * 若已加载则重建 ProjectileEntity。每 RECREATE_CHECK_INTERVAL tick 执行一次。
     */
    private static final int RECREATE_CHECK_INTERVAL = 10;
    private int recreateCheckCounter = 0;

    public void tryRecreateEntities() {
        if (++recreateCheckCounter % RECREATE_CHECK_INTERVAL != 0) return;
        ServerLevel serverLevel = (ServerLevel) level;
        for (int i = 0; i < count; i++) {
            if (!needsEntityRecreate[i] || !alive[i]) continue;
            if (!serverLevel.isPositionEntityTicking(
                    BlockPos.containing(posX[i], posY[i], posZ[i]))) continue;
            createProjectileEntity(i);
            needsEntityRecreate[i] = false;
        }
    }

    /**
     * 注册一个质点投射物到 SoA。
     * 在 PointProjectile 构造时调用。
     */
    public void addPointProjectile(PointProjectile p) {
        ensureCapacity(count + 1);
        int i = count++;
        posX[i] = p.getPosition().x;
        // ... 填充其余字段
        alive[i] = true;
    }

    /**
     * 批量更新所有活跃质点投射物。
     * 包含半隐式 Euler 积分、JME rayTest 碰撞检测、寿命检查。
     * <p>
     * dt 从 PhysicsLevel 获取（可通过 PhysicsLevel.getPhysicsTimeStep() 或
     * SparkLevel 查询的 TPS 换算: dt = 1.0f / tps）。
     */
    public void updatePointProjectiles(PhysicsLevel physicsLevel) {
        PhysicsWorld world = physicsLevel.getWorld();
        float dt = physicsLevel.getPhysicsTimeStep(); // 物理时间步 (s)

        for (int i = 0; i < count; i++) {
            if (!alive[i]) continue;

            // 1. 积分
            // 2. rayTest 碰撞
            // 3. 寿命检查 → alive[i] = false → swapRemove(i)
        }
    }

    private void swapRemove(int index) {
        // 先移除关联的 Entity（若存在）
        if (entities[index] != null) {
            entities[index].markOrphaned();
            entities[index] = null;
        }
        int last = count - 1;
        if (index != last) {
            // swap all arrays（含 needsEntityRecreate 和 entities）
            posX[index] = posX[last];
            // ... 其余数组
            needsEntityRecreate[index] = needsEntityRecreate[last];
            entities[index] = entities[last];
        }
        count--;
    }

    private void ensureCapacity(int required) {
        if (required <= capacity) return;
        int newCap = Math.max(required, capacity * 2);
        posX = Arrays.copyOf(posX, newCap);
        // ... 其余数组（含 needsEntityRecreate 和 entities）
        needsEntityRecreate = Arrays.copyOf(needsEntityRecreate, newCap);
        entities = Arrays.copyOf(entities, newCap);
        capacity = newCap;
    }
}
```

### 8.4 ProjectileEntity —— 轻量 Entity 兼容层

#### 8.4.1 设计动机

SOA 投射物运行在 JME 物理世界，不被 Minecraft 的 `instanceof Projectile` / `level.getProjectiles()` 识别，导致其他模组的投射物拦截、反弹、护盾等逻辑对 Machine-Max 投射物失效。`ProjectileEntity` 解决了这个问题——它不承担物理计算，仅作为 SOA 投射物的"兼容性外壳"。

#### 8.4.2 双轨制架构

```
物理层（性能优先）                    兼容层（模组生态）

┌──────────────────┐          ┌──────────────────────┐
│  ProjectileManager│◄─────────│   ProjectileEntity   │
│  (SoA 批量积分)   │  位置拉取  │   (extends Projectile)│
│  (JME rayTest)   │          │   (no physics)       │
│  (不受区块影响)   │          │   (DataTracker 极简) │
└──────────────────┘          └──────────────────────┘
         │                            │
         │ 物理线程 (100Hz)            │ 主线程 (20tick/s)
         │ 高吞吐 · 零GC              │ 模组可见 · 事件可订阅
         ▼                            ▼
    真实的物理结果               instanceOf Projectile ✓
    (碰撞 · 伤害 · 命中)          level.getProjectiles() ✓
                                  ProjectileImpactEvent ✓
```

#### 8.4.3 线程安全分析

`ProjectileManager.postTickAndSync()` 已在主线程（`LevelTickEvent.Post`）中将 SoA 位置/速度回写到 `PointProjectile.setPosition()` / `setLinearVelocity()`（写入 `SynchedEntityData`），而 `RigidProjectile` 本就在自己的 `postTick()` 中从 Bullet 刚体同步。因此 `IProjectile.getPosition()` / `getVelocity()` 在主线程中读取是安全的。

**时序**：

```
Tick N:
  物理线程: updatePointProjectiles() → 写 SoA 数组
  主线程:   LevelTickEvent.Post → postTickAndSync()
              → PointProjectile.setPosition() → 写 SynchedEntityData
  
Tick N+1:
  主线程:   Entity.tick() → ProjectileEntity.baseTick()
              → projectile.getPosition() → 读 SynchedEntityData ✓
              → 读到 Tick N 的位置 (1 tick 延迟，视觉不可感知)
```

因此 `ProjectileEntity` 应持有 `IProjectile` 对象的直接引用，而非通过 `objId` 查找 SoA 数组。

#### 8.4.4 客户端 IProjectile 引用获取机制

服务端通过 `bindToProjectile(IProjectile)` 直接持有对象引用，但客户端 Entity 由原版 EntityTracker 的 `ClientboundAddEntityPacket` 创建，无法直接传入。需通过 `IEntityWithComplexSpawn` 在 spawn 包中携带 `DestroyableObject.getId()`，客户端据此反查。

**数据流**：

```
服务端                                        客户端
───────                                       ───────
spawnProjectile():
  1. new PointProjectile → addToLevel()       1. ProjectileSpawnPayload 到达
       → objId = 123                              → new PointProjectile
                                              2. addToLevel() → 注册到客户端
  2. createProjectileEntity()                     ObjectManager.levelDestroyableObjects
     → entity.bindToProjectile(projectile)
  3. addFreshEntity(entity)
     → EntityTracker 发 ClientboundAddEntity   3. ClientboundAddEntity 到达
       + writeSpawnData(buf.writeInt(123))         → new ProjectileEntity()
                                              4. readSpawnData(123)
                                                 → ObjectManager.getDestroyableObject(123)
                                                   → IProjectile ✓
```

**竞态处理**：自定义 `ProjectileSpawnPayload` 与原版 `ClientboundAddEntityPacket` 通过独立网络通道发送，可能乱序。Entity 到达时 `IProjectile` 可能尚未创建。仿照 `MMPartEntity` 的 retry 模式：`baseTick()` 中若 `projectile == null` 则每 tick 重试查找，超过 100 tick 仍未找到则移除 Entity。

#### 8.4.5 类设计

```java
/**
 * 轻量 Entity 兼容层 —— 代表了 SOA 中一个投射物在 Minecraft 世界的"投影"。
 * <p>
 * 客户端通过 {@link IEntityWithComplexSpawn} 携带 objId 反查 IProjectile；
 * 服务端由 ProjectileManager 调用 {@link #bindToProjectile(IProjectile)} 直接绑定。
 */
public class ProjectileEntity extends Projectile implements IEntityWithComplexSpawn {

    // ===== 关联字段 =====
    private IProjectile projectile;        // 直接对象引用（服务端直接设置；客户端通过 lookup 获取）
    private volatile boolean orphaned;      // SOA 条目已不存在，本实体待清理
    private int projectileObjId = -1;      // 客户端反查键：DestroyableObject.getId()

    public ProjectileEntity(EntityType<? extends Projectile> type, Level level) {
        super(type, level);
        this.noPhysics = true;
        this.noCulling = true;
    }

    @Override
    protected void defineSynchedData(SynchedEntityData.Builder builder) {
    }

    /** 服务端：直接绑定到 IProjectile 对象 */
    public void bindToProjectile(IProjectile projectile) {
        this.projectile = projectile;
        this.projectileObjId = ((DestroyableObject) projectile).getId();
        this.orphaned = false;
    }

    // ===== IEntityWithComplexSpawn：客户端通过 objId 反查 =====

    @Override
    public void writeSpawnData(RegistryFriendlyByteBuf buffer) {
        buffer.writeInt(projectileObjId);
    }

    @Override
    public void readSpawnData(RegistryFriendlyByteBuf additionalData) {
        projectileObjId = additionalData.readInt();
    }

    /** 在客户端 Entity 的 ObjectManager 中查找对应的 IProjectile */
    private void tryBindProjectile() {
        if (projectileObjId < 0 || projectile != null) return;
        DestroyableObject obj = ObjectManager.getDestroyableObject(level(), projectileObjId);
        if (obj instanceof IProjectile proj) {
            this.projectile = proj;
        }
    }

    // ===== 每 tick：从 IProjectile 对象读取位置 =====

    @Override
    public void baseTick() {
        super.baseTick();
        if (orphaned) return;

        if (projectile == null) {
            tryBindProjectile();                 // 首次/重试绑定
            if (projectile == null) {
                if (tickCount > 100) {
                    MachineMax.LOGGER.warn("投射物实体未匹配到 IProjectile (objId={}), 已移除",
                        projectileObjId);
                    markOrphaned();
                }
                return;                          // 尚未就绪，等待下次 tick
            }
        }

        if (!projectile.isAlive()) { markOrphaned(); return; }

        Vector3f pos = projectile.getPosition();
        Vector3f vel = projectile.getVelocity();
        this.setPos(pos.x, pos.y, pos.z);

        double dx = vel.x, dy = vel.y, dz = vel.z;
        float yaw = (float)(Math.toDegrees(Math.atan2(-dx, dz)));
        float pitch = (float)(Math.toDegrees(Math.atan2(dy,
            Math.sqrt(dx * dx + dz * dz))));
        this.setRot(yaw, pitch);
        this.setDeltaMovement(dx * 0.05, dy * 0.05, dz * 0.05);
    }

    // ===== 区块卸载 =====

    @Override
    public void remove(RemovalReason reason) {
        super.remove(reason);
        if (!level().isClientSide && !orphaned && projectile != null
            && reason == RemovalReason.UNLOADED_TO_CHUNK) {

            ProjectileManager pm = ProjectileManager.get(level());
            if (pm != null) {
                int idx = pm.findIndexByObjId(projectileObjId);
                if (idx >= 0) pm.needsEntityRecreate[idx] = true;
            }
        }
    }

    @Override public void move(MoverType type, Vec3 delta) {}
    @Override public boolean isNoGravity()   { return true; }
    @Override public boolean isPickable()    { return false; }
    @Override
    public boolean isAlwaysTicking() {
        return projectile != null && projectile.isAlive() && !isRemoved();
    }

    void markOrphaned() {
        orphaned = true;
        this.remove(RemovalReason.DISCARDED);
    }
}
```

#### 8.4.6 Entity 注册（MMEntities.kt）

```kotlin
@JvmStatic
val PROJECTILE_ENTITY = MachineMax.REGISTER.entityType {
    id = "projectile"
    factory = entityTypeBuilder(::ProjectileEntity, MobCategory.MISC) {
        noSummon()                          // 禁止自然生成
        noSave()                            // 不存档——投射物是瞬态的
        fireImmune()                        // 不受火焰伤害
        eyeHeight(0.0F)
        setShouldReceiveVelocityUpdates(false)
        sized(0.25f, 0.25f)                 // 极小碰撞箱（视觉用途）
        clientTrackingRange(256)            // 远距离可见（配合超视距打击）
        updateInterval(Int.MAX_VALUE)       // 禁用原版 EntityTracker 周期性位置同步
    }
}
```

**关键决策——`updateInterval(Int.MAX_VALUE)`**：Minecraft 的 `ChunkMap.TrackedEntity` 每 `tickCount % updateInterval == 0` 时触发一次位置/速度同步。设为 `Integer.MAX_VALUE`（约 21 亿 tick）意味着几乎永不触发周期性同步。只有以下包仍会被发送：

| 包类型                                           | 受 updateInterval 影响 | 说明                      |
| --------------------------------------------- | ------------------- | ----------------------- |
| `ClientboundAddEntityPacket`（实体登场）            | ❌                   | 新玩家进入追踪范围时仍发送，携带当前服务端位置 |
| `ClientboundRemoveEntitiesPacket`（退场）         | ❌                   | Entity 销毁时正常发送          |
| `ClientboundSetEntityDataPacket`（DataTracker） | ❌                   | 独立 dirty 检测机制           |
| `ClientboundTeleportEntityPacket`（位置）         | ✅ 被阻止               | 周期性检查永不触发               |
| `ClientboundMoveEntityPacket`（速度）             | ✅ 被阻止               | 同周期性检查                  |

这与"关键事件同步"的设计完全吻合——投射物位置由客户端本地外推驱动，原版 EntityTracker 仅负责登场/退场和 DataTracker。无需任何 mixin 干预。

**关键决策——`noSave()`**：投射物本质是瞬态的，不应跨会话持久化。区块卸载时 Entity 消失；区块重载时，若 SOA 中投射物仍存活且飞回了加载区块，`tryRecreateEntities()` 会重建它。这样不会出现"区块存档复活旧投射物"的 bug。

### 8.5 区块穿越与 Entity 生命周期

#### 8.5.1 问题本质

Minecraft 的 Entity 依赖区块加载而存在——当实体所在区块卸载时，实体会被 `remove(UNLOADED_TO_CHUNK)`。但 SOA 投射物运行在 JME 物理世界，物理世界不感知区块边界。这意味着**投射物可以跨过未加载区块飞行长距离**，支持超视距打击，但 Entity 外壳无法跟随。

#### 8.5.2 状态机

```
[发射] → SOA 创建条目 + Entity 创建（若区块已加载）
                                             │
                    ┌────────────────────────┼────────────────────────┐
                    ▼                        ▼                        ▼
             [飞行中/区块加载]          [飞入未加载区块]          [命中/超时]
                    │                        │                        │
             Entity 正常 tick           Entity.remove()              │
             从 SOA 拉位置              → needsEntity=true           │
             模组可见                   → Entity 被销毁              │
                    │                        │                        │
                    │                  [每隔 10 tick]                 │
                    │                   tryRecreateEntities           │
                    │                        │                        │
                    │               ┌───────┴────────┐               │
                    │           区块仍未加载      区块已加载           │
                    │               │                │                │
                    │           跳过等待        重建 Entity           │
                    │                                │                │
                    └──────────┬─────────────────────┘               │
                               │                                     │
                               ▼                                     ▼
                          [继续飞行]                          swapRemove()
                                                             清理 Entity + SoA
```

#### 8.5.3 时序详解

以下是一个投射物从发射到穿越未加载区块再到命中的完整时序：

```
Tick 0 —— 发射（区块 A 已加载）
┌──────────────────────────────────────────────────────────┐
│ SOA: pos = [0,0,0], alive = true                        │
│ Entity: 已创建，正常存在                                 │
│ 区块状态: A 已加载，B 未加载                             │
└──────────────────────────────────────────────────────────┘

Tick 1 ~ N-1 —— 在加载区块 A 内正常飞行
┌──────────────────────────────────────────────────────────┐
│ SOA: 每物理步积分，不受区块影响                          │
│ Entity: baseTick() → 从 SOA 拉位置 → setPos()           │
│ EntityTracker: 正常向追踪玩家发送位置更新                │
└──────────────────────────────────────────────────────────┘

Tick N —— 飞入未加载区块 B
┌──────────────────────────────────────────────────────────┐
│ SOA: pos 跨过区块边界，继续运行                          │
│ Entity: setPos(未加载区块坐标)                           │
│   → EntityLookup 将实体移至区块 B 的列表                 │
│   → 区块 B 不 tick，实体暂时"悬空"                      │
└──────────────────────────────────────────────────────────┘

Tick N+1 ~ N+2 —— 清理（延迟 1-2 tick）
┌──────────────────────────────────────────────────────────┐
│ ServerLevel 遍历检测到实体在未加载区块中                 │
│ → remove(RemovalReason.UNLOADED_TO_CHUNK)                │
│ → 我们的 remove() 钩子: needsEntityRecreate[idx] = true │
│ → Entity 被销毁（noSave: 不写 NBT）                     │
│                                                          │
│ SOA: 仍在物理世界飞行，毫不知情                           │
└──────────────────────────────────────────────────────────┘

Tick N+3 ~ N+M —— 在未加载区块中飞行
┌──────────────────────────────────────────────────────────┐
│ SOA: 继续积分 + rayTest                                 │
│ needsEntityRecreate = true                              │
│ tryRecreateEntities() 每 10 tick 检查:                   │
│   → isPositionEntityTicking() = false → 跳过            │
│                                                          │
│ 无 Entity，无网络包，零额外开销                          │
└──────────────────────────────────────────────────────────┘

Tick N+M —— 飞回加载区块 C（另一个玩家基地附近）
┌──────────────────────────────────────────────────────────┐
│ SOA: pos 进入区块 C                                     │
│ tryRecreateEntities():                                   │
│   → isPositionEntityTicking() = true ✓                  │
│   → createProjectileEntity(idx)                         │
│   → new ProjectileEntity + setPos + addFreshEntity()    │
│   → EntityTracker 开始向区块 C 的玩家同步               │
│                                                          │
│ needsEntityRecreate[idx] = false                        │
│ 玩家 C 看到一个高速飞行物从远方飞入视野！                │
└──────────────────────────────────────────────────────────┘
```

#### 8.5.4 边界情况处理

| 情况                        | 行为                                                         | 说明                        |
| ------------------------- | ---------------------------------------------------------- | ------------------------- |
| **区块闪烁**（瞬间卸载又重载）         | Entity 可能尚未被 remove 就恢复                                    | Minecraft 自然行为即可覆盖        |
| **发射时区块就未加载**             | 不创建 Entity，needsEntity=true                                | `spawnProjectile()` 中已有检查 |
| **全路径都在未加载区，最终消逝**        | SOA 命中/超时 → swapRemove 清理 needsEntity                      | 从未创建 Entity，无资源浪费         |
| **命中未加载区块中的物理体**          | SOA rayTest 命中 → alive=false → needsEntity 随 swapRemove 清除 | 物理体存在意味着区块必加载             |
| **Entity 被其他模组移除**        | remove() 中 needsEntity=true → 后续按需重建                       | 与区块卸载同等处理                 |
| **原版 EntityTracker 位置同步** | `updateInterval(Int.MAX_VALUE)` 完全禁用周期性位置包                 | 仅登场/退场 + DataTracker，无冲突  |

#### 8.5.5 性能影响

| 场景                    | SOA 开销 | Entity 开销 | 网络开销  | 合计                  |
| --------------------- | ------ | --------- | ----- | ------------------- |
| 100 投射物，全在加载区块        | 30 μs  | 0.5-1 ms  | \~0\* | \~1 ms              |
| 500 投射物，全在加载区块        | 150 μs | 2.5-5 ms  | \~0\* | 2.5-5 ms (5-10% 预算) |
| 500 投射物，仅 200 在加载区块   | 150 μs | 1-2 ms    | \~0\* | \~1.2 ms            |
| tryRecreateEntities() | —      | \~50 μs/次 | —     | 每 10 tick           |

\* 网络开销：`updateInterval(Int.MAX_VALUE)` 禁用了周期性位置包，仅发送登场/退场/DataTracker 包。仅退场包在命中时触发一次。

**EntityTracker 内存**：每个追踪条目约 200 bytes。500 投射物 × 10 玩家 = 5000 追踪条目 ≈ 1 MB，可接受。

即使在最坏情况（500 投射物全部在加载区块内），约 5ms 占 50ms tick 预算的 10%，完全可接受。

#### 8.5.6 设计总结

| 状态         | SOA     | Entity         | 网络       | 模组可见                    |
| ---------- | ------- | -------------- | -------- | ----------------------- |
| 加载区块中飞行    | ✅ 积分+碰撞 | ✅ 正常 tick      | ⚡ 仅登场/退场 | ✅ instanceof Projectile |
| 刚飞入未加载区块   | ✅ 继续    | ⚠️ 存在但区块不 tick | ❌ 无追踪玩家  | ❌                       |
| 1-2 tick 后 | ✅ 继续    | ❌ 已 remove     | ❌        | ❌                       |
| 未加载区飞行中    | ✅ 积分+碰撞 | ❌ 不存在          | ❌        | ❌                       |
| 飞回加载区块     | ✅ 继续    | 🔄 自动重建        | ✅ 恢复同步   | ✅                       |

## 十、与 BallisticsFramework 的集成

### 10.1 伤害发起路径

```
投射物命中
  │
  ├─ 1. JME rayTest / 刚体碰撞 → 获取 owner
  │      ↓
  │   owner instanceof BFHurtTarget（SubPart / Entity 等）
  │      → 直接以此作为 target，无需二次映射
  │
  ├─ 2. 计算有效穿深/伤害
  │     pen = calculateCurrentPenetration()
  │     dmg = calculateCurrentDamage()
  │
  ├─ 3. 构造 BFDamageContext
  │     .source(DamageSources.generic())
  │     .baseDamage(dmg) .penetration(pen)
  │     .hitVelocity(vel) .hitPoint(hitPos) .hitNormal(hitNormal)
  │
  ├─ 4. BFDamageApi.hurt(target, ctx)
  │      │
  │      ├─ target 是 SubPart（继承 DestroyableObject 实现 BFHurtTarget）
  │      │    → getRHA / modifyPenetration / resolvePenetration
  │      │    → calculateFinalDamage → hurt → 伤害传递至 VehicleCore
  │      │
  │      ├─ target 是普通 Entity（实现了 BFHurtTarget）
  │      │    → 同上，走协议穿甲管线
  │      │
  │      └─ target 是普通 Entity（未实现 BFHurtTarget）
  │           → entity.hurt(source, baseDamage) 原版回退
  │
  └─ 5. 触发命中视觉效果（火花粒子 + 音效）
```

### 10.2 BFDamageContext 字段映射

| 字段            | 来源                                                    |
| ------------- | ----------------------------------------------------- |
| `source`      | `target.getBFEntity().damageSources().generic()`（阶段一） |
| `baseDamage`  | `calculateCurrentDamage()`                            |
| `penetration` | `calculateCurrentPenetration()`                       |
| `hitVelocity` | 当前速度（JME → MC Vec3，使用 PhysicsHelperKt）                |
| `hitPoint`    | rayTest.hitPoint / 刚体碰撞点（JME → MC Vec3）               |
| `hitNormal`   | rayTest.hitNormal / 碰撞接触法线                            |
| `extensions`  | 阶段一为空                                                 |
| `handler`     | 阶段一为 null                                             |

### 10.3 目标类型与管线分发

| 命中目标 owner                         | target 参数    | BFDamageApi 路径                         |
| ---------------------------------- | ------------ | -------------------------------------- |
| `SubPart`                          | `subPart` 自身 | 分支1：BFHurtTarget → 穿甲管线（HitBox RHA 判定） |
| `Entity` (implements BFHurtTarget) | `entity` 自身  | 分支1：BFHurtTarget → 穿甲管线                |
| `Entity` (普通实体)                    | `entity` 自身  | 分支3：原版 `entity.hurt()` 回退              |
| `null` (地形碰撞体)                     | —            | 仅视觉特效，不调用 hurt                         |

## 十四、未决问题（后续讨论）

1. **发射者追踪**：当前使用 `target.getBFEntity().damageSources().generic()` 丢失了发射者信息。后续集成 `LauncherSubsystem` 时，需传递发射者（玩家或载具）到投射物构造时保存，用于击杀归属、仇恨系统和正确的 DamageSource 构建。
2. **BFHurtTarget 非 Entity 场景**：如果 `BFHurtTarget` 的 `getBFEntity()` 返回 null，无法构造 `DamageSource`。阶段一可以先 fallback 到某个全局静态 `DamageSource`，或要求所有投射物可命中目标必有有效 Entity 引用。
3. **视觉特效网络包**：`ProjectileHitEffectPayload` 需要定义并注册。命中位置/法线/类型（装甲 vs 地形）作为 payload 字段。
4. **精度系统的发射器叠加**：`base_accuracy_mil` 定义了投射物自身的 1σ 散步角。发射器（`LauncherSubsystem`）的 `horizontal_accuracy_multiplier` / `vertical_accuracy_multiplier` 需要与此叠加计算出最终散布椭圆。叠加公式待定（乘性？加性？）。
5. **ProjectileImpactEvent 不触发的兼容性 gap**：由于 `move()` 为空 + `isPickable()=false`，原版碰撞检测不运行，`ProjectileImpactEvent` 不会被触发。依赖此事件的模组（护盾、拦截系统）无法用标准方式拦截 Machine-Max 投射物。阶段二可在 `ProjectileManager` 命中处理中手动触发事件（要求 Entity 在命中时存在）。
6. **blockbench 模型 vs debug 线框**：当前阶段使用红色线条/蓝色球体线框渲染。阶段三引入 blockbench 模型后，`ProjectileEntity` 可作为模型渲染的载体（类似于 MMPartEntity 是 SubPart 的渲染载体）。
7. **空 EntityRenderer 注册**：阶段一需为 `ProjectileEntity` 注册一个空 `EntityRenderer`，确保 `EntityTracker` 客户端初始化正常，避免其他模组通过 `entityRenderer.getRenderPosition()` 获取到异常位置。
