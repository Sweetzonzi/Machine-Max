# 武器系统 — 物理线程发射重构设计

**日期**: 2026-06-08 · **状态**: 设计阶段

## 1. 动机

当前武器发射全流程在**主线程**（20tps）执行，存在以下问题：

1. **射速上限 1200 RPM**：`calcFireInterval()` 最小间隔 1 tick，无法模拟更高射速的武器。
2. **枪口位姿偏差**：主线程读取的 `getMuzzleWorldTransform()` 可能滞后物理体实际位姿 1 tick。
3. **后坐力跨线程**：`applyImpulse` 需通过 `submitImmediateTask(PPhase.PRE, ...)` 回物理线程，有调度延迟。

本重构将发射相关计算迁移到**物理线程**，同时解决上述问题。

## 2. 核心思路

### 2.1 计时器累积发射模型

不再使用 `fireCooldown` 倒计时（每次 1 tick 打一发），改为**计时器累积 + 批量发射**：

```
主线程 onTick:
  fireAccumulator += 0.05s
  N = fireAccumulator / intervalSec   // 这段时间能打多少发
  若 N >= 1:
    从膛内取出 N 发弹药类型 → 入队 pendingFires
    fireAccumulator -= N * intervalSec
    逐发装填下一发（若有）

物理线程 onPrePhysicsTick:
  从 pendingFires 逐发出队
  每发：读刚体实时位姿 → 计算错开位置 → create → SoA → 后坐力
```

停止开火时 `fireAccumulator = 0`，防止"蓄力"。

### 2.2 弹丸错开

同一物理 tick 内多发的弹丸按初速 × 发射间隔错开起始位置：

```
staggerDist = muzzleVelocity × intervalSec
第 i 发起始位置 = muzzlePos + muzzleDir × i × staggerDist
```

### 2.3 线程职责严格划分

| 操作                                     | 线程      | 原因                          |
| -------------------------------------- | ------- | --------------------------- |
| 弹药装填（requestRound / consumeReadyRound） | 主线程     | 操作 ItemStack 容器             |
| 弹药清膛（chamberedType = null）             | 主线程     | 与装填同一事务                     |
| 计时器累积 + 发射数计算                          | 主线程     | 依赖装填状态                      |
| 枪口位姿读取                                 | 物理线程    | 与刚体实时同步                     |
| 散布 + 初速计算                              | 物理线程    | 纯计算，无副作用                    |
| 投射物 SoA 写入                             | 物理线程    | 符合 Manager 线程设计             |
| 投射物刚体注册                                | 物理线程    | Bullet 物理世界操作               |
| 后坐力 applyImpulse                       | 物理线程    | 直接操作物理体                     |
| Entity 创建 + 发包                         | 主线程     | `level.addFreshEntity` 限主线程 |
| 开火音效                                   | 主线程（间接） | 客户端收到包后播放                   |

### 2.4 批量网络包

不再每个投射物单独发送 `ProjectileSpawnPayload`，改为累积一批后一次 `ProjectileBatchSpawnPayload` 发送，减少小包数量。

批次包不携带 `maxLifetime` 和 `isRigid`，客户端从 `ProjectileType` 本地读取。

## 3. 数据流

```
┌─ 主线程 onTick ───────────────────────────────────────────────────┐
│                                                                     │
│  ① 开火信号判定：isFiring() ?                                       │
│                                                                     │
│  ② 计时器：                                                        │
│     fireAccumulator += 0.05s                                       │
│     rounds = fireAccumulator / intervalSec                          │
│                                                                     │
│  ③ 弹药消费（rounds 轮循环）：                                      │
│     pendingFires.add(chamberedType)                                 │
│     chamberedType = null                                            │
│     supplier.consumeReadyRound() → chamberedType（装填下一发）       │
│     若装填失败 → 结束入队                                           │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
        │ pendingFires (ConcurrentLinkedQueue<ProjectileType>)
        ▼
┌─ 物理线程 onPrePhysicsTick ────────────────────────────────────────┐
│                                                                     │
│  ④ 逐发出队发射：                                                   │

│                                                                     │

│       pos = muzzle + dir × i × staggerDist                          │
│       vel = 散布(dir) × finalSpeed + platformVel                   │
│       type.create(level, pos, vel)                                  │
│       applyImpulse(后坐力)                                          │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
        │ type.create() → addToLevel() → addProjectileInternal()
        │   ├─ SoA 写入（物理线程）
        │   └─ pendingEntityObjIds.add(objId)（ConcurrentLinkedQueue）
        ▼

│                                                                     │
│  ⑤ 从 pendingEntityObjIds 清空队列                                  │
│  ⑥ 逐个 createProjectileEntity()（区块加载则创建，否则标记重建）     │
│  ⑦ 一次 ProjectileBatchSpawnPayload.broadcast()                     │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
        │ 网络包 → 客户端
        ▼
┌─ 客户端 (ProjectileBatchSpawnPayload.handle) ──────────────────────┐
│                                                                     │
│  ⑧ 逐条 type.create() → addToLevel()                               │
│       ├─ ObjectManager 注册                                        │
│       ├─ SoA 写入（客户端渲染用）                                    │
│       └─ playFireSound()                                           │

└─────────────────────────────────────────────────────────────────────┘
```

## 4. 线程安全设计

### 4.1 跨线程字段

| 字段                    | 生产者           | 消费者                  | 方案                                      |
| --------------------- | ------------- | -------------------- | --------------------------------------- |
| `pendingFires`        | 主线程 add       | 物理线程 poll            | `ConcurrentLinkedQueue<ProjectileType>` |
| `pendingEntityObjIds` | 物理线程 add      | 主线程 poll             | `ConcurrentLinkedQueue<Integer>`        |
| `fireAccumulator`     | 主线程读写         | —                    | 普通 double（单线程）                          |
| `chamberedType`       | 主线程读写         | 物理线程读（仅 isFiring 判定） | `volatile`                              |
| SoA 数组                | 物理线程写(add+积分) | 主线程读(遍历)             | volatile `count` happens-before         |
| `typeCache`           | 物理线程写         | 主线程读                 | `volatile ProjectileType[]`             |

### 4.2 SoA 写入时机

`addProjectileInternal()` 仅从物理线程调用（经 `fireMultiple` → `type.create` → `addToLevel` → `addPointProjectile/addRigidProjectile`）。

写入顺序：

```
写 SoA[i] → projectileObjIds.add(id) → pendingEntityObjIds.add(id) → count++ (volatile)
```

主线程读 `volatile count` 后可见所有 SoA 写入。

### 4.3 `getOrAddType` 线程安全

`typeCache` 改为 `volatile`。物理线程 `Arrays.copyOf` + 引用替换在 `count++` volatile write 之前完成，主线程读 `count` 后通过 happens-before 语义可见新 `typeCache` 引用。

## 6. 关键细节

### 6.1 弹药消费循环

主线程每 tick 最多能消费 `N = fireAccumulator / intervalSec` 发弹药。循环中每消费一发就尝试装填下一发，弹药耗尽时提前终止：

```java
for (int i = 0; i < rounds; i++) {
    pendingFires.add(chamberedType);
    chamberedType = null;
    // 尝试装填
    if (supplier.isRoundReady(this)) {
        chamberedType = supplier.consumeReadyRound(this);
    } else if (!reloading) {
        supplier.requestRound(this);
        reloading = true;
        break; // 等待装填
    }
    if (chamberedType == null) break;
}
```

### 6.2 不兼容弹药处理

`handleIncompatibleAmmo` 逻辑在主线程装填循环中自然处理：兼容性校验失败 → 归还 → 切供给者 → 重新装填 → 若装填成功继续入队，否则 break。

### 6.3 弹丸错开退化

当 `fireRate` 极高（如 6000 RPM，`intervalSec = 0.01s`）且 `muzzleVelocity` 较低时，`staggerDist` 很小，弹丸自然接近但不重叠。极端情况下同一 tick 发射数极多时，应限制 `maxRoundsPerTick` 防止性能问题（后续优化项）。

### 6.4 客户端音效

客户端在 `addToLevel()` 中对每个投射物调用 `playFireSound()`。极高射速下可能同时播放大量音效，作为后续优化可改为"持续开火循环音效"。

### 6.5 旧 `ProjectileSpawnPayload` 兼容

旧的单发包保留不删，避免破坏性变更。`ProjectileTestItem` 等直接调用 `type.create()` 的路径不再广播（`addToLevel` 不再发包），旧包实际已无调用方。如后续确认无残留引用，可删除旧包。

## 7. 批量发包机制

### 7.1 收集与冲刷 — `flushProjectileEntities()`

`flushProjectileEntities()` 在 `ProjectileManager.preTick()` 开头调用（主线程），清空 `pendingEntityObjIds` 队列并完成 Entity 创建和网络广播。

**pos/vel 读取安全性**：通过 `objId` 从 `ObjectManager.levelDestroyableObjects` 取 `IProjectile` 对象，调用其 `getPosition()` / `getVelocity()` 获取初始发射位置。这些值由构造器设置，主线程 `postTick` 才回写新值，而 `flushProjectileEntities` 在 `preTick` 执行 —— 此时尚未被覆写，读到的是构造初始值。

```java
public void flushProjectileEntities() {
    if (pendingEntityObjIds.isEmpty()) return;

    Map<Integer, DestroyableObject> objMap = ObjectManager.levelDestroyableObjects.get(level);

    // ① 清空队列，收集本批所有 objId
    List<Integer> batchIds = new ArrayList<>();
    Integer id;
    while ((id = pendingEntityObjIds.poll()) != null) {
        batchIds.add(id);
    }
    if (batchIds.isEmpty()) return;

    // ② 逐个创建 Entity + 收集发包数据
    for (int objId : batchIds) {
        int idx = findIndexByObjId(objId);
        if (idx < 0) continue;

        // 用 IProjectile.getPosition() 读取初始发射位置（preTick 时尚未被 postTick 覆写）
        DestroyableObject obj = (objMap != null) ? objMap.get(objId) : null;
        Vector3f spawnPos = (obj != null) ? obj.getPosition() 
            : new Vector3f(posX[idx], posY[idx], posZ[idx]);

        if (isChunkLoadedAt(spawnPos)) {
            createProjectileEntity(idx);
            needsEntityRecreate[idx] = false;
        }
    }

    // ③ 一次批量发包
    if (level instanceof ServerLevel serverLevel) {
        ProjectileBatchSpawnPayload.broadcast(serverLevel, batchIds, this, objMap);
    }
}
```

**调用时机**：`preTick` 是主线程 `LevelTickEvent.Pre` 阶段，在 `tickAndPreTick` 之前执行。这保证 Entity 创建在新一帧投射物寿命递减之前完成。

```
preTick():
  flushProjectileEntities()     ← 先处理上轮物理线程新增的投射物
  tickAndPreTick()               ← 再递减寿命 + preTick 各投射物
  tryRecreateEntities()          ← 最后重试之前因区块未加载而延迟的
```

### 7.2 网络包结构 — `ProjectileBatchSpawnPayload`

```java
public record ProjectileBatchSpawnPayload(
    List<SpawnEntry> entries
) implements CustomPacketPayload {

    /** 单个投射物生成条目 */
    record SpawnEntry(
        int objId,                    // DestroyableObject ID
        ResourceLocation typeKey,     // 投射物类型注册键
        double posX, double posY, double posZ,  // 世界坐标
        double velX, double velY, double velZ   // 初速 (m/s)
    ) {}
}
```

**不传 `maxLifetime` 和 `isRigid`**：客户端收到包后通过 `ProjectileType.get(level, typeKey)` 获取类型实例，`maxLifetime` 从 `ProjectileType.getMaxLifetimeTicks()` 读取，类型枚举（POINT/RIGID）从 `ProjectileType.getType()` 读取。

**编解码器**：

```java
public static final StreamCodec<RegistryFriendlyByteBuf, ProjectileBatchSpawnPayload> STREAM_CODEC =
    new StreamCodec<>() {
        @Override
        public ProjectileBatchSpawnPayload decode(RegistryFriendlyByteBuf buf) {
            int count = buf.readVarInt();
            List<SpawnEntry> entries = new ArrayList<>(count);
            for (int i = 0; i < count; i++) {
                entries.add(new SpawnEntry(
                    buf.readVarInt(),
                    ResourceLocation.STREAM_CODEC.decode(buf),
                    buf.readDouble(), buf.readDouble(), buf.readDouble(),
                    buf.readDouble(), buf.readDouble(), buf.readDouble()
                ));
            }
            return new ProjectileBatchSpawnPayload(entries);
        }

        @Override
        public void encode(RegistryFriendlyByteBuf buf, ProjectileBatchSpawnPayload pkt) {
            buf.writeVarInt(pkt.entries.size());
            for (SpawnEntry e : pkt.entries) {
                buf.writeVarInt(e.objId);
                ResourceLocation.STREAM_CODEC.encode(buf, e.typeKey);
                buf.writeDouble(e.posX);
                buf.writeDouble(e.posY);
                buf.writeDouble(e.posZ);
                buf.writeDouble(e.velX);
                buf.writeDouble(e.velY);
                buf.writeDouble(e.velZ);
            }
        }
    };
```

### 7.3 服务端广播

```java
public static void broadcast(ServerLevel level, List<Integer> batchIds,
        ProjectileManager pm, Map<Integer, DestroyableObject> objMap) {
    List<SpawnEntry> entries = new ArrayList<>(batchIds.size());
    for (int objId : batchIds) {
        DestroyableObject obj = objMap != null ? objMap.get(objId) : null;
        if (!(obj instanceof IProjectile proj)) continue;

        Vector3f pos = proj.getPosition();   // 构造初始值，preTick 时尚未被覆写
        Vector3f vel = proj.getVelocity();
        ResourceLocation typeKey = proj.getProjectileType().getRegistryKey();

        entries.add(new SpawnEntry(objId, typeKey,
            pos.x, pos.y, pos.z, vel.x, vel.y, vel.z));
    }
    if (!entries.isEmpty()) {
        PacketDistributor.sendToPlayersInDimension(level,
            new ProjectileBatchSpawnPayload(entries));
    }
}
```

### 7.4 客户端处理

```java
public static void handle(ProjectileBatchSpawnPayload payload, IPayloadContext ctx) {
    ctx.enqueueWork(() -> {
        Level level = ctx.player().level();
        for (SpawnEntry entry : payload.entries) {
            ProjectileType type = ProjectileType.get(level, entry.typeKey);
            if (type == null) continue;
            Vector3f pos = new Vector3f(
                (float) entry.posX, (float) entry.posY, (float) entry.posZ);
            Vector3f vel = new Vector3f(
                (float) entry.velX, (float) entry.velY, (float) entry.velZ);
            // create → addToLevel: ObjectManager注册 + SoA写入 + playFireSound
            type.create(level, pos, vel);
        }
    });
}
```

客户端逐条调用 `type.create()` → `addToLevel()`，每条播放一次开火音效、写入 SoA 供渲染器读取。

### 7.5 带宽对比

Minecraft 每个网络包在线路上有固定的帧头：

```
[VarInt 包体总长] [VarInt 包ID] [String payload_identifier] [payload 数据]
```

以 `machine_max:projectile_spawn`（31 字符）为例，每包帧头 = VarInt(2) + VarInt(1) + String(31) = 34 字节。

**单条 entry 数据**（payload 部分）：

| 字段 | 旧 `ProjectileSpawnPayload` | 新 `SpawnEntry` |
|------|---------------------------|-----------------|
| objId | VarInt ≈ 1B | VarInt ≈ 1B |
| typeKey | String(RL) ≈ 22B | String(RL) ≈ 22B |
| pos/vel | double×6 = 48B | double×6 = 48B |
| maxLifetime | int = 4B | —（客户端从 type 读） |
| isRigid | boolean = 1B | —（客户端从 type 读） |
| **单条 payload 合计** | **76B** | **71B** |

**10 发投射物对比**：

| 方案 | 计算 | 总字节 |
|------|------|--------|
| 旧：10 个独立 `ProjectileSpawnPayload` | 10 × (34B 帧头 + 76B payload) | **1100B** |
| 新：1 个 `ProjectileBatchSpawnPayload` | 35B 帧头 + VarInt(10) + 10 × 71B | **745B** |

**节省 355B（约 32%）**，且随批量增大比例更高。核心收益来自消除 9 个重复的帧头开销（9 × 34B = 306B）。
