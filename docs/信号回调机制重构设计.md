# 信号回调机制重构设计

> 状态：草案（v2，已吸收外部审查意见）
> 分支：1.21.1
> 目标：消除`发送方`→`遍历全部目标`→`收集终端`→`批量回调`的绕圈逻辑，改为"向每个目标发送后该目标立即自主回调"的直送模式。

---

## 1. 现状诊断

### 1.1 当前回调流程（绕圈问题）

```
handShake()
  └─ sendSignalToAllTargetsWithCallback(channel, EmptySignal, false)
       └─ sendSignalToTarget(channel, targetName, EmptySignal, true, false)
            ├─ 写入 receiver.inputChannels + onSignalUpdated(channel, sender)     ← 信号到达
            ├─ collectTerminalTargets(signalReceiver, ...)                        ← 递归收集终端
            └─ 每个终端: sendCallbackToListener("callback", sender, channel)       ← 最后才回调
```

**问题**：

1. **语义倒置**：先遍历所有目标发送完信号，再回头收集终端发回调。`CarControllerSubsystem` 在 `onSignalUpdated("callback", engine)` 中 `addCallbackTarget(controlChannel, engine)` 本应是一次回调就完成的事，却被延后到全部目标遍历完后才触发。
2. **`collectTerminalTargets` 在 `ISignalBus` 分支的局限性**：已在 `ISignalSender.java:233-238` 中添加了 `ISignalBus` 识别分支，能递归收集所有订阅者。但该方案依然是**先全部写入再批量回调**，本质绕圈逻辑未变。

### 1.2 核心使用场景：握手-发现

五处子系统在 `onAttach` / `onVehicleStructureChanged` 时发握手信号：

| 发起者 | 频道来源 | 期望发现的接收者 |
|--------|---------|----------------|
| `CarControllerSubsystem` | `attr.controlOutputTargets.keySet()` | Engine / Motor / Gearbox / WheelDriver |
| `WeaponControllerSubsystem` | `attr.controlOutputTargets.keySet()` | TurretDriver / Launcher |
| `AmmoLoaderSubsystem` | `attr.discoveryOutputs.keySet()` | IAmmoConsumer |
| `RegenLoaderSubsystem` | `attr.discoveryOutputs.keySet()` | IAmmoConsumer |
| `AbstractControllableSubsystem` | `cameraDiscoveryTargets.keySet()` | CameraSubsystem |

**期望行为**：每发现一个终端，终端立即 `sendCallbackToListener("callback", 发起者, controlChannel)`，发起者在 `onSignalUpdated("callback", terminal)` 中补全内部连接表。

## 2. 方案

### 2.1 核心思路

在 `ISignalReceiver` 上新增 `respondCallbackToSender()` — 在 `onSignalUpdated()` **之前**独立执行。信号接收者自行决定是否/如何向发送者回传 callback，调用方无需关心接收者的内部转发拓扑（Port → Port → 终端）。

### 2.2 方法签名

```java
/**
 * 接收到信号后、onSignalUpdated 之前，按需向发送者回传 callback。
 *
 * 默认行为：若 requiresImmediateCallback=true 且发送者(this)均为有效 ISignalReceiver/ISignalSender，
 * 则通过 sendCallbackToListener 向发送者回传 "callback"。
 *
 * 覆写规则：
 *   - 普通子系统：不覆写，默认自动回传
 *   - SignalPort：覆写为空（端口仅是信道，不应作为终端发声）
 *   - SubsystemController：覆写，转发到所有订阅者（详见 §2.5）
 */
default void respondCallbackToSender(
        String channelName, ISignalSender sender, Object value,
        boolean requiresImmediateCallback, boolean callbackReturnsSignalValue) {
    if (requiresImmediateCallback && sender instanceof ISignalReceiver cbTarget
            && this instanceof ISignalSender cbSender) {
        Object cbValue = callbackReturnsSignalValue ? value : channelName;
        cbSender.sendCallbackToListener("callback", cbTarget, cbValue);
    }
}
```

### 2.3 调用链变化

```
修改前:
  sendSignalToTarget → onSignalUpdated → collectTerminalTargets → 逐个 sendCallbackToListener

修改后:
  sendSignalToTarget → respondCallbackToSender → onSignalUpdated  (respondCallbackToSender 内部直送 callback)
  broadcast          → onSignalUpdated                             (不负责回调，回调由更上层的 sendSignalToTarget 链处理)
```

```
sendSignalToTarget(channel, targetName, val, requiresCb=true, cbRetsValue)
  ├─ 写入 receiver.inputChannels
  ├─ receiver.respondCallbackToSender(channel, sender, val, requiresCb, cbRetsValue)  ← 新
  └─ receiver.onSignalUpdated(channel, sender)
      └─ (若 receiver 是 SubsystemController) broadcast(channel, val, sender)
           └─ 回调已由 §2.5 的 respondCallbackToSender 在广播前完成，broadcast 不感知回调
```

### 2.4 递归/循环防护

`respondCallbackToSender` → `sendCallbackToListener` → `onSignalUpdated("callback", ...)` 可能构成回调链。虽然当前所有 `onSignalUpdated("callback", ...)` 实现均不触发新一次带回调的 `sendSignalToTarget`，但为安全起见增加防护。

新增 ThreadLocal 防护（在 `ISignalReceiver` 接口上）：

```java
/** 防止 respondCallbackToSender → sendCallbackToListener → onSignalUpdated → … 形成循环 */
ThreadLocal<Set<ISignalSender>> CALLBACK_GUARD = ThreadLocal.withInitial(HashSet::new);
```

在 `respondCallbackToSender` 默认实现开头检查：

```java
default void respondCallbackToSender(
        String channelName, ISignalSender sender, Object value,
        boolean requiresImmediateCallback, boolean callbackReturnsSignalValue) {
    if (!requiresImmediateCallback) return;
    Set<ISignalSender> guard = CALLBACK_GUARD.get();
    if (!guard.add((ISignalSender) this)) {
        // 同一线程的回调链中出现循环触发，属编程错误，应修复调用方逻辑
        MachineMax.LOGGER.error(
            "信号回调循环触发！channel={}, sender={}, receiver={}, guard={}。" +
            "同一调用链中 {} 被重复要求回传 callback，跳过以避免栈溢出。" +
            "当前调用栈如下（供定位循环路径）：",
            channelName, sender.getClass().getSimpleName(), this.getClass().getSimpleName(),
            guard.stream().map(Object::getClass).map(Class::getSimpleName).toList(),
            this.getClass().getSimpleName(),
            new Exception("回调循环调用栈"));  // ← 附加栈追踪，SLF4J 会自动打印
        return;
    }
    try {
        if (sender instanceof ISignalReceiver cbTarget && this instanceof ISignalSender cbSender) {
            Object cbValue = callbackReturnsSignalValue ? value : channelName;
            cbSender.sendCallbackToListener("callback", cbTarget, cbValue);
        }
    } finally {
        guard.remove((ISignalSender) this);
    }
}
```

**原理**：用 `Set<ISignalSender>` 存 `this`（当前正在回传 callback 的接收者），利用引用比较（`HashSet` 的 `equals` 对接口默认为 `==`）。同一线程的回调链中，若同一接收者被第二次要求回传，直接跳过并打 error 日志。
```

### 2.5 SubsystemController — 关键覆写

这是整个设计的**核心难点**。SubsystemController 不覆写会导致 sender=Controller 的错误 callback；覆写为空又会导致 callback 丢失。

**方案 A（采用）**：`SubsystemController` 覆写 `respondCallbackToSender`，遍历所有订阅了该频道的订阅者，将回调请求转发给它们。

```java
@Override
public void respondCallbackToSender(
        String channelName, ISignalSender sender, Object value,
        boolean requiresImmediateCallback, boolean callbackReturnsSignalValue) {
    if (!requiresImmediateCallback) return;
    // 向所有接受此频道的订阅者转发回调请求
    // 每个订阅者的 respondCallbackToSender 自行决定是否/如何回传
    for (ISignalReceiver sub : getAllSubscribers()) {
        if (sub.acceptAllBroadcastInput() || sub.getAcceptedChannels().contains(channelName)) {
            sub.respondCallbackToSender(channelName, sender, value,
                    requiresImmediateCallback, callbackReturnsSignalValue);
        }
    }
}
```

**语义说明**：`respondCallbackToSender` 先于 `onSignalUpdated` 执行。SubsystemController 转发回调请求时，订阅者的 inputChannels 中尚未写入该信号——信号写入发生在后续 `broadcast()` 中。但这对回调本身**无影响**，因为 `respondCallbackToSender` 不读取接收者自身的 inputChannels，它只做两件事：

1. 检查 `requiresImmediateCallback` 和 `this instanceof ISignalSender`
2. 调用 `sendCallbackToListener("callback", originalSender, cbValue)`

而 `sendCallbackToListener` 写入的是**原始发送者的** inputChannels，与订阅者自身的数据无关。

### 2.6 SignalPort 透传 — 必须递归转发

`SignalPort.onSignalUpdated()` 收到信号后，内部转发时直接调用 `target.onSignalUpdated()`，**绕过了 `sendSignalToTarget`**，不会经过 `respondCallbackToSender`。

若 `SignalPort.respondCallbackToSender` 为空，终端接收者（Engine）的回调会被**吞掉**：

```
sendSignalToTarget → PortA.respondCallbackToSender(空) → PortA.onSignalUpdated
                                                             └─ PortB.onSignalUpdated
                                                                  └─ Engine.onSignalUpdated  ← 没有 respondCallbackToSender！
```

**正确做法**：`SignalPort` 应递归穿透到下一跳目标，而非静默：

```java
@Override
public void respondCallbackToSender(
        String channelName, ISignalSender sender, Object value,
        boolean requiresImmediateCallback, boolean callbackReturnsSignalValue) {
    if (!requiresImmediateCallback) return;
    // 穿透到对侧端口的下一跳目标，递归触发它们的 respondCallbackToSender
    if (owner instanceof AbstractConnector ownerConnector
            && ownerConnector.attachedConnector != null
            && ownerConnector.attachedConnector.signalPort instanceof SignalPort otherPort) {
        String translated = otherPort.translateChannel(channelName);
        Map<String, ISignalReceiver> targets = otherPort.getTargets().get(translated);
        if (targets != null) {
            for (ISignalReceiver target : targets.values()) {
                target.respondCallbackToSender(channelName, sender, value,
                        requiresImmediateCallback, callbackReturnsSignalValue);
            }
        }
    }
}
```

改写后链路（不会重复——`respondCallbackToSender` 只在 `sendSignalToTarget` 最外层调用一次，Port 内部转发走 `onSignalUpdated`，两者不重叠）：

```
Sender → PortA.respondCallbackToSender → 穿透 → PortB.respondCallbackToSender → 穿透 → Engine.respondCallbackToSender → callback ✓
```

### 2.7 各类型覆写汇总

| 接收者 | `respondCallbackToSender` | 理由 |
|--------|--------------------------|------|
| 普通子系统（Engine / Wheel 等） | **不覆写** | 默认自动回传 |
| `SignalPort` | **覆写**，递归穿透到下一跳目标 | Port 不应作为终端发声，但必须将回调请求传给终端 |
| `SubsystemController` | **覆写**，转发给订阅者 | §2.5 |
| `ScriptableSubsystem` | super + `Hook.run(this, channelName, sender)` | 保持与现有模式一致 |

## 3. 详细改动清单

### 3.1 `ISignalReceiver.java` — 新增 `respondCallbackToSender` + `CallbackGuard`

新增 `respondCallbackToSender` default 方法（见 §2.2），内含 `CALLBACK_GUARD` 防循环（§2.4）。

### 3.2 `ISignalSender.java` — 插入 `respondCallbackToSender`，删除旧回调循环

**在 `sendSignalToTarget()` 中**，`onSignalUpdated` 调用之前插入一行：

```java
signalReceiver.getSignalInputChannels()
        .computeIfAbsent(signalChannel, k -> new SignalChannel())
        .put(this, signalValue);
// …… signalStorage 写入等现有代码 ……
signalReceiver.respondCallbackToSender(signalChannel, this, signalValue,        // ← 新增
        requiresImmediateCallback, callbackReturnsSignalValue);                 // ← 新增
SignalResult result = signalReceiver.onSignalUpdated(signalChannel, this);
```

**删除**：`sendSignalToTarget()` 中第 152-165 行的旧回调循环（`collectTerminalTargets` + for 循环）。

**删除**：`collectTerminalTargets` 方法整体（`ISignalSender.java:213-236`）。

### 3.3 `ISignalBus.java` — `broadcast()` 恢复 3 参数

`broadcast()` 不负责回调——回调由 `sendSignalToTarget` → `SubsystemController.respondCallbackToSender` 路径处理，广播时回调已完成。

同时清理 `ISignalBus` 接口 Javadoc 和注释中关于回调的描述（`broadcast() 在运行时检查…` 等）。

```java
/**
 * 将信号广播给所有接受此频道的订阅者。
 * 遍历所有订阅者，检查其声明的接受条件后决定是否转发。
 *
 * @param channel        信号频道名
 * @param value          信号值
 * @param originalSender 原始发送者（保留身份，使接收方能区分信号来源）
 */
default void broadcast(String channel, Object value, ISignalSender originalSender) {
    for (ISignalReceiver sub : getAllSubscribers()) {
        if (sub.acceptAllBroadcastInput() || sub.getAcceptedChannels().contains(channel)) {
            sub.getSignalInputChannels()
                    .computeIfAbsent(channel, k -> new SignalChannel())
                    .put(originalSender, value);
            sub.onSignalUpdated(channel, originalSender);
        }
    }
}
```

## 4. 修改前后完整对比

### 4.1 握手场景 (CarController → Engine 发现)

**修改前**：
```java
CarController.handShake()
  sendSignalToAllTargetsWithCallback("engine", EmptySignal, false)
    sendSignalToTarget("engine", "vehicle", EmptySignal, true, false)
      SubsystemController.onSignalUpdated("engine", carController)
        broadcast("engine", EmptySignal, carController)
          Engine.onSignalUpdated("engine", carController)   ← 收到但无回调
          Wheel.onSignalUpdated("engine", carController)
      collectTerminalTargets(SubsystemController) → [SubsystemController]
      仅 SubsystemController.sendCallbackToListener("callback", carController, "engine")  ← sender 是控制器，不是 Engine
```

**修改后**：
```java
CarController.handShake()
  sendSignalToAllTargetsWithCallback("engine", EmptySignal, false)
    sendSignalToTarget("engine", "vehicle", EmptySignal, true, false)
      ├─ 写入 SubsystemController.inputChannels["engine"][carController] = EmptySignal
      ├─ SubsystemController.respondCallbackToSender("engine", carController, EmptySignal, true, false)
      │    └─ 遍历订阅者 → Engine.respondCallbackToSender("engine", carController, EmptySignal, true, false)
      │         └─ sendCallbackToListener("callback", carController, "engine")
      │              ├─ carController.inputChannels["callback"][engine] = "engine"
      │              └─ carController.onSignalUpdated("callback", engine)
      │                   └─ engines.put(engine, "engine")  ← 发现完成 ✓
      │         └─ Wheel.respondCallbackToSender(...) → sendCallbackToListener → carController.onSignalUpdated("callback", wheel) → wheels.put(wheel, "engine")
      └─ SubsystemController.onSignalUpdated("engine", carController)
           └─ broadcast("engine", EmptySignal, carController)
                ├─ Engine.inputChannels["engine"][carController] = EmptySignal
                │   Engine.onSignalUpdated("engine", carController)
                └─ Wheel.inputChannels["engine"][carController] = EmptySignal
                    Wheel.onSignalUpdated("engine", carController)
```

### 4.2 跨 Port 回调路径（多跳）

```
CarController  ─PortA──PortB──→  Engine
```

**修改后**：
```java
sendSignalToTarget("engine", portA, val, true, false)
  ├─ PortA.respondCallbackToSender("engine", carController, val, true, false)
  │    └─ 穿透到对侧 → PortB 的目标 → Engine
  │         └─ Engine.respondCallbackToSender("engine", carController, val, true, false)
  │              └─ sendCallbackToListener("callback", carController, "engine")
  │                   └─ carController.onSignalUpdated("callback", engine)  ✓ sender 是 Engine
  └─ PortA.onSignalUpdated("engine", carController)
       └─ 转发到 PortB
            └─ PortB.onSignalUpdated("engine", carController)
                 └─ 转发到 Engine
                      └─ Engine.onSignalUpdated("engine", carController)
```

多跳 Port 递归穿透后回调直达终端 Engine，Port 自身不发声。

## 6. 验证标准

1. **`./gradlew build` 编译通过，无错误**
2. **握手发现流程正确**：载具组装后，`CarControllerSubsystem` 能发现所有连接的引擎、变速箱、车轮
3. **跨 Port 回调正确**：信号跨越一对连接点传播后，回调的 sender 是终端子系统而非 SignalPort
4. **总线广播回调正确**：通过 "vehicle" 目标广播的信号，各订阅者回传 callback 的 sender 是订阅者自身而非 SubsystemController
5. **无递归/循环**：`CALLBACK_GUARD` 能阻断任何潜在的回调链路循环
6. **无回归**：点对点路由（非总线）的现有行为不变
