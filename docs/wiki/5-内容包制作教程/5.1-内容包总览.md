# 5.1 内容包总览

内容包（Content Pack）是 MachineMax 面向 UGC 作者提供的数据驱动扩展机制，与原版的资源包和数据包系统高度类似。通过内容包，你可以不编写任何 Java 代码，仅靠 JSON 配置文件与资源文件来添加新的零件、子系统、材料、配方以及完整的载具。本章作为内容包制作教程的开篇，先介绍内容包的基本构成、目录规范和依赖管理方式。

## 内容包是什么

MachineMax 的零件类型、子系统属性、材料、配方等数据全部以 JSON 配置文件的形式存储，而这些文件通过内容包被模组加载。内容包本质上是一个按特定目录结构组织的文件集合，可以以**目录**或 **.zip 压缩包**两种形式存在，放置在游戏目录下的 `spark_modules/` 文件夹内。

这一机制由 Spark-Core 核心库提供。模组启动或执行 `/spark package reload` 命令时，Spark-Core 会扫描 `spark_modules/` 下的所有内容包，读取其中的文件并提供给 MachineMax 注册。

## 内容包的构成

一个内容包由以下两部分组成：

### 1. 元数据文件（meta.json）

每个内容包的根目录下必须包含一个 `meta.json` 文件，用于声明包的基本信息和依赖关系。其完整结构如下：

```json
{
  "id": "example:my_pack",
  "version": "1.0.0",
  "name": "示例内容包",
  "author": "YourName",
  "description": "这是一个示例内容包。",
  "dependencies": [
    { "id": "machine_max:base", "type": "hard" }
  ]
}
```

| 字段             | 类型     | 必需 | 说明                                         |
| -------------- | ------ | -- | ------------------------------------------ |
| `id`           | 命名空间ID | 是  | 内容包的唯一标识符，格式为 `namespace:pack_id`。不得与其他包重复 |
| `version`      | 字符串    | 否  | 包的版本号，默认 `"1.0"`                           |
| `name`         | 文本组件   | 否  | 包的显示名称，支持 Minecraft 原始 JSON 文本格式           |
| `author`       | 文本组件   | 否  | 作者信息                                       |
| `description`  | 文本组件   | 否  | 包的描述文本                                     |
| `dependencies` | 数组     | 否  | 依赖声明列表，详见下文                                |

### 2. 模块目录（功能文件）

`meta.json` 之外的所有内容按 **命名空间 → 模块名 → 文件路径** 的三层结构组织。第一层目录名即为命名空间（如 `machine_max`），第二层目录名对应一个模块类型（如 `parts`），第三层及更深则为该模块下的具体 JSON 或资源文件。

以 MachineMax 官方内容包为例，一个典型的目录结构如下：

```
spark_modules/
└── machine_max.default/            ← 内容包根目录（目录形式）
    ├── meta.json                   ← 元数据文件
    └── machine_max/                ← 命名空间（第一层）
        ├── parts/                  ← 零件定义模块
        │   ├── chassis.json
        │   └── engine.json
        ├── connectors/             ← 连接点定义模块
        │   └── simple_connector.json
        ├── subsystems/             ← 子系统定义模块
        │   ├── engine_v8.json
        │   └── seat_single.json
        ├── materials/              ← 材料定义模块
        │   └── steel.json
        ├── control_groups/         ← 控制组预设模块
        │   ├── default_driver.json
        │   └── default_gunner.json
        ├── templates/              ← 已组装结构数据模块
        ├── blueprints/             ← 蓝图数据模块
        ├── assemblies/             ← 装配体数据模块
        ├── tooltips/               ← 物品描述模块
        ├── hud/                    ← 自定义HUD配置模块
        ├── colors/                 ← 自定义色彩合集模块
        ├── recipe/                 ← 配方模块
        ├── models/                 ← 基岩版几何模型模块
        ├── textures/               ← 贴图资源模块
        ├── animations/             ← 骨骼动画模块
        ├── animation_controllers/  ← 动画控制器模块
        └── lang/                   ← 语言翻译模块
```

> **注意**：内容包也可以打包为 `.zip` 文件（如 `machine_max.default.zip`），内部保持相同的目录结构。模组对目录形式和压缩包形式的加载方式完全等效。

## 内容包的模块一览

MachineMax 内容包涉及的所有模块及其用途如下：

| 模块名                     | 用途                                      | 对应教程                           |
| ----------------------- | --------------------------------------- | ------------------------------ |
| `parts`                 | 定义零件类型（PartType），包括子零件、碰撞体、连接点挂载、子系统挂载等 | [5.3 零件定义](5.3-零件定义.md)           |
| `connectors`            | 定义连接点的静态属性，包括简单连接点和高级连接点的关节参数           | [5.4 连接点定义](5.4-连接点定义.md)         |
| `subsystems`            | 定义子系统型号的静态属性，如某型号发动机的功率曲线、某型号变速箱的减速比    | [5.5 子系统定义](5.5-子系统定义.md)         |
| `materials`             | 定义材料的物理和其他属性，用于零件的物理表现和伤害机制             | [5.6 材料定义](5.6-材料定义.md)           |
| `templates`             | 预组装的载具结构数据，可直接作为蓝图来源                    | [5.7 模板、蓝图与装配体](5.7-模板、蓝图与装配体.md) |
| `blueprints`            | 完整的载具蓝图数据，可被蓝图物品引用，出现在创造模式物品栏           | [5.7 模板、蓝图与装配体](5.7-模板、蓝图与装配体.md) |
| `assemblies`            | 装配体数据，可被装配体物品引用，出现在创造模式物品栏              | [5.7 模板、蓝图与装配体](5.7-模板、蓝图与装配体.md) |
| `tooltips`              | 物品的文本描述信息，用于蓝图物品和装配体物品的悬浮提示             | [5.9 辅助模块](5.9-辅助模块.md)           |
| `hud`                   | 自定义 HUD（抬头显示）的布局和样式定义                   | [5.9 辅助模块](5.9-辅助模块.md)           |
| `control_groups`        | 控制组预设，定义座舱按键到信号的映射                     | [5.9 辅助模块](5.9-辅助模块.md)           |
| `colors`                | 自定义色彩合集，用于统一管理涂装等颜色方案                   | [5.9 辅助模块](5.9-辅助模块.md)           |
| `recipe`                | 配方定义（制造配方、研发配方、蓝图研发配方等）                 | [5.8 研发与制造配方](5.8-研发与制造配方.md)     |
| `models`                | 基岩版模型文件（`minecraft:geometry` 格式）        | [5.2 模型与动画](5.2-模型与动画.md)         |
| `textures`              | 贴图资源文件（.png）                            | [5.9 辅助模块](5.9-辅助模块.md)           |
| `animations`            | 基岩版骨骼动画文件                               | [5.2 模型与动画](5.2-模型与动画.md)         |
| `animation_controllers` | 动画控制器（动画状态机）文件                          | [5.2 模型与动画](5.2-模型与动画.md)         |
| `lang`                  | 语言翻译文件，为自定义零件和物品提供本地化文本                 | [5.9 辅助模块](5.9-辅助模块.md)           |

## 内容包的依赖关系

内容包之间可以通过 `meta.json` 中的 `dependencies` 字段声明依赖关系。当多个内容包同时存在时，Spark-Core 会根据依赖关系自动解析加载顺序，确保依赖的包先于被依赖的包加载。

### 依赖类型

每条依赖声明包含 `id`（目标包的标识符）和 `type`（依赖类型）。支持以下四种类型：

| 类型         | 说明                                          |
| ---------- | ------------------------------------------- |
| `hard`     | **硬依赖**：目标包必须在当前包之前加载。如果目标包缺失，当前包将导致加载错误    |
| `soft`     | **软依赖**：建议目标包在当前包之前加载。如果目标包缺失，仅输出一条警告，不影响加载 |
| `override` | **覆盖依赖**：当前包将覆盖目标包中同路径的文件内容                 |
| `conflict` | **冲突依赖**：当前包与目标包不能同时加载。如果目标包存在，将导致加载错误      |

### 使用示例

```json
{
  "id": "example:extended_parts",
  "version": "1.0",
  "name": "扩展零件包",
  "dependencies": [
    { "id": "machine_max:base", "type": "hard" },
    { "id": "other_author:shared_materials", "type": "soft" }
  ]
}
```

上述配置表示 `example:extended_parts` 必须依赖 `machine_max:base` 才能工作（硬依赖），同时建议加载 `other_author:shared_materials` 以获得额外材料（软依赖）。

依赖图使用**深度优先搜索**进行拓扑排序，确保所有硬依赖链上的包都在当前包之前完成加载。如果有循环依赖或缺失的硬依赖，加载过程会报错。

### 加载模式

每个模块还有一个**读取模式**（`ReadMode`），影响该模块数据在客户端与服务端之间的传输行为：

| 模式                  | 说明                                           |
| ------------------- | -------------------------------------------- |
| `SERVER_TO_CLIENT`  | 以服务端数据为准，服务端读取后同步到客户端。适用于配方、零件定义等需要保证双端一致的数据 |
| `LOCAL_ONLY`        | 双端各自读取本地文件，不进行跨端同步。适用于材料、贴图等纯本地的数据           |
| `CLIENT_LOCAL_ONLY` | 只有客户端读取本地文件，服务端不参与。适用于 HUD 配置等纯客户端数据         |

对于 UGC 作者来说，不需要手动指定读取模式——MachineMax 已为每种模块类型预设了合适的模式。了解这一机制有助于理解为什么某些文件只在客户端或服务端生效。

## 快速开始：创建最小内容包

以下是一个最小内容包的完整结构，它只添加一个自定义零件类型：

```
spark_modules/
└── my_first_pack/
    ├── meta.json
    └── my_mod/
        ├── parts/
        │   └── custom_chassis.json
        └── lang/
            └── zh_cn.json
```

**meta.json**：

```json
{
  "id": "my_mod:my_first_pack",
  "version": "1.0.0",
  "name": "我的第一个内容包",
  "author": "YourName",
  "dependencies": [
    { "id": "machine_max:base", "type": "hard" }
  ]
}
```

将 `my_first_pack` 文件夹放入游戏目录的 `spark_modules/` 文件夹下，启动游戏或执行 `/spark:package reload` 即可加载。具体的零件定义写法详见后续各节。
