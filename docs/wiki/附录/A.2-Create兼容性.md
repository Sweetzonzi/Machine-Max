# A.2 Create 模组兼容性

MachineMax 与机械动力（Create）之间目前存在**有限兼容**。对玩家来说，可以把它理解为：部分动态结构能够与 MachineMax 载具共存或发生基础交互，但这并不意味着所有 Create 扩展内容都已经完成适配。

本页主要说明目前已经明确的兼容范围，以及暂不支持的内容。

## 当前兼容范围

目前，MachineMax 载具可以与部分 Create 的动态结构发生物理层面的接触与碰撞。这意味着在一些常见场景下，Create 设备和 MachineMax 载具可以同时出现在同一世界中，而不会因为基础加载关系直接冲突。

不过，这种兼容主要应理解为“已有基础交互”，而不是“所有 Create 运动实体都经过了专门适配”。如果你的整合包玩法高度依赖复杂动态结构，仍然建议在正式游玩前先做场景测试。

## 明确不支持的内容

以下内容目前不在支持范围内，使用时需要特别注意。

### Create 火车

目前**不支持机械动力的火车系统**。

更具体地说，MachineMax 目前**不会与 Create 火车产生正常碰撞**。玩家不应期待以下行为能够正常成立：

- MachineMax 载具与火车之间进行可靠的实体碰撞
- 火车对 MachineMax 载具产生完整的物理阻挡
- 利用火车与载具之间的碰撞实现稳定的玩法机制

如果你的玩法依赖列车撞击、阻挡、推挤或轨道上的物理互动，那么目前不建议将 MachineMax 载具与 Create 火车混合使用。

### 航空学扩展 / Sable 的物理化结构

目前**不支持航空学扩展 / Sable 的物理化结构**。

这一部分既**没有经过专门测试**，也**没有编写兼容逻辑**。因此在实际运行中，结果通常是不确定的：

- 运气较好时，双方可能只是**没有碰撞**，表现为彼此穿过或互不作用。
- 运气较差时，则可能出现**报错、异常行为，甚至直接崩溃**。

换句话说，现阶段不应把这类结构视为可用的兼容对象，也不建议在正式存档或服务器环境中直接投入使用。

## 使用建议

如果你只是普通玩家，最稳妥的做法是：

- 将 MachineMax 与 Create 的兼容理解为“部分支持”，不要默认所有运动结构都可正常交互。
- 遇到火车系统时，默认按“无碰撞”处理。
- 遇到航空学扩展 / Sable 的物理化结构时，默认按“未兼容、存在崩溃风险”处理。

如果你是整合包作者或服务器管理员，则更建议在投放前单独测试以下场景：

- MachineMax 载具靠近或穿过 Create 火车时的表现
- MachineMax 载具接触航空学扩展 / Sable 物理结构时的稳定性
- 多玩家同时加载相关区域时是否出现额外问题

在当前阶段，MachineMax 与 Create 的兼容重点仍然是基础共存与部分动态结构交互，而不是完整覆盖所有衍生系统。对玩家而言，最重要的是提前知道哪些内容“可以尝试”，哪些内容“暂时不要依赖”。
