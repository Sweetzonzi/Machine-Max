# Machine-Max 武器系统 — 组件化投射物与类型体系设计

> 状态：设计阶段
> 创建时间：2026-06-27
> 上级文档：`武器系统-数据驱动投射物设计文档.md`（阶段一/二已实现）
> 配套文档：`武器系统-光束系统详细设计.md`

## 一、背景与动机

现有投射物系统（阶段一/二）聚焦纯动能弹丸，`ProjectileType` 为单一扁平结构，所有字段由 `RecordCodecBuilder` 平铺定义。随着武器种类的扩展，需要支持：

| 需求 | 说明 |
|------|------|
| **制导弹药** | 导引头（红外/雷达/激光）+ 制导律（比例导引/纯追逐） |
| **引信多样化** | 碰炸 / 延时 / 近炸，控制触发时机 |
| **战斗部效果** | 爆炸 / 破片（子投射物） / 烟雾 / 毒气 / EMP |
| **光束武器** | 脉冲激光（瞬时），持续照射激光（连续伤害），距离衰减穿深模型 |
| **数据驱动** | 内容包创作者通过 JSON 定义全部参数，无需 Java 代码 |
| **向后兼容** | 现有 `point` / `rigid` JSON 无需修改 |

核心设计决策：**按运动模型分派 Codec（dispatch），按行为能力组合组件（optional sub-objects）**。

## 二、类型体系：Codec Dispatch 分派

### 2.1 顶层设计

`ProjectileType` 从具体类变为 **abstract class**，通过 `Codec.dispatch()` 按 `"type"` 字段分派到子类：

```
ProjectileType (abstract, dispatch on "type")
│
├── KineticProjectileType     ← type: "point" | "rigid"
│   │   运动模型：飞行弹丸
│   │   管理器：ProjectileManager（物理线程 SoA）
│   │   发射器：LauncherSubsystem
│   │   有代理实体 (MMProjectileEntity)
│   │   速度-伤害幂函数模型
│   │
│   └── 可组合的行为组件：
│       seeker? / guidance? / fuze? / warhead?
│
└── RayProjectileType        ← type: "pulse" | "beam"
    │   运动模型：射线（瞬时或持续照射）
    │   管理器：RayManager（主线程）
    │   发射器：RayLauncherSubsystem
    │   无代理实体
    │   距离衰减穿深/伤害模型
    │
    └── 仅 `warhead` 组件可用
```

### 2.2 Codec 实现

```java
public static final Codec<ProjectileType> CODEC = Codec.STRING.dispatch(
    "type",
    ProjectileType::getSerializedName,
    name -> switch (name) {
        case "point", "rigid" -> KineticProjectileType.CODEC;
        case "pulse", "beam"  -> RayProjectileType.CODEC;
        default -> throw new IllegalArgumentException("未知投射物类型: " + name);
    }
);
```

- `point` / `rigid` / `pulse` / `beam` 是 JSON 中的用户可见字符串
- `point` 和 `rigid` 路由到同一个 `KineticProjectileType`（内部 `ProjectileTypeEnum` 区分）
- `pulse` 和 `beam` 路由到同一个 `RayProjectileType`（内部 `RayAttr.durationSeconds` 区分）

### 2.3 共享字段

所有 `ProjectileType` 子类保留这些平级字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `tags` | `List<ResourceLocation>` | 弹药标签，与发射器的 required_tags / acceptable_tags / forbidden_tags 匹配 |
| `maxLifetime` | float | 最大存活时间（秒），对光束为燃料/持续时间上限 |
| `bulletNum` | int | 单发弹丸数 |
| `visual` | VisualProperties (子类化) | 视觉属性 |
| `sounds` | ProjectileSoundAttr (子类化) | 音效属性 |

## 三、KineticProjectileType — 飞行弹丸

### 3.1 字段结构

```java
public class KineticProjectileType extends ProjectileType {
    ProjectileTypeEnum typeEnum;              // POINT / RIGID
    ExternalProperties external;              // 质量、阻力、重力、初速...
    TerminalProperties terminal;              // 速度-穿深/伤害模型
    @Nullable SeekerAttr seeker;            // 导引头
    @Nullable GuidanceAttr guidance;        // 制导律
    @Nullable FuzeAttr fuze;                // 引信
    @Nullable WarheadAttr warhead;          // 战斗部
    VisualProperties visual;
    ProjectileSoundAttr sounds;
}
```

### 3.2 ExternalProperties（现有，不变）

| 字段 | 默认值 | 说明 |
|------|--------|------|
| `mass` | 必填 | 质量（kg） |
| `gravity_factor` | 1.0 | 重力系数 |
| `drag_factor` | 0 | 空气阻力系数 |
| `radius` | 0.05 | 碰撞半径（m） |
| `base_velocity` | 必填 | 参考速度（m/s） |
| `base_accuracy_mil` | 5.0 | 精度（密位） |

### 3.3 TerminalProperties（现有，不变）

| 字段 | 默认值 | 说明 |
|------|--------|------|
| `base_penetration` | 必填 | 参考速度下穿深（mm RHA） |
| `base_damage` | 必填 | 参考速度下伤害 |
| `penetration_velocity_coefficient` | 0 | 穿深速度系数（德马尔≈1.43） |
| `damage_velocity_coefficient` | 0 | 伤害速度系数 |
| `block_damage_factor` | 1.0 | 方块破坏因子 |

速度-伤害模型：`effective = base × (speed / baseVelocity)^coefficient`（系数为 0 时退化常数）

## 四、行为组件设计

### 4.1 SeekerAttr — 导引头

决定投射物**如何获取目标位置**。`seeker` 字段缺失 → 纯弹道飞行。

```java
public record SeekerAttr(
    /// 导引头类型
    SeekerType type,
    /// 视场角（度）
    float fovDegrees,
    /// 锁定距离（米）
    float lockRange,
    /// 最大跟踪角速率（度/秒）
    float maxTrackRateDps,
    /// 最小热对比度（仅红外有效）
    float minContrast,
    /// 是否抗诱饵（仅红外有效）
    boolean rejectFlares
) {
    public enum SeekerType {
        INFRARED,            // 被动红外
        RADAR,               // 主动雷达
        SEMI_ACTIVE_LASER,   // 激光半主动（需外部照射）
        TV,                  // 电视（昼间）
        COMMAND,             // 无线电指令（外部指引）
    }
}
```

### 4.2 GuidanceAttr — 制导律

决定**如何根据目标位置修正飞行路径**。`guidance` 缺失 → 无制导。

```java
public record GuidanceAttr(
    /// 制导律类型
    GuidanceLaw law,
    /// 导航增益（比例导引用）
    float navigationGain,
    /// 最大横向加速度（m/s²，0=无限制）
    float maxLateralAcceleration
) {
    public enum GuidanceLaw {
        PROPORTIONAL_NAVIGATION,  // PN（比例导引）
        AUGMENTED_PN,             // APN（增广比例导引）
        PURE_PURSUIT,             // 纯追逐
        LEAD_PURSUIT,             // 前置追逐
    }
}
```

### 4.3 FuzeAttr — 引信

决定**何时触发战斗部**。`fuze` 缺失 → 默认碰炸。

```java
public record FuzeAttr(
    /// 引信类型
    FuzeType type,
    /// 起爆距离（近炸用，米）
    float proximityRadius,
    /// 解锁延迟（出膛后秒数，防止自伤）
    float armingDelaySeconds,
    /// 延时秒数（延时引信用）
    float delaySeconds
) {
    public enum FuzeType {
        CONTACT,             // 碰炸
        PROXIMITY,           // 近炸（激光/无线电）
        DELAY_AFTER_LAUNCH,  // 出膛后延时（空爆）
        DELAY_AFTER_HIT,     // 命中后延时（穿入后爆）
    }
}
```

### 4.4 WarheadAttr — 战斗部

决定**触发后产生什么效果**。`warhead` 缺失 → 纯动能（当前行为）。

```java
public record WarheadAttr(
    /// 战斗部类型
    WarheadType type,
    /// 爆炸威力
    float explosionPower,
    /// 爆炸半径
    float explosionRadius,
    /// 破片配置（仅 FRAGMENTATION 有效）
    @Nullable FragmentAttr fragments,
    /// 持续效果配置（仅 SMOKE / GAS / EMP 有效）
    @Nullable AreaEffectAttr areaEffect
) {
    public enum WarheadType {
        EXPLOSION,           // 高爆
        FRAGMENTATION,       // 破片（产生子投射物）
        SHAPED_CHARGE,       // 聚能装药（金属射流）
        SMOKE,               // 烟雾
        GAS,                 // 毒气
        EMP,                 // 电磁脉冲
        CONTINUOUS_BEAM,     // 持续光束伤害（光束专用）
    }

    /// 破片配置
    public record FragmentAttr(
        int count,                              // 数量
        ResourceLocation fragmentProjectileType, // 破片类型键
        float coneAngleDegrees,                 // 散布锥角
        float baseSpeed                         // 初速
    ) {}

    /// 区域持续效果
    public record AreaEffectAttr(
        ResourceLocation effectId,   // 效果 ID
        float radius,                // 半径
        int durationTicks            // 持续 tick
    ) {}
}
```

### 4.5 组件运行时架构

所有行为组件的运行时逻辑使用 **static 方法 + 配置对象**模式（非接口继承），以保持 SoA 热路径性能：

```
projectile/
├── component/
│   ├── seeker/SeekerLogic.java        ← static 方法：根据配置获取目标位置
│   ├── guidance/GuidanceLogic.java    ← static 方法：计算制导加速度
│   ├── fuze/FuzeLogic.java            ← static 方法：判断触发条件
│   └── warhead/WarheadLogic.java      ← static 方法：执行效果
```

### 4.6 默认行为

| 缺失组件 | 默认行为 |
|----------|----------|
| 无 `seeker` | 纯弹道飞行（不跟踪目标） |
| 无 `guidance` | 无路径修正 |
| 无 `fuze` | 碰炸（接触即触发） |
| 无 `warhead` | 纯动能命中（当前阶段一行为） |

## 五、RayProjectileType 概览

详见配套文档 `武器系统-光束系统详细设计.md`。本节仅列出与 `KineticProjectileType` 的关键区别：

| 维度 | KineticProjectileType | RayProjectileType |
|------|----------------------|-------------------|
| JSON key | `"point"`, `"rigid"` | `"pulse"`, `"beam"` |
| 运动模型 | 飞行弹丸（位置 + 速度矢量） | 线段（起点 + 方向 + 长度） |
| 时间模型 | 瞬时命中 | pulse=瞬时，beam=持续 |
| 终效模型 | 速度-伤害幂函数 | 等效距离线性衰减 |
| 管理器 | `ProjectileManager`（物理线程） | `RayManager`（主线程） |
| 发射器 | `LauncherSubsystem` | `RayLauncherSubsystem` |
| 代理 Entity | 有（`MMProjectileEntity`） | 无 |
| 可用组件 | seeker / guidance / fuze / warhead | 仅 warhead |
| 穿深消耗 | 无（残余速度衰减） | 有（穿透 RHA 消耗等效距离预算） |

### 5.1 RayAttr — 射线外弹道属性

射程、精度、半径、持续时间、油耗统一在 `RayAttr` 中。JSON 字段名 `external`，与 kinetic 共用：

```java
public record RayAttr(
    float maxRange,            // 最大射程（米）
    float radius,              // 射线半径（米），用于子采样密度计算
    float nearRange,           // 无衰减区间（米），0 = 立即衰减
    float durationSeconds,     // 0=pulse, >0=burst, -1=continuous
    float ammoPerSecond,       // 连续模式油耗（burst/pulse 无效）
    float baseAccuracyMil,     // 基础精度（密位），0 = 完美精准
    float accuracyDriftTime    // 回归半衰期（秒）
) {
    public boolean isPulse()     { return durationSeconds <= 0; }
    public boolean isBurst()     { return durationSeconds > 0; }
    public boolean isContinuous(){ return durationSeconds < 0; }
}

### 5.2 BeamTerminalProperties

JSON 字段名 `terminal`，与 kinetic 共用。Java 类不同，Codec dispatch 分派。

**等效距离——统一能量预算模型：**

```
等效距离 = 实际传播距离 + Σ(已穿透RHA × rhaToDistanceRatio)
穿深/伤害 = nearPenetration/damage → 线性插值 → farPenetration/damage
```

| 字段 | 说明 |
|------|------|
| `near_penetration_mm` | 零距离（nearRange 内）穿深 |
| `far_penetration_mm` | maxRange 处穿深 |
| `near_damage` | 零距离伤害 |
| `far_damage` | maxRange 处伤害 |
| `rha_to_distance_ratio` | 1mm RHA 等效多少米射程 |

## 六、管理器与发射器对应关系

```
ProjectileType 类型
│
├── KineticProjectileType (point / rigid)
│   │
│   ├── 发射器: LauncherSubsystem (现有，实现 IAmmoConsumer)
│   │   └── 膛内弹药 (chamberedType) → fireSingle() → pendingFires
│   │
│   └── 管理器: ProjectileManager (现有，物理线程)
│       └── SoA 数组，半隐式 Euler 积分 + rayTest
│       └── 有 MMProjectileEntity 代理
│
└── RayProjectileType (pulse / beam)
    │
    ├── 发射器: RayLauncherSubsystem (新增，实现 IAmmoConsumer)
    │   ├── pulse: consumeReadyRound() → 瞬时扫描 → RayManager 处理
    │   ├── burst: consumeReadyRound() → 创建 BeamInstance(durationTicks>1)
    │   └── continuous: consumeReadyRound() → 创建 BeamInstance(continuous)
    │                    → 持续消耗燃料 → 耗尽时 consumeReadyRound() 补充
    │
    └── 管理器: RayManager (新增，主线程)
        └── SoA 管理所有活跃 BeamInstance
        └── 每 tick 扫描 + 穿透判定 + 伤害
        └── 无代理 Entity，直接渲染
```

### 6.1 射速与持续时间正交

`RayLauncherSubsystem` 可同时持有多个 `BeamInstance`——射速不受光束持续时间限制：

```
Tick 0:  击发 → Beam#1 (burst, 3s)
Tick 0.05: 再次击发 → Beam#2 (burst, 3s)
          → #1 和 #2 同时在 RayManager 中活跃
Tick 3:  #1 到期
Tick 3.05: #2 到期
```

### 6.2 弹药框架兼容

两者均实现 `IAmmoConsumer`，共享 `AmmoLoaderSubsystem` 弹药供给：

- `LauncherSubsystem`: `consumeReadyRound()` → 1 发 → 1 次 fire
- `RayLauncherSubsystem`: `consumeReadyRound()` → 1 发 → pulse 或 N ticks 燃料

## 十、实施路线

| 阶段 | 内容 | 依赖 |
|------|------|------|
| **A. 类型体系重构** | `ProjectileType` → abstract + dispatch Codec；`KineticProjectileType` 继承 | 现有代码 |
| **B. 行为组件 Codec** | `SeekerAttr`, `GuidanceAttr`, `FuzeAttr`, `WarheadAttr` + optional 字段 | A |
| **C. 光束基础** | `RayProjectileType`, `RayAttr`, `BeamTerminalProperties`, `RayManager` SoA 核心 | A |
