> 状态：设计阶段

> 上级文档：`武器系统-组件化投射物与类型体系设计.md`

## 一、概述

光束系统是投射物体系中与飞行弹丸完全不同的运动模型。它包括：

| 子类型 | `durationSeconds` | 行为 | 弹药消耗 |
|--------|------------------|------|----------|
| **PULSE**（脉冲） | `0` | 瞬时射线。单帧扫描，结果立即由 RayManager 消费。RayLauncher 打完即释放。 | 1 发 / 次 |
| **BURST**（爆发光束） | `>0` | 持续 N 秒后自动停火。中间不可打断。 | 1 发 / 次 |
| **CONTINUOUS**（连续光束） | `-1` | 手动控制启停。持续消耗燃料，耗尽时自动从供给者获取下一发。 | `ammoPerSecond` 发/秒 |

三者共用同一个 `RayProjectileType`、`RayManager` 和 `RayLauncherSubsystem`，区别仅在于 `RayAttr.durationSeconds`。

## 二、线程模型：主线程执行

### 2.1 为什么是主线程

光束与物理世界无交互——没有 Bullet 刚体、没有碰撞回调、没有物理线程的 SoA 积分。主线程（20tps）执行有以下优势：

- **无异步时序问题** — 穿透判定立即可得结果，不需要 `hitPending` 暂停链
- **20Hz 伤害结算完全足够** — 持续照射下，每 0.05s 一次伤害，视觉和游戏性上都平滑
- **渲染直接可用** — 每 tick 扫描后立即更新光束长度，渲染器直接读取

### 2.2 调度的位置

```
LevelTickEvent.Pre（主线程）
  → ObjectManager.onPreTick()
      → RayManager.tickAllBeams()        ← 光束扫描 + 穿透判定 + 伤害
      → RayLauncherSubsystem.onTick()      ← 燃料消耗 + 补给 + 启停控制
      → DestroyableObject.preTick()        ← 现有生命周期

LevelTickEvent.Post（主线程）
  → RayManager.syncToRenderer()           ← 刷新供渲染器读取的数据
```

### 2.3 子 tick 采样

高速扫掠时，单束射线可能跳过目标。每主线程 tick 根据扫掠角度和射程自适应增加子采样：

```java
/// 综合角度和射程计算子采样数
/// farEndDisplacement = 2 × maxRange × sin(sweepDeg/2) — 远端的扫掠弧长
/// farEndSamples = farEndDisplacement / beamWidth — 保证不跳过 beamWidth 大小的目标
/// angleSamples = sweepDeg / 5.0 — 每 5° 一个保底采样
int calcSubSamples(float sweepDeg, float maxRange, float beamWidth) {
    float farEndDisplacement = 2 * maxRange * (float) Math.sin(Math.toRadians(sweepDeg / 2));
    int farEndSamples = (int) Math.ceil(farEndDisplacement / Math.max(beamWidth, 0.01f));
    int angleSamples = (int) Math.ceil(sweepDeg / 5.0f);
    return Math.max(1, Math.max(farEndSamples, angleSamples));
}
```

子采样的起点使用**最新枪口位置**（不插值，避免起点进入发射者体内），方向在 `prevDir` → `currentDir` 间均匀插值：

```java
for (int s = 0; s < subSamples; s++) {
    float t = (subSamples == 1) ? 0 : (float) s / (subSamples - 1);
    Vec3 sampleDir = slerp(beam.prevDir, beam.currentDir, t);
    // origin 不插值 — 全部用当前枪口位置
    scanSingleRay(beam.currentSrc, sampleDir, beamEndDistance);
}
```

## 二补充、光束精度：平滑漂移模型

### 2.4 核心思路

PULSE 的精度完全复用现有椭圆锥散布体系（`base_accuracy_mil` + 发射器精度乘子）。

对于 BURST / CONTINUOUS，持续光束**不能每 tick 随机跳变**——那会看起来像"光束在抽搐"。正确的模型是：

```
击发瞬间: 随机初始偏移，范围 ±maxAngularDeviationMil
每 tick:  偏移 = 偏移 × decay + 高斯噪声 × sqrt(1 − decay²)   ← AR(1) 过程
实际方向: launcher.refDir.rotate(azimuthDrift, elevationDrift)
```

这是离散 Ornstein-Uhlenbeck 过程——**均值回归的平滑随机游走**。

- 偏移始终被引力拉回 0（均值回归），不会漂出 `±maxAngularDeviationMil`
- 连续 tick 间平滑过渡，无跳变。渲染器做 `lerp(prevDrift, currentDrift, partialTick)` 帧间插值，完全丝滑
- 稳态下 ~99.7% 时间漂移在 `±3 × maxAngularDeviationMil` 内
- `reversionHalfLifeSec` 控制回归速度——越小越"紧"，越大越"晃"

### 2.5 精度字段

精度是外弹道的一部分，直接平铺在 `RayAttr` 中：

```java
public record RayAttr(
    float maxRange,
    float radius,
    float nearRange,
    float durationSeconds,
    float ammoPerSecond,
    float baseAccuracyMil,       // 基础精度（密位）。0 = 完美精准，无漂移
    float accuracyDriftTime      // 回归半衰期（秒）。baseAccuracyMil==0 时无效
) { ... }
```

| `reversionHalfLifeSec` | 效果 |
|------------------------|------|
| 0.1 | 几乎不动，极短促的微颤 |
| 0.3 | 平稳缓慢漂移（推荐默认） |
| 1.0 | 大幅度慢速摆动 |

### 2.6 漂移运行时

```java
/// BeamInstance 内维护的漂移状态
class BeamDriftState {
    float azimuthOffsetMil;       // 水平角偏移（密位）
    float elevationOffsetMil;     // 垂直角偏移（密位）
    
    /// 每 tick 由 RayManager 调用，执行 AR(1) 更新
    void tick(float dt, float maxDev, float halfLifeSec, Random rng) {
        float decay = (float) Math.pow(0.5, dt / halfLifeSec);
        float noiseScale = maxDev * (float) Math.sqrt(1 - decay * decay);
        
        azimuthOffsetMil = azimuthOffsetMil * decay + (float) rng.nextGaussian() * noiseScale;
        elevationOffsetMil = elevationOffsetMil * decay + (float) rng.nextGaussian() * noiseScale;
    }
    
    /// 应用漂移到参考方向
    Vec3 applyTo(Vec3 refDir, Vec3 right, Vec3 localUp) {
        // 先绕 right 轴做 elevation 偏移，再绕 localUp 轴做 azimuth 偏移
        float aziRad = azimuthOffsetMil / 1000f;
        float eleRad = elevationOffsetMil / 1000f;
        Vec3 result = rotateAroundAxis(refDir, right, eleRad);
        return rotateAroundAxis(result, localUp, aziRad);
    }
}
```

RayManager 的 `addBeam()` 中初始化漂移：

```java
// 击发瞬间：随机初始偏移
var external = type.rayAttr();
if (external.baseAccuracyMil() > 0) {
    beam.driftAzimuthMil = (random.nextFloat() * 2 - 1) * external.baseAccuracyMil();
    beam.driftElevationMil = (random.nextFloat() * 2 - 1) * external.baseAccuracyMil();
}
```

## 三、命中去重策略

子射线之间可能存在重叠区域，同一目标不应在同一 tick 被重复击中。

### 3.1 去重键

| 目标类型 | 去重键 | 说明 |
|----------|--------|------|
| `TerrainHit` | `BlockPos.toShortString()` | 同一方块只判定一次 |
| `SubPartHit` | `subPart.getId() + "/" + hitBoxId` | 同一 HitBox 只判定一次 |
| `EntityHit` | **不去重**，由原版 `invulnerableTime` 控制 | 见 §3.2 |

### 3.2 Entity 伤害频率

Entity 自带 `invulnerableTime`（原版默认 10 tick = 0.5s），光束系统**不手动清零**。BEAM 持续照射时，Entity 每 0.5s 受到一次伤害，视觉上是"光束持续照射"，数值上伤害频率受原版机制约束。

这意味着 RayManager **不需要维护 Entity 命中冷却**——全部由原版无敌时间 gating。

## 四、等效距离穿透模型

### 4.1 核心概念

激光穿透装甲等效于多走了额外距离。所有消耗统一为**等效距离**：

```
等效距离 = 实际已走距离 + Σ(已穿透RHA × rhaToDistanceRatio)
```

- 实际距离 = 光束从枪口到当前点的空气传播距离
- `rhaToDistanceRatio` = 每穿透 1mm RHA 消耗多少米射程预算
- 等效距离 ≥ `maxRange` → 光束终止

### 4.2 BeamTerminalProperties

与 kinetic 共用 JSON 字段名 `terminal`，但 Codec dispatch 分派到不同的 Java 类。

`nearRange` 和 `maxRange` 在外弹道 `external` 中，`terminal` 仅定义终端的衰减曲线值：

```java
/// 射线终点效应 — 等效距离线性衰减。
///
/// far* = external.maxRange 处的值。near* = external.nearRange 内的值。
/// 插值区间为 [nearRange, maxRange]。
///
/// @param nearPenetrationMM     零距离穿深（mm RHA）
/// @param farPenetrationMM      external.maxRange 处穿深
/// @param nearDamage            零距离伤害
/// @param farDamage             external.maxRange 处伤害
/// @param rhaToDistanceRatio    穿透换算比：1mm RHA 等效多少米射程
public record BeamTerminalProperties(
    float nearPenetrationMM,
    float farPenetrationMM,
    float nearDamage,
    float farDamage,
    float rhaToDistanceRatio
) {
    /// 等效距离 → 穿深（nearRange 和 maxRange 由调用方从 external 传入）
    public float penetrationAt(float effectiveDist, float nearRange, float maxRange) {
        if (effectiveDist <= nearRange) return nearPenetrationMM;
        if (effectiveDist >= maxRange) return farPenetrationMM;
        float t = (effectiveDist - nearRange) / (maxRange - nearRange);
        return nearPenetrationMM + (farPenetrationMM - nearPenetrationMM) * t;
    }

    public float damageAt(float effectiveDist, float nearRange, float maxRange) {
        if (effectiveDist <= nearRange) return nearDamage;
        if (effectiveDist >= maxRange) return farDamage;
        float t = (effectiveDist - nearRange) / (maxRange - nearRange);
        return nearDamage + (farDamage - nearDamage) * t;
    }

    public static float effectiveDistance(float actualMeters, float consumedRHA, float ratio) {
        return actualMeters + consumedRHA * ratio;
    }
}
```

### 4.4 扫描算法

```java
/// RayManager.tickBeam() — 主线程每 tick 调用
void tickBeam(int beamIndex) {
    var beam = getBeam(beamIndex);
    var external = beam.type.rayAttr();
    var terminal = beam.type.terminal();
    float maxRange = external.maxRange();
    float nearRange = external.nearRange();
    
    // 子采样
    int subSamples = calcSubSamples(beam.sweepDeg, maxRange, external.radius());
    
    Set<String> dedupTerrain = new HashSet<>();
    Set<Integer> seenEntities = new HashSet<>();
    
    float consumedRHA = 0f;
    float beamEndDistance = maxRange;
    
    for (int s = 0; s < subSamples; s++) {
        float t = (subSamples == 1) ? 0 : (float) s / (subSamples - 1);
        Vec3 dir = slerp(beam.prevDir, beam.currentDir, t);
        float subEnd = beamEndDistance;
        
        for (HitEntry hit : sortByDistance(scanRay(beam.src, dir, subEnd))) {
            float actualDist = hit.distance;
            float effDist = BeamTerminalProperties.effectiveDistance(
                actualDist, consumedRHA, terminal.rhaToDistanceRatio());
            
            if (effDist >= maxRange) {
                subEnd = Math.min(subEnd, actualDist);
                break;
            }
            
            float penNow = terminal.penetrationAt(effDist, nearRange, maxRange);
            
            switch (hit) {
                case TerrainHit tHit -> {
                    if (!dedupTerrain.add(tHit.blockPos.toShortString())) continue;
                    float rha = ArmorUtil.getBlockArmor(tHit);
                    if (penNow > rha) {
                        consumedRHA += rha;
                    } else {
                        subEnd = Math.min(subEnd, actualDist);
                    }
                }
                
                case SubPartHit spHit -> {
                    String key = spHit.subPartId + "/" + spHit.hitBoxId;
                    if (!dedupTerrain.add(key)) continue;
                    float rha = spHit.getRHA();
                    if (penNow > rha) {
                        consumedRHA += rha;
                    } else {
                        subEnd = Math.min(subEnd, actualDist);
                    }
                }
                
                case EntityHit eHit -> {
                    if (seenEntities.add(eHit.entityId)) {
                        submitBeamDamage(eHit, terminal.damageAt(effDist, nearRange, maxRange), penNow);
                    }
                    subEnd = Math.min(subEnd, actualDist);
                }
            }
            
            if (subEnd <= actualDist) break;
        }
        
        beamEndDistance = Math.min(beamEndDistance, subEnd);
    }
    
    beam.currentLength = beamEndDistance;
    beam.prevDir = beam.currentDir;
}
```

### 4.5 实体穿透延迟

Entity 命中走异步 BFDamageApi 管线，穿透判定结果延迟 1 tick。策略为**保守截断**——默认截断在 Entity 位置，确认穿透后下一 tick 光束自然延伸：

```
Tick N:
  → 命中 Entity A (RHA=80, penNow=60) → 默认截断
  → 提交异步伤害
  
Tick N+1:
  → 消费命中结果：Entity A 未穿透
  → 光束仍截断在 A 的位置 ✓
  
  或
  → 消费命中结果：Entity A 已穿透
  → 光束继续延伸，扫描后面的目标 ✓
```

光束不暂停等待结果（避免 stop-world），仅 1 tick 的保守延迟，视觉上几乎不可见。

## 六、RayLauncherSubsystem — 光束发射器

### 6.1 多发光束与类型约束

同一 RayLauncher **同时只能照射一种弹药类型**。发射器维护两个关键状态：

```java
class RayLauncherSubsystem implements IAmmoConsumer {
    /// ★ 当前正在照射的弹药类型。null = 未在照射。
    ///     所有活跃光束必须是此类型。切换弹药 → 自动停火。
    @Nullable RayProjectileType activeBeamType;
    
    /// 活跃光束实例列表（全部为 activeBeamType 类型）
    List<Integer> activeBeamIndices;      // SoA 索引
    
    /// 当前弹药燃料余量（秒），连续模式用
    float fuelRemainingSeconds;
    
    /// 上一 tick 的枪口位姿（供高射速 PULSE 插值使用）
    Vec3 prevTickMuzzlePos;
    Vec3 prevTickMuzzleDir;
}
```

**约束规则：**

| 操作 | 行为 |
|------|------|
| 击发（新弹药类型 ≠ activeBeamType） | 先 `deactivateAll()`，再以新类型击发 |
| 击发（新弹药类型 = activeBeamType） | 直接追加 BeamInstance |
| 用户切换弹药（WeaponController） | `activeBeamType` 变化 → 自动 `deactivateAll()` |
| 所有 `activeBeamIndices` 清空 | `activeBeamType = null`，允许切换 |

### 6.2 弹药消耗——不倍乘

多束同时照射**不翻倍消耗**——它们是同一束能量的多点输出。油耗仅跟随 `activeBeamType` 的 `ammoPerSecond`：

```java
/// RayLauncherSubsystem.onTick() — 主线程
void onTick() {
    if (activeBeamIndices.isEmpty()) return;
    if (!isContinuousMode) return;
    
    // 油耗 = ammoPerSecond / 20（不乘光束数量）
    fuelRemainingSeconds -= activeBeamType.rayAttr().ammoPerSecond() / 20f;
    
    if (fuelRemainingSeconds <= 0) {
        // 续弹：类型必须与 activeBeamType 完全一致
        ProjectileType next = currentSupplier.consumeReadyRound(this);
        if (next instanceof RayProjectileType nextBeam 
            && nextBeam.getRegistryKey().equals(activeBeamType.getRegistryKey())) {
            fuelRemainingSeconds += 1.0f;
        } else {
            deactivateAll();  // 类型不匹配或无弹药 → 停火
        }
    }
}
```

### 6.3 状态机

```
IDLE ──(triggerHeld && canFire)──→ FIRING
                                        │
  每次击发创建 BeamInstance             │
  → activeBeamIndices.add(idx)          │
  → activeBeamType = consumedType       │
                                        │
  ┌─────────────────────────────────────┤
  │                                     │
  │  continuous:                    burst:
  │  triggerReleased                 durationSeconds 到期
  │     │                               │
  │     ▼                               ▼
  │  deactivateAll()              单个 BeamInstance 到期
  │     │                          → RayManager.remove(idx)
  │     │                          → activeBeamIndices 空?
  │     │                               │
  │     └─────── IDLE ◄─────────────────┘
  
  弹药耗尽（fuelRemaining <= 0 且无法续弹）
     → deactivateAll() → IDLE
```

### 6.4 每 tick 更新参考方向

```java
/// RayLauncherSubsystem.preTick() — 更新所有活跃光束的源点和参考方向
void updateActiveBeams() {
    Vec3 muzzlePos = getMuzzlePos();
    Vec3 refDir = getMuzzleDirection();
    
    for (int idx : activeBeamIndices) {
        RayManager.get(level).updateBeamSource(idx, muzzlePos, refDir);
    }
    
    // 缓存供下 tick 子采样使用
    prevTickMuzzlePos = muzzlePos;
    prevTickMuzzleDir = refDir;
}
```

RayManager 内部在 `tickAllBeams()` 中对每条光束：先更新漂移，再用 `refDir + drift` = `currentDir`，然后执行扫描。

### 6.5 高射速 PULSE 的起点插值

当 PULSE 射速 > 20 发/秒（即 `roundsPerTick > 1`）时，不能所有脉冲从同一枪口位置出发。载具高速移动时，需在枪口路径上均匀分布起点：

```java
/// 高射速脉冲发射。roundsPerTick = RPM / 1200.0
void firePulseBurst(int roundsPerTick, RayProjectileType type) {
    Vec3 prevMuzzle = this.prevTickMuzzlePos;
    Vec3 prevDir = this.prevTickMuzzleDir;
    Vec3 currMuzzle = getMuzzlePos();
    Vec3 currDir = getMuzzleDirection();
    
    for (int i = 0; i < roundsPerTick; i++) {
        float t = (float)(i + 1) / (roundsPerTick + 1);
        Vec3 origin = lerp(prevMuzzle, currMuzzle, t);
        Vec3 direction = slerp(prevDir, currDir, t).normalize();
        
        // 叠加椭圆锥散布（复用现有精度体系）
        direction = applyEllipticSpread(direction, hRad, vRad);
        
        // PULSE → 瞬时扫描（不持有 BeamInstance，不入 activeBeamIndices）
        RayManager.get(level).scanPulse(origin, direction, type);
    }
    
    this.prevTickMuzzlePos = currMuzzle;
    this.prevTickMuzzleDir = currDir;
}
```

注意：PULSE 不走 `activeBeamIndices`——它是瞬时的，不需要 RayLauncher 维护引用。也不受类型约束限制（打完即忘）。

### 6.6 与弹药框架的集成

`RayLauncherSubsystem` 实现 `IAmmoConsumer`，与现有的 `AmmoLoaderSubsystem` 完全兼容：

```
WeaponControllerSubsystem
  │ 弹药类型选择 + 标签匹配
  │
  └── AmmoLoaderSubsystem (IAmmoSupplier)
        │ handshake → 发现 RayLauncherSubsystem
        │
        └── RayLauncherSubsystem (IAmmoConsumer)
              requestRound() → wait → isRoundReady()
              → consumeReadyRound() → 获得 RayProjectileType
              → 击发（或拒止，若类型不匹配）
```

## 七、RayAttr — 射线外弹道属性

射程、精度、半径、持续时间、油耗统一在 `RayAttr` 中。JSON 字段名 `external`，与 kinetic 共用。

```java
public record RayAttr(
    float maxRange,            // 最大射程（米），硬上限
    float radius,              // 射线半径（米），用于子采样密度
    float nearRange,           // 无衰减区间（米），0 = 立即开始衰减
    float durationSeconds,     // 0 = pulse, >0 = burst, -1 = continuous
    float ammoPerSecond,       // 连续模式每秒消耗的弹药量
    float baseAccuracyMil,     // 基础精度（密位）。0 = 完美精准，无漂移
    float accuracyDriftTime    // 回归半衰期（秒），baseAccuracyMil==0 时无效
) {
    public boolean isPulse()     { return durationSeconds <= 0; }
    public boolean isBurst()     { return durationSeconds > 0; }
    public boolean isContinuous(){ return durationSeconds < 0; }
    
    public int durationTicks() {
        if (isPulse()) return 1;
        if (isContinuous()) return Integer.MAX_VALUE;
        return Math.round(durationSeconds * 20);
    }
}
```

## 九、音效

与常规投射物不同，光束武器有三种音效模式：

| 音效 | 说明 |
|------|------|
| `fire_sound` | 击发瞬间播放（PULSE/BURST/CONTINUOUS 启动时） |
| `loop_sound` | 持续照射期间循环播放（BURST + CONTINUOUS） |
| `cease_fire_sound` | 停火瞬间播放（BURST 到期 / CONTINUOUS 松扳机） |

public record BeamSoundAttr(

    @Nullable SoundEvent ceaseFireSound      // 停火尾音
) {}

## 十一、与飞行弹丸的关键差异总结

| 维度 | 飞行弹丸 (KineticProjectileType) | 光束 (RayProjectileType) |
|------|----------------------------------|--------------------------|
| **线程** | 物理线程（Bullet SoA 积分） | 主线程（快照世界） |
| **运动** | 自由飞行，受重力/阻力 | 线段，无重力/阻力 |
| **速度** | 可变，初速→残余 | 无速度概念 |
| **终效** | 速度-伤害幂函数 | 等效距离线性衰减 |
| **穿透消耗** | 残余速度衰减（自动） | RHA → 等效距离消耗（显式） |
| **代理 Entity** | `MMProjectileEntity`（模组生态兼容） | 无 |
| **网络同步** | 关键事件（创建/命中/超时） | 持续状态同步（源点/方向/长度/启停） |
| **碰撞检测** | JME rayTest / Bullet 碰撞回调 | 每 tick 射线扫描 + 子采样 |
| **Entity 命中** | 异步暂停链（hitPending） | 1 tick 保守截断 + 无敌时间 gating |
| **发射器** | `LauncherSubsystem` | `RayLauncherSubsystem` |
| **弹药消耗** | 1 发 / 次 | pulse=1发，burst=1发，continuous=按时间 |
| **音效** | fire / cease / shell | fire / loop / cease |
| **可拦截** | 是（刚体） | 否 |
