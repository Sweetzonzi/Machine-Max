# 内容包命名词表

本文是内容包具名对象的取名判据：子系统、子零件、连接点、交互区、控制组这五类键怎么写，以及这些键对应的中文译文用哪个词。写内容、翻译、加校验、批量改名都以本文为准。

**不在本文范围**：内容 id（`<命名空间>/<文件名>`）、弹种 id 与效果词表（见 [`武器系统-弹药命名规范.md`](武器系统-弹药命名规范.md)）、材质名、型号 id（`fittings/`）、HUD 页面、投射物、配方。

**计数口径**：下文「个」指一个完整的白名单键（`subsystem.<命名空间>.<名字>`），同名出现在两个包里计两次；「去重后」指去掉命名空间后的名字数。数字是本文撰写时的盘点结果，随迁移归零，不随内容增加而失效。

---

## 一、前提

### 1.1 五类键里三类是存档键

内容里的名字统一写成完整键 `<类>.<命名空间>.<名字>`，整串就是 JSON 对象里的键，也是运行时寻址用的字符串。

| 类 | JSON 落点 | 进存档 | 改名的后果 |
| --- | --- | --- | --- |
| `subsystem.` | `sub_parts.<子零件>.subsystems` 的键；`hit_boxes.*.subsystem`、`signal_targets`、`passenger_num_outputs` 的值 | 是 | 旧档里该子系统找不到落点，安装块整块丢失 |
| `sub_part.` | `sub_parts` 的键 | 是 | 旧档里该子零件与其上的碰撞箱、连接点一起丢失 |
| `connector.` | `sub_parts.<子零件>.connectors` 的键；`signal_targets`、`signal_translations`、`passenger_num_outputs` 的值 | 是 | 旧档里该连接点丢失，装配体在该处断开 |
| `interact.` | `interact_boxes` 的键；`signal_targets`、`passenger_num_outputs` 的值 | 否 | 只影响交互面板显示名与信号路由 |
| `controlGroup.` | `control_groups/<名字>.json` 的文件名 | 否 | 需同步座位的 `control_group_preset` 与语言键 |

改一个名字要一起改的引用：`hit_boxes.*.subsystem`、`signal_targets`、`signal_translations`、`passenger_num_outputs`、动画里的 `local.subsystem_destroyed('…')`，以及 `templates/` 与 `assemblies/` 里同一变体的副本。正因为引用面这么大，前三类名字的改动属于**存档破坏性改动**。当前处于开发期，改名不保旧档、不做旧名映射；这条豁免随 beta 结束失效，正式版之后改名必须附 `LegacyNames` 映射或版本化迁移。

### 1.2 同一变体内同类名字唯一

四类键各存一张表，跨表不冲突（键前缀不同），同一张表内必须唯一。语言键一侧的约束更强：`checkContent` 已有反向检查（每个语言键必须有消费方），因此「翻译了但没人用」的空键会直接报错——**加译文之前先确认内容里已有同名键**。

### 1.3 译文归属跟着命名空间走

`LangModule` 按 `namespace:lang/<locale>.json` 合并同命名空间的语言文件，加载顺序 builtin → kit → 车包，后者覆盖前者。因此：

- `machine_max.*`：builtin 与所有 kit 共写。通名（并列机枪、火控、方向机、储物箱）放 builtin；某个型谱专有的型号名（PKTM、2A42）放对应 kit。
- `<车名>.*`：只有该车包写。

## 二、键的构形

```
<类>.<命名空间>.<名字>
```

- 类固定为 `subsystem` / `sub_part` / `connector` / `interact` / `controlGroup`，不新增。
- 名字只用小写字母、数字、下划线；**名字内不含点**。名字出现第四个点即违规：写 `interact.machine_max.golden_seat`，不写 `golden.seat`。
- 命名空间由包决定：车包用自己的包名，kit 与 builtin 共用 `machine_max`。

## 三、词表

### 3.1 方位词

封闭集：`left` `right` `front` `back` `top` `bottom` `middle`

四条规则：

1. **方位词一律作前缀**，不跟在名词后面。
2. **词序：垂直 → 侧向 → 纵向**。`top_left_front` 合规；`left_top`、`front_left` 不合规。
3. `middle` 是侧向的居中位：同一排只有它一件时单独写（`middle_marker_light`），与 `left` / `right` 排成三列时写中间那一列（`left_mount_01` / `middle_mount_01` / `right_mount_01`）。
4. 禁用同义词：`rear`（用 `back`）、`aft`（用 `back`）、`port`（用 `left`）、`up`（用 `top`）、`down`（用 `bottom`）、`center`（用 `middle`）、`mid`（用 `middle`）。

规则 2、3 描述的是带方位的位置短语；`subsystem.machine_max.engine`、`subsystem.machine_max.gearbox` 这类不带方位的通名不受影响。

现存量：**词序违规 0 个**、**同义词违规 0 个**、`mid` 0 个（三列货位写 `left_mount_01` / `middle_mount_01` / `right_mount_01`，居中单件写 `middle_marker_light`）。

尾部挂点写 `left_back_mount` / `right_back_mount`：`left_back` / `right_back` 已是门与座椅的路由点（`AbstractPart` 按名解析只命中一个），这两个挂点靠接口词 `mount` 区分开。面包车的后灯罩写 `left_tail_lamp` / `right_tail_lamp`——灯罩用 `_lamp` 收尾，不带 `glow_` 前缀（3.6）。

同义词不出现：`aft` / `port` / `rear` 不在任何名字里。M1A2 的四挺机枪按使用者写作 `coax` / `antimateriel` / `aa` / `loader_mg`（见 3.3），MTLB 的后舱门写作 `back_door`。

### 3.2 编号

```
<名字>_<两位序号>
```

- **下划线分隔**：`interior_light_01` 合规，`interior_light1` 不合规。
- **两位补零**：`_01` … `_09`、`_10`。
- **起点 01**，不跳号；左右对称件的编号必须同号（`left_road_wheel_01` ↔ `right_road_wheel_01`）。
- **编号紧跟在它所区分的名词之后**，不放到轴词、接口词后面：`left_atgm_launcher_01` 合规，`left_atgm_01_launcher` 不合规。
- **同一方位上不止一件时才编号**：方位词分得开就不编号（面包车四轮，写 `hull_left_front_wheel` / `hull_left_back_wheel`），分不开才用编号（大运车架每侧一个前轴、两个后轴，两个后轴都只能叫 `back`，写 `hull_left_back_wheel_01` / `hull_left_back_wheel_02`；`01` 是靠近车头的那个）。
- 只有一件时不编号（用 `left_main_light`，不用 `left_main_light_01`）。

现存量：**0 个**。负重轮（`sub_part.<命名空间>.left_road_wheel_01` … `_08`）、座位（`subsystem.machine_max.passenger_seat_01` … `_08`）、货厢挂点（`connector.machine_max.left_mount_01` … `_05`）、灯具（`subsystem.machine_max.light_01` … `_04`）与爆反（`hull_era_left_01` …）都是两位起步的编号。

### 3.3 角色词

子系统名字的最左一段是角色词，取自封闭集：

| 角色词 | 中文 | 用什么场合 |
| --- | --- | --- |
| `main` | 主炮 | 主武器 |
| `coax` | 并列机枪 | 与主炮同轴的机枪 |
| `aa` | 高射机枪 | 车顶 / 指挥塔上的大口径机枪，含 T-90A 与 59 的车顶高机、M1A2 车长指挥塔的 M2 |
| `antimateriel` | 反狙击机枪 | 随动炮管、口径大于并列机枪，用于反狙击 / 反器材 |
| `loader_mg` | 装填手机枪 | 装在装填手舱口、由装填手操作（当前只有 M1A2 一例） |
| `left` / `right` | 左 / 右 | 成对且不属于上述角色时用方位词；机枪不用方位词 |
| `rws` | 遥控武器站 | 遥控武器站整体 |
| `citv` | 车长独立观瞄 | 车长独立热像仪一类 |
| `atgm` | 反坦克导弹 | 导弹发射管与其配套件 |
| `commander` / `gunner` / `loader` / `driver` / `passenger` / `copilot` / `radio` | 车长 / 炮手 / 装填手 / 驾驶 / 载员 / 副驾驶 / 无线电员 | 座位、瞄具、舱口 |
| `track` | 履带 | 履带驱动与履带行驶控制 |
| `wheel` | 负重轮 | 轮式车的车轮与负重轮 |

**型号名不进名字。** 型号由 `definition` 与译文表达，名字只写角色。

现存量：**型号名与口径名 0 个**。七包的火器都按角色词写：

- 2S38：`main_launcher`（2A90）、`coax_launcher`（PKTM）。型号只留在 `definition`（`machine_max:57mm_2a90_launcher`）与零件名（`2s38_turret`）里，子零件按 3.7 写 `gun` / `mg`。
- K17：`main_launcher`（2A42）、`coax_launcher`（PKTM）、`left_atgm_launcher_01/02` 与 `right_atgm_launcher_01/02`（9M133 发射管）。
- MTLB：`main_launcher`（PKT 机枪塔）。
- Sd.Kfz.234：`main_launcher`（KwK39）、`coax_launcher`（MG34）。
- M1A2：`main_launcher`、`coax_launcher`（M240）、`antimateriel_launcher`（CSAMM）、`aa_launcher`（指挥塔 M2）、`loader_mg_launcher`、`rws_launcher`。
- 连接点：`coax_turret_lock`、`turret_coax_axis`（2S38）、`rws_terminal_mount`（M1A2）。

**机枪按使用者与用途命名，不用方位词。** M1A2 的四挺机枪是 `coax`（并列，M240 7.62）、`antimateriel`（反狙击，CSAMM 12.7）、`aa`（高射，车长指挥塔的 M2）、`loader_mg`（装填手舱口，M240）；子零件与驱动器沿用同一角色词，`aa_azimuth` / `aa_azimuth_driver`、`loader_mg_elevation` / `loader_mg_elevation_driver`。

**名实要对得上。** `coax_*` 一定是并列机枪、`antimateriel_*` 一定是反狙击机枪，从 `definition` 到名字到译文三者同指一件事。M1A2 的并列机枪是 M240 7.62、反狙击是 CSAMM 12.7，所以 `coax_*` 引 `7_62mm_m240_*`、`antimateriel_*` 引 `12_7mm_m2hb_*`。

**口径不算角色词。** `coax_762` 与 `coax_127` 这种写法把口径塞进了名字，与「名字只写角色」冲突；口径交给 `definition` 与零件名。

### 3.4 类型后缀

名字的最右一段由子系统类型决定，一个类型一个后缀：

| 类型 | 名字形状 | 中文正词 |
| --- | --- | --- |
| `basic` | `<部件名>`，无类型后缀 | 见 3.6 |
| `seat` | `<角色>_seat`、`<方位>_seat`、`passenger_seat_<编号>` | 座 |
| `item_storage` | `<部位>_box`、`<部位>_storage`、`trunk`；不写规格 | 储物箱 / 后备箱 |
| `engine` | `engine` | 发动机 |
| `motor` | `motor` | 电动机 |
| `gearbox` | `gearbox` | 变速箱 |
| `transmission` | `transmission` | 传动系统 |
| `track_controller` | `track_controller` | 履带行驶控制器 |
| `track_drive` | `left_track` / `right_track` | 左 / 右履带驱动 |
| `wheel_driver` | `<方位>_wheel_<编号>`、`<方位>_<front\|back>_wheel`（类型已表达驱动，名字不带 `_driver`） | 负重轮驱动 |
| `car_controller` | `car_controller` | 行驶控制器 |
| `motorbike_controller` | `motorbike_controller` | 摩托车控制器 |
| `turret_driver` | `[<角色>_]<azimuth\|elevation>_driver` | 方向机 / 高低机 |
| `light` | `<方位>_<用途>_light` | 灯（用途见 3.6） |
| `launcher` | `<角色>_launcher` | 发射器 |
| `ammo_loader` | `<角色>_loader` | 自动装弹机 |
| `regen_ammo_rack`、`ammo_rack` | `<角色>_rack` | 弹药架 |
| `weapon_controller` | `<角色>_controller` | 所控武器的名字（与同角色发射器一致） |
| `camera` | `<角色>_optics` | 观瞄 |
| `sight` | `<角色>_sight` | 瞄准镜 |
| `reactive_armor` | `<部位>_era_<方位>_<编号>` | 反应装甲 |

四条推论：

- **装弹与弹药分开**：`_loader` 只给 `ammo_loader`（会自动装弹的机构），`_rack` 只给 `regen_ammo_rack` / `ammo_rack`（弹药架）。同一门炮带两套弹种时，用 `ap` / `he` 夹在角色词与后缀之间区分：`main_ap_loader` / `main_he_loader`、`main_ap_rack` / `main_he_rack`（2S38、59 式、M1A2）；AP 与 HE 共用一个机构时只留一份（T-90A 的 `main_loader`）。
- **观瞄与瞄准镜分开**：`camera`（热像仪、车长独立观瞄、炮手主镜）用 `_optics`，`sight`（机械瞄具、直瞄镜）用 `_sight`。后缀由 `type` 决定，所以 2S38 / K17 / M1A2 的炮手镜写 `gunner_optics`，Sd.Kfz.234 / T-90A / 59 式的直瞄镜写 `gunner_sight`。限定词排在后缀之前：`citv_azimuth_driver`、`rws_terminal_controller`。
- **座位与控制组条目的值只写角色**：座位写 `<角色>座`（`驾驶座`、`车长座`、`炮手座`、`装填手座`、`高射机枪座`、`无线电员座`、`载员座 01`），不写该乘员能操作哪些武器，也不写型号——「能打什么」由座位的控制组条目名承担（3.10）。观瞄与瞄准镜同理：写 `炮手观瞄`、`高射机枪瞄准镜`，不写装在哪个指挥塔上、用什么型号。
- **武器控制器按所控武器译**：`weapon_controller` 的译文写它所控的武器，与同角色的发射器同名——`main_controller` 与 `main_launcher` 都译「主炮」，`coax_controller` 与 `coax_launcher` 都译「并列机枪」，英文同理（`Main Gun`、`Coaxial Machine Gun`）。这个值同时是武器 HUD 的标题：`weapon.name` 绑在 `weapon_hud_components/` 各页面的标题条上，与弹药数、装填读数并排，那一行要读作这门炮的名字，带上类型词就成了额外的歧义。两处例外：`rws_terminal_controller` 是终端设备，译「遥控武器站终端」；`citv_controller` 不控武器、只让车长镜随动，译「CITV 视线随动」。控制器与发射器同名意味着两者同时损坏时，装配 HUD 会打出两条一样的 `❌ 主炮瘫痪`——提示只写名字，不带类型。
- **规格不进子系统名**：储物箱的体积（`container_16x16x32`、`reinforced_container_16x16x8`）是零件级的规格，写在零件名上；子系统只写它是储物箱。同一变体里有两个以上储物箱时才用方位词区分（`left_glove_box` / `right_glove_box`）。
- **同义的子系统名归 `machine_max`**：两个以上车包各挂一份、而且显示上就是同一个东西的子系统（`driver_seat`、`gunner_seat`、`loader_seat`、`aa_seat`、`azimuth_driver`、`main_controller`、`coax_rack`、`left_track`、`hull_era_left_01` 一类），名字写 `machine_max.<名>`，译文只进 builtin 一份；车包自己的命名空间只留本车独有的名字（M1A2 的 `citv_*` / `rws_*` / `loader_mg_*` / `antimateriel_*`、K17 的 `atgm_*`、MTLB 的 `main_*` 机枪组）。判据是「另一个车包会不会用同一个子系统」——只看角色与译文，不看 `definition`：静态属性按车各自标定，同一个名字在不同车包里指向各自的 `definition`，两者互不影响。名字是实例名，也是存档键与 `signal_targets` / `control_outputs` 的引用目标，所以合并名字只是删掉重复的键，不会让两辆车共享属性。

现存量：**0 个安装点**。判据落在「名字末段」上：末尾是 `_<数字>` 时先剥掉编号再判——`left_atgm_launcher_01` 判作 `left_atgm_launcher`、`passenger_seat_3` 判作 `passenger_seat`，因为编号紧跟在它所区分的名词之后（3.2）。

子系统名共 187 个（另有 61 个 `subsystem.<零件>.<频道>` 是信号地址，不是名字）：其中 153 个在 `machine_max`、34 个留在车包命名空间（M1A2 21、K17 9、MTLB 4）。

**裸名只允许出现在「一个变体内只有一个」的位置**：`engine`、`gearbox`、`transmission`、`motor`、`car_controller`、`track_controller`、`seat`（builtin 的通用座椅）都只有一件，直接用类型名；一旦同一变体内出现两个同类，必须带角色词。发射器一律写 `<角色>_launcher`：T-90A / 59 式 / M1A2 / MTLB 的主炮写 `main_launcher`（同变体里还有并列、反狙击、高射、装填手、遥控武器站各路发射器）。

### 3.5 轴词

只用 `azimuth`（回转 / 方向）与 `elevation`（俯仰 / 高低）两个词，**不用 `yaw` / `pitch`**。

```
[<角色>_]<azimuth|elevation>_driver        # 子系统
[<角色>_]<azimuth|elevation>               # 子零件
```

- 炮塔主回转与主炮俯仰在变体内唯一，可以省角色词：`azimuth_driver`、`elevation_driver`。
- 其余武器一律带角色词：`aa_azimuth_driver`、`rws_elevation_driver`、`left_atgm_elevation_driver`、`citv_azimuth_driver`。
- 子零件用同一套轴词：`aa_azimuth`、`aa_elevation`、`rws_azimuth`、`loader_mg_elevation`、`citv_azimuth`。

现存量：**`yaw` / `pitch` 0 个**。轴词用在子系统、子零件与连接点三处：

| 位置 | 写法 | 现存例子 |
| --- | --- | --- |
| 子系统 | `[<角色>_]<azimuth\|elevation>_driver` | `azimuth_driver` / `elevation_driver`（炮塔主回转与主炮俯仰，变体内唯一）、`aa_azimuth_driver`、`rws_elevation_driver`、`loader_mg_elevation_driver`、`citv_azimuth_driver`、`left_atgm_elevation_driver` |
| 子零件 | `[<角色>_]<azimuth\|elevation>` | `aa_azimuth`、`aa_elevation`、`rws_azimuth`、`loader_mg_elevation`、`citv_azimuth` |
| 连接点 | `[<角色>_]<azimuth\|elevation>[_lock]` | `aa_elevation`、`aa_elevation_lock`、`rws_elevation`、`rws_elevation_lock`、`loader_mg_elevation_lock`、`turret_coax_axis` |

`gun_elevation_driver` 这类冗余前缀不写：主炮俯仰就是裸名 `elevation_driver`。

### 3.6 灯、玻璃、镜

`basic` 类型是「任何可被伤害的子系统」，用来做零碎的破坏效果——玻璃、灯罩、后视镜这类。它**没有专属命名规则**：名字就写这个部件在车上是什么，不套用 3.4 的后缀表，也不要求角色词。

`light` 类型是灯具。**发光与否不是类型的判据，而是 `definition` 的**：`beam_light` 画定向体积光、`point_light` 画点光，`dummy_light` 的 `range` 是 0、`intensity` 是 0，只占一个可摧毁的位。因此：

- 灯具一律用 `light` 型，名字 `<方位>_<用途>_light`；亮不亮由它引用的 `definition` 决定。
- 只作可摧毁装饰的灯罩用 `basic`，名字写部件本身，推荐 `<方位>_<部件>_lamp`，与 `_light` 一眼可分。

| 类型 | 名字 | 中文 | 说明 |
| --- | --- | --- | --- |
| `basic` | `glass`、`<方位>_glass` | 玻璃、前窗 / 后窗玻璃 | |
| `basic` | `rearview_mirror` | 后视镜 | 固定词 |
| `basic` | `<方位>_<部件>_lamp` | 灯罩 | 推荐写法，不强制 |
| `light` | `<方位>_<用途>_light` | 前照灯 / 雾灯 / 示廓灯 / 尾灯 / 车内灯 | 用途封闭集：`main`（前照）、`fog`（雾灯）、`marker`（示廓）、`tail`（尾灯）、`interior`（车内） |

`glow_` 前缀在代码里没有依赖（全仓库 `grep` 无引用），词表不收录：灯罩写 `<方位>_<用途>_lamp`，用途词与 `_light` 共用一套。

现存 27 个 `light` 安装点（13 个不同名字）：酒狐 / K螺 的车体与灯件、面包车用 `light` 型，另有 6 个 `basic` 型灯罩（`left_main_lamp`、`left_fog_lamp`、`left_tail_lamp` 及右侧）。`light` 型里只有 K螺车体的 `left_main_light` / `right_main_light` 引用 `beam_light`，其余 25 个引用 `dummy_light`；`point_light` 定义了但没有任何零件引用。同一个类型里既有亮灯也有不亮的，命名上不区分，区分靠 `definition`。

同名前照灯有两处：K螺与酒狐的车体力 `left_main_light`（K螺那对是 `beam_light`）与各自灯件里的 `left_main_light`（`dummy_light` 灯罩位）。两块是不同零件、同一用途，按名解析各自只命中本零件的那一个，所以共用同一个名字与同一条译文——「左前照灯」。

### 3.8 连接点

```
<本端或位置>[_<对端>][_<接口词>]
```

- 成对的接口两端互为本端与对端：`hull_turret_axis` ↔ `turret_hull_axis`、`turret_gun_axis` ↔ `gun_turret_axis`、`barrel_cradle` ↔ `cradle_barrel`。
- 接口词封闭集：`axis`（回转轴）、`lock`（锁止）、`mount`（挂点）、`turret`（回转座）、`host`（承力座）、`connection`（通用对接）、`locator`（定位对接，仅存量使用）、`elevation`（俯仰接口）、`trailer`（牵引）。
- 轮类接口的本端写 `hull`（车体侧）与 `hub`（轮毂侧），位置短语用 3.7 的词干：`hull_left_road_wheel_01` ↔ `hub_left_road_wheel_01`（履带车）、`hull_left_wheel_01`（轮式车）；诱导轮与主动轮同法：`hull_left_idler_wheel` ↔ `hub_left_idler_wheel`、`hull_left_sprocket_wheel` ↔ `hub_left_sprocket_wheel`。轮座不论有几个都带 `hull`：只有前后两轮时写 `hull_front_wheel` / `hull_back_wheel`，四轮车写 `hull_left_front_wheel` / `hull_left_back_wheel`，同一方位有多个轴时写 `hull_left_back_wheel_01`。
- 附加装甲件侧在位置名后加 `_host`（承力座）：`hull_era_left`（车体侧安装座）↔ `hull_era_left_host`（装甲件侧连接座）、`turret_era_right` ↔ `turret_era_right_host`。
- **两侧不必同名**：配对按几何与 `definition`，不按名字。同一个接口在车体/底盘侧写位置（`left_front_door_axis`、`hull_right_front_wheel`），在可拆件侧写接口词（门件与舱盖件 `axis` / `lock`，车轮件 `chassis_connection`）。名字只描述本端，所以把车门并在车体零件里当子零件、或把两个零件合进一个零件时，不必因为撞名而改名。
- **限定词只补到「本件内能区分」为止**：本件只有一个该接口时只写接口词；同件内有多个同类接口才补方位与编号（车体侧同侧两扇门 → `left_front_door_axis` / `left_back_door_axis`，一件上并排四个裙板 → `hull_skirt_left_01` … `_04`）。
- 接口通名归 `machine_max`，一份译文进 builtin（见 1.3）；车包命名空间只留本车独有的接口名。判据是「另一个车包会不会用同一个接口」：行走机构（负重轮 / 诱导轮 / 主动轮的车体侧与轮毂侧）、炮塔座圈、火炮俯仰、炮管、附加装甲与爆反、裙板、高射机枪、车体后部挂点都在 `machine_max`；只有本车才有的接口留在车包命名空间——K17 的反坦克导弹挂点（`left_atgm_turret`、`turret_left_atgm_axis`）、M1A2 的 CITV 与遥控武器站（含装填手机枪）、Sd.Kfz.234 的防盾（`shield_turret_axis` …）、2S38 的并列机枪锁止（`coax_turret_lock`、`turret_coax_axis`）。MTLB 的机枪塔全用通名，命名空间里没有自有连接点。
- 方位与编号按 3.1、3.2。

现存量：连接点 204 个名字（自有命名空间 20、`machine_max` 184），其中**编号违规 0**、**方位词序 0**；方位同义词、型号名与轴词均为 0，**位置 + 编号的裸名字 0 个**。货位与轮座的写法：拖车平板的 15 个货位写作 `<列>_mount_01..05`（`left` / `middle` / `right` 三列，5 排），吉普车顶的 6 个写作 `top_left_mount_01..03` / `top_right_mount_01..03`；轮座一律以 `hull` 开头（`hull_left_wheel_01` … `hull_left_front_wheel`、`hull_front_wheel`），被挂的车轮件那侧写 `chassis_connection`（见上一条）；吉普与 Sd.Kfz.234 车体后部的 `fixed_back` 挂点共用 `hull_back_mount`（车体侧备胎挂点，两侧定义相同所以共用一个名字）。只写方位、不写名词的名字有一批（容器的 `top` / `bottom` / `left` / `right` / `front` / `back`、吉普车顶的 `top_front`、货架的 `left_front` 一类），它们挂什么由零件名给出，按 3.9 的限定词规则不补。自有命名空间那 20 个按包分：M1A2 11（CITV、遥控武器站、装填手机枪）、K17 4（反坦克导弹）、Sd.Kfz.234 3（防盾）、2S38 2（并列机枪锁止）。

### 3.9 交互区

```
interact.<命名空间>.<部位或角色>
```

- **不带 `_interact` 后缀**：交互区就是交互区，名字只写它开的是什么——`back_hatch`、`driver_hatch`、`commander_cover`、`back_case`。代码不读后缀，加与不加都不影响行为，只让读的人多一层噪音。
- **动词只有两个**：`进入`（座位、舱口、乘员舱）、`打开`（箱、门、盖）。不用「坐上」「开启」「拉开」。
- **名词分三种**：有角色词的座位写 `进入<角色>座`（`进入驾驶座`）；只有方位或排数的写 `进入<方位>座位`（`进入左侧座位`、`进入后排左侧座位`）；进的是乘员舱而非某个座位写 `进入<部位>舱`。
- **限定词只补「零件名和变体名没说、又确实会撞」的那一段**。基准是装到车上的那一刻要区分什么，零件名或变体名已经承担的区分不重复进名字：
  - 一个零件里同侧一扇门，车上也没有第二扇 → `<方位>_door`（吉普 `jeep_chassis` 的 `left_door` / `right_door`）。
  - 车上同侧有两扇门 → 都写前后：`<方位>_front_door` / `<方位>_back_door`。AE86 与 miniEV 的四扇门都在各自的 `_hull` 一个零件里；面包车分在前门件 `van_door` 与滑门件 `van_door_slide` 两件上，照样写前后——都叫 `left_door` 在同一台车上就分不清是哪一扇，而两者的提示与信号频道并不相同。
  - 一个零件里并排两座 → `<方位>_seat`。`ae86_back_seat` 一件里就是后排那两座，叫 `left_seat` / `right_seat`，名字里不写 `back`：「后排」由零件名承担，这件相对它自己只有左右两位。
  - 一个零件里前后两排都要区分 → `<方位>_<前/后>_seat`（miniEV 的 `left_front_seat` / `left_back_seat`）。
  - 一个零件里只有一座 → 裸名 `seat`（`ae86_seat` 装在驾驶位与副驾驶位，`van_seat` 的四个变体名分别是 `left_front_seat` / `left_back_seat` / `right_front_seat` / `right_back_seat`，方位由变体名承担）。
  这条同时管 3.8 的连接点：车体侧同侧两扇门就有两个门轴，写 `left_front_door_axis` 与 `left_back_door_axis`；门件侧只写 `axis` / `lock`，哪一扇由零件名与变体名承担。
- 名字不含点：写 `golden_seat`，不写 `golden.seat`。
- 交互区名不进存档，改名只动 `interact_boxes` 的键、两张路由表的值与语言键。

现存量：交互区 53 个名字，**`_interact` 后缀 0 个**、**带点的 0 个**；译文一律「进入」「打开」两个动词开头。门：面包车、AE86、miniEV 写全前后，吉普只写左右。盖：桑塔纳的 `hood` 与 `trunk_door` 按开的是什么写，后备箱的储物交互仍叫 `trunk`。座位：`ae86_seat` 与 `van_seat` 用裸名 `seat`；`ae86_back_seat` 用 `left_seat` / `right_seat`；大运、K螺、Senna、酒狐、吉普用 `left_seat` / `right_seat`；miniEV 用 `left_front_seat` / `left_back_seat`。

### 3.10 控制组

```
controlGroup.<命名空间>.<用途>
```

这一族键是控制组**条目**的显示名。条目写在 `control_groups/<文件名>.json` 里，一个文件可以有多组（`base_group` 与 `groups[]`），每组的 `name` 字段指向一个这样的键；预设 id 才是文件名（`control_group_preset` 引用 `<命名空间>:<文件名>`），子目录不参与 id 拼装，因此名字里不要靠目录区分同类。

- 条目名与预设文件所在的包不必同名：跨包同角色的条目共用 `machine_max` 下的键，车包只写本车独有的条目。`machine_max` 现有 8 个（`base`、`weapon_control`、`backup_fire_control`、`gunner`、`aa`、`observer`、`commander_base`、`commander_override`），M1A2 自有 6 个（`gunner_coax`、`gunner_antimateriel`、`gunner_main_only`、`loader_mg`、`commander_observe`、`commander_backup_fire`），K17 自有 2 个（`atgm_control`、`autocannon_control`）。判据与 3.4 的同名规则一致——另一个车包会不会用同一个条目。
- 不带包名冗余：命名空间已经说明归属，写 `controlGroup.machine_max.gunner`，不写 `t90a_gunner`。
- 不带车名、型号名与口径名：值写 `炮手`、`高射机枪`、`车长超控`，不写 `T-90A 炮手`、`车长（探出）／指挥塔 M2`、`装填手／车顶机枪`。哪个乘员能操作哪门武器由条目控的频道表达，不进显示名。
- 用途词取自角色词表（3.3）加职责词：`driver`、`commander`、`gunner`、`loader`、`observer`、`aa`、`base`、`override`、`backup_fire`。武器也按角色词写（`gunner_coax`、`gunner_antimateriel`）；几个站位共用的组不写人，写它控什么：`weapon_control`、`autocannon_control`、`atgm_control`、`backup_fire_control`。
- 一组不止一个条目时，子条目的显示名说明它多控什么（`炮手：主炮、并列机枪`、`车长：备用火控（主炮／机枪）`），中文标点用全角 `／` 与 `、`，不写 `＋`。

现存量：16 个条目键、35 处使用；命名空间前缀、包名冗余、车名、型号名与口径名违规均为 0。

### 3.11 机器标签

两类，都写在 `tags` 里：

| 类 | 形状 | 已用维度 |
| --- | --- | --- |
| 维度标签 | `<维度>/<值>` | `type`、`category`、`direction`、`series`、`caliber`、`ammo`、`armor`、`addon_armor` |
| 种类标签 | 单个词 | `hull`、`turret`、`chassis`、`seat`、`wheel`、`door`、`hood`、`trunk`、`rack`、`storage`、`bumper`、`spoiler`、`gt` |

- 维度值用小写下划线，不带空格：`caliber/12_7mm`、`ammo/apfsds`。
- 标签的命名空间决定归属：`machine_max:` 下的标签由 builtin 提供，车包不得为了自己排序另造同名标签。

**两个层次，判据是「跨包查询会不会得到同一个答案」：**

| 层次 | 放哪 | 例子 | 判据 |
| --- | --- | --- | --- |
| 维度标签 | `machine_max:<维度>/<值>` | `type/land`、`category/weapon`、`series/t90a`、`caliber/125mm`、`armor/hull_left` | 任何包都想用它筛选同一类东西 |
| 包私有标签 | `<包名>:<词>` | `m1a2_sep:m153_crows`、`m1a2_sep:m153_crows_terminal` | 只有本包知道它指什么，没有跨包查询需求 |

现存 75 个标签，73 个在 `machine_max:` 下，只有上表那两个 `m1a2_sep:m153_crows*` 是包私有。标签同时是**配对键**：零件的 `tags` 声明它提供什么，命中箱的 `required_tags` 声明它要求什么，改一个标签必须两端一起改，否则命中箱静默失配。

**`armor/` 是唯一既带部位又带槽号的维度**，值形状 `<部位>_<方位>[_<槽号>]`：

| 值 | 谁在用 | 中文 |
| --- | --- | --- |
| `armor/hull_left`、`hull_right` | M1A2 的 ARAT 瓦、T-90A 的 Kontakt-5 瓦，整侧覆盖 | 车体左侧装甲 / 车体右侧装甲 |
| `armor/turret_left`、`turret_right` | 同上，炮塔侧 | 炮塔左侧装甲 / 炮塔右侧装甲 |
| `armor/hull_front` | T-90A 车体正面爆反 | 车体正面装甲 |
| `armor/hull_left_01`…`_04`、`hull_right_01`…`_04` | 2S38 的逐块附加装甲槽 | 车体左侧装甲 01 … |

整侧覆盖不加编号，逐块装配才加，槽号两位补零。平面种类标签 `machine_max:armor` 表示「这是一件附加装甲」。

**标签的译名键是 `<命名空间>.<路径>`，路径里的 `/` 换成 `.`**——`TextUtil.getTagLanguageKey` 就是这么拼的，写成 `machine_max.armor/hull_left` 的键永远查不到。通用标签的译名放在 builtin 的 `machine_max` 语言文件里。

### 5.1 名字的引用面

改名的风险不在键位，而在把名字当字符串用的地方——下面这些引用面不参与「三类名字无重名」的检查，写错了也不报错：

| 引用面 | 形式 | 解析不到的表现 |
| --- | --- | --- |
| 变体 JSON 内部 | 碰撞箱 / 交互区的 `condition` MoLang；碰撞箱的 `subsystem` 字段；子系统的 `connector` / `power_output` / `power_outputs`；`signal_targets`；`control_outputs` | 条件恒假、子系统找不到控制对象、信号发进虚空 |
| 动画 | `animations/**/*.animation.json` 的 `local.has_connector` / `connector_offset` / `connector_rotation` / `has_subsystem` / `subsystem_active` / `subsystem_destroyed`，参数是完整名字键 | 查询恒为 0、恒为「未摧毁」：悬架摆臂不跟动、爆反挡板不缩 |
| 模板 | `advConnectorName` / `simplePointConnectorName` | 两个零件的连接点配不上，装配体少一组约束 |
| 语言表 | 键本身就是名字 | 孤儿键，或界面上原样显示键名 |

`checkContent` 第 13 条核前三条，作用域各有不同：变体内的字符串引用按**本变体**的名字集合核（`AbstractPart#findConnector` / `#findSubsystem` 只查本部件）；动画按**引用它的变体们的名字并集**核（一份动画可被同一装配体的多个零件共用，每个零件只认自己有的连接点）；模板按**全部内容包的定义并集**核（模板的职责就是把跨零件的连接点配成一条线）。

按本变体核还能顺手发现「写的是别的零件的名字」这类错：目标名在另一个零件里存在、在本变体里不存在时，全局并集查不出来，本变体查得出来——那几条信号一直发不出去。

[`tools/naming/mm_refs.py`](../tools/naming/mm_refs.py) 是同一套判据的离线版，另覆盖 `checkContent` 不扫的两处：模组源码字符串里的名字（GameTest 内联的 JSON），以及语言表里没有对应内容定义的孤儿键。它逐层报告，未解析时退出码为 1。

```bash
python tools/naming/mm_refs.py            # 三层引用 + 孤儿键
python tools/naming/mm_refs.py --kind connector
python tools/naming/mm_refs.py --verbose  # 连同已解析的动画作用域一并列出
```

音效 id 也占用 `subsystem.` 前缀（`sounds/*.json` 的键形如 `subsystem.gearbox.up.light`），与名字键同形，两个工具都把它排除在名字之外。

映射文件是扁平 JSON（`{"旧完整键": "新完整键"}`）。改名按文本替换执行，保留 JSONC 注释、缩进与原文件的换行风格；替换与新键的撞名判定都带右边界断言，`subsystem.x.foo` 不会命中 `subsystem.x.foo_bar`，新名是旧名的前缀时（`driver_hatch` 对 `driver_hatch_interact`）也不算撞名。

## 七、开放问题

### 7.1 已定

| 问题 | 结论 |
| --- | --- |
| 灯的类型与名字 | 灯具一律 `light` 型，名字 `<方位>_<用途>_light`；亮不亮由 `definition` 决定 |
| `basic` 要不要命名规则 | 不要。它是「任何可被伤害的子系统」，名字写部件本身 |
| 装饰灯罩叫什么 | 推荐 `<方位>_<部件>_lamp`，与 `_light` 分开，不强制 |
| M1A2 两挺随动炮管的机枪怎么分 | 按用途：`coax`（并列，M240 7.62）与 `antimateriel`（反狙击，CSAMM 12.7）。名实以 `definition` 为准，`coax_*` 引 `7_62mm_m240_*`、`antimateriel_*` 引 `12_7mm_m2hb_*` |
| 车长指挥塔的 M2 归哪类 | 高射机枪 `aa_*`。`commander_mg` 这个角色词不收录 |
| 装填手舱口的 M240 | `loader_mg_*`。只因当前只有 M1A2 一例，角色词照样收录——它描述的是使用者，不是型号 |
| K17 / Sd.Kfz.234 的「副武器」 | 都是同轴机枪 → `coax_*`；主武器是 `main_*` |
| 储物箱的规格 | 写在零件名上，不进子系统名 |
| 口径算不算角色词 | 不算，口径不进名字 |
| 哪些子系统留在车包命名空间 | 跨包同义的收进 `machine_max`（座位、瞄具、爆反、发动机、炮塔与机枪各角色、履带驱动、储物箱）；只有本车才有的留在车包命名空间（M1A2 的 `citv_*` / `rws_*` / `loader_mg_*` / `antimateriel_*`、K17 的 `atgm_*`、MTLB 的 `main_*` 机枪组） |
| 座位的值写不写职责 | 不写。值只写角色（`炮手座`、`高射机枪座`），该乘员能操作哪些武器由控制组条目表达 |
| 控制组条目名跨包共用吗 | 同角色共用 `machine_max` 键（`base`、`gunner`、`aa`、`observer`、`commander_base`、`commander_override` 等），值不写车名与型号；一组多条目时子条目写它多控什么 |
| 标签归属 | 通用维度标签一律 `machine_max:`（放 builtin），只有包私有标记留在包命名空间；15 个越界标签已收口 |
| 装甲维度 | 只保留 `armor/`，`addon_armor/*` 并入其槽号形式；平面种类标签 `machine_max:armor` 表示附加装甲件 |
| 连接点两侧要不要同名 | 不要。配对按几何与 `definition`，不按名字，名字只描述本端。两端同名会让名字随打包方式变化：把两端合进同一个零件时，同一变体里出现两个同名连接点，`VariantAttr` 的查重会直接拒绝加载 |
| 什么时候写裸接口词 | 本件只有一个该接口时（门件与舱盖件 `axis` / `lock`，车轮件 `chassis_connection`）；同件内同类接口多起来才补方位与编号，接口通名归 `machine_max` |
| 负重轮、诱导轮、主动轮叫什么 | `road_wheel` / `idler_wheel` / `sprocket_wheel`，都带 `_wheel` 收尾；轮式车用 `wheel`（`hull_left_wheel_01`）。2S38 是履带车，负重轮连接点写 `road_wheel`，与 K17 / Sd.Kfz.234 的 `wheel` 分开 |
| 哪些连接点进 `machine_max` | 跨包同义的接口进 `machine_max`（行走机构、炮塔座圈、火炮俯仰、炮管、附加装甲与爆反、裙板、高射机枪、车体后部挂点）；只有本车才有的接口留在车包命名空间（K17 的反坦克导弹挂点、M1A2 的 CITV / 遥控武器站 / 装填手机枪、Sd.Kfz.234 的防盾、2S38 的并列机枪锁止）。MTLB 的机枪塔座圈与枪体接口用的都是通名，命名空间里没有自有连接点 |
| 裸 `launcher` 怎么定名 | 写 `main_launcher`。`main` 是角色词，不表示「车上有主炮」；发射器一多就轮不到裸名，而 `main_launcher` 与 `main_controller` / `main_rack` / `main_loader` 同属一组角色词 |
| 同一门炮的 AP / HE 装弹机怎么并列 | `ap` / `he` 夹在角色词与后缀之间：`main_ap_loader` / `main_he_loader`、`main_ap_rack` / `main_he_rack`。共用一套机构时只写一份 |
| 遥控武器站的终端叫什么 | `rws_terminal_controller`。它和炮架上的 `rws_controller` 引同一个 `weapon_controller` 定义，是两个安装点，名字要能分开；`crows`（M153）是型号，不进名字 |
| 轴词与接口词能不能叠 | 能。锁止接口写 `<角色>_elevation_lock`（`aa_elevation_lock`、`rws_elevation_lock`、`loader_mg_elevation_lock`），因为 3.5 要求用 `elevation` 而不是 `pitch` |
| 类型后缀遇到编号怎么判 | 先剥掉末尾的 `_<数字>` 再判后缀：`left_atgm_launcher_01` 判作 `left_atgm_launcher`、`passenger_seat_3` 判作 `passenger_seat`（编号跟在名词之后，见 3.2） |
| 存档兼容 | 开发期不做旧名映射 |
