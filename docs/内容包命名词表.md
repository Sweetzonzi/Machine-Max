# 内容包命名词表

本文是内容包具名对象的取名判据：子系统、子零件、连接点、交互区、控制组这五类键怎么写，以及这些键对应的中文译文用哪个词。写内容、翻译、加校验、批量改名都以本文为准。

**不在本文范围**：内容 id（`<命名空间>/<文件名>`）、弹种 id 与效果词表（见 [`武器系统-弹药命名规范.md`](武器系统-弹药命名规范.md)）、材质名、型号 id（`fittings/`）、HUD 页面、投射物、配方。

**计数口径**：下文「个」指一个完整的白名单键（`subsystem.<命名空间>.<名字>`），同名出现在两个包里计两次；「去重后」指去掉命名空间后的名字数。数字是本文撰写时的盘点结果，随迁移归零，不随内容增加而失效。

---

## 一、前提

### 1.1 五类键里三类是存档键

内容里的名字统一写成完整键 `<类>.<命名空间>.<名字>`，整串就是 JSON 对象里的键，也是运行时寻址用的字符串。

| 类 | JSON 落点 | 进存档 | 改名的后果 |
| --- | --- | --- | --- |
| `subsystem.` | `sub_parts.<子零件>.subsystems` 的键；`hit_boxes.*.subsystem`、`signal_targets`、`passenger_num_outputs` 的值 | 是 | 旧档里该子系统找不到落点，安装块整块丢失 |
| `sub_part.` | `sub_parts` 的键 | 是 | 旧档里该子零件与其上的碰撞箱、连接点一起丢失 |
| `connector.` | `sub_parts.<子零件>.connectors` 的键；`signal_targets`、`signal_translations`、`passenger_num_outputs` 的值 | 是 | 旧档里该连接点丢失，装配体在该处断开 |
| `interact.` | `interact_boxes` 的键；`signal_targets`、`passenger_num_outputs` 的值 | 否 | 只影响交互面板显示名与信号路由 |
| `controlGroup.` | `control_groups/<名字>.json` 的文件名 | 否 | 需同步座位的 `control_group_preset` 与语言键 |

改一个名字要一起改的引用：`hit_boxes.*.subsystem`、`signal_targets`、`signal_translations`、`passenger_num_outputs`、动画里的 `local.subsystem_destroyed('…')`，以及 `templates/` 与 `assemblies/` 里同一变体的副本。正因为引用面这么大，前三类名字的改动属于**存档破坏性改动**。当前处于开发期，改名不保旧档、不做旧名映射；这条豁免随 beta 结束失效，正式版之后改名必须附 `LegacyNames` 映射或版本化迁移。

### 1.2 同一变体内同类名字唯一

四类键各存一张表，跨表不冲突（键前缀不同），同一张表内必须唯一。语言键一侧的约束更强：`checkContent` 已有反向检查（每个语言键必须有消费方），因此「翻译了但没人用」的空键会直接报错——**加译文之前先确认内容里已有同名键**。

### 1.3 译文归属跟着命名空间走

`LangModule` 按 `namespace:lang/<locale>.json` 合并同命名空间的语言文件，加载顺序 builtin → kit → 车包，后者覆盖前者。因此：

- `machine_max.*`：builtin 与所有 kit 共写。通名（并列机枪、火控、方向机、储物箱）放 builtin；某个型谱专有的型号名（PKTM、2A42）放对应 kit。
- `<车名>.*`：只有该车包写。

## 二、键的构形

```
<类>.<命名空间>.<名字>
```

- 类固定为 `subsystem` / `sub_part` / `connector` / `interact` / `controlGroup`，不新增。
- 名字只用小写字母、数字、下划线；**名字内不含点**。名字出现第四个点即违规，`interact.machine_max.golden.seat` 是唯一一处。
- 命名空间由包决定：车包用自己的包名，kit 与 builtin 共用 `machine_max`。

## 三、词表

### 3.1 方位词

封闭集：`left` `right` `front` `back` `top` `bottom` `middle`

四条规则：

1. **方位词一律作前缀**，不跟在名词后面。
2. **词序：垂直 → 侧向 → 纵向**。`top_left_front` 合规；`left_top`、`front_left` 不合规。
3. `middle` 只用于居中单件，不与 `left` / `right` 连用。
4. 禁用同义词：`rear`（用 `back`）、`aft`（用 `back`）、`port`（用 `left`）、`up`（用 `top`）、`down`（用 `bottom`）、`center`（用 `middle`）。

规则 2、3 描述的是带方位的位置短语；`subsystem.machine_max.engine`、`subsystem.machine_max.gearbox` 这类不带方位的通名不受影响。

现存量：**词序违规 10 个**、**同义词违规 29 个**。

词序违规（都在 `machine_max` 与 M1A2 里）：

| 名字 | 应作 |
| --- | --- |
| `connector.machine_max.back_left`、`back_right` | 不能直接换序——`left_back` / `right_back` 已是门与座椅的路由点，须按用途改成 `left_back_door_hinge` 一类 |
| `connector.machine_max.front_bumper_left`、`front_bumper_right`、`back_bumper_left`、`back_bumper_right` | `left_front_bumper`、`right_front_bumper`、`left_back_bumper`、`right_back_bumper` |
| `connector.machine_max.front_light_left`、`front_light_right` | `left_front_light`、`right_front_light` |
| `subsystem.machine_max.glow_back_left_light`、`glow_back_right_light` | `glow_left_back_light`、`glow_right_back_light`（`glow_` 前缀另见 3.6） |

同义词违规（28 个在 M1A2、1 个在 MTLB）：M1A2 的 `aft_mg_*`（`aft` = 后）与 `port_mg_*`（`port` = 左）横跨子系统、连接点、子零件；MTLB 的 `interact.mtlb.rear_door_interact` 用了 `rear`。`aft` / `port` 是舰船词，本项目的方位词只有 3.1 列的七个。机枪这几个名字不靠换序修，而是改成按使用者命名的角色词，见 3.3；`rear_door` 改成 `back_door`。

### 3.2 编号

```
<名字>_<两位序号>
```

- **下划线分隔**：`interior_light_01` 合规，`interior_light1` 不合规。
- **两位补零**：`_01` … `_09`、`_10`。
- **起点 01**，不跳号；左右对称件的编号必须同号（`left_road_01` ↔ `right_road_01`）。
- **编号紧跟在它所区分的名词之后**，不放到轴词、接口词后面：`left_atgm_tube_01` 合规，`left_atgm_01_tube` 不合规。
- 只有一件时不编号（用 `left_main_light`，不用 `left_main_light_01`）。

现存量：**编号违规 291 个**（`connector.` 191、`sub_part.` 64、`subsystem.` 36），去重后 187 个名字。

子系统那 36 个是：`left_wheel_1..4` 与 `right_wheel_1..4`（K17、Sd.Kfz.234 各一套，共 16）、`passenger_seat_1..8`（MTLB）、`left_atgm_tube_1/2` 与 `right_atgm_tube_1/2`（K17）、`left_back_wheel_1_driver` 一类 4 个、`light1..4`（builtin，缺下划线）。爆反（`hull_era_left_01` …）已经合规，是唯一成体系的编号写法。

### 3.3 角色词

子系统名字的最左一段是角色词，取自封闭集：

| 角色词 | 中文 | 用什么场合 |
| --- | --- | --- |
| `main` | 主炮 | 主武器 |
| `coax` | 并列机枪 | 与主炮同轴的机枪 |
| `aa` | 高射机枪 | 车顶 / 指挥塔上的大口径机枪，含 T-90A 与 59 的车顶高机、M1A2 车长指挥塔的 M2 |
| `antimateriel` | 反狙击机枪 | 随动炮管、口径大于并列机枪，用于反狙击 / 反器材 |
| `loader_mg` | 装填手机枪 | 装在装填手舱口、由装填手操作（当前只有 M1A2 一例） |
| `left` / `right` | 左 / 右 | 成对且不属于上述角色时用方位词；机枪不用方位词 |
| `rws` | 遥控武器站 | 遥控武器站整体 |
| `citv` | 车长独立观瞄 | 车长独立热像仪一类 |
| `atgm` | 反坦克导弹 | 导弹发射管与其配套件 |
| `commander` / `gunner` / `loader` / `driver` / `passenger` / `copilot` / `radio` | 车长 / 炮手 / 装填手 / 驾驶 / 载员 / 副驾驶 / 无线电员 | 座位、瞄具、舱口 |
| `track` | 履带 | 履带驱动与履带行驶控制 |
| `wheel` | 负重轮 | 轮式车的车轮与负重轮 |

**型号名不进名字。** 型号由 `definition` 与译文表达，名字只写角色。

现存量：**型号名与口径名 29 个子系统 + 7 个连接点**。

- 2S38：`2a90`、`2a90_ap_autoloader`、`2a90_ap_loader`、`2a90_he_autoloader`、`2a90_he_loader`、`pktm`、`pktm_ammo_autoloader`、`pktm_ammo_loader`、`pktm_elevation_driver`
- K17：`2a42`、`2a42_ammo_autoloader`、`2a42_ammo_loader`、`pktm`、`pktm_ammo_autoloader`、`pktm_ammo_loader`
- MTLB：`pkt`、`pkt_ammo_autoloader`、`pkt_ammo_loader`
- Sd.Kfz.234：`50mm`、`50mm_ammo_loader`、`50mm_he_ammo_loader`、`mg34`、`mg34_ammo_autoloader`、`mg34_ammo_loader`
- M1A2：`crows_terminal`（CROWS 是遥控武器站的型号，应写 `rws_controller`）、`coax_762_autoloader`、`coax_762_controller`、`coax_762_launcher`、`coax_762_loader`（口径进名字）
- 连接点：`pktm_turret_lock`、`turret_pktm_axis`（2S38），`hull_pkt_axis`、`pkt_gun_axis`、`pkt_gun_lock`、`pkt_hull_axis`（MTLB），`crows_terminal_mount`（M1A2）

**机枪按使用者与用途命名，不用方位词。** `aft` / `port` 既不在方位词封闭集里，也说不清是谁的枪：M1A2 的 `aft_mg_*` 是车长指挥塔上的 M2，口径 12.7、装在高射枪架上，归 `aa`；`port_mg_*` 是装填手舱口的 M240，归 `loader_mg`。同一辆车的四挺机枪因此是 `coax`（并列）、`antimateriel`（反狙击）、`aa`（高射）、`loader_mg`（装填手）。

M1A2 还有一处名实颠倒：`coax_762_*` 才是并列机枪（M240 7.62），`coax_*` 是反狙击的 CSAMM 12.7。按本表两者互换——`coax_762_*` → `coax_*`，`coax_*` → `antimateriel_*`。

**口径不算角色词。** `coax_762` 与 `coax_127` 这种写法把口径塞进了名字，与「名字只写角色」冲突；口径交给 `definition` 与零件名。

### 3.4 类型后缀

名字的最右一段由子系统类型决定，一个类型一个后缀：

| 类型 | 名字形状 | 中文正词 |
| --- | --- | --- |
| `basic` | `<部件名>`，无类型后缀 | 见 3.6 |
| `seat` | `<角色>_seat`、`<方位>_seat`、`passenger_seat_<编号>` | 座 |
| `item_storage` | `<部位>_box`、`<部位>_storage`、`trunk`；不写规格 | 储物箱 / 后备箱 |
| `engine` | `engine` | 发动机 |
| `motor` | `motor` | 电动机 |
| `gearbox` | `gearbox` | 变速箱 |
| `transmission` | `transmission` | 传动系统 |
| `track_controller` | `track_controller` | 履带行驶控制器 |
| `track_drive` | `left_track` / `right_track` | 左 / 右履带驱动 |
| `wheel_driver` | `<方位>_wheel_<编号>`、`<方位>_<front\|back>_wheel`（类型已表达驱动，名字不带 `_driver`） | 负重轮驱动 |
| `car_controller` | `car_controller` | 行驶控制器 |
| `motorbike_controller` | `motorbike_controller` | 摩托车控制器 |
| `turret_driver` | `[<角色>_]<azimuth\|elevation>_driver` | 方向机 / 高低机 |
| `light` | `<方位>_<用途>_light` | 灯（用途见 3.6） |
| `launcher` | `<角色>_launcher` | 发射器 |
| `ammo_loader` | `<角色>_loader` | 自动装弹机 |
| `regen_ammo_rack`、`ammo_rack` | `<角色>_rack` | 弹药架 |
| `weapon_controller` | `<角色>_controller` | 火控 |
| `camera` | `<角色>_optics` | 观瞄 |
| `sight` | `<角色>_sight` | 瞄准镜 |
| `reactive_armor` | `<部位>_era_<方位>_<编号>` | 反应装甲 |

三条推论：

- **装弹与弹药分开**：`_loader` 只给 `ammo_loader`（会自动装弹的机构），`_rack` 只给 `regen_ammo_rack` / `ammo_rack`（弹药架）。`2a90_ap_loader` 的 `type` 是 `regen_ammo_rack`，名字里却是 `_loader`，属于把两类混写。
- **观瞄与瞄准镜分开**：`camera`（热像仪、车长独立观瞄、炮手主镜）用 `_optics`，`sight`（机械瞄具、直瞄镜）用 `_sight`。现状里 `gunner_sight` 在 2S38 / M1A2 是 `camera`、在 Sd.Kfz.234 / T-90A / 59 是 `sight`，同一个名字指两种东西。
- **规格不进子系统名**：储物箱的体积（`container_16x16x32`、`reinforced_container_16x16x8`）是零件级的规格，写在零件名上；子系统只写它是储物箱。同一变体里有两个以上储物箱时才用方位词区分（`left_glove_box` / `right_glove_box`）。

现存量：**83 个安装点的后缀与类型不符**（子系统，去重后 61 个名字；裸名不计入这一条，见下段），集中在 `*_autoloader`（应为 `_loader`）、`*_loader`（`regen_ammo_rack`，应为 `_rack`）、`main_weapon` / `atgm_weapon` / `secondary_weapon` / `weapon`（应为 `_controller`）、`*_sight`（`camera`，应为 `_optics`）、`commander_citv`（应为 `citv_optics`）、`crows_terminal`（应为 `rws_controller`）。

**裸名只允许出现在「一个变体内只有一个」的位置**：`engine`、`gearbox`、`transmission`、`motor`、`car_controller`、`track_controller`、`seat`（builtin 的通用座椅）都只有一件，直接用类型名；一旦同一变体内出现两个同类，必须带角色词。M1A2 的裸 `launcher` 与并列、反狙击、遥控武器站、车长、装填手五路发射器并存，若它真是主炮，应作 `main_launcher`。

### 3.5 轴词

只用 `azimuth`（回转 / 方向）与 `elevation`（俯仰 / 高低）两个词，**不用 `yaw` / `pitch`**。

```
[<角色>_]<azimuth|elevation>_driver        # 子系统
[<角色>_]<azimuth|elevation>               # 子零件
```

- 炮塔主回转与主炮俯仰在变体内唯一，可以省角色词：`azimuth_driver`、`elevation_driver`。
- 其余武器一律带角色词：`aa_azimuth_driver`、`rws_elevation_driver`、`left_atgm_elevation_driver`、`citv_azimuth_driver`。
- 子零件用同一套轴词：`aa_azimuth`、`aa_elevation`、`rws_azimuth`、`loader_mg_elevation`、`citv_azimuth`。

现存量：**`yaw` / `pitch` 27 个**（子系统 11、子零件 11、连接点 5 个 `*_pitch_lock`），另有 2 处虽已用 `elevation` 但需改写——`2s38.gun_elevation_driver` 的 `gun_` 是冗余前缀（主炮俯仰即裸名 `elevation_driver`）、`2s38.pktm_elevation_driver` 是型号名（应作 `coax_elevation_driver`）。

| 现名 | 应作 |
| --- | --- |
| `aft_mg_yaw_driver` / `aft_mg_pitch_driver`（子零件 `aft_mg_yaw` / `aft_mg_pitch`） | 子系统 `aa_azimuth_driver` / `aa_elevation_driver`；子零件写 `aa_azimuth` / `aa_elevation` |
| `port_mg_yaw_driver` / `port_mg_pitch_driver`（子零件 `port_mg_yaw` / `port_mg_pitch`） | `loader_mg_azimuth_driver` / `loader_mg_elevation_driver` |
| `rws_yaw_driver` / `rws_pitch_driver`（子零件 `rws_yaw` / `rws_pitch`） | `rws_azimuth_driver` / `rws_elevation_driver` |
| `citv_yaw_driver`（子零件 `citv_yaw`） | `citv_azimuth_driver` |
| `aa_yaw_driver` / `aa_pitch_driver`（子零件 `aa_yaw` / `aa_pitch`，T-90A 与 59 各一套） | `aa_azimuth_driver` / `aa_elevation_driver` |

### 3.6 灯、玻璃、镜

`basic` 类型是「任何可被伤害的子系统」，用来做零碎的破坏效果——玻璃、灯罩、后视镜这类。它**没有专属命名规则**：名字就写这个部件在车上是什么，不套用 3.4 的后缀表，也不要求角色词。

`light` 类型是灯具。**发光与否不是类型的判据，而是 `definition` 的**：`beam_light` 画定向体积光、`point_light` 画点光，`dummy_light` 的 `range` 是 0、`intensity` 是 0，只占一个可摧毁的位。因此：

- 灯具一律用 `light` 型，名字 `<方位>_<用途>_light`；亮不亮由它引用的 `definition` 决定。
- 只作可摧毁装饰的灯罩用 `basic`，名字写部件本身，推荐 `<方位>_<部件>_lamp`，与 `_light` 一眼可分。

| 类型 | 名字 | 中文 | 说明 |
| --- | --- | --- | --- |
| `basic` | `glass`、`<方位>_glass` | 玻璃、前窗 / 后窗玻璃 | |
| `basic` | `rearview_mirror` | 后视镜 | 固定词 |
| `basic` | `<方位>_<部件>_lamp` | 灯罩 | 推荐写法，不强制 |
| `light` | `<方位>_<用途>_light` | 前照灯 / 雾灯 / 示廓灯 / 车内灯 | 用途封闭集：`main`（前照）、`fog`（雾灯）、`marker`（示廓）、`interior`（车内） |

`glow_` 前缀在代码里没有依赖（全仓库 `grep` 无引用），属于历史写法，词表不收录。

现存两套灯：酒狐 / K螺 用 `light` 型，面包车用 `basic` 型灯罩。`light` 型共 27 个安装点（15 个不同名字），其中只有 K螺的 `left_front_light` / `right_front_light` 引用 `beam_light`，其余 25 个引用 `dummy_light`；`point_light` 定义了但没有任何零件引用。同一个类型里既有亮灯也有不亮的，命名上不区分，区分靠 `definition`。

现存名字里缺用途词的有：`left_light` / `right_light`、`middle_light`、`light1..4`（都不是本节允许的形状）；`left_front_light` 与 `left_main_light` 同时存在且都可能指前照灯，改名前要先按用途把它们分清。

### 3.7 子零件

| 词 | 中文 | 说明 |
| --- | --- | --- |
| `main` | 主体 | 每个变体恰好一个，承载车体 / 炮塔本体 |
| `gun` | 炮身 | 火炮本体（不含管） |
| `barrel` | 炮管 | 管状部分 |
| `mg` | 机枪 | 泛称机枪子零件，型号不进名 |
| `left_atgm` / `right_atgm` | 左 / 右反坦克导弹 | 导弹发射子零件 |
| `<角色>_<azimuth\|elevation>` | 回转体 / 俯仰体 | 见 3.5 |
| `<方位>_road_<编号>` / `<方位>_wheel_<编号>` | 负重轮 | 履带车用 `road`，轮式车用 `wheel` |
| `<方位>_idler` / `<方位>_sprocket` | 诱导轮 / 主动轮 | |

现存量：**编号 64 个**（`left_road_1..7` 一类）、**轴词 11 个**（见 3.5）。另有两处写法不统一：`road` 与 `roadwheel` 并存（MTLB 用 `roadwheel`）、`gun_barrel` 与 `barrel` 并存。

### 3.8 连接点

```
<本端或位置>[_<对端>][_<接口词>]
```

- 成对的接口两端互为本端与对端：`hull_turret` ↔ `turret_hull`、`gun_turret` ↔ `turret_gun`、`barrel_cradle` ↔ `cradle_barrel`。
- 接口词封闭集：`axis`（回转轴）、`lock`（锁止）、`mount`（挂点）、`turret`（回转座）、`host`（承力座）、`connection`（通用对接）、`locator`（定位对接）、`elevation`（俯仰接口）、`trailer`（牵引）。
- 方位与编号按 3.1、3.2。

现存量：连接点 387 个名字（自有命名空间 280、`machine_max` 107），其中**编号违规 191**、**方位词序 8**、**方位同义词 8**（`aft_mg_*`、`port_mg_*`、`turret_aft_mg`、`turret_port_mg`）、**型号名 7**、**轴词 5**（`*_pitch_lock`）。

### 3.9 交互区

```
interact.<命名空间>.<部位或角色>
```

- **不带 `_interact` 后缀**：`back_hatch_interact`、`driver_hatch_interact`、`commander_cover_interact`、`back_case_interact` 等 10 个名字要去掉后缀（代码对后缀无依赖）。
- **动词只有两个**：`进入`（座位、舱口、乘员舱）、`打开`（箱、门、盖）。不用「坐上」「开启」「拉开」。
- **名词分三种**：有角色词的座位写 `进入<角色>座`（`进入驾驶座`）；只有方位或排数的写 `进入<方位>座位`（`进入左侧座位`、`进入后排左侧座位`）；进的是乘员舱而非某个座位写 `进入<部位>舱`。
- **限定词只补「零件名和变体名没说、又确实会撞」的那一段**。基准是装到车上的那一刻要区分什么，零件名或变体名已经承担的区分不重复进名字：
  - 一个零件里同侧一扇门，车上也没有第二扇 → `<方位>_door`（吉普 `jeep_chassis` 的 `left_door` / `right_door`）。
  - 车上同侧有两扇门 → 都写前后：`<方位>_front_door` / `<方位>_back_door`。AE86 与 miniEV 的四扇门都在各自的 `_hull` 一个零件里；面包车分在前门件 `van_door` 与滑门件 `van_door_slide` 两件上，照样写前后——都叫 `left_door` 在同一台车上就分不清是哪一扇，而两者的提示与信号频道并不相同。
  - 一个零件里并排两座 → `<方位>_seat`。`ae86_back_seat` 一件里就是后排那两座，叫 `left_seat` / `right_seat`，名字里不写 `back`：「后排」由零件名承担，这件相对它自己只有左右两位。
  - 一个零件里前后两排都要区分 → `<方位>_<前/后>_seat`（miniEV 的 `left_front_seat` / `left_back_seat`）。
  - 一个零件里只有一座 → 裸名 `seat`（`ae86_seat` 装在驾驶位与副驾驶位，`van_seat` 的四个变体名分别是 `left_front_seat` / `left_back_seat` / `right_front_seat` / `right_back_seat`，方位由变体名承担）。
  这条同时管 3.8 的连接点：同侧两扇门就有两个门轴，写 `left_front_door_axis` 与 `left_back_door_axis`。
- 名字不含点：`golden.seat` 应作 `golden_seat`。
- 交互区名不进存档，改名只动 `interact_boxes` 的键、两张路由表的值与语言键。

现存量：**带 `_interact` 后缀 10 个**。门：面包车、AE86、miniEV 写全前后，吉普只写左右。座位：`ae86_seat` 与 `van_seat` 用裸名 `seat`；`ae86_back_seat` 用 `left_seat` / `right_seat`；大运、K螺、Senna、酒狐、吉普用 `left_seat` / `right_seat`；miniEV 用 `left_front_seat` / `left_back_seat`。

### 3.10 控制组

```
controlGroup.<命名空间>.<用途>
```

这一族键是控制组**条目**的显示名。条目写在 `control_groups/<文件名>.json` 里，一个文件可以有多组（`base_group`、`weapon_control` 等），按「`base_group` 的 `name`」取语言键；预设 id 才是文件名（`control_group_preset` 引用 `<命名空间>:<文件名>`）。子目录不参与 id 拼装，因此名字里不要靠目录区分同类。

- 条目必须带命名空间前缀，且与所在包一致。`ae86_driver.json` 的 `"name": "base"` 是唯一漏写前缀的条目。
- 不带包名冗余：`controlGroup.t90a.t90a_gunner` 的 `t90a_` 去掉，命名空间已说明车名。
- 不带型号名：`controlGroup.m1a2_sep.loader_m240` 的 `m240` 是型号。
- 用途词取自角色词表（3.3）加职责词：`driver`、`commander`、`gunner`、`loader`、`observer`、`aa`、`base`、`override`、`backup_fire`。

现存量：24 个条目、35 处使用；其中**漏写前缀 1 个**、**包名冗余 7 个**（`m1a2_sep.m1a2_aft_mg`、`t90a.t90a_gunner|t90a_aa|t90a_observer`、`type59.type59_gunner|type59_aa|type59_observer`）、**型号名 1 个**（`loader_m240`）。

### 3.11 机器标签

两类，都写在 `tags` 里：

| 类 | 形状 | 已用维度 |
| --- | --- | --- |
| 维度标签 | `<维度>/<值>` | `type`、`category`、`direction`、`series`、`caliber`、`ammo`、`armor`、`addon_armor` |
| 种类标签 | 单个词 | `hull`、`turret`、`chassis`、`seat`、`wheel`、`door`、`hood`、`trunk`、`rack`、`storage`、`bumper`、`spoiler`、`gt` |

- 维度值用小写下划线，不带空格：`caliber/12_7mm`、`ammo/apfsds`。
- 标签的命名空间决定归属：`machine_max:` 下的标签由 builtin 提供，车包不得为了自己排序另造同名标签。

**两个层次，判据是「跨包查询会不会得到同一个答案」：**

| 层次 | 放哪 | 例子 | 判据 |
| --- | --- | --- | --- |
| 维度标签 | `machine_max:<维度>/<值>` | `type/land`、`category/weapon`、`series/t90a`、`caliber/125mm`、`armor/hull_left` | 任何包都想用它筛选同一类东西 |
| 包私有标签 | `<包名>:<词>` | `m1a2_sep:m153_crows`、`m1a2_sep:m153_crows_terminal` | 只有本包知道它指什么，没有跨包查询需求 |

现存 75 个标签，73 个在 `machine_max:` 下，只有上表那两个 `m1a2_sep:m153_crows*` 是包私有。标签同时是**配对键**：零件的 `tags` 声明它提供什么，命中箱的 `required_tags` 声明它要求什么，改一个标签必须两端一起改，否则命中箱静默失配。

**`armor/` 是唯一既带部位又带槽号的维度**，值形状 `<部位>_<方位>[_<槽号>]`：

| 值 | 谁在用 | 中文 |
| --- | --- | --- |
| `armor/hull_left`、`hull_right` | M1A2 的 ARAT 瓦、T-90A 的 Kontakt-5 瓦，整侧覆盖 | 车体左侧装甲 / 车体右侧装甲 |
| `armor/turret_left`、`turret_right` | 同上，炮塔侧 | 炮塔左侧装甲 / 炮塔右侧装甲 |
| `armor/hull_front` | T-90A 车体正面爆反 | 车体正面装甲 |
| `armor/hull_left_01`…`_04`、`hull_right_01`…`_04` | 2S38 的逐块附加装甲槽 | 车体左侧装甲 01 … |

整侧覆盖不加编号，逐块装配才加，槽号两位补零。平面种类标签 `machine_max:armor` 表示「这是一件附加装甲」。

**标签的译名键是 `<命名空间>.<路径>`，路径里的 `/` 换成 `.`**——`TextUtil.getTagLanguageKey` 就是这么拼的，写成 `machine_max.armor/hull_left` 的键永远查不到。通用标签的译名放在 builtin 的 `machine_max` 语言文件里。

## 五、校验

以下规则可由 `checkContent` 机械判定，接入后作为内容包的准入条件：

| 规则 | 判据 | 现状违规 |
| --- | --- | --- |
| 键构形 | 名字段数恰为 3，且类在封闭集内 | 0（`checkContent` 第 12 条） |
| 方位词词序 | 方位词出现顺序为 垂直 → 侧向 → 纵向 | 10 |
| 方位同义词 | 名字中出现 `aft` / `port` / `rear` / `up` / `down` / `center` 即失败（`rearview_mirror` 除外） | 29 |
| 编号 | 出现编号时必须是 `_` + 两位数字 | 291 |
| 角色词 | 名字首段命中型号词表（`pktm`、`pkt`、`2a42`、`2a90`、`mg34`、`50mm`、`csamm`、`crows`）或口径段（`762`）即失败 | 36 |
| 轴词 | 出现 `yaw` / `pitch` 即失败 | 27 |
| 类型后缀 | 名字末段与 `type` 的对应关系一致（3.4 表），裸名除外 | 83 个安装点 |
| 裸名 | 同一变体内同类型安装块超过一个时，裸名失败 | 待统计 |
| 中文译文 | 每个具名键在 `zh_cn` 与 `en_us` 各有条目；中文值含汉字；两侧键集相同 | 0（`checkContent` 第 12 条，887 个名字键全覆盖） |
| 术语 | 中文值不含 4.1 的「不采用」列（不含 `description.` 散文键） | 14 |
| 控制组 | 文件名与语言键一致，且被至少一处 `control_group_preset` 引用 | 0 |
| 控制组名 | 条目 `name` 带命名空间前缀、不含包名冗余与型号名 | 8 |
| 标签命名空间 | 维度标签（`type` / `category` / `direction` / `series` / `caliber` / `ammo` / `armor` / `addon_armor` / 种类词）在 `machine_max:` 下 | 0 |
| 标签译名键 | 键写作 `<命名空间>.<路径>`，路径里的 `/` 换成 `.`；不得出现 `/` | 0 |

「键构形」与「中文译文」两条已接进 `checkContent`（第 12 项），逐条列出声明了却没有译文的键。判据按**命名空间**算：名字就是完整翻译键，语言表由所有提供 `<命名空间>/lang/<语言>.json` 的包合并成一张（`LangModule.mergeCollectedContents`），客户端只加载这一份。因此 `machine_max` 命名空间的名字写进 builtin 那一份就对每个包可见，写进某个车包则只在那份贡献存在时可见；车包私有命名空间的名字写自己那份。缺一条的后果是界面原样显示这个键——装配 HUD 的连接点提示、载具信息面板与交互提示都直接吃这些键，没有别的回退。

各条之间会命中同一个名字（例如 `aft_mg_yaw_driver` 同时犯方位同义词与轴词两条），违规数不可相加。校验按整表生效，所以实施顺序是：先把本表列出的名字改完，再打开校验。

## 六、迁移

名字是存档键，因此改名按批次做，每批一个提交，批内不留半改状态：

| 批次 | 内容 | 触及键 | 存档破坏 |
| --- | --- | --- | --- |
| 0 | 类型 id `lighting` → `light`；15 个标签收进 `machine_max:`；标签译名归 builtin（已完成） | 类型 30 处 + 标签 27 处 | 是（类型 id 进存档） |
| 1 | 补缺译（已完成：887 个名字键 0 缺译）、改 14 处错译 | 0 | 否 |
| 2 | 轴词 `yaw` / `pitch` → `azimuth` / `elevation`，含子零件与 `*_pitch_lock` | 27 | 是 |
| 3 | 类型后缀对齐：`_autoloader` → `_loader`、`_loader` → `_rack`、`_weapon` → `_controller`、`_sight` → `_optics` | 83 个安装点 | 是 |
| 4 | 型号名与口径名 → 角色词（含 7 个连接点）；`aft_mg_*` / `port_mg_*` 按使用者改名 | 64 | 是 |
| 5 | 方位词序（`back_left`、`*_bumper_left`、`*_light_left`）与 `rear_door` | 11 | 是 |
| 6 | 编号补零、下划线分隔 | 291 | 是 |
| 7 | 交互区去 `_interact` 后缀、去名字里的点；控制组条目名去包名前缀 | 20 | 否 |
| 8 | 连接点接口词与对端顺序 | 待定 | 是 |

每批的做法固定：先跑脚本产出「旧名 → 新名」映射，按映射重写 JSON 键与四处引用，再改语言键，最后跑 `checkContent` 与 `runGameTestServer`。GameTest 里断言了具体名字的用例（`machine_max:2s38_turret` 一类）应按映射同步，或改成断言结构而非字面名字。

批量操作由 [`tools/naming/mm_names.py`](../tools/naming/mm_names.py) 承担：

```bash
python tools/naming/mm_names.py scan                  # 按本文规则列出违规
python tools/naming/mm_names.py scan --rule numbering -v
python tools/naming/mm_names.py rename --map m.json   # 预演
python tools/naming/mm_names.py rename --map m.json --apply
```

映射文件是扁平 JSON（`{"旧完整键": "新完整键"}`）。改名按文本替换执行，保留 JSONC 注释、缩进与原文件的换行风格；替换带右边界断言，`subsystem.x.foo` 不会命中 `subsystem.x.foo_bar`；新键已在同一文件出现时拒绝改写该文件，避免撞名。

批次 6 的量最大但规则最机械，可以一次改完；批次 2–5 建议一车一改，改完一辆车就提交一次，避免长时间停在半改状态。

## 七、开放问题

### 7.1 已定

| 问题 | 结论 |
| --- | --- |
| 灯的类型与名字 | 灯具一律 `light` 型，名字 `<方位>_<用途>_light`；亮不亮由 `definition` 决定 |
| `basic` 要不要命名规则 | 不要。它是「任何可被伤害的子系统」，名字写部件本身 |
| 装饰灯罩叫什么 | 推荐 `<方位>_<部件>_lamp`，与 `_light` 分开，不强制 |
| M1A2 两挺随动炮管的机枪怎么分 | 按用途：`coax`（并列，M240 7.62）与 `antimateriel`（反狙击，CSAMM 12.7）；现存两个名字互换 |
| 车长指挥塔的 M2 归哪类 | 高射机枪 `aa_*`。`commander_mg` 这个角色词不收录 |
| 装填手舱口的 M240 | `loader_mg_*`。只因当前只有 M1A2 一例，角色词照样收录——它描述的是使用者，不是型号 |
| K17 / Sd.Kfz.234 的「副武器」 | 都是同轴机枪 → `coax_*`；主武器是 `main_*` |
| 储物箱的规格 | 写在零件名上，不进子系统名 |
| 口径算不算角色词 | 不算，口径不进名字 |
| 标签归属 | 通用维度标签一律 `machine_max:`（放 builtin），只有包私有标记留在包命名空间；15 个越界标签已收口 |
| 装甲维度 | 只保留 `armor/`，`addon_armor/*` 并入其槽号形式；平面种类标签 `machine_max:armor` 表示附加装甲件 |
| 存档兼容 | 开发期不做旧名映射 |

写完一个名字，按顺序问：

1. 它是三类存档键之一吗？是的话，改名代价算过没有。

5. 首段是角色词，还是型号名？
6. 末段与 `type` 对得上吗？
7. 同一个变体里，这个名字和别的名字撞吗？
8. 中文译文用了正词表里的词吗？键在两份语言文件里都有吗？
