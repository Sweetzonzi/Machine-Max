# 武器系统 — 投射物命中处理重构设计

> 日期: 2026-06-18 · 状态: 计划阶段 · 版本: 2.0（审阅修订）

## 1. 问题陈述

### 1.1 当前架构

投射物的命中检测和解析逻辑分散在两处，且能力严重不对等：

| 能力      | 质点 (PointProjectile)          | 刚体 (RigidProjectile) |
| ------- | ----------------------------- | -------------------- |
| 运动积分    | Manager 半隐式 Euler             | Bullet 物理引擎          |
| 碰撞检测    | Manager.rayTest               | body.isColliding     |
| 地形穿透判定  | 有（方块护甲→穿深→速度衰减）               | **无**                |
| 方块破坏    | 有（动能×blockDamageFactor）       | **无**                |
| 实体/零件命中 | 有（BFDamageApi + 分层分派）         | **无**                |
| 穿透后继续飞行 | 有（AfterHitResult.passThrough） | **无**                |
| 跳弹/碾压   | 有（BFHurt 管线回调）                | **无**                |

**刚体投射物**的命中处理仅有一处残桩（`RigidProjectile.checkBodyCollision()`）：检查 `body.isColliding` 后直接销毁并广播，不区分钟类、不走 BallisticsFramework 管线。

### 1.2 根因

命中**解析**逻辑（地形穿透、实体伤害、方块破坏）被硬编码在 `ProjectileManager.updatePointProjectiles()` 的大循环内，与运动积分和 rayTest 紧耦合。刚体不经过这个循环，自然丢失了一切命中处理。

### 1.3 未来需求

- 刚体投射物需要完整的穿透/伤害管线
- 未来可能有激光射线类投射物（瞬时线段检测）

***

## 2. 设计目标

1. **分离检测与解析**：命中检测因类型而异（rayTest / Bullet 回调 / sweep），但命中解析逻辑对所有类型统一
2. **接口驱动、类型安全**：`IProjectile` 提供类型化命中解析端点（`onTerrainHit` / `onEntityHit` / `onPartHit`），让类型系统承担校验，避免 `Object` + `instanceof` 的脆弱的默认实现
3. **对齐 SubPart/CollisionHandler 模式**：`IProjectile` 相当于 `SubPart`，调用方（Manager 或刚体自身）负责碰撞检测和分派，IProjectile 默认方法负责解析

***

## 3. 方案设计

### 3.1 整体流

```
质点: Manager.rayTest → 识别目标类型 ─→ projectile.onTerrainHit(...)
                                      ├→ projectile.onEntityHit(...)
                                      └→ projectile.onPartHit(...)

刚体: Bullet onCollideProcessed → 碰撞组过滤 ─→ this.onTerrainHit(...)
                                                ├→ this.onEntityHit(...)  (阶段一: 覆写返回 DESTROYED)
                                                └→ this.onPartHit(...)

激光: 瞬时 sweep 检测 → 识别目标类型 ─→ projectile.onTerrainHit(...)  (未来)
                                      └→ ...
```

> **注**：`PhysicsBodyExtension.kt` 的 `onCollideProcessed` 是一个 Kotlin 扩展函数。在 Java 中需以静态方法形式调用：
> `PhysicsBodyExtensionKt.onCollideProcessed(body, handler)`。

### 3.2 IProjectile 新增三个 default 方法

#### 3.2.1 `onTerrainHit()` — 地形命中解析

从 `ProjectileManager.updatePointProjectiles()` 第 852\~908 行提取。

```java
/**
 * 处理地形命中。计算方块等效护甲，判定穿透/停住，可选方块破坏。
 * 由 Manager（质点 rayTest）或碰撞回调（刚体）调用。
 *
 * @param level               维度
 * @param blockPos            命中方块坐标
 * @param blockState          方块状态（调用方预先获取，可通过
 *                            PhysicsChunkSection.getBlockSnapshot(blockPos) → SectionSnapshot
 *                            获得，或直接从 level.getBlockState(blockPos) 获取）
 * @param currentPenetration  当前速度下的穿深（mm RHA）
 * @param currentSpeed        当前速度（m/s）
 * @param hitPoint            命中点世界坐标（MC Vec3）
 * @param hitNormal           命中面法线（指向投射物）
 * @return AfterHitResult — passThrough(速率保留率) / DESTROYED
 */
default AfterHitResult onTerrainHit(
    Level level, BlockPos blockPos, BlockState blockState,
    float currentPenetration, float currentSpeed,
    Vec3 hitPoint, Vec3 hitNormal
)
```

内部逻辑：

1. 调用 `ArmorUtil.getBlockArmor(level, blockState, ...)` 获取方块等效护甲（mm RHA）
2. 若 `currentPenetration > blockArmor` → 穿透：
   - 计算穿透后速度：`speedAfterPenetration(currentSpeed, currentPenetration, blockArmor, coeff)`
   - 若服务器配置 `MMServerConfig.projectileDestroyBlocks()` 允许，且 `blockDamageFactor > 0`、`damage × blockDamageFactor > 方块耐久`：
     ```java
     // destroyBlock 必须在主线程执行，用去重任务包装
     SparkLevel.submitDeduplicatedTask(level, blockPos.toShortString(), PPhase.PRE,
         () -> level.destroyBlock(blockPos, false));
     ```
     注：方块破坏判定使用当前伤害值×因子，而非动能公式。投射物有明确的伤害属性，与 SubPart（无伤害属性，靠碰撞能量）不同。
   - 返回 `AfterHitResult.passThrough(velocityRetention, ...)`
3. 否则 → 无法穿透：
   - 返回 `AfterHitResult.DESTROYED`（广播由调用方负责：Manager 侧用 `broadcastTerrainHit`，刚体侧用 `applyHitResultAfterCollision`）

**穿透去重**：`onTerrainHit()` 不维护穿透密钥（`penetratedKeys`）。**调用方应在调用** **`onTerrainHit()`** **之前**检查穿透密钥（通过 `ObjectManager.getOrCreateProjectileManager(level).hasPenetrated(...)`），若已穿透则跳过。穿透后由调用方写入密钥。详见 §3.3。

#### 3.2.2 `onEntityHit()` — 实体命中解析

对应 Manager 中 Entity 异步路径（第 998\~1046 行）。

```java
/**
 * 处理实体命中。委托 BFDamageApi 管线，异步完成后由 BFDamageHandler 回调写入结果。
 * 调用方应在下一帧通过 consumePendingHitResult() 消费。
 *
 * @param level              维度
 * @param entity             命中实体（LivingEntity / Boat / Minecart 等）
 * @param currentPenetration 当前穿深（mm RHA）
 * @param currentDamage      当前伤害
 * @param hitPoint           命中点世界坐标
 * @param hitNormal          命中面法线
 * @return null — 异步管线，结果由回调链写入 pendingHitResult
 */
@Nullable
default AfterHitResult onEntityHit(
    Level level, Entity entity,
    float currentPenetration, float currentDamage,
    Vec3 hitPoint, Vec3 hitNormal
)
```

内部逻辑：

1. 决议目标：`BFDamageApi.resolveHitTarget(entity, ...)`
2. 构造 `BFDamageContext`，注入 `this` 作为 handler
3. 设置 `hitPending = true`（暂停物理积分）
4. 通过 `SparkLevel.submitDeduplicatedTask` 提交主线程：`BFDamageApi.hurt(entity, ctx)`
5. 返回 `null`（结果由 BFDamageHandler 回调 → `setPendingHitResult` → 下一帧物理线程开头 `consumePendingHitResult` 消费）

**阶段一限制**：刚体投射物命中实体时，暂不走异步管线。`RigidProjectile` 覆写此方法为：

```java
@Override
public AfterHitResult onEntityHit(Level level, Entity entity, ...) {
    broadcastHitSync(...); // 广播命中效果到客户端
    return AfterHitResult.DESTROYED;
}
```

待整体异步命中框架就绪后移除覆写，统一使用默认实现。

#### 3.2.3 `onPartHit()` — 零件/非Entity BFHurtTarget 命中解析

对应 Manager 中 SubPart / BFHurtTarget（非 Entity）同步路径（第 967\~984 行）。

```java
/**
 * 处理零件或 BFHurtTarget（非 Entity）命中。同步执行 BFDamageApi 管线。
 *
 * @param level              维度
 * @param target             命中目标（SubPart 或其他 BFHurtTarget）
 * @param currentPenetration 当前穿深（mm RHA）
 * @param currentDamage      当前伤害
 * @param hitPoint           命中点世界坐标
 * @param hitNormal          命中面法线
 * @return AfterHitResult — passThrough / DESTROYED / ricochet
 */
default AfterHitResult onPartHit(
    Level level, BFHurtTarget target,
    float currentPenetration, float currentDamage,
    Vec3 hitPoint, Vec3 hitNormal
)
```

内部逻辑：

1. 构造 `BFDamageContext`，注入 `this` 作为 handler
2. 调用 `this.dealDamage(target, hitPoint, hitNormal)` 走完整 BallisticsFramework 穿甲管线
3. 返回 `consumePendingHitResult()`

调用方负责在调用前过滤掉 `MMPartEntity` 和 `MMProjectileEntity`（它们仅是渲染代理，不应触发命中）。

### 3.3 穿透去重机制

`ProjectileManager` 通过 `ObjectManager` 按 Level 注册，任意调用方均可获取：

```java
ProjectileManager pm = ObjectManager.getOrCreateProjectileManager(level);
```

**调用方协议**（对 Manager 和 RigidProjectile 统一）：

```java
// Manager 侧（质点）— pm 就是 this
if (!pm.hasPenetrated(projectileId, blockPos)) {
    AfterHitResult r = projectile.onTerrainHit(...);
    if (r instanceof AfterHitResult.PassThrough) {
        pm.markPenetrated(projectileId, blockPos);
    }
}

// RigidProjectile 侧（刚体）
ProjectileManager pm = ObjectManager.getOrCreateProjectileManager(level);
if (!pm.hasPenetrated(getId(), blockPos)) {
    AfterHitResult r = this.onTerrainHit(...);
    if (r instanceof AfterHitResult.PassThrough) {
        pm.markPenetrated(getId(), blockPos);
    }
}
```

**检查必须在调用** **`onTerrainHit()`** **之前**，这与当前 Manager 第 840\~850 行的顺序一致——穿透密钥检查发生在进入地形分支之前。

### 4.2 ProjectileManager.java — 内联替换

`updatePointProjectiles()` 中：

- **地形分支**（约 60 行）→ 替换为 `projectile.onTerrainHit(...)` + 穿透密钥管理（§3.3 协议）
- **实体/零件分支**（`handleSubPartHit` / `handleEntityHit` 等）→ 替换为：
  - `MMPartEntity` / `MMProjectileEntity` → 跳过（调用方过滤）
  - `SubPart` → `projectile.onPartHit(level, (BFHurtTarget) subPart, ...)`
  - 其他 `BFHurtTarget`（非 Entity） → `projectile.onPartHit(level, target, ...)`
  - `Entity` → `projectile.onEntityHit(level, entity, ...)`
- 部分辅助方法**保留**在 Manager，因其涉及 SoA 数组操作和网络包发送：
  - `applyHitResult()` — 将 AfterHitResult 写回 SoA 数组（posX/Y/Z, velX/Y/Z, alive, lifetime）
  - `broadcastTerrainHit()` — 发送 ProjectileHitSyncPayload
  - `broadcastEntityHit()` — 同上

**S4 子任务：审计广播路径**。提取后需确认：
1. `broadcastTerrainHit` 对每个穿透失败只调用一次（不被 `onTerrainHit` 和 Manager 双重触发）
2. `broadcastHitSync`（穿透后广播）在以下三条路径中调用时机一致：
   - `handleSubPartHit` → `applyHitResult` → 广播
   - `handleSyncBfHit` → `applyHitResult` → 广播  
   - `handleEntityHit` → 异步，广播延迟到主线程
3. 提取后 `onTerrainHit` 自身不广播，由调用方统一负责

### 4.3 RigidProjectile.java — 事件驱动命中

**碰撞回调注册**（`addToLevel()` 末尾新增）：

```java
PhysicsBodyExtensionKt.onCollideProcessed(body, event -> {
    handleBulletCollision(
        event.getO1(), event.getO2(),
        event.getO1Point(), event.getO2Point()
    );
    return null; // Unit
});
```

**`handleBulletCollision()`** **方法**：

```java
private void handleBulletCollision(
    PhysicsCollisionObject o1, PhysicsCollisionObject o2,
    ManifoldPoint point1, ManifoldPoint point2
) {
    if (hasHit || isDestroyed()) return;

    PhysicsRigidBody other = (PhysicsRigidBody) o2;
    int group = other.getCollisionGroup();

    // ① 碰撞组过滤：仅处理 TERRAIN / PHYSICS_BODY / PAWN
    if (group != CollisionGroups.TERRAIN
        && group != CollisionGroups.PHYSICS_BODY
        && group != CollisionGroups.PAWN) {
        return;
    }

    // ② 获取接触点与法线
    Vector3f hitPointJme = new Vector3f();
    Vector3f hitNormalJme = new Vector3f();
    point1.getPositionWorld(hitPointJme);
    point2.getNormalWorld(hitNormalJme);  // 法线指向 o1（投射物）
    Vec3 hitPointMc = new Vec3(hitPointJme.x, hitPointJme.y, hitPointJme.z);
    Vec3 hitNormalMc = new Vec3(hitNormalJme.x, hitNormalJme.y, hitNormalJme.z);

    float currentPen = calculateCurrentPenetration();
    float currentDamage = calculateCurrentDamage();
    float currentSpeed = getSpeed();
    Object otherOwner = PhysicsBodyExtensionKt.getOwner(other);

    AfterHitResult result = null;

    // ③ 按碰撞组分派
    if (group == CollisionGroups.TERRAIN) {
        // 地形：通过 SectionSnapshot 安全获取方块信息（物理线程可访问）
        if (otherOwner instanceof PhysicsChunkSection terrain) {
            BlockPos blockPos = terrain.getBlockPosFromContactPoint(
                hitPointJme, hitNormalJme, -0.01f);
            SectionSnapshot.BlockSnapshot blockSnap = terrain.getBlockSnapshot(blockPos);
            if (blockSnap == null || terrain.isRemoved(blockPos)) return;
            BlockState blockState = blockSnap.getState();
            result = onTerrainHit(level, blockPos, blockState,
                currentPen, currentSpeed, hitPointMc, hitNormalMc);
        }
    } else if (group == CollisionGroups.PHYSICS_BODY) {
        // 零件：过滤渲染代理后分派
        if (otherOwner instanceof BFHurtTarget target
            && !(otherOwner instanceof MMPartEntity)
            && !(otherOwner instanceof MMProjectileEntity)) {
            result = onPartHit(level, target,
                currentPen, currentDamage, hitPointMc, hitNormalMc);
        }
    } else if (group == CollisionGroups.PAWN) {
        // 实体：阶段一覆写直接返回 DESTROYED（见 §3.2.2）
        // 注：碰撞组过滤已排除投射物自身的碰撞（投射物在 PHYSICS_BODY 组，自碰撞由 Bullet 碰撞掩码处理）
        if (otherOwner instanceof Entity entity) {
            result = onEntityHit(level, entity,
                currentPen, currentDamage, hitPointMc, hitNormalMc);
        }
    }

    // ④ 应用结果
    if (result != null) {
        applyHitResultAfterCollision(result, hitPointMc, hitNormalMc);
    }
}

/**
 * 刚体侧命中结果应用。
 * 将 AfterHitResult 转换为刚体状态变更：速度回写、hasHit、销毁、网络广播。
 */
private void applyHitResultAfterCollision(AfterHitResult result,
    Vec3 hitPointMc, Vec3 hitNormalMc) {
    if (result instanceof AfterHitResult.PassThrough pass) {
        // 穿透后减速：回写 Bullet 刚体和 SoA
        Vector3f newVel = getVelocity().mult(pass.velocityRetention());
        setLinearVelocity(newVel);
        body.setLinearVelocity(newVel);
        // 广播穿透同步（非销毁，携带新速度）
        if (level instanceof ServerLevel serverLevel) {
            ProjectileHitSyncPayload.broadcast(serverLevel, getId(),
                hitPointMc, hitNormalMc, false, newVel, false);
        }
    } else if (result == AfterHitResult.DESTROYED) {
        // 无法穿透/被阻挡：广播命中后销毁
        if (level instanceof ServerLevel serverLevel) {
            ProjectileHitSyncPayload.broadcast(serverLevel, getId(),
                hitPointMc, hitNormalMc, true, new Vector3f(), false);
        }
        markHit();
        destroy();
    }
    // ricochet 等其他结果同理
}
```

**`RigidProjectile`** **覆写** **`onEntityHit`**：

```java
@Override
public AfterHitResult onEntityHit(Level level, Entity entity,
    float currentPen, float currentDamage, Vec3 hitPoint, Vec3 hitNormal) {
    // 阶段一简化：命中即销毁，不等待异步管线
    // 广播命中同步到客户端（复用 ProjectileHitSyncPayload）
    if (level instanceof ServerLevel serverLevel) {
        ProjectileHitSyncPayload.broadcast(serverLevel, getId(),
            hitPoint, hitNormal, true, new Vector3f(), false);
    }
    return AfterHitResult.DESTROYED;
}
```

**删除**：`checkBodyCollision()`（原 15 行）、`postTick()` 中对其的调用行（仅删该行，刚体位姿同步逻辑保留）。

> **线程安全**：`handleBulletCollision` 在物理线程回调中执行，会设置 `hasHit`。需将 `RigidProjectile.hasHit` 声明为 `volatile`，确保对主线程 `postTick` 可见。一旦 `checkBodyCollision` 被新回调完全取代，该字段仅有物理线程写入、主线程只读，`volatile` 即可满足。
