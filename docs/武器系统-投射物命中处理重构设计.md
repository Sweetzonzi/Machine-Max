# 武器系统 — 投射物命中处理重构设计

> 日期: 2026-06-18 · 状态: 计划阶段 · 版本: 1.0

## 1. 问题陈述

### 1.1 当前架构

投射物的命中检测和解析逻辑分散在两处，且能力严重不对等：

| 能力 | 质点 (PointProjectile) | 刚体 (RigidProjectile) |
|------|------------------------|-------------------------|
| 运动积分 | Manager 半隐式 Euler | Bullet 物理引擎 |
| 碰撞检测 | Manager.rayTest | body.isColliding |
| 地形穿透判定 | 有（方块护甲→穿深→速度衰减） | **无** |
| 方块破坏 | 有（动能×blockDamageFactor） | **无** |
| 实体/零件命中 | 有（BFDamageApi + 分层分派） | **无** |
| 穿透后继续飞行 | 有（AfterHitResult.passThrough） | **无** |
| 跳弹/碾压 | 有（BFHurt 管线回调） | **无** |

**刚体投射物**的命中处理仅有一处残桩（`RigidProjectile.checkBodyCollision()`）：检查 `body.isColliding` 后直接销毁并广播，不区分钟类、不走 BallisticsFramework 管线。

### 1.2 根因

命中**解析**逻辑（地形穿透、实体伤害、方块破坏）被硬编码在 `ProjectileManager.updatePointProjectiles()` 的大循环内，与运动积分和 rayTest 紧耦合。刚体不经过这个循环，自然丢失了一切命中处理。

### 1.3 未来需求

- 刚体投射物需要完整的穿透/伤害管线
- 未来可能有激光射线类投射物（瞬时线段检测）
- 霰弹多弹丸批量命中

---

## 2. 设计目标

1. **分离检测与解析**：命中检测因类型而异（rayTest / Bullet 回调 / sweep），但命中解析逻辑对所有类型统一
2. **接口驱动**：`IProjectile` 提供命中解析的默认实现，调用方（Manager 或刚体自身）负责检测
3. **对齐 SubPart/CollisionHandler 模式**：`IProjectile` 相当于 `SubPart`，提供 `onTerrainHit()` / `onTargetHit()` 两个分派端点，调用方自行获取碰撞数据后分派

---

## 3. 方案设计

### 3.1 整体流

```
质点: Manager.rayTest → 识别目标类型 ─→ projectile.onTerrainHit(...)
                                      └→ projectile.onTargetHit(...)

刚体: Bullet onCollideProcessed → 识别碰撞组 ─→ this.onTerrainHit(...)
                                                └→ this.onTargetHit(...)

激光: 瞬时 sweep 检测 → 识别目标类型 ─→ projectile.onTerrainHit(...)  (未来)
                                      └→ projectile.onTargetHit(...)
```

### 3.2 IProjectile 新增 default 方法

#### `onTerrainHit()` — 地形命中解析

从 `ProjectileManager.updatePointProjectiles()` 第 852~908 行提取。

```java
/**
 * 处理地形命中。计算方块等效护甲，判定穿透/停住，可选方块破坏。
 * 由 Manager（质点 rayTest）或碰撞回调（刚体）调用。
 *
 * @param level               维度（用于查询方块状态和护甲）
 * @param blockPos            命中方块坐标
 * @param blockState          方块状态（调用方预先获取以避免重复查询）
 * @param currentPenetration  当前速度下的穿深（mm RHA）
 * @param currentSpeed        当前速度（m/s）
 * @param hitPoint            命中点世界坐标（MC Vec3）
 * @param hitNormal           命中面法线（指向投射物）
 * @return AfterHitResult — passThrough(速率保留率) / DESTROYED
 */
default AfterHitResult onTerrainHit(
    Level level, BlockPos blockPos, BlockState blockState,
    float currentPenetration, float currentSpeed,
    Vec3 hitPoint, Vec3 hitNormal
)
```

内部逻辑：

1. 调用 `ArmorUtil.getBlockArmor(level, blockState, ...)` 获取方块等效护甲（mm RHA）
2. 若 `currentPenetration > blockArmor` → 穿透：
   - 计算穿透后速度：`speedAfterPenetration(currentSpeed, currentPenetration, blockArmor, coeff)`
   - 若 `blockDamageFactor > 0` 且动能 × 因子 > 方块耐久 → `level.destroyBlock(blockPos, false)`
   - 返回 `AfterHitResult.passThrough(velocityRetention, ...)`
3. 否则 → 无法穿透：
   - 广播命中效果
   - 返回 `AfterHitResult.DESTROYED`

**穿透去重**：`onTerrainHit()` 不维护穿透密钥（`penetratedKeys`），由调用方管理。调用方在调用前通过 `ObjectManager.getOrCreateProjectileManager(level)` 获取 Manager 并查询 `penetratedKeys`，若已穿透则跳过。`onTerrainHit` 仅返回结果，调用方负责写入密钥。

#### `onTargetHit()` — 实体/零件命中解析

从 `ProjectileManager.updatePointProjectiles()` 第 910~1046 行提取。

```java
/**
 * 处理实体或零件命中。委托 BFDamageApi 管线分派。
 * 同步目标（SubPart / 非 Entity 的 BFHurtTarget）直接返回结果；
 * 异步目标（Entity）标记 hitPending 后由主线程消费，返回 null。
 *
 * @param level              维度
 * @param target             命中目标（Entity / SubPart / BFHurtTarget）
 * @param currentPenetration 当前穿深（mm RHA）
 * @param currentDamage      当前伤害
 * @param hitPoint           命中点世界坐标
 * @param hitNormal          命中面法线
 * @return AfterHitResult，异步时返回 null（由回调链后续写入 pendingHitResult）
 */
@Nullable
default AfterHitResult onTargetHit(
    Level level, Object target,
    float currentPenetration, float currentDamage,
    Vec3 hitPoint, Vec3 hitNormal
)
```

内部逻辑：

1. 判断目标类型：
   - `MMPartEntity` / `MMProjectileEntity` → 跳过（返回 null）
2. 决议目标：`BFDamageApi.resolveHitTarget(target, ...)`
3. 若决议到 SubPart / 非 Entity 的 BFHurtTarget → **同步路径**：
   - `this.dealDamage(resolvedTarget, hitPoint, hitNormal)`
   - 返回 `consumePendingHitResult()`
4. 若决议到 Entity → **异步路径**：
   - 设置 `hitPending = true`（暂停物理积分）
   - 通过 `SparkLevel.submitDeduplicatedTask` 提交主线程
   - 返回 null（结果由 BFDamageHandler 回调写入，下一帧消费）

**阶段一限制**：刚体投射物命中实体时，暂时保持命中即销毁的简化行为（不进入异步等待）。待整体异步命中框架就绪后再统一。

### 3.3 调用方如何访问 Manager 穿透密钥

`ProjectileManager` 通过 `ObjectManager` 按 Level 注册：

```java
ProjectileManager pm = ObjectManager.getOrCreateProjectileManager(level);
```

`onTerrainHit()` 不直接持有 Manager 引用，但调用方（无论是 Manager 自身还是 RigidProjectile）都可以通过 `ObjectManager` 获取 Manager，在调用 `onTerrainHit()` 前后管理穿透密钥：

```java
// Manager 侧（质点）
ProjectileManager pm = this;  // 自身
if (!pm.hasPenetrated(projectileId, blockPos)) {
    AfterHitResult r = projectile.onTerrainHit(...);
    if (r instanceof AfterHitResult.PassThrough) {
        pm.markPenetrated(projectileId, blockPos);
    }
}

// RigidProjectile 侧（刚体）
ProjectileManager pm = ObjectManager.getOrCreateProjectileManager(level);
if (!pm.hasPenetrated(getId(), blockPos)) {
    AfterHitResult r = this.onTerrainHit(...);
    if (r instanceof AfterHitResult.PassThrough) {
        pm.markPenetrated(getId(), blockPos);
    }
}
```

## 4. 各文件改动

### 4.1 IProjectile.java — 新增 default 方法

| 方法 | 来源 | 行数估计 |
|------|------|----------|
| `onTerrainHit()` | 从 Manager 第 852~908 行提取 | ~60 行 |
| `onTargetHit()` | 从 Manager 第 910~1046 行提取 + 简化 | ~70 行 |

新增 import：`BlockPos`, `BlockState`, `ArmorUtil`, `BFDamageApi`, `SparkLevel`, `ObjectManager`

### 4.2 ProjectileManager.java — 内联替换

`updatePointProjectiles()` 中：

- 地形分支（约 60 行）→ 替换为 `projectile.onTerrainHit(...)` + 穿透密钥管理
- 实体/零件分支（`handleSubPartHit` / `handleEntityHit` 等）→ 替换为 `projectile.onTargetHit(...)`

部分辅助方法（如 `applyHitResult`、`broadcastTerrainHit`）保留，因涉及 SoA 数组操作和网络包发送，不适合放入接口。

### 4.3 RigidProjectile.java — 事件驱动命中

- `addToLevel()` 新增 `body.onCollideProcessed(event -> handleBulletCollision(...))`
- 新增 `handleBulletCollision()` 方法：按碰撞组分派到 `onTerrainHit()` / `onTargetHit()`
- 删除 `checkBodyCollision()`（原 15 行残桩）
- `postTick()` 中移除对 `checkBodyCollision()` 的调用

```java
// addToLevel() 末尾新增
body.onCollideProcessed(event -> {
    handleBulletCollision(
        event.getO1(), event.getO2(),
        event.getO1Point(), event.getO2Point()
    );
    return null;
});
```
