# Machine-Max 地面载具控制 — 油门/刹车双模式设计文档

> 状态：第一阶段（油门/刹车分离）已实现，平滑改造待开工
> 创建时间：2026-05-18
> 影响范围：客户端输入 → 网络协议 → 服务端控制分发 → 发动机/电动机/车轮

## 一、问题背景与设计目标

### 1.1 用户诉求

当前地面载具的 W/S 键使用**移动方向意图**模式：W 表示"我想向前移动"，S 表示"我想向后移动"。载具根据当前速度方向自动判断应踩油门还是刹车——倒车中按 W 会先刹车再反向加速。

有用户提出需要**原始映射**模式：W 固定是油门、S 固定是刹车，与车辆当前运动方向无关。这与现实汽车的踏板逻辑一致。

### 1.2 设计目标

1. 两种模式通过客户端配置切换，默认为意图模式
2. 利用 `MovementInputPayload` 中现有但未被使用的 `inputConflict` 通道传递刹车信号，**协议零改动**
3. 分离模式下油门与刹车完全解耦，各自独立生效（可同时满油满刹满足烧胎等需求）
4. 自动换档逻辑在分离模式下正确工作
5. 转向行为不受影响
6. 分离模式下倒车由玩家手动操作变速箱负挡完成，不在本设计中处理

## 二、现状分析

### 2.1 数据流全景

```

  │  计算 trans_z_input (前进/后退, -100~100)
  │  计算 trans_z_conflict (冲突标志, 仅当前进后退同时按下时=1)
  │
  ├──→ MovementInputPayload(input[6], inputConflict[6])  ──网络──→
  │
  └──→ 服务端 MovementInputPayload.handler()
        │
        └──→ AbstractControllableSubsystem.setMoveInputSignal(input, conflict)
              │
              └──→ MoveInputSignal(input, conflict)  ──信号频道──→
                    │
                    └──→ CarControllerSubsystem.updateMoveInputs()
                          this.moveInput = input
                          this.moveInputConflict = conflict
                          │
                          └──→ distributeControlSignals()
```

### 2.2 当前油门/刹车耦合机制

核心判读在 [CarControllerSubsystem.distributeControlSignals()](file:///d:/Files/Project_MinecraftMods/Machine-Max/src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/CarControllerSubsystem.java#L363-L475)：

```java
if (moveInput[2] != 0) {
    if (moveInput[2] * speed > 0 || Math.abs(speed) < 1) {
        // 输入方向与速度方向一致 → 踩油门
        actualThrottle = 平滑逼近(moveInput[2])
        actualBrake = 0
    } else if (moveInput[2] * speed < 0) {
        // 输入方向与速度方向相反 → 踩刹车
        actualThrottle = 0
        actualBrake = 1
    }
}
```

**油门和刹车互斥** — 由 `moveInput[2]` 的正负与 `speed` 的正负共同决定当前处于哪个分支。二者永远不同时生效。

### 2.3 `moveInputConflict` 通道使用情况

经过全量搜索确认：**`moveInputConflict` 数组中没有任何一个元素被实际读取用于控制决策。** 它是一个完整的死数据通道。

| 索引 | 客户端含义 | 服务端读取？ | 当前唯一"使用" |
|------|----------|------------|--------------|
| `[0]` trans_x_conflict | 左右平移冲突 | ❌ | — |
| `[1]` trans_y_conflict | 上下平移冲突 | ❌ | — |
| `[2]` trans_z_conflict | **前进/后退冲突** | ❌ | — |
| `[3]` rot_x_conflict | 滚转冲突 | ❌ | — |
| `[4]` rot_y_conflict | 转向冲突 | ❌ | — |
| `[5]` rot_z_conflict | 俯仰冲突 | ❌ | — |

唯一的"使用"是在 [distributeControlSignals() 第364行](file:///d:/Files/Project_MinecraftMods/Machine-Max/src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/CarControllerSubsystem.java#L364) 作为入口条件：

```java

```

仅判断引用非 null，不读取数组元素值。

### 2.4 下游子系统对输入信号的依赖

| 子系统 | 如何获取控制信号 | 当前依赖的输入字段 |
|--------|----------------|-------------------|
| `EngineSubsystem` | `updateThrottleInput()` 读取信号频道的 `Float` 或 `MoveInputSignal` | `moveInput[2]` → 取绝对值 |
| `MotorSubsystem` | 同上 | `moveInput[2]` → 保留正负 (`throttleInput`: -1~1) |
| `WheelDriverSubsystem` | `getControlInput()` 读取 `WheelControlSignal` | `brake` = `moveInput[2]/100` (fallback路径) |
| `GearboxSubsystem` | `switchGear()` 由 `CarControllerSubsystem` 调用 | 不直接读输入 |
| `CarControllerSubsystem.autoGearShift()` | `direction` 参数来自 `moveInput[2]` | 用于方向过滤、低速起步档位选择 |

**关键发现**：[WheelDriverSubsystem.getControlInput()](file:///d:/Files/Project_MinecraftMods/Machine-Max/src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/WheelDriverSubsystem.java#L183-L188) 有一个不走 `CarController` 的 fallback 路径，直接使用 `moveInput[2]` 作为刹车信号。分离模式下此处必须改读 `moveInputConflict[2]`。

### 2.5 电动车倒车机制

[MotorSubsystem](file:///d:/Files/Project_MinecraftMods/Machine-Max/src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/MotorSubsystem.java#L302-L315) 的 `throttleInput` 范围是 **-1~1**，负值即可驱动电机反转。`autoGearShift()` 中对纯电动车 (`engineCount==0 && motorCount>0`) 已跳过正/负档的方向过滤（[第539行](file:///d:/Files/Project_MinecraftMods/Machine-Max/src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/CarControllerSubsystem.java#L539)）。

## 三、设计方案

### 3.1 信号布局

复用 `MovementInputPayload` 现有的双 `byte[6]` 结构：

```
                 ┌─────────────────────────────────────────────────────┐
                 │           MovementInputPayload (协议不改)             │
                 │                                                     │
                 │  byte[] input[6]           byte[] inputConflict[6]   │
                 │  ─────────────             ──────────────────────    │
                 │  [0] trans_x                [0] 保留                 │
                 │  [1] trans_y                [1] 保留                 │
                 │  [2] trans_z  ←─油门/意图──→ [2] trans_z_conflict ★  │
                 │  [3] rot_x                  [3] 保留                 │
                 │  [4] rot_y (转向)           [4] 保留                 │
                 │  [5] rot_z                  [5] 保留                 │
                 └─────────────────────────────────────────────────────┘
```

#### 简单模式（意图，默认）

意图模式也使用双通道，W 和 S 同时驱动两个通道：

| 按键 | `input[2]` | `inputConflict[2]` | 语义 |
|------|-----------|-------------------|------|
| W | `+step` → `+100` (前进) | `-step` → `0` (松刹) | 前进意图 |
| S | `-step` → `-100` (后退) | `+step` → `+100` (刹车) | 后退意图 |
| 松键 | 各自回零 (power_off/brake_off) | 刹车回零 (brake_off) | 滑行 |
| W+S 同时 | 归零 | `+step` → `+100` (刹车) | 冲突=刹车 |

两个通道各自独立平滑：
- `input[2]` 用 `full_power_time`(建立)/`power_off_time`(归零) 平滑 — 慢
- `conflict[2]` 用 `full_brake_time`(建立)/`brake_off_time`(归零) 平滑 — 快

服务端行为：同时读取 `input[2]`（方向意图）和 `conflict[2]`（刹车道），比较输入方向与车速方向：
- **方向一致**（或静止）→ 加速：`throttle = abs(input[2])`，`brake = 0`
- **方向相反**（意图反转方向）→ 刹车：`throttle = 0`，`brake = conflict[2]`

这消除了"松开 S 后 trans_z 还负着、刹车迟迟不放"的根本问题——`conflict[2]` 独立用 `brake_off_time`(默认 0.2s) 平滑，松 S 后 ~0.35s 内刹车完全释放。

#### 分离模式（原始映射）

| 按键 | `input[2]` | `inputConflict[2]` | 语义 |
|------|-----------|-------------------|------|
| W | `+step` → `+100` | `0` | **油门 0→100** |
| S | `0` | `+step` → `+100` | **刹车 0→100** |
| 松 W | 回 0 | — | 收油 |
| 松 S | — | 回 0 | 松刹车 |
| W+S 同时 | `+step` → `+100` | `+step` → `+100` | 同时满油满刹，支持烧胎等操作 |

服务端行为：
- `input[2]` → `actualThrottle`（0~1），传给引擎/电动机
- `inputConflict[2]` → `actualBrake`（0~1），传给车轮
- **两者完全独立、各自平滑、可同时满值生效**

### 3.2 模式枚举与配置

**两个入口，同一份数据：**

- **客户端** `MMClientConfig.shouldRawThrottleBrake()` — `RawInputHandler` 直接读本地 NeoForge 配置，决定按键映射方式
- **服务端** `ControlPreference.shouldRawThrottleBrake(ctrl)` — 从玩家 Attachment 读取，决定如何解释收到的 `input[2]`/`conflict[2]`

**同步流程：**

```
MMClientConfig (NeoForge 客户端配置文件)
  │  用户在设置界面修改 ground_throttle_brake_mode
  │
  ├─→ 1. MMClientConfig.shouldRawThrottleBrake()
  │       └→ 客户端 RawInputHandler 直接读取，决定 WS→input[] 的填充方式
  │
  ├─→ 2. ControlPreferenceAttachment(..., groundThrottleBrakeMode, ...)
  │       └→ 构造时读取 MMClientConfig 各配置项的值
  │
  ├─→ 3. ControlPreferencePayload(preferences)
  │       └→ 委托 ControlPreferenceAttachment.STREAM_CODEC 编码，发出网络包
  │
  └─→ 4. 服务端接收 → player.setData(CONTROL_PREFERENCE, preferences)
          │
          └→ 5. CarControllerSubsystem.distributeControlSignals()
                 └→ ControlPreference.shouldRawThrottleBrake(this)
                       └→ ctrl.getController().getData(CONTROL_PREFERENCE)
                             → 与服务端收到的 payload 一致
```

触发时机：`MMClientConfig.onPlayerLogin()` 登录时发送，`onChangeConfig()` 修改配置时重发。

public static boolean shouldRawThrottleBrake(CarControllerSubsystem ctrl) {
    if (ctrl.getController() == null)
        return false; // 无驾驶员时默认意图模式（安全回退）
    var data = ctrl.getController().getData(MMAttachments.getCONTROL_PREFERENCE());
    return switch (data.groundThrottleBrakeMode) {
        case ALWAYS_ENABLED -> true;   // 分离模式
        case ALWAYS_DISABLED -> false; // 意图模式
        default -> false;              // FOLLOW_VEHICLE → 意图模式（默认）
    };
}

### 3.3 客户端 `RawInputHandler` 改动

在 `GROUND` 分支根据配置分两路。**简单模式的现有代码完全不动**，新增分离模式分支：

```java
case GROUND -> {
    // ... 转向逻辑不变 ...

    if (MMClientConfig.shouldRawThrottleBrake()) {
        // === 分离模式：W=油门通道, S=刹车通道 ===
        if (forward) {
            if (trans_z_input < 0) trans_z_input = 0;
            trans_z_input += step;
        }
        if (backWard) {
            if (trans_z_conflict < 0) trans_z_conflict = 0;
            trans_z_conflict += step;
        }
        // 松键回零
        if (!forward) trans_z_input = Math.max(0, trans_z_input - step);
        if (!backWard) trans_z_conflict = Math.max(0, trans_z_conflict - step);

        // 手柄：RT→油门轴, LT→刹车轴（各自独立，不合并）
        if (手柄RT或LT有输入) {
            trans_z_input    = RT_to_0_100;    // 写入 input[2]
            trans_z_conflict = LT_to_0_100;    // 写入 inputConflict[2]
        }

    } else {
        // === 简单模式：现有意图逻辑（完全不动） ===
        // ... 现有 forward/backWard 处理逻辑 ...
        // 手柄：RT-LT 合并写入 trans_z_input（现有行为不动）
    }
}
```

**注意**：分离模式下 `trans_z_input` 和 `trans_z_conflict` 均为 0~100（非负）。`trans_z_conflict` 语义从"冲突标志"变为"刹车量"。

### 3.4 服务端 `CarControllerSubsystem.distributeControlSignals()` 改动

```java
protected void distributeControlSignals() {
    if (this.moveInput != null && moveInputConflict != null) {
        byte[] moveInput = this.moveInput;
        byte[] moveInputConflict = this.moveInputConflict;

        if (ControlPreference.shouldRawThrottleBrake(this)) {
            // ============================================================
            // 分离模式：input[2]=油门(0~100), inputConflict[2]=刹车(0~100)
            // ============================================================
            float targetThrottle = moveInput[2] / 100f;          // 0~1
            float targetBrake = moveInputConflict[2] / 100f;     // 0~1

            actualThrottle = actualThrottle * 0.9f + targetThrottle * 0.1f;
            actualBrake = actualBrake * 0.9f + targetBrake * 0.1f;

            // 自动手刹逻辑
            if (targetThrottle < 0.01f && targetBrake < 0.01f) {
                // 无踏板输入 → 低速自动拉手刹
                if (Math.abs(speed) < 1f && ControlPreference.shouldAutoHandBrake(this)) {
                    handBrake = true;
                }
            } else if (targetThrottle > 0.05f) {
                // 踩油门 → 松手刹
                if (ControlPreference.shouldAutoHandBrake(this) && handBrake)
                    handBrake = false;
            }

            // 计算引擎转速并分发油门信号
            float avgEngineSpeed = calculateAvgSpeedAndControl();

            // 自动换挡方向推断：
            // 玩家可能手动挂了R挡踩油门倒车，此时 direction 应为负，否则 autoGearShift
            // 的方向过滤器会把负挡排除掉，覆盖手动选择。通过检查当前档位推断正确方向。
            byte direction = inferDirectionForAutoShift(targetThrottle);

            for (GearboxSubsystem gearbox : gearboxes.keySet()) {
                if (overrideCountDown.getOrDefault(gearbox, 0f) <= 0) {
                    gearbox.switchGear(autoGearShift(gearbox, avgEngineSpeed, direction));
                }
            }

            // 分发车轮控制
            for (Map.Entry<WheelDriverSubsystem, String> entry : wheels.entrySet()) {
                String channel = entry.getValue();
                WheelDriverSubsystem wheel = entry.getKey();
                if (wheel.connector.joint != null) {
                    float steeringInput = steering(actualSteering, wheel.connector);
                    float effectiveBrake = calculateEffectiveBrake(wheel, actualBrake);
                    sendCallbackToListener(channel, wheel,
                        new WheelControlSignal(effectiveBrake, actualHandBrake, steeringInput));
                }
            }

        } else {
            // ============================================================
            // 意图模式：双通道 → 方向匹配判断
            // ============================================================
            float throttleInput = moveInput[2] / 100f;          // -1~+1 方向意图
            float brakeInput    = moveInputConflict[2] / 100f;  // 0~1 刹车道

            byte inputDir = throttleInput > 0.01f ? 1 : (throttleInput < -0.01f ? -1 : 0);
            byte speedDir = speed > 0.5f ? 1 : (speed < -0.5f ? -1 : 0);
            boolean dirMatches = inputDir == 0 || speedDir == 0 || inputDir == speedDir;

            if (dirMatches) {
                actualThrottle = actualThrottle * 0.2f + abs(throttleInput) * 0.8f;
                actualBrake = 0;
                // ... 手刹、换挡等 ...
            } else {
                actualThrottle = 0;
                actualBrake = actualBrake * 0.2f + brakeInput * 0.8f;
            }
        }
    } else {
        // 无输入信号 → 现有逻辑不动
    }
}
```

**`inferDirectionForAutoShift` 辅助方法**（新增在 `CarControllerSubsystem` 中）：

```java
/**
 * 分离模式下推断自动换挡的方向参数。
 * <p>
 * 踩油门时检查当前档位：若已有变速箱处于负挡（玩家手动挂R挡），
 * 则 direction = -1 避免 autoGearShift 的方向过滤器把负挡排除掉。
 * 松油门时使用车速方向作为回退。
 */
private byte inferDirectionForAutoShift(float targetThrottle) {
    if (targetThrottle > 0.05f) {
        // 踩油门中 → 检查是否有变速箱已在负挡
        for (GearboxSubsystem gearbox : gearboxes.keySet()) {
            if (gearbox.getCurrentGear() < 0) {
                return -1;
            }
        }
        return 1;
    }
    // 松油门 → 用速度方向推断
    if (Math.abs(speed) < 0.5f) return 0;
    return (byte) (speed >= 0 ? 1 : -1);
}
```

### 3.5 `autoGearShift`

`autoGearShift` 本身无需修改。分离模式下只需在调用前通过 `inferDirectionForAutoShift` 计算出正确的 `direction` 参数即可。`direction == 0`（松油滑行）和 `direction == -1`（倒车）的路径在 `autoGearShift` 内部已有正确处理：
- `direction == 0` → 用 `speed` 推断实际行驶方向
- 纯电动车跳过正/负档方向过滤

## 六、MotorSubsystem 与 EngineSubsystem 的信号接收差异

需注意发动机和电动机对油门信号的语义差异：

| 子系统 | `throttleInput` 范围 | 意图模式输入 | 分离模式输入 |
|--------|---------------------|------------|------------|
| `EngineSubsystem` | 0~1（取绝对值） | `abs(moveInput[2]/100)` | `moveInput[2]/100`（0~1） |
| `MotorSubsystem` | -1~1（保留正负） | `moveInput[2]/100` | `moveInput[2]/100`（0~1） |

`EngineSubsystem.updateThrottleInput()` 第293行对 `MoveInputSignal` 已取 `Math.abs(moveInput[2])`，引擎只关心油门开度大小——分离模式下无需修改引擎侧。

`MotorSubsystem.updateThrottleInput()` 第310行保留正负——分离模式下油门仅传正值为 0~1，电动车的倒车由玩家挂手动负挡 + 踩油门自然完成（变速箱反转扭矩方向），不需要向电机传负值电门。

## 七、设计决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 刹车信号载体 | `moveInputConflict[2]` | 协议零改动，该通道完全未被使用 |
| 模式默认值 | `FOLLOW_VEHICLE`（意图模式） | 意图模式对一般玩家更友好 |
| 分离模式下 WS 同时按下 | 油门和刹车各自独立到满值 | 玩家可能有烧胎等需求，两踏板完全解耦 |
| 分离模式下倒车 | 玩家手动操作变速箱负挡 | 倒车键不是必需的，复用现有手动换挡机制 |
| `WheelDriverSubsystem` fallback 路径 | 阶段一保持意图语义 | 该路径无控制器引用，暂不感知模式 |
| 配置同步 | 走现有 `ControlPreferenceAttachment` → `ControlPreferencePayload` 管线 | 复用现有基础设施 |

## 十一、平滑分离改造（补充问题）

### 11.1 问题描述

用户反馈：意图模式下松开 S 键后，轮胎仍会抱死一段时间，而不是立即重新滚动。

### 11.2 现状：双层平滑叠加

当前输入信号到最终控制量之间经过**两层独立的平滑**：

**第 1 层 — 客户端线性步进**（[RawInputHandler](file:///d:/Files/Project_MinecraftMods/Machine-Max/src/main/java/io/github/sweetzonzi/machine_max/client/input/RawInputHandler.java#L103-L126)）：

```
trans_z_input 以 step = 100 / (fullPowerTime × 20) 每 tick 线性变化
松开按键时以同样步进回零
```

默认 `fullPowerTime` = 1.2s → step ≈ 4.17/tick → 单方向变化需 ~24 ticks (1.2s)

**第 2 层 — 服务端指数平滑**（[CarControllerSubsystem.distributeControlSignals](file:///d:/Files/Project_MinecraftMods/Machine-Max/src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/CarControllerSubsystem.java#L382-L508)）：

各分支中的指数移动平均系数：

| 场景 | `actualThrottle` | `actualBrake` | 从 1→0.05 所需 tick |
|------|-----------------|--------------|-------------------|
| 加速 | `prev×0.9 + input×0.1` | `prev×0.8 + 0×0.2` | ~13 (刹车释放) |
| 刹车 | `prev×0.8 + 0×0.2` | `prev×0.9 + 1×0.1` | ~28 (刹车建立) |
| 滑行(s<1) | `prev×0.9 + 0×0.1` | `prev×0.9 + 1×0.1` | ~28 (手刹维持) |
| 滑行(s>1) | `prev×0.9 + 0×0.1` | `prev×0.8 + 0×0.2` | ~13 (自然衰减) |

### 11.3 意图模式下松开 S 的完整时间线

```
t=0:  按住 S, trans_z_input = -100, 车速 10m/s
       → 刹车分支: actualBrake = 1.0 (全刹)

t=0~1.2s: 松开 S, trans_z_input 线性从 -100→0 (step=4.17/tick)
       → 期间 moveInput[2] < 0, 车速 > 0, 仍在刹车分支
       → actualBrake = prev×0.9 + 1×0.1 ≈ 1.0 (持续全刹)
       → ★ trans_z_input 回零这一路全程都在刹车!

t=1.2s: trans_z_input = 0, 车速降至例如 3m/s
       → 进入 moveInput[2]==0 分支
       → 车速 > 1: actualBrake = prev×0.8 + 0×0.2 (开始衰减)
       → 从 1.0 衰减到 0.05 还需 ~13 ticks (0.65s)

t=1.85s: actualBrake ≈ 0, 车轮恢复滚动
```

**总计约 1.85 秒**从松开 S 到刹车完全释放。主要耗时：

| 阶段 | 耗时 | 占比 |
|------|------|------|
| 客户端 trans_z_input 回零（线性） | ~1.2s | 65% |
| 服务端 actualBrake 衰减（指数 0.8） | ~0.65s | 35% |

### 11.4 分离模式下的同样问题

分离模式下松开 S 的时间线：

```
t=0:  按住 S, trans_z_conflict = 100, 车速 10m/s
       → actualBrake = prev×0.9 + 1.0×0.1 ≈ 1.0

t=0~1.2s: 松开 S, trans_z_conflict 线性从 100→0
       → 期间 targetBrake 从 1.0→0.0
       → actualBrake = prev×0.9 + targetBrake×0.1  (指数平滑叠加线性输入)

t=1.2s: trans_z_conflict = 0, targetBrake = 0
       → actualBrake = prev×0.9 + 0×0.1, 需要再 ~28 ticks 衰减到 0

t=2.6s: actualBrake ≈ 0
```

**总计约 2.6 秒** — 因为 0.9 的平滑系数比意图模式的 0.8 更慢。

### 11.5 根因

**两层平滑的意图是相同的：防止突变。** 但叠加使用产生了过量延迟：
- 客户端一层的平滑本已足够承担全部"渐进变化"的角色
- 服务端一层在客户端层之上额外增加了 0.35~1.3s 的延迟

### 11.6 改造方案

#### A. 客户端配置：[MMClientConfig.java](file:///d:/Files/Project_MinecraftMods/Machine-Max/src/main/java/io/github/sweetzonzi/machine_max/client/MMClientConfig.java)

将现有的单 `full_power_time` 拆分为四个独立时间常数（`ground_vehicle` 组）：

```java
// 保留（意图模式中同名参数控制 trans_z_input 正负变化速度）
private static final ModConfigSpec.DoubleValue GROUND_FULL_POWER_TIME;
// ★ 新增
private static final ModConfigSpec.DoubleValue GROUND_POWER_OFF_TIME;     // 收油归零
private static final ModConfigSpec.DoubleValue GROUND_FULL_BRAKE_TIME;    // 刹车建立
private static final ModConfigSpec.DoubleValue GROUND_BRAKE_OFF_TIME;     // 刹车释放
```

参数说明：

| 配置项 | 默认值 | 语义 | 意图模式影响 | 分离模式影响 |
|--------|--------|------|------------|------------|
| `full_power_time` | 1.2s | 油门/方向输入 0→100% | W按下时 trans_z 正向变化 | W按下时 trans_z 0→+100 |
| `power_off_time` | 0.3s | 收油后归零 | W松开时 trans_z +→0 | W松开时 trans_z +→0 |
| `full_brake_time` | 0.3s | 刹车 0→100% | S按下时 trans_z 负向变化 | S按下时 conflict 0→+100 |
| `brake_off_time` | 0.2s | 松开刹车后归零 | S松开时 trans_z -→0 | S松开时 conflict +→0 |
| `full_steering_time` | 0.4s | 转向建立（保留） | 不变 | 不变 |
| `steering_off_time` | 0.4s | 转向回正（★新增） | 转向松开时回正 | 转向松开时回正 |

**注意**：意图模式中 trans_z_input 是正负共享的单轴，所以：
- `full_power_time` 控制 W 按下时 trans_z 朝 + 方向的步进
- `full_brake_time` 控制 S 按下时 trans_z 朝 - 方向的步进
- 跨零（从正到负或反之）需要两个方向时间之和

#### B. 服务端平滑系数调整：[CarControllerSubsystem.distributeControlSignals](file:///d:/Files/Project_MinecraftMods/Machine-Max/src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/CarControllerSubsystem.java#L382-L508)

**大幅降低指数平滑系数**，让服务端仅保留最基本的防抖动功能：

| 当前系数 | 改为 | 接近稳态时间 | 理由 |
|---------|------|------------|------|
| `0.9` (油门) | `0.2` | ~2 ticks | 平滑职责交给客户端 |
| `0.8` / `0.9` (刹车) | `0.2` | ~2 ticks | 平滑职责交给客户端 |
| `0.8` (过渡) | `0` (直接赋值) | 0 | 过渡场景不需要额外平滑 |

改造后的大致代码：

```java
// 分离模式（新）
actualThrottle = actualThrottle * 0.2f + targetThrottle * 0.8f;
actualBrake   = actualBrake   * 0.2f + targetBrake   * 0.8f;

// 意图模式加速
actualThrottle = actualThrottle * 0.2f + moveInput[2] * 0.8f;
actualBrake   = actualBrake * 0.0f + 0 * 1.0f; // 立即归零

// 意图模式刹车
actualThrottle = actualThrottle * 0.0f + 0 * 1.0f; // 立即归零
actualBrake   = actualBrake * 0.2f + 1 * 0.8f; // 略平滑但快

// 滑行(s>1)
actualBrake = actualBrake * 0.2f + 0 * 0.8f; // ~10 ticks
```

**效果对比**（分离模式，松开 S）：

| 阶段 | 改前 | 改后 |
|------|------|------|
| conflict 回零 | 1.2s (fullPowerTime) | 0.2s (brake_off_time) |
| actualBrake 平滑 | 0.9系数 → ～28 ticks 残余 | 0.2系数 → ～3 ticks 残余 |
| **总计** | **～2.6s** | **～0.35s** |

**意图模式，松开 S 效果对比**：

| 阶段 | 改前 | 改后 |
|------|------|------|
| trans_z 回零 | 1.2s (fullPowerTime) | 0.2s (brake_off_time) |
| actualBrake 平滑 | 0.8系数 → ～13 ticks | 0.2系数 → ～3 ticks |
| **总计** | **～1.85s** | **～0.35s** |
