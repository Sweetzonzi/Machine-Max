## 一、背景与问题

### 1.1 现状

当前 RegenLoader 每个实例只提供单一弹种（`projectile_type`），已在上一步 `850c0b5` 中从静态属性移至动态属性。用户选择弹药时选的是**弹种**：

```
选弹 = 选弹种（"我要打AP"）
       → 如果弹链中包含曳光弹，曳光弹位被 Launcher 拒绝击发 → ❌
```

AmmoHud 通过 `ammoPool.get(typeKey)` 按单种弹药聚合总计数。

### 1.2 目标

弹链（ammo belt）：一个**有序、循环的弹种序列**，模拟现实机枪弹链（AP-AP-AP-Tracer-AP-AP-AP-Tracer...）。单一弹种退化为长度为 1 的弹链。

核心观念转变：

```
之前：选弹种 → 弹种切换
之后：选弹链 → 弹链切换（单一弹种 = 长度1的弹链）
```

Launcher 照单全收，`isAmmoCompatible()` 仅作逐发安全校验。

## 二、设计

### 2.1 JSON 格式 — `projectile_type` 替换为 `projectile_types`

```json
// 之前（已移除）
{ "projectile_type": "machine_max:7_92mm_smk" }

// 之后 — 弹链（键值对，保序）
{ "projectile_types": {
    "machine_max:7_92mm_smk":    3,
    "machine_max:7_92mm_ap":     2,
    "machine_max:7_92mm_tracer": 1
  }
}

// 单一弹种（即长度为1的弹链）
{ "projectile_types": {
    "machine_max:50mm_pzgr39": 1
  }
}
```

**Java 侧**（`RegenLoaderSubsystemAttr` 构造函数）：

不在序列化层做展平，而是在构造函数中接收 `Map<ResourceLocation, Integer>`，展平为不可变的 `List<ResourceLocation>` 存储为 `final` 字段：

```java
/** 展平后的弹链序列（不可变，构造时从 JSON map 展平） */
public final List<ResourceLocation> projectileTypes;

public RegenLoaderSubsystemAttr(
        ResourceLocation modelName,
        Map<ResourceLocation, Integer> projectileTypesMap,   // JSON 键值对
        Map<String, List<String>> discoveryOutputs) {
    super(modelName);
    this.staticAttribute = (RegenLoaderSubsystemStaticAttr) getStaticAttr();

    // 构造时展平：{SMK:3, AP:2, Tracer:1} → [SMK,SMK,SMK, AP,AP, Tracer]
    List<ResourceLocation> flat = new ArrayList<>();
    for (var entry : projectileTypesMap.entrySet()) {
        for (int i = 0; i < entry.getValue(); i++)
            flat.add(entry.getKey());
    }
    this.projectileTypes = List.copyOf(flat);

    this.discoveryOutputs = discoveryOutputs;
}
```

### 2.3 WeaponController — ammoPool 重构

**核心变更**：选弹 = 选弹链，ammoPool key 从单弹种改为弹链。

#### 数据结构

```java
// 之前
Map<ResourceLocation, List<LoaderEntry>> ammoPool;
//   "7_92mm_smk" → [loader1, loader2]

// 之后
Map<List<ResourceLocation>, List<LoaderEntry>> ammoPool;
//   [SMK,SMK,SMK, AP,AP, Tracer] → [loader1]      ← MG34 标准弹链
//   [AP,AP,AP,AP,AP,AP]          → [loader2]      ← 全穿甲弹链
//   [Pzgr39]                     → [loader3]      ← 50mm 单弹种
```

#### LoaderEntry

```java
// 之前：弹种 + 可用数 + 装填时间
public record LoaderEntry(
    ResourceLocation projectileType,
    int availableCount,
    int reloadTimeTicks,
    String channel
) {}

// 之后：
public record LoaderEntry(
    List<ResourceLocation> projectileTypes,   // 弹链序列（不可变）
    int availableCount,
    int reloadTimeTicks,
    String channel
) {}
```

#### rebuildAmmoPool()

遍历所有 launcher → supplierChannels → loader：

```java
void rebuildAmmoPool() {
    ammoPool.clear();
    Set<IAmmoSupplier> visited = new HashSet<>();

    for (var entry : getLaunchers().entrySet()) {
        LauncherSubsystem launcher = entry.getKey();
        for (var channelEntry : launcher.getSupplierChannels().entrySet()) {
            String channel = channelEntry.getKey();
            for (var supplier : channelEntry.getValue()) {
                if (!visited.add(supplier)) continue;  // 去重

                if (supplier instanceof RegenLoaderSubsystem regenLoader) {
                    List<ResourceLocation> types = regenLoader.getProjectileTypes();
                    if (types.isEmpty()) continue;

                    LoaderEntry loaderEntry = new LoaderEntry(
                        types,
                        regenLoader.getRemainingCount(),
                        regenLoader.getReloadTimeTicks(),
                        channel
                    );
                    ammoPool.computeIfAbsent(types, k -> new ArrayList<>()).add(loaderEntry);
                }
                // AmmoLoader 也按弹链处理（后续）
            }
        }
    }
}
```

#### 弹链切换

```java
// 之前：cycleSelectedType() 在 ResourceLocation 间循环
// 之后：cycleSelectedBelt() 在 List<ResourceLocation> 间循环

private void cycleSelectedBelt(boolean reverse) {
    if (ammoPool.isEmpty()) return;

    List<List<ResourceLocation>> belts = new ArrayList<>(ammoPool.keySet());
    // 按第一发弹种排序（保持稳定顺序）
    belts.sort(Comparator.comparing(b -> b.isEmpty() ? "" : b.get(0).toString()));

    int currentIdx = belts.indexOf(selectedBelt);
    int step = reverse ? -1 : 1;
    int nextIdx = (currentIdx + step + belts.size()) % belts.size();
    selectedBelt = belts.get(nextIdx);
}
```

接口签名完全不变。

### 2.6 AmmoHud — 微调

当前（[AmmoHud.java](file:///d:/Files/Project_MinecraftMods/Machine-Max/src/main/java/io/github/sweetzonzi/machine_max/client/render/gui/hud/AmmoHud.java)）显示的是弹种名 + 总数。弹链模式下：

- **第一行（弹种名）**：显示弹链当前/下一发的弹种名（`launcher.getCurrentAmmoType()` 不变）
- **总数**：`ammoPool.get(selectedBelt)` 聚合
- **弹种切换预览**（可选增强）：在弹链名旁显示弹链概览，如 `"[AP×3·T×1]"`

### 2.7 AmmoLoader — 留待后续

AmmoLoader 基于物品容器（`SimpleContainer`），弹药类型从物品读取。未来弹链支持可通过物品的 NBT/ScriptedItem 携带弹链构成信息，设计时预留弹链路由的接入点（`LoaderEntry.projectileTypes`），当前暂不实现。

## 四、设计决策记录

1. **选弹 = 选弹链**：不再存在"选了一种弹却被 Launcher 拒绝"的问题
2. **`List.copyOf()`** **做 Map 键**：不可变 + 正确 hashCode/equals，比 `Collections.unmodifiableList` 安全
3. **弹链冗余展开**：`{AP:3, T:1}` 展平为 `[AP,AP,AP,T]`，`getSuppliedType()` 只需取 `projectileTypes.get(projectileTypeIndex)`，O(1)
4. **保持 AmmoLoader 接入点预留**：`LoaderEntry.projectileTypes` 统一，后续扩展无缝
5. **移除** **`getAmmoBreakdown()`**：弹链重构后 WeaponController 三个调用点 (`rebuildAmmoPool`/`refreshAmmoPoolCounts`/`findBestLoaderFor`) 全部改用新 API，接口及实现一并删除
