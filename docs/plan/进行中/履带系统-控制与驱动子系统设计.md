## 0. 结论与实施顺序

### 0.1 设计结论

- 履带需要独立的控制语义与驱动执行器。`TrackControllerSubsystem` 负责差速转向、单流制动分配、双流转向编排；`TrackDriveSubsystem` 负责主动轮滚动轴的多路功率汇合、制动、手刹与反馈。两者都不把履带语义塞进 `WheelDriverSubsystem`。
- 地面控制器共享部分抽到 `AbstractGroundControllerSubsystem`：油门/刹车/手刹、发动机/电机/变速箱发现、自动换挡、方向推断、通用握手与输出。
- 履带控制沿用座椅的 `ControlMode.GROUND` 输入映射（W/S 油门/刹车，A/D 转向）。不新增 `ControlMode.TRACK`，也不使用 `VehicleCore.ControlMode`。
- 驱动资格只检查有效连接器、存活的被驱动 `SubPart` 与有限正轮半径；控制器和驱动器都不以 `TrackLink` 是否存在、是否为主动轮或是否断带来限制驱动。断带后主动轮可继续旋转，车辆偏航与牵引变化由接触和约束求解产生。
- 多输入反馈使用实测总转速，按各 producer 最近一次输入转速的比例分摊；单输入时退化为实测值。反馈不区分模式，也不回显指令。
- 控制器与驱动之间不依赖 `SubsystemController` 的遍历顺序；控制信号在 `onPrePhysicsTick` 写入并在频道中保持，驱动最坏晚一 tick 读取。

### 0.2 实施阶段

| 阶段 | 内容 | 验收点 |
| --- | --- | --- |
| A | 从 `CarControllerSubsystem` 抽 `AbstractGroundControllerSubsystem`，`Car`/`Motorbike` 继承它；`ControlPreference` 形参上移 | 轮式/摩托车 `runClient` 行为不变；现有 JUnit 通过 |
| B | 新增 `TrackDriveSubsystem`（多输入缓存，先接主传动）、`TrackControlSignal`、`TrackControllerSubsystem`；两履带单流 | 直行、左右转、倒车、手刹、内侧制动饱和；`runServer` 解码注册 |
| C | 增加转向电机 + 转向传动，`TrackDrive` 接第二路输入；双流中心转向 | 零速中心转向；左右反向；反馈不抵消 |
| D | 四履带、HUD、性能优化 | 四履带线性分配；多驱动布局与非对称接地的物理响应 |

阶段 A / B 已实现，沿用现有 `GearboxSubsystem` 与 `TransmissionSubsystem`。阶段 B 的驱动包含多输入缓存；阶段 C 的转向电机、转向传动、反馈分摊标定与中心转向验收属于后续工作。

### 0.3 不在本文范围

- `TrackLink` 的成员关系、`GearJoint` 星形耦合、张力、耐久、断带物理与包络渲染；
- 具体 PID/PD 增益的实机标定值；
- 轮式 `CarControllerSubsystem` 的阿克曼/漂移/ABS 细节，除基类抽取涉及的成员外；
- 履带节模型、贴图与音效资产。

## 1. 术语与范围

### 1.1 术语

| 术语 | 含义 |
| --- | --- |
| `AbstractGroundControllerSubsystem` | 地面载具控制器基类：共享输入、发动机/电机/变速箱、自动换挡、握手与输出 |
| `TrackControllerSubsystem` | 履带控制器：差速转向、单流制动分配、双流转向编排 |
| `TrackDriveSubsystem` | 车体侧履带驱动：一个主动轮连接器、一个滚动轴、多路 `MechPower` 输入 |
| 主动轮 | 履带的功率输入轮；履带中唯一有驱动的轮 |
| 负重轮 | 履带成员，只有 `GearJoint`/车体约束，没有轮驱子系统 |
| 主传动 | 把发动机/变速箱功率分到各履带驱动的 `TransmissionSubsystem` 实例 |
| 转向传动 | 把转向电机功率分到各履带驱动的另一个 `TransmissionSubsystem` 实例 |
| 单流 | 转向功率来自主功率，通过制动产生差速；第一版实现 |
| 双流 | 转向功率有独立路径（电机/液压），可直接给左右加/减速度；后续阶段 |
| 功率流 | `MechPower(power, speed)` 沿 `IMechPowerProducer` → `IMechPowerConsumer` 的传递 |
| 反馈转速 | 消费者回给生产者的速度，用于生产者的闭环/功率分配 |
| 横向位置 `x_i` | 第 `i` 个履带驱动在控制器车体局部坐标系中的 X 坐标，已按全部驱动均值中心化 |
| 半径 `r_i` | 第 `i` 个被驱动 `SubPart` 的轮半径（`getMaxWheelRadius()`） |
| 基础速度 `v_base` | 单流取外侧履带线速度；双流取各履带线速度均值；控制器只观测，不直接命令 |
| `r_des` | 期望横摆角速度（rad/s） |
| `v1` / `v2` | 实施阶段：v1 单流，v2 双流；不是两套代码分支 |

### 1.2 范围

本文讨论履带载具的控制层与驱动支撑层：

- 谁接受座椅输入、谁编排发动机/变速箱/传动/驱动；
- 驱动如何挂载、如何接收多路功率、如何汇合、如何反馈；
- 单流与双流如何由现有 `TransmissionSubsystem` + `MotorSubsystem` 组合出来；
- 多履带（含四条履带）如何按横向位置分配相对速度；
- 需要引入的类型、属性、信号与接口改动。

不讨论物理文档覆盖的 `TrackLink` 成员关系、约束、张力、耐久、渲染与音效。

## 2. 现状与约束

### 2.1 现有功率流

当前机械功率链：

```text
Engine / Motor（IMechPowerProducer）
  → Gearbox（IMechPowerConsumer + IMechPowerProducer）
    → Transmission（IMechPowerConsumer + IMechPowerProducer）
      → 驱动执行器（IMechPowerConsumer）
```

履带接入后，最后一级由 `TrackDriveSubsystem` 承担：

```text
Engine / Motor → Gearbox → Transmission（主传动）
                              └─→ TrackDrive（左/右主动轮）
```

双流阶段增加第二条路径：

```text
Engine / Motor → Gearbox → Transmission（主传动） ─┐
                                                   ├─→ TrackDrive
转向电机 → Transmission（转向传动） ───────────────┘
```

关键约定：

- [`MechPower`](../../../src/main/java/io/github/sweetzonzi/machine_max/common/mech/energy/MechPower.java) 是 `(power, speed)`：`power = τ × |speed|`，`speed` 有符号。`MechPower.EMPTY` 用 `NaN` 表示“该路无功率”。
- [`IMechPowerConsumer`](../../../src/main/java/io/github/sweetzonzi/machine_max/common/mech/energy/IMechPowerConsumer.java) 有 `onMechPowerReceived(String producerName, MechPower power)`、`getFeedbackSpeed()`、`isPowerPathConnected(String producerName)`。v2 增加按 producer 的反馈重载，见 §7.1。
- [`IMechPowerProducer.collectFeedbackSpeeds()`](../../../src/main/java/io/github/sweetzonzi/machine_max/common/mech/energy/IMechPowerProducer.java) 遍历自己的目标，读取消费者的反馈。
- [`TransmissionSubsystem`](../../../src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/TransmissionSubsystem.java) 支持 N 个输出、每个输出一个减速比、开放差速/差速锁。
  - 输出目标转速：`refSpeed = inputSpeed / ratio`。
  - 输出功率：`power = torque * ratio * |targetSpeed|`。
  - 反馈汇总：`consumer.getFeedbackSpeed() * ratio` 后平均。
- [`WheelDriverSubsystem`](../../../src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/WheelDriverSubsystem.java) 是轮式执行器：滚动轴 + 转向伺服、单路功率、实测反馈。履带不复用它，理由见 §6.8。

### 2.2 履带的边界

- 履带成员是普通 `SubPart`：主动轮 + 负重轮。
- 标准履带内容包只给主动轮配置 `TrackDriveSubsystem`，负重轮通过 `GearJoint` 和车体约束被动跟随；这是内容包接线约定，驱动器的有效性检查只要求被驱动轮可提供有效半径。
- 主动轮通过 `GearJoint` 与各负重轮耦合：`ω_road = (r_sprocket / r_road) * ω_sprocket`，线速度一致。
- 标准履带内容包的功率流只到主动轮；只有显式配置了驱动的轮子参与功率分配。
- `TrackLink` 是 `VehicleCore` 级的关系/状态对象，持有成员、约束、张力、耐久；它不被任何驱动子系统持有。
- 履带列表没有名字；控制层按主动轮的横向位置区分左右，不按列表顺序。
- 断带时 `TrackLink` 解除全部 `GearJoint` 耦合，张力置零；主动轮按驾驶输入受驱动，其余未配置驱动的负重轮自由滚。主动轮制动只作用于主动轮，不能通过已解除的耦合制动负重轮。

### 2.3 代码约束

**继承链。** 目标结构是：

```text
AbstractSubsystem
  └ BasicSubsystem
      └ AbstractGroundControllerSubsystem
          ├ CarControllerSubsystem
          │    └ MotorbikeControllerSubsystem
          └ TrackControllerSubsystem
```

[`AbstractControllableSubsystem`](../../../src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/AbstractControllableSubsystem.java) 属于座椅侧（控制组、相机/武器握手），不在这条链上。当前 [`CarControllerSubsystem`](../../../src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/CarControllerSubsystem.java) 直接继承 `BasicSubsystem`；阶段 A 抽出基类后，`Car`、`Motorbike`、`Track` 都继承基类。`Motorbike` 仍通过 `Car` 间接继承。

**tick 顺序。** [`SubsystemController`](../../../src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/SubsystemController.java) 按 `CopyOnWriteArraySet` 遍历，集合来自 `HashSet`，没有拓扑顺序保证。控制器与驱动都不依赖遍历顺序：

- 控制器在 `onPrePhysicsTick` 计算并写入信号；驱动在自身 `onPrePhysicsTick` 读取；
- 驱动若已经先 tick，读到的是上一 tick 的信号，最坏延迟一 tick；信号在频道中保持，不会丢；
- 功率推送同样允许一 tick 最坏延迟；不做拓扑排序。

**信号解析。** `control_outputs` 的目标名可以是：

- 控制器所在 `SubPart` 内的子系统名；
- 同 `SubPart` 的连接点 `SignalPort` 名，由端口转发到对侧；
- `"global"`，由 `SubsystemController.broadcast` 分发给声明接受该频道的订阅者。

局部名只在发送者所在 `SubPart` 内解析；跨 `SubPart` 用连接点端口或 `global`。三条路径都允许，控制器按 sender 类型归类并用身份去重。频道名必须与目标子系统的 `control_inputs` 一致：发动机、变速箱与 `TrackDrive` 默认都读 `car_control`；需要独立频道时，在 `TrackDrive` 的静态属性里覆盖 `control_inputs`，并让控制器的 `control_outputs` 使用同一个频道名。

**属性与注册。** 静态属性（`*StaticAttr`）按 `definition` 注册，动态属性（`*Attr`）按实例 JSON 的 `type` 注册。JSON 的 `type` 是 [`MMCodecs.kt`](../../../src/main/kotlin/io/github/sweetzonzi/machine_max/common/registry/MMCodecs.kt) 里 `MMDataRegistries.SUBSYSTEM_ATTR_CODEC` / `SUBSYSTEM_STATIC_ATTR_CODEC` 的注册键；`SubsystemTypes` 只用于 `getType()` 的类型校验。新增类型必须同时注册动态、静态两个 codec，并补内容包 schema。

**横向位置与半径。** 横向位置用 `AbstractConnector.offsetFromMassCenter`（稳定局部量），不用 `actualTransform`（安装变换，attach 时会改写）。同 `SubPart` 直接取 X；跨 `SubPart` 用 `MMMath.worldPointLocalPos(MMMath.relPointWorldPos(offset, driveBody), controllerBody)` 换算到控制器车体局部。半径用 `SubPart.getMaxWheelRadius()`，与 `GearJoint` 传动比、包络推导同一口径；`WheelDriver` 的 `abs_wheel_radius` 是 ABS 专用，不用于履带。

**控制模式。** 座椅使用 [`common/mech/control/ControlMode`](../../../src/main/java/io/github/sweetzonzi/machine_max/common/mech/control/ControlMode.java) 的 `GROUND`。`VehicleCore.ControlMode` 不参与座椅输入门控，不新增 `TRACK`。

**履带状态与驱动独立。** `src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/track/TrackLink.java#damage` 处理断带并解除轮组耦合，`src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/track/TrackLink.java#dispose` 在解散时清空成员的 `trackLink` 引用。控制器与驱动器在完整、断带、未铺设和解散状态下均按有效驱动轮处理；轮子继续参与 `v_base` 与差速分配。履带状态本身不触发离合断开、强制制动、转向权限缩放或扭矩降额，也不附加拖拽力。

### 2.4 线程与同步

| 数据 | 写入 | 读取 | 同步方式 |
| --- | --- | --- | --- |
| 座椅输入 / 控制组 | 主线程 | 控制器（物理线程读） | 信号频道 / `MoveInputSignal` |
| 控制器发现表、绑定表 | 主线程（attach / 结构变化） | 物理线程 | `volatile` 不可变列表 / 并发 Map |
| `TrackDrive.received` | 物理线程（producer push） | 物理线程 | `ConcurrentHashMap` |
| `TrackDrive` 离合/制动 | 物理线程（控制器信号） | 物理线程 | 信号频道 |
| `TrackDrive` 实测转速/力 | 物理线程 | 控制器/HUD | 方法读取 / 信号输出 |

不新增网络载荷。`TrackLinkSyncPayload` 继续只承担履带关键状态；控制信号是本地信号，步进前后在服务端物理线程内消费。

## 3. 总体架构

### 3.1 v1 单流（阶段 B）

```text
座椅（ControlGroup，GROUND）
  │ move_input / regular_input（可走 global）
  ▼
TrackControllerSubsystem（AbstractGroundControllerSubsystem）
  ├─ Engine / Motor        油门、转速
  ├─ Gearbox               换挡、离合
  ├─ 主传动（TransmissionSubsystem）
  │     ├─→ TrackDrive(左)
  │     └─→ TrackDrive(右)
  └─ TrackControlSignal → 各 TrackDrive（制动/手刹/离合）

TrackLink（VehicleCore）
  └─ 独立处理轮组耦合、张力与接触属性；断带解除耦合
```

- 左/右主动轮各一个 `TrackDriveSubsystem`；`TrackDriveSubsystem` 挂在车体 `SubPart`，`connector` 指向车体—主动轮连接器。
- 主传动是现有 `TransmissionSubsystem`，每个主动轮一个输出，比值 `1.0`；`diff_lock` 用开放差速（`false`）或高阈值 `auto`，避免锁止削弱差速转向。
- 控制器输出 `TrackControlSignal(brakeControl, handBrakeControl, clutchEngagement)`；内侧制动产生差速，外侧保持主路速度。
- 控制器与驱动器按连接器和轮半径建立驱动绑定，驱动资格与 `TrackLink` 状态独立（见 §5.6）。

### 3.2 v2 双流（阶段 C）

```text
座椅 → TrackControllerSubsystem
  ├─ Engine / Gearbox → 主传动 ──────────────┐
  ├─ 转向电机（MotorSubsystem）→ 转向传动 ──┤
  │                                         ├─→ TrackDrive(左)
  │                                         └─→ TrackDrive(右)
  └─ TrackControlSignal → 各 TrackDrive（制动/手刹/离合）
```

- 主传动与转向传动都是现有 `TransmissionSubsystem`；`TrackDrive` 已经支持多路 `MechPower`，v2 只增加第二路 producer。
- 转向几何写在转向传动的 `power_outputs` 比值里（`x_ref / x_i`）；`TrackDrive` 只做求和。
- 单流没有转向电机/转向传动；控制器按执行器存在性选择分配方式，不设 `mode` 字段。

### 3.3 组件职责

| 组件 | 阶段 | 挂载 | 职责 |
| --- | --- | --- | --- |
| `AbstractGroundControllerSubsystem` | A | 抽象基类 | 地面载具共性：发动机/电机/变速箱发现、油门/刹车/手刹、自动换挡、方向推断、握手、输出模板 |
| `TrackControllerSubsystem` | B | 车体 | 接受座椅输入；编排发动机/变速箱/传动/转向电机/履带驱动；计算差速分配 |
| `TrackDriveSubsystem` | B | 车体，每个主动轮连接器一个 | 多路 `MechPower` 缓存与汇合；驱动/制动/手刹/离合；按 producer 反馈；无 `TrackLink` |
| `TransmissionSubsystem` | 现有 | 车体 | 主传动与转向传动的功率分配；比值表达转向几何与符号 |
| `MotorSubsystem` | 现有 | 车体 | 双流/电传动的转向动力源 |
| `GearboxSubsystem` | 现有 | 车体 | 换挡、离合；由控制器编排 |
| `TrackLink` | 现有 | `VehicleCore` | 履带成员、GearJoint、张力、耐久；不参与驱动 |
| `TrackControlSignal` | B | 信号 | `brakeControl` / `handBrakeControl` / `clutchEngagement` |

### 3.4 设计原则

1. **控制器发运动意图，不发绝对速度。** 基础速度由发动机/变速箱/主传动决定；控制器只发相对制动、手刹、离合、转向电机命令。
2. **驱动是独立执行器。** `TrackDriveSubsystem` 只知道“被驱动 SubPart、半径、多路功率、上限”，可驱动履带主动轮或普通滑移车轮；转向伺服与 ABS 属于 `WheelDriverSubsystem`。
3. **单流与双流共用同一控制器和驱动。** 单流靠制动分配；双流靠转向传动的比值；`TrackDrive` 只做多路求和与反馈分摊。
4. **横向位置决定分配。** 多履带按中心化 `x_i` 逐条处理，不写“左/右”分组。
5. **履带关系与驱动资格独立。** `TrackLink` 负责轮组耦合、张力、耐久与接触属性；控制器和驱动器只检查连接器、被驱动轮与半径。断带后的非对称牵引和偏航由物理求解产生。
6. **反馈是实测值。** 单输入返回实测；多输入把实测总量按输入转速比例分摊。不回显指令，不引入反馈模式。
7. **不依赖 tick 顺序。** 控制信号在频道中保持，最坏晚一 tick；不做拓扑排序。

## 4. `AbstractGroundControllerSubsystem`

### 4.1 继承关系

```text
AbstractSubsystem
  └ BasicSubsystem
      └ AbstractGroundControllerSubsystem
          ├ CarControllerSubsystem
          │    └ MotorbikeControllerSubsystem
          └ TrackControllerSubsystem
```

- 基类直接继承 `BasicSubsystem`，不继承 `AbstractControllableSubsystem`；控制组、相机、武器握手属于座椅侧。
- 共享的输入 / 动力 / 换挡逻辑由基类承载，轮式转向 / 漂移 / ABS 由 `CarControllerSubsystem` 承载。
- `MotorbikeControllerSubsystem` 继续继承 `CarControllerSubsystem`，通过它间接继承基类。
- `TrackControllerSubsystem` 直接继承基类。

### 4.2 基类成员

从 `CarControllerSubsystem` 上移到基类的成员：

- `Map<EngineSubsystem, String> engines`
- `Map<MotorSubsystem, String> motors`
- `Map<GearboxSubsystem, String> gearboxes`
- `actualThrottle` / `actualBrake` / `actualHandBrake` / `handBrake`
- `moveInput` / `moveInputConflict` / `speed`
- `overrideCountDown`
- `handShake()`：通过 `control_outputs` 频道发现发动机/电机/变速箱/执行器
- `updateMoveInputs()`
- `updateRegularInputs()`
- `calculateAvgSpeedAndControl()`：向发动机/电机发油门，返回平均转速
- `autoGearShift(GearboxSubsystem, float, byte)`
- `inferDirectionForAutoShift(float)`
- `resetSignalOutputs()` 的共享部分
- `onTick()` 中速度输出与手刹音效的共享部分
- `onPostPhysicsTick()` 中共享油门/刹车/手刹输出的发送

`CarControllerSubsystem` 保留：`wheels`、`computedSteeringCenter`、`driftWeight`、`driftingPD`、`steering()`、`ackermannSteering()`、`driftSteering()`、`calculateDriftBrakeBias()`、`calculateEffectiveBrake()`、轮端 `WheelControlSignal` 分配。

`TrackControllerSubsystem` 保留：`tracks` 驱动轮绑定表、差速制动分配、`TrackControlSignal` 发送；绑定表的成员资格与 `TrackLink` 状态独立。

### 4.3 抽象钩子

```java
protected abstract void distributeDriveControl();      // onPrePhysicsTick 中调用
protected abstract void onActuatorDiscovered(ISignalSender sender, String channel);
protected void onHandShakeComplete() {}
```

- `onActuatorDiscovered` 接住 `onSignalUpdated("callback", sender)` 的回调：基类先处理 `EngineSubsystem` / `MotorSubsystem` / `GearboxSubsystem`，子类再处理 `WheelDriverSubsystem` 或 `TrackDriveSubsystem`。
- 基类的 `handShake()` 只负责发送 `control_outputs` 与清理/重建；具体执行器归类由钩子完成。
- 基类不假定执行器在同一个 `SubPart`；local、连接点端口、`global` 三条路径都允许。

### 4.4 生命周期顺序

基类 `onPrePhysicsTick`：

1. `super.onPrePhysicsTick()`
2. 读取 `speed` / 车体横摆角速度
3. `updateMoveInputs()` / `updateRegularInputs()`
4. 更新 `actualThrottle` / `actualBrake` / `actualHandBrake`
5. 自动换挡与方向推断
6. `calculateAvgSpeedAndControl()`
7. `distributeDriveControl()`

基类 `onPostPhysicsTick`：

1. `super.onPostPhysicsTick()`
2. 发送共享的油门/刹车/手刹输出（HUD / 脚本）
3. 子类可追加输出

履带控制信号只在 `onPrePhysicsTick` 发送；`onPostPhysicsTick` 不发送履带控制信号。驱动若晚一 tick 读取，控制量保持，不产生丢帧。

`onAttach` / `onVehicleStructureChanged` 都调用 `handShake()`；`Car` 在 `onHandShakeComplete()` 重算转向中心，`Track` 在钩子中重建履带绑定。

### 4.5 迁移与回归

阶段 A 的迁移顺序：

1. 新建 `AbstractGroundControllerSubsystem`，把 §4.2 的成员从 `CarControllerSubsystem` 上移；保持方法可见性为 `protected` 或包内可见，避免 `private` 阻挡子类。
2. `CarControllerSubsystem` 继承 `AbstractGroundControllerSubsystem`；`wheels`、转向、漂移、ABS 留在 `Car`。
3. `onSignalUpdated("callback")` 的 `instanceof` 链拆成基类处理发动机/电机/变速箱 + `onActuatorDiscovered` 钩子；`Car` 在钩子中处理 `WheelDriverSubsystem`。
4. `handShake()` 的通用部分留基类；`Car` 在 `onHandShakeComplete()` 中重算转向中心，`Track` 在钩子中重建履带绑定。
5. `ControlPreference` 的 `shouldAutoHandBrake` / `shouldAutoSwitchGear` / `shouldRawThrottleBrake` 形参使用 `AbstractGroundControllerSubsystem`；`shouldDriftAssist` / `shouldLimitSpeedTurning` 保留 `Car` 形参。
6. 回归：`runClient` 驾驶现有轮式载具与摩托车，油门/刹车/换挡/漂移/倾斜行为不变；`gradlew test` 通过。

`MotorbikeControllerSubsystem.onPrePhysicsTick` 覆盖了 `CarControllerSubsystem` 的全流程；迁移时把基类共享阶段放进它的调用链，摩托车特有的 roll / balancing 保持在子类，避免绕过基类的输入/换挡/油门。

`CarControllerSubsystem` 的静态属性类型保持 `CarControllerSubsystemStaticAttr`；`TrackControllerSubsystem` 使用自己的静态属性类。基类通过抽象方法读取需要的开关：

```java
protected abstract boolean isAutoHandBrakeEnabled();
protected abstract boolean isManualGearShift();
protected abstract boolean isSeparateThrottleBrake();
```

### 4.6 `ControlPreference` 的边界

- `shouldAutoHandBrake`、`shouldAutoSwitchGear`、`shouldRawThrottleBrake`：基类形参，`Car`/`Track` 共用。
- `shouldDriftAssist`、`shouldLimitSpeedTurning`：轮式专用，保留 `CarControllerSubsystem` 形参。
- 玩家偏好缺失时，回退到各自静态属性；`TrackController` 的静态属性提供同名开关。

## 5. `TrackControllerSubsystem`

### 5.1 输入与发现

- 继承 `AbstractGroundControllerSubsystem`，由座椅 `ControlGroup` 发送 `MoveInputSignal` / `RegularInputSignal`。
- `control_inputs` 频道（默认与 `CarControllerSubsystem` 相同）：
  - `move_input_p0` … `move_input_p3`、`move_input`
  - `regular_input_p0` … `regular_input_p3`、`regular_input`
- `control_outputs` 频道（示意）：

```json
{
  "car_control": [
    "subsystem.machine_max.engine",
    "subsystem.machine_max.gearbox",
    "subsystem.machine_max.left_track_drive",
    "subsystem.machine_max.right_track_drive"
  ]
}
```

- `car_control` 是发动机、变速箱与 `TrackDrive` 的默认读频道；控制器用一个频道完成发现与下发。需要隔离履带控制信号时，在 `TrackDrive` 静态属性里覆盖 `control_inputs`，并在 `control_outputs` 增加同名频道。
- `control_outputs` 的目标可以是 local 名、连接点 `SignalPort` 名或 `"global"`。跨 `SubPart` 时用端口或 `global`；局部名只在控制器所在 `SubPart` 内解析。
- 示例使用控制器同一 `SubPart` 的局部名；目标跨 `SubPart` 时，把对应列表改为 `["global"]` 或连接点端口名。
- 握手时：
  - 基类发现发动机/电机/变速箱；
  - 子类在 `onActuatorDiscovered` 中发现 `TrackDriveSubsystem`，读取 `connector`、`drivenSubPart()`、`radius()`；
  - 转向电机（双流）走 `steering_motor_control` 频道，由基类或子类发现；
  - 转向传动不需要被控制器直接发现：它由转向电机的 `power_output` 驱动，输出接到各履带驱动。
- 履带驱动按中心化 `x_i` 排序；不依赖子系统名或列表顺序。
- 发现结果用身份去重：同一个驱动从 local 与 `global` 两条路径各回调一次时只保留一个绑定。
- `TrackDrive` 的 `drivenSubPart()` 是连接器对位的被驱动轮。绑定要求连接器已连接、关节可用、被驱动轮存活且 `SubPart.getMaxWheelRadius()` 返回有限正值；与 `trackLink`、`isSprocket`、`broken`、`disposed` 无关。标准履带内容包只给主动轮挂驱动，其他有有效半径的轮子也可由内容包显式配置驱动。

### 5.2 控制量

- `speed`：车体局部前向速度，`speed = -localVel.z`，与 `CarControllerSubsystem` 同口径。
- `bodyYawRate`：车体局部 Y 角速度，`body.getAngularVelocityLocal(null).y`。
- `actualSteering`：座椅转向输入的平滑值，范围 `-1..1`。
- `x_i`：主动轮连接器 `offsetFromMassCenter` 换算到控制器车体局部 X，再减去全部绑定均值：

```text
x_i = localX_i - mean(localX_j)
B   = max(x_i) - min(x_i)
```

- `v_base`：
  - 单流：前进取 `max(v_i)`，倒车取 `min(v_i)`；统计全部有效驱动轮，包含断带侧和未铺履带的轮子；没有有效驱动轮时退回车体 `speed`；`|v_base| < 0.5` 时单流不转向。
  - 双流：取各履带线速度均值（主路基础速度）。
- `maxYawRate(speed)`：静态速度表给出基础上限；再受侧向加速度和最小转弯半径限制：

```text
maxYawRate = min(
    table(|speed|),
    maxLateralAcceleration / max(|v_base|, 0.5),
    |v_base| / minTurningRadius
)
```

- 单流 `v_base ~ 0` 时 `maxYawRate = 0`，不能中心转向；双流在 `|v_base| < pivotSpeedThreshold` 时改用 `pivotYawRate`，允许零速中心转向。
- `r_des` 与横摆 PD：

```text
r_des   = actualSteering * maxYawRate
r_error = r_des - bodyYawRate
r_cmd   = clamp(r_des + yawP * r_error + yawD * d(r_error)/dt, -maxYawRate, maxYawRate)
```

- 不使用积分项；饱和时由 `r_cmd` 的钳位自然限制，避免积分 windup。
- `v_i^des`：

```text
v_i^des = v_base + r_cmd * x_i
```

- 符号链：
  - 车体局部 `+X` 为右、`+Y` 为上、前方为 `-Z`；
  - `bodyYawRate > 0` 对应左转；
  - `x_i > 0` 的履带在左转时获得更大的前向速度；
  - `v_i = v_base + r * x_i` 与 `TrackDrive` 的 `feedback = -ω_x`、`GearJoint` 的负比值在同一条符号链上；首次实机验证时同时检查前进/倒车/左右转。
  - 转向输入映射到横摆角速度：同一 `actualSteering` 在前进与倒车下给出同一偏航方向。若后续需要汽车式倒车反打，增加静态开关，不在第一版。

### 5.3 单流分配（制动差速）

没有转向电机/转向传动时：

```text
前进: v_i^ach = clamp(v_i^des, 0, v_base)
倒车: v_i^ach = clamp(v_i^des, v_base, 0)

brake_i = max(
    actualBrake,
    clamp(|v_base - v_i^ach| / max(|v_base|, 0.5), 0, 1)
)
```

- 前进时外侧履带的 `v_i^des >= v_base`，钳到 `v_base`，制动 0；内侧履带按差值制动。
- 倒车时区间为 `[v_base, 0]`，外侧是更负的一侧；公式取绝对值，前进/倒车共用。
- 制动上限由每个 `TrackDriveSubsystem` 的 `max_brake_torque` 决定；控制器只发归一化 `brakeControl`。
- `handBrakeControl` 单独发送，驱动用 `max_hand_brake_torque` 施加；手刹不参与差速分配。
- 单流正常驾驶使用 `clutchEngagement = 1`，差速由内侧制动完成。离合断开属于明确的离合命令或控制失效保护（§8.4），履带断带 / 解散不改变离合目标。
- 饱和处理：
  - 实际横摆率由 `bodyYawRate` 反馈；`r_cmd` 钳位后不累积；
  - 若 `|r_cmd|` 达到 `maxYawRate` 且 `|bodyYawRate| < |r_des|`，说明制动已饱和，保持钳位，不提高 `r_des`；
  - `v_base ~ 0` 时单流没有转向权限，`r_des = 0`。
- 断带后的驱动控制与完整履带共用本节分配。主动轮继续参与 `v_base` 与差速分配，未配置驱动的负重轮自由滚；单侧断带后按 W，主动轮旋转和车辆偏航属于预期响应。转向几何只按有效驱动轮计数（见 §5.5），不按完整履带计数。

### 5.4 双流分配（转向电机 + 转向传动）

有转向电机/转向传动时：

```text
ω_steer_ref = r_des * x_ref / r_track
```

- 控制器向转向电机发送 `ω_steer_ref`（或对应的速度/油门命令）。
- `x_ref` 取 `max(|x_i|)`；两履带时即半轮距，四履带时取最外侧。
- 转向传动的 `power_outputs` 用 `x_ref / x_i`（带符号），把 `ω_steer_ref` 变成每条履带的转向分量：
  - 两履带：`+1 / -1`；
  - 四履带：`+x_ref/1.5, +x_ref/0.5, -x_ref/0.5, -x_ref/1.5`。
- `TrackDriveSubsystem` 把主路 `MechPower` 与转向路 `MechPower` 求和，得到最终 `ω_i`、`τ_i`。
- 双流时制动用于停车 / 紧急制动；正常转向靠转向功率流，履带断带本身不产生制动命令。
- 中心转向时 `v_base = 0`，主路输出为 0，转向电机提供全部功率；发动机/变速箱保持怠速或空挡，由控制器协调。
- `pivotSpeedThreshold` 与 `pivotYawRate` 是静态属性；单流不使用。

### 5.5 多履带

控制器不把履带分成“左/右”两组，而是逐条按中心化 `x_i` 处理：

- 每个驱动有 `x_i` 与 `r_i`；
- `v_i^des = v_base + r_cmd * x_i`；
- 四履带 `x = ±1.5, ±0.5` 时，四条履带得到四个不同的目标线速度；
- 单流：内侧两条按各自差值制动，外侧两条保持 `v_base`；
- 双流：转向传动的比值按 `x_i` 分配，四条履带同时得到正确的转向分量；
- 控制器的横摆反馈仍取车体 `bodyYawRate`，不按履带平均。
- `B = max(x_i) - min(x_i)`；`B < 0.1` 或有效驱动轮少于 2 个时视为没有转向几何，`r_cmd = 0`。有效性依据 §5.1，履带完整性不参与判定。

### 5.6 履带关系与驱动资格

控制器和驱动器的绑定、功率通路、离合及制动计算不读取 `TrackLink` 状态。轮半径由 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/SubPart.java#getMaxWheelRadius` 提供，驱动有效性见 §5.1。

| 轮组状态 | 驱动与控制 | 物理结果 |
| --- | --- | --- |
| 完整履带 | 按驾驶输入驱动配置了 `TrackDrive` 的轮子 | `GearJoint` 把主动轮与负重轮耦合 |
| 履带断带 | 有效驱动轮保持功率通路，并参与速度统计与差速分配 | 轮组解除耦合；主动轮可旋转，未配置驱动的负重轮自由滚 |
| 未铺设 / 履带解散 | 有有效连接器和轮半径即可驱动 | 被驱动轮作为普通车轮与地面接触 |
| 履带修复 | 驱动继续按驾驶输入工作 | `TrackLink` 恢复轮组耦合与张力 |
| 连接器断开 / 轮子销毁 / 半径无效 | 该驱动禁用，退出统计与差速分配 | 按剩余有效驱动轮计算控制量 |

单侧断带时，按 W 可使两侧主动轮旋转；完整侧与断带侧的接地牵引不同，车体可产生偏航。断带本身不触发自动纠偏、强制制动、离合断开、扭矩降额或转向权限缩放。控制器不保证在非对称接地下直行，额外拖拽力不在本设计范围。

### 5.7 输出与信号

| 输出 | 目标 | 内容 |
| --- | --- | --- |
| 油门 | 发动机/主电机 | `actualThrottle`（基类共享） |
| 换挡/离合 | 变速箱 | `switchGear` / `setClutched`（基类共享） |
| `TrackControlSignal` | 每个 `TrackDriveSubsystem` | `brakeControl` / `handBrakeControl` / `clutchEngagement` |
| 转向命令 | 转向电机（双流） | 目标转速或油门 |
| 差速锁（可选） | 主传动 | 手动差速锁信号 |
| `vehicle_speed` | HUD/脚本 | 车体前向速度 |

- `TrackControlSignal` 走 `sendCallbackToListener` 逐个发送，避免广播串扰。
- `TrackDrive` 的 `getAcceptedChannels()` 返回 `control_inputs`，默认 `car_control`。
- 控制器的 `onPostPhysicsTick` 发送共享输出；`distributeDriveControl()` 在 `onPrePhysicsTick` 发送 `TrackControlSignal`。
- `TrackDrive` 的 `track_speed` / `track_force` 输出供 HUD/脚本使用；控制器可直接读取驱动方法，不依赖信号延迟。
- `TrackController.getTargetNames()` 返回 `control_outputs` 与 `speed_outputs` 的并集；`TrackDrive.getTargetNames()` 返回 `speed_outputs` 与 `force_outputs` 的并集。

### 5.8 线程

| 阶段 | 线程 | 内容 |
| --- | --- | --- |
| `onTick` | 主线程 | 控制组、输入、握手、速度输出、履带状态快照 |
| `onPrePhysicsTick` | 物理线程 | 横摆目标、混音、`TrackControlSignal` 计算与发送、转向电机命令 |
| `onPostPhysicsTick` | 物理线程 | 共享油门/刹车/手刹输出、HUD 信号 |
| 物理体操作 | 物理线程 | 仅经驱动的关节电机/制动，不直接改刚体 |

- 控制器与驱动不依赖遍历顺序；驱动晚一 tick 读取控制信号时，信号仍在频道中。
- 服务端负责物理驱动；客户端控制器/驱动可运行同一套计算，但客户端关节不求解，驱动不施加电机力。
- 控制器 / 驱动器只发布并读取驱动绑定与控制量，`TrackLink` 的成员更新和耦合生命周期由履带物理链路独立处理（物理文档 §7.1 / §7.2）。

### 5.9 失败模式

| 情况 | 行为 |
| --- | --- |
| 没有 `TrackDriveSubsystem` | 控制器不激活；不输出油门/制动 |
| 驱动连接器缺失/未连接 | 该驱动禁用；控制器按剩余驱动降级 |
| 被驱动轮销毁 / 半径非有限值或 <= 0 | 该驱动禁用；履带成员生命周期由 `TrackLink` 独立处理 |
| 被驱动轮属于履带负重轮 | 有有效半径即可按显式配置驱动；内容包作者负责安排动力输入 |
| 履带断带 / 解散 / 未铺设 | 有效驱动轮按驾驶输入工作，保留功率通路与差速分配资格 |
| 没有转向电机/转向传动 | 走单流制动分配；不能中心转向 |
| 制动饱和 | 保持 `r_cmd` 钳位；不累积积分；不继续提高 `r_des` |
| 转向电机堵转/功率不足 | 转向命令饱和；车体横摆误差由 PD 处理 |
| 履带修复 | 轮组恢复耦合与张力；驱动按驾驶输入工作 |
| 乘客离开/控制器失活 | 驱动收到默认制动信号；车辆保持停车 |

## 6. `TrackDriveSubsystem`

### 6.1 挂载与连接

`TrackDriveSubsystem` 是车体侧子系统：

- 挂在车体 `SubPart` 上；
- 动态属性 `connector` 指向车体—被驱动轮连接器（`AdvancedConnector`）；
- 被驱动 `SubPart` 是连接器另一侧的轮子；标准履带配置中该轮为主动轮；
- 只操作关节的滚动电机（axis 0），不碰转向轴；关节旋转顺序设为 `RotationOrder.XZY`，确保 axis 0 是滚动轴；
- 半径：`drivenSubPart.getMaxWheelRadius()`；
- 横向位置：由控制器读取 `connector.offsetFromMassCenter` 计算，驱动不提供 `lateralOffset()`；
- 不持有 `TrackLink`。

被驱动 `SubPart` 的几何接口只需提供有限正轮半径；普通车轮、主动轮以及内容包显式配置驱动的其他轮子使用同一驱动规则。控制器与驱动器均不检查该轮是否接入履带或是否为履带主动轮。

### 6.2 属性

静态属性（`TrackDriveSubsystemStaticAttr`）：

```json
{
  "type": "machine_max:track_drive",
  "basic_durability": 40,
  "control_inputs": ["car_control"],
  "max_drive_torque": 30000,
  "max_brake_torque": 20000,
  "max_hand_brake_torque": 20000,
  "max_speed": 120,
  "sounds": {}
}
```

| 字段 | 类型 | 默认 | 含义 |
| --- | --- | --- | --- |
| `basic_durability` | float | 40 | 子系统耐久 |
| `control_inputs` | list | `["car_control"]` | `TrackControlSignal` 读取频道，按优先级 |
| `max_drive_torque` | float | 30000 | 关节驱动扭矩上限（N·m） |
| `max_brake_torque` | float | 20000 | 服务制动扭矩上限（N·m） |
| `max_hand_brake_torque` | float | 20000 | 驻车制动扭矩上限（N·m） |
| `max_speed` | float | 120 | 主动轮角速度上限（rad/s） |
| `sounds` | object | 空 | 可选音效；第一版可只保留基础音效 |
| `sounds` | object | 空 | 可选音效；第一版可只保留基础音效 |

动态属性（`TrackDriveSubsystemAttr`）：

```json
{
  "type": "machine_max:track_drive",
  "definition": "machine_max:track_drive_heavy",
  "connector": "connector.machine_max.left_sprocket",
  "speed_outputs": { "track_speed": ["local", "global"] },
  "force_outputs": { "track_force": ["local", "global"] }
}
```

- `definition`：静态属性注册名。
- `connector`：车体侧连接点名。
- `speed_outputs` / `force_outputs`：信号输出目标；`track_speed` 单位 m/s（前进为正），`track_force` 单位 N（前进为正）。
- 实例级字段不包含 `max_*`、`control_inputs`；那些属于 `definition`。
- 驱动向上层提供 `linearMaxDriveForce()` / `linearMaxBrakeForce()` / `linearMaxSpeed()`（扭矩 / 半径、速度 × 半径），控制器做饱和判断。

### 6.3 多输入缓存

```java
private final Map<String, MechPower> received = new ConcurrentHashMap<>();

@Override
public void onMechPowerReceived(String producerName, MechPower power) {
    received.put(producerName, power);
}
```

- 每路 producer 缓存最近一次 `MechPower`；`MechPower` 不可变，`ConcurrentHashMap` 足够。
- 载具结构变化、传动断开或驱动重新装配时清空 `received`；下一物理 tick 由生产者重新下发。
- 离合断开时：
  - `isPowerPathConnected(producerName)` 返回 false，传动系统的反馈收集/功率分配排除该驱动；
  - `onMechPowerReceived()` 照常缓存，但 `onPrePhysicsTick` 不把该路计入汇合；
  - 重新结合时从缓存恢复，避免丢一帧。
- 生产者断开时下发 `MechPower.EMPTY`；汇合时跳过 `isEmpty()`。
- 缓存按 producer 名区分，不要求 producer 是“主路”或“转向路”。

### 6.4 汇合

```java
float omega = 0f;
float torque = 0f;
for (var entry : received.entrySet()) {
    if (!isPowerPathConnected(entry.getKey())) continue;
    MechPower p = entry.getValue();
    if (p == null || p.isEmpty()) continue;
    float speed = p.speed();
    omega += speed;
    torque += p.power() / Math.max(Math.abs(speed), MIN_SPEED_FOR_TORQUE);
}

torque = Math.clamp(torque, -maxDriveTorque, maxDriveTorque);
torque -= brakeControl * maxBrakeTorque;
torque -= handBrakeControl * maxHandBrakeTorque;

rollingMotor.set(MotorParam.MaxMotorForce, Math.abs(torque));
if (torque > 0) {
    rollingMotor.set(MotorParam.TargetVelocity, -Math.clamp(omega, -maxSpeed, maxSpeed));
} else {
    rollingMotor.set(MotorParam.TargetVelocity, 0);
}
```

- `omega` 是主路与转向路的叠加；符号由各路的 `MechPower.speed` 决定。
- `torque` 是各路扭矩的叠加；内侧负功率自然变成负扭矩，进入制动/反拖分支。
- 制动/手刹在汇合之后叠加，上限由该驱动静态属性决定。
- 负功率不是异常：转向时内侧功率为负，正是差速所需的反拖/制动。
- 与 `WheelDriverSubsystem` 的负扭矩分支一致：目标速度 0、最大力 `|torque|`。
- `clutchEngagement` 在 0~1 之间时按比例缩放驱动扭矩；`isPowerPathConnected` 用同一结合度判断。

### 6.5 反馈分摊

单输入直接返回实测转速。多输入使用实测总量按各 producer 最近一次输入转速的比例分摊：

```text
actual = 实测主动轮角速度（rad/s，前进为正）
S      = Σ speed_i        // 参与汇合的 producer
A      = Σ |speed_i|

if A < ε:
    fb_i = 0
else if |S| >= max(ε, 0.1 * A):
    fb_i = actual * speed_i / S
else:
    fb_i = speed_i        // 指令互相抵消，回退到指令分量
fb_i = clamp(fb_i, -maxSpeed, maxSpeed)
```

- 单输入时 `S = speed_1`，`fb_1 = actual`，退化为实测反馈。
- 正常多输入时 `Σ fb_i = actual`；每个 producer 看到的是自己路径的负载分量。
- 转向传动左右比值 `+1 / -1` 时，左右各自拿到自己的转向分量；乘回比值后平均不抵消。
- `|S|` 很小时（中心转向、主/转向指令互相抵消），回退到 `speed_i`，避免除零放大；此时 `Σ fb_i` 不保证等于 `actual`，但不会产生 NaN/无穷大。
- `fb_i` 钳位到 `[-maxSpeed, maxSpeed]`，防止小分母导致异常值。
- 不区分 `feedback_mode`，不标记主路/转向路；反馈规则只有这一条。

接口改动：

```java
// IMechPowerConsumer
default float getFeedbackSpeed(String producerName) {
    return getFeedbackSpeed();
}
```

调用侧：

- `IMechPowerProducer.collectFeedbackSpeeds()` 使用 `consumer.getFeedbackSpeed(getName())`；
- `TransmissionSubsystem.collectRawFeedbackSpeeds()` 与 `collectFeedbackSpeeds()` 使用 `consumer.getFeedbackSpeed(getName())`；
- `MechPowerPort` 转发 `getFeedbackSpeed(producerName)` 到本地消费者或对侧端口；
- `WheelDriverSubsystem` 使用默认实现，行为不变；
- `TrackDriveSubsystem` 覆盖带 producer 的版本；无参版本返回 `actual`。

### 6.6 离合与制动

`TrackControlSignal`：

```java
public record TrackControlSignal(
        float brakeControl,
        float handBrakeControl,
        float clutchEngagement
) {}
```

- `brakeControl`：0~1，乘以 `max_brake_torque`。
- `handBrakeControl`：0~1，乘以 `max_hand_brake_torque`。
- `clutchEngagement`：0~1，1 为结合；驱动内部可做斜坡，避免发动机反馈速度阶跃。
- `isPowerPathConnected()` 按目标离合状态判断；离合 0 时该路退出传动反馈，发动机只看到剩余履带。
- 制动/手刹上限逐驱动配置；控制器不需要全局制动上限。
- 第一版只使用一个离合；双流如果需要主/转向独立断开，再给 `TrackControlSignal` 增加 `steeringClutch`，不在第一版预置。

### 6.7 线程与失败模式

| 情况 | 行为 |
| --- | --- |
| `received` 写入/读取 | 物理线程；`ConcurrentHashMap` |
| 连接器未连接 | 驱动禁用；不输出电机力 |
| 被驱动 `SubPart` 销毁 | 驱动禁用；控制器降级 |
| 半径非有限值或 <= 0 | 驱动禁用并记录日志 |
| 履带断带 / 解散 / 未铺设 | 不触发驱动失效；按有效连接器、轮半径与驾驶输入工作 |
| 某路 `MechPower.EMPTY` | 跳过该路；其余路继续 |
| 离合 0 | 该路不计入汇合；`isPowerPathConnected` false |
| `omega` 为 0、`torque` 非 0 | 目标速度 0、最大力 `|torque|`；保持/制动 |
| `torque` 超过上限 | 钳位；控制器通过 `track_speed` 看到饱和 |

### 6.8 与 `WheelDriverSubsystem` 的关系

| 项 | `WheelDriverSubsystem` | `TrackDriveSubsystem` |
| --- | --- | --- |
| 挂载 | 车体，连接器指向车轮 | 车体，连接器指向主动轮/被驱动轮 |
| 关节轴 | 滚动 axis 0 + 转向 axis 1 | 仅滚动 axis 0 |
| 输入 | 单路 `MechPower` | 多路 `MechPower` 缓存与求和 |
| 反馈 | 单值实测转速 | 实测总量按输入转速比例分摊 |
| 控制信号 | `WheelControlSignal`（制动/手刹/转向） | `TrackControlSignal`（制动/手刹/离合） |
| 上限 | 单轮 `max_drive_force` / `max_brake_force` / `max_hand_brake_force` / `max_rpm` | 履带级 `max_drive_torque` / `max_brake_torque` / `max_hand_brake_torque` / `max_speed` |
| `TrackLink` | 不持有 | 不持有 |
| 用途 | 轮式转向轮 / 轮式滑移车轮 | 履带主动轮 / 轮式滑移车轮 |

- 两者共享的是“关节滚动轴 + `MechPower` + 实测反馈”这一层物理事实，不共享类型。履带的离合、手刹、多输入、按 producer 反馈都在 `TrackDrive` 内实现。
- `WheelDriver` 保持现有行为；不为履带增加模式字段或分支。

### 6.9 输出

`TrackDrive` 在 `onPostPhysicsTick` 输出：

- `feedbackSpeed`：实测角速度（rad/s，前进为正）；
- `linearSpeed()`：`feedbackSpeed * radius`（m/s），供控制器读取；
- `track_speed`：`feedbackSpeed * radius`（m/s）；
- `track_force`：`driveTorque / radius`（N，前进为正；制动扭矩不计入驱动力的语义）；
- `linearMaxSpeed()` / `linearMaxDriveForce()` / `linearMaxBrakeForce()` 供控制器读取。

控制器直接调用方法读取，信号输出供 HUD/脚本使用。

### 7.1 接口改动

调用侧改动：

  ```java
  result.put(entry.getKey(), consumer.getFeedbackSpeed(getName()));
  ```
- `TransmissionSubsystem.collectRawFeedbackSpeeds()` 与 `collectFeedbackSpeeds()`：
  ```java
  consumer.getFeedbackSpeed(getName())
  ```
- `MechPowerPort`：
  ```java

      if (resolvedLocalConsumer != null) {
          return resolvedLocalConsumer.getFeedbackSpeed(producerName);
      }
      // 沿 attachedConnector 委托，保持现有循环保护
  }
  ```
- `WheelDriverSubsystem` 使用默认实现，行为不变。
- `TrackDriveSubsystem` 覆盖，返回 §6.5 的分摊值。

### 7.2 主传动

- 用现有 `TransmissionSubsystem`。
- `power_outputs` 全部 `1.0`，每个履带驱动一个输出：

```json
{
  "power_outputs": {
    "subsystem.machine_max.left_track_drive": 1.0,
    "subsystem.machine_max.right_track_drive": 1.0
  }
}
```

- 主传动把基础速度/功率等分给各履带驱动；`diff_lock` 用 `false` 或高阈值 `auto`。
- 主传动的反馈是各驱动主路分量的平均，等于基础速度。
- 单流时内侧制动，主传动仍向两侧输出；开放差速允许内外侧转速差。

### 7.3 转向传动

- 同样用现有 `TransmissionSubsystem`。
- `power_outputs` 用带符号的 `x_ref / x_i`：

```json
{
  "power_outputs": {
    "subsystem.machine_max.left_track_drive": 1.0,
    "subsystem.machine_max.right_track_drive": -1.0
  }
}
```

- 两履带：`+1 / -1`，`x_ref = |x|`。
- 四履带（`x = ±1.5, ±0.5`，`x_ref = 1.5`）：

```json
{
  "power_outputs": {
    "subsystem.machine_max.left_outer_track_drive": 1.0,
    "subsystem.machine_max.left_inner_track_drive": 3.0,
    "subsystem.machine_max.right_inner_track_drive": -3.0,
    "subsystem.machine_max.right_outer_track_drive": -1.0
  }
}
```

- 转向传动建议 `diff_lock: false`（开放差速）。
- 控制器的转向电机命令 `ω_steer_ref` 进入转向传动；转向传动的比值把它变成每条履带的转向分量。

### 7.4 负比值的正确性

`TransmissionSubsystem` 对负比值的处理是确定的：

1. **输出目标速度**：
   ```text
   refSpeed = inputSpeed / ratio
   ```
   负比值把目标速度反向；`computeTargetSpeed()` 用 `direction = signum(refSpeed)` 处理符号，返回带符号的目标。

2. **输出功率**：
   ```text
   power = torque * ratio * |targetSpeed|
   ```
   比值为负的一侧，功率为负；负功率在履带驱动里变成负扭矩，进入制动/反拖。比值为正的一侧功率为正，驱动。两侧符号相反就是差速本身。

3. **反馈汇总**：
   ```text
   feedback = consumer.getFeedbackSpeed(getName()) * ratio
   ```
   左右输出的反馈都乘自己的比值：
   - 左：`+ω * (+1) = +ω`
   - 右：`-ω * (-1) = +ω`
   - 平均：`+ω`，不抵消。

   四履带时同理：`fb_i = ω_in * x_i/x_ref`，乘 `x_ref/x_i` 后都是 `ω_in`，平均 `ω_in`。

4. **功率与扭矩分配**：
   ```text
   P_i = torque_common * ratio * |targetSpeed| = torque_common * |inputSpeed|
   τ_i = P_i / |ω_i| = torque_common * |ratio|
   ```
   其中 `torque_common` 是 `distributeOpenDiff` 的公共输出扭矩。比值绝对值更大的履带得到更大扭矩、更低转速；比值绝对值更小的相反。这是转向差速的合理分配。

**结论：** 负比值不是异常输入，是转向传动的正常表达方式；反馈不会抵消，功率符号相反是差速所需。

### 7.5 转向功率源

| 方案 | 主路 | 转向路 | 转向速度独立 | 备注 |
| --- | --- | --- | --- | --- |
| 引擎 + 电机 | 引擎→变速箱→主传动 | 电机→转向传动 | 是 | 第一阶段双流方案；复用 `MotorSubsystem`/`TransmissionSubsystem` |
| 引擎 + 可控分动箱 + 双传动 | 引擎→分动箱→主传动 | 分动箱→转向传动 | 否，随发动机转速 | 固定比转向传动的速度是 `发动机转速/传动比`；低速转向弱 |
| 引擎 + 分动箱 + 可变比转向传动 | 主传动 | 液压/可变比传动 | 是 | 接近双流从零件搭出；需要新的可变比传动 |
| 专用双流子系统 | 内部 | 内部 | 是 | 本文用主传动 + 转向传动 + 多输入驱动替代 |

- 分动箱只分配功率/扭矩，不分配速度。固定比转向传动的转向速度仍随发动机转速。
- 第一阶段双流采用“引擎 + 电机”：主路和转向路反馈天然分开，中心转向时电机自己带负载。
- 单引擎机械双流作为后续选项：需要可控分动箱 + 可变比转向传动；固定比传动不足以让转向速度独立。

### 7.6 四履带示例

以四条履带、`x = ±1.5, ±0.5`、`x_ref = 1.5` 为例：

| `x_i` | 转向传动比值 | 转向目标速度 | 转向扭矩 |
| --- | --- | --- | --- |
| `+1.5` | `+1.0` | `+ω_steer` | `τ_steer` |
| `+0.5` | `+3.0` | `+ω_steer/3` | `3τ_steer` |
| `-0.5` | `-3.0` | `-ω_steer/3` | `-3τ_steer` |
| `-1.5` | `-1.0` | `-ω_steer` | `-τ_steer` |

- `x_i` 的正负对应两侧；`+1.5` 与 `+0.5` 是同一侧的外/内位置。
- 线速度：`v_i = v_base + ω_steer * x_i * (r_track/x_ref)`，与 `x_i` 成正比；
- 功率：每条履带的转向功率等分（符号由比值给出）；
- 反馈：每条履带返回 `ω_steer * x_i/x_ref`，乘回比值后都是 `ω_steer`，平均不抵消；
- 单流时没有转向传动，内侧两条按 `v_i^des` 制动，外侧两条保持 `v_base`；不能中心转向。

### 7.7 由现有传动组合表达双流

本设计用“主传动 + 转向传动 + 多输入履带驱动”的组合表达双流：

- 转向几何在转向传动的 `power_outputs` 比值里，内容包作者可直接看到；
- 履带驱动只做多路求和，不判断主/转向；
- 不需要 `TrackSteeringTransmissionSubsystem`；
- 单流是同一套组合去掉转向电机/转向传动；控制器按执行器存在性选择分配方式。

1. 完好、对称轮组在对称接地的直行工况下，左右履带线速度差在容差内；
2. 转向时内外侧速度符号/大小符合 `v_i = v_base + r*x_i`；
3. 单流载具不能中心转向；双流可以；
4. 四履带的速度分布与 `x_i` 成正比；
5. 驱动资格由有效连接器、存活轮子与有限正半径决定；断带 / 未铺设 / 解散不切断驱动，单侧断带后的偏航由物理求解产生；
6. 多输入反馈不因左右符号抵消而失稳，且 `Σ fb = actual`（正常驾驶区间）；
7. 不引入网络载荷；客户端只消费既有物理同步；
8. 轮式 / 摩托车通过 §4.5 的油门 / 刹车 / 换挡 / 漂移 / 倾斜回归验收。

## 10. 设计取舍

### 10.1 独立 `TrackDriveSubsystem`，而非复用 `WheelDriverSubsystem`

- **本设计**：履带驱动独立，承载多输入、离合、手刹、按 producer 反馈；`WheelDriver` 保持轮式语义。
- **备选**：给 `WheelDriver` 加 `isTrack` 模式或继承它。
- **选择理由**：履带需要“多路功率 + 离合 + 按 producer 反馈”，轮式需要“转向伺服 + ABS + 单路功率”；塞进同一类型会让两套语义互相污染，后续拆分的迁移成本高于直接独立。

### 10.2 基类抽取，而非 `TrackController` 复制 `CarController`

- **本设计**：`AbstractGroundControllerSubsystem` 收共享输入/动力/换挡/握手；`Car`/`Track` 只保留差异。
- **备选**：`TrackController` 复制 `CarController` 的共享逻辑。
- **选择理由**：两套控制器共享的发动机/变速箱/油门/换挡逻辑量大；复制会在修 bug 时产生分叉。基类抽取有一次性回归成本，但边界清晰。

### 10.3 实测反馈比例分摊，而非反馈模式

- **本设计**：实际总转速按输入转速比例分摊；单输入退化为实测；`S ~ 0` 回退到指令。
- **备选**：`command` / `measured_total` / `measured_residual` 三种模式。
- **选择理由**：模式需要额外标记 producer 角色，配置复杂且容易与内容包不一致；比例分摊只用一路实际值和各路指令，规则单一，发动机仍能看到负载。

### 10.4 不设 `mode`

- **本设计**：所有差速转向共用一套混音；执行器存在性决定单流/双流分配。
- **备选**：`TRACK` / `SKID_STEER` / `DUAL_FLOW` 等 mode 字段。
- **选择理由**：mode 与执行器能力重复，容易出现“mode 说双流但没有转向电机”的不一致；直接查询执行器更可靠。

### 10.5 横向位置中心化

- **本设计**：`x_i` 减全部驱动均值，`B = max - min`。
- **备选**：直接用质心/转向中心坐标。
- **选择理由**：差速分配只依赖相对位置；中心化消除车体局部原点偏移，二履带得到 `±B/2`，四履带得到对称分布。

### 10.6 单流不拆离合

- **本设计**：单流正常驾驶使用 `clutchEngagement = 1`，用内侧制动完成差速；断带 / 未铺设 / 解散状态与驱动离合独立。
- **备选**：内侧离合断开，让发动机只驱动外侧。
- **选择理由**：开放差速在离合断开后如何分配功率取决于 `TransmissionSubsystem` 的剩余输出集合，口径不稳定；制动分配更直接，也保留发动机负载反馈。

### 10.7 `Ground` 控制模式

- **本设计**：座椅沿用 `ControlMode.GROUND`，W/S/A/D 语义不变。
- **备选**：新增 `ControlMode.TRACK`。
- **选择理由**：履带与轮式共用同一套移动输入；新增模式只影响客户端门控，没有额外语义，反而需要同步维护两份 `ControlMode`。

## 11. 未决与后续

阶段 B 实现前需要收敛两项控制技术契约：§5.2 / §5.3 的单流速度分配应以外侧速度锚定，避免中心化公式经裁剪后把目标差速减半；§5.3 / §6.4 需要明确实测带速误差到制动力矩的闭环及驱动抵消规则，单纯从驱动扭矩中扣除固定比例制动不能保证达到目标带速。这两项属于实现设计修正，不涉及履带脱落后的行为选择。

1. **基类边界**：`AbstractGroundControllerSubsystem` 的最终成员表、`onActuatorDiscovered` 的签名、`ControlPreference` 哪些方法上移；需要在阶段 A 的代码评审中定稿。
2. **反馈分摊阈值**：`0.1 * A` 的经验值、`S ~ 0` 回退到指令还是按 `|speed|` 分摊、`maxSpeed` 钳位；需要纯数学测试 + 实机标定。
3. **`TrackControlSignal` 离合**：第一版一个离合；双流是否要主/转向独立断开，取决于转向电机能否在断开主路时独立工作。
4. **`TrackDrive` 静态属性**：`max_speed` 用 rad/s 还是 rpm、`max_*_torque` 的默认值、音效字段；需要内容包 schema 定稿。
5. **`v_base` 口径**：单流取外侧、双流取均值；四履带/非对称布局、倒车转向方向是否保持同一偏航方向，需要实机验证。
6. **断带物理边界（已定）**：解除轮组耦合与张力，主动轮按驾驶输入受驱动，未配置驱动的负重轮自由滚；额外拖拽力不在本轮范围。
7. **HUD**：`track_speed` / `track_force` 的显示位置、是否走 `global` 信号；第一版只输出信号，不做专用 HUD。
8. **驱动与履带耐久独立（已定）**：`TrackLink` 耐久与断带状态不参与驱动扭矩、离合和转向权限计算。
9. **四履带归一化**：`x_ref` 的取值、非对称履带布局、各主动轮半径不一致时的修正。
10. **制动热/能量/再生**：单流内侧制动耗散、双流转向功率、再生制动的建模深度。

## 附录 A：符号与公式

| 符号 | 含义 |
| --- | --- |
| `P` | `MechPower.power`（W） |
| `ω` | `MechPower.speed`（rad/s，有符号） |
| `τ` | 扭矩（N·m） |
| `v` | 履带线速度（m/s） |
| `r` | 主动轮/车轮半径（m） |
| `x_i` | 第 `i` 条履带的中心化横向位置（m） |
| `x_ref` | 转向比值的参考横向位置（m） |
| `r_des` | 期望横摆角速度（rad/s） |
| `v_base` | 单流外侧 / 双流均值的履带线速度（m/s） |
| `S` / `A` | 反馈分摊的输入转速代数和 / 绝对值和 |

核心公式：

```text
τ_i = P_i / max(|ω_i|, MIN_SPEED_FOR_TORQUE)
ω   = Σ ω_i
τ   = Σ τ_i
v_i = ω_i * r_i
v_i^des = v_base + r_des * x_i
转向传动比值 = x_ref / x_i
speed_out = speed_in / ratio
feedback_upstream = mean(feedback_i * ratio_i)
fb_i = actual * speed_i / Σ speed_j          // |Σ speed_j| 足够大
```
