# 控制分配：作动器 wrench 分配设计

**状态**：进行中；批量阻尼伪逆与批量钉界基线、纯数学测试和裸 Bullet 力学验证已实现。完整闭环飞控、真实作动器响应、可选平衡辅助与游戏接线尚未完成，落地坐标与验证结果见 §11.5。

**归属**：Machine-Max 的通用工具包，内核为 `src/main/java/io/github/sweetzonzi/machine_max/util/WrenchAllocator.java#WrenchAllocator`；ARMS-Core 与载具控制器作为调用方。本文路径以 Machine-Max 仓库根目录为基准，`../ARMS-Core/` 指同级机娘仓库。

> **本文是什么**：把「这一步我想要这样一份合力与合力矩」翻译成「每个作动器出多少」的那套机制。它是一条**纯函数**：输入是各作动器的雅可比列与界、分配目标、权重与正则化系数，输出是归一化控制量 `u`（油门 / 偏角）。不碰 `PhysicsSpace`、不需要活着的世界、不依赖载具类型——机娘与固定翼共用同一份解。
>
> **本文不是什么**：不写角色控制器的姿态自由度、落地处理、接触摩擦与速度语义（见 `../ARMS-Core/docs/角色控制器-刚体动力学方案.md` §4–§9）；不写气动模型本身（见该文 §10）；不写引擎允许什么（见 `../ARMS-Core/docs/角色控制器-刚体原型与引擎约束.md` §2–§12）。

**适用范围**：连续可调的推进器、舵面与姿控器件。过驱动载具在本文中指作动器存在冗余、同一份目标 wrench 可由多组控制量实现的载具；是否冗余取决于当前活行上的列相关性，不能只数器件。§5.2 的作动器代价决定冗余时如何分担，§5.1 处理出力饱和，§8 允许调用方约束自由度。虚拟作动器（§2.4）与平衡辅助（§5.3）是可选的游戏建模能力，通用分配不要求安装它们。

**工程目标**：服务游戏中的可用控制、物理可信与有界计算成本。允许分配误差与器件使用效率上的损失，不要求全局最优、最省能或所有可达目标都精确实现。必须保证指令有界、输出有限、实际施力遵守作动器模型，并通过典型配装与故障场景的裸物理测试确认可控性。首版采用阻尼伪逆与级联钳制；是否增加固定预算的修正，由 §11 的运动表现与性能读数决定。

## 1. 五类驱动，两个去向

分类判据是**控制器能不能命令它**——也就是这个力源有没有一个**可命令的致动器状态**：

| 类型 | 可命令量 | 力由什么决定 | 典型例子 |
| --- | --- | --- | --- |
| **推进器** | 出力（油门） | 指令，与速度、姿态**无关** | 喷射推进、悬浮 |
| **姿控器件** | 某一轴上的力或力矩 | 指令，与速度、姿态**无关**，而且**不经过力臂** | RCS、动量轮 |
| **接触型** | 落脚点选择 | 指令 + 接触状态（受摩擦锥限制） | 双足、轮足、履带 |
| **固定零件气动** | **无** | 完全由当前运动与姿态决定 | 机翼、机身、尾翼 |
| **舵面气动** | 偏转角 | 指令 + 动压 `q = ½ρv²` | 副翼、升降舵、方向舵 |

**有可命令量的一类进分配器，而且是同一个分配器。** 推进器、舵面、以及被当作减速板用的气动面**全部是同一件事**：各有一个可命令量 `u`，各对刚体贡献一份力与一份力矩。它们之间的差别只落在两份数据上——每个作动器的**界**（§2.2）与它的**雅可比列**（§3）——而不是落在几条不同的处理路径里。分配问题不区分器件的「类型」，只读这两份数据。

**姿控器件是唯一能只出力矩的一类。** 其余四类都靠"一份力再加力臂"产生力矩，因此力与力矩在它们的列里是绑在一起的（§4）；姿控器件按定义没有这份绑定，RCS 的力线过质心、动量轮的力恒为零。它因此是**六轴解耦**这句话在数据上的实现形态，也是唯一能提供纯力偶的器件——不可命令的纯力偶（反扭矩）属于同一形态，见 `../ARMS-Core/docs/角色控制器-刚体动力学方案.md` §8.2。数据形态、界的取法与"解耦是一句建模约定"的理由见 §2.4。

减速板因此不是单独一类，而是舵面的一个特例：可命令量同样是偏角，只是外形让它的雅可比列偏向沿来流方向的力而不是力矩。这件事由列自动表达，不需要类型标记。

接触型也产出一份力，但它的方向不是安装出来的——本体坐标系里没有「落脚点」这个量，写不出固定的列（`../ARMS-Core/docs/角色控制器-刚体动力学方案.md` §9.5），因此留在分配器之外。

**没有可命令量的一类去目标上的矢量减法。** 固定零件气动的力完全由当前运动与姿态决定，控制器无法支配它；环境已经把它给了刚体，于是控制器的任务是**减掉它**：期望净 wrench 减去这一份，剩下的才是作动器要凑的量（§2.1）。这个去向不是「另加一股力」，而是**同一个目标上的减法**；完整算式与三条路的对比见 `../ARMS-Core/docs/角色控制器-刚体动力学方案.md` §10.4、§10.6。

**「固定零件」与「舵面」按可命令量划分，不按外形或安装位置划分。** 同一片翼面，作为固定零件时装它就完全不参与控制、只被减掉；装上作动器后它就成为舵面。判据是那台作动器，不是那片翼面。

## 2. 作动器数据与分配目标

### 2.1 目标的语义

```
w_des    = 刚体的期望净 wrench（控制层的意图）
w_known  = 一切不由本控制器作动器提供、但已知的 wrench
           （固定零件气动、舵面 δ=0 基准项、重力、其它可测的已知扰动）
分配目标 w_alloc = w_des − w_known          ← 矢量减法
```

**`w_des` 的语义钉死为「刚体的期望净 wrench」**，否则这条减法无从写起：环境已经给了刚体的那一份必须先从目标里减掉，剩下的才是作动器要凑的量。

**`w_known` 是被减项，不是被遗忘项。** 施加的永远是各力源的实际力（`../ARMS-Core/docs/角色控制器-刚体动力学方案.md` §8.1 的单一施加点），`w_known` 只是从**需求**里预先扣掉，不会改变任何一份实际力的归属。

**为什么是减法而不是「在输出上再加一股抵消力」**：手工合力再 `applyCentralForce` 之后，**引擎不会替我们检查这个力作动器出不出得来**，因此加在输出上会凭空造力；而减去之后，这份需求会进入分配器的饱和判断，缺口与 windup 回退全都自洽。完整论证与反例见 `../ARMS-Core/docs/角色控制器-刚体动力学方案.md` §10.6。

### 2.2 各作动器的界

| 来源 | 界的形状 | 什么时候变 |
| --- | --- | --- |
| **推进器** | `u ∈ [0, 1]`（归一化油门，单侧） | 当前方向、力臂与满出力共同决定列；转动、变形、损伤、燃料可使其变化 |
| **舵面 / 减速板** | `u ∈ [−1, +1]`（偏角 / `δ_max`，双侧） | 形状配装期定死，模长随动压 `q` 缩放（§2.3） |
| **接触型** | 不进分配器 | §1 |

**两个端点都要给，而且不必对称。** 首版接受有限且满足 `u_min ≤ 0 ≤ u_max` 的静态幅值界，允许 `[0, 0]` 表示关闭的器件。`[0, 1]` 表示推进器只能推不能拉；零指令在界内，因此 `w_alloc = 0 ⟹ u_cmd = 0`（§7）。响应速度由分配之后的响应模型处理；若未来把速率限制折进本步界而使零不在界内，需要另行定义中立指令与零目标契约。

**界与雅可比列合起来才是能力。** 界说明「能推多远」，列说明「推一单位得到什么」。两者都按当前状态取，所以「舵面的能力随速度变」不需要任何特判——低速时它的列模长趋零，分配器自然不会用它（§3.1）。

### 2.3 从零件到作动器数据

一个**作动器**是「有一个可命令量、并对刚体贡献一份力与一份力矩」的对象。它对分配器只需要交出四样东西：

| 项 | 内容 | 从哪来 |
| --- | --- | --- |
| **可命令量 `u` 的界** | `[u_min, u_max]`。归一化后大多是 `[0, 1]`（油门）或 `[−1, +1]`（偏角 / `δ_max`） | 零件属性与当前状态，见 §2.2 |
| **雅可比列 `J_k`** | 该作动器的 `u` 变化一单位对合力与合力矩的贡献 | §3 |
| **作用点 `p`** | 世界作用点，用于算力臂 | 定位点的世界位姿 |
| **力函数** | `u → (p, F)`，代回复核要用（§7） | 该器件自己的模型 |

映射分三层，每层对应作动器的一类信息：

| 层 | 输入 | 输出 | 说明 |
| --- | --- | --- | --- |
| **位置 → 力臂** | 定位点的世界位姿 | 该点相对刚体质心的位移 `r = p − c` | 决定这份力**能产生多大力矩** |
| **姿态 → 方向** | 定位点的世界旋转 | 力在本体坐标系下的方向 | 决定这份力**落在哪一轴**，也决定雅可比列的方向 |
| **属性 + 状态 → 大小** | 零件属性（最大出力、响应时间、能耗）与状态（接触 / 动压） | 该作动器当前能出多大 | 决定 `u` 的界，也决定雅可比列的模长 |

**力臂 `r` 必须每物理步按实际位姿重算**，不能在配装期缓存。零件之间存在约束余量、损伤与相对运动，这与「安装朝向只在配装期算一次」不是一回事。

**界的来源分两种：配装期定死形状，运行期缩放。** 推进器的**方向**是配装期常数，**大小**不必是——推力包络随高度与空气密度、损伤、燃料变化。分配器只需要当前值，所以这一点不构成负担。舵面的界由**最大偏角** `δ_max` 在配装期定死形状，运行期**随动压 `q` 缩放**：

```
该作动器在某方向能出的力 = q 决定的比例因子 × ( 最大偏角下的力在该方向上的分量 )
```

**力矩的可达范围不能从力的范围导出。** 每个作动器的力矩是它的力与力臂的叉积 `(p − c) × F`，这套关系写在雅可比列里（§3.1），不是另一组独立的界。参考点全场唯一为刚体质心。

### 2.4 虚拟作动器：六根解耦的有界列

**姿控器件可以没有真实零件。** §1 那一类的数据形态允许它只由一条配装期声明构成——没有定位点、也没有随速度或姿态变的项，只有"哪一轴、多大"两项。这样的器件称为**虚拟作动器**：RCS 与动量轮各一类，都是**可选安装**的装备；装了就与其他作动器走完全同一条路，交出的就是 §2.3 那四样。

两类的列形状固定，这正是「六轴解耦」在数据上的含义：

| 器件 | 列 | 界 | 形状 |
| --- | --- | --- | --- |
| **RCS** | `[ d ; 0 ] · F_max` | `[−1, +1]` | 力矩三行恒零——力线过质心，力臂为零 |
| **动量轮** | `[ 0 ; ê ] · τ_max` | `[−1, +1]` | 力三行恒零——纯力偶 |

`d` 与 `ê` 取该轴的单位方向（三根列对应三个力轴，三根列对应三个力矩轴），作用点一律取质心，因此 §2.3 的力臂那一步退化为零向量，复核算式不变。六根列合起来块对角，互不耦合。

**「解耦」是一句建模约定，不是对真实 RCS 的描述。** 有安装位置的喷口必然同时出力与力矩，纯平移要靠成对喷口差动开火；虚拟作动器把这份等效直接写成"一轴一根列"，因此配装期那条声明里没有"喷口在哪"这一项。写成一根**双侧**列（而不是两根 `[0, 1]` 的单侧列）还有一条直接后果：分配器不会给出"两边对烧、净力为零"的解。

**动量轮的界不随状态变。** 它的转速视为无限：既不建模角动量饱和，也不建模卸载，也不计轮子自身的转动惯量与陀螺耦合。因此它的 `u` 不产生任何需要跨端同步的状态（§9 同步的只有 `u` 本身）。

**四样数据里的「力函数」对虚拟作动器退化为常值映射**：RCS 是 `u → (c, d·u·F_max)`，动量轮是 `u → (c, 0)` 外加固有的**直接力矩**项 `ê·u·τ_max`。直接力矩也可以由不可命令的力源提供：`../ARMS-Core/docs/角色控制器-刚体动力学方案.md` §8.2 的反扭矩就是这种形态。

**它按载荷进入分配问题，与推进器、舵面没有优先级差别**——`J` 里它就是一列。谁多干一点由 §5.2 的作动器代价决定：想让真推进器多承担姿态动作，就把动量轮那一列的代价调高（那是"谁来干"，不是"能不能干"）。

**本节的两类器件按连续量建模**（界 `[−1, +1]`），与 §7 排除的二值作动器（`u ∈ {0, 1}`）不是同一件事：前者是一根连续列，后者的可行集非凸。

**它与 §5.3 的平衡辅助是两件事**：虚拟作动器是**装上去的设备**，进 `J`、参与分配，可以任意超过该轴的强弱差；平衡辅助是**分配之后的补齐**，不进 `J`，上限由已装作动器的权限导出。

## 3. 雅可比 `J`：割线列

### 3.1 两类列的取法

**推进器按当前方向、作用点与满出力构造线性列。** 在一次求解内，力沿当前方向、大小与 `u` 成正比：

```
J_k = [ d ; (p − c) × d ] · F_max        d = 当前单位推力方向，F_max = 当前满油门推力
```

方向 `d` 与力臂 `r = p − c` 必须在同一坐标系。刚性安装且用本体系表示时它们可以保持；喷口偏转、关节运动、机体构型变化或世界系下的整体转动，都可能要求按当前物理位姿更新。`F_max` 同样取当前值以体现推力包络、损伤和燃料。上下文支持每步覆盖整列或只更新变化列（§11.6），不能将配装时的方向当作所有工况的常数。

**气动面的列只能数值求导，而它几乎免费。** 气动力函数的入参里**没有偏角**——偏角是通过定位点自身坐标系的旋转、改变局部来流角进入的（`src/main/java/io/github/sweetzonzi/machine_max/util/mechanic/DynamicUtil.java#advancedAeroForce`）。因此列这样取：

```
J_k = ( w(u_k = u_max) − w(u_k = 0) ) / u_max
```

**首版用正向界上的割线作单列近似。** 它在 `u = 0` 与正向 `u = u_max` 两点精确，不能据此推断负偏角端点也精确。`u_max = 0` 时不做除法：双向器件若只有负向权限，可取非零负端点建列；两端都为零时关闭该列。

**升力与阻力不能统一按偏角变号。** 例如增量力函数 `f(u) = (u, u²)`，正向割线是 `(1, 1)`，但负端点实际为 `(-1, 1)`，单列预测为 `(-1, -1)`。这说明模型误差可能包含方向错误，而不只是模长误差。首版允许采用这份近似，但正负偏角都须参加 §11 的力函数与闭环测试；实际施力必须用实际偏角代回原力函数（§7）。若表现不合格，再评估双侧近似或工作点差分，不以非线性最优求解作为前置条件。

**成本可以忽略，因为贵的那一步与偏角无关：**

| 步骤 | 成本 |
| --- | --- |
| 遮挡 `rayTest`（JNI 往返） | 每 tick 每个气动点**一次**，与偏角无关，求导时复用 |
| 力函数本体（`atan2` + 约 40 次浮点） | 每列多一次 |
| 射线方向随偏角转动的误差 | 遮挡半径默认 1.0 m，`δ_max = 25°` 时射线端点横移约 0.42 m；只在有零件落在这段距离内时才有影响，且误差是**乘性因子** |

上表是成本构成估算，不能据此认定总耗时已达标。力函数采样与环境查询在一次分配调用内复用，级联每轮只处理数值列；多载具和最坏迭代数的性能验收见 §11.3。

### 3.2 割线的实测精度

**截距与斜率是每拍重取的，不是配装期标定值。** `w_aero(0)` 与 `J_k` 都与偏角无关，但与**当前工况**有关，因此同样每物理步现算：

| 重算的输入 | 影响哪一部分 |
| --- | --- |
| 当前速度（气动场合含 `ω × r`，逐计算点） | 两者。它决定攻角，因而决定 `cl`、`cd` 与动压 `q` |
| 当前位姿（`p` 与坐标系朝向） | 两者。它决定力臂 `(p − c)`，也决定力的方向落回本体坐标系后是哪一轴 |
| 当前遮挡因子 | 列的模长。它是个乘性因子，与偏角无关，所以求导时复用 |
| 当前气动系数（损伤、构型） | 两者。翼面被打坏后 `cl` / `cd` 直接变，不需要另设「损伤模型」 |

**三遍力函数共用同一套输入，因此「重算」不会让三份数据互相矛盾**：截距用 `u = 0` 那一遍，割线用 `u = 0` 与 `u = u_max` 两遍之差，复核用实际 `u` 那一遍（§7 的链条）。每列需要额外的端点求值；实际耗时与环境查询的复用情况按 §11.3 测量。

**误差量级由该器件的力函数决定，只能实测。** 以气动面为例（系数取 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/attr/AdvancedAeroAttr.java#DEFAULT`、`V = 25 m/s`、参考投影面积 1.0 m²、`δ_max` = 25°，列模长 1118 N）：

| `δ` | 误差占列模长 | 误差绝对值 |
| --- | --- | --- |
| 0° | **0** | 0 N |
| 2° | 2.2% | 24.5 N |
| 5° | 4.8% | 53.4 N |
| 10° | 7.2% | 80.3 N |
| 12.5°（区间正中） | **7.5%** | 83.8 N |
| 15° | 7.2% | 80.5 N |
| 20° | 4.8% | 53.9 N |
| 25° = `δ_max` | **0** | 0 N |

这组正偏角样本的误差在采样两端为零、在区间中点取峰值，形状近似 `4t(1−t)`（`t = δ / δ_max`）。**7.5% 是该工况下的模型读数，不是负偏角、失速区或闭环稳定性的保证。** 游戏可以接受这一级别的近似，条件是实际出力遵守力函数，并在设定增益、响应滞后和步长下通过闭环测试。力函数形态与两个曲率来源见 `../ARMS-Core/docs/角色控制器-刚体动力学方案.md` §10.3。

## 4. 问题的形状

每个作动器**只有一个可命令量** `u_k`（推进器的油门、舵面的偏角），而它一次同时决定一份力与一份力矩。所以真实可达集不是「一个 3 维力盒加一个 3 维力矩盒」，而是 6 维 wrench 空间里由 `N` 条一维曲线张成的集合。

把每条曲线在当前工作点线性化，就得到一张矩阵：

```
列 k = 该作动器的 u_k 变化一单位，给刚体带来多少力与多少力矩
```

分配问题于是写成

```
J u ≈ w_alloc      J: 6×N（按 §8 可降维）    u: N 个可命令量
u_min ≤ u ≤ u_max  逐作动器的界（§2.2）
```

**这张矩阵保留同一作动器的力／力矩耦合。** 有界线性模型的可达集是 `{Ju | u_min ≤ u ≤ u_max}`，不是无界的整个列空间。解出的有界 `u` 给出一份模型内可实现的 wrench，但级联未必找到满足目标的那一组，非线性器件的实际出力也可能偏离 `Ju`。这些差额按 §5.1、§7 记录，不能把期望 wrench 直接当作已实现的力。

**这里没有「器件类型」这个概念。** 推进器、副翼、升降舵、减速板**都是列**。减速板不过是「力矩行小而力行大」的列，副翼是反过来的列。§6 说明为什么不需要给它们分类。

**推进器与舵面可以共用一个分配问题。** 低速与悬停时气动列趋零，推进器承担需求；高速时舵面参与分担，其比例由当前列与 §5.2 的代价共同决定。分配器无需按器件类型另设切换速度；列变化、钉界与作动器响应带来的输出变化是否平顺，由 §11.2 的跨工况测试验证。

**附带收益（一）：气动面的力变成已知量。** `u` 是分配的输出，因此该偏角下的气动力**是算出来的，不是预测的**——前馈一侧只需要承担 `u = 0` 的截距（`../ARMS-Core/docs/角色控制器-刚体动力学方案.md` §10.3）。

**附带收益（二）：控制量本身就是程序性动画要的那个量。** `u` 恰好是显示层的原始输入——推进器的 `u` 就是油门（尾焰大小、音效强度、粒子发射率），舵面的 `u` 乘以 `δ_max` 就是偏角（模型姿态）。三点具体好处：

| 好处 | 为什么 |
| --- | --- |
| **物理与动画同源** | 动画用的是分配器算出的那一个偏角，不是另按输入猜一个，因此不存在「模型显示 30°、物理用的是 18°」这种漂移 |
| **出力边界看得见** | 指令撞界可以作为诊断状态；实际尾焰与偏角由响应模型之后的 `u_actual` 驱动，因此能表现舵面转到极限所需的时间 |
| **诊断可可视化** | §5.1 的未满足需求与控制量一起显示，可以观察哪些方向没有完成；残差本身不证明作动器已经饱和 |

按 §6 的逐轴钳制做法，偏角需要从分配的力反解，还要处理同轴多面之间的分担。本分配器直接输出 `u_cmd`，响应模型产生 `u_actual`；实际施力与动画共用后者，不能只显示尚未执行的指令。跨线程与跨端通路见 §9。

## 5. 求解：阻尼伪逆

**首版采用阻尼最小二乘产生指令，再用 §5.1 的级联保证幅值边界。** 这是一种有界成本的近似分配，不承诺带界问题的全局最优。行缩放与作动器代价分别输入（§5.2）：

```
min ‖S (J u − w_alloc)‖² + λ² · uᵀ W u
S：m×m 正对角行缩放，m 为活行数，最多 6
W：N×N 正对角作动器代价，N 为作动器数
A = S J，b = S w_alloc
```

无界子问题用行空间形式求解：

```
u = W⁻¹ Aᵀ (A W⁻¹ Aᵀ + λ² I)⁻¹ b
```

**实现用 Cholesky 分解与前代／回代，不显式求逆。** 要分解的矩阵至多 6×6，全部用 `double`；首版不引入外置线性代数依赖。`W` 为正对角且 `λ > 0` 时该矩阵在实数运算下正定，数值实现仍须检查分解与结果的有限性。

**正则项在归一化后取值，并在一次级联调用内固定。** 建议起点：

```
λ² = max(λ_floor², ρ_reg · mean(diag(A W⁻¹ Aᵀ)))
ρ_reg 从 1e-4 起调；λ_floor 为归一化空间内的有限正数
```

`λ_floor` 与 `ρ_reg` 是可配置数值参数，初始值及可接受范围由 §11 的尺度与退化用例确定。固定本次 `λ` 后，各轮只更新自由列与剩余目标，避免因剩余列数改变而暗中改变正则强度。物理幅值界负责限制指令，不能把某条仅适用于无界、特定权重的范数估计当成整个级联的硬保证。

**退化与错误输入有明确出口：**

| 情况 | 处理 |
| --- | --- |
| 无活行 | 返回零指令；有效行上的残差为空，外部目标的死行由 §8 处理 |
| 无作动器、全部关闭或有效列全零 | 返回零指令，活行上的原始需求完整留在残差中，不做分解 |
| 零列夹在正常列之间 | 零列指令取零，其余列参与分配 |
| 所有列都已钉界 | 用已固定的指令重算残差并结束，不分解空系统 |
| 秩亏或列近乎重合 | 用固定正则项求解，指令须有限且在界内；不要求任意病态方向都能精确追踪 |
| 非有限输入、尺寸错误、非正缩放／代价、界不含零 | 在纯函数边界明确拒绝；调用方记录诊断并按器件的停机／响应规则处理，不能把无效值写进刚体 |
| 分解或结果出现数值失败 | 返回明确失败状态与有限零指令，报告相应未满足需求；调用方执行同一故障处理规则 |

**核心契约表**用于纯数学 JUnit；场景质量与性能按 §11 单独验收：

| 用例 | 验收内容 |
| --- | --- |
| 幅值与有限性 | 单侧、双侧、不对称及 `[0,0]` 界下，输出逐项合法、无 NaN／Inf |
| 零分配目标 | `w_alloc = 0` 时 `u_cmd = 0`；悬停的 `w_alloc` 通常非零，不能把“玩家没输入”当成该条件 |
| 无权限与秩亏 | 覆盖上表的空集、零列、全零、近共线及固定列耗尽情形，出口与残差符合定义 |
| 对称分担 | 两列、边界与代价相同时，指令在容差内相等；改变代价后只要求分担符合受控示例，不要求任意布局的逐项单调性 |
| 可控参考场景 | 正交、对称及选定冗余布局，在指定目标、正则强度与误差容限下达到预期，不断言所有可达目标都精确达成 |
| 不可达目标 | 指令守界，输出 `r_alloc = w_alloc − J u_cmd`，不能用期望值冒充实现值 |
| 行缩放与掩码 | 等价单位换算同时调整 `S` 后结果一致；相同有效行及固定 `λ` 下，删除死行与置零等价 |
| 耦合与已知量 | 同一 `u` 同时决定力与力矩；已知基准项只从需求扣一次，实际施力链不重复计数 |
| 级联局限 | §5.1 的批量反例须完整报告损失；逐个钉界等候选若实施，再与同一例及数十器件布局对照，不能断言任意配装都精确达成 |
| 确定性与预算 | 相同输入和列顺序得到相同输出；钉界轮数、分解次数及可选修正次数受显式预算约束 |

### 5.1 饱和处理：级联，不追最优

**当前基线一次固定所有越界项，然后对剩余列批量重算。** 对角代价使固定列的代价成为常数，自由子问题只需扣除固定列已经提供的 wrench：

```
① 对自由列求阻尼解；初始自由集排除关闭与零权限列
② 找出所有越界指令，各自钉在对应下界或上界
③ w_free = w_alloc − J_fixed u_fixed
④ 对剩余自由列重解；没有越界或自由列为空时结束
⑤ 用完整 J 与完整 u_cmd 重算预测出力、残差和撞界标记
```

每轮继续迭代至少固定一列，后续轮次基于剩余目标重算，已固定项在本次分配内不释放。关闭或完全无效的列预先固定为零。至多 `N` 轮钉界、至多 `N+1` 次无界子问题求解，空自由集直接结束。**这个上界保证计算会停，不保证找到了最好的有界分配。** 固定变量会收缩可选指令集合，不能声称“去掉列后可行集变大”或残差必定单调下降。

**已知可达反例必须纳入质量评估。** 三台单侧器件的二维列和目标为：

```
J = [ -2   2   1 ]       w_alloc = (-1.5, 0)
    [ -1  -1   2 ]       0 ≤ u_i ≤ 1
```

`u = (1, 0, 0.5)` 可以精确达成目标。取 `S=I`、`W=I`、`ρ_reg=1e-4` 且正则下限未主导时，初始无界解约为 `(0.300, -0.420, -0.060)`。该阶段允许反向使用 B、C，因而能用较小的控制量完成目标，但负油门不属于器件的实际能力。批量钉界会把 B、C 同时固定为零，最终约为 `(0.600, 0, 0)`，预测 wrench 约为 `(-1.200, -0.600)`，残差范数约 `0.67082`。

**逐个钉界是待比较的候选，不属于当前实现。** 在这个例子中，若先固定越界最严重的 B=0，立刻用 A、C 重算，无阻尼等式解为 `(1, 0, 0.5)`，采用小正则时接近该解。A 的方向与目标接近，但仅使用 A 会带出向下分量，C 的正向出力负责抵消它。初始无界解中某个器件为负，不表示在其它器件被限制之后它也应该关闭。该例解释基线的局限，不能据此认定逐个方法在数十器件场景下的质量和性能必然合适。

**是否接受这份近似，用运动表现决定。** 逐个钉界与批量钉界都不保证全局最优或所有可达目标都能达成；两者最坏钉界轮数均为 `N`，逐个写法可能增加实际分解次数。首版先对照典型配装的目标误差、方向偏差、故障响应与耗时。若出现影响操控的持续跑偏、能力浪费或抖动，再评估固定次数的解除钳制或残差修正；不要求无限迭代、全局最优或逐帧满足 KKT。固定布局与相同目标会重复产生相同分配，不能假定下一拍反馈必然消除偏差。级联遗漏可达目标的相关研究见 [NASA：Modified Cascading Generalized Inverse Control Allocation](https://ntrs.nasa.gov/api/citations/20220018474/downloads/AIAA_SciTech2023_Final.pdf) §I。

**可选的一阶最优性诊断只用于解释结果。** 对本文带正则、带行缩放的目标，完整梯度的半值为：

```
g = Aᵀ (A u_cmd − b) + λ² W u_cmd
下界处 g_i ≥ 0，上界处 g_i ≤ 0，自由项 g_i ≈ 0（数值上用容差）
```

不满足符号条件表示仍有可改进方向，不等于实现必然有 bug，也不强制触发重解。诊断不能漏掉固定列贡献或正则项；`g` 与正则系数 `λ` 使用不同符号。

**输出首先叫“未满足需求”，不统一归因为饱和。** 分配器输出 `u_cmd`、`J u_cmd`、`r_alloc = w_alloc − J u_cmd`、撞界标记与求解状态。`r_alloc` 可以同时包含幅值不足、几何不可达、正则化偏差和级联损失；实际执行链还会引入模型误差与响应滞后（§7）。防积分累积由调用方结合轴、方向和实际执行缺口处理，不能只凭残差非零就判定所有器件用满。

`w_alloc` 包含顶重力、顶阻力等正常配平需求；**只有目标减去预测／实际出力后的差额才是未满足需求**。调试输出应同时给出需求、实现量和撞界状态，区分正常配平与跟踪不足。

### 5.2 行缩放 `S` 与作动器代价 `W`

**两组参数分别表示“哪些误差更值得纠正”和“冗余时倾向使用谁”。** 首版都用对角数据，无需通用稠密权重矩阵：

| 参数 | 数据与含义 | 游戏例子 |
| --- | --- | --- |
| `S` | 每个活行一个有限正缩放；把 N 与 N·m 的误差归一化，并表达软优先级 | 悬停优先保高度与姿态，横向加速可以让步 |
| `W` | 每个作动器一个有限正代价；在冗余方案之间偏向较便宜的控制量 | 高速偏向舵面、减少喷口使用；或为表现效果偏向大喷口 |

可以用 `S_ii = priority_i / reference_i`，其中 `reference_i` 是该行的正参考力／力矩尺度；具体基准由调用方按质量、惯量、权限或容许误差选定（§10.1）。这是一组软权重，不承诺任何轴的严格词典序优先。正则系数在这份归一化之后确定（§5）。

`W_i` 较大表示该器件的努力较贵；它影响指令分担，也可能影响谁先撞界。不能只凭器件的归一化 `u_max` 判断饱和次序，列大小、目标、权重与其它器件都参与决定。首版只要求受控场景符合预期与整体运动可用，不要求所有布局下代价变化产生逐项单调的指令变化。

“推进器贵、气动面便宜”可以表达燃料、发热或美术偏好，但不是唯一正确的配置。低速时气动列趋零，昂贵的推进器也可能是唯一有用的器件；高速的实际分担与过渡平顺性通过 §11.2 测量。无需为了最省能引入额外最优控制层。

### 5.3 平衡辅助：分配之后的残差补齐

**平衡辅助是可选的游戏能力，首版通用内核不依赖它。** 只有斜向喷口的机体可能无法实现纯竖直动作；本节允许按明确预算额外提供一份力／力矩来改善操控。它是单独声明的供给，必须参与实际施力与记账，不能伪装成已装作动器的出力。

#### 逐轴、逐侧的预算

从已装的全部作动器（含 §2.4 的虚拟作动器）按当前有界线性列计算各轴边际权限，使用物理单位的 `J`，不乘行缩放 `S`：

```
A⁺_i = Σ_k max(J_ik · u_min,k, J_ik · u_max,k)
A⁻_i = Σ_k min(J_ik · u_min,k, J_ik · u_max,k)
强 = max(A⁺, |A⁻|)          弱 = min(A⁺, |A⁻|)
预算_弱侧 = k × (强 − 弱)     预算_强侧 = 0
w_辅助_i = clamp(r_alloc,i, −预算_i⁻, +预算_i⁺)
```

`u_min ≤ 0 ≤ u_max` 使每轴边际区间含零；上式覆盖单侧、双侧与关闭的器件。`预算_i⁺` 与 `预算_i⁻` 中只有弱侧非零，两侧相等时均为零。`k` 为抹平比例，默认 `0.5`，定义域 `[0,1]`；`k=0` 关闭辅助，`k=1` 使弱侧边际权限加预算等于强侧。超出对称预算的额外设备能力由 §2.4 的虚拟作动器表达。

虚拟作动器必须参与预算锚定：给弱侧加设备会缩小强弱差；两侧等量增加的设备不改变该差。逐轴边际只用于定义预算，不能说明多轴需求能否同时实现，也不能仅靠 `k` 保证所有配装的控制质量。§6 讨论了把逐轴区间当作整体可达集的局限。

#### 辅助改变哪些量

**强侧预算为零，只保证该轴强侧的残差分量不被辅助改动。** 弱侧也可能在某个目标下达到幅值极限，多轴耦合与级联损失又会混入残差；不能声称辅助只填几何缺口，或保留所有饱和缺口。

```
u_cmd = 级联分配(J, 界, S, W, λ, w_alloc)   真作动器与虚拟作动器一起解
r_alloc = w_alloc − J u_cmd                  原始分配残差，始终保留
w_辅助 = clamp(r_alloc, 逐轴逐侧预算)         单独记账的辅助供给
r_预测剩余 = r_alloc − w_辅助                 模型预测的剩余需求
```

| 报表量 | 含义 | 用途 |
| --- | --- | --- |
| `r_alloc` 与撞界标记 | 分配模型的未满足需求，可能含级联与正则化损失 | 配装期与求解诊断 |
| `w_辅助`、`r_预测剩余` | 辅助供给与预测剩余需求 | 辅助效果诊断 |
| §7 的 `r_actual` | 响应与实际力函数之后，计入实际辅助出力的未满足需求 | 调用方防积分累积与闭环诊断 |

#### 实际施力与表现

辅助按质心力与直接力矩处理，不占作动器控制量 `u`。它没有实体零件，默认不计工质；这是明确的游戏建模约定，而不是从真实硬件推导出的能力。启用时记录实际辅助出力，`k=0` 时该通道的出力必须为零。

已知气动力属于 §2.1 的 `w_known`，辅助属于额外供给，二者不能混入同一项或重复施加。相关角色施力记账讨论见 `../ARMS-Core/docs/角色控制器-刚体动力学方案.md` §10.6。

辅助使用与分配器同一张活行表（§8），死行预算为零。它没有 `u_actual`，若需要喷流等视觉效果，走独立的辅助表现通道。

## 6. 被取代的做法：按轴独立钳制

一种不引入任何线性代数的做法是：把每个力源的方向投影到体轴上逐轴求和，得到「各轴可用的力区间」，再把力的包络当成一个 3 维盒、力矩的包络当成另一个 3 维盒，各自独立钳制。写下来是因为它的三处代价**恰好就是本方案要消除的东西**，而且它们生效时都不报错。

**逐轴求和的形式**（本体坐标系）：

```
上限_i = Σ_力源 max(0, 方向_i) × 该力源可用出力
下限_i = Σ_力源 min(0, 方向_i) × 该力源可用出力
```

这两个量是**带符号的力**，不是出力的幅度；`方向_i` 是该力源推力方向在体轴 `i` 上的分量，取正取负由安装朝向决定。公式里只有 `max` 与 `min`，没有取绝对值、也没有下限截断，因此 `上限_i ≥ 0`、`下限_i ≤ 0` 由构造保证：

| 该轴上装了什么 | 方向分量符号 | 可用区间 | 说明 |
| --- | --- | --- | --- |
| 正反向各一组 | 两种符号都有 | `[−a, +b]`，`a, b > 0` | 双向下限非零，**这是唯一有意的非零下限情形** |
| 只有正向 | 全为正 | `[0, +b]` | 下限为零 |
| 只有反向 | 全为负 | `[−a, 0]` | 上限为零 |
| 没装 | 无项 | `[0, 0]` | 上限下限同时为零 |

**下限为零的含义是「该轴没有反向驱动能力」，不是「出力关不掉」。** 区间以零为一个端点，恰好说明零出力永远可达（不点火）；推力不可反向的推进器**不会**表现为非零下限，它只往一侧贡献，另一侧的界就是 0。这条语义在分配器里以「`u = 0` 永远在界内、且 `w_alloc = 0 ⟹ u = 0`」的形式保留（§2.2、§7）。

**三处代价：**

| # | 代价 | 为什么 |
| --- | --- | --- |
| 1 | **力的方向自由** | 按轴分解之后，单个机构的实际力矢量允许与安装方向或可达曲线不同。舵面比推进器严重——它的可达集是一维曲线，连盒的角点都不可达。模型因此「比真实机构更能干」 |
| 2 | **形状近似** | 逐轴求和与真实可达集的形状无关。**斜装是触发点**：一台方向为 `(0.3, 0, 0.95)` 的推进器会把上下界同时抬高一截，而它的真实贡献只是一条一维线段；逐轴求和把它铺成了二维或三维区域。最坏情况的系统性高估是体对角上的 `√3 ≈ 1.73`。纯正交安装（`±X` / `±Y` / `±Z` 各就各位）时两条代价都不产生误差 |
| 3 | **力与力矩的耦合不建模** | 同一次分配同时决定 `ΣF` 与 `Σ(r×F)`，两者可能冲突，而独立钳制会悄悄牺牲其中一方，**没有任何地方报告这个冲突**。若力矩由引擎从作用点导出，`Σ(r×F)` 的相消关系会自动成立；本方案手工算力矩，所以相消必须显式保留 |

**为什么最终不采用它**：这三处代价都不是数值误差，而是**模型与真实能力不一致**，并且都在静默生效——高估只表现为收敛比模型预测的慢，冲突只表现为某个轴悄悄不到位。修掉它们必须在 wrench 空间里描述可达集，那正是 §4 的那张 `J`。而「各作动器的方向、满出力、最大偏角、力函数」这些数据在两种做法里都要准备，**引入分配器只多一个 6×6 求解器，却省掉整套逐轴盒的合成、合并与钳制规则**。此外它还省掉一步：这条路分配出来的是**逐轴力**，每个作动器的偏角要从力反解，而且同轴多面之间有剩余自由度、得再定一条分担规则；分配器直接输出 `u`（§4 附带收益二）。

**相关的一条做法：按主/副输出给气动面分类。** 给每个气动面标一个类型，让它的「副输出」（控制面的阻力增量、减速板的力臂力矩）换一条通道走前馈，主输出进控制力。它在动力学上不重不漏（`F` 与 `τ` 出自同一个 `δ`，分开送进两条通道后相加仍等于真实值），代价是**配装期负担 + 配错即静默失效**：把控制面配成减速板，它的力矩会被前馈预先抵消掉，副翼推不动飞机，而且不报错。分配器里没有「主输出/副输出」这个概念——一片舵面的力与力矩由同一个 `u` 一起产出，不存在「哪一半算控制力」，因此那个配置字段与配套的配装期校验都不需要。

## 7. 混合作动器与代回复核

单侧与双侧的界共存于同一个控制向量，钉界记录具体上下界。可选梯度诊断按 §5.1 的上下界条件判断，不按器件名称猜测符号。

**零分配目标产生零指令。** 首版幅值界含零（§2.2），`W` 为正对角且 `λ>0`，因此 `w_alloc=0 ⟹ u_cmd=0`。它不保证有响应滞后的 `u_actual` 立即归零，也不表示悬停无需点火；重力等基准项使悬停的 `w_alloc` 通常非零。

**分配输出是指令，实际施力取决于执行状态。** 完整链条为：

```
u_cmd → 作动器响应模型 → u_actual → 器件自己的力函数 → 实际 wrench
```

物理可以接受分配预测有误差，但必须按实际状态计算力与作用点，保留力臂力矩。调用方可逐器件施加，或先统一坐标与质心后汇总施加；同一份力不能同时走两条路径。有限响应、非线性与损伤都不能被“按期望 wrench 补齐”的隐式力覆盖。动画同样使用 `u_actual`（§4、§9）。

**预测残差与实际未满足需求采用相同的增量口径。** 舵面零偏角基准已在 `w_known` 中计入，因此实际作动器增量要扣去该基准：

```
w_actual_inc = 实际器件完整 wrench − 已计入 w_known 的器件基准
r_alloc  = w_alloc − J u_cmd
r_actual = w_alloc − w_actual_inc − w_辅助实际
```

`w_辅助实际` 在辅助关闭时为零。`w_actual_inc` 由实际控制量与力函数计算，是当前施力模型的执行量，不是对引擎积分结果的精确测量；碰撞等未建模扰动由闭环场景验证。防积分累积由调用方结合 `r_actual`、误差方向与撞界状态处理，纯分配器不持有积分器状态。

二值作动器（`u∈{0,1}`）不属于首版连续分配范围。接入前须单独选择 PWM 等效或独立调度；连续的 50% 指令不能直接当成二值设备的实际状态。该扩展边界登记在 §10.2。

## 8. 分配问题的维度

**分配问题的行 = 引擎实际接受的 wrench 分量。** 引擎不接受的分量不该进目标。把它们留在问题里会让分配器把作动器权限花在无效方向上，而且残差会报出一个**并不存在的有效行需求缺口**——残差是 windup 保护的输入（§5.1），这个谎会被用上。角色控制器侧哪些分量不被接受、由什么门控，见 `../ARMS-Core/docs/角色控制器-刚体动力学方案.md` §8.3、§9.4。

**行集合由调用方给出。** 分配器只收一个行掩码（或等价地，一张「力 3 行 + 若干力矩行」的表），它不知道掩码是怎么来的：

```
活行 = { 力 x, 力 y, 力 z } ∪ { 力矩 i | 掩码_i ≠ 0 }
```

**降维与置零掩码的等价以相同数值参数为前提。** 用 §5 的 `A=S J`、`b=S w_alloc` 表达，死行置零后只在 `A W⁻¹ Aᵀ + λ²I` 中留下 `λ²` 对角元，对应右端为零，不影响指令。直接删除死行可以减少分解维度，例如角色地面状态为 4 行（`../ARMS-Core/docs/角色控制器-刚体动力学方案.md` §9.4）。比较两种写法时必须使用同一有效行缩放和同一 `λ`；不能因补入死行改变 §5 正则项均值的分母。求解后残差只对活行有控制意义。

死行上的需求不参与分配，权限用于活行。比如锁住 pitch 时，偏心推进器的 pitch 分量由调用方的自由度约束处理，分配器只追踪实际允许的行。

**地面 yaw 行的权限范围要写清。** 它只覆盖作动器能提供的那部分（偏心力源的力臂力矩）。机娘的转向能力还来自**落脚点选择**，而接触型在分配器之外（§1），所以**分配器不管走路转向**。

**切换瞬间的指令阶跃**，两个方向不对称：

| 方向 | 后果 | 由什么吸收 |
| --- | --- | --- |
| **收行**（6 → 4） | 需求本来就在趋零 | 角色控制器的落地摆正已经把 pitch / roll 的力矩需求往零收敛，**「先摆正、后降维」是自然顺序，不需要额外过渡逻辑**（`../ARMS-Core/docs/角色控制器-刚体动力学方案.md` §5.1、§5.3） |
| **放行**（4 → 6） | 两行突然出现，分配器第一次能命令 pitch / roll 力矩 | 由调用方的飞行控制层吸收：PD 属它，角加速度必须限幅（`../ARMS-Core/docs/角色控制器-刚体原型与引擎约束.md` §7.2）。**但控制层必须知道当前行表**，否则它在什么维度上工作都是猜的 |

**死行上出现非零分量有两种来源，处置完全不同**：

| 来源 | 例子 | 处置 |
| --- | --- | --- |
| `w_des` 在死行上非零 | 地面上控制层还在要 pitch 力矩 | **上层搞错了**，应当断言或记日志 |
| `w_known` 在死行上非零 | 地面上一片机翼的升力在质心上方产生 pitch 力矩 | **正常，静默丢弃**——引擎也会吃掉那份力矩，所以它既进不了刚体、也不需要被抵消 |

**平衡辅助（§5.3）在死行上不给预算。** 它不设独立的允许行掩码，读的就是这张行表；死行上的处置与上面 `w_known` 那一行同族——引擎会吃掉那份力矩，而辅助把它算进已补齐的量就会谎报缺口（§5.3 的第二行报表）。

## 9. 跨线程与跨端

**`u` 要跨线程、也大概率要跨端。** 分配器在**物理线程**上跑，而程序性动画（§4 附带收益二）在客户端渲染侧。通路：

```
物理线程：解出 u  →  不可变快照  →  主线程  →  同步给客户端  →  动画消费
```

三件事要一起定：

1. **不要跨线程直接读写。** 调用方把 `u_cmd`、`u_actual`、作动器标识与残差发布为不可变快照，主线程读取快照；分配器不持有世界、网络或动画对象。ARMS-Core 的物理线程 → 主线程出口实例见 `../ARMS-Core/src/main/java/io/github/sweetzonzi/arms_core/common/control/MechaControl.java#LogicStateSnapshot`。
2. **同步频率不必跟物理步。** 动画要的是平滑过渡，不是 100 Hz 的原始序列：可以按较低频率发实际控制量 `u_actual` 并在客户端插值，也可以只发已经归一化的「油门」与「偏角」两组量。
3. **同步接线由调用方负责。** 载具接入时选用 Machine-Max 的同步通道，并定义作动器标识与配装变化时的映射；ARMS-Core 接入时可使用 `SynchedEntityData` 或载荷字段，其 `EntityDataAccessor` 只能在末尾追加，改动字段表或载荷字段须同时提升 `../ARMS-Core/src/main/java/io/github/sweetzonzi/arms_core/network/ARMSNetwork.java#PROTOCOL_VERSION`。这条 ARMS-Core 协议约束不属于纯函数接口。

1. **舵面负偏角与失速区的模型质量**：先测实际方向误差、输出抖动与闭环运动，再决定是否需要双侧近似、差分、滤波或偏角范围限制。模型形态见 `../ARMS-Core/docs/角色控制器-刚体动力学方案.md` §10.1、§10.3。
2. **遮挡复用误差**：端点采样复用环境查询，检验邻近零件是否造成明显误差；不能把估算耗时当作实测性能。相关尺度调查见 `../ARMS-Core/docs/角色控制器-刚体动力学方案.md` §12.6。
3. **响应模型与闭环参数**：按器件选择速率限或一阶响应，记录步长与增益。单拍分配误差不自动构成闭环稳定性结论；角色气动时序见 `../ARMS-Core/docs/角色控制器-刚体动力学方案.md` §10.2。
4. **级联修正预算**：只有场景中出现影响操控的跑偏、能力损失或抖动，才评估固定次数的释放／残差修正；修正必须纳入性能对照。

### 10.3 虚拟作动器的量级

**式子定了，数值没定。** §2.4 只规定列的形状与界的形式，`F_max` / `τ_max` 取多大还没有依据。要定的是两件：

1. **量级基准**：按机体的加速度给（"该轴权限 = `m × a_辅助`，`a_辅助` 是一个配置的加速度"），还是按真作动器权限的一个比例给。前者与机体尺度挂钩，后者与美术挂钩——按美术那一条会让"喷口强的机体辅助也强"，与 §5.3 的锚定同源。
2. **代价挂在哪**：本节的设计不计工质也不计质量，因此虚拟作动器是**免费的权限**。若要它有代价，两个钩子的效果不同——`F_max` / `τ_max` 是配装期属性，改它改的是"能不能干"；§5.2 的作动器代价 `W_i` 改的是"谁来干"。选哪个取决于要的是平衡还是手感。

**需要谁定**：与配装期数据一起定，量纲基准与 §10.1 的归一化基准是同一件事的两面。

**定了之后动什么**：§2.4 的 `F_max` / `τ_max` 取值、§5.2 的器件代价、§10.1 的行参考尺度。

## 11. 实施与验证

**批量基线内核与基础力学验证已落地，完整控制链按阶段推进。** 当前代码与结果见 §11.5；真实机型、舵面与网络接入不因内核测试通过而自动视为完成。

内核位于 `src/main/java/io/github/sweetzonzi/machine_max/util/WrenchAllocator.java#WrenchAllocator`。相关控制工具还包括 `src/main/java/io/github/sweetzonzi/machine_max/util/control/PDController.java#PDController` 与 `src/main/java/io/github/sweetzonzi/machine_max/util/control/PIDController.java#PIDController`。分配器不引用模组入口、世界、刚体或网络对象；调用方负责数据构造、响应与施力。依赖方向为 ARMS-Core → Machine-Max；角色接入阶段见 `../ARMS-Core/docs/角色控制器-刚体动力学方案.md` §11（P4）、§15。

### 11.1 纯数学内核

实现 §5 的归一化、阻尼求解、退化出口、级联与完整残差输出。以 §5 核心契约表组织 JUnit，包括正交、对称、斜装、近共线、空集、损坏与混合界。测试使用明确的坐标、单位、缩放与正则参数。

小规模枚举或独立有界最小二乘参考解用于发现严重能力损失，属于离线诊断，不是运行时依赖。对照带正则目标时参考解使用同一目标；比较纯跟踪能力时单独注明关闭／扣除正则偏差。只对指定参考场景设定误差容限，不要求所有输出与最优解一致。

### 11.2 裸 Bullet 刚体与闭环

建立 `PhysicsSpace`，按固定步长（初始取 100 Hz）推进真实动态刚体。已有独立 native 加载与步进测试可参考 `src/test/java/io/github/sweetzonzi/machine_max/track/GearJointPhysicsTest.java#GearJointPhysicsTest`。通过 `.\gradlew --offline test --tests <测试类>` 运行，无需 Minecraft、ServerLevel 或 GameTest。

分配器输出必须经过响应与器件力函数，再由 Bullet 积分；不能直接把目标 wrench 写成刚体速度。测试分别覆盖单步力学和长时间闭环：

| 场景 | 观察与验收 |
| --- | --- |
| 单器件解析力学 | 在无接触、小转角条件下，对照 `Δv≈FΔt/m` 与已知惯量的角速度变化，核对作用点、坐标与正负号 |
| 对称与斜装推进器 | 平移时的寄生转动、转向时的寄生平移符合指定容限；保留耦合，不凭空补力 |
| 悬停与目标阶跃 | 给定质量、重力、增益与响应参数后，记录高度漂移、跟踪误差、超调与稳定时间 |
| 越界与作动器故障 | 突然关闭或降低器件权限，输出有界、无无效数值；能力不足时呈现可解释的失控与残差 |
| 级联与行切换 | 对照批量／逐个钉界、活行变化附近的输出变化，检查持续跑偏与抖动 |
| 舵面扩展 | 加入真实或明确标注的测试力函数，覆盖正负偏角、低动压、失速附近及响应滞后；线性推进器阶段不以此为前置 |

每个场景在测试定义中先写明目标、容差、持续时间与采样口径；参数未标定时输出测量结果并标明未验收，不能只用“不抛异常”宣称可控。对不可控机型不强求悬停成功，但必须守住数值、出力边界和诊断契约。

### 11.3 性能与计算预算

单次无界子问题的数值工作量约为 `O(m²N + m³)`，`m≤6`；级联至多 `N` 轮钉界，总成本需按各轮自由列数计入。记录分解次数、钉界轮数和可选修正次数，不以“一次 6×6 很小”代替完整测量。

力函数端点采样、坐标变换与环境查询在单次调用内复用，级联循环只处理数值列与目标。复用线程私有的工作数组，按发布相位生成快照，避免每轮查询世界、JNI 往返或发布动画状态。

性能测试记录机器、JVM、步长、作动器数、活行数、并行载具数与预热条件；分别量内核与包含采样的整条适配链，报告典型、近共线、连续越界和故障布局的耗时分位数、峰值与分配量。按目标载具数量给出该功能可用的物理步预算，达标后接受近似解，不为最优性无限增加迭代。

### 11.4 可选能力与游戏接入

虚拟作动器按普通列参加内核用例；其简化模型与量级通过配装配置确定。平衡辅助独立验收预算、死行零出力、`k=0` 关闭、原始残差保留与实际施力记账，不以“保留所有饱和缺口”作为断言。它们不阻塞基础分配与裸物理阶段。

游戏接入再处理部件发现、能源与损伤、实际机型参数、同步和动画。线性内核及裸物理通过并不等于这些接线已完成；文档状态按实际落地阶段更新。

### 11.6 输入辅助、输出生命周期与 GC 预算

**每台载具保留一个自带输入的 Workspace，物理步覆盖数值，发布时按需复制。** `src/main/java/io/github/sweetzonzi/machine_max/util/WrenchAllocator.java#Workspace` 的有参构造一次创建输入列、目标、幅值界、代价、行配置与求解缓冲；调用方直接更新上下文并调用实例 `solve`，不需要分别构造输入辅助和工作区。`Problem` 保留为低层借用视图，普通使用不必显式访问它。

**喷口朝向、力臂与满出力可以每步变化。** 用稳定器件索引覆盖对应效能列，未修改列及配置保持当前值。`forceAtOffset` 同时写入本步的力与 `r×F`，因此方向或作用点变化不会遗留旧的力矩分量。每次求解都依据当前列重建归一化与分解数据，临时指令和钉界标记从头开始；复用的是内存，不是上一拍的解或分解。

调用方从当前物理姿态取得喷口方向与相对质心位移，统一到同一坐标系后写入；上下文不读取世界、关节或渲染动画，也不自动推断坐标变换。刚性安装且在本体系表示的列可以保持，目标和已知外力则要转换到该体系；若使用世界系，机体整体转动也可能要求更新全部列。数量变化时重建上下文，损坏／油门权限改变只更新界；几何更新不恢复已关闭器件的权限。

| Workspace 更新方法 | 输入与作用 |
| --- | --- |
| `src/main/java/io/github/sweetzonzi/machine_max/util/WrenchAllocator.java#forceAtOffset` | 单位指令的力与相对质心位移，自动组装 `[F; r×F]`；采用原始数值参数，不创建临时向量。力与位移须在同一坐标系，位移不能直接传世界绝对位置 |
| `src/main/java/io/github/sweetzonzi/machine_max/util/WrenchAllocator.java#wrench`、`src/main/java/io/github/sweetzonzi/machine_max/util/WrenchAllocator.java#pureTorque` | 直接写割线／固有力矩列，或清零力分量写纯力矩列；幅值界单独配置 |
| `src/main/java/io/github/sweetzonzi/machine_max/util/WrenchAllocator.java#target`、`src/main/java/io/github/sweetzonzi/machine_max/util/WrenchAllocator.java#subtractKnown` | 每步先覆盖期望净 wrench，再扣已知项；已知项方法累积扣除，不能在未覆盖目标时跨帧重复调用 |
| `src/main/java/io/github/sweetzonzi/machine_max/util/WrenchAllocator.java#limits`、`src/main/java/io/github/sweetzonzi/machine_max/util/WrenchAllocator.java#disable`、`src/main/java/io/github/sweetzonzi/machine_max/util/WrenchAllocator.java#cost` | 更新当前幅值权限与努力代价；更新安装几何不改变损坏／关闭状态，恢复权限须显式设置界 |
| `src/main/java/io/github/sweetzonzi/machine_max/util/WrenchAllocator.java#rowScale`、`src/main/java/io/github/sweetzonzi/machine_max/util/WrenchAllocator.java#activeRow` | 设置软权重和实际可用行，上下文不另建姿态门控表 |

**`Solution` 是工作区借用对象，`Result` 是独立快照。** `src/main/java/io/github/sweetzonzi/machine_max/util/WrenchAllocator.java#Solution` 只能在下一次同工作区求解之前消费，不能直接发布到主线程或当历史值保存。标量访问和 `copyControlsTo` 不分配数组；`snapshot` 则显式复制为独立 `Result`。两个 `allocate` 入口都产生快照；因此复用 `Workspace` 并不等于调用 `allocate` 时没有分配。

`Result.controls()`、`achieved()`、`residual()` 每次还会返回数组副本。下表快照字节数只计创建 `Result`，不计这些后续副本；频繁消费控制量时使用标量访问，或由 `Solution.copyControlsTo` 写入调用方的预分配数组。

```java
// 配装确定时创建并保留一个上下文，两个喷口的力臂力矩相消。
var workspace = new WrenchAllocator.Workspace(2);

// 物理线程每步按当前姿态覆盖需要改变的列；这里给出水平姿态的一拍。
workspace.forceAtOffset(0, 0, 100, 0, 1, 0, 0)
        .forceAtOffset(1, 0, 100, 0, -1, 0, 0)
        .target(0, 100, 0, 0, 0, 0);
var output = workspace.solve();
double leftCommand = output.control(0); // 当步交给响应／力函数。
// 若下一拍喷口方向改变，覆盖该列的力方向和力臂，再 solve 即可。
// 需要保存分配诊断时调用 output.snapshot()；动画实际油门来自响应后的状态。
```

**分配字节测量（2026-10-27）**：使用与 §11.5 相同的 JVM，探针通过 JDK 的线程分配字节计数，在每种模式预热 10000 次后采样 20000 次。打印和一次性初始化在计数区间之外，重建模式则将整套上下文创建计入；结果对象通过 volatile 槽消费，减少优化掉输出的可能。复现：`python tools/verify_wrench_allocator.py --allocation`，入口为 `src/test/java/io/github/sweetzonzi/machine_max/util/WrenchAllocatorReferenceProbe.java#measureAllocations`。

| 器件数 | 复用输入／工作区，每步独立 Result（B/步） | 复用一体化 Workspace，更新目标／方向／力臂并 solve（B/步） | 每步重建整个一体化上下文（B/步） |
| --- | --- | --- | --- |
| 16 | 400 | 0 | 3776 |
| 32 | 592 | 0 | 6352 |
| 64 | 976 | 0 | 11504 |

64 器件、100 Hz、100 台载具若每步创建分配快照，仅结果就约 `976×100×100=9.76 MB/s`；若每步重建整套一体化上下文，输入与暂存部分约 `115.04 MB/s`。采用复用上下文与借用 `solve`，本次测量的填充和求解为 `0 B/步`；需要时以 20 Hz 保存诊断快照，则同一假设下的结果分配约 `1.952 MB/s`。这些速率采用十进制 MB，仅描述本组件的对象分配，不预测整个游戏 JVM 的 GC 暂停。

容量扩张、配装重建、显式快照和非法配置异常允许分配；气动采样、数学向量转换、网络与实际油门快照属于适配层，须单独计量。该测量不等同于游戏运行完全没有 GC，也不要求引入对象池、共享可变快照或跨线程复用工作区。
