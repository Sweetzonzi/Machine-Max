# 履带系统：数据模型设计

> **状态：** 决策已定，待实现。本文定义 `TrackAttr`、`FittingVisual`、材料复用方式、音效边界与单节模型渲染口径。
> **日期：** 2026-10-22
> **关联：**
>
> - [履带系统：内容包模块与类型注册设计](履带系统-内容包模块与类型注册设计.md)：`fittings/` 目录、`FittingModule`、`FittingType` / `TrackType`、物品与持久化链路
> - [履带系统：物理实现设计文档](履带系统-物理实现设计文档.md) §2.4（轮面半径与履带厚度）、§4.4（张力近似）
> - `HitBoxAttr` / `MaterialAttr`：材料、装甲覆写、物理属性的现有定义
> - `TrackRenderer`：单节履带与程序化回退的现有渲染入口

## 1. 范围与原则

### 1.1 本文解决

- `TrackAttr` 的字段集合、单位、默认值与校验。
- `FittingVisual` 的字段：单节模型与贴图。
- 履带如何复用 `MaterialAttr` 的装甲与物理属性。
- 履带接触的摩擦口径：前向/侧向摩擦，不使用轮胎滑移曲线。
- 履带音效的数据边界：命中音可配，滚动/滑移音保持硬编码。
- 单节模型在近处/远处的渲染分工与回退。

### 1.2 本文不解决

- `fittings/` 目录、模块 id、注册表与 `type` 分派；这些由模块文档定义。
- 履带物理算法（GearJoint、张力、包络求解）；这些由物理实现文档定义。
- 物品经济（一件物品对应一条带，还是按节消耗）、蓝图是否携带履带、按型号切换 2D 图标。
- 装甲板、装饰物、`Fitting` 运行时对象、两点放置。
- LOD 与合批；远处渲染直接使用程序化履带。

### 1.3 设计原则

1. **材料是装甲与接触物理的唯一来源。** 履带存在期间，成员轮面的摩擦、滚动/自旋摩擦、弹性、湿滑适应、方块伤害因子读履带材料；装甲在履带未断带时读履带材料。轮子自身的 `HitBox` 材料在这两类路径中不参与。
2. **厚度只有一个。** `thickness` 同时是几何厚度与装甲厚度；几何侧由毫米换算为米。
3. **不给履带套轮胎模型。** 履带只保留前向/侧向各向异性摩擦；`slip_curve` 是轮胎摩擦椭圆的近似，履带不读取。
4. **音效保持硬编码。** 命中音提供两个可配字段；滚动音与滑移音由 `CollisionEffectManager` 固定选择，不进入履带数据。
5. **视觉是模型加贴图。** 单节履带必须指定模型与贴图；程序化扁长方体只作为模型缺失或远处渲染的回退。
6. **近处模型，远处程序化。** 不做距离 LOD；由渲染入口选择模式。

## 2. 数据模型总览

```text
TrackType
├── FittingVisual visual   // model + texture
└── TrackAttr attr
    ├── durabilityPerLink
    ├── lengthPerLink
    ├── thickness
    ├── minEffectiveWheels
    ├── material           // 材料 id，装甲 + 物理
    ├── overwrite          // 可选，复用 HitBoxAttr.OverwriteAttr
    ├── sounds             // 仅 hit_un_pen / hit_pen
    └── tension
```

- `TrackType` 与 `FittingVisual` 的类关系由模块文档定义；本文只定义字段。
- `TrackAttr` 在构造时解析材料并缓存 `MaterialAttr`，避免每次接触都查表与合并。
- `TrackAttr` 是 class，不是 record；缓存 `resolved` 需要实例字段。

## 3. `TrackAttr`

### 3.1 字段

| 字段 | 类型 | 单位 | 默认 | 校验 | 用途 |
| -- | -- | -- | -- | -- | -- |
| `durabilityPerLink` | float | 点 | 20 | 有限且 > 0 | 每节耐久；整条带最大耐久 = `durabilityPerLink × N` |
| `lengthPerLink` | float | 米 | 0.2 | 有限且 > 0 | 节长；用于节数 `N` 与相位 |
| `thickness` | float | 毫米 | 50 | 有限且 > 0 | 节厚；同时用于装甲 RHA 与几何/渲染 |
| `minEffectiveWheels` | int | 个 | 2 | ≥ 2 | 有效成员下限（含主动轮） |
| `material` | ResourceLocation | — | `machine_max:track_steel` | 必须存在 | 装甲与接触物理来源 |
| `overwrite` | Optional&lt;HitBoxAttr.OverwriteAttr&gt; | — | 空 | 可选 | 按 physics / armor 覆写材料 |
| `sounds` | MaterialAttr.MaterialSoundAttr | — | `hard_metal` 固定范围事件 | 可选 | 仅 `hit_un_pen` / `hit_pen` |
| `tension` | Tension | — | 见 3.3 | 见 3.3 | 相邻轮弹簧-阻尼参数 |

`thickness` 与几何的换算：

```text
thicknessMeters() = thickness × 0.001
```

- `TrackEnvelope2D`、`TrackRenderer`、轮面半径约定都使用 `thicknessMeters()`。
- `SubPart.getRHA` 直接使用 `thickness` 的毫米值。

### 3.2 `TrackAttr` 形状

```java
public final class TrackAttr {
    private final float durabilityPerLink;
    private final float lengthPerLink;
    private final float thickness;            // mm
    private final int minEffectiveWheels;
    private final ResourceLocation materialId;
    private final Optional<HitBoxAttr.OverwriteAttr> overwrite;
    private final MaterialAttr.MaterialSoundAttr sounds;
    private final Tension tension;
    private final MaterialAttr resolved;      // 构造时解析

    public float durabilityPerLink() { return durabilityPerLink; }
    public float lengthPerLink() { return lengthPerLink; }
    public float thickness() { return thickness; }
    public float thicknessMeters() { return thickness * 0.001f; }
    public int minEffectiveWheels() { return minEffectiveWheels; }
    public ResourceLocation materialId() { return materialId; }
    public MaterialAttr material() { return resolved; }
    public MaterialAttr.ArmorAttr armor() { return resolved.armor(); }
    public MaterialAttr.PhysicsAttr physics() { return resolved.physics(); }
    public MaterialAttr.MaterialSoundAttr sounds() { return sounds; }
    public Tension tension() { return tension; }
}
```

- `resolved = HitBoxAttr.resolve(materialId, overwrite.orElse(null))`。
- `HitBoxAttr` 需要提供公共静态 `resolve(ResourceLocation, OverwriteAttr)`，把现有 `getEffectiveMaterial` 的合并逻辑抽出来；`HitBoxAttr` 与 `TrackAttr` 共用。
- 材料缺失时 `resolve` 回退 `MaterialAttr.DEFAULT` 并打 warn；`FittingModule` 在加载时应校验 `MMDynamicRes.MATERIALS` 中存在该 id，缺失记为内容包错误。

### 3.3 `Tension`

沿用物理文档 §4.4 的字段集合：

| 字段 | 单位 | 默认 |
| -- | -- | -- |
| `enabled` | bool | true |
| `stiffness` | N/m | 12000 |
| `damping` | N·s/m | 900 |
| `preload` | 米 | 0 |
| `slack` | 米 | 0.015 |
| `max_force` | N | 800 |

`rest` 不声明，装配 / 载入时按相邻轮心距采样。

## 4. `FittingVisual`

```java
public record FittingVisual(ResourceLocation model, ResourceLocation texture) {
    public static final Codec<FittingVisual> CODEC = RecordCodecBuilder.create(instance -> instance.group(
            ResourceLocation.CODEC.fieldOf("model").forGetter(FittingVisual::model),
            ResourceLocation.CODEC.fieldOf("texture").forGetter(FittingVisual::texture)
    ).apply(instance, FittingVisual::new));
}
```

- `model`：单节履带模型，按 `ModelIndex("part", model)` 加载，与零件模型同一套 `OModel`。
- `texture`：该模型的贴图全路径。
- 两个字段都必填；`TrackType` 不接受只有贴图、没有模型的型号。
- `FittingVisual` 只有 `model` 与 `texture`；渲染宽度与颜色不进入型号数据。程序化回退使用 `TrackRenderer` 的 `LINK_WIDTH` / `LINK_COLOR` / 纯白贴图。
- 未来 `prop` 也使用“模型 + 贴图”；需要纯程序化几何的类型另设 `kind`，不要放宽 `FittingVisual`。

## 5. 材料语义

### 5.1 装甲

```text
rhaCoeff(ratio) = decay_rha + (rha − decay_rha) × ratio^decay_power
RHA = thickness(mm) × rhaCoeff(ratio)
ratio = 当前耐久 / 最大耐久
```

- `rha`、`decay_rha` 是**系数**，与 `HitBoxAttr.thickness × rhaCoeff` 语义一致。
- 默认标定：

| 参数 | 值 |
| -- | -- |
| `material` | `machine_max:track_steel` |
| `thickness` | 50 mm |
| `rha` | 0.6（冲压/穿孔履带板的结构系数） |
| `decay_rha` | 0.3 |
| `decay_power` | 1.5 |
| `unpen_power` | 0.6 |
| `dmg_resist` | 1.0 |
| `dmg_mult` | 0.95 |
| `decay_dmg_resist` | 0.0 |
| `decay_dmg_mult` | 1.0 |

| 耐久 | RHA |
| -- | -- |
| 100% | 30.0 mm |
| 50% | ≈ 16.4 mm |
| 0% | 9.0 mm |

以上是首版标定，实机后按手感调整；`decay_rha` / `decay_power` 不属于兼容性字段。

### 5.2 物理

履带接触读取 `material.physics()` 的以下字段：

| 字段 | 用途 |
| -- | -- |
| `friction` | 各向异性摩擦向量；`x` = 侧向，`y` = 前向 |
| `rolling_friction` | 滚动摩擦 |
| `spinning_friction` | 自旋摩擦 |
| `restitution` | 弹性 |
| `slip_adaptation` | 湿滑适应；参与 `wetFactor` |
| `block_damage_factor` | 方块破坏能量系数 |

`slip_curve` 不参与履带：它是轮胎椭圆摩擦模型的近似。`material` 仍保留 `slip_curve` 字段供轮胎/碰撞箱使用；履带路径忽略它。

### 5.3 覆写

- `overwrite` 复用 `HitBoxAttr.OverwriteAttr`。
- 对履带生效的组：`physics`、`armor`。
- 对履带不生效的组：`sounds`；履带命中音由 `TrackAttr.sounds` 定义。
- `overwrite` 的合并由 `HitBoxAttr.resolve` 完成，履带与碰撞箱使用同一套规则。

### 5.4 缺席材料

| 场景 | 处理 |
| -- | -- |
| 材料 id 在 `MMDynamicRes.MATERIALS` 中不存在 | `HitBoxAttr.resolve` 回退 `MaterialAttr.DEFAULT`，打 warn；`FittingModule` 记内容包错误 |
| 客户端缺少材料 | 回退 `MaterialAttr.DEFAULT`，打 warn；不影响载具加载 |
| 服务端缺少材料 | 回退 `MaterialAttr.DEFAULT`，打 warn；物理以服务端解析结果为准 |

## 6. 接触摩擦口径

### 6.1 完全覆盖

履带存在（`trackLink != null && !isDisposed()`）且接触属于履带成员轮面时：

- 摩擦、滚动/自旋摩擦、弹性、湿滑适应、方块伤害因子全部读 `track.attr().physics()`。
- 轮子自身 `HitBox` 材料的这些字段不参与。

建议在 `SubPart` 提供统一入口：

```java
MaterialAttr contactMaterial(HitBox hitBox) {
    TrackLink track = this.trackLink;
    if (track != null && !track.isDisposed()) return track.attr().material();
    return hitBox.attr.getEffectiveMaterial();
}

MaterialAttr armorMaterial(HitBox hitBox) {
    TrackLink track = this.trackLink;
    if (track != null && !track.isDisposed() && !track.isBroken()) {
        return track.attr().material();
    }
    return hitBox.attr.getEffectiveMaterial();
}
```

`CollisionHandler` 的摩擦路径使用 `contactMaterial`；`SubPart` 的 BF 装甲路径使用 `armorMaterial`。

### 6.2 不走轮胎滑移曲线

`CollisionHandler.setupContactFriction` 对履带接触走简单合成摩擦，不调用 `applyWheelFriction`：

```java
boolean isTrackContact = track != null && !track.isDisposed() && subPart.isWheel(hitBoxIndex);

if (isTrackContact) {
    // 前向/侧向摩擦由 body 的 anisotropicFriction 提供；
    // 这里只写合成摩擦标量，不设 LATERAL_FRICTION 方向。
    ManifoldPoints.setCombinedFriction(manifoldPointId,
            Math.max(0.001f, subPart.body.getFriction() * blockFriction * wetFactor));
    ManifoldPoints.setFlags(manifoldPointId,
            ManifoldPoints.getFlags(manifoldPointId) & ~ContactPointFlag.LATERAL_FRICTION);
} else if (subPart.isWheel(hitBoxIndex) && subPart.isWheelSurface(hitBoxIndex)) {
    applyWheelFriction(hitBox, slipAngle, slipRatio, slipVel,
            manifoldPointId, blockFriction, wetFactor); // 轮胎
} else {
    // 非轮 / 非轮面
}
```

- `applyFriction` 在履带成员轮面设置 `body.setAnisotropicFriction(physics.friction(), AfMode.basic)`；前向/侧向摩擦由该向量承担。
- `wetFactor` 的 `slipAdaptation` 用履带 physics；`block_damage_factor` 的三处读取同样读履带 physics。
- `applyBlockDamage` 里的 `hitBox.getRHA(subPart)` 读履带装甲（断带时回退 HitBox）。

### 6.3 断带

| 属性 | 断带后 |
| -- | -- |
| 装甲 RHA / 装甲修正器 | 回退到成员轮 `HitBox` 材质 |
| 命中音 | 回退到成员轮 `HitBox` 材质音效 |
| 前向/侧向摩擦、滚动/自旋、弹性、湿滑适应、方块伤害因子 | 仍读履带材料（`!isDisposed()`） |
| 滚动音 | 仍为履带硬编码滚动音 |

断带只解除装甲层与传动耦合，不改变履带仍挂在轮组上的接触属性。

## 7. 音效

### 7.1 数据字段

`TrackAttr.sounds` 是 `MaterialAttr.MaterialSoundAttr`，只包含：

| 字段 | 默认 |
| -- | -- |
| `hit_un_pen` | `part.collision.terrain.hard_metal` |
| `hit_pen` | `part.collision.terrain.hard_metal` |

`MaterialSoundAttr.CODEC` 使用 `SoundEvent.DIRECT_CODEC`，支持字符串或 `{ "sound_id": ..., "range": ... }`。现有 material JSON 不写 `sounds` 也能解析。履带的 `sounds` 缺省值是 `hard_metal` 固定范围事件，与当前履带命中音一致；`MaterialSoundAttr.DEFAULT` 是碰撞箱的 `hit_box.hit.*`，不作为履带缺省值。

### 7.2 播放路径

| 音效 | 来源 | 代码 |
| -- | -- | -- |
| 命中（未击穿 / 击穿） | `TrackAttr.sounds` | `SubPart.hurt` 在履带存活时读 `track.attr().sounds()`；断带后读 `HitBox` 材质 |
| 持续滚动 | 硬编码 | `CollisionEffectManager.getFrictionSound` 对履带成员固定返回 `TIRE_METAL` |
| 额外滑移 | 硬编码 | `updateSlipSound` 固定 `TIRE_EXTRA_SLIP` |

- `material.sounds` 与 `overwrite.sounds` 对履带不生效，文档与 schema 需注明。
- 滚动音不提供数据字段；内容包不能为某个履带型号单独指定滚动音。
- 滑移音不按地面材质细分，也不提供数据字段。

## 8. 视觉与渲染

### 8.1 模型

- `visual.model` 是**单节**模型，不是整条带；渲染器在每个节的世界矩阵下绘制一份。
- 模型局部约定：

| 轴 | 含义 |
| -- | -- |
| +X | 切线 / 前进方向 |
| +Y | 外法线 |
| +Z | 轮轴 / 宽度方向 |

- 原点在节中心；沿 X 的长度 ≤ 节距 `lengthPerLink`，沿 Y 的厚度应等于 `thicknessMeters()`，沿 Z 的宽度由模型决定。
- 若模型原点在底面，渲染时沿 +Y 补 `thicknessMeters() / 2`；补偿放在渲染器，不写进模型。
- 贴图路径由 `visual.texture` 明确给出；不使用 `ModelIndex` 的默认贴图推导。

### 8.2 渲染分工

```java
public enum TrackRenderMode { MODEL, PROCEDURAL }

public static void renderTrack(SubPart subPart, PoseStack poseStack,
                               MultiBufferSource bufferSource,
                               float partialTick, int packedLight,
                               TrackRenderMode mode)
```

| 调用方 | 模式 | 行为 |
| -- | -- | -- |
| `PartEntityRenderer` | `MODEL` | 模型存在则逐节渲染模型；模型缺失则回退程序化 |
| `DistantVehicleRenderer` | `PROCEDURAL` | 始终画程序化扁长方体，不加载内容包模型 |

- 不做距离 LOD；近处/远处由渲染入口选择。
- 模型路径：`ModelIndex("part", visual.model())`；借用主动轮所属 `Part` 作为 `IAnimatable` 创建静态 `ModelPose`；用 `ModelRenderHelperKt.render` 逐骨骼绘制。
- 缓存：`ModelPose`、`RenderType`、`OModel` 按 `TrackLink` 或 `TrackType` 缓存，不每帧新建。
- `RenderType` 按 `visual.texture()` 缓存 `RenderType.entitySolid(texture)`；需要 alpha 时用 `entityCutout`。
- 模型缺失（`OModel.EMPTY`）：日志一次，回退程序化，不崩。
- 程序化回退：`LINK_WIDTH`、`LINK_LENGTH_RATIO`、`LINK_COLOR`、纯白贴图，沿用 `TrackRenderer` 现有常量。

### 8.3 性能

- 单节模型如果只有一个骨骼/少量 cube，逐节绘制的成本与现有逐节扁长方体同一量级。
- 多骨骼模型需要合批或 LOD；首版不做，远处已由 `PROCEDURAL` 分流。
- 模型纹理缓存避免每节重复创建 `RenderType`。

{

## 10. 代码落点

| 位置 | 改动 |
| -- | -- |
| `TrackAttr` | 新字段集合；`thicknessMeters()`；构造时 `HitBoxAttr.resolve` |
| `TrackAttr.CODEC` | `material`、`thickness`、`durability_per_link`、`length_per_link`、`min_effective_wheels`、`overwrite`、`sounds`、`tension` |

| `CollisionHandler` | 履带接触跳过 `applyWheelFriction`；摩擦/湿滑/方块伤害读履带 physics |

| `TrackRenderer` | `TrackRenderMode`；模型/程序化两条路径；缓存 |
| `PartEntityRenderer` / `DistantVehicleRenderer` | 分别传 `MODEL` / `PROCEDURAL` |
| `FittingModule` | 校验 `material`、`model`、`texture` |
| Schema | `track_attr` 字段、`material` 引用、`visual` 两字段、`sounds` 两字段 |

## 11. 验收

| 项 | 验收 |
| -- | -- |
| 数据解析 | 示例 JSON 在 `runServer` 解码成功；缺 `material` / `model` / `texture` 产生内容包错误 |
| 装甲 | `thickness=50`、`rha=0.6`、`decay_rha=0.3` 时，100%/50%/0% 耐久 RHA 为 30 / ≈16.4 / 9 |
| 摩擦 | 履带接触走简单合成摩擦，不设 `LATERAL_FRICTION`；轮胎支路不变 |
| 断带 | 装甲与命中音回退 HitBox 材质；摩擦/滚动音仍用履带材料 |
| 音效 | 命中音由 `TrackAttr.sounds` 决定；滚动固定 `TIRE_METAL`；滑移固定 `TIRE_EXTRA_SLIP` |
| 渲染 | 近处显示单节模型；远处显示程序化履带；模型缺失时近处回退程序化 |
| 同步 | `TrackLinkData.track_type` 往返保留；旧存档回落默认型号 |
