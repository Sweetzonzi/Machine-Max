# 部件精确准星拾取与渲染包围盒设计

**状态**：进行中；P0–P2 的代码接入已完成（部件命中解析、ProjectileUtil 精确求交、完整 AABB 与主动轮履带剔除），P3 的准星/近战运行期验收、Eyesight 查询结果发布修正待做。实现范围见 §7，验收矩阵见 §8。

**目标**：部件实体保留完整 AABB 和 `isPickable() == true`；原版准星及使用 ProjectileUtil 的投射物只在射线命中部件的有效碰撞形状时选中部件。射线经过部件 AABB 的空白区域时，可以选择后方方块或普通实体。普通部件使用完整刚体 AABB 做渲染剔除，履带主动轮额外合并整条履带的 AABB。

本文相对路径以 Machine-Max 仓库根为基准；`../Spark-Core/`、`../Libbulletjme/` 为同级源码仓库。Minecraft 源码坐标中的 `jar!/路径#符号` 指向开发环境生成的 sources jar 内对应文件。

## 1. 职责与行为契约

| 对象 | 用途 | 本方案的约束 |
| --- | --- | --- |
| 实体 `getBoundingBox()` | 实体空间查询、原版交互距离校验等 | 使用部件刚体的完整世界 AABB，不乘 0.7 |
| 部件拾取几何 | 准星是否真正命中部件 | 使用有效 HitBox 的物理形状，排除轮胎辅助球体 |
| `getBoundingBoxForCulling()` | 视锥剔除 | 普通部件取完整刚体 AABB；履带主动轮合并整条履带 AABB，接受动画外伸造成的边缘剔除 |
| `isPickable()` | 实体是否允许被选中 | 返回 `true`，近战、原版实体右键和中键入口继续可达 |
| Bullet 碰撞体 | 实际物理接触 | 拾取过程只查询，不修改形状、碰撞组、位姿或约束 |

最近目标规则：在 ProjectileUtil 的每候选求交位置，普通实体提供原版 AABB 命中点，部件提供有效形状命中点；原版循环比较距离、选出优胜实体，再由 GameRenderer 与方块比较。方块在前时阻挡部件；部件在前时可以攻击或交互；部件形状之间的空隙允许射线通过。

这里的“精确”指部件碰撞形状，而非模型三角形或贴图透明度。没有建成 HitBox 空隙的模型开口，不承诺可穿透。独立的座椅 InteractBox、连接器触发区不作为原版近战的部件表面。

## 3. 注入位置：ProjectileUtil 的每候选求交

共通 `ProjectileUtilMixin` 已登记到 `src/main/resources/machine_max.mixins.json` 的 `mixins` 数组。共享查询与过滤逻辑位于共通包；原版求交适配层与 Eyesight 共用同一套子形状索引规则，该层不得引用客户端类。

Minecraft 1.21.1 有三个 `getEntityHitResult` 重载，其中两条执行候选循环，一条负责转调。两条循环共用部件精确求交，按完整签名分别定位注入点：

| 签名 | 用途与接入范围 |
| --- | --- |
| `(Entity, Vec3, Vec3, AABB, Predicate, double)` | GameRenderer 等使用；包装候选的 clip 与 contains，原版负责最大平方距离与乘客规则 |
| `(Level, Entity, Vec3, Vec3, AABB, Predicate)` | 以默认膨胀量 0.3 转调下一条；通过转调自动获得精确部件判定，无需重复注入 |
| `(Level, Entity, Vec3, Vec3, AABB, Predicate, float)` | 箭矢、抛射物等使用；包装候选 clip，并修正最终普通 EntityHitResult 的部件命中位置 |

double 重载的原版循环结构为：

```java
for (Entity candidate : level.getEntities(source, searchBox, predicate)) {
    AABB box = candidate.getBoundingBox().inflate(candidate.getPickRadius());
    Optional<Vec3> point = box.clip(from, to);
    if (box.contains(from)) {
        // AABB 内部起点的距离 0 快捷分支
    } else if (point.isPresent()) {
        // 按 point 的距离与当前最佳候选比较，并处理乘客排除
    }
}
```

double 重载使用两处 `@WrapOperation`，并捕获当前 `candidate`：

1. 包装 `AABB.clip(Vec3, Vec3)`：普通实体调用 `original.call`；MMPartEntity 调用共享查询，返回本部件最近有效形状的真实命中点，未命中返回 `Optional.empty()`。
2. 包装 `AABB.contains(Vec3)`：普通实体调用 `original.call`；MMPartEntity 返回 false，禁用“位于整个部件 AABB 内就强制距离 0”的快捷路径。部件内部起点的几何语义见 §4.4。

候选枚举、原版谓词、距离比较与乘客规则保留在原版循环中。部件 A 未命中时循环会检查后面的部件 B 与普通实体；不需要事后重跑普通实体查询或另写候选合并器。距离完全相等时采用该重载自身的遍历与比较语义；最终部件结果的命中位置见下段约定。

float 重载使用同一个 clip 包装函数；它没有 contains 快捷分支。普通实体继续使用该重载传入的 AABB 膨胀量。部件以有效 HitBox 的真实表面为准，不把 0.3 等 AABB 宽容量加在部件外面；因此擦过部件包围盒的空白区域应当穿过。若某类投射物需要有限半径扫掠，必须显式提供半径和形状扫掠语义，不能把 AABB 膨胀参数当成精确射线的半径。

float 重载原版通过命中点选目标，但返回的是 `new EntityHitResult(entity)`，结果位置是实体位置，并非实际表面。对最终优胜的部件，使用已有构造器 `new EntityHitResult(entity, precisePoint)` 返回真实命中点。两个重载均保留原版方法签名与普通 EntityHitResult 返回类型；HitBox、法线等伤害几何不附着到该返回值，也不在候选循环中改写投射物伤害状态。

共享解析方法返回 §4.0.1 定义的有序 `List<RayHit>`，其中部件、连接器、交互区等使用各自的结果类型。ProjectileUtil 适配层与 PartHitHandler 只消费 SubPartRayHit 的部件目标与命中几何；其余结果类型留给后续调用方按需读取。§5.1 定义 PartHitHandler 在实际命中时使用解析结果的流程。

共享查询结果由 MixinExtras `@Share` 保存在本次调用上下文中：遇到第一个需要查询的部件时执行一次当前射线查询，按 SubPart 索引最近有效命中，其余候选只查表。不能每遍历一个部件就再次向整个物理空间发射同一条射线。该上下文不放在静态可变字段里；重入、客户端和服务端调用各自隔离。

候选局部变量由 `Entity.getBoundingBox` 的 `@WrapOperation` 捕获，经本次 `@Share` 的 `candidate` 槽传递；不使用 `@Local` 选择器，避免依赖局部变量 ordinal 或反编译变量名。

方块 OUTLINE 查询、实体/方块交互距离过滤，以及 `Minecraft.hitResult` 与 `Minecraft.crosshairPickEntity` 发布继续由 GameRenderer 完成。这里不覆盖整个方法。`@WrapOperation` 的普通实体分支通过 `original.call` 保留包装链，具体约定见 [MixinExtras 官方说明](https://github.com/LlamaLad7/MixinExtras/wiki/WrapOperation)。

## 4. 部件窄相查询

### 4.0 共用的子形状判据

识别 SubPart、跳过 wheel 辅助球体、跳过未激活 HitBox 的规则统一在 `SubPart.findPickableHitBox` 与 `InteractBoxes.findInteractBox` 中实现；Eyesight 对指定碰撞组与观察者自身的排除属于其调用方策略。`RayHitResolver` 用同一套方法产出完整 `List<RayHit>`，供原版实体求交适配层与 PartHitHandler 使用；Eyesight 直接调用这两个领域方法过滤自己的候选循环。三处不各自维护部件过滤条件或子形状索引注册表。

当前采用“共用查询方法”：准星与投射物用本帧起终点在只读物理快照上解析，保留本帧转头响应；Eyesight 在物理线程向真实世界发射自己的 tick 级射线。两者共用判据，不共用射线输入；§4.1 描述查询来源，§4.2 说明读取时序与 Eyesight 结果发布的现状。

后置否决有明确适用边界：在私有 `GameRenderer.pick` 比较方块前，将无效的最终实体结果置为 `null`，可以回到其已保留的方块结果；在整个 pick 返回后直接设 MISS 则会丢掉方块。仅否决最终优胜实体也不会自动找回被其 AABB 抢先选取机会的其他实体。§3 把否决和命中点替换放在原版候选循环内部，由原版继续比较后续候选，解决这两个问题。

### 4.0.1 公用算法的输入、输出与调用方式

公用核心是 `RayHitResolver.resolve`。它接收已经执行完的物理射线结果，负责按 owner 解析成不同命中类型、完成部件有效性过滤并准备命中几何；射线发射由调用方选择实际世界或只读快照。每条命中都提供距离排序所需的 fraction、世界坐标命中点与世界空间法线，目标身份由具体结果类型给出：

```java
public static List<RayHit> resolve(
        List<PhysicsRayTestResult> rawHits,
        Vec3 from,
        Vec3 to);

public interface RayHit {
    double fraction();
    Vec3 point();
    Vec3 normal();
}

public record SubPartRayHit(
        double fraction,
        SubPart subPart,
        HitBox hitBox,
        Vec3 point,
        Vec3 normal) implements RayHit {}

public record ConnectorRayHit(
        double fraction,
        AbstractConnector connector,
        Vec3 point,
        Vec3 normal) implements RayHit {}

public record InteractBoxRayHit(
        double fraction,
        InteractBox interactBox,
        boolean enabledAtQuery,
        Vec3 point,
        Vec3 normal) implements RayHit {}

public record TerrainRayHit(
        double fraction,
        PhysicsChunkSection section,
        Vec3 point,
        Vec3 normal) implements RayHit {}

public record EntityRayHit(
        double fraction,
        Entity entity,
        Vec3 point,
        Vec3 normal) implements RayHit {}

public record OtherRayHit(
        double fraction,
        PhysicsHost owner,
        Vec3 point,
        Vec3 normal) implements RayHit {}
```

这些类型使用接口加 record 实现，没有共享字段的抽象基类。每条命中都提供 `fraction`、世界坐标命中点 `point` 与世界空间法线 `normal`；目标身份（SubPart / HitBox、连接器、交互判定区、地形区块、实体或未知 owner）由具体类型给出。SubPartRayHit 的 subPart、hitBox、point、normal 由构造入口保证非空；其余类型的领域对象与几何同样非空。InteractBoxRayHit 直接指向从 InteractBoxes 子形状解析出的单个 InteractBox，`enabledAtQuery` 是解析时从交互判定区读到的启用状态，交互模式（FAST / ACCURATE）仍由调用方策略处理。

`rawHits` 不包含完整射线起终点，只有沿本次射线的命中比例，所以 `from/to` 必须和这份列表来自同一次 rayTest。命中点按 `point = from + (to - from) * fraction` 用原版 double 起终点重建；法线直接复制引擎结果中的世界空间值。任一几何数值非有限时，该条命中不进入输出。结果中的领域对象是身份引用，不代表其指向对象的全部状态被冻结。

解析器只接收原始射线结果与起终点，直接读取物理体的 owner 与两类子形状映射。owner 来自 `PhysicsBodyExtensionKt.getOwner`；SubPart 的可拾取判定走 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/SubPart.java#findPickableHitBox`，交互判定区走 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/interact/InteractBoxes.java#findInteractBox`。两者都严格校验子形状索引：越界或映射缺失返回 null，该条命中不进入输出，不使用 `SubPart.getHitBox(int)` / `InteractBoxes.getInteractBox(int)` 的“异常回退首个元素”行为。ConnectorRayHit 只表示物理射线直接命中 AbstractConnector；“先命中 SubPart，再从其连接器中挑最近可用者”属于 Eyesight 后续策略，不在解析器中伪造成直接连接器命中。

算法固定为以下步骤：

1. 检查起终点有限；零长度射线返回空列表。逐条检查 fraction 有限且在 `[0, 1]`。
2. 取得 owner；没有 owner 时跳过。
3. 计算该条命中的世界命中点与法线；任一非有限时跳过。
4. 按 owner 分派：SubPart 经 `findPickableHitBox` 过滤激活状态与轮胎辅助球体后生成 SubPartRayHit；AbstractConnector 生成 ConnectorRayHit；InteractBoxes 经 `findInteractBox` 生成 InteractBoxRayHit；PhysicsChunkSection 生成 TerrainRayHit；Entity 生成 EntityRayHit；其他有 owner 的命中生成 OtherRayHit，避免静默丢掉未知目标。SubPart 无效形状直接跳过，不能转成 OtherRayHit 绕过过滤。
5. 按 fraction 升序排序，返回不可变列表。输入列表不修改；同一刚体的多个有效子形状均保留，不在这里按刚体去重。

没有有效结果时返回空列表，不返回 null。公共结果接口只提供几何与排序信息，不提供通用 hitBox() 或 owner()；消费方先按具体结果类型判断，再读取目标身份。核心不应用观察者自身排除、Eyesight 的 PROJECTILE 碰撞组排除、实体交互距离、原版 canHitEntity/乘客规则，也不写投射物字段或触发伤害；这些属于调用方策略。碰撞组等底层筛选若依赖真实碰撞对象，应由调用方在合法线程上、进入解析器前完成，不能为此给每种结果强加 native 对象字段。

三个调用方的消费方式为：

| 调用方 | 执行 rayTest 的位置 | 如何消费解析结果 |
| --- | --- | --- |
| LivingEntityEyesightAttachment | 物理线程真实世界 | 自己的候选循环；用 SubPart.findPickableHitBox / InteractBoxes.findInteractBox 过滤并保留各类型的遮挡/选择语义，再发布到自己的 tick 缓存 |
| ProjectileUtilMixin | 当前方法调用中，只读物理快照 | 首次遇到部件候选时经 RayQueryContext 查询、解析一次；从 `List<RayHit>` 筛出 SubPartRayHit，以 `putIfAbsent(hit.subPart(), hit)` 建最近命中索引。每个候选只查自己的 SubPart 并返回 point，原版继续做实体间比较 |
| PartHitHandler | 实际命中事件中的只读物理快照 | 沿用该次候选查询的起终点与谓词，取仍符合谓词的最近 SubPartRayHit；与事件目标一致才消费其 HitBox、point、normal。不能越过仍有效的前方部件，但应跳过原版已明确排除的实体 |

例如输入顺序为“未激活形状 A@0.1、部件 B@0.3、地形@0.5、部件 B 的另一形状@0.7”，输出为 SubPartRayHit(B@0.3)、TerrainRayHit(@0.5)、SubPartRayHit(B@0.7)。调用方可以识别地形类型，Mixin 给 B 建索引时保留 0.3，Handler 的最近部件也是 B@0.3。保留所有有效命中使调用方可以共用解析核心，而不把它们的目标选择策略混在一起。

输入列表本身不提供线程安全；跨线程传递时发布输出及对应射线输入的完整不可变快照，不向主线程公开正在填充的引擎结果列表。列表按 `RayHit::fraction` 排序。

### 4.1 查询来源与时间口径

ProjectileUtil 适配层使用方法参数或 source.level() 对应 Level 的 `worldSnapshot.rayTestDp(from, to, reusableResults)`。起终点从 Minecraft `Vec3` 直接转为 `Vec3d`，中途不转成世界坐标 `Vector3f`。Eyesight 则在物理线程向真实世界发射自己的射线，并用同一套子形状索引规则过滤候选。

实体求交适配层在客户端准星和双端投射物的主线程调用中消费只读快照，复用结果容器。主线程不得向正在步进的真实物理世界查询，也不得为了对齐画面临时移动快照刚体。结果中的命中比例仍为 float；世界命中点使用原版 double 起终点重建：`from + (to - from) * fraction`。

首期采用“最新完整物理快照”的时间口径。画面的位置插值由 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/DestroyableObject.java#getWorldPositionMatrix` 完成，因此高速平移、快速旋转时，快照表面与当前插值画面可能有一个 tick 量级的偏移。首期不声称逐帧贴合可见模型。若实机验收不能接受该偏移，单列插值拾取工作：使用独立查询对象或单形状只读查询，按同一 `partialTick` 变换射线；禁止修改共享 `WorldSnapshot` 位姿。

射线起点和方向使用被包装调用的参数，遵循原版相机实体眼睛的口径；不改用第三人称相机的后移位置，也不重定向炮镜或武器瞄准系统。

### 4.2 读取时序与 Eyesight 结果发布

主线程的准星与投射物查询使用只读物理快照的位姿与命中比例；`HitBox.active` / `InteractBox.enabled` 则是在解析时直接读普通字段，由物理线程更新。两者最多相差一个物理步：该差异只决定一个条件激活的形状是否参与本次查询，不改变形状索引，也不改变命中点相对快照位姿的几何。本方案接受这个口径；若实机验收发现条件激活形状的响应不可接受，再单列“同代只读元数据发布”工作，不修改共享 `WorldSnapshot`。

Eyesight 的查询调度与缓存发布需要单独修正。`src/main/java/io/github/sweetzonzi/machine_max/common/attachment/LivingEntityEyesightAttachment.java#onTick` 将真实世界射线送入 `PPhase.PRE`，避免在主线程直接查询真实物理世界；但 `targetBodyCache` 是普通 HashMap，由物理线程清空和写入、由主线程 getter 消费。`sortedTargetBodyCache` 等 CopyOnWriteArraySet 的 `clear` 与 `addAll` 分为两次发布，不构成跨集合的完整结果替换。`getHitPoint` 又组合共享的 `startPos`、`view` 与传入结果的比例，不能保证它们来自同一条射线。

修正方向是：提交任务时捕获本次不可变射线输入；物理线程在局部容器中完成查询、过滤、排序和命中点计算；最后通过单个 volatile 引用一次发布不可变结果。消费方每次操作只读一次该引用，不跨集合拼接结果。对同一刚体的多个命中保留最近有效值，不能让按升序遍历时后面的 `put` 覆盖较近命中。共享结果中保留世界命中点、目标身份、输入射线与采样序号，使读方无需重新读取真实刚体来恢复命中信息。发布结果中的实体在使用前再次检查存活、Level 与 `entity.subPart` 绑定关系；部件重建、变体切换、实体移除、维度卸载和断线时使相应记录失效。

索引构造在物理空闲阶段读取形状，不在渲染调用里 `listChildren()` 或调用会读取真实刚体的懒初始化。普通帧不重新解析模型或建立 native 对象。

### 4.3 每条命中的有效性

§4.0.1 定义公共解析器的规则；本节补齐 ProjectileUtil 部件候选的适配条件，任一失败就令该候选返回 Optional.empty：

1. 候选是仍存活、位于当前 Level 且绑定关系吻合的 MMPartEntity；resolve 保留的其他 owner 不在此转换为部件实体。
2. 当前快照的 SubPart 索引中有该部件；解析器只为 `findPickableHitBox` 返回非 null 的子形状生成结果。
3. 实体通过原版谓词；§3 的原版循环继续处理 root vehicle 与 `canRiderInteract()` 的乘客排除规则。不在共享物理查询中笼统排除整辆载具，以免车内可用部件失去选择入口。
4. 子形状映射走 `SubPart.findPickableHitBox` 与 `InteractBoxes.findInteractBox`，禁止使用带兜底的 `SubPart.getHitBox(int)` / `InteractBoxes.getInteractBox(int)`。wheel 的一般判定圆柱保留；辅助球体与圆柱的来源见 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/attr/SubPartAttr.java#getCollisionShape`。
5. 世界命中点有限，并符合该重载的射线和距离条件；原版循环仍执行自己的距离比较。

结果为空、实体刚出生尚无快照、子形状映射缺失时，本次不生成部件命中；不退回整块 AABB 精选。这样缺失精确数据不会使空间中的空白区域成为阻挡。

引擎查询是否覆盖同一 compound 的多个子形状，要由本机 native 回归钉住。源码中 `../Libbulletjme/src/main/native/glue/com_jme3_bullet_CollisionSpace.cpp#JmeRayResultCallback` 返回 1，且 compound 遍历会逐子形状回调，依据是 `../Libbulletjme/src/main/native/bullet3/BulletCollision/CollisionDispatch/btCollisionWorld.cpp#rayTestSingleInternal`。当前实现依赖每条有效子形状都出现在回调结果中；若本机回归显示只能拿到第一条，需要补子形状查询。

### 4.4 距离、内部起点与原版边界

包装器仅替换部件候选的求交点，不提前按玩家实体交互距离删掉部件。私有 `GameRenderer.pick` 的最后一层过滤保持原版语义：实体在实体交互距离之外、但位于方块之前时，结果可能是 MISS，不自动改选后方方块。

部件不使用 `AABB.contains(eye)` 制造零距离命中，也不把原版 `getPickRadius()` 膨胀量套在部件形状上。眼睛位于大 AABB 内但处于各实际形状之间的空隙时，射线仍应正常选择面前目标。

眼睛确实位于某个实心形状内部时，采用 Bullet 正向射线的内部起点语义；P3 验收需对 box、cylinder、capsule、sphere 实测并记录结果，不能用整个部件 AABB 代替形状内外判定。这一情况与“位于驾驶舱空隙”分开验收。

## 5. 近战与原版交互的接续

优胜部件生成 `EntityHitResult(partEntity, preciseWorldHitPoint)`。外层公共 `GameRenderer.pick` 统一写入 `Minecraft.hitResult` 与 `Minecraft.crosshairPickEntity`。不只写其中一个字段。

攻击、命名牌、履带物品和中键继续走原版实体入口；独立的 `LivingEntityEyesightAttachment` 上车/工具选择保持其用途。原版实体右键管线见 [NeoForge 1.21.1 文档](https://docs.neoforged.net/docs/1.21.1/items/interactionpipeline/)。在实体 `interact()` 返回 PASS 不是重新射线选择方块的机制，穿透必须在 pick 阶段决定。

服务端继续接收原版 `ServerboundInteractPacket`；客户端精确命中不作为服务端伤害权威，原版交互包仍不携带客户端指定的 HitBox。`MMPartEntity.hurt` 的服务端物理射线与 BFDamageContext 管线承担伤害定位。

### 5.1 投射物接续与单次分发

统一接入涵盖 Minecraft 源码中的三条入口（均位于 §2 所述 sources jar）：`net/minecraft/world/entity/projectile/AbstractArrow.java#findHitEntity` 转调 Level 重载，`net/minecraft/world/entity/projectile/ThrowableProjectile.java#tick` 与 `net/minecraft/world/entity/projectile/AbstractHurtingProjectile.java#tick` 使用 `ProjectileUtil.getHitResultOnMoveVector`，由其内部进入 float 重载。距离排序、方块截短后的射线段、`canHitEntity` 谓词与箭矢穿透忽略列表由这些原版调用链继续提供。

本文“穿透箭”专指原版弩的 Piercing（穿透）附魔产生的箭矢多实体命中：等级 I–IV，成功命中的实体数上限为等级加一。它不是 Machine-Max 的装甲穿深或 RHA 判定，也不是普通箭、雪球等所有投射物默认具有的能力。官方行为说明见 [Minecraft 1.14 Java 发布说明的 Piercing 小节](https://feedback.minecraft.net/hc/en-us/articles/360027306551-Minecraft-Village-Pillage-1-14-0-Java)。1.21.1 的具体代码依据为同一 sources jar 内 `net/minecraft/world/entity/projectile/AbstractArrow.java#getPierceLevel`、`#onHitEntity` 与 `#canHitEntity`：命中过的实体 ID 加入忽略集合，后续查询通过谓词跳过它们。

`src/main/java/io/github/sweetzonzi/machine_max/common/entity/MMPartEntity.java#hurt` 的投射物分支依赖 `IProjectileMixin` 中的命中点、法线、HitBox 和 SubPart。由 `src/main/java/io/github/sweetzonzi/machine_max/common/entity/PartHitHandler.java#onProjectileHit` 在实际命中时调用与 ProjectileUtil 共用的射线解析核心，取得这些完整数据，再按现有 IProjectileMixin 通道交给伤害管线。完整数据无需经过 getEntityHitResult 的返回值传递。

具体流程为：从事件取出目标 MMPartEntity；取得本次原版候选查询的输入；用相同起终点调用共享射线方法；在解析结果中应用该次查询的实体谓词，再确认最近有效部件与事件目标一致；将复核得到的命中点、法线、HitBox 与 SubPart 一起写入既有通道。复核不命中或目标不一致时按现有事件机制拒绝本次部件命中，不把伤害转交给另一个目标。不能借用观察者 Eyesight 的射线输入，也不能自行延长射线后忽略原版过滤条件。

为独立复核保留的只是 `RayQueryContext(from, to, predicate)`，不包含完整伤害几何。ProjectileUtil 的返回类型保持普通 EntityHitResult；返回部件命中时，在投射物侧以返回结果实例的身份关联这份输入上下文，Handler 按事件中的结果实例读取。该关联支持同 tick 多次查询：以结果实例为键，不同查询互不覆盖；使用后立即移除，避免串用或长期持有谓词引用。

例如箭矢先成功命中仍存活的 A，原版将 A 加入忽略集合，再沿同一运动段选中 B；Handler 对 B 复核时必须应用该次谓词并跳过 A。未经谓词筛选就取原始列表中的第一块部件会错误否决 B。这个过滤属于调用方目标选择策略，公共 RayHitResolver 继续只解析和过滤物理形状。

这里共用的是几何与过滤算法，不要求三个调用方共享同一个结果对象。实际命中事件允许执行一次独立复核，完整伤害数据来自这次复核；不建立跨查询的完整几何搬运协议。命中通道中的数据应以本次分发为作用域，不能让取消、偏转或下一次查询沿用上次命中的字段。

同文件的补充命中路径由 `ProjectileHitCoverage` 控制：`EntityTickEvent.Pre` 为每个投射物记录本 tick 运动段起点；候选查询标记“已覆盖”，实际命中事件标记“已产生原版命中”；`EntityTickEvent.Post` 只对两者都不成立且未被移除的投射物执行补充查询，调用 `machine_Max$manualProjectileHit`。对完全绕过 ProjectileUtil 的第三方投射物，补充查询使用本 tick 实际运动段，并至少通过相同的部件形状过滤与方块遮挡约束；如其自身已有伤害回调，也必须复用该回调而非再施加一次伤害。

上述覆盖标记必须绑定投射物身份与 tick，不是跨调用的“上一次用了什么”的全局变量。箭矢穿透循环中的每一次查询拥有独立命中结果，以原版忽略列表筛选后续实体；共享射线方法只返回数据，不自行发伤害或消耗投射物。兼容入口的范围由调用链核对与测试确定，不因其类继承 Projectile 就无条件手动调用 onHit。PartHitHandler 的兼容补充查询也调用相同的共享射线方法。

必须验收一个已有边界：`MMPartEntity.hurt` 对生物来源用固定 5 格射线，且可能把伤害交给射线命中的其他 SubPart；原版攻击包只带目标实体，没有本次客户端 HitBox 信息。若精确拾取的测试暴露“选中 A、伤害到 B”或交互距离属性下的漏伤，应在玩家近战分支做针对性修正：使用玩家交互距离与原版服务端容差，校验服务端真实命中与被攻击实体一致，再进入既有伤害管线。不得让不一致的目标静默重定向伤害；也不把该修正扩散到爆炸、投射物和非玩家生物伤害。

## 6. 完整 AABB 与渲染剔除

`MMPartEntity.makeBoundingBox` 返回完整刚体世界 AABB 并缓存到 `cachedWorldAabb`；实体空间查询、原版交互距离校验与渲染剔除共用这一份。`blocksBuilding = false` 与原版实体碰撞配置保持各自职责；不通过拾取代码改变物理接触或方块放置占位规则。

`PartEntityRenderer.shouldRender` 从 `getBoundingBoxForCulling()` 取盒，主动轮再经 `TrackRenderer.cullingAabb` 并入履带范围，规则为：

```text
普通部件：完整刚体 AABB
履带主动轮：完整刚体 AABB ∪ 所属整条履带 AABB
```

这里的“静态 AABB”指几何范围按部件完整刚体盒确定；世界位置和刚体旋转变化时正常更新世界 AABB。骨骼动画、悬挂模型偏移、出生效果的 1.3 倍缩放，以及渲染插值中间姿态超出该盒而造成的边缘剔除均可接受。本期不建立逐骨骼边界缓存、动画全程包络或旋转扫掠包围球。

主动轮的特殊处理依据是 `src/main/java/io/github/sweetzonzi/machine_max/client/render/renderer/TrackRenderer.java#renderTrack`：只有主动轮实体绘制整条履带。`TrackRenderer.cullingAabb` 按当前轮组位姿现算整条履带包络，计入履带厚度、宽度和型号单节几何的静态外伸，不保留跨帧缓存；创建、断带、解散、型号资源重载和主动轮变更在下一次求值时体现。范围计算限于履带路径，不建立通用 PartRenderBounds 系统。普通成员轮使用自己的完整刚体盒。

该合并只影响主动轮的剔除盒，不扩大其 getBoundingBox 或射线交互形状。无需为了履带链节相位逐节重建模型边界；剔除盒是包住整条履带的保守 AABB。

远近渲染分派保持既有距离规则。`src/main/java/io/github/sweetzonzi/machine_max/client/render/renderer/DistantVehicleRenderer.java#render` 自有远近阈值，不能只修改近处渲染器的距离门而制造两条管线的空档或重复；距离分派的重构单列后续工作。视锥验收在近处实体管线负责的距离内进行，并另测交接边缘。

| 世界坐标约 ±1.5e7；旋转部件、薄形状 | 双精度射线端点不先量化为 float；记录模型与快照自身精度的剩余限制 |
| 创建首 tick、部件重建、维度切换、卸载、断线 | 缺失/过期记录不生成错误命中、不保留跨 Level 引用 |

| 箭矢、三叉戟、抛射物高速穿过部件间隙；部件表面命中 | 间隙可穿透；表面只触发一次原版命中，伤害使用的 HitBox、法线与命中点均来自 Handler 的同次复核 |
| 原版穿透附魔箭依次命中两个仍存活的部件 A、B | B 的 Handler 复核沿用其查询谓词，跳过已在原版忽略列表中的 A；两个目标各结算一次 |
| 事件取消、偏转、同 tick 多次查询 | 原版返回结果与其输入上下文逐次对应；没有补充命中重放或上次伤害几何残留 |
| 射线擦过 float 重载膨胀 AABB，但没有碰到部件形状 | 部件不因 AABB 宽容量被误命中；普通实体维持该调用的膨胀规则 |
| 第三方投射物未走 ProjectileUtil，或有自定义命中回调 | 兼容路径按实际运动段和遮挡判定；同一次碰撞只有一条伤害分发 |

P3 验收时自动化分两层：纯逻辑测激活/身份过滤、命中点、边界与记录失效；裸 Bullet 测 compound 子形状、wheel 与双精度射线。接线测试必须覆盖“空 AABB 后方普通实体”“AABB 内起点但没有形状命中”“实际表面远近与 AABB 远近相反”“一次方法调用有多个部件候选但只执行一次物理射线”，并确认两个执行循环的重载均已接入、委托重载没有重复查询。投射物 GameTest 验证命中次数、伤害次数、遮挡、穿透与取消；客户端 runClient 验证准星注入及视锥、Iris 阴影与多人交互。测试不放 Mixin 独占包；服务端 GameTest 不能代替客户端 pick 接线验收。

所有 Gradle 命令使用 `gradlew --offline`。P0–P2 已接入代码并通过离线 `compileJava` 与 `test`；P3 的客户端/多人运行期验收、§4.2 的 Eyesight 结果发布修正尚未执行。本文不把文档审查或现有自动化测试当作这些场景的运行验收。
