## 1. 目标、已落地的基线与范围

### 1.1 目标行为

1. 车体两侧各 13 块爆反砖，每块是独立的耐久单元；被达到灵敏度的攻击命中的砖当场失效并从模型上消失，其余 12 块不受影响。
2. 砖在有效期内提供约 78 mm 等效装甲（`thickness` 65 × `rha` 1.2），失效后该处只剩内层裙板（30 mm）。
3. 生效与消失的判据是"这块砖被**足够强**的攻击命中过"，不是"累计受到多少伤害"：入砖穿深达到灵敏度阈值（默认 50 mm 等效穿深）即引爆失效，当次是否击穿无关；低于阈值的攻击既不引爆、也不磨损它。碰撞冲击不引爆。
4. 砖的 78 mm 等效装甲不随宿主耐久衰减；命中音效与火花的既有语义不变。

## 3. 命中钩子 `onHit`

### 3.1 为什么 `onHurt` 不够

`onHurt` 只在**进口金额为正**时才被调用（S1 的 1080 行）。有一整类"命中已经发生、但金额为 0"的情形到不了它：

| 情形 | 金额为 0 的原因 |
| --- | --- |
| 未击穿且材质没有钝伤 | `calculateFinalDamage` 在 `unpen_power ≤ 0` 时返回 0，事件金额因此是 0 |
| 完全被 `damage_modifiers` 抹平 | `HitBox#modifyDamage` 的线性减伤把金额压到 0 |
| 碰撞冲击 | `COLLISION_IMPACT` 上下文不掷跳弹、不算穿深，小冲击被 `modifyArmorDamage` 归零 |

对普通装甲这没问题——没打出伤害就什么都不该发生。对爆反砖则相反：**挡住一发正是它该被引爆的时刻**。当前材料（`unpen_power: 2`）让未击穿的命中仍带钝伤，于是砖会掉耐久；那是标定值的副产品，既不足以表达"被打到了"，也不该被用来磨损砖（§5.3 第 3 条）。`onHit` 让"砖被打到了"这件事与伤害算术无关。

### 3.2 调用点

```java
// SubPart#settleAccumulatedDamage
if (event.isCanceled() || event.isTrackAbsorbed()) continue;   // 1078：没打到这块砖
// 复用 1072 行算出的 hitBox，不重算
if (hitBox != null && hitBox.getSubsystem() != null) {
    hitBox.getSubsystem().onHit(event);                        // 每个结算命中一次
}
float entryDamage = event.getDamageAmount();                    // 1079
if (entryDamage <= 0f) continue;                                // 1080
if (hitBox != null && hitBox.getSubsystem() != null) {
    hitBox.getSubsystem().onHurt(event);                        // 1082-1084 的既有调用
}
```

`findHitBox` 在 1072 行已经算过一次，实现时复用它、不要重算，也不要改变它与 `collectHitEffect` 的先后。

### 3.3 契约

| 项 | 约定 |
| --- | --- |
| 调用次数 | 每次结算命中恰好一次；与金额无关 |
| 调用时机 | 主线程、`onHurt` 之前；对事件的修改对随后的 `onHurt` 可见 |
| 不调用 | 入口取消（`isCanceled()`）、履带吸收（`isTrackAbsorbed()`） |
| 默认实现 | 空方法，不改任何状态 |
| 与 `onHurt` 的分工 | 金额与取消属于 `onHurt`；`onHit` 只表达"被命中了"，不承担伤害语义 |
| 线程 | `主线程`（与 `settleAccumulatedDamage` 相同），可以直接 `setDurability` |

### 3.4 同一 tick 的二次命中

一发弹在同一个结算批里两次命中同一块砖（多层穿透、爆炸射线的多个子步）时，第二次仍会走 `onHit`：砖的碰撞箱在 `updateActive` 下次重算前还是活跃的，`condition` 因此还没翻转。此时第一次调用已经把耐久归零，第二次调用按幂等处理（见 §5.3），不产生额外副作用。跨 tick 的第二次命中则被 `active` 挡掉，砖已经透明。

## 4. 爆炸射线按 `active` 过滤

### 4.1 三条射线路径的现状

| 路径 | 代码 | 是否过滤 `active` |
| --- | --- | --- |
| 投射物、玩家拾取、视线 | `RayHitResolver#resolve` → `SubPart#findPickableHitBox` | 是（S7） |
| 实体的非协议射线 | `common/entity/MMPartEntity.java`（248）显式 `if (!hitBox.isActive()) continue` | 是 |
| 爆炸射线 | `ExplosionInstance#rayTestRigid` → `SubPart#getHitBox(int)` | **否**（S9） |

后果：一块已经失效的爆反砖对投射物是透明的，对爆炸射流却仍是一块 65 mm 厚（78 mm 等效）的砖，而且会一直如此。射流被它按 78 mm 拦下，砖本身已经看不见了。

### 4.2 修改

`rayTestRigid` 里把 `subPart.getHitBox(tri)` 换成 `subPart.findPickableHitBox(tri)`，返回 `null` 时 `continue`：

```java
HitBox hitBox = subPart.findPickableHitBox(tri);
if (hitBox == null) continue;
```

两个方法用的是同一套子形状索引（`collisionShape.listChildren()[childIndex].getShape().nativeId()`），因此是可直接替换的一行。换成严格映射还顺带消掉 S8 的兜底：`getHitBox` 在索引越界或名字缺失时把命中算到任意一个框上，那条路径下 `rha`、穿深修正与累积键都取自与射线无关的框。

### 4.3 连带语义

- **失效框对爆炸透明**：与投射物一致。
- **轮胎辅助球体不参与爆炸命中**：当前 `getHitBox` 不看辅助球体标记，轮面辅助球因此也按装甲结算；`findPickableHitBox` 对"同时登记在 `isWheelSurface` 与 `wheelHalfWidths`"的球体返回 `null`，改装后爆炸只认一般判定用的圆柱。这是一次真实的行为变更，需要在 §9 里用实机爆炸对轮胎确认。
- **越界不再落到任意框**：S8 的兜底在爆炸路径上失效，代价是那一次命中不再登记累积——比记到错的框上更接近事实。

## 5. 爆反子系统类型 `machine_max:reactive_armor`

### 5.1 为什么需要新类型

现有 `machine_max:basic` 的行为是"按伤害扣耐久"（S2、S3），而爆反砖要的是"被足够强的命中引爆，且不被小弹磨掉"。两者的差值不能靠现有字段表达：

| 方案 | 代价 |
| --- | --- |
| 给 `BasicAttr` 加 `consume_on_hit` 字段 | 每种类型的静态属性都内嵌一份 `BasicAttr`（26 个属性类引用它），而每个类型的 schema 文件各自内联一份 `basic_*` 属性块；新增字段要改 21 份 schema 并同步 11 份副本与技能快照，其中只有爆反砖用得上它 |
| 调 `basic_durability` 到 1 | 只能让"有伤害的命中"一次打死砖；零伤害命中（§3.1）依旧不消耗 |
| 新类型 | 一份静态属性、一份安装属性、一行登记、一份 schema |

新类型是代价最小且语义最直白的一条：爆反砖本来就是一个独立的功能类型。

### 5.2 字段

```json
{
  "$schema": "../docs/zh_cn/schemas/subsystem/subsystem_static_attr.schema.json",
  "type": "machine_max:reactive_armor",
  "basic_durability": 8,
  "pass_damage": false,
  "hidden": false,
  "trigger_penetration": 50
}
```

- `trigger_penetration` 是灵敏度阈值，单位 mm 等效穿深，取 50。这是新类型唯一真正新增的字段。
- 复用 `BasicSubsystemStaticAttr.BasicAttr` 与 `BasicSoundAttr`（S17）：`basic_durability` 是"存活位"，达到阈值的命中直接把它归零，因此数值只影响 HUD 与维修读数；`pass_damage: false` 让砖拦下的命中不往车体传金额，穿透的弹丸继续飞行、由后面的框各自结算。
- `hidden: false`：砖的损坏状态要在 HUD 的子系统清单里可见，§1.2 的 26 条语言键就是清单上的名字。
- 声音一律留空：爆反起爆的专属音效不在本轮（§11 D4），缺省值即静音事件，不加 `sounds` 段。

### 5.3 类与登记

继承 `BasicSubsystem` 复用落点与音效，覆盖两处行为：**阈值引爆**与**不按伤害磨损**。

```java
// common/mech/subsystem/ReactiveArmorSubsystem.java
public class ReactiveArmorSubsystem extends BasicSubsystem {
    public ReactiveArmorSubsystem(ISubsystemHost owner, String name, ReactiveArmorSubsystemAttr attr) {
        super(owner, name, attr);
    }

    /** 静态属性在父类里是 BasicSubsystemStaticAttr 类型，这里收窄回本类型。 */
    private ReactiveArmorSubsystemStaticAttr era() {
        return (ReactiveArmorSubsystemStaticAttr) attr.getStaticAttribute();
    }

    @Override
    public void onHit(SubPartDamageEvent.Pre event) {
        if (getDurability() <= 0f) return;                             // 幂等：同批第二次命中无副作用
        BFDamageContext ctx = event.getCtx();
        if (Boolean.TRUE.equals(ctx.extensions().get(MMDamageExtensions.COLLISION_IMPACT))) return;
        if (ctx.penetration() < era().getTriggerPenetration()) return;
        setDurability(0f);
    }

    @Override
    public void onHurt(SubPartDamageEvent.Pre event) {
        // 砖拦下的伤害不往车体传；不调 super.onHurt，耐久只由 onHit 的阈值决定
        if (!era().getBasicAttr().passDamage()) event.setCanceled(true);
    }
}
```

配套三件：

1. `ReactiveArmorSubsystemAttr extends BasicSubsystemDynamicAttr`：自带 `CODEC` 单例（字段仍是 `definition`），`createSubsystem` 返回上面的类。
2. `ReactiveArmorSubsystemStaticAttr extends BasicSubsystemStaticAttr`：自带 `CODEC` 单例，在父类字段之上多一个 `trigger_penetration`（`Codec.FLOAT.optionalFieldOf("trigger_penetration", 50f)`），覆盖 `codec()` 返回自己的单例。动态侧构造器会把静态属性转型成 `BasicSubsystemStaticAttr`，所以静态侧必须是它的子类。
3. `SubsystemKinds` 的静态初始化里加一行 `register("reactive_armor", …)`（S16）。`SubsystemCodecs` 不用改，它按登记表分派。两个 Codec 必须是各自的新实例：登记表按实例身份反查类型 ID，与 `basic` 共用会直接抛异常。

三条判据的顺序即语义：

1. **碰撞冲击不引爆**：`COLLISION_IMPACT` 为真时（S22）上下文带的是撞击折算式伤害，`penetration` 取的是伤害量本身；不排除的话，蹭一下墙就能掀掉一块砖。
2. **穿深低于阈值不引爆**：读 `ctx.penetration()`，即**进砖之前**的穿深，不受本砖自己的 `penetration_modifiers`（§6）影响。爆炸射流走 `settleSubPart` 时把 `penetration` 写成该框在本批里的最大 `A_pen`（S10），因此射流与其他攻击走同一条判据。
3. **不磨损**：`onHurt` 不调 `super.onHurt`，`basic_durability` 不会被小弹的钝伤一点点磨掉——12.7 每发约 1.6 点钝伤，六发就能磨掉一块砖，那样"低于阈值不引爆"名存实亡。

摧毁状态仍由 `AbstractSubsystem#onTick` 在耐久归零后的下一 tick 翻转，动画与 `condition` 因此在下一次 `updateActive` 时生效（延迟与 S6 相同）。

### 5.4 被否决的备选

- **在 `HitBox` 上加"命中即摧毁子系统"的框级开关**：动作发生在子系统上，把开关放在框上会让"谁拥有耐久"变得更难读，也要在每个框上重复声明。
- **让 `BasicSubsystem` 对所有零伤害命中都调 `setDurability(0)`**：等于把 83 份 `pass_damage: false` 的子系统定义全部改成"一碰就碎"，与"弱点可修"的设计冲突。

## 6. 穿透修正与数值标定

### 6.1 施加位置

`penetration_modifiers` 在 `SubPart#modifyPenetration`（S12）统一施加，三个消费点全部经过它：

| 消费点 | 位置 | 用途 |
| --- | --- | --- |
| 击穿判定 | `SubPart#resolvePenetration`（758-777） | 修正后的穿深与 `rha` 比较决定 PENETRATED / BLOCKED / RICOCHET |
| 投射物余速 | `BallisticProjectile#resolvePenetrationSpeed`（S19） | 修正后穿深折算能量，再换回速度；余速为 0 即弹丸销毁 |
| 爆炸射流 | `ExplosionInstance#consume`（S10） | `eta` 取修正后的穿深，未击穿则射线终止 |

施加位置选**专用材质**而不是共用材质：`m1a2_sep:m1a2_arat` 同时被炮塔附甲使用，直接改它会一并改掉炮塔。26 块砖因此改用美系基础包的 `machine_max:arat_ii`（ARAT II 瓦的材质）：`rha: 1.2`、`decay_rha` 与 `rha` 相同（§6.4）、`penetration_modifiers` 按来源分两段加性削弱（§6.3）。零件侧只写 `material` 与子系统 `definition`，不必逐框覆写；型号放在基础包里，后续美系车族可以直接复用同一份瓦。

### 6.2 单一加法常数的量级问题

加性的形状是对的，错在用一个常数覆盖所有弹种：取 `add -400` 时，它把 3BM42 与 57mm AP 一起压到 0（`apply` 见负即归零），于是连瓦都过不去：

| 弹种 | 原始穿深 | `add -400` 后 | 与 78 mm 比较 |
| --- | --- | --- | --- |
| 120mm M829 APFSDS | 550 | 150 | 击穿 |
| 125mm 3BM42 AP | 280 | 0（`apply` 见负即归零） | **未击穿** |
| 57mm BR281 AP | 130 | 0 | **未击穿** |
| 30mm 3UBR6 AP | 50 | 0 | 未击穿 |

3BM42 在实用距离上足以打穿 78 mm 的裙板瓦，`-400` 却让它连瓦都过不去；-400 同时把轻弹与重弹一起抹平，这条路不采用。加法要按来源分段：动能弹吃一个小的固定值，化学能再吃一个大值，两段都是 `add`（§6.3）。

### 6.3 这一轮的做法：按来源分段的加性削弱

爆反削掉的是**固定的穿透量**：飞板与装药把射流或杆截断一段，损失与来弹的总穿深无关。按比例削弱会让强弹损失更多毫米（M829 550 → 385 损失 165 mm，57mm AP 130 → 91 只损失 39 mm），等于让强弹替弱弹承担得更多，方向是反的。因此两段都用 `add`，只按伤害来源分段：动能与其它来源吃 −30，爆炸/射流再吃 −320（合计 −350）。

```json
"armor": {
  "rha": 1.2,
  "decay_rha": 1.2,
  "penetration_modifiers": [
    { "operation": "add", "value": -30, "condition": { "type": "always" } },
    { "operation": "add", "value": -320, "condition": {
        "type": "or",
        "conditions": [
          { "type": "damage_type", "id": "machine_max:blast" },
          { "type": "damage_tag", "id": "minecraft:is_explosion" }
        ] } }
  ]
}
```

两段都是起点值（§11 D3），作用在两条路径上：

| 弹种 | 原始穿深 | 修正后 | 与 78 mm 比较 | 备注 |
| --- | --- | --- | --- | --- |
| 120mm M829 | 550 | 520 | 击穿 | 余速下降 |
| 125mm 3BM42 | 280 | 250 | 击穿 | 余速下降 |
| 57mm BR281 | 130 | 100 | 击穿 | 余速下降 |
| 30mm 3UBR6 | 50 | 20 | 未击穿 | 本来也不到 78 |
| 爆炸射流（`A_pen` 500） | 500 | 150 | 击穿，`eta` 0.75 → 0.43 | 化学能段合计 −350 |
| 152mm 9M133 射流（1200） | 1200 | 850 | 击穿，`eta` 0.88 → 0.84 | 重射流仍以近全长穿过 |

两条路径的读法不同，但方向一致：

- **动能路径**：修正后的穿深同时进击穿判定（S12）与余速换算（S19）。加性把余速压下去，于是弹丸穿过第一块瓦之后对内层板的威胁变小——这正是爆反对动能弹该有的效果，而且重弹与轻弹各自损失同样的 30 mm，不再按比例放大。
- **爆炸射流路径**：`eta` 是**保留**比例（S11），穿深越小保留越少。射流吃的是两段之和 −350，穿过瓦后只剩三成到四成的能量；下降方向与动能路径一致，不能写反。

动能段不能超过 52 mm：57mm BR281（130）减到 78 及以下就会被瓦直接挡住，翻转“57mm 能打穿裙板”的结论。化学能段的量级由射流决定：9M133 的 1200 mm 射流在 −350 之后仍有 850 mm，穿瓦只掉约 4 个百分点的能量，说明单块瓦拦不住重型反坦克导弹——与实车 ARAT II 的定位一致，要拦住它得靠多块瓦与内层板叠加。

### 6.4 RHA 不随宿主衰减

`getRHA` 的耐久比取自**宿主 SubPart**（S13），不是砖自己的耐久。`m1a2_arat` 材质本身是 `decay_rha: 0.2`、`decay_power: 1.5`，照它算，车体裙板掉到半血时单块砖只剩 36 mm、掉到三成只剩约 24 mm。

爆反的等效来自装药，装药不会因为基甲受损而变弱，因此爆反瓦用自己的材质 `machine_max:arat_ii`，把 `decay_rha` 写成与 `rha` 相同的 `1.2`。S13 的系数是 `decay_rha + (rha − decay_rha) × ratio^decay_power`，两项相等时系数恒为 1.2，单块瓦恒定在 65 × 1.2 = 78 mm，直到被打掉。`m1a2_arat` 的 0.2 继续作用于炮塔附甲（66 mm 那两块），那两块按既有设定随耐久衰减。

若沿用材质的 `decay_rha: 0.2`，单块砖会随宿主耐久这样掉：

| 宿主耐久比 | 单块砖 RHA |
| --- | --- |
| 100% | 78 mm |
| 50% | 36 mm |
| 30% | 24 mm |

上表是专用材质要避开的情形：裙板跟着车体一起变弱，会让"爆反完好但基甲受损"的车侧凭空少掉三成到七成防护。

## 7. 明确不做

1. **不做"已摧毁子系统不吸收伤害"的全局改动**。`BasicSubsystem` 在耐久为 0 且 `pass_damage: false` 时仍会取消事件（S3），剩余的窗口是"同一次结算批"与"爆炸路径未过滤 `active`"。后者由 §4 修掉，前者由 §3.4 认定为可接受的一 tick 窗口。全局改这条会触碰 83 份 `pass_damage: false` 的子系统定义（另有 251 处同名字段出现在 JSON 里，含各包 schema 副本），代价与本特性的收益不成比例。
2. **`condition` 里 Molang 子系统名的静态校验**。`subsystem` 字段的拼错已由 `HitBoxAttr#validate` 在装载期拦下（S14）；`condition` 里的名字写错时 `local.subsystem_destroyed` 返回 0（S18），框恒为激活。Molang 表达式可以拼接字符串，静态校验必然有假阴性，本轮不改。
3. **把 26 个框的活性判据从 Molang 换成随子系统存活**。那会把"每个物理步 26 次 Molang 求值"换成一次布尔读，但它是全局语义变更（所有绑定了子系统的框都会随子系统失效），需要先有性能数据。
4. **爆炸自伤与链式引爆**。爆反失效时不产生爆炸，没有自伤源，因此不需要 `ignoredKeys` 与攻击者归属。
5. **不给"未触发的砖"单独降低防护**。砖的 78 mm 是"外壳 + 装药"的整体近似，装药只是其中一部分；把它拆成"反应层 + 外壳"两个框才能让未触发状态弱一些，代价是每个位置翻倍框数，而现有的内层裙板已经在砖被打掉后提供 30 mm。理由详见 §12 Q9。

## 12. 自检记录与待裁定问题

本节是写作时的自检结论，供审阅方逐条裁定；每条给出正文里的落点。

| 编号 | 质疑 | 结论 |
| --- | --- | --- |
| Q1 | 穿深修正为什么给砖单开一份材质 | `m1a2_sep:m1a2_arat` 被 `m1a2_turret_armor.json` 的两处命中箱共用，直接改它会一并改掉炮塔；改用基础包的 `machine_max:arat_ii` 既保住炮塔的衰减曲线，又让后续美系车共用一个型号（§6.1） |
| Q2 | 为什么不用 `add -400` 这类加法常数 | 它同时把 3BM42（280）与 57mm AP（130）压到 0，连 78 mm 的砖都过不去（§6.2） |
| Q3 | 爆炸射流的方向是否被说反 | `eta` 是**保留**比例（S11），减小穿深即减小保留；§6.3 的结论按这个方向写 |
| Q4 | `onHit` 会不会在客户端跑 | 不会：`settleAccumulatedDamage` 首行按 `level.isClientSide()` 直接返回（S1） |
| Q5 | 换类型会不会让旧存档的砖复活或凭空爆掉 | 不会：存档只写 `durability_ratio` 与摧毁标记（`AbstractSubsystem#saveData`，602-610），与类型无关；已打掉的砖读回比例 0，按耐久判毁 |
| Q6 | `onHit` 会不会打乱命中表现的顺序 | 不会：`collectHitEffect`（1075-1077）在 `onHit` 之前，`onHit` 紧接 1078 行的跳过之后（§3.2） |
| Q7 | 失效框被跳过之后，一次爆炸会不会因为穿过去而反而更痛 | 是：这正是 T02 的目的——失效砖不再替车体挡射流，射流按后面的内层板结算 |

| Q8 | 轻武器能不能打掉一块砖 | 不能：`onHurt` 不调 `super.onHurt`，耐久只由阈值决定。若沿用 `basic` 的按伤害扣耐久，12.7 每发约 1.6 点钝伤、六发就能磨掉，阈值就白设了（§5.3 第 3 条） |
| Q9 | 触发不了它的攻击又打不穿它，是否自相矛盾 | 不矛盾：78 mm 是"外壳 + 装药"的整体近似，轻武器打不穿的是整体，不是单独那层装药。要让"未触发状态"弱一些就得把砖拆成反应层与外壳两层框，成本见 §7 第 5 条 |
| Q10 | 爆炸射流怎么过灵敏度阈值 | 射流的 `penetration` 是该框在本批里的最大 `A_pen`（§5.3 第 2 条），量级数百，远高于阈值；不带口径的伤害（摔伤、近战）穿深为伤害量本身，通常低于阈值，因此不会误引爆 |

需要审阅方裁定的仍是 §11 的 D3 与 D5 两个数值：加性的 −30／−320 与灵敏度 50 都是起点值，要靠实机对打标定。
