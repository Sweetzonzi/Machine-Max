# Machine-Max 渲染 — 屏幕空间光照物理化设计

> **状态**：阶段 A、B、C、D1、D2、D3 已实现（2026-10-17 落地 A–D1，2026-10-18 落地 D2 与 D3）。`shaders/program/screen_space_light.fsh` 采用"线性空间 + `1/d²`/窗 + 朝向响应 + 有界合成曲线 + 沿视线积分的空气散射光晕 + 屏幕空间十字星芒"，`LightMinDist[16]` 逐槽上传 `d_min`、`LightGlow[32]` 逐槽上传光晕的阈值半径与倍率、`LightGlare[16]` 逐槽上传星芒倍率，13 个弹种与两处代码缺省写入了绝对辐照度。
>
> **本文自包含**：符号、公式、参数默认值与判据都在文内给出，不要求先读其他文档。§1 给出被替换的基线算子，后文的对比都以它为准；引用现有代码只为定位。

**术语**：E = 辐照度（照到表面上的光，单位面积功率）；L = 辐亮度（表面/空气沿视线发出的光，相机看到的量）；ρ = 反照率（表面反射比例，0–1）；I = 光源光强（本文用归一化单位，见 §4.1）；R = 剔除半径；`w` = 有限支撑窗函数。

## 1. 基线算子与它的问题

### 1.1 基线算子

本节给出下文所有对比所用的基线算子。仓库里已经没有这段代码，公式完整列在这里，理解后文只需这一节。

```glsl
att    = (1 − d/R)²;                       // d = 表面点到光心的距离
light += color × (att × intensity);        // 逐光源求和
light  = min(light, 1);                    // 硬截断
out    = src + light × (1 − src);          // screen 混合，sRGB 显示空间
```

一条光源贡献的是**与表面无关的常数 RGB**：不知道表面反照率、不知道法线、不做 `1/d²`、不在线性空间、没有色调映射。

### 1.2 三个可量化的缺陷

| 缺陷 | 数学原因 | 观感 |
| --- | --- | --- |
| 衰减形状是"平板" | `(1 − d/R)²` 在 `d = R/2` 时恒为 0.25，与大半径配对时整片区域亮度几乎不随距离变化 | 大范围均匀发亮，没有"光池"的层次 |
| 合成算子压低对比 | `out = src + L(1 − src)`：暗像素吃满 L、亮像素几乎不变，加一次就把动态范围向 1 压缩 | 纹理细节被抹平，像刷了一层漆 |
| 硬截断成纯白 | `min(L,1)` 之后超出部分直接变纯白；`intensity` 越大只是白斑越大 | "更亮"表现为"更白、更大的一片白" |

还有一层色彩上的问题：`light` 是近白颜色时，R/G/B 被等量抬高；screen 混合又压缩通道差，于是**色相一起被洗掉**——红墙也会发白。物理上，白光照明提高的是亮度，色相由反照率保持不变。

### 1.3 信号弹的计算实例（`flare_illum`：R = 40 m，基线 intensity = 1.8，color ≈ (1.00, 0.93, 0.80)）

信号弹悬在 20 m 高时，正下方地面 `d ≈ 20`，`att = (1 − 0.5)² = 0.25`，于是

```text
L ≈ 0.45 × (1.00, 0.93, 0.80) = (0.45, 0.42, 0.36)
```

- 影响球落在地面上是一个半径 `√(40² − 20²) ≈ 34.6 m` 的圆盘，中心 0.45、边缘 0——**大面积近似均匀**。
- 夜间地面 `src ≈ 0.04 ~ 0.12`，叠加后 `out ≈ 0.47 ~ 0.50`：纹理对比从 0.08 压到 0.03。
- 近白光色 + screen 混合：地面上任何颜色都被推向同一种淡黄灰。

这就是"被涂白"：它不是亮度高，而是**对比与色相同时丢失**。

### 1.4 枪口火光的对照（120 mm：R = 20 m，基线 intensity = 2）

| d (m) | `att` | `L` | 结果 |
| --- | --- | --- | --- |
| 2 | 0.81 | 1.62 | 截断 → 纯白 |
| 5 | 0.56 | 1.13 | 截断 → 纯白 |
| 10 | 0.25 | 0.50 | 半亮 |
| 20 | 0 | 0 | 无 |

炮口周围是"纯白圆心 + 一圈过渡到 0.5 的盘"，不是"离得越近越刺眼、向外平滑衰减的光池"。

## 2. 物理模型

点光源在表面点 P 处产生的辐照度：

```text
E(P) = I · max(cos θ, 0) / d²        θ = 表面法线与入射方向夹角
```

漫反射（Lambert）表面的出射辐亮度：

```text
L = (ρ / π) · E
```

相机看到的最终值是曝光与色调曲线的结果：`display = tonemap(exposure · L)`。空气里看到的光晕是**散射**，沿视线积分：

```text
L_air = ∫ σs · p(θ) · I / d² ds
```

这四项里，我们手上只有 depth（→ 表面点 P 与距离 d）。缺：

| 量 | 现状 | 影响 |
| --- | --- | --- |
| 法线 | 从深度重建（S4，见 §3.5） | 已有 `cos θ`；仍是屏幕空间的一阶近似，拿不到逐顶点法线细节 |
| 反照率 ρ | 最终颜色里与已有光照乘在一起，无法分离 | 无法"让白墙亮、黑墙暗"，这是根本限制 |
| 曝光 | 画面已经被原版渲染器曝光并编码 | 新增光只能以"增量"形式叠加，不能重新曝光整帧 |

因此**在这条链里做不到物理正确的表面光照**；能做的是采用"物理形状 + 合理近似"的算子，让结果在观感上符合物理直觉。

## 3. 可达近似

### 3.1 在线性空间里做

`src` 是 sRGB 编码的显示值。与光照相加必须在线性辐射度上进行，落地用的是精确分段函数而不是 `pow(x, 2.2)`：

```glsl
vec3 srgbToLinear(vec3 c) {                 // 与光源表提交侧的换算同源
    vec3 low  = c / 12.92;
    vec3 high = pow((c + 0.055) / 1.055, vec3(2.4));
    return mix(high, low, lessThanEqual(c, vec3(0.04045)));
}
vec3 linearToSrgb(vec3 c) {                 // 编码回显示值
    vec3 low  = c * 12.92;
    vec3 high = 1.055 * pow(c, vec3(1.0 / 2.4)) - 0.055;
    return mix(high, low, lessThanEqual(c, vec3(0.0031308)));
}
```

未受光的像素直接旁路：`e` 全零时着色器不进入解码/编码，原样返回 `src`；某个通道 `e` 为零时该通道同样保持原始编码值。因此**没有光源的地方逐位不变**，不存在"解码再编码"的浮点抖动。

**光源颜色同样要解码**：内容包里的颜色是 sRGB 的 `[0,255]`，直接当线性系数用会让暖色偏冷（线性 `(1, 0.85, 0.60)` 与 sRGB `(1, 0.93, 0.80)` 不是同一个颜色）。换算在光源表写入槽位时完成一次（`ScreenSpaceLightBuffer#write`），着色器只接收线性 RGB。

### 3.2 衰减：`1/d²` + 有限支撑窗

```text
w(d) = (1 − (d/R)⁴)²        d < R 时为 1→0，d ≥ R 时为 0
E_i  = c_i · I_i(t) · w(d_i) / max(d_i², d_min,i²) · V_i · B_i · N_i
```

其中 `c_i` 是线性光色、`I_i(t)` 含内容强度与时间包络、`V_i` 是遮挡、`B_i` 是锥角响应（球光为 1）、`N_i = max(N·L_i, 0)` 是朝向响应。逐项乘进同一条 E，最后求和得到 §3.3 的 `e`。

- `1/d²` 给出物理的近距离陡增与远距离长尾；`R` 只承担**剔除**与**窗**，不参与亮度（修掉 §1.2 的耦合）。
- `(1 − (d/R)⁴)²` 在 `d = R` 处严格归零且一阶导为零，包围剔除不会在边界留硬边。
- `d_min`（0.5–0.75 m，逐来源，见 §4.3）截住 `d → 0` 的奇点，避免光源贴在表面上时出现无穷大。
- `N_i` 是朝向响应：`max((1 − w) + w·max(N·L_i, 0), 0)`，法线由邻域深度重建、权重 `w` 在配置里可调（§3.5）。

### 3.3 合成：先累加，再一次有界映射

所有光源先在线性空间逐通道求和（**求和后再合成一次**，因此结果与遍历顺序无关），再用同一条曲线映射到显示值：

```text
q     = C + β(1 − C)
C_out = (C + e ⊙ q) / (1 + e ⊙ q) = 1 − (1 − C) / (1 + e ⊙ q)
```

`e` 是求和后的光照响应（逐通道、非负），`C` 是解码后的线性显示 RGB（`[0,1]`），`β` 是暗部补偿常数（取 0.03），乘除均逐通道。

**推导**：设虚拟亮度 `H = C/(1−C)`，令 `H' = H + e(H+β)`，再取 `C_out = H'/(1+H')`，代入化简即得上式。`H` 只是构造增亮曲线的中间量，不代表恢复出了真实 HDR 或反照率。

**性质**（`0 ≤ C ≤ 1`、`e ≥ 0`）：

| 性质 | 内容 |
| --- | --- |
| 零光恒等 | `e = 0` 且无光晕时 `C_out = C`；这种像素直接旁路，画面逐位不变 |
| 输出有界 | 恒在 `[0,1]`；分母 `1 + e·q ≥ 1`，不会除零，也不需要编码前硬截断 |
| 灰阶单调 | `∂C_out/∂C = (1+e) / [1 + e(β + (1−β)C)]² > 0`（固定 `e`、逐通道） |
| 光色隔离 | `e` 逐通道，某通道 `e = 0` 时该通道不动；纯蓝光不会抬红通道 |
| 端点行为 | `C = 0` 时 `C_out = eβ/(1+eβ)`（黑面被照成随光色的暗色）；`C = 1` 时恒为 1 |
| 强光饱和 | `e → ∞` 时 `C_out → 1`，渐进饱和，没有硬截断 |

着色器里的合成部分（`screen_space_light.fsh`）：

```glsl
vec3 C     = srgbToLinear(src.rgb);                        // 解码
vec3 q     = C + DARK_BOOST * (vec3(1.0) - C);             // β = 0.03
vec3 outL  = vec3(1.0) - (vec3(1.0) - C) / (vec3(1.0) + e * q);
outL      += glow;                                         // 空气散射，线性叠加、不进曲线（§3.6）
vec3 enc   = linearToSrgb(outL);                           // 编码
enc = mix(enc, src.rgb, lessThanEqual(e + glow, vec3(0.0)));  // 两者都为零的通道逐位旁路
```

**为什么不用另外三种写法**：

| 算子 | 问题 |
| --- | --- |
| 纯加性 `C + e` | 抬得动夜间暗面，但平等加在所有通道上，压平细节、去饱和，且会削顶 |
| 纯乘性 `C × (1 + k·e)` | 保色相、保纹理，但抬不动近黑的地面（0.03 × 2 仍是 0.06）；且乘性系数若取自亮度就是中性增亮，彩色光会点亮其它通道 |
| 基线 screen（§1.1） | 压对比、去饱和，`min(L,1)` 之后直接变纯白 |

**`β` 的代价**：`q` 逐通道，暗通道的 `β(1−C)` 占比更大，所以暗部的饱和色会轻微去饱和。`β = 0.03` 时 `(0.1, 0, 0)` 在白光 `e = 1` 下变为 `(0.201, 0.029, 0.029)`，比例仍约 7:1；`β` 越大，黑色材质越容易被抬灰，因此保持小值。

`E` 逐光源钳到 `[0, E_MAX]`（着色器常量 1024），兜住异常内容：曲线本身有界，但内容里的强度没有上界。

### 3.4 光晕与 bloom 的分工

信号弹"看起来亮"的主体是空气散射，而不是把 40 m 地面刷亮。表面光照与光晕是两个物理量：前者是**表面反射**进眼睛的光，后者是**视线上的空气**散射进眼睛的光。光晕在同一个片元 pass 里、在合成曲线之后叠加，设计见 §3.6。

镜头 bloom 是另一条链路：它会给太阳、火把、岩浆一并加光，而且帧已经过色调映射，阈值要重新设计，不并入本设计。

### 3.5 朝向响应（S4）：从邻域深度重建法线

`N` 从深度快照重建，不需要额外的反照率或法线缓冲：每个像素在横竖两条轴上各取一个相邻像素，重建出视空间切向，叉积得到法线，再用 `dot(N, −P)` 校正到朝相机的一侧。

**轮廓保护**：每条轴只用与中心深度更接近的那一侧作切向。轮廓处另一侧是别的物体，用它算出的斜率不是本平面的斜率；两侧都不可信（天空、近裁面）或切向退化时，该像素回落为 `o = 1`——少乘法线项，而不是把轮廓画黑。取侧规则让代价固定为每像素 4 次深度采样，与光源数无关。

**权重**：`o = max((1 − w) + w·max(dot(N, L̂), 0), 0)`，`w` 由客户端配置 `screen_space_light_normal_weight` 给出，取值范围 `[0, 1]`，缺省 0.5。`w = 0` 时整段跳过、不发生任何额外采样，算子与 §3.2 里不含 `N_i` 的形式逐位一致；`w = 1` 时就是 `max(cos, 0)`。

插值放在钳零之前，这一顺序是刻意的：掠射面（`cos = 0`）保留 `1 − w` 的底，而真正背光的面（`cos ≤ −(1 − w)/w`）恒为 0，权重不会把墙的背面照亮。缺省 0.5 即常见的 wrap lighting（`0.5 + 0.5·cos`）：竖直的交叉面片（草、蕨）在 `cos ≈ 0.1` 处拿到 0.55，背向光源的面按角度递减、在 `cos = −1` 处归零。取满 1 时，草叶在高处光源下 `cos ≈ 0` 会保持原版的暗色、在受光地面里变成黑点——几何上没错，但草叶发亮靠的是透射与多次散射，单次 Lambert 没有这两项。

**对观感的影响**：低处光源对地面的照射按 `cos θ = h/√(h²+r²)` 折减，光源越高折减越小。以车顶炮塔（约 1.5 m）为例：水平距离 1 m 处 0.83、3 m 处 0.45、5 m 处 0.29、10 m 处 0.15；35 m 高空的信号弹在 20 m 内不小于 0.87。因此枪口与爆炸的地面光斑会收紧，曳光对地面的亮带会显著变弱，信号弹的光池基本不变。

**与标定的关系**：§4.2 的反解式假设 `N = 1`（灰板正对光源），表里的 `I` 就是这个条件下的反解值；朝向响应改变的是"场景里有没有正对光源的面"，不改变 `I` 的定义。实机若觉得低处光源的地面光照不足，先降 `NormalWeight`，再考虑抬高 `I`——后者会让贴近光源的车体与炮管过曝。

### 3.6 光晕：空气散射（D2）

视线穿过被照亮的空气时，散射进眼睛的光构成光晕。它不乘表面颜色、不过合成曲线，是加在最终线性值上的一项。

**沿视线解析积分**。设视空间光心 `C`、归一化视线方向 `d`，撞击参数 `tc = dot(C, d)`、垂距 `b = sqrt(|C|² − tc²)`；在阈值半径 `Rg` 内：

```text
h    = sqrt(Rg² − b²)                      弦半长
t0   = max(0, tc − h)
t1   = min(tc + h, t_hit)                  深度截断
I0   = (1/b) · [atan((t1 − tc)/b) − atan((t0 − tc)/b)]
glow = Scatter · k · color_lin · I · I0 · win(b/Rg)
```

`I0` 是 `∫ 1/r² dt` 的解析解，`win(x) = (1 − x⁴)²` 与 §3.2 同一条窗，在 `b = Rg` 处把值压到 0。`Scatter` 是全局强度系数，`k` 是逐来源倍率（§4.3）。两条前置判断：`b ≥ Rg` 直接跳过（弦长为虚数），`t1 ≤ t0` 也直接跳过（表面在光晕球之前，可见段里没有空气）；`b` 用该光源的 `d_min` 截断，视线正穿光心时不会发散。

**遮挡来自 `t_hit`**。深度快照给出沿视线第一个表面的距离，空气只在它前面可见：按 `t_hit` 截断后，墙会把积分截短，光心在墙后则区间为空、贡献为 0。这是本方案不需要额外采样就获得逐像素遮挡的原因。换算容易写错：表面点是 `vec3(q, −1) · zfwd`，其到相机的真实距离是 `zfwd · L`，`L = sqrt(1 + |q|²)`，必须乘上 `L`。

**天空是光晕的主要背景**。深度取到端点值时没有表面，`t_hit = ∞`，取整段弦；因此本像素不能按表面光照的天空分支提前返回，要按"表面项为 0、光晕照算"处理。

**合成位置**。光晕加在合成曲线之后、编码之前：

```glsl
lit  = 1 − (1 − C) / (1 + e·q);   // 表面光照，过曲线
lit += glow;                       // 空气散射，线性叠加
```

天空的线性值接近 0，`q ≈ β = 0.03`，把光晕并进 `e` 会被曲线吃掉。D2 落地后，§3.3 的"未受光像素逐位不变"要收窄为"无光晕且未受光的像素逐位不变"。

**阈值半径是观感参数，不是几何尺寸**。`Rg` 的含义是"光晕在这里淡到看不见"，等价于把 `1/sinθ` 的长尾在阈值处截断：

| 量 | 普通自发光物体 | 空气散射光晕 |
| --- | --- | --- |
| 角尺寸 | `∝ 1/D`（`atan(R/D)`） | `∝ 1/D`（`atan(Rg/D)`） |
| 固定角偏移处的亮度 | 与 `D` 无关（辐亮度沿视线守恒） | `∝ 1/D` |
| 总通量 | `∝ 1/D²` | `∝ 1/D` |

所以"更远更小"与普通物体同律，"更远更暗"比物体慢——这正是远处灯光在夜里仍然可见的原因。若把形状固定成屏幕角度，远处就不会缩小：那是镜头成像（§3.7）或 sprite/bloom，不属于散射。

**半径按亮度派生**：`Rg = GlowScale · sqrt(I_base) · k`。理想模型里阈值半径正比于 `I`；这条链的帧经过色调映射，用 `sqrt` 压缩后更接近观感。半径用**基础强度** `I_base`（不乘时间包络），尺寸在闪烁期间稳定；亮度项用**当前包络强度** `I`，所以火焰熄灭时是变暗而不是缩小。

**`R` 不参与**。照明半径只决定表面光照的剔除与窗（§3.2），光晕只看亮度。当前标定下 `I ∝ R²`（§4.2 的 `d_ref = R/2`），于是 `sqrt(I) ∝ R`：**同一组锚点与光色下 `Rg` 与 `R` 之比恒定**，换锚点或光色则整体平移。`GlowScale = 0.32` 时各来源的 `Rg/R`：枪口 0.32（锚点与光色相同，逐弹种严格恒定）、曳光 0.18–0.26（光色不同，暖色偏大）、爆炸 0.52、信号弹 0.31。这是标定的副作用，不是依赖关系。

**倍率 `k`** 同时缩放 `Rg` 与 `glow`：`k = 1` 为标定值，`k = 0` 关闭该光源的光晕，`k > 1` 更大更亮。内容包三处可选字段：`visual.tracer_glow`、`visual.muzzle_flash.glow`、爆炸参数的 `light.glow`，缺省 1.0，非负且**没有上界**。

**曳光在缺省倍率下没有可见光晕**，这是 `glow ∝ I` 的直接后果，不是实现缺失：曳光的 `I` 比信号弹低两三个数量级，`Rg` 只有 0.5–1.3 m，视线必须落在 3° 以内才穿得进光晕球，峰值又只有 1e-4 量级（7.62 mm，10 m 处）。`k` 写 10 才到 0.038（显示值约 0.21），写 30 到 0.12。因此 `tracer_glow` 的定位是"需要时放大"，不是常规开关；缺省倍率下可见的光晕来自信号弹、枪口与爆炸。

**上限**：`Rg` 钳到 32 m；光晕与星芒的加法之和逐通道钳到 `GLOW_MAX`（§3.7），兜住异常内容与贴脸光源。

**契约**：逐槽两个 float，`LightGlow[32]`（阈值半径 m、倍率），与 `LightView[64]` / `LightColor[64]` / `LightTol[16]` / `LightOcclusion[16]` / `LightMinDist[16]` 并列，链加载期的 `verifyArrayCounts` 核验这一项的长度（星芒另有一条 `LightGlare[16]`，见 §3.7）。半径与倍率都在光源表写入时算好（`ScreenSpaceLightBuffer#glowRadius`），因此 `ScreenSpaceLight` 携带**基础强度**：它的 `intensity` 已经乘过时间包络，不能拿来推半径；基础强度由来源在提交时用 `setGlow` 填入，取内容强度、不含类别倍率与全局倍率。着色器只做积分，不做 `sqrt`。影响球取 `max(R, Rg)`，否则 `Rg > R` 的光源会在剔除处丢掉光晕；着色器的垂距剔除同样用 `max(R, Rg)`。

**v1 不做的两项**：相位函数（看向光源与侧视亮度相同；真实散射前向增强）与多次散射（光晕之间的相互照亮），都留作后续。

### 3.7 星芒：镜头成像（D3）

D2 与 D3 是两种不同的东西：光晕是**空气散射**（光在路上被散射进视线），星芒是**镜头成像**
（光圈衍射叠上传感器饱和溢出）。两者可以同时出现在同一盏灯上，参数却完全不共用：

| 量 | D2 光晕（空气散射） | D3 星芒（镜头成像） |
| --- | --- | --- |
| 角尺寸 | `atan(Rg/D)`，按 `1/D` 缩小 | 固定角度（2°–22°），与 `D` 无关 |
| 固定角偏移处的亮度 | `∝ 1/D` | `∝ 1/D²` |
| 遮挡 | 按像素深度截断（墙前的空气没有光晕） | 不截断；只要求光源自身可见 |
| 形状 | 以光心为心的圆 | 沿屏幕 ±x / ±y 的四条窄臂 |
| 内容开关 | `glow` 倍率 `k` | `glare` 倍率 `g` |

固定角度是镜头成像的必然：星芒是光圈在像面上留下的图案，尺度由 `λ/D_aperture` 决定，换多远
都是同一个角度。远处的路灯有光晕而没有星芒，正是因为 `1/D²` 掉得比 `1/D` 快。

**形态**。星芒画在**画幅**上而不是世界里（星芒滤镜与光圈叶片固定在镜头上，转动视角时十字不跟着
转），因此不需要任何视空间向量运算，只要光心的屏幕投影与像素偏移：

```text
lightPx  = 屏幕中心 + FocalPx · (C.xy / zc)          与遮挡判定用同一个投影
dp       = px − lightPx
thPx     = θ · FocalPx                               角长 → 像素
ux       = |dp.x| / thPx,  uy = |dp.y| / thPx
armX     = (1 − ux)^1.5 · exp(−(dp.y / σx)²)           横臂：沿 x 衰减、横跨 y 收窄
armY     = (1 − uy)^1.5 · exp(−(dp.x / σy)²)           竖臂
σx       = 屏高 × 0.0022 · (1 − 0.55·ux)              向臂尖收窄（1080p 上根部 2.4 px → 臂尖 1.1 px）
starburst = color_lin · A · max(armX, armY)
```

`(1 − u)^1.5` 沿臂缓慢衰减、在臂尖平滑归零，所以不需要 §3.2 的窗函数也不会留硬边；取 `max` 而不是求和，让两条
臂在光心处合成一个干净的点而不是一块方块。宽度**向臂尖收窄**：可见宽度由"峰值亮度压过阈值的范围"决定，亮度沿臂
下降时它会自己变窄，若再用 σ 外扩去抵消就会得到一根等宽长条。按信号弹 30 m 的实测参数，可见宽度从根部的 9.5 px
收到臂尖的 2.2 px，臂长 226 px——这是照片里星芒的形状（根粗尖细）。

宽度同样按**屏高比例**取而不是固定像素：它决定屏幕上一条线有多宽，1–2 px 以下会随镜头转动逐帧闪烁（这条链没有
时域抗锯齿），按屏高取让 720p 与 4K 上的相对粗细一致。方框剔除（`|dp| > thPx`）把每盏灯的求值限制在边长
`2·thPx` 的方块内，22° 在 1080p 上约 296 px 见方。

**亮度与臂长由相机处的表观照度驱动**：

```text
L_app = I / max(|C|², d_min²)                        镜头处的照度，I 含时间包络
s     = L_app / (L_app + GlareHalf)                  0 → 1 饱和
θ     = GlareMin + (GlareMax − GlareMin) · s
A     = GlareGain · s · g
```

用 `I/d²` 而不是 `I`：星芒表达的是"这盏灯在画面里有多刺眼"，与它在 1 m 处的绝对强度无关。
用带包络的 `I` 而不是基础强度：闪光熄灭时星芒**变短变暗**，与真实过曝的收尾一致——这与 D2
"尺寸稳定、只有亮度变"刻意相反，因为两者依赖的是不同的物理量（D2 的长度由阈值半径决定）。
`s` 让近处不爆表：`L_app` 从 0.15 跨到 15 两个数量级，`s` 只从 0.20 走到 0.96。

`g` 同时缩放亮度（线性）与臂长（开方）。**臂长另有像素封顶**：`thPx ≤ 0.45 · 屏高`。默认视场
（垂直 70°）下 22° 是 296 px，封顶不参与；炮镜一类的小视场会把同一个角度放大到铺满画面，这条封顶只在
那里生效。

**不被前景截断**。星芒生成在镜头内，不照亮任何东西：墙挡住光源时整条消失（光源自身的遮挡判定
仍生效，见 §3.2 的 `LightOcclusion`），但光源可见时星芒会压在墙与车体上——真实相机拍到的就是压在
前景上的十字。这是它与 D2 最本质的差别，也就不必把 `t_hit` 接进星芒。

**合成**。星芒与光晕一样是曲线之后的线性加法，两者共用同一个 `GLOW_MAX = 4.0` 的加法预算：

```glsl
lit = 1 − (1 − C) / (1 + e·q);         // 表面光照
lit += min(glow + glare, vec3(GLOW_MAX));
```

**代价**：每盏灯在方框内多两次 `exp` 与几次乘加，方框外只有四次比较；遮挡采样的次数不变
（它与 D2 共用同一次光源级判定）。**v1 不做**：衍射的真实角度—强度关系（取决于光圈形状与曝光，
无法建模）、鬼影（沿"光心—画面中心"连线对称的次级镜像）、时域抖动抑制。星芒只有一层剖面，
没有"亮核 + 宽尾"的两级结构。


## 4. 参数与标定

### 4.1 `intensity` 的语义

`I` 是**光源在 1 m 处的辐照度**（归一化单位，不是坎德拉）：`I = 1` 表示在 1 m 处 `E = 1`。不引入真实单位，是因为这条链没有曝光量，绝对单位不可校准；取 1 m 处归一化可以让内容数值与观感一一对应。

三个量各管一件事，互不派生：

| 量 | 管什么 | 不管什么 |
| --- | --- | --- |
| `radius` | 剔除范围与窗宽（`1/d²` 的长尾截在哪里） | 亮度 |
| `intensity` | 照明水平（参考距离上把参考灰板抬多高） | 范围 |
| `duration_ticks` / 时间包络 | 随时间的衰减 | 峰值 |

`I` 逐弹种写显式值，**不从半径或口径自动派生**：同样口径的枪与炮、不同的装药与炮口装置，可以给出不同的值。

来源提交时先把内容强度乘上类别倍率与时间包络得到 `I_i(t)`，再乘进 `E_i`；`g`（光照响应倍率）并进已有的总倍率与类别倍率，不单独占 uniform。

### 4.2 从目标灰度反解 `I`

标定不是凭感觉调数字，而是指定"在参考距离上把参考灰板从多亮抬到多亮"，再反解。由 §3.3 的曲线解出所需响应：

```text
e_target = (y − c) / ((1 − y) [c + β(1 − c)])
```

再用衰减式反推光源强度（`Y_light` 是线性光色的亮度，`g` 在标定时取 1）：

```text
I = e_target · max(d_ref², d_min²) / (w(d_ref) · Y_light)
```

`c` 是参考灰板在无光帧的线性显示值，`y` 是希望达到的值，`d_ref` 取 `R/2`（窗函数在这个位置约 0.88，光照分布最具代表性）。反推式假设 `V = B = N = 1`——无遮挡、球光、灰板正对光源；实测场景里按实际遮挡与朝向修正。

**算例**：120 mm 枪口火光，`R = 20`、`d_ref = 10 m`、灰板 `c = 0.10 → y = 0.30`、`β = 0.03`、线性光色 `(1.00, 0.578, 0.188)` 的亮度 `Y = 0.639`：

```text
e_target = (0.30 − 0.10) / (0.70 × (0.10 + 0.03 × 0.90)) = 2.249
I        = 2.249 × 100 / (0.879 × 0.639) ≈ 400
```

仓库内 13 个弹种与两处代码缺省按同一组锚点反解，写入值如下（`R` 为内容包解析后的半径，`d_ref = R/2`）：

表里是**首轮标定起点**，不是最终值；锚点本身也要按 §4.4 的实机观感调整。代码缺省值取同一张表的中档：`MuzzleFlash.DEFAULT.intensity = 90`（50 mm 档）、`ExplosionLightParams.DEFAULT.intensity = 166`、`VisualProperties.DEFAULT.tracerLightIntensity = 3.0`（7.62 mm 档）。

### 4.3 全局常量

| 常量 | 落地值 | 作用 |
| --- | --- | --- |
| `β` | 0.03（着色器 `DARK_BOOST`） | 暗部补偿；越大越容易把黑色材质抬灰 |
| `d_min` | 曳光与枪口 0.5 m、爆炸 0.75 m（光源表逐槽上传） | `1/d²` 的奇点截断；贴得越近的来源取值越小 |
| `E_MAX` | 1024（着色器 `E_MAX`） | 单光源辐照度上限，兜异常内容 |
| `D_MIN_FLOOR` | 0.001 m（着色器） | `d_min` 配 0 且表面点正好落在光心时避免 `0/0` |
| `NormalWeight` | 0.5（配置 `screen_space_light_normal_weight`） | 朝向响应权重；`o = max((1 − w) + w·cos, 0)`，0 关闭法线项，1 为完整 Lambert 项 |
| `g` | 1 | 光照响应倍率；并进已有的总倍率与类别倍率 |
| `GlowScale` | 0.32 m | 阈值半径 `Rg = GlowScale·sqrt(I_base)·k`；`I = 40` 时为 2.0 m |
| `Scatter` | 2.1e-4（着色器 `SCATTER`） | 光晕整体强度：信号弹停在 30 m 外、光晕中心接近饱和的反解值 |
| `k` | 1.0，非负、无上界（内容字段） | 逐来源光晕倍率，同时缩放 `Rg` 与亮度；0 关闭该光源的光晕。超过 `32 m / (GlowScale·sqrt(I_base))` 后半径封顶、只剩亮度增长 |
| `GLOW_MAX` | 4.0 | 光晕与星芒之和的逐通道上限（两者共用同一个加法预算） |
| `Rg` 上限 | 32 m | 兜异常内容与贴脸光源 |
| `GlareHalf` | 0.6 | 星芒饱和曲线的半值照度：`L_app` 等于它时臂长与亮度各取一半 |
| `GlareMin` / `GlareMax` | 2° / 22° | 臂长区间（画幅上的固定角度）；`g` 与像素封顶在其上再缩放 |
| `GlareGain` | 2.0（着色器 `GLARE_GAIN`） | 臂根亮度（线性，曲线之后）；2.0 即压到接近纯白 |
| `GlareSigma` / `GlareTaper` | 屏高的 0.22%（1080p 上 2.4 px）/ 0.55 | 臂根部横向标准差与收窄系数（臂尖为根部的 0.45 倍宽） |
| `g` | 1.0，非负、无上界（内容字段） | 逐来源星芒倍率，同时缩放臂根亮度与臂长；`0` 关闭该光源的星芒 |
| 臂长封顶 | 屏高的 45% | 小视场（炮镜倍率）下防止十字铺满画面 |

### 4.4 标定流程

固定场景与相机，每次只改一个量：

1. **灰阶序**：同一盏灯照在一片从 0.02 到 0.90 的灰阶上，5 个台阶必须保持顺序，且两端都不跳过相邻台阶（检验 `β` 是否过大）。
2. **夜景地面**：信号弹停在 20 m 高，调整 `I` 使光池中心亮度符合预期，同时记录被照区域的白像素占比与亮度标准差。
3. **车体侧面**：发射器单发，取炮口正对的装甲板，检查是否出现整块刷白。
4. **光色隔离**：把某盏灯临时改成纯蓝 `[0, 0, 255]`，画面里除蓝通道外不应有变化（检验逐通道性）。
5. **光晕（D2）**：夜间让信号弹停在 30 m 外，先定 `Scatter`，使光晕中心接近饱和、边缘在 15° 内淡出且看不到圆边；再把同一发信号弹放到 100 m 外，确认角半径按 `1/D` 缩小、亮度按 `1/D` 下降。枪口与爆炸的光晕等 `Scatter` 定下来之后，只调各自的 `k`。

每个场景记录：被照区域**白像素占比**（任一通道 ≥ 0.98）、**亮度标准差**（纹理是否还在）、**色相偏移**（与无光帧比较）。判据见 §7。

| D2 | 空气散射光晕：沿视线解析积分、深度截断、逐来源阈值半径 | 已实现：`screen_space_light.fsh` 的积分与 `SCATTER`/`GLOW_MAX`、`ScreenSpaceLight#setGlow`、`ScreenSpaceLightBuffer#glowRadius`、`LightGlow[32]` 上传、三个来源与三处内容字段 |
| D3 | 星芒/十字炫光：屏幕空间固定角度、由 `I/d²` 驱动、不被前景截断 | 已实现：`screen_space_light.fsh` 的四臂剖面与 `GLARE_*` 常量、`ScreenSpaceLight#setGlare`、`LightGlare[16]` 上传、三个来源与三处内容字段 |

A 与 B 在同一次改动里落地（只改片元算子与上传契约），C 是纯标定。

**上线前置**：`LightMinDist`、`LightGlow` 与 `LightGlare` 是程序 JSON 里的数组，改动数组声明之后必须
重启客户端（数组 `count` 在链加载期与 Java 数组长度比对）；只改数值不重启不算生效。`NormalWeight` 是
标量 uniform，随链重新加载生效，改权重只需退世界重进；片元里的 `SCATTER`/`GLOW_MAX`/`GLARE_*` 是着色器
常量，改它们要退世界重进而非重启。

## 6. 与现有实现和内容的关系

- **分层不变**：来源 → 光源表 → 效果三层与容量 16 都不变。数组契约有三个逐槽数组 `LightMinDist[16]`（`d_min`）、`LightGlow[32]`（`(Rg, k)`）与 `LightGlare[16]`（`g`），与已有的 `LightView[64]` / `LightColor[64]` / `LightTol[16]` / `LightOcclusion[16]` 并列，Java 侧在链加载期逐条核验长度（`ScreenSpaceLightEffect#verifyArrayCounts`）。朝向响应不需要逐槽数据，只有一个标量 uniform `NormalWeight`，由配置 `screen_space_light_normal_weight` 每帧上传。
- **同步**：枪口火光与曳光参数不进网络（两端各自加载同一份弹种数据）；爆炸火光的字段随起爆包一起过线，`light.glow` 与 `light.glare` 各让线格式多一个 float，`sync` 协议组因此到 `2.2.0`，两端必须同版本。
- **内容数值是绝对量**：`tracer_light_intensity`、爆炸参数 `light.intensity`、弹种 `muzzle_flash.intensity` 都表示"1 m 处辐照度"，数值按 §4.2 的表写入。外部内容包若沿用倍率语义的旧数值，会明显偏暗，需要按 §4.2 重标。
- **字段范围**：`muzzle_flash.intensity` 与爆炸 `light.intensity` 的上界是 4096（155 mm 枪口 638、信号弹 1524 都在范围内）；曳光强度没有范围限制。
- **光晕（D2）**：数组契约有 `LightGlow[32]`（每槽 `(Rg, k)` 两个 float），光源表的影响球取 `max(R, Rg)`；内容包有三个可选字段（`visual.tracer_glow`、`visual.muzzle_flash.glow`、爆炸参数的 `light.glow`），缺省 1.0，现有 13 个弹种不需要改。爆炸火光的 `light.glow` 进入 `ExplosionLightParams` 的编解码；曳光与枪口参数不进网络。
- **星芒（D3）**：数组契约有 `LightGlare[16]`（每槽一个 `g`），它不进影响球、也不参与任何派生——臂长与亮度都在片元里按 `I/d²` 现场求值。内容包同样有三个可选字段（`visual.tracer_glare`、`visual.muzzle_flash.glare`、爆炸参数的 `light.glare`），缺省 1.0；爆炸的 `light.glare` 与 `light.glow` 一起改变线格式，`sync` 协议组为 `2.2.0`。
- **文档联动**：`docs/plan/进行中/渲染-屏幕空间光照通用化设计.md` 与本节口径一致；`docs/plan/计划中/武器系统-投射物曳光光照设计.md` §8.2 的"LDR 帧用 screen 混合而非加法"以本文 §3.3 的算子为准。

## 7. 验收

沿用本项目惯例：**主视图实机目视**，不建立像素级自动断言。每个场景同时记录上文的像素统计作为参考：

| 场景 | 判据 | 失败指向 |
| --- | --- | --- |
| 灰阶序 | 同一盏灯照在一片 5 级灰阶（0.02 / 0.10 / 0.30 / 0.60 / 0.90）上：顺序不反转，相邻台阶不互相跳过 | `β` 过大或该处 `e` 过大 |
| 光色隔离 | 把某盏灯临时改成纯蓝 `[0,0,255]`：画面除蓝通道外逐像素不变 | 合成曲线不是逐通道（回到了中性乘性/加法） |
| 信号弹悬停 | 地面出现半径约 10–20 m 的**光池**：中心亮、向外连续变暗；光照区内纹理与色相仍可辨；白像素占比不超过 5% | 衰减、`I` 或 `β` 不当 |
| 枪口单发 | 炮口附近有明亮核心，5 m 外是可见的柔和亮区；车体不被整块刷白 | `I` 过大或 `d_min` 过小 |
| 连射 | 持续光而非频闪；亮度不随射速线性增长到全白 | 重叠条目 × `I` 过大 |
| 曳光 | 弹道线经过处有细亮带，地面光斑不沿整条弹道连成一片 | 曳光 `I` 偏大或 `d_min` 偏大 |
| 爆炸 | 爆心亮、向外衰减；不与波前折射互相干扰 | 同爆炸火光参数 |
| 朝向 | 同一盏低处光源同时照地面与同距离的竖直墙面：两者亮度不同；背向光源的面不受光；物体轮廓不出现黑边或亮边 | 法线的取侧规则与回落条件（§3.5） |
| 光晕形状 | 夜间信号弹：光晕是以光源为心的圆、向外连续变暗，边缘没有可见的硬边 | `Rg` 与窗的配合、`Scatter` |
| 光晕遮挡 | 站在墙后看信号弹：墙前没有光晕；绕出墙角后光晕重新出现 | `t_hit` 截断或天空分支写错 |
| 光晕距离 | 同一发信号弹在 10 m 与 100 m 处分别观察：角半径按 `1/D` 缩小，亮度按 `1/D` 下降 | `Rg` 的派生式或 `Scatter` |
| 光晕关闭 | 把某弹种的 `tracer_glow` 设为 0：该弹种只剩表面光照，画面里没有它的光晕 | `k = 0` 没有短路到零半径 |
| 星芒形状 | 夜间信号弹：光心处是由两条正交窄臂组成的十字，臂沿屏幕 ±x/±y，向外连续变细变暗，臂尖没有可见的方角 | 剖面写成硬边，或 `GlareMax` 过大 |
| 星芒尺度 | 同一发信号弹在 10 m 与 100 m 处分别观察：臂长的**角度**不变、亮度按 `1/D²` 下降（10 m 处明显更长更亮） | `s` 曲线或 `GlareHalf` |
| 星芒门禁 | 站在墙后看信号弹：十字消失，绕出墙角后重新出现；把该弹种的 `glare` 设为 0：只剩表面光照与光晕 | 光源级遮挡与星芒共用了同一条门禁，或 `g = 0` 没有短路 |
| 星芒覆盖前景 | 光源贴着车体侧面时十字压在车体上 | 镜头成像的预期行为；若观感像 UI 叠加，降 `GlareMax` 或该来源的 `g` |
| 回归 | 无光晕的光源只改受光像素，天空与未受光像素逐位不变；关闭总开关时画面与无该效果一致；同一画面重复渲染两次结果逐位相同 | 线性化/编码的恒等性与旁路 |

数值参考（非硬门槛）：被照区域的亮度标准差应不低于无光帧的 60%；白像素占比 ≤ 5%（信号弹场景）。

## 8. 风险与未决

| 类别 | 内容 | 处理 |
| --- | --- | --- |
| 根本限制 | 没有反照率，无法真正区分"黑墙被照亮"与"白墙在阴影里" | 曲线只能按像素现值整体抬高；`β` 是替代手段，不声称物理正确 |
| 根本限制 | 画面已被曝光，新增光只能做增量 | 曲线作用在显示值上、输出有界；整帧 HDR 需要独立 HDR 通路，不在本设计内 |
| 已知近似 | `β > 0` 时暗部饱和色会轻微去饱和（`(0.1,0,0)` 在白光 `e=1` 下变 `(0.201,0.029,0.029)`） | `β` 取 0.03；实机若黑色材质发灰，先降 `β`，不要动 `I` |
| 内容迁移 | 13 个弹种、爆炸缺省与两处代码缺省的 `intensity` 都是绝对量，与旧内容包的数值不可比 | 首轮值已按 §4.2 写入，实机按 §4.4 重标；外部内容包同步重标 |
| 观感回归 | 曳光、爆炸、枪口火光的观感全部重做 | 按 §7 逐场景实机目视；标定表随实测更新 |
| 性能 | 每光源约 12 条 ALU（`1/d²`、窗、朝向点积、颜色乘、钳制），每像素额外 4 次深度采样（法线）与 2 次 `pow(vec3)`（解码与编码） | 深度采样与光源数无关，`NormalWeight = 0` 时归零；不改颜色采样数 |
| 光影兼容 | 只改颜色运算，不涉及深度快照与目标格式 | 原版/ Iris 都适用；按 §7 的同一套判据覆盖两种会话 |
| 已实现 | 朝向响应（S4）由邻域深度重建法线（§3.5） | 权重经 `screen_space_light_normal_weight` 调节；天空、近裁面与退化邻居处回落为 `o = 1`；折角处 1–2 像素可能取到相邻面的斜率，受光有轻微偏差 |
| 已知近似 | 竖直薄面片（草、蕨等交叉模型）在高处光源下 `cos ≈ 0`，几乎不受光；真实草叶靠透射与多次散射发亮 | 权重 0.5 时掠射面拿到一半；按材质区分需要额外的植物 mask，不在本设计内 |
| 观感（D2） | 空气亮起来之后，信号弹把地面刷亮一片会显得多余 | 实机标定时可下调 `flare_illum` 的照明半径（40 → 25–30 m）；当前仍取 40 m |
| 性能（D2） | 天空像素也要参与光晕计算，每光源多两次 `atan` 与一次除法 | 与表面项共用循环次数；`k = 0`、`b ≥ Rg`、`t1 ≤ t0` 三种情形直接跳过 |
| 叠加（D2） | 多发同时存在时光晕线性相加 | 逐光源与总和都逐通道钳到 `GLOW_MAX = 4.0` |
| 未决（D2） | 相位函数未做：看向光源与侧视亮度相同 | 各向同性；前向散射留作后续 |
| 未决（D2） | 烟尘、粒子不写深度，光晕会透过它们 | 已知近似；与爆炸烟尘同时出现时接受 |
| 观感（D2） | 曳光在缺省倍率下没有可见光晕（见 §3.6 的倍率一段） | 需要时把 `tracer_glow` 写到 10 以上；不作为回归项 |
| 观感（D3） | 星芒压在墙与自车车体上，可能被读成 UI 叠加 | 这是镜头成像的预期行为；嫌重就降 `GlareMax` 或该来源的 `glare` |
| 闪烁（D3） | 细臂在镜头转动时逐帧闪烁（本链没有时域抗锯齿） | 根部宽度按屏高取（1080p 上 2.4 px）并向臂尖收窄；枪口与爆炸只亮 6 tick，可辨的只有悬停的信号弹 |
| 小视场（D3） | 炮镜倍率把固定角度的星芒放大到铺满画面 | 臂长按屏高 45% 封顶 |
| 叠加（D3） | 星芒与光晕共用 `GLOW_MAX` 的加法预算，同屏多光源时互相挤占 | 逐通道钳制；要更亮就抬 `GLOW_MAX`，它同时抬高光晕 |
| 未决（D3） | 只有一层剖面，没有"亮核 + 宽尾"的两级结构，也没有鬼影 | 观感不足时再加一层剖面或一条沿"光心—画面中心"的次级镜像 |

## 附录 A · 公式与取值推导

**窗函数选择**：`(1 − (d/R)⁴)²` 在 `d = R` 处值与一阶导同时为 0，且中心附近接近 1，能把 `1/d²` 的长尾平滑截断；`(1 − d/R)²` 的中心平坦正是"平板"感的来源，不用于衰减。

**合成曲线的推导**：设虚拟亮度 `H = C/(1−C)`，令 `H' = H + e(H+β)`，取 `C_out = H'/(1+H')`。代入：

```text
H' = C(1+e)/(1−C) + eβ
C_out = [C(1+e) + eβ(1−C)] / [1−C + C(1+e) + eβ(1−C)]
      = [C(1+e) + eβ(1−C)] / [1 + eC + eβ(1−C)]
```

令 `q = C + β(1−C)`，分子分母同除 1 后即 `(C + eq)/(1 + eq)`。`H` 只是构造这条曲线的中间量，不代表真实 HDR 或反照率。

**单调性**：令 `q = β + (1−β)C`，则

```text
C_out = (C + eq)/(1 + eq)
dC_out/dC = (1 + e) / (1 + eq)²  > 0
```

**端点**：`C = 0` 时 `q = β`，`C_out = eβ/(1+eβ)`；`C = 1` 时 `q = 1`，`C_out = 1`。`e → ∞` 时对任何 `C > 0` 都有 `C_out → 1`。

**反解**：令 `C_out = y`、`C = c`：

```text
y(1 + eq) = c + eq  ⇒  y − c = eq(1 − y)  ⇒  e_target = (y − c) / ((1 − y)[c + β(1 − c)])
```
