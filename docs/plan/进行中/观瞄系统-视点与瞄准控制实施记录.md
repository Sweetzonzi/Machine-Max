### 2.1 2S38：车体座位、独立方向机／高低机

`Machine-Max_Builtin/machine_max/subsystems/weapon_controller/main_weapon_controller.json` 的 `aim_inputs` 顺序为 p0、p1、p2、p3、无后缀，因此样例中超控 p1 > 炮手 p2 > 备用无后缀。两个驱动定义的 `control_inputs` 都为 `["weapon_control"]`，该样例的竞争层级在 WC 输入。

2S38 主 SubPart 还有 `subsystem.machine_max.pktm_elevation_driver`，同样使用 `machine_max:basic_elevation_driver`。主 WC 广播 `weapon_control` 时可发现主炮和机枪的高低机。固定炮镜的目标正反解必须明确选用主炮机构，不能以 `WeaponControllerSubsystem.java#turrets` 的 HashMap 遍历顺序选第一条高低机。机枪机构应具有自己的几何适配，不能把主炮局部角当作任意高低机的世界欧拉角。

`src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/SubPart.java#getLerpedLocatorWorldTransform` 使用所属 SubPart 的刚体位姿合成静态挂点。因而上述炮塔主 SubPart 中的炮镜不会仅因挂点名而取得炮管俯仰。P5/P6 应明确光轴的实际绑定；配置中的炮镜位置可以保留在炮塔，朝向需要按重构方案 §7 绑定实际炮管。

方向机资源 `Machine-Max_Builtin/machine_max/connectors/turret_azimuth_axis.json` 的 yr 下限 1、上限 −1 表示连续回转；高低机资源 `turret_elevation_axis.json` 的 xr 限位为 −15° 到 60°。纯函数中的正 yaw 为右、正 pitch 为抬高；真实 New6Dof 的读数／伺服符号及连接点零位尚未通过运行实测，本批不把语义符号测试当作引擎符号验证。

## 3. 基础代码及使用边界

源码公共目录为 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/control/`。

| 模块 | 已实现契约 |
| --- | --- |
| `aim/AimGeometrySnapshot.java#forward` | 根位姿 → 方向机关节零位 → yaw → 高低机关节零位 → pitch → 光轴偏置；局部计算使用 JME Transform／Quaternion／Vector3f，构造时复制可变输入 |
| `aim/AimPose.java#AimPose` | 世界位置使用现有双精度 Vec3，旋转使用防御性复制的 JME Quaternion；作为位姿发布边界，不实现四元数或向量代数 |
| `aim/AimMath.java#solveAim` | 配对有限点正反解；局部阻尼解算、连续角分支及机械限位；反向驻点通过单轴搜索后细化 |
| `aim/AimMath.java#solveSingleAxisAim` | 固定无稳轴，单自由度搜索可达近似方向，退化时优先保持已有解 |
| `aim/AimMath.java#filterLead` | 30°新输入领先上限，零输入不裁既存目标，反向立即响应 |
| `aim/AimTargetState.java#AimTargetState` | 相对、双稳及两种单轴目标保持；applyMouse 更新预测目标，applyCommand 只向无稳轴施加增量 |
| `view/ViewMath.java#ViewMath` | 完整参考旋转合成、自由世界点保持、切入目标转换；输入显式给出逻辑观察原点 |

客户端第三人称状态位于 `src/main/java/io/github/sweetzonzi/machine_max/client/input/ThirdPersonViewpoint.java#ThirdPersonViewpoint`，持有相对观察角或世界点。可转设备直接按重构方案 §3 的实体子系统／属性结构接入，设备身份缓存和销毁／断线接线属于 P5；可转镜头观察角同步属于后续 TODO。

数学类型按职责选择：世界点与世界位移使用 Minecraft Vec3 的 double，局部轴和旋转使用现有 JME 数学库及 `jme3utilities.math.MyMath`／`MyQuaternion`。世界坐标相减之后才转换到局部 float。目标角和输入增量均使用现有 Vec2，x=pitch、y=yaw，单位为弧度，由 targetAngles／inputDelta 等参数名区分；AimAxisLimit 表达连续轴或有限轴的边界。共享几何快照复制 Transform／Quaternion／Vector3f，避免发布者修改同一对象影响消费者。

## 4. 输入交付与车长超控

车长超控由控制组切换完成：输出从备用频道切换至高优先级频道，退出时释放高频道，WC 按已有 aim_inputs 顺序选择有效来源；多个 WC 驱动同一执行机构时沿用 control_inputs 顺序。本模块不提供来源竞争仲裁器，也不定义同频道冲突时的额外选择规则。实际内容接线见本记录 §2.1；运行接入需验证重构方案 T20—T22。

跨线程逐条输入交付复用 `../Spark-Core/src/main/kotlin/cn/solarmoon/spark_core/util/TaskSubmitOffice.kt#submitImmediateTask`：该方法向对应 phase 的 ConcurrentLinkedDeque 逐项追加；`#processTasks` 逐项取出执行。接入时在 PhysicsLevel 上使用 PPhase.PRE，每次提交完整输入及其来源校验信息。同 tick 多次调用不能使用按键覆盖的 submitDeduplicatedTask。释放动作与输入消费在同一物理相位排序，过期会话不能恢复已释放的输出。这些是接入约束，当前 ViewInputPayload 路径尚未实施。

## 5. 验证与剩余验收

测试位于 `src/test/java/io/github/sweetzonzi/machine_max/control/`：

- `AimMathTest.java#AimMathTest`：T1—T6、T18/T19、T24 的数学部分；世界位置 ±2e7、横滚 0/30/90°、100 次连续输入、不同关节零位／符号、独立枢轴、有限边界和反向输入；另测 JME 输入修改不影响已发布几何。
- `ViewMathTest.java#ViewMathTest`：T10、T13—T15、T23 的纯观察部分，以及观察点与有限目标重合时的有限性。

Vec2 的 float 角累计按 1e-6 rad 检查，标量 double 输入过滤按 1e-12 rad 检查；经过 JME float 四元数的几何往返、连续输入等价性及观察方向按 1e-5 rad／单位方向误差检查，口径对应重构方案 §11.9 的 float 几何通道。世界点保持用 Vec3 精确相等检查，目标生成距离按 1e-9 m 检查。测试容差分别对应这些数据通道。

验证命令为 `.\gradlew --offline -g C:\Users\13680\.gradle test`。本轮全量测试成功（43 秒），134 条通过、失败 0、跳过 0，其中观瞄基础测试 15 条。观瞄基础测试不创建 Minecraft 世界或 native PhysicsSpace；全量任务包含仓库已有的 native 测试。

未运行 runClient、服务端启动、网络延迟实测或 schema 迁移验证。真实机构追赶、轴向、光轴绑定、来源释放和游戏画面均需后续按重构方案 §8.2、§11.9 验收；数学单测不能作为 P0—P6 整阶段完成的依据。
