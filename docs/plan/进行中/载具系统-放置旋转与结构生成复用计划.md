# 载具系统：放置旋转与结构生成复用计划

> **状态**：稳定放置锚点、玩家预览与服务端校验、无玩家实例化入口已实现。射程及同步容差的游戏内标定、客户端画面验收和结构生成调用方待完成。本计划不实现世界生成 processor。
> **日期**：2026-11-26
> **相关备忘**：[结构生成载具备忘](../计划中/载具系统-结构生成载具备忘.md)。

## 1. 目标

1. 蓝图和装配体预览默认按世界轴向摆放，并允许玩家在放置前选择世界 Y 轴朝向。
2. 将鼠标目标点、载具参考锚点、碰撞几何、预览和服务端确认统一到同一套放置变换。
3. 旋转与落点处理只作用于一次放置使用的数据副本，保留 `VehicleData`、蓝图和模板的现有持久化格式。
4. 把载具构造与入世整理成不依赖玩家和物品的服务端入口，后续结构生成可传入模板、目标地面锚点、参考根朝向和初始状态后复用。

## 2. 重构前基线

- `BaseVehicleItem` 的客户端预览与服务端放置各自计算目标变换，旋转固定为 `Quaternion.IDENTITY`。
- 瞄准射线长度使用玩家 `ENTITY_INTERACTION_RANGE`；目标位置通过 `VehicleData.min.y` 作竖直偏移。
- 放置包围盒来自 `VehicleData.min/max`，服务端用 `WorldSnapshot.contactTest` 检查，客户端预览则向活动物理世界提交接触查询。
- `VehicleCore.setTransform` 将全车位姿变换应用到各部件，但当前以 `partMap` 中第一个部件根零件作为参考姿态。
- `VehicleData.rebased()` 提供以原点为基准的副本；`VehicleData` 及其子零件位姿已有持久化和传输格式，本计划不增加朝向字段。
- Spark-Core 默认实体 PAWN 将由[WorldSnapshot 纳入 PAWN 查询计划](物理系统-WorldSnapshot纳入PAWN查询计划.md)纳入主线程只读快照；放置动态占位检查依赖该查询能力。静态地形仍需单独查询。

## 3. 设计决定

### 3.1 朝向只属于本次放置变换

### AABB 坐标语义

源几何始终从各子零件的物理碰撞形状按当前位姿现算；`VehicleData.min/max` 仅为旧格式兼容缓存，不参与放置、射程、预览或蓝图有效性判定，也不为缺失碰撞形状提供回退。

放置锚点不是旋转后世界 AABB 的 `bottomCenter`。先选择一个参考根子零件，将所有子零件的物理碰撞形状变换到该根的局部坐标系并合成局部 AABB；该局部 AABB 的 `bottomCenter` 是固定的载具局部锚点。目标位置表示这个固定局部锚点的地面投影：目标 XZ 由锚点投影对齐，目标 Y 表示地面高度；放置计算另按目标朝向下整体碰撞形状的最低 Y 自动确定竖直平移，使载具在平地上接地。用户和上层调用方不传载具高度，也不要求旋转后的世界 AABB 底心与目标点重合。

目标朝向下，各物理形状变换到世界系后合成的世界 XYZ 轴向 AABB 只用于预览、静态地形与动态碰撞校验、边界检查及尺寸估算。它随 yaw 改变，世界 AABB 的 `bottomCenter` 也可能移动；这不改变固定局部锚点的目标投影。放置射程取该朝向下世界 AABB 的 X/Z 较长边，不使用高度。

玩家选择的角度是放置请求中的临时世界朝向，不写回物品、蓝图或 `VehicleData`。初始角度为世界 Y 轴 yaw 0，旋转轴固定为世界竖直轴；首版不支持 pitch/roll。

复用现有部件安装角的增减按键：持有 `PartAssemblyItem` 时更新 `attachRotation`；持有 `AssemblyItem` 或 `VehicleBlueprintItem` 时更新 `VehicleAssemblyHelper` 中独立的 `vehiclePlacementYaw`。两种角度各自保存、互不覆盖；每次按键旋转 90°，并归一化到 `[0,360)`。输入仅在未打开界面、玩家允许使用物品且手持物品类型匹配时生效。该角度是客户端临时预览状态，不写入物品或载具数据。

客户端确认放置时发送单独的载具放置请求，携带使用的手、请求来源载具 ID（适用时）、目标地面锚点和 yaw。位置字段表示固定局部锚点应对齐到的世界地面点，不表示旋转后世界 AABB 的 `bottomCenter` 或载具实例 UUID。若物品使用内联 `VehicleData` 而没有模板 ID，来源 ID 可缺省，服务端仍以指定手中的实际物品为准。客户端提供的 ID 只用于核对请求上下文，不构成模板读取权限；服务端从手持物品解析载具数据并验证 ID 是否匹配。新载具实例 UUID 始终由服务端生成。

服务端校验物品仍在指定手中；请求携带来源 ID 时，核对它与手持物品解析结果匹配；yaw 必须是有限的 90° 倍数。服务端根据自身玩家视线和载具尺寸计算候选地面锚点，并校验请求位置在同步误差容限内、处于尺寸相关的允许放置范围且没有越界或穿墙，再用服务端解析的数据计算最终位姿与碰撞结果。视线误差容限和尺寸相关射程纳入 P0 标定。若需请求去重标识，它与模板 ID、载具实例 UUID 分开处理，并配合服务端限频。预览状态本身不构成服务端权限或权威数据。

### 3.2 以最大质量部件的根子零件建立稳定锚点坐标系

从载具各 `RegularPart` 中选择 `totalMass` 最大者，再取该部件的 `rootSubPart` 作为参考根。这样放置锚点坐标系与现有目标 yaw 的参考朝向使用同一个根，避免出现“按一个根定朝向、按另一个根定落点”的双重语义。最大质量并列时按稳定的部件 UUID 顺序决胜，不依赖 `HashMap` 或数据声明顺序。

通过参考根当前位姿的逆变换，将整车所有子零件物理碰撞形状映射到参考根局部坐标系并合成 AABB；取其 `getBottomCenter()` 作为固定局部锚点。该点不写入 `VehicleData` 或网络格式。计算放置位姿时，先将参考根朝向旋转到请求的世界 yaw，再平移整车，使固定局部锚点的世界 XZ 投影对齐目标地面锚点，并使目标朝向下整体碰撞形状的最低 Y 对齐目标地面高度。最终世界 AABB 重新计算，不再拿它的 `bottomCenter` 反向定义请求落点。

### 3.3 AABB 地形检测与动态形状查询

鼠标命中上表面时直接采用碰撞形状的实际命中点，半砖与台阶按命中的高度处理。命中侧面、底面或从碰撞体内部开始的命中不可放置；未命中时，射线终点是空中放置锚点。最低碰撞边界对齐锚点 Y，不尝试搜索支撑面、贴合坡度或推移到另一个落点。

整体 AABB 是首版地形拒绝判据。通过 `Level.noBlockCollision` 查候选包围盒的方块碰撞；每轴向内最多收缩 `1e-4` 格，避免把边界贴合判为穿透。若整体 AABB 因部件间空隙造成明显误报，可另行细化为逐 `RegularPart` 或逐 `SubPart` 检测。

变换后的总 AABB 同时服务预览边框、粗筛和尺寸估计。动态物体（玩家、现有载具）的占位由 `WorldSnapshot` 的物理形状查询判定，不用总 AABB 代替动态目标的最终形状接触检查。静态地形仍由明确的方块/地形查询覆盖。

### 3.4 放置净空与交互距离分离

瞄准射程取 `max(ENTITY_INTERACTION_RANGE, 目标朝向下 AABB 的 X/Z 较长边 ÷ 2 + 玩家宽度 ÷ 2 + 2 格)`。射程只决定看多远，不保证落点净空；是否侵入地形、玩家或其他载具以该落点的最终占位检查为准。客户端锚点与服务端瞄准锚点暂允许至多 1 格的距离误差，实际生成使用服务端检查过的锚点。射程和误差容差尚未在游戏内标定。

### 3.5 共用无玩家的服务端生成入口

将放置拆为两个边界清晰的阶段：

1. **请求解析**：玩家路径接收手、来源 ID（适用时）、目标地面锚点和 yaw，结合服务端手持物品与玩家净空规则验证；结构路径由 processor/延迟兑现器提供世界地面锚点、目标参考根朝向和可选随机状态。
2. **载具实例化与入世**：接收 `Level`、不可变 `VehicleData` 副本、目标地面锚点、目标参考根朝向和恢复/初始状态策略；检查所需区块与碰撞空间后构造 `VehicleCore`，应用全车位姿并经 `ObjectManager.addVehicle` 正式入世。数据坐标到世界坐标的刚体变换留在服务内部，不作为调用方必须构造的输入。

底层服务不得要求 `Player`、`ItemStack`、准星或交互距离。玩家输入和结构生成只负责提供不同的请求来源；载具数据校验、几何变换、碰撞判定和正式入世复用同一路径。

结构 processor、chunk attachment、随机耐久、幂等键和延迟兑现策略继续由结构生成备忘及后续专门计划定义。本计划只确保届时可以调用不依赖玩家的载具生成入口。

## 4. 实施阶段

### P0：数学与几何契约

1. 选取总质量最大的普通部件的 `rootSubPart`；同质量时取 UUID 自然顺序最小的部件。
2. 将全部物理碰撞形状变换到参考根局部坐标系并合成 AABB，以其 `bottomCenter` 固定局部锚点；测试该点映射到目标地面 XZ 后，yaw 0°/90°/180°/270° 间不漂移。
3. 定义鼠标命中到目标地面锚点的解析规则，明确水平支撑面、竖直墙面和斜面分别如何取得目标 XZ 与地面 Y。
4. 定义从“目标地面锚点 + 目标根朝向”求子零件最终位姿的规则：锚点投影对齐目标 XZ，目标朝向下整体最低 Y 对齐地面 Y；另测世界 AABB `bottomCenter` 随 yaw 变化不影响锚点。
5. 从最终子零件碰撞形状求世界总 AABB，用同一结果生成预览边框与方块/地形检测盒；标定 AABB 边界接触容差。
6. 标定最长轴净空的全长/半长公式、玩家碰撞半径与地形拒绝边界。
7. 标定客户端目标地面锚点与服务端视线候选锚点的允许误差，以及按载具尺寸扩展的视线射程。

### P1：统一放置几何与投影

1. 提供“目标地面锚点 + 目标根朝向”到最终子零件位姿的共用计算；数据到世界的刚体变换只作为实现细节，不作为 `Placement` 的公开字段或调用方输入。
2. 统一 `VehicleAnimatable` 的坐标语义：`updateTransform` / `setTransform` 接收目标放置位姿，其中 translation 表示目标地面锚点、rotation 表示目标参考根朝向；它不是数据坐标到世界坐标的刚体变换。两者都从规范源子零件位姿计算结果；`updateTransform` 逐件调用插值更新，`setTransform` 立即设置。删除专用的 `updatePlacementPose`，不得在预览路径另起一套子零件坐标变换。
3. 世界预览首次使用 `setTransform` 落位，后续 tick 使用 `updateTransform` 保留插值。物品展示将参考根对齐坐标轴，在同一锚点语义下平移至碰撞盒几何中心居中，不读取质量加权中心。
4. 若需要移动已存在的 `VehicleCore`，提供接收同一目标锚点语义的高层入口；不要直接把当前以 `partMap` 首个根零件为枢轴的 `VehicleCore.setTransform` 当成锚点 API。
5. 保留 `VehicleCore` 的正式构造与 `ObjectManager.addVehicle` 生命周期；实例 UUID 在每次成功请求中独立生成，不修改原始模板或增加序列化字段。

### P2：玩家朝向输入和服务端请求

1. 在 `VehicleAssemblyHelper` 增加独立的客户端 `vehiclePlacementYaw`；复用现有角度增减按键，按当前手持物品上下文分别更新部件 `attachRotation` 或载具放置角，每次 90°。
2. 增加专用载具放置请求包，携带手、可选来源载具 ID、目标地面锚点与 yaw；必要时另设去重序号，不复用模板 ID 或实例 UUID 的语义。位置字段语义变更时同步更新 payload 文档、编解码测试和协议版本。
3. 客户端右键只发送该请求；服务端普通 `BaseVehicleItem.use` 路径不得再次创建载具，避免一次交互走两条创建路径。请求处理器在主线程从玩家指定手读取物品和数据，并权威验证手持物品、可选 ID、位置、yaw、区块可用性、实体/载具冲突及地形冲突。
4. 装配体物品只在服务端成功登记载具后消费；载具蓝图可重复使用。失败时保留物品。请求限频也适用于创意模式。

### P3：动态与静态碰撞验证

1. 动态目标（PAWN、现有载具）通过 `WorldSnapshot` 的物理形状查询检查。
2. 静态方块/地形通过局部总 AABB 检查；若空隙导致实测误报，再按 Part/SubPart AABB 细化。
3. 预览颜色反映同一候选姿态的可放置性；服务端对最终结果重新判定。
4. 用大型、偏心、多部件载具验证玩家不会被生成载具推挤，且旋转过程不导致目标锚点不连续跳动。

### P4：结构生成复用准备

1. 暴露无玩家的服务端实例化/放置入口，输入包含载具模板数据副本、目标地面锚点、目标参考根朝向、恢复模式和可选初始状态。
2. 允许结构兑现器在区块完整加载后调用该入口；结构局部锚点与结构旋转由调用方转换为世界地面锚点和目标参考根朝向，不要求调用方拼装数据坐标到世界坐标的刚体变换。
3. 结构随机耐久先作用于独立 `VehicleData` 副本，再执行放置变换；随机和幂等细节遵循结构生成专门计划。
4. 结构生成不走玩家射线、玩家净空输入、物品消费或客户端预览逻辑。

## 5. 验收场景

- 新模板默认放置 yaw 0，参考锚点朝向与世界轴一致；现有角度按键在部件物品上下文更新安装角，在载具物品上下文更新放置角，且两者状态互不串扰。
- yaw 为 0°、90°、180°、270° 时，参考根局部 AABB 底心的世界水平投影始终对齐目标地面锚点；世界 AABB `bottomCenter` 可以变化。所有子零件相对几何、连接关系与部件状态保持不变，整体最低碰撞边界对齐目标地面高度。
- 同一模板预览、放置或失败重试后，源 `VehicleData`、物品内蓝图和内容包模板 JSON 均未被修改。
- 高低、细长、偏心、多部件载具根据旋转后的碰撞形状生成总 AABB；视觉模型 AABB 不替代物理形状。
- 总 AABB 与方块碰撞形状的包围盒产生非零体积相交时拒绝放置，边界贴合按容差处理；稀疏载具因包围盒空隙误拒时，可由 Part/SubPart AABB 细化判定。
- 长轴很大的载具可以在超过原版实体交互距离所暗示的锚点距离处安全生成；固定局部锚点不随 yaw 漂移，接地高度由放置逻辑处理，且不会因此侵入墙体或地形。
- 玩家或其他载具占据候选体积时，预览与服务端均拒绝放置；PAWN 由快照查询发现，静态方块由独立地形查询覆盖。
- 请求中的手持物品与来源 ID 不匹配、位置越界、yaw 非 90° 倍数、重复请求、物品切手、切维度或放置失败均不会产生重复载具、错角度生成或误消耗物品；服务端新建的实例 UUID 不由客户端指定。
- 一个无 `Player`、无 `ItemStack` 的结构生成测试能提供模板、世界坐标和 yaw，经过相同实例化入口登记到 `ObjectManager`。

## 6. 非目标

- 不为放置旋转改写 `VehicleData` 持久化格式、网络格式或内容包模板定义。
- 不允许自由 pitch/roll，不实现完整建造模式或拖动旋转 gizmo。
- 不在本计划实现结构 processor、世界生成注册、chunk attachment、重试持久化或随机耐久 schema。
- 不绕过 `ObjectManager.addVehicle` 单独添加实体、子零件刚体或客户端同步包。

## 7. 主要代码位置

- `common/item/prop/BaseVehicleItem.java`：玩家物品放置入口、客户端预览、目前的目标与包围盒计算。
- `common/item/prop/AssemblyItem.java`、`VehicleBlueprintItem.java`：物品恢复模式、成功消费和模板来源。
- `common/mech/vehicle/data/VehicleData.java`、`SubPartData.java`：可复制的载具与刚体位姿数据。
- `common/visual/VehicleAnimatable.java`：统一目标锚点位姿的直接设置与插值更新，移除放置专用的第二更新入口。
- `common/mech/vehicle/VehicleCore.java#setTransform`：全车位姿变换及当前参考姿态选择。
- `common/mech/ObjectManager.java#addVehicle`：载具正式入世入口。
- `client/input/` 与网络载荷注册：放置 yaw 输入和服务端请求。
- `docs/plan/计划中/载具系统-结构生成载具备忘.md`：worldgen processor、延迟兑现、随机状态和幂等细化项。
