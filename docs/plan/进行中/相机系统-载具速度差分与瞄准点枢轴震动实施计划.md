# 相机系统：载具速度差分与瞄准点枢轴震动实施计划

**状态**：进行中。投射物冲击弹簧与相机位移偏移已接入；载具主线程速度差分响应和以武器目标点为枢轴的统一相机位姿合成尚未实现。

日期：2026-11-23。

本文为独立实施计划，处理载具平动速度差分引发的相机冲击反馈、投射物与载具震动的位姿合成，以及第三人称目标点附近的相机旋转枢轴。源码路径以 Machine-Max 仓库根为基准。

## 1. 目标与范围

客户端按主线程步采样载具速度差分 `ΔV`，将加速、制动、自由下落和碰撞带来的线速度变化转换为有限的镜头响应。第三人称震动绕同帧武器世界目标点 `P_render` 合成旋转，以减少目标环因单纯角扰动在画面中游移。相机观察方向仍独立于武器目标方向；枢轴变换不得调用 `lookAt(P)` 或改写瞄准目标。

交付范围：

- 每个客户端主线程步至多采样一次载具线速度；不读取物理线程刚体，也不在渲染帧对速度再次求差。
- 比较独立弹簧逐步冲量与二阶输入响应，选定载具反馈模型；载具与投射物响应状态相互隔离。
- 将载具差分、投射物冲击和相机位移偏移合成同一帧显示位姿；旋转统一以四元数或角轴状态表示。
- 第三人称绕 `P_render` 合成旋转，并限制远距离枢轴造成的相机位移。
- 保留座椅观察方向、目标环投影、相机轨道遮挡、第一人称与设备视点语义。
- 自动化覆盖纯数学与采样契约；画面和手感由用户进行客户端验收。

网络协议字段、接触采集、碰撞回调和服务端效果均不在首版范围内。不从 `ΔV` 中扣除重力贡献；自由落体差分属于输入。首版只处理载具质心平动速度差，不推导独立角速度冲击，不引入鼠标输入平滑、第三人称参考姿态平滑或设备转轴限速。

## 2. 当前基线

### 2.1 抖动实现

`client/input/CameraShakeController.java` 持有投射物旋转与位置两台 `SpringDamper`。投射物命中按速度、距离和视角模式注入一次脉冲；失色压制在同一命中路径处理。两台弹簧使用 `k=12`、`d=6.93`。

控制器还持有 `vehicleChaseDamper`，并定义 `onVehicleCameraChase` 与偏移读取接口。全仓库生产调用点检索没有发现该方法的调用，追赶偏移也没有进入最终相机位置。因此它当前未接线，不代表运行中的载具镜头惯性。实施时需明确清理未接线状态，或只复用其通用弹簧数学。

`CameraShakeController.tick` 由 `CameraController.updateCameraRot` 在渲染角事件中调用，按游戏 tick 与 `partialTick` 的差值积分。`CameraController` 先写基础 `renderPose`，再把旋转偏移作为欧拉分量加到角事件；位置事件另读位置偏移。两路输出没有共同的最终位姿求值。

### 2.2 速度来源与时序

`common/mech/vehicle/VehicleCore.java` 的 `velocity` 由 `preTick` 对载具根子零件线速度求平均后缓存。客户端 `ObjectManager.onPreTick(LevelTickEvent.Pre)` 推进该缓存；`ClientTickEvent.Post` 晚于客户端 Level Pre、实体 tick 与 Level Post。控制器可从当前座椅所属装配体取得 `VehicleCore`，在主线程读取缓存速度。

差分器自己保存上一主线程样本，不读取 `SubPart` 的 Bullet 刚体，也不依赖 `VehicleCore.oldVelocity` 的内部更新时间。速度无效、离座、载具切换、世界卸载与暂停恢复都由差分器显式管理。

### 2.3 与瞄准点几何的边界

第三人称瞄准点计划规定：`P_render` 是武器目标与 HUD 环投影点；相机按独立观察方向 `V_render` 构造显示旋转，不朝向 `P_render` 来消除目标环偏置。本计划把 `P_render` 仅用作震动变换枢轴，不把它重新解释为相机光轴，也不修改武器目标。

## 3. 主线程步 `ΔV` 契约

客户端主线程第 `n` 步在 `ClientTickEvent.Post` 读缓存速度 `V_n`：

```text
ΔV_n = V_n - V_(n-1)
```

采样步长按固定 20 TPS，即 `0.05 s`。不创建加速度字段或物理步采样链；响应参数直接按每步 `ΔV` 标定。渲染帧只推进／插值显示响应，不重新求速度差。

1. 首次进入座椅、首次取得有效速度、切换载具或世界时，只建立基线，输出零差分。
2. 同一载具换座可保留差分基线；若观察几何重建，则单独重置相机响应状态。
3. 离座、载具对象失效、世界卸载、暂停或速度无效时清状态；恢复时重新建立基线，不把暂停跨度当作冲击。
4. 自由落体的向下速度变化不做抵消。连续小样本与落地单步大样本都走同一输入链，由响应参数区分强弱。
5. 世界空间 `ΔV` 按当前座椅参考姿态变换到局部轴。轴向增益与正负号集中定义并测试，不散落在相机事件中。

该输入描述载具质心平动变化，不等同于接触冲量。没有明显质心线速度变化的纯转动冲击不在首版覆盖范围；角速度或接触信息另行立项。

## 4. 响应模型选择

投射物命中是异步事件脉冲，载具差分是每个主线程步都可能出现的样本。不得将车辆样本注入投射物弹簧实例。

| 模型 | 输入语义 | 优点 | 风险与判定重点 |
| --- | --- | --- | --- |
| 独立弹簧逐步冲量 | 每个主线程样本向专属二阶弹簧注入与局部 `ΔV` 成比例的速度增量 | 可复用 `SpringDamper` 的脉冲数学；保留冲击峰值；实现简单 | 自由落体形成连续小脉冲列并产生稳态偏移，需标定大小与恢复时间 |
| 二阶输入响应 | `ΔV` 样本驱动独立二阶响应器，响应状态连续求值或在渲染帧插值 | 持续变化输入语义直接；可明确控制加速、冲击和恢复 | 需定义输入保持、离散系数和插值；固定步下可能与逐步冲量数学等价 |
| 输入低通后再响应 | 先低通 `ΔV`，再交给上述模型 | 可压制已证实的 tick 级噪声 | 会削弱落地峰值、延长尾部；没有噪声证据时不叠加该层 |

首轮采用独立载具状态和原始 `ΔV`，不扣重力、不预先低通；用相同速度记录比较前两种模型在自由落体、匀加速、急刹和硬着地时的峰值、稳态偏移、恢复时间与帧率影响。若两者差异小且语义一致，选独立弹簧逐步冲量；若持续重力或长加速带来难以接受的偏移，再选二阶输入响应并约束零输入恢复。只有记录证明存在非物理噪声时才加入低通。

明确区分 `ΔV`（每步米每秒变化）、弹簧响应速度、角偏移与平移偏移。不能把同一个无单位向量同时当成角度、米和冲量。首轮增益使用客户端常量。

## 5. 相机位姿与目标枢轴

### 5.1 枢轴公式与距离上限

渲染角事件先生成未震动基础位姿 `(C0, Q0)`：`C0` 已经过座椅轨道与地形遮挡求值，`Q0` 保留相机观察方向 `V_render` 及座椅滚转。普通跟随时使用本帧 HUD 投影的武器目标点 `P_render`；临时自由观察时使用 HUD 当前投影的逻辑武器目标 `expectedPoint`。两者都只作震动枢轴，不参与基础相机朝向计算。第一人称、固定炮镜或目标点无效时不使用第三人称枢轴轨道。

设合成角扰动为世界旋转 `S`，第三人称候选位姿为：

```text
C1 = P_render + S · (C0 - P_render)
Q1 = S · Q0
```

位置扰动为零且没有遮挡裁剪时，`P_render` 在相机局部空间的位置保持不变。`Q1` 从基础相机旋转变换而来；不得通过 `lookAt(C1, P_render)` 求旋转，否则会破坏相机光轴与武器方向分离。

枢轴距离 `r=|C0-P_render|` 时，旋转 `θ` 引发的相机位移为 `2r·sin(θ/2)`。相机枢轴位移上限 `D_max` 反推出有效角上限：

```text
θ_eff = min(θ_raw, 2·asin(clamp(D_max / (2r), 0, 1)))
```

远目标自动降低可用角扰动，近目标允许较大角度；不按距离区间硬切。`D_max` 和各轴增益以保守常量起步，经客户端验收标定。

### 5.2 合成顺序与遮挡

1. 投射物位置弹簧与载具线性响应分别输出有限位移；第三人称平移通道设独立上限。启用平移时允许目标环有小幅屏幕位移，枢轴公式不消除此项影响。
2. 枢轴变换后的候选位置再次经过现有相机轨道遮挡检查。防止相机穿入地形优先于严格保持目标投影；遮挡引起的目标环位移纳入人工验收。
3. 各来源在一个相机求值点取样、组合并形成 `(C_final, Q_final)`；来源状态不得各自直接写入相机事件。
4. `ComputeCameraAngles` 建立最终姿态，后续 `ComputeCameraPosEvent` 只读取同一份位置。渲染重复采样不推进 `ΔV` 差分，也不回写 `ThirdPersonViewpoint`、`expectedPoint` 或自由观察状态。
5. 四元数到原版欧拉角的转换仅在事件边界执行一次。基础位姿与抖动位姿保持独立，禁止把最终震动结果反馈为下一帧基础状态。

目标点无效或相机与枢轴距离接近零时，跳过枢轴轨道并走受模式限制的旋转回退。相机裁剪不回写逻辑目标，也不通过旋转基础相机来补偿目标环位置。

### 5.3 来源隔离

- 投射物命中继续走现有命中包；不增加网络载荷，保留命中旋转、位置偏移与失色压制。
- `ΔV` 只驱动独立车辆状态。多来源在最终位姿层合成，不能污染彼此的弹簧速度或阻尼状态。
- 明确处置未接线的 `vehicleChaseDamper`：若新响应覆盖其用途则清理死状态和接口；若保留独立追赶功能，则另行定义其输入、输出及枢轴关系。
- 压制视觉、弹道命中方向、武器输入、相机参考姿态、视点选择与网络目标不读取震动后的相机姿态。

## 6. 模式与生命周期

| 模式 | 载具 `ΔV` 响应 | 枢轴轨道 | 投射物反馈 |
| --- | --- | --- | --- |
| 普通第三人称 | 低幅旋转与受限位移 | 有效 `P_render` 时启用，受 `D_max` 约束 | 保留现有视角系数并进入统一合成 |
| 临时自由观察 | 可保留低幅乘员反馈 | 使用瞄准计划指定的 HUD 目标采样 | 目标数据不改写 |
| 第一人称 | 仅保留客户端验收通过的微弱旋转 | 不改变眼点位置，不绕远点平移 | 关闭位置抖动，单独复核旋转比例 |
| 固定炮镜／设备视点 | 默认关闭载具位置扰动 | 不使用第三人称轨道枢轴 | 沿用设备视点独立衰减规则 |
| 离座／换世界 | 清零并重建速度基线 | 关闭 | 投射物命中状态按各自生命周期处理 |

每种模式的缩放只在一个位置定义。切换视点、载具或座椅时检查状态复位，不让残留弹簧状态决定新视点首帧。

## 7. 实施阶段

### P0：职责确认

1. 记录 `CameraController.tick`、`ObjectManager.onPreTick`、`VehicleCore.preTick`、`updateCameraRot` 和 `updateCameraPos` 的实际相位及线程。
2. 确认 `onVehicleCameraChase` 只有定义、无生产调用；界定死状态清理范围。
3. 固定 `P_render` 来源、自由观察目标语义、第三人称轨道锚点和遮挡入口。
4. 确定目标环允许的屏幕位移、`D_max` 与模式基线。

### P1：主线程差分采样

1. 在客户端 `ClientTickEvent.Post` 从当前控制座椅所属 `VehicleCore` 读取缓存线速度。
2. 实现独立差分状态；首样本只建基线，结果不依赖 `oldVelocity`。
3. 覆盖暂停、载具身份、离座、卸载、空对象和非有限速度的状态清理。
4. 增加纯逻辑测试：每主线程步至多一个差分，任意渲染采样次数不改变输入序列。

### P2：响应对照与标定

1. 建立不与投射物共用状态的车辆响应。
2. 对照独立弹簧逐步冲量和二阶输入响应，使用相同样本与输出范围。
3. 比较自由落体、静止、匀速、匀加速、急刹和单步大差分的峰值、稳态、恢复时间及帧率影响。
4. 不扣重力、不预先低通；确定局部轴映射、符号、各轴增益、衰减和最大角幅。
5. 记录响应选型依据以及质心差分无法涵盖的纯转动冲击边界。

### P3：统一相机位姿

1. 将基础位姿、来源响应、目标枢轴轨道、有限平移和遮挡结果汇入单一求值路径。
2. 用四元数合成旋转，绕 `P_render` 求轨道位置，并在生成候选位姿前按 `D_max` 限角。
3. 复用轨道遮挡检查；最终显示姿态与基础逻辑状态分离。
4. 使位置事件读取角事件生成的同帧结果，并定义无目标、离座和换目标的回退。
5. 清理或隔离未接线的 `vehicleChaseDamper`，不保留第二条未标定相机路径。

### P4：验证与用户验收

运行局部纯逻辑测试和仓库离线 JUnit 回归；记录实际命令与结果。用户在客户端完成 G1—G12。根据结果调整响应与 `D_max`，不以鼠标灵敏度、`expectedPoint` 或接触事件掩盖镜头反馈问题。

## 8. 自动化判据

自动化聚焦数学和时序不变量；力度、晕动感与可读性由用户客户端验收。

| 编号 | 输入 | 判据 |
| --- | --- | --- |
| A1 | 首次进入载具且速度非零 | 只建立基线，输出 `ΔV=0` |
| A2 | 连续两步速度相同 | 第二步差分为零 |
| A3 | 速度由 `V0` 变为 `V1` | 输出严格为 `V1-V0`，符号正确 |
| A4 | 自由落下若干步 | 保留向下重力速度变化；无重力抵消与接触门 |
| A5 | 同一主线程步重复渲染采样 | `ΔV` 只消费一次；响应不依赖回调次数 |
| A6 | 离座、换载具、卸载、暂停恢复 | 清状态并重建基线，不形成跨度冲击 |
| A7 | 投射物与车辆输入先后到达 | 两种来源的弹簧状态彼此隔离 |
| A8 | 有效 `P_render`、无平移、无裁剪 | 扰动前后目标点的相机局部坐标一致 |
| A9 | 近、中、远目标施加相同原始角度 | 位移不超过 `D_max`，有效角符合上限公式 |
| A10 | 多轴四元数扰动 | 结果有限且归一，不产生欧拉轴序跳变 |
| A11 | 枢轴候选与方块相交 | 相机被裁剪，逻辑目标与武器方向不变 |
| A12 | 无目标、第一人称、固定炮镜 | 不执行第三人称远点轨道，回退有界 |
| A13 | 输入和响应均归零 | 最终位姿等于未震动基础位姿 |

## 10. 预计改动面与风险

- `client/input/CameraController.java`：主线程差分采样、模式生命周期和同帧最终位姿共享。

- 纯逻辑帮助类与 `src/test/java/` 测试：速度差分、响应模型、枢轴几何、距离上限；测试不得放在 `mixin` 包。
- `docs/plan/README.md`：维护状态和范围索引。

主线程 `ΔV` 是载具整体平动差分，不等同于接触冲量。缓存速度按根子零件线速度求平均，载具解体或缓存停滞会影响代表性。二阶响应可能把重力呈现为稳态偏移，也可能延长硬着地尾部，必须同时标定自由下落和落地恢复。远距离枢轴会放大相同角度对应的位置变化，`D_max` 是必需边界。遮挡安全与精确保留目标投影可能冲突，裁剪时允许受限投影误差。质心速度无法识别纯角冲击，首版不声称覆盖该场景。
