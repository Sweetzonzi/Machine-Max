# 履带系统：重力下垂渲染实现方案

> **状态：** 待实现；本文规定初版实现范围，不表示代码已经接入。
> **日期：** 2026-10-22
> **关联设计：** [履带系统：物理实现设计文档](../进行中/履带系统-物理实现设计文档.md) §2.4（半径与厚度）、§4.4（物理张力近似）、§8.3—§8.5（基础包络、相位与实体渲染）。

## 1. 初版决议与边界

目标是在世界重力方向上产生适量视觉下垂，并保持基础包络中直线与轮缘圆弧的相切关系。初版采用**固定切点的四次曲线**，不求解真实悬垂线的移动切点。

- 服务端为轮子所属 `SubPart` 维护每物理步汇总的 `wheelSupported` 标记，主线程经已有 SubPart 同步通道发布给客户端。
- 客户端从基础包络中识别真正的轮间直线跨段；圆弧、既有点接触位置与铺设绕向由基础包络决定。
- 当前世界重力所朝向的外侧跨段，只要任一端轮子受支撑，就禁止下垂；两端均未受支撑时允许下垂。另一侧自由跨段允许下垂，即使它的端轮受支撑。
- 下垂只用于客户端节位置与朝向，不参与服务端长度、节数、耐久、轮间张力、GearJoint 或碰撞半径计算。
- 初版不做下垂后的穿轮、自交、包围关系复检，不查询跨段地形，不增加履带节刚体。相关限制和后续 TODO 见 §8。

这里的“下侧”按当前世界重力定义，与铺设时“先下行程、后上行程”的成员顺序是两个概念；车体翻转后按世界重力选择禁垂侧。实现无需为此变更成员顺序或 `clockwise`。

## 2. 数学定义与光滑性

### 2.1 世界向下的平面投影

基础包络使用主动轮刚体局部 `(Y,Z)` 平面。令 `R` 为主动轮局部系到世界系的纯旋转，世界单位下方向为 `d_world = (0,-1,0)`：

```text
d_local = transpose(R) * d_world
q = (d_local.y, d_local.z)
```

`q` 不归一化，其长度处于 `[0,1]`，表示世界向下在履带平面内的分量。只转换方向，不带平移或缩放。每帧与轮位姿使用相同的 `partialTick`；主动轮自转造成的局部坐标变化应由变换自然抵消。

当 `|q| <= 1e-6` 时，全部跨段取零下垂。侧倾使平面内重力分量减小时，下垂幅度随 `q` 连续衰减。

### 2.2 固定切点的四次形变

对一条真正的基础直线跨段，设起点为 `A`，终点为 `B`，长度为 `D = |B-A|`，单位切向为 `t = (B-A)/D`。零长度跨段直接跳过。将重力分量中的沿跨段部分去掉：

```text
d = q - t * dot(q, t)
f(u) = 16 * u^2 * (1-u)^2
P(u) = A + u*(B-A) + h*f(u)*d,  u in [0,1]
P'(u) = (B-A) + 32*h*u*(1-u)*(1-2*u)*d
```

`d` 也不归一化。跨段平行于平面内重力时 `d = 0`，只有横向重力分量产生弯曲。由于 `dot(d,t)=0`，曲线沿基础跨段方向的投影保持单调。

端点条件为：

```text
P(0) = A, P(1) = B
P'(0) = P'(1) = B-A
```

因此切点位置固定，端点切向与基础直线完全相同，原本相切的直线—圆弧接头保持切向连续。按共同弧长参数表达时该接头为 C1 连续。基础包络中凹角点接触已有的折角由原几何保留，本方案不承诺消除这类折角，也不要求接头曲率连续。

这是带反弯区的视觉曲线，不是均匀柔索自重平衡的悬垂线。真实悬垂线 `y = a*cosh((x-b)/a)+c` 满足 `y'' > 0`，非竖直跨段无法在非零下垂时同时保持原公切线两个切点的相同切向；真实悬垂线需要联立轮缘接触求解移动切点，属于 §8 的后续范围。

### 2.3 幅度参数

初版采用客户端渲染常量，不接内容包，不读取 `TrackAttr.Tension` 的弹簧参数：

```text
h_base = min(SAG_MAX, SAG_COEFFICIENT * D^2)
SAG_MAX = 0.12 m
SAG_COEFFICIENT = 0.02 / m
```

以上是初始视觉标定值，可在实机验收时调整。`h_base` 为有限非负数；零值表示关闭下垂。实际中点位移为 `h*d`，大小是 `h*|d|`，不是无条件等于 `h`。短跨段的幅度按长度平方减小，长跨段由上限控制。

该幅度没有质量或张力的物理含义；基础物理张力由关联设计 §4.4 的相邻轮单边弹簧承担。

## 3. SubPart 轮面支撑标记

### 3.1 标记语义

`wheelSupported` 是本文规定的待实现字段名，表示至少存在一个有效轮面接触，接触面的支撑方向朝世界上方。非轮子 SubPart 为 `false`，普通轮子也可维护此标记，不要求必须挂载履带。

初版接触筛选：

1. 接触子形状通过 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/SubPart.java#isWheelSurface`，并通过同文件 `isEffectiveContact` 的有效性检查。
2. 支撑对象为世界地形、Create 地形代理或另一装配体的刚体；排除本装配体成员和普通生物接触。
3. 使用指向当前轮子的单位支撑法线 `n_support`，要求 `dot(n_support, worldUp) >= 0.2`。该阈值是视觉筛选常量，用于排除近竖直墙面，不是车辆爬坡能力限制。
4. 接触距离不大于 `0.01 m`，并且该接触最终未被丢弃。无需用接触冲量大小作为必要条件。

法线正负必须根据 A/B 身份明确处理，可对照 `../Spark-Core/src/main/kotlin/cn/solarmoon/spark_core/physics/body/ManifoldPoint.kt#getNormalWorld`；禁止用法线 Y 分量的绝对值判定，以免把顶住天花板算成支撑。

接触入口见 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/collision/CollisionHandler.java#onContactProcessed`。高度场路径会修改法线和距离，方块失效路径会丢弃接触，参见同文件 `handleTerrainCollision`；支撑汇总应读取处理后的有效结果，覆盖高度场提前返回分支，并排除丢弃分支。本文不依赖该接触回调已经拿到本步最终求解冲量这一假设。

### 3.2 物理步生命周期与线程发布

```text
服务端 prePhysicsTick：清空本步私有支撑累积
本步有效接触：累计 hasSupport |= qualifies(contact)
服务端 postPhysicsTick：发布本步完成态 wheelSupported
服务端主线程 postTick：将完成态写入 SynchedEntityData 并走已有增量同步
客户端：读取同步值用于跨段门控
```

私有累积由物理线程持有；对主线程发布使用 `volatile` 完成态，不能在步开始把对外可见状态清成 `false`。一轮接触中只要有一个有效支撑就成立，墙面等其它接触不能覆盖为 `false`。

休眠刚体保留最后一个完成态；唤醒后按完整物理步重新结算。移出物理世界、销毁或失去轮面时清成 `false`。实机验证必须覆盖停车休眠，不能仅凭没有新回调就判离地；休眠期间支撑物变化的额外刷新属于 §8 的 TODO。

接线入口为 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/SubPart.java#prePhysicsTick`、同文件 `postPhysicsTick`，以及 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/DestroyableObject.java#postTick` 的主线程同步链。SubPart 在主线程写入同步字段，随后由本 tick 增量发送链发布；客户端运动学刚体不自行覆盖服务端支撑值。

在 SubPart 的同步字段定义中注册布尔值，初值 `false`，按已有字段顺序追加。物理步更新频率与网络发送频率独立；沿用主线程增量同步，不每物理步发送 `TrackLinkSyncPayload`。标记属于运行状态，不写入 `VehicleData` 或蓝图。

`src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/collision/CollisionEffectManager.java#latestWheelSnapshot` 只保留最后一次效果接触且会被消费清空，支撑汇总应有独立状态，不从该字段推导。

## 4. 跨段禁垂规则

取基础直线跨段按固定闭环绕向计算的单位外法线 `n_out`：

```text
gravityFacing = dot(n_out, q) > 1e-6
blocked = gravityFacing && (supported(startWheel) || supported(endWheel))
h = blocked ? 0 : h_base
```

| 当前跨段 | 两端支撑状态 | 初版结果 |
| --- | --- | --- |
| 世界重力所朝向的外侧（通常为下侧） | 任一端受支撑 | `h = 0`，保持基础直线 |
| 世界重力所朝向的外侧 | 两端均未受支撑 | `h = h_base` |
| 另一侧（通常为上侧） | 任意 | `h = h_base` |
| 重力平面投影近零、跨段近零或凸包回退 | 任意 | 使用基础包络 |

任一端受支撑就禁垂，是初版针对单端离地的保守选择；不增加“单端接地时只放行一部分下垂”的独立规则。相同两个轮之间可能同时存在上下两段，必须按动态跨段分别判断，不能按轮对全局禁垂。

初版门控直接使用最近收到的支撑值，不增加离地保持计时器或幅度平滑状态。接地后该侧跨段直接取零幅度；同步延迟和瞬时视觉切换按本版近似接受，时间平滑列入 §8。

## 5. 路径数据与客户端采样

### 5.1 基础几何与渲染路径分工

基础包络继续按轮位姿和 `R-t` 半径构建，保持关联设计 §2.4 的厚度契约。基础求解的穿轮检查属于已有算法；本方案推迟的是**形变后的再次检查**。

实现应从基础求解结果保留最小的语义片段数据：

- 直线跨段：端点、起终轮的原成员索引、沿闭环的切向。
- 轮缘圆弧：所属轮索引、起始角、带符号扫角和半径。

数据出处是 `src/main/java/io/github/sweetzonzi/machine_max/util/geometry/OrderedBeltSolver.java#Piece` 与同文件 `assemble`；两轮路径由 `src/main/java/io/github/sweetzonzi/machine_max/util/geometry/BeltPath2D.java#buildTwo` 提供相同语义。不得对 `BeltPath2D.Edge` 逐条套下垂函数：圆弧采样弦也会表现为 Edge，且一条真实跨段的长度应整体用于幅度计算。同轮两次接触及额外支撑轮以动态片段的轮索引为准，不从成员表的相邻关系猜端轮。

可以为基础路径增加只读片段描述，再由纯数学的客户端渲染路径构建器执行 §2 / §4；类名由实现者确定。共享几何代码不引用客户端类，服务端调用基础包络不执行形变。原型对照规则见关联设计 §8.3；若修改基础路径输出结构，对应保留 Java 与 `prototype/track-envelope-2d/ordered-belt-solver.js#solve` 的基础几何一致性。

### 5.2 弧长采样、切向与法线

初版为每条下垂曲线建立 32 个均匀参数区间的弧长查找表：采样 `u=j/32`，累加相邻曲线点的距离。给定段内弧长，用二分定位区间并线性反解 `u`，然后用 §2.2 的解析式求位置和 `normalize(P'(u))`。查找表近似弧长，切向取解析导数，不取采样弦方向。

零下垂直线按精确线段采样。圆弧按半径与角度精确采样：弧长 `r*abs(sweep)`，切向取有向圆弧导数。这样保留相切接头的切向性质；基础 `src/main/java/io/github/sweetzonzi/machine_max/util/geometry/BeltPath2D.java#sampleAt` 返回折线边方向，不能直接作为圆弧的光滑切向。

各片段用累计长度索引，闭合端取模。外法线根据解析单位切向 `t=(tx,ty)` 与基础闭环绕向确定：逆时针取 `(ty,-tx)`，顺时针取 `(-ty,tx)`。绘制时按关联设计 §2.4 将内表面采样点沿该外法线偏移 `t_thickness/2` 得到节中心，节几何全厚为 `t_thickness`。

### 5.3 节数、相位与退化处理

- 客户端下垂路径总长记为 `L_render`，与服务端基础包络长区分。节数 `N` 按基础包络与既有关键事件规则确定；禁止按 `L_render` 重算节数、最大耐久或发送履带拓扑更新。
- 沿渲染路径放节：`s_i = (L_render*i/N + phase_render) mod L_render`。间距和占位节长随 `L_render/N` 调整，接受视觉伸缩，不建立带长守恒。
- `phase_render` 沿用主动轮相对角速度积分及双值插值，参考 `src/main/java/io/github/sweetzonzi/machine_max/client/render/renderer/TrackRenderer.java#tick`；带速继续使用轮面碰撞半径 `R` 和基础闭环绕向。下垂或支撑状态变化不重置相位。
- 凸包回退使用基础路径，不形变；渲染路径的长度或采样结果非有限时使用当帧基础路径。该数值兜底不包含形变后的碰撞或自交检测。
- 绘制接入 `src/main/java/io/github/sweetzonzi/machine_max/client/render/renderer/TrackRenderer.java#renderBelt`，主动轮实体绘制、远处补画、光照和阴影沿用关联设计 §8.5 的实体管线。

## 6. 建议实施顺序

1. SubPart 支撑标记：有效接触累积、休眠处理、完成态发布与主线程同步。
2. 基础路径只读片段：保留真实直线跨段的两端轮索引和圆弧参数，覆盖两轮路径；基础包络的数值与调用语义保持可验证。
3. 纯数学渲染路径：重力投影、禁垂门控、四次曲线、弧长查找表与解析朝向。
4. TrackRenderer 接入：固定基础节数、连续相位、按形变后路径布节；实机标定幅度。
5. 对照 §7 验收，源代码在适当落点保留 §8 对应 TODO，并更新本文状态及关联设计的实现范围。

## 7. 初版验收

纯逻辑测试放在现有 `src/test/java/io/github/sweetzonzi/machine_max/track/` 或几何测试包，运行 `./gradlew --offline test`。覆盖：

1. 四次曲线两端位置、切向等于基础直线；圆弧与原本相切的跨段在接头处同向。
2. 中点位移符合 `h*d`；零幅度、竖直跨段和零重力投影输出基础形状。
3. 下侧任一端支撑时禁垂，上侧在相同支撑标记下允许下垂；两端均未支撑时两侧均可下垂。
4. 主动轮整圈自转只改变坐标表达；同一世界轮组得到相同世界下垂形状。整体侧倾、翻转后投影和禁垂侧随世界重力变化，固定绕向保持。
5. 弧长采样闭合、位置和切向有限、法线方向正确；改变幅度及标记不改变基础包络、基础节数、耐久或相位状态。
6. 支撑聚合覆盖多个接触的逻辑或、墙面排除、法线 A/B 换序和被丢弃接触排除；同步布尔值可往返。

游戏内验收：平地停车、停车休眠、前进与倒车、单端轮离地、整组腾空、坡面、侧倾和翻转。检查下侧禁垂、上侧下垂、履带节朝向、连续相位，以及光照和阴影。形变后的穿轮、穿地、自交属于 §8 的已知边界，不作为初版验收失败条件。
