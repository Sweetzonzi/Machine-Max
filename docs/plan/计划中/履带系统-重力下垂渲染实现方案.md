# 履带系统：重力下垂渲染实现方案

> **状态** 待实现。固定切点的四次曲线和主动轮啮合规则已确定，可进入实现。
>
> **关联设计** [履带系统：物理实现设计文档](../进行中/履带系统-物理实现设计文档.md) §2.4（半径与厚度）、§4.4（物理张力）、§8.3—§8.5（基础包络、啮合与渲染）。

## 1. 实现目标与边界

自由跨段沿世界重力方向弯曲，以曲线相对直线多出的弧长表现松弛。接地侧按轮面支撑状态限制下垂。渲染路径按当帧轮位姿和垂度自然变化，整圈允许有少量视觉伸缩。

渲染从履带内表面包络出发，沿用现有节数、闭环绕向、主动轮啮合和输送相位。间距变化由主动轮之外的路径承担。物理张力由关联设计 §4.4 的相邻轮单边弹簧承担，节数、耐久、GearJoint 和碰撞半径沿用各自的物理输入。

## 2. 数学定义与光滑性

### 2.1 世界向下的平面投影

基础包络使用主动轮刚体局部 `(Y,Z)` 平面。令 `R` 为主动轮局部系到世界系的纯旋转，世界单位下方向为 `d_world = (0,-1,0)`：

```text
d_local = transpose(R) * d_world
q = (d_local.y, d_local.z)
```

`q` 的长度处于 `[0,1]`，表示世界向下在履带平面内的分量。方向转换只使用旋转，与轮位姿使用相同的 `partialTick`。主动轮自转只改变曲线在局部坐标系里的表达。侧倾使重力投影与垂度连续减小。若 `|q| <= 1e-6`，全部跨段保持基础形状。

### 2.2 固定切点的四次形变

对一条真正的基础直线跨段，设起点为 `A`，终点为 `B`，长度为 `D = |B-A|`，单位切向为 `t = (B-A)/D`。零长度跨段直接跳过。将重力分量中的沿跨段部分去掉：

```text
d = q - t * dot(q, t)
f(u) = 16 * u^2 * (1-u)^2
P(u) = A + u*(B-A) + h*f(u)*d,  u in [0,1]
P'(u) = (B-A) + 32*h*u*(1-u)*(1-2*u)*d
```

`d` 也不归一化。跨段平行于平面内重力时 `d = 0`，只有横向重力分量产生弯曲。由于 `dot(d,t)=0`，曲线沿基础跨段方向的投影保持单调。

端点条件为：

```text
P(0) = A, P(1) = B
P'(0) = P'(1) = B-A
```

因此切点位置固定，端点切向与基础直线完全相同，原本相切的直线—圆弧接头保持切向连续。按共同弧长参数表达时该接头为 C1 连续。基础包络中凹角点接触已有的折角由原几何保留，本方案不承诺消除这类折角，也不要求接头曲率连续。

四次曲线在跨段内有反弯区，作用是保留两个固定切点的切向。曲线中部向下偏移并多走一段弧长，用来表现带有松量的自由跨段。

### 2.3 下垂幅度与余隙

令 `H = h * |d|` 为跨段的实际中点垂度。当 `|d| <= 1e-6` 或 §4 的支撑门控阻止下垂时，取 `H = 0`。其余跨段按下式取值。

~~~text
h_base = min(0.12 m, (0.02 / m) * D²)
H = min(h_base * |d|, H_clearance)
~~~

`H_clearance` 是下垂方向上的轮盘余隙允许的最大垂度。端轮切点允许相切。候选曲线切入轮盘时，沿从零到目标垂度的方向缩减，使用保持轮盘余隙的幅度。各段确定后，按 §5.4 检查整圈形状。基础包络中的凹角点接触沿用基础形状。

`0.12 m` 和 `0.02 / m` 是首版渲染常量，按 §7 实机标定。各段独立取幅度，允许下垂在接触变化时收敛或消失。

## 3. SubPart 轮面支撑标记

### 3.1 标记语义

`wheelSupported` 是本文规定的待实现字段名，表示至少存在一个有效轮面接触，接触面的支撑方向朝世界上方。非轮子 SubPart 为 `false`，普通轮子也可维护此标记，不要求必须挂载履带。

初版接触筛选：

1. 接触子形状通过 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/SubPart.java#isWheelSurface`，并通过同文件 `isEffectiveContact` 的有效性检查。
2. 支撑对象为世界地形、Create 地形代理或另一装配体的刚体；排除本装配体成员和普通生物接触。
3. 使用指向当前轮子的单位支撑法线 `n_support`，要求 `dot(n_support, worldUp) >= 0.2`。该阈值是视觉筛选常量，用于排除近竖直墙面，不是车辆爬坡能力限制。
4. 接触距离不大于 `0.01 m`，并且该接触最终未被丢弃。无需用接触冲量大小作为必要条件。

法线正负必须根据 A/B 身份明确处理，可对照 `../Spark-Core/src/main/kotlin/cn/solarmoon/spark_core/physics/body/ManifoldPoint.kt#getNormalWorld`；禁止用法线 Y 分量的绝对值判定，以免把顶住天花板算成支撑。

接触入口见 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/collision/CollisionHandler.java#onContactProcessed`。高度场路径会修改法线和距离，方块失效路径会丢弃接触，参见同文件 `handleTerrainCollision`；支撑汇总应读取处理后的有效结果，覆盖高度场提前返回分支，并排除丢弃分支。本文不依赖该接触回调已经拿到本步最终求解冲量这一假设。

### 3.2 物理步生命周期与线程发布

```text
服务端 prePhysicsTick：清空本步私有支撑累积
本步有效接触：累计 hasSupport |= qualifies(contact)
服务端 postPhysicsTick：发布本步完成态 wheelSupported
服务端主线程 postTick：将完成态写入 SynchedEntityData 并走已有增量同步
客户端：读取同步值用于跨段门控
```

私有累积由物理线程持有；对主线程发布使用 `volatile` 完成态，不能在步开始把对外可见状态清成 `false`。一轮接触中只要有一个有效支撑就成立，墙面等其它接触不能覆盖为 `false`。

休眠刚体保留最后一个完成态；唤醒后按完整物理步重新结算。移出物理世界、销毁或失去轮面时清成 `false`。实机验证必须覆盖停车休眠，不能仅凭没有新回调就判离地；休眠期间支撑物变化的额外刷新属于 §8 的 TODO。

接线入口为 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/SubPart.java#prePhysicsTick`、同文件 `postPhysicsTick`，以及 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/DestroyableObject.java#postTick` 的主线程同步链。SubPart 在主线程调用 `super.postTick()` 前写入同步字段，由基类在本 tick 发布。客户端使用服务端同步的支撑值。

在 SubPart 的同步字段定义中注册布尔值，初值 `false`，按已有字段顺序追加。物理步更新频率与网络发送频率独立；沿用主线程增量同步，不每物理步发送 `TrackLinkSyncPayload`。标记属于运行状态，不写入 `VehicleData` 或蓝图。

`src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/collision/CollisionEffectManager.java#latestWheelSnapshot` 只保留最后一次效果接触且会被消费清空，支撑汇总应有独立状态，不从该字段推导。

## 4. 跨段禁垂规则

取基础直线跨段按固定闭环绕向计算的单位外法线 `n_out`。世界重力朝向该外侧且至少一端轮子受支撑时，跨段保持直线。另一侧的自由跨段按 §2.3 计算幅度。两端都无支撑时，两侧都可下垂。

~~~text
gravityFacing = dot(n_out, q) > 1e-6
blocked = gravityFacing && (supported(startWheel) || supported(endWheel))
~~~

翻转后按世界重力判断下侧，成员顺序和闭环绕向采用铺设时确定的值。同一对轮的上下跨段分别判断。收到新的支撑状态后，接地侧立即归零。轮端标记描述端点附近的接触。悬空跨段中部遇到凸起时，准确贴地属于 §8 的后续工作。

## 5. 路径数据与客户端采样

### 5.1 基础几何与渲染路径

从基础求解结果保留两类语义片段。直线跨段保存端点、起终轮的原成员索引和沿闭环的切向。轮缘圆弧保存所属轮索引、起始角、带符号扫角和半径。入口是 `src/main/java/io/github/sweetzonzi/machine_max/util/geometry/OrderedBeltSolver.java#assemble` 与 `src/main/java/io/github/sweetzonzi/machine_max/util/geometry/BeltPath2D.java#buildTwo`。同轮二次接触和额外支撑轮按实际片段索引处理。按真实跨段整体计算幅度，圆弧的采样弦只用于基础折线路径。基础几何与 `prototype/track-envelope-2d/ordered-belt-solver.js#solve` 保持一致。

客户端使用同一条渲染路径求长度、累计弧长和布节。圆弧按 `r*abs(sweep)` 取精确长度。下垂跨段以 §2.2 的解析导数取切向，在 `u=j/32` 处取点并累加弦长，按弧长二分查找区间并线性反解位置。外法线按解析切向和固定绕向确定，节中心沿外法线从内表面偏移半个节厚。

### 5.2 视觉松量

渲染路径长为 `L_render = L0 + Σ(S_i - D_i)`，其中 `L0` 为直线与精确圆弧组成的基础环长，`S_i` 是第 i 条变形跨段的弧长，`D_i` 是它的基础直线长度。每一项 `S_i - D_i` 就是该段表现出来的松量，供标定与验证时观察。贴地禁垂、余隙不足或重力投影减弱时，该项自然减小。

两轮离线算例中，单个 3 m 水平跨段在中点下垂 120 mm 时增加约 11.7 mm 弧长。这个量级可用于判断视觉幅度，布节按实际渲染路径长度进行。

### 5.3 主动轮啮合与输送相位

沿用 `src/main/java/io/github/sweetzonzi/machine_max/client/render/renderer/TrackBeltLayout.java#sample` 的两段节序映射。主动轮接触弧长为 `A = r*abs(sweep)`，弧上占 `A/p` 个连续节位，保持角间距 `p/r`，其中 `p` 是型号标称节距。其余 `N - A/p` 个节位沿 `L_render - A` 铺放，`N` 取持久化节数。切点的累计距离取渲染路径的弧长索引。模型节保持其几何尺寸，程序化占位节使用布局返回的局部间距。

`src/main/java/io/github/sweetzonzi/machine_max/client/render/renderer/TrackBeltPhase.java#label` 以实际主动轮转角和入带切点角确定节序，角速度用于跨圈预测，断带时冻结输送角。形变和回退沿用同一个相位状态。近处模型、程序化占位及远处渲染使用同一布局。剔除盒在轮组包围盒的基础上计入允许的最大形变。

### 5.4 形状复核与回退

形变后检查轮盘余隙、闭环自交和轮心包围。基础包络走凸包回退、变形布局失效、长度或采样结果非有限、几何复核失败时，使用当帧基础路径和已有啮合布局。基础布局不可用时沿用 `src/main/java/io/github/sweetzonzi/machine_max/client/render/renderer/TrackRenderer.java#renderTrack` 的跳过绘制规则。

## 6. 实施顺序

1. SubPart 汇总有效轮面支撑，发布物理步完成态并接入已有增量同步。
2. 从有序求解和两轮路径保留直线跨段与圆弧片段，保持基础包络、节数和耐久的推导口径。
3. 客户端构建下垂路径，计算轮盘余隙并复核形状，接入已有布节、相位和剔除流程。
4. 按 §7 测试和标定垂度。

## 7. 验收

- 纯几何用例覆盖曲线端点和切向、中点位移、弧长与闭合采样、两轮不等高、多跨段支撑切换、翻转和近零重力投影。重力方向平行于跨段时保持直线。穿轮、自交等退化触发余隙限制或基础路径回退。
- 布节用例核对主动轮固定角节距、相位跨圈、前进与倒车、断带与修复，以及下垂和回退互切时的输送相位。节数取持久化的 `N`。
- 接触用例覆盖接触聚合、法线 A/B 换序、墙面排除、已丢弃接触排除、休眠支撑保持及同步往返。
- 游戏内检查平地停车、单端离地、整组腾空、坡面、侧倾和翻转。重点观察自由跨段的下垂、接地侧的禁垂、主动轮啮合、节间距以及屏幕边缘的剔除。跨坑和跨段中部凸起用来记录端轮门控的适用边界。

## 8. 后续工作

实机标定后可按需要加入跨段地形余隙、支撑过渡和休眠支撑刷新。若需要颠簸产生可见响应，再把车体的垂向加速度用于调节幅度，并验证近失重和落地时的表现。
