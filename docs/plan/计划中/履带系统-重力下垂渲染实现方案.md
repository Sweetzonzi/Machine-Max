# 履带系统：重力下垂渲染实现方案

> **状态** 已接入客户端渲染与服务端轮面支撑同步。游戏内画面标定见 §7。
>
> **关联设计** [履带系统：物理实现设计文档](../进行中/履带系统-物理实现设计文档.md) §2.4（半径与厚度）、§4.4（物理张力）、§8.3—§8.5（基础包络、啮合与渲染）。

## 1. 实现目标与边界

自由跨段沿世界重力方向弯曲，呈现有松量时的外观。接地侧按轮面支撑状态限制下垂。渲染路径按当帧轮位姿和垂度自然变化，整圈允许有少量视觉伸缩。

渲染从履带内表面包络出发，沿用现有节数、闭环绕向、主动轮啮合和输送相位。间距变化由主动轮之外的路径承担。物理张力由关联设计 §4.4 的相邻轮单边弹簧承担，节数、耐久、GearJoint 和碰撞半径沿用各自的物理输入。

### 1.1 决议与待验证项

| 主题 | 决议 | 待验证 |
| --- | --- | --- |
| 支撑状态（P0/P1） | 按 Bullet 激活态结算。两侧碰撞分发后统一汇总，主线程同步，渲染读取 volatile 镜像 | 休眠唤醒、腾空首步及接触两侧顺序 |
| 平滑（P0） | 法线判据用进出迟滞。垂度按帧低通，几何余隙优先 | 过坎往复位移、落地和低帧率观感 |
| 几何与布节（P2） | 内表面轮盘余隙，语义段表，沿用啮合与路径距离的混合口径 | 最大幅度、穿轮回退和性能预算 |
| 断带与单端支撑（P2） | 断带沿用支撑门控与垂度，单端支撑的下侧跨段以绷直为目标 | 断带修复和单端悬挂的画面 |

## 2. 数学定义与光滑性

### 2.1 世界向下的平面投影

基础包络使用主动轮刚体局部 `(Y,Z)` 平面。令 `R` 为主动轮局部系到世界系的纯旋转，世界单位下方向为 `d_world = (0,-1,0)`：

```text
d_local = transpose(R) * d_world
q = (d_local.y, d_local.z)
```

`q` 的长度处于 `[0,1]`，表示世界向下在履带平面内的分量。`src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/track/TrackEnvelope2D.java#worldDownInPlane` 只使用主动轮的旋转，与轮位姿取同一份 `partialTick` 样本。主动轮自转只改变曲线在局部坐标系里的表达。侧倾使重力投影与垂度连续减小。若 `|q| <= 1e-6`，全部跨段保持基础形状。

### 2.2 固定切点的四次形变

对一条语义上的基础直线跨段计算形变，圆弧的 1° 采样弦不计入。设起点为 `A`，终点为 `B`，长度为 `D = |B-A|`，单位切向为 `t = (B-A)/D`。零长度跨段直接跳过。以下的 `d` 为重力投影中垂直于跨段的分量。

```text
d = q - t * dot(q, t)
f(u) = 16 * u^2 * (1-u)^2
P(u) = A + u*(B-A) + h*f(u)*d,  u in [0,1]
P'(u) = (B-A) + 32*h*u*(1-u)*(1-2*u)*d
```

`d` 也不归一化。跨段平行于平面内重力时 `d = 0`，只有横向重力分量产生弯曲。由于 `dot(d,t)=0`，曲线沿基础跨段方向的投影保持单调。

两个端点的位置和导数如下。

```text
P(0) = A, P(1) = B
P'(0) = P'(1) = B-A
```

基础包络中与该跨段相切的直线—圆弧接头保持切向连续，按共同弧长参数表达时为 C1 连续。凹角点接触的折角取自基础包络。四次曲线中部向下偏移，在视觉上表现自由跨段松弛。

### 2.3 下垂幅度与余隙

令 `H = h * |d|` 为实际中点垂度。若 `|d| <= 1e-6`，取 `H = h = 0`。其余跨段按以下关系计算。渲染器将平滑并限制后的 `H` 通过 `h = H / |d|` 代回 §2.2。

```text
h_base = min(0.12 m, (0.02 / m) * D²)
H_target = blocked ? 0 : h_base * |d|
```

`BeltPath2D#freeSagHeight` 使用 `MAX_SAG_HEIGHT = 0.12 m` 和 `SAG_COEFFICIENT = 0.02 / m` 计算自由跨段垂度。分界取 `sqrt(0.12 / 0.02) = sqrt(6) m`，约 2.45 m。

轮盘余隙使用 `BeltPath2D` 的输入圆，半径为内表面半径 `r = R - t`，`R` 是碰撞半径，`t` 是节厚。对沿固定方向变形的跨段，按 `u` 检查从直线点到候选曲线点的扫过区域。候选 `H` 越大，该区域越大，余隙判定可二分。常规余隙取 0.5 mm。对每个轮盘，额外余隙限于基础跨段与该轮盘的最小非负间隙。相切轮盘使用内表面半径作硬边界，因此切点附近可以弯曲，并保留相切。0.5 mm 的数值余隙常量放在执行检查的 `BeltPath2D`。

先对 `H_target` 做余隙检查，失败时从零二分到满足余隙的最大值，垂度区间收敛到 0.2 mm 即可。使用保守细分覆盖采样点之间的扫过区域，渲染用的 32 段弦只服务弧长表。滤波期间旧垂度可能大于当帧目标，应用前也要检查其余隙，并把限幅结果写回滤波状态。整圈复核见 §5.4。

## 3. SubPart 轮面支撑标记

### 3.1 标记语义与汇总位置

`wheelSupported` 表示该轮至少有一个合格的向上轮面支撑。由服务端物理线程汇总，普通轮子也可维护。合格接触满足以下条件。

1. 当前碰撞子形状通过 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/SubPart.java#isWheelSurface` 与同文件的 `isEffectiveContact`。
2. 对方是地形区块段、Create 地形代理，或另一装配体的 `SubPart`。排除本装配体成员和普通生物。同装配体以非空装配体身份相等为准，见 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/SubPart.java#onPreCollision`。
3. 取从支撑物指向轮子的单位世界法线 `n`，检查带符号的 `n.y`。上一完成态为 `false` 时进入阈值为 `0.25`，上一完成态为 `true` 时维持阈值为 `0.15`。同一个物理步内全部接触使用同一阈值。两值是 `CollisionHandler` 的静态常量，与爬坡判据独立。`CollisionHandler#isSupportingTerrainContact` 使用 `abs(normal.y)`，会将顶住天花板的接触计为支撑，因此视觉判据单独计算。
4. 分支处理后的接触距离有限且 `<= 0.01 m`。排除 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/collision/CollisionPostSettlement.java#DISABLED_DISTANCE` 及更大的丢弃值。0.01 m 定义在 `CollisionHandler`。

统一汇总点选在 Spark 的 `PhysicsWorld#onContactProcessed` **末尾**发布的 `PhysicsContactEvent.Process`，见 [PhysicsWorld.kt](../../../../Spark-Core/src/main/kotlin/cn/solarmoon/spark_core/physics/level/PhysicsWorld.kt)。Spark 先依次调用 A/B 两侧的 `Collide.Processed`，再发此事件。把汇总放在单个 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/collision/CollisionHandler.java#onContactProcessed` 末尾只能看到该侧处理结果，而对侧仍可改写同一点，例如零件碰撞会把原生点 ID 传给脚本，见 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/ScriptableSubsystem.java#onCollideWithPart`。

在 `SubPart` 的现有事件订阅点加 `onWheelSupportContact`。对事件两侧分别检查 owner 为 `SubPart` 且 `!level.isClientSide()`，活动客户端零件也可能进入原碰撞回调。将合格候选交给该零件的 `CollisionHandler#isWheelSupport`。以轮侧为 `point1`、对方为 `point2`，用 `point1.getDistance()` 和 `point2.getNormalWorld(normal)` 统一重读原生点。后者按 A/B 身份换符号，见 [ManifoldPoint.kt](../../../../Spark-Core/src/main/kotlin/cn/solarmoon/spark_core/physics/body/ManifoldPoint.kt) 的 `getNormalWorld` 和 `distance`。高度场提前返回和丢弃值都经此汇总点处理，接触分支各自处理地形、零件或生物碰撞。

`PhysicsContactEvent.Process` 在求解前发布，支撑判据只用几何状态。`CollisionPostSettlement#collectManifold` 是步末备选入口，已有 A/B 归一和丢弃值过滤。它由 `settle` 在存在地形撞击候选时调用，而且只接收 `PhysicsChunkSection`。扩展该扫描才能覆盖静置轮、Create 代理与零件间支撑。

### 3.2 物理步生命周期与线程发布

在服务端 `SubPart#prePhysicsTick` 中，进入方法后清零本步私有累积，此清零先于 `effectManager.resetLatestStates()` 与 `if (!isActive()) return` 执行。每个合格接触把累积置为 `true`，直至本步结束。其他接触无权覆盖它。`src/main/java/io/github/sweetzonzi/machine_max/common/mech/ObjectManager.java#onPostPhysicsTick` 独立分发步末回调，`prePhysicsTick` 提前返回也会结算。服务端 `SubPart#postPhysicsTick` 按以下优先顺序更新 volatile 完成态。

```text
已移出物理世界、已销毁或失去轮面 → false
本步有合格接触                   → true
本步无合格接触且 body.isActive()  → false
本步无合格接触且刚体休眠          → 保持上一完成态
```

活动分支使用 Bullet 的 `body.isActive()`。`src/main/java/io/github/sweetzonzi/machine_max/common/mech/DestroyableRigidObject.java#isActive` 读取 `IS_ACTIVE_ID`。该字段在同文件的 `postTick` 中依据激活态或运动学状态更新，会滞后于当前物理步。是否入世单独以 `body.isInWorld()` 判断。活动刚体无接触的第一步即发布离地。固定 N 步的无接触超时会把这段真实离地误报成支撑，休眠则可能因超时误报离地。销毁、移出物理世界或失去轮面时由相应生命周期入口失效。若对象已从 tick 调度注销，由清理入口负责清除完成态与客户端镜像，避免依赖之后的一次物理步。休眠期间支撑物消失且刚体未唤醒的刷新见 §8。

`SubPart` 按字段顺序追加 `WHEEL_SUPPORTED_ID`，覆写 `defineSyncedData(SynchedEntityData.Builder)`，先调用父类定义，再注册初值 `false`。在服务端 `SubPart#postTick` 调用 `super.postTick()` 前，把完成态写入该字段，由基类通过 `src/main/java/io/github/sweetzonzi/machine_max/network/payload/SubPartSyncPayload.java#handler` 对应的同步通道发布。同步字段表由 `sync:2.9.3` 约束，见 `src/main/java/io/github/sweetzonzi/machine_max/network/MMPayloadRegistry.java#register`。

`SubPart` 另覆写 `onSyncedDataUpdated(EntityDataAccessor<?>)`，调用父类并在客户端收到该字段时写入独立的 `volatile boolean` 镜像。`TrackRenderer` 通过只读 getter 读取该镜像，方式与 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/track/TrackLink.java#broken` 的可见性约定相同。`SynchedEntityData` 的读取和写入留在主线程。支撑标记随运行时增量同步。`src/main/java/io/github/sweetzonzi/machine_max/common/mech/ObjectManager.java#pushVehicleRuntimeState` 在载具初始化包发出后向该客户端补发为真的支撑字段，值取自服务端主线程已发布的同步表。存档和蓝图不存储此标记。

## 4. 跨段禁垂与帧间平滑

取基础跨段的单位外法线 `n_out`。世界重力朝向该外侧且至少一端轮子受支撑时，该段的 `H_target` 取零。单端受支撑的下侧前伸段以绷直为目标，表现轮端仍有张力。上侧自由段照常取 §2.3 的目标。两端无支撑时，两侧各自计算目标。

```text
gravityFacing = dot(n_out, q) > 1e-6
blocked = gravityFacing && (supported(startWheel) || supported(endWheel))
```

翻转按世界重力判断下侧，沿用铺设时的成员顺序和绕向。同一对轮的上下跨段分别记录垂度。断带继续绘制时，沿用相同的支撑门控和垂度计算，输送角按 §5.3 冻结。

支撑布尔值按服务端主线程 tick 同步，轮位姿按帧插值。垂度变化会经 `rest` 同时改变非啮合节位和程序化节长。单个 3 m 跨段从零切到最大下垂时，仅弧长增量就约为 11.7 mm，见 §5.2。渲染线程在 `TrackRenderer#State` 中按履带与稳定跨段身份存储 `H`，每世界渲染帧只推进一次。

```text
alpha = 1 - exp(-dt / tau)
H_blend = H_previous + alpha * (H_target - H_previous)
H_render = min(H_blend, safeClearance)
```

`TrackRenderer#sagBlendFactor` 使用 `tau = 0.15 s`，`dt` 取相邻渲染帧的实际秒数，限到 0.05 s，暂停时取零。用有向端轮对及该对在闭环中的出现序号区分跨段。同对跨段的接触拓扑发生变化时重置该对的滤波状态，新段从零开始。近处、远处和阴影共享该帧结果。履带拓扑失效或换世界时清理相应滤波状态。

支撑翻转更新目标，滤波余量受当帧几何上限约束。轮盘余隙下降时立即截断并写回。下侧从有垂度转入支撑时，只在能由客户端已加载的原版方块碰撞形状确认支撑与余隙时保留残余垂度。以世界坐标包围盒保守覆盖外表面的扫过区域，并与方块碰撞形状求交。命中地形、区块数据缺失或支撑无法由这些形状确认时，当帧取零。跨段中部的准确贴地与 Create 代理余隙属于 §8。

## 5. 路径数据与客户端采样

### 5.1 语义段表与弧长口径

在 `src/main/java/io/github/sweetzonzi/machine_max/util/geometry/BeltPath2D.java` 保存只读语义段表，由内部构造方法 `fromData` 接收。记录段类型、基础累计起点 `startDistance`、基础长度 `baseLength`。直线段带端点和两端原成员轮索引，圆弧段带所属轮索引、起始角、带符号扫角和半径。`src/main/java/io/github/sweetzonzi/machine_max/util/geometry/OrderedBeltSolver.java#assemble` 与 `BeltPath2D#buildTwo` 在各自内部填表。凸包回退走基础路径。圆弧采样弦仍供基础路径使用，语义段表负责区分圆弧和直线。额外支撑轮、同轮二次接触和同轮对上下跨段使用表里的轮索引。基础求解保持与 `prototype/track-envelope-2d/ordered-belt-solver.js#solve` 一致。

由 `BeltPath2D` 提供形变入口 `withSag`，接收渲染器算出的方向和垂度，复用 `sampleAt`、`distanceAt` 和 `length`。共享几何只处理坐标、曲线和轮盘，客户端负责时间和支撑状态。跨段在 `u=j/32`（`j=0..32`）处取点累加弦长，按累计距离二分并线性反解 `u`，切向取解析导数。`distanceAt` 与 `sampleAt` 使用同一张弧长表和同一套累计段偏移，轮缘切点按段端点定位。变形路径上的圆弧由索引距离反解角度，返回解析位置和切向。语义段的累计距离与基础路径使用同一闭环零点及绕向。节中心沿外法线从内表面偏移半个节厚。

路径距离沿用 `TrackBeltLayout` 的混合口径。圆弧在路径索引上按基础折线距离计长，下垂直线用形变弦长代替。主动轮啮合节位使用解析弧长 `r * abs(sweep)`。1° 弦采样的相对长度差约为 `1.3e-5`，保留此精度即可。服务端基础包络的长度计算保持现有折线口径。

### 5.2 表现出来的长度增量

在同一轮位姿下，`L_render = L0 + Σ(S_i - D_i)`。`L0` 是基础包络长，`S_i` 和 `D_i` 分别是跨段的形变弧长和基础直线长度。差值供标定观察，属于视觉形变额外引入的长度。

幅度取自跨段几何、支撑与余隙。`N*p - L0` 的差额已经由现有非啮合节距映射体现，用它再驱动下垂会重复计入。离线算例中，3 m 水平跨段下垂 120 mm 时，解析曲线弧长增加约 11.7 mm。

### 5.3 主动轮啮合与输送相位

沿用 `src/main/java/io/github/sweetzonzi/machine_max/client/render/renderer/TrackBeltLayout.java#sample` 的两段节序映射。设 `A = r * abs(sweep)` 为主动轮解析接触弧长，`covered` 为相同接触段在路径索引中的距离。弧上占 `A/p` 个连续节位，角间距为 `p/r`，`p` 取型号标称节距。其余 `N - A/p` 个节位沿 `rest = L_render - covered` 铺放，`N` 取持久化节数。

`spacing()` 有 `max(pitch, ...)` 下限。程序化占位节实际读取 `spacing(sample)`，啮合段返回 `pitch`，其余段直接返回 `rest / (N - A/p)`。固定轮位姿时，增加下垂只会拉大或保持非啮合段间距。轮位姿变化和收垂可以使间距减小。模型节保持几何尺寸。

`src/main/java/io/github/sweetzonzi/machine_max/client/render/renderer/TrackBeltPhase.java#label` 以实际主动轮转角和入带切点角确定节序。角速度用于跨圈预测，断带时冻结输送角。形变和回退使用同一相位状态。

### 5.4 复核、回退与性能

形变后检查轮盘余隙、闭环自交和轮心包围。基础包络走凸包回退、变形布局失效、数值非有限或几何复核失败时，使用当帧基础路径和已有啮合布局。基础布局不可用时沿用 `src/main/java/io/github/sweetzonzi/machine_max/client/render/renderer/TrackRenderer.java#renderTrack` 的跳过绘制规则。

`TrackRenderer` 在客户端 `RenderFrameEvent.Pre` 推进帧编号并取帧时间。以帧编号和履带拓扑为键，每侧每帧至多构建一次变形路径。`TrackRenderer#State` 复用跨段垂度和路径采样缓冲。形变路径构建不为采样点分配对象。近处、远处和阴影复用该结果。`TrackRenderer#cullingAabb` 可能先于绘制调用，按同一垂度上限扩展轮组包围盒，无需触发构建。自由垂度、平滑时间及服务端支撑判据分别使用 §2.3、§4 和 §3.1 规定的类内常量。各客户端使用同一组内建值，`MMClientConfig` 无需承载这些选项。

## 6. 实施顺序

1. `SubPart` 接入 `prePhysicsTick` 清零和 `postPhysicsTick` 结算，实现支撑字段的 `defineSyncedData`、`postTick`、`onSyncedDataUpdated` 与只读 getter。`SubPart#onWheelSupportContact` 订阅两侧分发后的事件，`CollisionHandler#isWheelSupport` 重读并汇总支撑，`MMPayloadRegistry#register` 更新 `sync` 协议版本。
2. `OrderedBeltSolver#assemble` 和 `BeltPath2D#buildTwo` 填语义段，`BeltPath2D#fromData` 透传。`BeltPath2D#withSag` 构建形变路径并复用路径距离与采样入口。
3. `TrackRenderer#State` 保存帧缓存、跨段滤波状态与采样缓冲，`renderTrack` 和 `cullingAabb` 按 §4、§5 接线。`TrackBeltLayout` 用变形路径的长度与切点距离计算非啮合间距。
4. 按 §7 验收。先确认接触时序和线程发布，再标定画面幅度与过坎平滑。

## 7. 验收

- `src/test/java/io/github/sweetzonzi/machine_max/util/geometry/BeltPath2DTest.java` 覆盖端点、切向、中点、弧长索引一致性、两轮不等高、轮盘余隙和闭环回退。水平跨段在 `D < sqrt(6) m` 时验证 `0.02 D²`，在 `D >= sqrt(6) m` 时验证 0.12 m。另验零投影、重力平行跨段和已有切点相切。
- `src/test/java/io/github/sweetzonzi/machine_max/track/TrackEnvelope2DTest.java` 核对翻转、重力投影、内表面半径与基础包络的长度口径。`src/test/java/io/github/sweetzonzi/machine_max/client/render/renderer/TrackBeltLayoutTest.java` 覆盖啮合角节距、回退与连续相位、非啮合槽位及占位节长。把轮位姿和轮相位固定，在 3 m 跨段交替注入每 50 ms 翻转的支撑值，比较滤波稳定后同一非啮合节的沿路径峰峰位移，目标小于 3 mm。至少在 30 和 120 FPS 下，用不同的帧与 tick 相位差重复测试。此项针对余隙允许滤波的抖动场景，避碰截断单独检查。
