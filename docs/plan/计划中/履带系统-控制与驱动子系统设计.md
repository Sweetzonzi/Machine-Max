## 1. 术语与范围

### 1.1 术语

| 术语 | 含义 |
| --- | --- |
| 履带驱动 | 本文的 `TrackDriveSubsystem`：车体侧、控制一个旋转关节的驱动执行器。可驱动主动轮，也可驱动轮式滑移的车轮 |
| 主动轮 | 履带的功率输入轮；履带中唯一有驱动的轮 |
| 负重轮 | 履带成员，只有 `GearJoint`/车体约束，没有轮驱子系统 |
| 主传动 | 把发动机/变速箱功率分到各履带驱动的 `TransmissionSubsystem` 实例 |
| 转向传动 | 把转向电机功率分到各履带驱动的另一个 `TransmissionSubsystem` 实例 |
| 单流 | 转向功率来自主功率，通过制动/离合产生差速 |
| 双流 | 转向功率有独立路径（电机/液压），可直接给左右加/减速度 |
| 功率流 | `MechPower(power, speed)` 沿 `IMechPowerProducer` → `IMechPowerConsumer` 的传递 |
| 反馈转速 | 消费者回给生产者的速度，用于生产者的闭环/功率分配 |
| 横向位置 `x_i` | 第 `i` 个履带驱动连接器在车体局部坐标系中的 X 坐标。正负对应两侧；本文不规定哪侧为左，符号在实现时按车体局部坐标校准 |
| 半径 `r_i` | 第 `i` 个被驱动 `SubPart` 的轮半径（`getMaxWheelRadius()`） |
| 基础速度 `v_base` | 主路给出的履带线速度；由发动机/变速箱/主传动决定，控制器只观测、不直接命令 |

### 1.2 范围

本文讨论履带载具的**控制层**与**驱动支撑层**：

- 谁接受座椅输入、谁编排发动机/变速箱/传动/驱动；
- 驱动如何挂载、如何接收多路功率、如何汇合、如何反馈；
- 单流与双流如何由现有 `TransmissionSubsystem` + `MotorSubsystem` 组合出来；
- 多履带（含四条履带）如何按横向位置分配相对速度；
- 需要引入的类型、属性、信号与接口改动。

不讨论：

- `TrackLink` 的成员关系、`GearJoint` 星形耦合、张力、耐久、断带物理；
- 履带包络/履带节渲染；
- 具体 PID 增益的实机标定值。

这些内容见[履带系统-物理实现设计文档](../进行中/履带系统-物理实现设计文档.md)。

## 2. 现状与约束

### 2.1 现有功率流

当前代码的机械功率链：

```
Engine / Motor（IMechPowerProducer）
  → Gearbox（IMechPowerConsumer + IMechPowerProducer）
    → Transmission（IMechPowerConsumer + IMechPowerProducer）
      → WheelDriver（IMechPowerConsumer）
```

关键约定：

- [`MechPower`](../../../src/main/java/io/github/sweetzonzi/machine_max/common/mech/energy/MechPower.java) 是 `(power, speed)`：`power = τ × |speed|`，`speed` 有符号。
- [`IMechPowerConsumer`](../../../src/main/java/io/github/sweetzonzi/machine_max/common/mech/energy/IMechPowerConsumer.java) 目前只有单值 `getFeedbackSpeed()`；`onMechPowerReceived(String producerName, MechPower power)` 已经带生产者名。
- [`IMechPowerProducer.collectFeedbackSpeeds()`](../../../src/main/java/io/github/sweetzonzi/machine_max/common/mech/energy/IMechPowerProducer.java#L13-L22) 遍历自己的目标，读取消费者的反馈。
- [`TransmissionSubsystem`](../../../src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/TransmissionSubsystem.java) 支持 N 个输出、每个输出一个减速比、开放差速/差速锁。
  - 输出目标转速：`refSpeed = inputSpeed / ratio`。
  - 输出功率：`power = torque * ratio * |targetSpeed|`。
  - 反馈汇总：[`collectFeedbackSpeeds()`](../../../src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/TransmissionSubsystem.java#L356-L365) 对每个输出做 `consumer.getFeedbackSpeed() * ratio` 再平均。
- [`WheelDriverSubsystem`](../../../src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/WheelDriverSubsystem.java) 是车体侧子系统：`controlledConnector` 指向车体—车轮连接器，操作关节的滚动电机（axis 0）与转向伺服（axis 1）。
  - 驱动扭矩由 `power / max(|speed|, MIN_SPEED_FOR_TORQUE)` 反推，再减去制动扭矩。
  - 负扭矩时目标速度为 0、最大力为 `|torque|`，即制动/反拖。

### 2.2 履带的边界

- 履带成员是普通 `SubPart`：主动轮 + 负重轮。
- **只有主动轮有驱动能力**；负重轮没有轮驱子系统，只通过 `GearJoint` 和车体约束被动跟随。
- 主动轮通过 `GearJoint` 与各负重轮耦合：`ω_road = (r_sprocket / r_road) * ω_sprocket`，线速度一致。
- 履带的功率流只到主动轮；负重轮不参与功率分配。
- `TrackLink` 是 `VehicleCore` 级的关系/状态对象，持有成员、约束、张力、耐久；它不被任何驱动子系统持有。
- 履带列表没有名字；控制层按主动轮的横向位置区分左右，不按列表顺序。

### 2.3 设计约束

- 控制层不直接操作物理体；物理体操作经 `getPhysicsLevel().submitImmediateTask(PPhase...)`。
- 主线程负责输入、握手、履带状态；物理线程负责 `onPrePhysicsTick`/`onPostPhysicsTick` 中的驱动与功率汇合。
- 内容包数据驱动：新类型要有静态/动态属性与 schema；不在代码里硬编码车辆。
- 履带控制不复用 `CarControllerSubsystem` 的 Ackermann/漂移逻辑；只复用变速箱/油门等地面载具共性逻辑。
- 一条履带的主动轮是唯一的功率消费者；传动系统的输出只接主动轮，不接负重轮。

## 3. 总体架构

### 3.1 组件图

```
座椅（ControlGroup）
  │ MoveInput / RegularInput
  ▼
TrackControllerSubsystem（编排 + 差速混音）
  ├─ Engine / Motor       油门、转速
  ├─ Gearbox              换挡、离合
  ├─ 主传动（TransmissionSubsystem）──┬─→ TrackDrive(左)
  │                                   └─→ TrackDrive(右)
  ├─ 转向电机（MotorSubsystem）→ 转向传动（TransmissionSubsystem）
  │                                   ├─→ TrackDrive(左)
  │                                   └─→ TrackDrive(右)
  └─ TrackControlSignal → 各 TrackDrive（制动/离合）

TrackLink（VehicleCore）
  └─ 控制器读取 broken / durability，用于能力降级
```

- 主传动与转向传动是**两个 `TransmissionSubsystem` 实例**，不需要新的双流类型。
- `TrackDriveSubsystem` 是**车体侧**子系统，每个主动轮一个；它同时接收主传动与转向传动的 `MechPower`，汇合成一个目标转速/扭矩。
- 单流载具没有转向电机/转向传动；`TrackDriveSubsystem` 只有主路输入，控制器用制动/离合分配。
- 控制器不持有 `TrackLink`；它通过 `drive.drivenSubPart().trackLink` 按需读取履带状态。

### 3.2 组件职责

| 组件 | 状态 | 挂载 | 职责 |
| --- | --- | --- | --- |
| `AbstractGroundControllerSubsystem` | 新增（重构） | 抽象基类 | 地面载具共性：发动机/电机/变速箱发现、油门/刹车/手刹、自动换挡、方向推断、握手、输出模板 |
| `TrackControllerSubsystem` | 新增 | 座椅/车体 | 接受座椅输入；编排发动机/变速箱/传动/转向电机/履带驱动；计算差速相对速度 |
| `TrackDriveSubsystem` | 新增 | 车体，每个主动轮连接器一个 | 多路 `MechPower` 缓存与汇合；驱动/制动/离合；按 producer 反馈；无 `TrackLink` |
| `TransmissionSubsystem` | 现有 | 车体 | 主传动与转向传动的功率分配；比值表达转向几何与符号 |
| `MotorSubsystem` | 现有 | 车体 | 双流/电传动的转向动力源 |
| `GearboxSubsystem` | 现有 | 车体 | 换挡、离合；由控制器编排 |
| `TrackLink` | 现有 | `VehicleCore` | 履带成员、GearJoint、张力、耐久；不参与驱动 |
| `TrackControlSignal` | 新增 | 信号 | `brakeControl` / `clutchEngagement` |
| `TransferCaseSubsystem` | 可选新增 | 车体 | 单引擎方案的分动；本文不作为第一版必需件 |

### 3.3 设计原则

1. **控制器发运动意图，不发绝对速度。** 基础速度由发动机/变速箱/主传动决定；控制器只发相对偏置、制动、离合、转向电机命令。
2. **驱动是通用执行器。** `TrackDriveSubsystem` 不知道“履带/轮胎”，只知道“被驱动 SubPart、半径、上限、多路功率”。
3. **转向几何由传动比值表达。** 主传动全 1；转向传动的 `x_ref / x_i` 同时给出方向和大小；驱动只做求和。
4. **执行器存在性决定分配方式。** 有转向电机/转向传动就走双流分配；没有就走制动分配；不设 `mode` 字段。
5. **`TrackLink` 只做履带状态。** 驱动不持有它；控制器在断带/低耐久时做能力降级。
6. **复用现有功率流。** 本设计引入的是多输入消费者与按 producer 反馈，不引入一套双流功率类型。

## 4. `AbstractGroundControllerSubsystem`

### 4.1 继承关系

```
AbstractSubsystem
  └─ AbstractControllableSubsystem（控制组、座椅输入、信号发送）
       └─ AbstractGroundControllerSubsystem（地面载具共性）
            ├─ CarControllerSubsystem（轮式，Ackermann/漂移）
            │    └─ MotorbikeControllerSubsystem（摩托车）
            └─ TrackControllerSubsystem（差速转向：履带/轮式滑移）
```

- `CarControllerSubsystem` 的现有行为保持不变；共享逻辑上移。
- `MotorbikeControllerSubsystem` 继续继承 `CarControllerSubsystem`，通过它间接继承新基类。
- `TrackControllerSubsystem` 直接继承新基类，不继承 `CarControllerSubsystem`。

### 4.2 共享职责

从 `CarControllerSubsystem` 上移到基类的成员：

- `Map<EngineSubsystem, String> engines`
- `Map<MotorSubsystem, String> motors`
- `Map<GearboxSubsystem, String> gearboxes`
- `actualThrottle` / `actualBrake` / `actualHandBrake` / `handBrake`
- `moveInput` / `moveInputConflict` / `speed`
- `overrideCountDown`
- `handShake()`：通过 `control_outputs` 频道发现发动机/电机/变速箱
- `updateRegularInputs()`
- `calculateAvgSpeedAndControl()`：向发动机/电机发油门，返回平均转速
- `autoGearShift(GearboxSubsystem, float, byte)`
- `inferDirectionForAutoShift(float)`
- `resetSignalOutputs()` 的共享部分
- `onPostPhysicsTick()` 中油门/刹车/手刹输出的发送

### 4.3 抽象钩子

```java
protected abstract void distributeDriveControl(); // onPrePhysicsTick 中调用
protected abstract void sendDriveOutputs();       // onPostPhysicsTick 中调用
protected abstract void resetDriveOutputs();      // 无输入/失活时调用
protected void onHandShakeActuators() {}          // 子类扩展握手
```

基类的 `onPrePhysicsTick` 顺序：

1. `super.onPrePhysicsTick()`
2. 读取 `speed` / 车体横摆角速度
3. 更新 `actualThrottle` / `actualBrake` / `actualHandBrake`
4. 自动换挡与方向推断
5. `calculateAvgSpeedAndControl()`
6. `distributeDriveControl()`

基类的 `onPostPhysicsTick`：

1. `super.onPostPhysicsTick()`
2. 发送共享的油门/刹车/手刹输出
3. `sendDriveOutputs()`

### 4.4 重构范围与回归

- `CarControllerSubsystem` 保留：`wheels`、`computedSteeringCenter`、`driftWeight`、`driftingPD`、`steering()`、`ackermannSteering()`、`driftSteering()`、`calculateDriftBrakeBias()`、`calculateEffectiveBrake()`、轮端 `WheelControlSignal` 分配。
- 基类只收共性；不把 Ackermann 相关字段带进基类。
- 回归验证：
  - `runClient` 驾驶现有轮式载具，油门/刹车/换挡/漂移行为与重构前一致；
  - `runClient` 摩托车，倾斜/转向行为一致；
  - `gradlew test` 现有纯物理测试不受影响。

## 5. `TrackControllerSubsystem`

### 5.1 输入与发现

- 继承 `AbstractGroundControllerSubsystem`，由座椅 `ControlGroup` 发送 `MoveInputSignal` / `RegularInputSignal`。
- `control_outputs` 频道（示意）：
  - `engine_control` → 发动机/主电机
  - `gearbox_control` → 变速箱
  - `track_control` → 各 `TrackDriveSubsystem`
  - `steering_motor_control` → 转向电机
  - `main_transmission_control` → 主传动的差速锁（可选）
- 握手时：
  - 基类发现发动机/电机/变速箱；
  - 子类发现 `TrackDriveSubsystem`，读取 `lateralOffset()`、`radius()`、`drivenSubPart()`；
  - 子类发现转向电机（`MotorSubsystem`，走 `steering_motor_control` 频道）；
  - 转向传动不需要被控制器直接发现：它由转向电机的 `power_output` 驱动，输出接到各履带驱动。
- 履带驱动按 `lateralOffset` 排序；不依赖子系统名或列表顺序。

### 5.2 控制量

- `speed`：车体局部前向速度，与 `CarControllerSubsystem` 同口径。
- `bodyYawRate`：车体局部 Y 角速度。
- `actualSteering`：座椅转向输入的平滑值。
- `r_des`：期望横摆角速度。

```text
r_des = actualSteering * maxYawRate(speed)
r_error = r_des - bodyYawRate
steeringCommand = clamp(feedforward(r_des) + PID(r_error), -1, 1)
```

- `maxYawRate(speed)` 由静态属性表给出；低速允许更大横摆率，高速按侧向加速度限制。
- 单流载具的 `maxYawRate` 还受最小转向半径限制：`|r| <= |v| / R_min`。
- 双流载具在 `v ~ 0` 时允许中心转向，单独给一个 `pivotYawRate` 上限。
- `v_base` 是观测量，不是输出量：
  - 单流：前进取 `max(v_i)`，倒车取 `min(v_i)`（外侧/未制动侧为基础速度）；
  - 双流：取 `mean(v_i)`（主路速度）。
- 每条履带的期望线速度：

```text
v_i^des = v_base + r_des * x_i
```

- 符号约定：本文统一写成 `+`；`r_des` 的方向与车体局部坐标的对应关系在实现时校准，控制器只依赖 `x_i` 的相对大小与符号，不依赖“左/右”命名。
- 控制器只发 `v_i^des` 与 `v_base` 的差（相对偏置）、制动、离合、转向电机命令；不发绝对 `v_i` 给发动机。

### 5.3 单流分配（离合制动/差速制动）

没有转向电机/转向传动时：

```text
v_i^ach = clamp(v_i^des, 0, v_base)          // 前进
        = clamp(v_i^des, v_base, 0)          // 倒车

brake_i = clamp(|v_base - v_i^ach| / max(|v_base|, ε), 0, 1)
```

- 取绝对值，前进/倒车共用同一公式；内外的差别由 `v_i^ach` 相对 `v_base` 的方向决定。
- 前进时，外侧履带的 `v_i^des >= v_base`，钳到 `v_base`，制动 0；外侧不能超过基础速度。倒车时符号相反，钳位区间由 `v_i^ach` 的公式处理。
- 内侧履带的 `v_i^des` 低于基础速度时，按差值制动；`v_i^ach` 接近 0 时离合置 0，制动保持。
- 制动上限由每个 `TrackDriveSubsystem` 的静态属性决定；控制器只发归一化 `brakeControl`。
- 如果各驱动上限不同，控制器可以查询 `linearMaxBrakeForce()` 做等减速度归一化；源数据仍在驱动侧。
- 饱和处理：
  - 实际横摆率 `r_ach = (v_i - v_j) / (x_i - x_j)`（两履带即 `(v_left - v_right)/B`；四履带可用任意一对，或对 `v_i` 关于 `x_i` 做最小二乘）由 `track_speed` 反馈算出；
  - 若 `|r_ach| < |r_des|` 且制动已饱和，降低 `r_des` 或降油门，不能让积分器继续累积；
  - `v_base ~ 0` 时单流没有转向权限，`r_des` 置 0；单流不能中心转向。
- 离合：
  - `v_i^ach <= ε` 时 `clutchEngagement = 0`，否则 1；
  - 驱动内部做离合斜坡；`isPowerPathConnected()` 按目标离合状态判断；
  - 内侧离合断开后，传动系统把它从反馈和功率分配里剔除，发动机只驱动外侧。

### 5.4 双流分配（转向电机 + 转向传动）

有转向电机/转向传动时：

```text
ω_steer_ref = r_des * x_ref / r_track     // r_track 取主动轮半径；各轮半径不一致时按 r_i 修正
```

- 控制器向转向电机发送 `ω_steer_ref`（或对应的油门/速度命令）。
- 转向传动的 `power_outputs` 用 `x_ref / x_i`（带符号），把 `ω_steer_ref` 变成每条履带的转向分量：
  - 两履带：`+1 / -1`；
  - 四履带：`+x_ref/1.5, +x_ref/0.5, -x_ref/0.5, -x_ref/1.5`。
- `TrackDriveSubsystem` 把主路 `MechPower` 与转向路 `MechPower` 求和，得到最终 `ω_i`、`τ_i`。
- 双流时制动只用于停车/紧急/断带；正常转向不靠制动。
- 中心转向时 `v_base = 0`，主路输出为 0，转向电机提供全部功率；发动机/变速箱可以保持怠速或空挡，由控制器协调。

### 5.5 多履带

控制器不把履带分成“左/右”两组，而是逐条按横向位置处理：

- 每个驱动有 `x_i`（横向位置）与 `r_i`（主动轮半径）；
- `v_i^des = v_base + r_des * x_i`；
- 四履带 `x = ±1.5, ±0.5` 时，四条履带得到四个不同的目标线速度；
- 单流：内侧两条按各自差值制动，外侧两条保持 `v_base`；
- 双流：转向传动的比值按 `x_i` 分配，四条履带同时得到正确的转向分量；
- 控制器的横摆反馈仍取车体 `bodyYawRate`，不按履带平均。

### 5.6 `TrackLink` 集成

- 控制器通过 `drive.drivenSubPart().trackLink` 取履带：
  - `trackLink == null`：轮式滑移或未铺履带，跳过履带状态检查；
  - `trackLink.isBroken()`：该驱动 `clutchEngagement = 0`、`brakeControl = 1`，并降低转向权限（`maxYawRate` 打折或 `r_des` 钳位）；
  - `trackLink.durability()`：可选地给该驱动降额；第一版可不做。
- 驱动本身不持有 `TrackLink`，也不判断断带；它只执行离合/制动。
- 断带后主动轮与负重轮的 `GearJoint` 被移除；主动轮制动只作用于主动轮，不能替代履带状态降级。控制器必须依赖 `TrackLink.isBroken()` 降级。

### 5.7 输出与信号

| 输出 | 目标 | 内容 |
| --- | --- | --- |
| 油门 | 发动机/主电机 | `actualThrottle`（共享基类） |
| 换挡/离合 | 变速箱 | `switchGear` / `setClutched`（共享基类） |
| `TrackControlSignal` | 每个 `TrackDriveSubsystem` | `brakeControl` / `clutchEngagement` |
| 转向命令 | 转向电机 | 目标转速或油门 |
| 差速锁（可选） | 主传动 | 手动差速锁信号 |

- `TrackControlSignal` 走 `sendCallbackToListener` 逐个发送，避免广播串扰。
- 驱动的 `getAcceptedChannels()` 返回 `track_control`。
- 控制器的 `onPostPhysicsTick` 发送共享输出；`sendDriveOutputs()` 发送履带/转向输出。

### 5.8 线程

| 阶段 | 线程 | 内容 |
| --- | --- | --- |
| `onTick` | 主线程 | 控制组、输入、握手、履带状态读取 |
| `onPrePhysicsTick` | 物理线程 | 横摆目标、混音、`TrackControlSignal` 计算、转向电机命令 |
| `onPostPhysicsTick` | 物理线程 | 发送油门/制动/履带/转向信号 |
| 物理体操作 | 物理线程 | 仅经驱动的关节电机/制动，不直接改刚体 |

### 5.9 失败模式

| 情况 | 行为 |
| --- | --- |
| 没有 `TrackDriveSubsystem` | 控制器不激活；不输出油门/制动 |
| 驱动连接器缺失/未连接 | 该驱动禁用；控制器按剩余驱动降级 |
| 主动轮被销毁/半径 <= 0 | 该驱动禁用；履带 `TrackLink` 自行解散或降级 |
| 履带断带 | 该驱动离合 0、制动 1；转向权限降低 |
| 没有转向电机/转向传动 | 走单流制动分配；不能中心转向 |
| 制动饱和 | 降低 `r_des`/油门；积分器抗饱和 |
| 转向电机堵转/功率不足 | 转向命令饱和；车体横摆误差由 PID 处理 |

## 6. `TrackDriveSubsystem`

### 6.1 挂载与连接

`TrackDriveSubsystem` 是**车体侧**子系统，和 `WheelDriverSubsystem` 同一模式：

- 挂在车体 `SubPart` 上；
- 静态属性 `connector` 指向车体—主动轮连接器；
- 被驱动 `SubPart` 是连接器另一侧的主动轮；
- 只操作关节的滚动电机（axis 0），不碰转向轴；
- 半径：`drivenSubPart.getMaxWheelRadius()`，不加 override；
- 横向位置：`connector.actualTransform.getTranslation().x`；
- 不持有 `TrackLink`。

被驱动 `SubPart` 可以是主动轮，也可以是轮式滑移的车轮；驱动本身不区分类别。

### 6.2 属性

静态属性（示意，字段名以实现时 schema 为准）：

```json
{
  "type": "machine_max:track_drive",
  "definition": "machine_max:track_drive_heavy",
  "connector": "connector.machine_max.left_sprocket",
  "control_inputs": ["track_control"],
  "max_drive_torque": 30000,
  "max_brake_torque": 20000,
  "max_speed": 120,
  "speed_outputs": { "track_speed": ["local", "global"] },
  "force_outputs": { "track_force": ["local", "global"] }
}
```

- `max_drive_torque` / `max_brake_torque`：关节扭矩（N·m）。履带切线力 = 扭矩 / 半径。
- `max_speed`：主动轮角速度上限（rad/s）；线速度上限 = `max_speed * radius`。
- 驱动向上层提供 `linearMaxDriveForce()` / `linearMaxBrakeForce()` / `linearMaxSpeed()`，控制器做饱和判断。
- 动态属性只需要 `connector`、控制频道、输出频道；没有 `TrackLink`、没有 `radius_override`。

### 6.3 多输入缓存

```java
private final Map<String, MechPower> received = new ConcurrentHashMap<>();

@Override
public void onMechPowerReceived(String producerName, MechPower power) {
    received.put(producerName, power);
}

@Override
public boolean isPowerPathConnected(String producerName) {
    return clutchEngaged;
}
```

- 每路 producer 缓存最近一次 `MechPower`；`MechPower` 不可变，`ConcurrentHashMap` 足够。
- 载具结构变化、传动断开或驱动重新装配时清空 `received`；下一物理 tick 由生产者重新下发。
- 离合断开时：
  - `isPowerPathConnected()` 返回 false，传动系统的反馈收集/功率分配排除该驱动；
  - `onMechPowerReceived()` 照常缓存，但 `onPrePhysicsTick` 不把该路计入汇合；
  - 重新结合时从缓存恢复，避免丢一帧。
- 生产者断开时下发 `MechPower.EMPTY`；汇合时跳过 `isEmpty()`。
- 缓存按 producer 名区分，不要求 producer 是“主路”或“转向路”。

### 6.4 汇合

```java
float omega = 0f;
float torque = 0f;
for (var entry : received.entrySet()) {
    if (!isPowerPathConnected(entry.getKey())) continue;
    MechPower p = entry.getValue();
    if (p == null || p.isEmpty()) continue;
    float speed = p.speed();
    omega += speed;
    torque += p.power() / Math.max(Math.abs(speed), MIN_SPEED_FOR_TORQUE);
}

torque = Math.clamp(torque, -maxDriveTorque, maxDriveTorque);
torque -= brakeControl * maxBrakeTorque;

rollingMotor.set(MotorParam.MaxMotorForce, Math.abs(torque));
if (torque > 0) {
    rollingMotor.set(MotorParam.TargetVelocity, -Math.clamp(omega, -maxSpeed, maxSpeed));
} else {
    rollingMotor.set(MotorParam.TargetVelocity, 0);
}
```

- `omega` 是主路与转向路的叠加；符号由各路的 `MechPower.speed` 决定。
- `torque` 是各路扭矩的叠加；内侧负功率自然变成负扭矩，进入制动/反拖分支。
- 制动在汇合之后叠加，上限由该驱动静态属性决定。
- 负功率不是异常：转向时内侧功率为负，正是差速所需的反拖/制动。
- 与 `WheelDriverSubsystem` 的负扭矩分支一致：目标速度 0、最大力 `|torque|`。

### 6.5 反馈

```java
@Override
public float getFeedbackSpeed(String producerName) {
    MechPower p = received.get(producerName);
    return p == null || p.isEmpty() ? 0f : p.speed();
}
```

- 驱动按 producer 返回**该路缓存的分量**，不是合成后的总速度。
- 传动系统在上游乘回自己的输出比值：
  - 主传动比值 1：反馈 = 主路分量；
  - 转向传动比值 `x_ref / x_i`：反馈 = `(ω_in * x_i/x_ref) * (x_ref/x_i) = ω_in`；
  - 左右符号在传动比里被抵消，平均值不会归零。
- 每个 producer 看到的是自己的路径速度，主路不会被转向分量污染，转向路不会被主路分量污染。
- `track_speed` / `track_force` 输出供控制器/HUD 使用，不参与 producer 反馈。

### 6.6 离合与制动

- `TrackControlSignal`：

```java
public record TrackControlSignal(float brakeControl, float clutchEngagement) {}
```

- `brakeControl`：0~1，乘以 `max_brake_torque`。
- `clutchEngagement`：0~1，1 为结合；驱动内部做斜坡，避免发动机反馈速度阶跃。
- `isPowerPathConnected()` 按目标离合状态判断；离合 0 时该路退出传动反馈，发动机只看到剩余履带。
- 制动上限逐驱动配置；控制器不需要全局制动上限。

### 6.7 线程与失败模式

| 情况 | 行为 |
| --- | --- |
| `received` 写入/读取 | 物理线程；`ConcurrentHashMap` |
| 连接器未连接 | 驱动禁用；不输出电机力 |
| 被驱动 `SubPart` 销毁 | 驱动禁用；控制器降级 |
| 半径 <= 0 | 驱动禁用并记录日志 |
| 某路 `MechPower.EMPTY` | 跳过该路；其余路继续 |
| 离合 0 | 该路不计入汇合；`isPowerPathConnected` false |
| `omega` 为 0、`torque` 非 0 | 目标速度 0、最大力 `|torque|`；保持/制动 |
| `torque` 超过上限 | 钳位；控制器通过 `track_speed` 看到饱和 |

### 6.8 与 `WheelDriverSubsystem` 的关系

| 项 | `WheelDriverSubsystem` | `TrackDriveSubsystem` |
| --- | --- | --- |
| 挂载 | 车体，连接器指向车轮 | 车体，连接器指向主动轮/被驱动轮 |
| 关节轴 | 滚动 axis 0 + 转向 axis 1 | 仅滚动 axis 0 |
| 输入 | 单路 `MechPower` | 多路 `MechPower` 缓存与求和 |
| 反馈 | 单值实际转速 | 按 producer 返回各分量 |
| 上限 | 单轮 `max_drive_force`/`max_brake_force` | 履带级 `max_drive_torque`/`max_brake_torque` |
| `TrackLink` | 不持有 | 不持有 |
| 用途 | 转向轮 | 主动轮、轮式滑移车轮 |

`WheelDriverSubsystem` 保持现有行为；`TrackDriveSubsystem` 是独立的通用差速驱动执行器。

## 7. 功率流：双传动组合

### 7.1 接口改动

在 [`IMechPowerConsumer`](../../../src/main/java/io/github/sweetzonzi/machine_max/common/mech/energy/IMechPowerConsumer.java) 增加按 producer 的反馈：

```java
default float getFeedbackSpeed(String producerName) {
    return getFeedbackSpeed();
}
```

调用侧改动：

- [`IMechPowerProducer.collectFeedbackSpeeds()`](../../../src/main/java/io/github/sweetzonzi/machine_max/common/mech/energy/IMechPowerProducer.java#L13-L22)：
  ```java
  result.put(entry.getKey(), consumer.getFeedbackSpeed(getName()));
  ```
- [`TransmissionSubsystem.collectFeedbackSpeeds()`](../../../src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/TransmissionSubsystem.java#L356-L365) 与 `collectRawFeedbackSpeeds()`：
  ```java
  consumer.getFeedbackSpeed(getName())
  ```
- `WheelDriverSubsystem` 使用默认实现，行为不变。
- `TrackDriveSubsystem` 覆盖，返回缓存分量。

### 7.2 主传动

- 用现有 `TransmissionSubsystem`。
- `power_outputs` 全部 `1.0`，每个履带驱动一个输出：

```json
{
  "power_outputs": {
    "subsystem.machine_max.left_track_drive": 1.0,
    "subsystem.machine_max.right_track_drive": 1.0
  }
}
```

- 主传动把基础速度/功率等分给各履带驱动；`diff_lock` 由内容包选择（开放/锁止）。
- 主传动的反馈是各驱动主路分量的平均，等于基础速度。

### 7.3 转向传动

- 同样用现有 `TransmissionSubsystem`。
- `power_outputs` 用带符号的 `x_ref / x_i`：

```json
{
  "power_outputs": {
    "subsystem.machine_max.left_track_drive": 1.0,
    "subsystem.machine_max.right_track_drive": -1.0
  }
}
```

- 两履带：`+1 / -1`，`x_ref = |x|`。
- 四履带（`x = ±1.5, ±0.5`，`x_ref = 1.5`）：

```json
{
  "power_outputs": {
    "subsystem.machine_max.left_outer_track_drive": 1.0,
    "subsystem.machine_max.left_inner_track_drive": 3.0,
    "subsystem.machine_max.right_inner_track_drive": -3.0,
    "subsystem.machine_max.right_outer_track_drive": -1.0
  }
}
```

- 转向传动建议 `diff_lock: false`（开放差速）。
- 控制器的转向电机命令 `ω_steer_ref` 进入转向传动；转向传动的比值把它变成每条履带的转向分量。

### 7.4 负比值的正确性

`TransmissionSubsystem` 对负比值的处理是确定的：

1. **输出目标速度**：
   ```text
   refSpeed = inputSpeed / ratio
   ```
   负比值把目标速度反向；`computeTargetSpeed()` 用 `direction = signum(refSpeed)` 处理符号，返回带符号的目标。

2. **输出功率**：
   ```text
   power = torque * ratio * |targetSpeed|
   ```
   比值为负的一侧，功率为负；负功率在履带驱动里变成负扭矩，进入制动/反拖。比值为正的一侧功率为正，驱动。两侧符号相反就是差速本身。

3. **反馈汇总**：
   ```text
   feedback = consumer.getFeedbackSpeed() * ratio
   ```
   左右输出的反馈都乘自己的比值：
   - 左：`+ω * (+1) = +ω`
   - 右：`-ω * (-1) = +ω`
   - 平均：`+ω`，不抵消。

   四履带时同理：`fb_i = ω_in * x_i/x_ref`，乘 `x_ref/x_i` 后都是 `ω_in`，平均 `ω_in`。

4. **功率与扭矩分配**：
   ```text
   P_i = torque_common * ratio * |targetSpeed| = torque_common * |inputSpeed|
   τ_i = P_i / |ω_i| = torque_common * |ratio|
   ```

   其中 `torque_common` 是 `distributeOpenDiff` 的公共输出扭矩：
   `torque_common = P_in / max(Σ|fb_j * ratio_j|, 0.2|inputSpeed|)`。
   在本例的 `Σ|fb_j * ratio_j| = N|inputSpeed|` 下，`P_i = P_in/N`，各输出等功率；比值绝对值更大的履带得到更大扭矩、更低转速，比值绝对值更小的相反。这是转向差速的合理分配。
   以上按 `computeTargetSpeed` 的理想同步目标推导；实际目标含驱动偏置时，功率按 `targetSpeed` 略有偏差，符号与反馈关系不变。

**结论：** 负比值不是异常输入，是转向传动的正常表达方式；反馈不会抵消，功率符号相反是差速所需。

### 7.5 转向功率源

| 方案 | 主路 | 转向路 | 转向速度独立 | 备注 |
| --- | --- | --- | --- | --- |
| 引擎 + 电机 | 引擎→变速箱→主传动 | 电机→转向传动 | 是 | 第一版推荐；复用 `MotorSubsystem`/`TransmissionSubsystem` |
| 引擎 + 可控分动箱 + 双传动 | 引擎→分动箱→主传动 | 分动箱→转向传动 | 否，随发动机转速 | 固定比转向传动的速度是 `发动机转速/传动比`；低速转向弱 |
| 引擎 + 分动箱 + 可变比转向传动 | 主传动 | 液压/可变比传动 | 是 | 接近双流从零件搭出；需要新的可变比传动 |
| 专用双流子系统 | 内部 | 内部 | 是 | 本设计用主传动 + 转向传动 + 多输入驱动替代 |

- 分动箱只分配功率/扭矩，不分配速度。固定比转向传动的转向速度仍随发动机转速。
- 第一版采用“引擎 + 电机”：主路和转向路反馈天然分开，中心转向时电机自己带负载，不需要发动机驱动转向泵。
- 单引擎机械双流作为后续选项：需要可控分动箱 + 可变比转向传动；固定比传动不足以让转向速度独立。

### 7.6 四履带示例

以 279 工程式四条履带、`x = ±1.5, ±0.5`、`x_ref = 1.5` 为例：

| `x_i` | 转向传动比值 | 转向目标速度 | 转向扭矩 |
| --- | --- | --- | --- |
| +1.5 | +1.0 | +ω_steer | τ_steer |
| +0.5 | +3.0 | +ω_steer/3 | 3τ_steer |
| -0.5 | -3.0 | -ω_steer/3 | -3τ_steer |
| -1.5 | -1.0 | -ω_steer | -τ_steer |

- `x_i` 的正负对应两侧；`+1.5` 与 `+0.5` 是同一侧的外/内位置。转向时该侧整体加速或减速，哪侧加速取决于 `r_des` 的符号。
- 线速度：`v_i = v_base + ω_steer * x_i * (r_track/x_ref)`，与 `x_i` 成正比；
- 功率：每条履带的转向功率等分（符号由比值给出）；
- 反馈：每条履带返回 `ω_steer * x_i/x_ref`，乘回比值后都是 `ω_steer`，平均不抵消；
- 单流时没有转向传动，转向内侧的两条按 `v_i^des` 制动，转向外侧的两条保持 `v_base`；不能中心转向。

### 7.7 由现有传动组合表达双流

本设计用“主传动 + 转向传动 + 多输入履带驱动”的组合表达双流：

- 转向几何在转向传动的 `power_outputs` 比值里，内容包作者可直接看到；
- 履带驱动只做多路求和，不判断主/转向；
- 不需要 `TrackSteeringTransmissionSubsystem`；
- 单流是同一套组合去掉转向电机/转向传动；控制器按执行器存在性选择分配方式。

```json
    "definition": "machine_max:steering_transmission",
    "power_outputs": {
      "subsystem.machine_max.left_track_drive": 1.0,
      "subsystem.machine_max.right_track_drive": -1.0
    }
  }
}
```

- 发动机 → 变速箱 → 主传动；转向电机 → 转向传动；两组传动都指向同一对履带驱动。
- 转向传动的 `definition` 里 `diff_lock: false`。
- 四履带时增加两条 `track_drive`，主传动输出全 `1.0`，转向传动输出按 `x_ref/x_i`。

### 8.4 持久化与网络

- `TrackControllerSubsystem` / `TrackDriveSubsystem` 的静态/动态属性随内容包加载；运行时状态（离合、制动、缓存）不单独持久化。
- `TrackLinkData` 不变；不引入网络载荷。
- 履带驱动的 `track_speed` / `track_force` 是本地/全局信号，供 HUD/控制器使用；不引入 `SynchedEntityData`。
- 若后续需要客户端 HUD 显示离合/制动，再加同步字段；第一版不做。
- `TrackControlSignal` 是本地信号，不走网络。

### 8.5 线程表

| 数据 | 写入 | 读取 | 同步方式 |
| --- | --- | --- | --- |

## 9. 测试与验收

### 9.1 纯单元测试

把可纯化的数学抽成不依赖 Minecraft 的工具类，放 `src/test/java/.../track/`：

- `TrackPowerCombinerTest`
  - 单路输入：`ω`、`τ` 与 `MechPower` 一致；
  - 双路同向：`ω = ω1 + ω2`，`τ = τ1 + τ2`；
  - 双路反向（转向）：内侧 `τ` 为负，外侧为正；
  - `MechPower.EMPTY` 跳过；
  - `|speed| < MIN` 时扭矩钳位；
  - 驱动上限钳位；
  - 离合断开时该路不计入。
- `TrackControlMathTest`
  - 两履带 `v_i^des = v_base + r*x_i`；
  - 四履带 `x = ±1.5, ±0.5` 的线性分配；
  - 单流钳位 `[0, v_base]` / `[v_base, 0]`；
  - 制动量归一化；
  - `v_base ~ 0` 时单流 `r_des = 0`。
- 反馈测试
  - 主传动比值 1、转向传动 `±1`，左右反馈乘回后都是 `ω`；
  - 四履带 `x_ref/x_i` 比值，反馈乘回后都是 `ω_steer`；
  - 不发生抵消。

### 9.2 运行期验证

- `runServer`：内容包解码、`TRACK_CTRL`/`TRACK_DRIVE` 注册、schema 诊断无错误。
- `runClient`：
  - 两履带直行：左右 `track_speed` 一致；
  - 两履带转向：内侧减速、外侧保持/加速；
  - 双流中心转向：左右反向，车体原地转；
  - 四履带转向：四条线速度按 `x_i` 线性分布；
  - 断带：该侧驱动离合 0、制动 1，转向权限降低；
  - 离合断开/结合：发动机反馈速度平滑，无阶跃；
  - 制动饱和：转向不足，但不抖、不积分饱和；
  - 性能：每 tick 的驱动/混音为 O(N)，N 为履带数。

### 9.3 验收标准

1. 直行时左右履带线速度差在容差内；
2. 转向时内外侧速度符号/大小符合 `v_i = v_base + r*x_i`；
3. 单流载具不能中心转向；双流可以；
4. 四履带的速度分布与 `x_i` 成正比；
5. 断带后该驱动退出功率流，车辆可继续用剩余履带行驶；
6. 传动反馈不因左右符号抵消而失稳；
7. 不引入网络载荷；客户端只消费既有物理同步；
8. 现有轮式/摩托车行为不变。

## 10. 设计取舍

### 10.1 两个传动 + 多输入驱动，而非专用双流子系统

- **本设计**：主传动与转向传动都是现有 `TransmissionSubsystem`；履带驱动做多路求和。
- **备选**：`TrackSteeringTransmissionSubsystem` 作为一个独立类型，内部完成主路/转向路叠加。
- **选择理由**：复用现有功率流与内容包接线；转向几何直接写在 `power_outputs` 里；不需要新的大类。代价是履带驱动要支持多输入缓存与按 producer 反馈。

### 10.2 车体侧驱动，而非主动轮侧

- **本设计**：`TrackDriveSubsystem` 挂在车体，`controlledConnector` 指向车体—主动轮连接器；主动轮保持简单零件。
- **备选**：驱动子系统挂在主动轮 `SubPart` 上。
- **选择理由**：与 `WheelDriverSubsystem` 的既有模式一致；主动轮不需要拥有子系统；关节电机在车体侧即可控制。

### 10.3 不设 `mode`

- **本设计**：所有差速转向共用一套混音；执行器存在性决定单流/双流分配。
- **备选**：`TRACK` / `SKID_STEER` / `DUAL_FLOW` 等 mode 字段。
- **选择理由**：mode 与执行器能力重复，容易出现“mode 说双流但没有转向电机”的不一致；直接查询执行器更可靠。履带与轮式滑移的数学相同，不需要分支。

### 10.4 传动比值表达转向几何，而非驱动侧 `s_i`

- **本设计**：转向传动 `power_outputs = x_ref/x_i`；驱动只求和。
- **备选**：转向传动等分输出，驱动按 `s_i` 缩放。
- **选择理由**：现有传动的比值、反馈乘回、功率符号已经能表达方向和大小；把几何放在传动比值里，内容包作者可直接看到，驱动保持通用。负比值是正常输入，不是异常。

### 10.5 第一版引擎 + 电机，而非分动箱

- **本设计**：主路引擎/变速箱，转向路电机/转向传动。
- **备选**：单引擎 + 可控分动箱 + 转向传动。
- **选择理由**：电机让转向速度独立于发动机转速；反馈天然分开；复用现有 `MotorSubsystem`。分动箱只分配功率，不分配速度；固定比转向传动的转向速度随发动机转速，低速转向弱。分动箱作为后续单引擎方案。

### 10.6 缓存分量反馈，而非合成速度反馈

- **本设计**：驱动按 producer 返回各路的缓存分量；传动比在上游乘回。
- **备选**：驱动返回合成后的实际速度，或把实际速度按比例拆给各路。
- **选择理由**：缓存分量确定、稳定，主路/转向路互不污染；传动比乘回后正好还原各路输入速度。负载反馈的细化（主路 = 实际 − 转向分量）作为后续选项，需要标记转向 producer。

## 11. 未决与后续

1. **分动箱**：单引擎机械双流的 `TransferCaseSubsystem`；需要配合可变比转向传动才能让转向速度独立。
2. **转向电机速度环**：`MotorSubsystem` 当前是油门/扭矩输入；控制器可以用 PD 闭速度环，或给电机加 `target_speed` 模式。
3. **负载反馈细化**：`getFeedbackSpeed(producerName)` 返回缓存分量；若要保留主路负载反馈，主路分量可以取 `实际 − 转向分量`，需要在驱动静态属性里标记转向 producer。
4. **四履带归一化**：`x_ref` 的取值、非对称履带布局、各主动轮半径不一致时的修正。
5. **制动热/能量/再生**：单流内侧制动耗散、双流转向功率、再生制动的建模深度。
6. **内容包 schema**：`TRACK_CTRL` / `TRACK_DRIVE` 的完整字段、默认值、诊断信息。
7. **`AbstractGroundControllerSubsystem` 重构回归**：轮式/摩托车行为、现有测试、`runClient` 实机。
8. **HUD**：履带速度/力矩/离合/断带状态的显示；是否走现有 `global` 信号。
9. **渲染**：履带包络/履带节/相位动画；见物理文档第 8 章，不在本文范围。

## 附录 A：符号与公式

| 符号 | 含义 |
| --- | --- |
| `P` | `MechPower.power`（W） |
| `ω` | `MechPower.speed`（rad/s，有符号） |
| `τ` | 扭矩（N·m） |
| `v` | 履带线速度（m/s） |
| `r` | 主动轮/车轮半径（m） |
| `x_i` | 第 `i` 条履带的横向位置（m） |
| `x_ref` | 转向比值的参考横向位置（m） |
| `r_des` | 期望横摆角速度（rad/s） |
| `v_base` | 主路基础线速度（m/s） |

核心公式：

```text
τ_i = P_i / max(|ω_i|, MIN_SPEED_FOR_TORQUE)
ω   = Σ ω_i
τ   = Σ τ_i
v_i = ω_i * r_i
v_i^des = v_base + r_des * x_i
转向传动比值 = x_ref / x_i
speed_out = speed_in / ratio
feedback_upstream = mean(feedback_i * ratio_i)
```
