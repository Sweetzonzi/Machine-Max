# Machine-Max 渲染 — 屏幕空间遮挡（S3）设计

> **状态**：设计完成，未实现。落地位置是 `shaders/program/screen_space_light.fsh` 的表面项，参数与判据见 §4、§9。
>
> **本文自包含**：S2 与 S3 的定义、公式、参数默认值、失败模式与验收都在文内给出，不要求先读其他文档。引用现有代码只为定位。

**术语**：`P` = 本像素的视空间表面点；`C` = 光源的视空间光心；`R` = 光源的照明半径；`raw` = 深度快照里的原始深度值（0–1，未解码）；`z` = 前向深度（m）。

## 1. 问题：S2 回答的不是表面项要问的问题

链路里有两种"光源可不可见"，它们不是同一个问题：

| 判定 | 回答的问题 | 粒度 | 谁需要 |
| --- | --- | --- | --- |
| S2 | **相机**能不能看见光源 | 整盏灯（一次深度采样） | 星芒：光源不在画面上就没有星芒 |
| S3 | **这个受光点**能不能看见光源 | 逐像素 | 表面项 `E_i` |

S2 用"相机能否看见光源"代替"受光点能否看见光源"，在两个方向上都错：

| 几何 | S2 的结论 | 事实 | 观感 |
| --- | --- | --- | --- |
| 光源被墙挡住、但它的光池落在可见地面上（门缝、墙角、枪口被自车挡住的前方地面） | 整盏跳过 | 那些地面确实被照到 | 该亮的地方不亮 |
| 光源可见、但某块可见表面背对它（墙角内侧、车体背面） | 整盏通过 | 那块表面没有受光 | 沿墙漏光 |

第一种是第一轮实机反馈里的主导现象：**光照范围可见，但不亮**。它不是参数问题，S2 的采样点上根本没有"这块地面"的信息。

## 2. 为什么屏幕空间能算，而且能算得便宜

手上只有一张从相机出发的深度图，但线段 `P→C` 的两个端点都在这个视锥里时，它在屏幕上的投影是一条直线，而且沿这条直线的深度是**仿射**的。

**推导**。设视空间点 `(x, z)`（`z` 为前向深度）、投影后屏幕坐标 `x_s = x / z`（差一个常数因子，不影响线性）。沿 3D 线段 `P→C`，令参数 `t ∈ [0,1]`，则 `x(t) = x_P + t·Δx`、`z(t) = z_P + t·Δz`，都是 `t` 的线性函数。于是

```text
x_s(t) = (x_P + t·Δx) / (z_P + t·Δz)
```

把 `t` 用 `x_s` 反解并代入 `1/z`，得到 `1/z` 是 `x_s` 的一次函数：**屏幕上的直线段里，`1/z` 线性插值**。

而深度快照的编码恰好是 `1/z` 的仿射函数（`BlastProjectionUtil#calibrateDepth` 两点标定）：

```text
raw = DepthB / z − DepthA        ⇔        z = DepthB / (raw + DepthA)
```

所以 **`raw` 可以直接沿屏幕线段线性插值**，两种深度约定（标准与反向）都成立。这条性质是整个方案便宜的原因：每一步只要一次插值、一次采样、一次比较，**不需要重投影、没有除法、不做 sRGB 转换**。

## 3. 算法

```glsl
// 只在表面项真正求值的那一段里执行（本像素有表面、且 d < R）
float rayRaw   = zBuf;                         // 本像素的 raw 深度 = 线段在 P 端
float lightRaw = DepthB / zc - DepthA;         // 线段在 C 端（每盏灯一次除法）
vec2  duv = (lightPxUV - texCoord) / STEPS;

float occ = 0.0;
for (int k = from; k <= to; k++) {
    vec2 uv = texCoord + duv * k;
    if (uv.x < 0.0 || uv.x > 1.0 || uv.y < 0.0 || uv.y > 1.0) continue;   // 出屏的步不判
    float sceneRaw = texture(MCDepthSampler, uv).r;
    float ray      = rayRaw + (lightRaw - rayRaw) * (k / STEPS);          // 线性插值
    float diff     = (sceneRaw - ray) * depthSign - BIAS_REL * ray;       // > 0 表示场景比射线更近
    occ += clamp(diff / (SOFT_REL * ray) + 0.5, 0.0, 1.0);                // 半软边，避免采样点级的硬台阶
}
float visible = 1.0 - occ / float(to - from + 1);
e += min(radiance * (intensity * win * orient * visible / dEff2), vec3(E_MAX));
```

`depthSign` 由 `DepthB` 的符号给出：`DepthB < 0` 时 `z` 随 `raw` 增大而增大（标准约定，场景更近即 `raw` 更小），取 `-1`；否则取 `+1`。每个 pass 算一次，不进循环。

`from` / `to` 由两个端点的排除区给出：

```text
from = ceil (STEPS · START)
to   = floor(STEPS · (1 − LIGHT_MARGIN))
```

`to < from` 时（两个排除区吃掉了整条线段）直接判可见，不做除法：`STEPS = 8` 时 `from = 1`、`to = 7`，共 7 次采样，不会发生；这条守卫是给未来调大 `START` 或调小 `STEPS` 留的。

**为什么两端都要排除**：

- **`START`（近端）**：投影到同一像素的两个表面会互相遮挡。掠射的地面（视线几乎与地面平行）上，射线刚离开 `P` 时与地面只差毫厘，必然自遮挡成条纹（shadow acne）。排除前 6% 的段。
- **`LIGHT_MARGIN`（灯端）**：光源常贴在自己的几何体旁边（枪口在炮口制退器里、信号弹挂在自己的弹体上、爆炸夹在火球里）。这一小段在屏幕上就是光源自己的像素，必然被判成"更近"。排除最后 12% 的段。

### 3.1 与既有六条工程契约的对应

`docs/plan/进行中/渲染-屏幕空间光照通用化设计.md` §9.3 已经给出 S3 的六条工程契约。它们是**约束**，本节是这些约束的具体落法：

| 契约 | 本文怎么落 |
| --- | --- |
| 1. 先用距离/强度筛掉无贡献像素再步进 | 步进嵌在表面项内部，只有"本像素有表面、`d < R`、且光源可见性不否决"时才执行。强度阈值没有采用：步进只发生在受光像素上，省下的不是大头 |
| 2. 对线段做近裁面/视口裁剪，两端留排除区 | 出屏的步跳过；两端排除用线段比例（`S3_START`、`S3_LIGHT_MARGIN`），因为屏幕空间步进的完整性由屏幕长度决定，用米制反而与 `STEPS` 脱钩 |
| 3. 屏幕步进必须透视正确，插值 `Q/w` 与 `1/w`，不能线性插值米制深度 | 插值的是 `raw`。标定式 `raw = DepthB/z − DepthA` 说明 `raw` 是 `1/z` 的**仿射函数**，所以沿线段的仿射插值就是 §9.3 要求的 `1/w` 插值；比"除回视空间深度"省掉每步一次除法（附录 B） |
| 4. 深度用有限厚度区间，不能把"射线在表面之后"一律判成命中 | `S3_BIAS_REL` 与 `S3_SOFT_REL` 给出厚度带：`diff > BIAS + SOFT/2` 全命中、`< BIAS − SOFT/2` 全不命中、中间线性计入。厚度按 `raw` 的相对量给，因此厚度随距离成比例缩放，前景不会拖出过长的假阴影 |
| 5. 结果区分 `HIT` / `NO_HIT` / `UNKNOWN`，未知按可见处理 | 出屏与裁断的步不产生证据，只有"明确更近"才计入 `occ`；`visible = 1 − occ/K` 因此是"命中比例"而不是"无遮挡证明" |
| 6. `K = 4/8/16` 是质量/成本候选，不承诺误差单调下降、首期不做抖动 | v1 取 `K = 8`；`SOFT_REL` 负责压台阶，不引入逐帧随机抖动（本链没有时域累积，抖动会变成噪声） |

## 4. 参数

| 常量 | 落地值 | 作用 |
| --- | --- | --- |
| `S3_STEPS` | 8 | 线段上的采样数；0 表示关闭 S3（A/B 用） |
| `S3_START` | 0.06 | 近端排除比例，压自遮挡条纹 |
| `S3_LIGHT_MARGIN` | 0.12 | 灯端排除比例，压光源自身几何的误判 |
| `S3_BIAS_REL` | 0.01 | 相对偏置：判定阈值取 `raw` 的 1%，抵消采样点的量化 |
| `S3_SOFT_REL` | 0.02 | 半软边宽度（`raw` 的 2%），避免 8 级台阶 |

`BIAS_REL` 之所以按 `raw` 的相对值给：`raw` 是 `1/z` 的仿射函数，**距离的相对变化与 `raw` 的相对变化同阶**，因此"偏置 1%"在任何距离上都近似是"深度差 1%"。

## 5. 失败模式与回落

屏幕空间遮挡的已知边界，写清楚是为了不让它们被当成缺陷反复"修"：

| 情形 | 行为 | 处理 |
| --- | --- | --- |
| 光源在相机背后（`zc <= NEAR_Z`） | 无法投影，判可见 | 保持现状：表面项照算，不投影就没有遮挡信息 |
| 光心的屏幕投影出屏 | 仍可按屏幕内的一段走 | 线段按出屏裁剪，出屏的步不判；灯端排除区照常 |
| 遮挡物不在画面上（屏幕外、或相机背后） | 判可见 | 屏幕空间固有限制；S3 不是阴影贴图 |
| 薄遮挡物（栏杆、栅栏、玻璃） | 可能漏光 | 采样间距大于薄物件的屏幕宽度时必然漏；`STEPS` 越大漏得越少 |
| 光源贴在遮挡物上 | 灯端排除区吃掉 | 超出 12% 的遮挡物仍会被判到 |
| 掠射的地面 | 自遮挡条纹 | `START` 与 `BIAS_REL` 一起压；先加 `START`，再加偏置 |
| 线段在屏幕上退化成一个点（光源几乎沿相机视线） | 所有采样落在同一像素：光源在表面之后 → 全命中，在表面之前 → 全不命中 | 两者都正确，不需要特判 |

## 6. 与现有两项的关系

三项各管一件事，互不替代：

| 项 | 判定 | 粒度 |
| --- | --- | --- |
| 表面项 | S3：`P` 能不能看见 `C` | 逐像素，沿 `P→C` 走 K 步 |
| 光晕 | 沿相机视线的解析积分 + `t_hit` 截断 | 逐像素，沿**相机射线** |
| 星芒 | S2：相机能不能看见光源 | 整盏灯，一次采样 |

**`LightOcclusion` 的语义收窄为"星芒的光源可见性"**：它只决定星芒是否受光心可见性约束；表面项由 §3 的步进决定，光晕由逐像素 `t_hit` 决定。字段、上传与容差都保留，来源的 `SOURCE_DEPTH` / `NONE` 只影响星芒。

**`NONE` 的用途**：车灯一类的常亮光源可以把星芒的光源门禁关掉，也可以完全不要星芒。

## 7. 性能

1080p、60 fps 即 124 M 像素/秒。下表只数**深度采样**（漫反射采样不计）：本像素一次、S4 的四邻域四次、每盏光源 S2 一次、S3 每盏 K 次。

| 配置 | 每像素深度采样 | 折合吞吐 | 占中端 GPU 的比例 |
| --- | --- | --- | --- |
| 无光源 | 0 | 0 | 0（链不提交 pass） |
| 今天，2 盏受光 | 1 + 4 + 2 = 7 | 0.87 G/s | < 1% |
| S3、K=8、2 盏受光 | 7 + 2×8 = 23 | 2.9 G/s | 约 2.5% |
| S3、K=8、16 盏全部受光（极端） | 7 + 16 + 16×8 = 151 | 18.8 G/s | 约 16% |

口径：中端独立显示核心按 64 个纹理单元、1.8 GHz 计，约 115 G 次点采样/秒。每步的 ALU 是 2 次乘加（uv）+ 2 次乘加（`raw`）+ 1 次比较 + 1 次钳制，约 8 条指令；`STEPS = 8` 实际走 7 步，每盏每像素约 56 条。

三点判断：

1. **平均开销远低于峰值**。光源数是实战里的主要变量；同时照到同一像素的受光光源通常是 1–3 盏，16 盏是刻意构造的场景。
2. **采样是规则的**。屏幕空间等步长的 UV 在相邻像素间连续，深度纹理的缓存命中率高；这条比绝对次数更重要。
3. **循环不早退**，同 warp 的迭代次数一致；只有出屏的步用 `continue` 跳过，会在光源接近视口边缘时引入轻微分歧。

**测量方法**：`S3_STEPS = 0` 与 `S3_STEPS = 8` 在同一场景、同一视角下各记 60 秒的帧时间，差值即净开销。这个 A/B 不关总开关，因此不会把"灯本身也一起关掉"的收益算进来。

## 9. 验收

沿用本项目惯例：主视图实机目视，不建立像素级自动断言。

| 场景 | 判据 |
| --- | --- |
| 车体后方的枪口 | 车体朝向相机的一侧不被照亮；前方可见地面仍被照亮，亮区边界与车体轮廓一致 |
| 门缝 / 墙角 | 光源自身被挡住、它的光池落在可见地面上：地面亮起，而不是整片缺失（§1 的第一种误判） |
| 墙面内侧 | 光源挂在墙外、可见的是墙的内侧：墙面不被照亮（S2 的漏光方向） |
| 接触阴影 | 光源贴地时车底、墙根出现暗区；暗区随光源移动 |
| 自遮挡 | 视线接近平行地面时，地面不出现条纹或摩尔纹 |
| 薄遮挡物 | 栏杆、栅栏处允许漏光（§5 的已知限制），不出现整块异常 |
| 熄灭 | 光源熄灭时暗区随之消失，不残留 |
| 性能 | `S3_STEPS = 8` 相对 `0` 的帧时间差在 1080p 下不超过 1.5 ms |

数值参考（非硬门槛）：同一场景下被照亮区域的白像素占比与亮度标准差与 `S3_STEPS = 0` 时同量级；暗区边界不出现宽于 2 像素的锯齿带。

## 10. 风险

| 类别 | 内容 | 处理 |
| --- | --- | --- |
| 屏幕空间固有限制 | 画面外与被前景完全盖住的遮挡物没有信息 | 不声称物理正确；与 S2 相比是"少漏光、不失光"的方向 |
| 薄遮挡物漏光 | 采样间距大于物件屏幕宽度时漏 | 提高 `STEPS` 或接受；不引入屏幕外几何 |
| 自遮挡条纹 | 掠射地面上射线与自身相交 | `START` 与 `BIAS_REL`；实机优先调 `START` |
| 量化台阶 | 8 步给出 8 级软边 | `SOFT_REL` 降低硬边；需要更细腻的暗区边界时提高 `STEPS` |
| 性能 | 极端多光源场景每像素上百次采样 | 实测 A/B；必要时按光源屏幕长度自适应 `STEPS`，但那会引入分支发散 |
| 与 S2 语义重叠 | 两种"可见性"很容易被混用 | `LightOcclusion` 的注释与文档都写明它只服务星芒 |

## 附录 B · 为什么 `raw` 而不是 `z`

把每步的 `z` 从 `raw` 解出来要一次除法（`z = DepthB/(raw + DepthA)`），8 步就是 8 次除法；而 `raw` 本身已经是 `1/z` 的仿射函数，沿线段的仿射插值在 `raw` 上**精确**成立。唯一的代价是偏置与比较要按 `raw` 的相对尺度给（§4 已说明它与距离的相对变化同阶）。

原始深度在两种约定下的符号差异由 `depthSign` 吸收，因此这套判据对标准深度与反向深度都成立，不需要在着色器里写死方向。
