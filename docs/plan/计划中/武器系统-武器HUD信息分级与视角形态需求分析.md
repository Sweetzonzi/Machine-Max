# 武器 HUD 信息分级与视角形态需求分析

> 版本 2.0 · 2026-10-18
> **状态**：需求分析（计划中，未实现）。本文回答“武器 HUD 该向玩家显示什么、按什么信息量分级、第三人称与炮镜如何分工”，不定义具体 AUI 页面结构，也不替代数据层设计。
>
> 相关文档：数据快照与 `weapon.*` 查询见《[武器系统-武器控制器HUD样式与布局设计](武器系统-武器控制器HUD样式与布局设计.md)》；样式、布局、元素与视角字段见《[界面-HUD样式挂载与布局设计](../进行中/界面-HUD样式挂载与布局设计.md)》；炮镜分划的投影与行为见《[观瞄系统-炮镜HUD自定义分划设计](../已实现/观瞄系统-炮镜HUD自定义分划设计.md)》。

## 一、结论摘要

1. **四款 HUD 共用一份数据，只改变呈现**：`minimal`（紧凑条）、`standard`（标准卡）、`scope`（炮镜环）、`full`（技术面板）。它们是由布局选择的样式档位；框架不提供自动映射。
2. **三条设计轴**：信息量（持久 / 情境 / 按需）、武器类型（机枪 / 主炮 / 机关炮 / 多管导弹 / 再生武器 / 曲射武器）、视角（第三人称 / 第一人称 / 炮镜）。先由武器类型决定“哪些字段有意义”，再由视角决定“放在哪、占多大”，最后才由信息量档位决定“显示几项”。
3. **核心信息只有五类**：能不能打、打的是什么、还剩多少、什么时候能再打、为什么不能打。其余都是这五类的展开或诊断。
4. **计数口径必须先定死**：膛内、库存、容量是三个不同的量。容量为 1 的多管武器（如 K-17 的四根 ATGM 发射管）全部上膛后，装弹机余量为 0，若 HUD 只汇总装弹机余量，会出现“四管全就绪却显示 0/4”。HUD 的主数字应当是**可用总数**，并把膛内那一发单独表达。
5. **第三人称是“余光可读”**：少字、固定槽位，不遮挡车身与准星；**炮镜是“中心不遮挡”**：分划 + 装填环 + 边缘文字，不重复绘制准星。座椅当前控制组选中的 WC 全部显示，多台同时显示时的重叠由内容包布局处理。
6. **装填环只对存在装填/再生节奏的武器有意义**：单管主炮是一整圈装填进度；多管武器按管分段；批量再生是整圈冷却；弹链机枪没有环，显示余量即可。

## 二、问题与边界

### 2.1 现状

- 一个座位（`SeatSubsystem`）在一个时刻可激活多台武器控制器：基础组始终参与，另加当前选中的子控制组。这些 WC 就是该座椅的“选中集合”，其 HUD 全部显示。选中集合由 `getActiveWeaponControllers()` 给出，来源是控制组频道经 connector 转发或 `global` 广播的发现回调。本设计不使用主/副角色分类。
- 一台武器控制器（下称“武器组”）可以下挂多根发射管（`LauncherSubsystem`）和多台装弹机（`AmmoLoaderSubsystem` / `RegenLoaderSubsystem`），并拥有多条可选弹链。弹链是**有序弹种序列**，不是单一弹种。
- 现有 `WeaponHudOverlay` 用一块 AUI 面板显示所有激活武器组，按主/副分组，含弹种、计数、装填段、弹链选项卡；这是当前实现。目标形态是每台选中的 WC 各自显示布局；炮镜模式同样显示选中 WC 的 `scope` 元素。`AmmoHud` 是未注册图层的回退实现。`SightHud` 只在炮镜中心画一个参考圆环，十字线绘制代码当前注释停用。
- 每台控制器的按视角 `*_hud_layout` 字段已加入动态属性，默认省略即无 HUD；`HudStyle` / `HudElement` / `HudLayout` 与 `HudView` / `IHudHost` 已存在，`CustomHud` 按宿主集合渲染。武器控制器尚无使用这些字段的内容包示例；武器专用元素、快照与 `weapon.*` 仍未实现。

### 2.2 本文回答的问题

- 哪些信息必须常驻，哪些只在装填、切弹、异常时出现，哪些折叠到技术面板。
- 不同武器类型（高射速机枪、低速主炮、机关炮、多管导弹、再生武器、曲射武器）各自应该突出什么。
- 第三人称、第一人称、炮镜三种视角的信息量与空间分工。
- 炮镜下准星与武器 HUD 的归属关系，装填环的语义、分段方式与边界情况。
- 可验收的需求条目与需要产品决策的开放问题。

### 2.3 非目标

- 不规定 AUI 页面的 DOM 结构、CSS 类名与动画参数；这些属于样式实现。
- 不设计弹道解算、命中判定、伤害模型或服务器同步协议。
- 不规定内容包如何编写弹种与弹链；只提出 HUD 需要内容包提供的字段。

## 三、信息模型

### 3.1 五层对象

```text
武器组（WeaponControllerSubsystem）
├─ 发射管 1..N        每根管有：膛内弹种、逐管状态、当前供给者
├─ 装弹机 1..M        每台有：余量、容量、装填/再生进度、被哪根管占用
└─ 弹链 1..K          每条是有序弹种序列；武器组同一时刻选中一条
      └─ 弹种          展示名、口径、初速、穿深、制导、战斗部等
```

三者是多对多关系，HUD 不能假设“一管一机”或“一链一弹”：

- 一台装弹机可以依次服务多根管；独占式装弹机同一时刻只推进一根管的输送计时器，其余管在等待。
- 一根管同一时刻只有一个供给者；供给者可以随路由变化。
- 弹链属于武器组，不属于单根管；不同管可以装着不同弹种的膛内弹，尤其在新旧弹链切换的窗口里。

### 3.2 三个计数口径

| 口径 | 定义 | 是否含膛内 | 典型用途 | 风险 |
| --- | --- | --- | --- | --- |
| 膛内数 | 已压入发射管、尚未打出的弹 | 是 | 逐管状态、齐射可用数 | 多管时逐管不同 |
| 库存 | 装弹机内剩余弹量之和 | 否 | 补给深度、弹链余量 | 上膛后库存下降，看起来像“打掉了” |
| 容量 | 装弹机容量之和；`-1` 表示无限 | 否 | 显示上限 | 与库存混用会出现 `/∞` 错误 |
| **可用总数** | 库存 + 膛内数 | 是 | HUD 主数字 | 需要按实例去重，避免共享装弹机重复计数 |

**建议**：HUD 的大号数字显示“可用总数”，小号显示“库存/容量”或“膛内 N 发”。三者关系必须在同一条 HUD 上可解释，不能让玩家自己猜。

以 K-17 炮塔的四根 ATGM 发射管为例：每根管配一台容量 1 的再生装弹机，装填完成后装弹机余量为 0、发射管膛内为 1。若主数字只汇总装弹机余量，四管全就绪时显示 `0/4`；正确口径应显示 `4/4`，或显示 `0/4` 的同时明确标注“膛内 4”。这是 HUD 需求里优先级最高的口径问题。

另一个边界：同一武器组下的发射管可以有不同炮闩兼容标签。按弹链汇总的余量不等于每根管都能用；某条弹链没有任何管能接受时，HUD 必须把它标为不可用，`full` 中按管列出兼容性。

### 3.3 单管状态机

| 状态 | 判据 | 建议文案 | 颜色语义 |
| --- | --- | --- | --- |
| 就绪 | 膛内有弹，或供给者已备好待取 | 就绪 | 正常/绿 |
| 装填中 | 该管已被供给者排上，计时器在走 | 装填 2.1s / 62% | 黄 |
| 等待供弹 | 该管未被排上，装弹机正在服务别的管 | 等待供弹 | 灰/暗黄 |
| 空弹 | 无膛内弹、无库存、也不在再生 | 空弹 | 红 |
| 再生中 | 再生装弹机正在按速率回弹 | 再生 43% | 青/黄 |
| 失效 | 发射管或武器组被摧毁/未激活 | 失效 | 灰/红 |
| 弹种不符 | 膛内弹种不在当前选中的弹链上 | 警示标记，不作为独立状态 | 黄 |

当前 `SupplierStatus` 只有 `READY` / `EMPTY` / `RELOADING` 三档；“等待供弹”可以由 `isRoundScheduled` 与装弹机是否已被占用推导，HUD 需要把它与“真的在装填”分开，否则多管共享装弹机时每根管都会显示一个进度为 0 的装填条。

### 3.4 信息项清单

优先级定义：

- **P0**：交火中随时要读，缺失会导致误判（能不能打、打什么、还剩多少、何时能再打、为什么不能打）。
- **P1**：装填、切弹、异常时需要读，允许出现在情境区。
- **P2**：技术信息或低频信息，默认折叠或只在 `full` 出现。
- **P3**：内容包作者/调试信息，不面向普通玩家。

| 类别 | 信息项 | 回答的问题 | 优先级 | 变化频率 | 建议形态 |
| --- | --- | --- | --- | --- | --- |
| 身份 | 武器组名称/型号 | 这是哪门武器 | P1 | 静态 | 文本，可截断 |
| 身份 | 当前控制组/武器模式 | 我现在在操作哪组武器 | P1 | 切换时 | 小字或图标 |
| 身份 | 失效/摧毁 | 它还能不能用 | P0 | 事件 | 灰化 + 文案 |
| 弹药 | 膛内弹种 | 扣扳机会打出什么 | P0 | 每发 | 弹种短名 |
| 弹药 | 下一发/弹链指针 | 接下来会装什么 | P2 | 每发 | 小字或箭头 |
| 弹药 | 当前选中弹链 | 现在用哪条供弹链 | P0 | 切弹时 | 标签/高亮 |
| 弹药 | 弹链组成（有序） | 这条链里依次是什么弹 | P2 | 静态 | 弹种色块/短名序列 |
| 弹药 | 各弹链余量 | 还有哪些弹、各多少 | P1 | 缓慢 | 选项卡 + 数字 |
| 弹药 | 可用总数/容量 | 还能打多少发 | P0 | 每发 | 大号 `cur/cap` |
| 弹药 | 弹种不符 | 膛内这发是不是当前链上的 | P1 | 切弹/上膛 | 黄色警示 |
| 弹药 | 弹种属性（口径/初速/穿深/制导/战斗部） | 这发弹能干什么 | P3 | 静态 | `full` 表格 |
| 装填 | 装填剩余时间 | 什么时候能再打 | P0（主炮） | 每 tick | 秒数 |
| 装填 | 装填进度 | 装到哪了 | P1 | 每 tick | 条/环 |
| 装填 | 逐管状态 | 哪根管现在能打 | P0（多管） | 每 tick | 分段条/弧段 |
| 装填 | 等待供弹 | 为什么这根管还没动静 | P1 | 每 tick | 独立文案 |
| 装填 | 装弹机余量/容量 | 补给还深不深 | P2 | 缓慢 | `full` 行 |
| 装填 | 批量再生/冷却 | 打空后还要等多久 | P1 | 每 tick | 环/倒计时 |
| 装填 | 再生速率/能量成本 | 持续火力受什么限制 | P3 | 静态 | `full` |
| 装填 | 装填完成 | 现在可以打了 | P0 | 事件 | 一次性闪亮，不常驻 |
| 火控 | 能否开火/是否已瞄准 | 为什么扣扳机没反应 | P1 | 每 tick | 状态词/图标 |
| 火控 | 射击模式（齐射/轮射） | 多管会怎么打 | P2 | 静态 | `full` 或小字 |
| 火控 | 目标距离/弹道修正 | 该抬多少 | P2（炮镜） | 每帧/每 tick | 分划标尺或数字 |
| 火控 | 稳定器/炮塔回旋 | 现在稳不稳 | P3 | 每 tick | 图标，默认省略 |
| 火控 | 炮管磨损/模块耐久 | 精度为什么下降 | P3 | 缓慢 | `full` |
| 告警 | 空弹/无弹 | 打不了了 | P0 | 事件 | 红色 + 文案 |
| 告警 | 无供给者/供弹中断 | 有弹却装不上 | P0 | 事件 | 红色 + 原因 |
| 告警 | 低弹药 | 快打完了 | P2 | 阈值 | 变黄，不闪烁 |
| 反馈 | 切弹确认 | 切成功了吗 | P1 | 事件 | 高亮迁移，不弹窗 |

## 四、武器类型画像

武器类型决定“哪些字段有意义”，而不是只决定排版。以下按现有内容包中的真实配置归纳。

| 类型 | 典型配置 | 玩家核心问题 | 必显 | 可省 | 特殊 |
| --- | --- | --- | --- | --- | --- |
| 高射速机枪 | PKTM：容量 2000，再生 700/min，无装填计时；MG34：容量 150，再生 800/min | 还有多少弹、能不能连续压制 | 余量、弹种、状态 | 装填环、逐管细节、弹链选项卡 | 再生速度接近射速时，不显示再生条 |
| 主炮 | KwK39 50mm：容量 40，装填 2s；单管、少弹 | 什么时候能再打、下一发是什么弹 | 装填倒计时、膛内弹种、余量 | 装弹机细节 | 炮镜里以装填环为主 |
| 机关炮 | 2A42：容量 300，射速 550/min，再生 100/min，无装填计时 | 还能扫多久、火力是否衰减 | 余量、弹种、再生状态 | 单发装填时间 | 余量下降和再生要同时可见 |
| 多管导弹 | K-17 ATGM：4 根管，每管容量 1，轮射间隔 1s | 哪几根管有弹、下一发从哪根出 | 逐管就绪、可用总数、下一根 | 聚合装填时间 | 分段弧/分段条是主要形态 |
| 再生/能量武器 | 逐发再生或整仓批量再生，可能消耗能量 | 下一发何时充好、还能连打几发 | 充能/再生进度、可用数、能量 | 实体弹链 | 批量再生显示整圈冷却 |
| 曲射/榴弹 | 低初速、弹道弯曲、多弹种 | 用哪种弹、打多远、抬多少 | 弹种、余量、距离/标尺 | 逐管细节 | 炮镜标尺与弹种绑定 |

### 4.1 类型 × 信息矩阵

`●` 必显；`◐` 按需/折叠；`○` 不显示。

| 信息 | 机枪 | 主炮 | 机关炮 | 多管导弹 | 再生武器 | 曲射 |
| --- | --- | --- | --- | --- | --- | --- |
| 膛内弹种 | ● | ● | ● | ● | ● | ● |
| 可用总数 | ● | ● | ● | ● | ● | ● |
| 装填剩余时间 | ○ | ● | ○ | ◐ | ● | ● |
| 装填/再生进度条 | ○ | ● | ◐ | ● | ● | ● |
| 逐管状态 | ○ | ○ | ○ | ● | ○ | ○ |
| 弹链选项卡 | ◐ | ● | ◐ | ◐ | ◐ | ● |
| 再生/充能 | ◐ | ○ | ● | ◐ | ● | ○ |
| 弹道/距离 | ○ | ◐ | ○ | ◐ | ○ | ● |
| 射击模式 | ○ | ○ | ○ | ● | ○ | ○ |

矩阵的用法：内容包为某台控制器选样式时，先按这张表决定字段，再按视角决定布局。一个字段在某个类型里是 `○`，不是“样式没写好”，而是该类型下它不构成有效信息。

## 五、视角形态

### 5.1 第三人称

玩家在第三人称下同时承担驾驶、观察和射击，视线主要落在世界与车体上，HUD 只能占用余光。

- **任务**：回答“现在能不能打、打的是什么、还剩多少”，不要求读出每一根管。
- **信息量**：每台选中的 WC 由自己的布局选择 `minimal` 或 `standard`；多管武器最多显示分段条，不展开装弹机明细。
- **位置**：屏幕右下或左下，锚定在快捷栏上方；与座椅仪表、PDA、原版状态条共享安全区，避免互相遮挡。
- **文字**：允许较短的名称与弹种短名；数字要大，计时要有固定宽度。
- **准星**：沿用原版准星或当前座椅 HUD，不由武器 HUD 另画。
- **切换**：控制组切换时选中集合整体替换，旧组数据不得残留；不显示角色标签。

### 5.2 第一人称（非炮镜）

视野更近、屏幕中心更敏感，但可用屏幕空间比第三人称多。

- **信息量**：`standard` 为主；可以显示弹链选项卡和逐管分段。
- **位置**：屏幕下方或右下，仍需避开中心准星。
- **与第三人称的差异**：可以多一行“下一发/弹链组成”，但不因此把面板做成全量表格。

### 5.3 炮镜

炮镜的视线被分划钉在中心，玩家处于“瞄准—射击—等装填”的循环，HUD 的目标是**不遮挡目标、不要求视线离开分划**。

- **信息量**：`scope`；只保留 P0 与少量 P1。
- **位置**：分划外围、屏幕下缘和上缘；中央安全区留给分划与目标。
- **准星**：炮镜分划是唯一的瞄准参考；武器 HUD 只显示状态，不绘制十字线或中心点。
- **弹链**：不展开选项卡；显示当前弹种短名与余量，切弹时用短暂高亮或浮层确认。
- **逐管**：多管武器用环上的分段弧表达，不另开面板。
- **告警**：空弹、无供给、弹种不符放在分划上方或环外侧，用短词，不写长句。
- **进入/退出**：切到炮镜时第三人称面板隐藏，`scope` 元素出现；两者不得同时绘制。

### 5.4 视角矩阵

| 信息 | 第三人称 | 第一人称 | 炮镜 |
| --- | --- | --- | --- |
| 武器组名称 | 短名 | 短名 | 可省略或极小 |
| 膛内弹种 | 显示 | 显示 | 显示（分划旁） |
| 可用总数/容量 | 显示 | 显示 | 显示（下缘） |
| 装填剩余时间 | 数字/条 | 数字/条 | 环内或环下数字 |
| 装填环 | 不显示 | 可选 | 主形态 |
| 逐管分段 | 多管时显示 | 显示 | 环上分段弧 |
| 弹链选项卡 | 折叠为当前链 | 可显示 | 只显示当前链 |
| 弹种不符 | 黄色标记 | 黄色标记 | 环外短警示 |
| 阻断原因 | 一行短词 | 一行短词 | 分划上方短词 |
| 目标距离/弹道 | 不显示 | 可选 | 分划标尺/数字 |
| 全量技术信息 | 不显示 | 可展开 | 不显示 |

### 5.5 多控制器

一个座位在某一时刻选中基础组与当前子组的多台控制器。第三人称、第一人称与炮镜都把选中的 WC 全部显示；不设焦点组，不按主/副分组。

建议规则：

1. **全部显示**：选中集合内、当前视角有布局的 WC 各画自己的元素；框架不按激活/摧毁状态过滤宿主，也不做自动堆叠、折叠或“+N”。是否因失效灰化或隐藏由内容包样式按 `weapon.state` 决定。
2. **布局自负**：多台 WC 同时显示时可能重叠；内容包通过不同 `offset`/布局避免，或明确接受叠放。框架不按角色或顺序重新定位。
3. **炮镜**：所有选中且配置了 `scope_hud_layout` 的 WC 都绘制自己的环/文字元素；内容包应只给需要同时出现的控制器配置 `scope` 布局。多台 WC 可以各自画环/文字，但中心准星仍只由相机/分划样式提供，内容包不得让多台 WC 各画一个准星。多环重叠由内容包负责。
4. **切换**：控制组切换后旧组的元素在 1 tick 内消失；新组各 WC 按自己的当前进度出现，不继承上一组状态。

焦点组与主武器优先级不属于本设计；所有选中的 WC 同等显示。

## 六、四款 HUD

### 6.1 分级原则

信息量不是“把所有字段塞进一块面板”，而是分三层：

- **持久层**：交火中一直可见，只放五类核心信息。
- **情境层**：装填、切弹、空弹、等待供弹时出现；出现时**在原槽位内展开**，不改变面板高度。
- **按需层**：`full` 面板、弹链组成、弹种属性、装弹机明细；默认折叠，由按键或席位打开。

这样可以在“装填中的空档”给玩家更多信息，而不在交火最紧张时增加阅读负担。

### 6.2 `minimal`：紧凑条

**适用**：紧凑显示、第三人称、机枪、屏幕空间紧张时；由布局选择，不绑定角色。

**内容**：一行一个武器组。

```text
[PKTM] 7.62 AP   1480/2000   ●
[MG34] 7.92 AP    120/150    ●
```

- 短名、弹种短名、可用总数/容量、状态点。
- 装填中：在行尾放一个很短的条或秒数（如 `▮▮▮▯ 0.8s`）；没有装填机制时不放。
- 空弹：整行转红并写“空弹”，不删除行。
- 多弹链：只显示当前链；切换时高亮闪一下，不展开列表。
- 不显示：逐管分段、装弹机、弹种属性、弹链组成。

**约束**：行高固定，数字列预留宽度；同一武器组在装填前后不得改变行高。

### 6.3 `standard`：标准卡

**适用**：标准显示、第三人称/第一人称、机关炮与主炮；由布局选择，不绑定角色。

**内容**：一个武器组一块，固定槽位。

```text
┌ 120mm 主炮 ─────────────────── 2.1s ┐
│ APFSDS                    24/30      │
│ ▮▮▮▮▮▮▮▮▮▯  逐管装填段             │
│ [APFSDS 24] [HEAT 12] [HE 18]        │
└──────────────────────────────────────┘
```

- 标题行：名称、状态尾标（就绪/秒数/空弹）。
- 主行：膛内弹种、可用总数/容量。
- 装填行：单管为条，多管为分段条；一段对应一根管。
- 弹链行：仅当可选弹链多于一条时出现；每条显示名称与余量，当前链高亮。
- 警示：弹种不符时弹种文字转黄；无供给者时状态尾标写“无供弹”。
- 不显示：装弹机明细、弹种属性、能量成本。

**约束**：槽位的有无由结构决定（管数、弹链数、是否有装填机制），运行态只改内容；面板高度在载具结构不变时恒定。

### 6.4 `scope`：炮镜环

**适用**：炮镜模式、炮手席、狙击/反坦克导弹。

**内容**：分划 + 环 + 边缘文字，不显示大面板。

```text
              ╭───────────╮
              │     ◎     │   ← 分划（由相机/分划样式提供）
              │   2.1s    │   ← 装填环与剩余时间
              ╰───────────╯
        APFSDS  24/30      [AP]
        空弹 / 无供弹（仅异常时出现在上方）
```

- 环：单管为整圈装填进度；多管为 N 段弧，每段一根管。
- 文字：弹种短名与可用总数放在下缘；剩余秒数放在环内下方或 4 点钟方向。
- 弹链：只显示当前链；切弹时短暂显示新链名。
- 告警：分划上方一行短词；不遮挡中心。
- 不显示：武器组全名、弹链选项卡、装弹机明细。

**约束**：环与文字必须落在分划安全区之外；不得绘制第二个准星；多台控制器各自绘制，重叠由内容包布局负责，框架不设焦点组。

### 6.5 `full`：技术面板

**适用**：车长席、武器站、内容包调试、玩家主动展开。

**内容**：按武器组展开的表格。

- 每根管：名称、状态、膛内弹种、装填进度、供给者。
- 每台装弹机：余量/容量、装填/再生模式、进度、被哪根管占用。
- 每条弹链：名称、组成、余量、是否选中。
- 武器组：射击模式、轮射间隔、瞄准容差、能否开火。
- 当前弹种：口径、初速、基础穿深、制导、战斗部。
- 平台：炮管磨损、能量成本、模块耐久。

**约束**：默认不显示；打开时不拦截游戏输入（AUI Overlay 不参与鼠标）；行数超过一屏时折叠或分页，不做滚动条式交互。

### 6.6 四款对比

| 信息 | `minimal` | `standard` | `scope` | `full` |
| --- | --- | --- | --- | --- |
| 武器组名称 | 短名 | 全名 | 省略/极小 | 全名 |
| 膛内弹种 | 短名 | 短名 | 短名 | 全名 |
| 可用总数/容量 | 数字 | 大号数字 | 下缘数字 | 表格 |
| 装填剩余时间 | 可选短秒数 | 尾标 | 环内/环下 | 每管 |
| 装填条/环 | 短条 | 分段条 | 整圈/分段弧 | 每管进度 |
| 逐管状态 | 不显示 | 分段条 | 分段弧 | 每管一行 |
| 弹链选项卡 | 当前链 | 有 | 当前链 | 全部 |
| 弹种不符 | 颜色 | 颜色+文案 | 环外警示 | 标记 |
| 阻断原因 | 短词 | 短词 | 短词 | 详细原因 |
| 弹种属性 | 不显示 | 不显示 | 不显示 | 显示 |
| 装弹机明细 | 不显示 | 不显示 | 不显示 | 显示 |
| 默认场景 | 紧凑/第三人称 | 标准/第三人称 | 炮镜 | 车长/调试 |

### 6.7 默认映射建议

| 武器类型 / 席位 | 第三人称 | 第一人称 | 炮镜 |
| --- | --- | --- | --- |
| 高射速机枪 | `minimal` | `minimal` | 不显示或短暂 `minimal` |
| 主炮 | `standard` | `standard` | `scope` |
| 机关炮 | `standard`（紧凑） | `standard` | `scope` |
| 多管导弹/火箭 | `standard`（分段条） | `standard` | `scope`（分段弧） |
| 再生/能量武器 | `standard` | `standard` | `scope` |
| 车长/武器站 | `full`（按需） | `full`（按需） | `scope` + 可选 `full` |

这张表是内容包按武器类型选择样式的建议，不是框架的角色映射；玩家与内容包都可以覆盖。

## 七、炮镜专项：准星与装填环

### 7.1 准星归属

炮镜里只能有一个瞄准参考。现有分工是：

- 相机/分划样式负责分划板、边框、遮罩与中心参考；
- 武器 HUD 负责弹药、装填与状态，**不画十字线、不画中心点**；
- 如果内容包提供了自定义分划模型，武器 HUD 的环必须能配置“安全半径”，避让分划的刻度与中心标记。

多台选中 WC 的 `scope` 布局可以同时存在，但它们只画环/文字；中心准星仍由相机或分划样式提供，不得每台 WC 各画一个准星。

这样做的理由：不同载具的分划大小、刻度、中心样式不同，武器 HUD 若硬编码一个准星，会与分划重叠或指向不一致。

### 7.2 环的语义

| 武器形态 | 环的含义 | 分段 | 中心/环内文字 | 完成时 |
| --- | --- | --- | --- | --- |
| 单管主炮 | 当前这一发的装填进度 | 整圈 | 剩余秒数 | 闪一下，转为就绪 |
| 多管导弹/火箭 | 每根管的再装填/再生进度 | N 段弧，一段一管 | 就绪管数/总管数 | 对应弧段常亮 |
| 多管共享装弹机 | 每根管的状态 | N 段弧；“等待供弹”的弧段暗显 | 就绪/等待/空 | 只点亮真正就绪的段 |
| 批量再生 | 整仓冷却进度 | 整圈 | “再生” + 剩余秒数 | 整圈回满 |
| 弹链机枪 | 无装填环 | 无 | 余量即可 | 无 |
| 逐发再生 | 下一发的再生进度 | 整圈或一个小充能点 | 百分比/秒数 | 闪一下 |

**环的方向与颜色**：从 12 点钟方向顺时针填充；装填用黄/白，完成为绿；空弹与阻断用红，但红色不用于“正在装填”。环不使用实心圆盘，避免遮挡目标。

### 7.3 多管与多控制器

- 多管武器的环按“显示顺序”分段，段与发射管的对应关系必须稳定；段序应与 `standard` 的分段条一致，不能一个按名字、一个按索引。
- 每台选中的 WC 各自画自己的环；哪些控制器配置 `scope` 环由内容包决定。框架不设焦点组，也不因角色隐藏环。
- 如果某台 WC 只有一根管有弹、其余在等待，环上应能看出“1 段亮、N 段暗”，而不是整圈按最慢进度走。
- 轮射模式下，可以额外用一个小三角或高亮标出“下一根要打的管”，但不另画一套进度。

### 7.4 视觉与边界

- **半径**：由分划安全半径决定，建议为分划外缘的 1.2～1.6 倍；粗细 2～3 逻辑像素；透明度 0.6～0.8。
- **文字**：剩余秒数放在环内下方或 4 点钟方向；弹种与总数放在屏幕下缘，避免与环挤在一起。
- **刷新**：数据按 tick 更新，环按渲染帧插值；至少不能出现“走一格停一下”的机械跳动。
- **0%**：环不消失，显示为暗色空环，表示“在装填但还没开始/刚被打断”。
- **100%**：先闪一下再转为常亮，不能长期停在“99%”。
- **空弹**：环可以保留为暗环，但文字必须是“空弹”，不能用“100%”误导。
- **屏幕比例**：超宽屏与窄窗口都把环钉在中心，文字留安全边距；不随 FOV 缩放。
- **多台控制器**：各自按自己的进度画环；内容包负责布局避免重叠；切换控制组时从新组各 WC 的当前进度画起，不播放上一组的完成动画。

## 八、布局、视觉与交互规则

### 8.1 信息层级

同一块 HUD 内按以下顺序分配视觉权重：

1. 状态（能否开火/空弹/失效）；
2. 膛内弹种（打出去是什么）；
3. 可用总数/容量（还能打多少）；
4. 装填时间/进度（何时能再打）；
5. 弹链选择与余量（换什么打）；
6. 诊断与技术信息。

字号、颜色、位置都服从这个顺序；不要给弹链选项卡比“空弹”更高的对比度。

### 8.2 稳定槽位

- 槽位的有无由静态结构决定：管数、弹链数、是否存在装填机制。
- 运行态只改文字、填充比例、颜色，不增删行。
- 数字与计时器预留固定宽度，避免 `2.1s` 与 `12.4s` 之间横向抖动。
- 多管数量超过 8 根时折叠为“前 6 段 + `+N`”，不无限拉长；弹链超过 6 条时同理。

### 8.3 颜色与可读性

- 正常：白/浅灰；就绪：绿；装填/警告：黄；空弹/阻断：红；失效：灰。
- 颜色不是唯一载体：空弹必须同时有“空弹”文字，弹种不符必须有标记或文案，不能只靠变色。
- 半透明底板只在第三人称面板使用；炮镜环与文字用描边/阴影，不用大块底板。
- 字体沿用项目窄体工业字体，中文回退；数字尽量等宽或预留宽度。

### 8.4 告警优先级

同时出现多个问题时，按以下顺序只显示最高级的一条短文案，其余用图标/颜色表达：

1. 武器失效/被摧毁；
2. 无弹可用（空弹/无供给者）；
3. 膛内弹种不符；
4. 装填中/等待供弹；
5. 低弹药。

告警不使用持续闪烁；一次性脉冲或颜色变化即可。装填音效由装弹机按自身配置播放，HUD 只做视觉提示，不叠加新音效。

### 8.5 切弹与切组

- 切弹链：当前链高亮立即迁移；弹种槽显示膛内旧弹种并标“不符”，直到旧弹打出或退膛；数字不跳变。
- 切控制组：旧组 HUD 在 1 tick 内消失，新组出现；新组各 WC 的环从各自当前进度开始，不继承旧组。
- 切换过程中不得出现“两组数字拼在一起”的中间帧。

### 8.6 隐藏规则

- 未乘坐激活座椅：全部隐藏。
- 座椅无激活武器组：隐藏武器 HUD。
- `F1` 隐藏 GUI：跟随原版。
- 炮镜：第三人称面板隐藏，选中 WC 的 `scope` 元素显示；若选中的 WC 都没有 `scope` 布局，则只显示分划。
- 武器组失效：`minimal`/`standard` 隐藏或灰化；`scope` 只保留分划与“失效”短词，不画空环。

### 8.7 无障碍与适配

- 最小字号不低于 9 逻辑像素；关键数字不低于 12。
- 对比度满足半透明背景上的可读性；炮镜内文字加阴影。
- GUI 缩放、窗口尺寸变化时按视口缩放，不裁切；缩放下限与现有面板一致。
- 色盲模式下，状态必须可由文字/形状区分。

## 九、数据与实现约束

### 9.1 单一快照

所有款式必须从同一份每 tick 快照取数，避免 `minimal` 与 `standard` 对同一武器组显示不同数字。每台 WC 各自发布一份快照；座椅不聚合弹药数据。快照至少包含：

- 武器组：名称、状态、射击模式、能否开火；
- 每根管：膛内弹种、状态（就绪/装填/等待/空/失效）、装填进度、剩余时间、供给者身份；
- 每条弹链：标签、组成、余量、容量、是否选中；
- 汇总：可用总数（含膛内）、库存、容量、是否无限、弹种不符；
- 再生：模式（逐发/批量）、进度、剩余时间、能量成本；
- 弹种：展示名、注册键、口径、初速、穿深、制导等可选属性。

现有 `HudWeaponSnapshot` 草案已经覆盖大部分字段，需要补的是：膛内计数、逐管“等待供弹”状态、再生模式与批量剩余时间。快照按 WC 各自持有，不包含座椅、角色或焦点。

### 9.2 计数与去重

- 汇总必须按装弹机实例去重：同一台装弹机服务多根管时，不能按管累加。
- 可用总数 = 去重后的库存 + 各管膛内数；膛内数按管计，不按装弹机计。
- 容量无限时显示 `∞`，不参与求和；只要有一台无限，整组显示无限。
- 负库存/负进度按 0 处理，不显示负数。
- 同一台装弹机被多个武器组共享时，各组 HUD 会显示同一批弹药；默认口径是“本组可调用量”，`full` 中标出共享供给者，避免玩家误以为存在两份独立库存。

### 9.3 客户端与服务端

- 库存、弹链指针、供给者指认以服务端为准；客户端只读同步值。
- 装填/再生进度可以用客户端本地计时器平滑，但完成时刻要与服务端一致；延迟下允许短暂“客户端已就绪、服务端未确认”，HUD 不因此闪回 0。
- 供给者切换、结构变化时，旧数据最多保留 1 tick，用于防止闪烁；超过 1 tick 必须清空。

### 9.4 AUI 与渲染

- 第三人称面板可继续用 AUI Overlay；每 tick 只改文本与类名，不重建 DOM。
- 炮镜环建议用独立 `LayeredDraw` 图层或 AUI 的固定几何元素绘制；不假设 CSS `conic-gradient` 可用，环的分段数应可配置。
- 环的几何在初始化时生成，运行时只改每段的填充比例/颜色；避免每帧创建顶点缓冲。
- 每帧绘制成本与管数、弹链数线性相关；超过上限时折叠。

### 9.5 内容包与本地化

- 武器组名、弹种名、弹链名来自内容包语言键；HUD 不硬编码。
- 弹链名可能重复（两条链都以同一弹种开头），HUD 需要能显示组成或用内容包提供的 `belt_label` 区分；两者都没有时显示“弹种1/弹种2/…”。
- 未知弹种/缺失翻译显示注册键或路径，保证可诊断，不崩溃。
- 分划安全半径、环的粗细/颜色、是否显示环，应由样式或内容包配置，不由代码硬编码。

## 十二、待决问题

1. **主数字口径**：采用“可用总数（含膛内）”还是“库存（不含膛内）”？本文建议前者，并在小字显示库存/容量；需要确认是否接受“上膛后数字不变”的语义。
2. **控制组切换的过渡**：旧组 HUD 立即消失还是允许 1 tick 淡出？多台 WC 同时切换时是否需要统一过渡？
3. **多管环的形态**：每根管一段弧，还是一圈按“最慢的一根”走？本文建议分段弧，但需要确认段数上限与段序。
4. **弹链组成的表达**：色块序列、短名序列，还是只显示 `belt_label`？混合弹链（AP/HE 交替）如果只显示首弹种，两条链无法区分。
5. **低弹药告警阈值**：按容量百分比、按绝对发数，还是按“还能打几秒”？不同武器类型可能需要不同阈值。
6. **`full` 面板的入口**：车长席专用、按键切换，还是内容包为某台控制器默认打开？
7. **分划安全半径的来源**：内容包字段、样式字段，还是按分划模型包围盒自动推导？自动推导对非对称分划可能不准。
8. **装填完成的判定**：以服务端为准还是客户端本地计时为准？延迟下两者可能差 1～2 tick，HUD 需要决定是否允许“提前显示就绪”。
9. **是否显示“下一发”**：弹链指针的下一发对混合弹链有价值，但会增加一行；哪些类型需要默认显示？
