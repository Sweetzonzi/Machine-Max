# 载具系统：锁扣子系统实施计划

> **状态**：进行中。P1–P3 的代码与内容已落地：`AbstractConnector` 的可观察断开结果、同件动态连接入口、`coupler` 类型登记、候选冻结与物理采样、桑塔纳四扇车门与引擎盖/后备箱盖迁移、双语 schema、内容检查与作者文档。已通过的验收项见 §9 的 T1–T5、T6（同步脏值）、T7、T8（重扣门控与物理施力）、T11（半截引用、缺边补入与陈旧边删除）、T12、T13；尚未完成 T6 的客户端声音基线、T9（铰链叠加探针）与 G1–G5（客户端人工验收）。
> **日期**：2026-11-24
> **范围**：Machine-Max `VehicleCore` 内的运行时连接点对接；桑塔纳四扇车门、引擎盖与后备箱盖、同 `Part` 双 `SubPart` 夹具和可分离配重件验收。
> **依赖**：现有 `Connector`、`VehicleCore`、`InteractBox` 和关节驱动。首版解扣使用 `onInteract(LivingEntity)`；[事件车道](信号系统-事件车道设计.md)不是前置依赖。

## 1. 目标与范围

1. 动画关节驱动以既有力矩开合车门；车门到位后，门边的第二对连接点扣合并承力。撞击不能单靠克服关门伺服把门弹开；解扣不改变铰链的行程、马达或关节身份。
2. `machine_max:coupler` 安装在主动高级连接点上。运行时只在同一 `VehicleCore` 内按几何发现最近的简单连接点，并以现有双向 Connector 条件检查作为兼容判据；内容不指定被动点。扣合生成**真实的 Connector 连接**，不建立第二套临时关节表或装配图。操作涉及跨 `Part` 边时，载具照常维护拓扑和同步；同 `Part` 的两个 `SubPart` 只改变内部连接。
3. 首版唯一的**主动解扣输入**是玩家点击交互区；交互区始终可用，开、关共用同一个交互区，每次点击都请求解扣。扣合依靠几何判据和重扣门控。允许同车配重件在最后一条边断开后变成独立载具，但不做跨装配体捕获、合并或回收。

**非目标**：不增加信号频道、脉冲投递、专用按键或脚本入口；不修改碰撞过滤、全局铰链求解或 `JointDriverSubsystem` 的力矩公式；不新增求解器过载脱扣模型，不实现多扣互锁、ARMS 动态装备或设备专用投放逻辑。连接点已有的结构损伤与拆件流程照常工作。

## 3. 内容与寻址契约

沿用 `JointDriverSubsystemAttr` 的型号／安装分层；由 `SubsystemKinds` 注册 `coupler`。运行类继承 `BasicSubsystem`，服从通用启用、损坏、卸载生命周期。Connector 配对和物理关节是连接事实的权威；`connected` 仅持久化并同步该事实，不保存对侧身份或建立第二份连接关系。

| 位置 | 字段 | 语义与校验 |
| --- | --- | --- |
| 型号 | `capture_distance`、`lock_distance` | 米，有限且 `0 < lock_distance <= capture_distance`；边界值包含在范围内。 |
| 型号 | `max_capture_force` | N，有限且 `>= 0`。只在扣合前施力；`0` 合法，表示由已有作动器或外力合拢。不是接合后承载强度。 |
| 型号 | `lock_angle_tolerance`、`max_lock_speed` | 分别用度和 m/s；前者有限且 `(0, 90]`，后者有限且 `>= 0`。分别限制两端目标朝向的误差和两端点的相对速率。 |
| 型号 | `rearm_distance_multiplier` | 默认 `2`，有限且 `> 1`。重武装距离 `max(capture_distance, n * lock_distance)`；乘积也必须有限。 |
| 型号静态属性 | `sounds` | 沿用基础子系统的 `sounds` 对象及基础生命周期音效；锁扣专属 `on_attach`、`on_detach` 都默认 `minecraft:block.tripwire.attach`，定义可覆写。 |
| 安装 | `definition`、`connector` | 必填；`connector` 是子系统所在 `SubPart` 的主动高级连接点，不是铰链。被动端由运行时发现，不配置名称、路径或标记。 |
| 同步／存档状态 | `connected` | 子系统唯一新增状态，布尔，初始 `false`。锁扣在自身 tick 与 `refreshSyncBaseline` 中核对 `attachedConnector` 双端是否互指：互指写 `true`，实际断开写 `false`；同 `Part` 的已保存标记先按 §5.4 用于恢复，恢复结束后才进入这一对账。物理关节是否入世由 §5.2 巡检对账，不单独阻塞标记。通过子系统 `SynchedEntityData` 同步，并由 `saveData` 持久化。运行时它是逻辑配对的镜像，不替代 Connector 引用、关节或 `partNet`；存档值在同 `Part` 恢复时作为候选提示。 |

**静态校验**：主动端存在、是高级端、每个高级连接点最多挂一个锁扣（同一子零件上的多个锁扣各绑各的连接点即可，车体一处装四扇门与两块盖板的锁扣属正常布置）；Connector 现有 `internal`、条件标签和信号／能源配置继续按原语义工作，不新增 Connector 配置字段。静态内容检查不能预先断言运行时哪一个对侧会进入范围。

**运行时校验**：只枚举同一 `VehicleCore` 内有效简单端；候选与主动端必须属于不同刚体、同一物理空间、均已入世，双向 `conditionCheck` 通过且目标空闲。优先选端点距离最小者；距离并列在物理容差内时不捕获并限频报告歧义，不依赖 Map 遍历顺序。候选离开本车、被占用、拆除或条件失效后，丢弃其待办并重新搜索，不跨载具连接、不触发载具合并。无候选是正常状态，不按物理步刷日志。

静态属性的 `sounds` 沿用专属音效子系统的组合方式：复用 `BasicSoundAttr.basicSounds(...)`，在同一个 `sounds` 对象中添加 `on_attach`、`on_detach` 两个 `SoundEvent` 字段。它们的默认值均为 `minecraft:block.tripwire.attach`，内容可分别覆写。此结构与 `GearboxSubsystemStaticAttr.GearBoxSoundAttr`（基础声音加专属动作声音）一致；通用基础音效字段保持原样。

## 4. 物理判据与重扣

### 4.1 吸合和进入锁止窗口

1. 每 tick 在服务端主线程对本 `VehicleCore` 当前所有 `Part`／`SubPart` 枚举简单 Connector，先排除主动端自身、已被占用端、同刚体端、未入世端、跨物理空间端和双向 `conditionCheck` 任一失败的端，再用 `offsetFromMassCenter` 与服务端刚体位姿计算剩余候选的世界端点 `pA`、`pB`。不用动画 locator、呈现位姿或已经校正过的 `actualTransform`。选择距离最短的唯一候选，把本轮候选身份与端点冻结后交给物理侧；并列在物理容差内时暂停捕获，不依赖容器顺序。对齐误差沿用 `ConnectorAlignmentHelper` 的相向法线约定；速度用端点的 `v + ω × r`，其中 `r` 是刚体质心指向端点的世界偏移。拒绝非有限样本。
2. 仅在已武装、距离 `d <= capture_distance` 且法线误差在 `lock_angle_tolerance` 内施加吸力。首版用 `F = max_capture_force * clamp(1 - d / capture_distance, 0, 1)`，沿端点连线在两端施加等大反向力；零距离跳过归一化。力写入物理 Pre；锁住、禁用、等待分离或目标变化时无吸力。不瞬移刚体，不写速度，不调铰链。桑塔纳先取 `max_capture_force = 0`。
3. 锁止同时要求 `d <= lock_distance`、法线误差在角容差内、端点相对速率 `<= max_lock_speed`，且本次不是明显向外反弹。用 `dot(vB-vA, normalize(pB-pA))` 量分离速度；允许的数值噪声限取 `min(0.01 m/s, max_lock_speed)`。零距离没有分离方向，只检查相对速率。检查的是当前端点，不是动画进度、目标角或动画是否结束。
4. 起始标定建议仅用于桑塔纳夹具：锁止 0.015 m、捕获 0.04 m、法线误差 3°、相对速率 0.25 m/s、重武装倍率 2；在 §9 的物理测试中确认或调整。门边连接采用现有刚性 Connector 关节，不在原铰链写入限位。动态接合用本步姿态求两端共同的世界参考系，等价于 `alignActualTransformForJoint` 的无位移配准；编码时使用冻结的两端局部帧，失败不得残留 `actualTransform`。避免以固定六轴关节强拉一个尚未到位的门。

### 4.2 状态和转换

| 状态 | 行为与退出条件 |
| --- | --- |
| 已扣合 | `connected == true` 且当前 Connector 双端配对与物理关节核对通过。吸力为零，现有关节负责承力。玩家请求解扣时尝试断开，否决则保持该状态。 |
| 等待分离 | 成功解扣后立即进入；不吸合、不检测扣合。观察到 `d > max(capture_distance, n * lock_distance)` 后才进入已武装状态。当次越界不执行扣合。 |
| 已武装 | 可在捕获范围内施力；本轮捕获周期暂存最近的唯一兼容候选，离开扩展捕获范围或候选失效才重新选取。进入锁止窗口后提交一次连接请求。失败不改变 `connected`，同一物理样本不可重复提交。 |
| 无有效对侧／子系统停用 | 无吸力，无扣合请求。停用不是主动解扣，不拆已存在的机械连接。对侧重新可用时从等待分离起算。 |

每个锁扣最多有一个未完成的逻辑变更；正在解扣时不能创建同端点的扣合。`connected` 是 Connector 逻辑配对的持久化／同步镜像，不保存对侧名称；跨 `Part` 的实际对侧仍随既有 `ConnectionData` 保存，恢复后通过一致性巡检核对。同 `Part` 动态连接没有 `partNet` 边，若存档标记为已连接，则载具恢复完毕后只在锁止距离内寻找唯一兼容候选并静默恢复；找不到或有歧义就清除标记。运行时解扣后进入等待分离，存档中的旧标记不会被当作运行时新扣合。首版不存候选、吸合计时器和开合过程。门把手在“开、关”之间切换：每次交互都请求解扣，开门必须如此；关门时多发的解扣请求无害——解扣是瞬时的，门合拢需要时间。

## 5. 提交、拓扑与同步

### 5.1 权威与顺序

- **服务端主线程**在子系统 tick 枚举候选、核对占用和生命周期、执行可否决的 Connector 事件、提交逻辑变更并维护配对及拓扑；候选身份与端点冻结后交给物理侧。**物理线程**在 Pre 只对冻结候选施加吸力，在已完成的物理步采样锁止判据，发布最新的不可变样本（候选身份、步号、几何；必要时含局部帧）；不改 `partNet`、写 `connected`、发包、触发动画或播放声音。`connected` 由主线程在逻辑接合／断开后按 `attachedConnector` 对账更新；客户端只应用服务端结果。
- 关节增删沿现有 `addToLevel`／`detachJoint` 的 `submitImmediateTask` 机制，晚于逻辑接合一个物理相位；本阶段不为运行时锁扣增加物理任务的完成回报（见 §5.5）。主线程在 `attach` 返回 `true` 后发布双端配对、结构变化和网络结果；物理关节是否入世由 §5.2 巡检对账。构造期、模板恢复、客户端镜像沿用现有非物理采纳路径，不要求所有调用方走同一预检。
- `onDetach` 清除本子系统待办和吸力请求，不隐式解扣仍然有效的机械连接。

### 5.2 连接状态一致性巡检

锁扣在稳定边界对账四项事实：① `connected` 标记；②两端 `attachedConnector` 是否互相指向；③两端是否持有同一个 `New6Dof`，其刚体端点及局部帧是否对应当前连接；④服务端刚体均已入世后，该关节是否确实属于当前 `PhysicsSpace`。跨 `Part` 另核对 `partNet` 恰有一条对应边；同 `Part` 不得有图边。只核对主动端及其真实／候选对侧，不扫描无关结构来猜连接。

构造／读档恢复、载具分裂和当前锁扣操作令牌未完成时属于过渡态，暂缓巡检；物理任务是否执行完毕不是可查询条件，不作为暂缓依据。对刚由对账改变配对状态的端点，巡检至少跳过一个物理相位（实现为一个服务端 tick 的宽限）再判定；用时间窗而不是任务状态，避免在 `addToLevel`／`detachJoint` 执行前把有效连接误判为失效或把待移除关节误判为孤儿。锁扣在自己的解扣入口直接读取 `tryDetach` 的布尔结果；其它接合／断开路径由稳定边界巡检对账，不要求逐路径回调。稳定态按下表收敛：

| 稳定态不一致 | 处理要求 |
| --- | --- |
| 实际 Connector 配对、共享有效物理关节和拓扑均成立，`connected == false` | 以真实连接为准补正标记；`refreshSyncBaseline` 在 `pushAllTo` 采样前先对账，完整载入完成后的首次快照即为真值并静默建立声音基线。运行时成功连接的标记变化按 §5.4 播放一次连接声。 |
| `connected == true`，但双端引用缺失或不互指；存档／拓扑记录确认这对端点，且有唯一匹配的有效关节 | 修复双端引用和端口登记，不创建第二个关节；将拓扑规范为恰好一条跨 `Part` 边或零条同 `Part` 边。修复静默。若引用被另一有效连接占用，不覆盖对方，进入隔离。 |
| `connected == true`，无配对引用或有效关节，且不是待办／未完成恢复 | 仅在恢复阶段按 `connected` 标记和锁止距离寻找唯一兼容端，成功后静默建立真实 Connector 连接；运行时则视为意外断开，清除标记并进入等待分离，不就地重新吸回。 |
| 双端引用互指，但关节为空、不在本物理空间或端点不匹配；无本锁扣待办 | 真实约束已失效。经统一断开收尾清除两端引用、复位局部帧和端口；跨 `Part` 删除对应边并执行分裂／同步；标记置 `false`。不得在漂开的当前位置补建锁止关节。 |
| 找到关节但无对应 Connector 配对；存在唯一关节且其刚体、锁扣局部帧与主动端及候选端完全匹配 | 若 `connected == true` 且恢复记录确认此连接，可认领并补齐 Connector 引用；否则在确认该关节不是铰链后，移除这个唯一匹配的锁扣孤儿关节。多个关节都匹配或帧无法唯一辨认时，隔离主动端、停用吸力并限频诊断，不得误删。 |
| `partNet` 边存在但 Connector 连接失效；或连接有效但图边缺失／重复 | 前者删除陈旧边并执行既有分裂；后者补入且只保留一条对应边。内部连接始终不进图。两种修复均通过 `VehicleCore` 同步，不由子系统私改图。 |
| 活动操作被 `ConnectorAttachEvent.Pre`／`ConnectorDetachEvent.Pre` 否决 | 保留否决前的 Connector 引用、关节、拓扑和 `connected` 值；释放操作占位，不播放连接／断开音效。交互动画在询问锁扣前已由交互区触发，保持其内容侧结果，不回滚、不计作解扣成功。不得出现“拒绝了断开但图边已删除”。 |

所有修复通过 Connector／`VehicleCore` 的统一入口，使双端引用、物理关节、能源／信号端口、`partNet`、保存的 `ConnectionData` 和同步结果作为一个连接变化收敛。修复不能递归触发新捕获。无法唯一识别或对账失败时，保持端点隔离，不施力、不提交，留下一条可定位且限频的诊断。`connected` 只镜像逻辑配对；§5.5 的罕见竞态可能让逻辑配对成立而物理关节缺失，行 4 的统一断开收尾是恢复路径，不在漂开位置补建关节。

### 5.3 连接提交结果

| 变化 | 承担者 | 成功结果 |
| --- | --- | --- |
| 跨 `Part` 接合 | `VehicleCore` 同载具路径 | 双端配对确立，`partNet` 加一条边，走结构收尾及接合包；关节由既有 `addToLevel` 在物理相位加入，随后由巡检核对。无新部件、无跨载具合并。 |
| 跨 `Part` 断开 | `VehicleCore#detachConnections` 或其共享提交入口 | 只删成功断开的配对对应边；关节由 `detachJoint` 在物理相位移除；沿用成功后的结构收尾、连通性检查和分裂包。门的铰链边保留；独立配重件可分离。 |
| 同 `Part` 接合或断开 | `VehicleCore` 的同件动态入口，由 `AbstractPart` 建立配对 | 只对两端都不是 `internal` 的连接点开放；按真实候选端点维护双端配对，物理关节同样经 `addToLevel`／`detachJoint` 延迟增删。配对写成 `partNet` 的自环边（两端是同一个节点）：它随 `ConnectionData` 持久化，但自环不产生邻接，因此不影响连通性与分裂。 |

普通断开先补明确结果（可保留现有 `void` 入口并由内部 `tryDetach` 返回 `boolean`）。事件否决、永久内部连接、已断开等都不可作为成功；空成功批不发包或重算拓扑。对外提交前验证预期配对与边一致。锁扣在自己的解扣入口读 `tryDetach` 的布尔结果，没有单独的物理完成回调；客户端应用权威结果时不重新跑可能否决的本地预事件。既有 `ConnectorAttachEvent` / `ConnectorDetachEvent` 仍是 Connector 生命周期事件，不拿来充当锁扣音效判据。

### 5.4 存档与客户端

1. **跨 `Part`**：真实连接仍由既有 `partNet` 导出 `ConnectionData`，不为锁扣另存对侧名称或第二份连接表。恢复顺序是先按现有连接记录重建真实 Connector 配对／关节，再对账 `connected`；完整状态、蓝图和客户端快照都不得靠“模型接近”猜跨件连接。
2. **同 `Part`**：运行时配对在 `partNet` 里写成自环边（两端是同一个节点），因此随 `ConnectionData` 一起保存与恢复；读档时按保存的安装姿态直接重建双端引用与关节，不靠距离猜测。模板与蓝图按 `STRUCTURE_ONLY` 恢复、连接记录不含这条配对时，才用 `connected` 标记在锁止距离内恢复唯一兼容候选；配对存在但图边缺失时，巡检按双端引用补边，同样不靠距离猜测。没有标记就不因附近几何自动恢复旧连接。
3. **同步和声音**：`connected` 用 `SynchedEntityData` 并走现有 `SubsystemController` 批量同步和迟加入全量快照；只新增子系统类型、不改既有同步字段顺序时不需要提升 `MMPayloadRegistry` 的 `sync` 版本，只有改动既有 accessor 编号或字段顺序时才提升。客户端按 `GearboxSubsystem` 的声音基线范式：首份包含该字段的快照只记录当前值（`refreshSyncBaseline` 在 `pushAllTo` 采样前先对账，因此完整载入完成后的首份快照已是真值，不会先发 `false` 再补救）；随后只在连续 tick 观察到值变化时播放对应 `sounds.on_attach`／`sounds.on_detach`，从而迟加入、初始装配和状态补发不响。Connector 包仍负责跨 `Part` 的实际连接镜像；不增加声音专用包，也不在客户端执行物理连接。

### 5.5 已知风险：同一连接点在一个物理相位内重接

`AbstractConnector#addToLevel` 与 `#detachJoint` 都经 `submitImmediateTask` 把入世／移除推迟到物理相位，任务执行时才读连接点的 `joint` 字段。若同一端点在旧任务执行前完成“解扣 → 重接”，旧解扣任务可能读到新关节并把它从物理世界移除。结果是 `attachedConnector`、`partNet` 与 `connected` 都表示已连接，而世界中没有对应关节，或留下一个无配对的关节。

触发窗口很窄：锁扣解扣后进入等待分离，必须等门离开重武装距离、再回到锁止窗口才会再次接合，中间隔若干 tick，而旧任务在下一个物理相位就会执行。真正可能触发的是同一 tick 内的外部重接：手工装配与损伤断开落在同一 tick、脚本直接调连接入口，或将来加入“立即重扣”路径。

当前处理：稳定边界巡检（§5.2）把“引用在、关节不在本物理空间”收敛为统一断开收尾；无法唯一识别的孤儿关节只记录诊断并隔离，不自动删除，避免误删铰链。

本阶段不做：给 `addToLevel`／`detachJoint` 传入关节实例并在任务里校验身份；物理任务的完成回报与每连接点的待办令牌。若将来出现上述症状，或加入立即重扣／外部同 tick 重接路径，先补这两项，并把 T10 从风险跟踪改为必过用例。

## 6. 交互和表现

1. 门边交互区由既有动画事件目标保持可交互，不随锁扣状态变暗或失效。`onInteract(entity)` 在服务端按当下实际状态处理：存在有效锁扣连接就请求解扣，没有连接时只让动画照常切换；有连接且解扣被接受时返回 `CONSUME`，无连接或被否决时返回 `PASS`，不阻断同一交互区的其它终端。连续点击、转发和过期输入均不可重复解扣。无需修改 `InteractBox` 回调签名，不走普通信号槽。
2. 同 `Part` 的把手直接指向锁扣子系统名；跨 `Part` 的把手经持续存在的铰链端口转发，接收侧端口把到达频道指向指定锁扣，不给锁扣本身接线。为这条接线实现 `getAcceptedChannels()` 可用一个固定的 `interact` 到达频道；它是端口解析标签，不是新增的解扣信号输入。右键内容门控继续使用现有 `InteractBox` 机制。
3. 动画由既有交互区的动画事件驱动：点击先切换开／关目标，随后 `onInteract` 请求解扣。动画只负责摆目标，不决定扣合；客户端通过交互回放包执行同一动画事件，从既有子零件位姿同步看到门的真实运动，不从点击镜像猜解扣成败；本期不新建动画事件包。桑塔纳六处可开合部件的 `interact_<位置>_door` / `interact_hood` / `interact_trunk_door → global` 频道保留并同时承担开、关切换，不另设关闭交互区。
4. 连接与断开的单次音效由客户端观察 `connected` 同步值变化后播放，沿用 `GearboxSubsystem` 的首份快照建基线、连续 tick 检测变化的范式；不从 `onInteract` 点击镜像播放，不新建音效包。分别取 `sounds.on_attach`／`sounds.on_detach`，默认都是 `minecraft:block.tripwire.attach`，声源位置用主动端所属 `SubPart` 的位置，`SoundSource.NEUTRAL`。首次快照、载入、重连补发不响；运行时权威状态变更才响。基础启用／损坏声继续走 `BasicSoundAttr`。

## 7. 内容夹具与迁移

- **桑塔纳六处可开合部件**：四扇车门、引擎盖与后备箱盖，在车体与可拆件上各新增一枚锁扣 locator；车体连接点安装主动 `coupler`，被动端不配置，由双向标签条件和近场搜索从同车的简单端中识别。关合到位时两端 locator 重合、法线相向；P0 实测核对。四扇车门的锁扣点取门后边缘的把手高度，比门轴低 0.375 m——前门的锁扣点落在后门铰链所在的那根立柱上，高度差把两者的近场搜索与提示彻底分开；两块盖板的锁扣点取自由边中点下方（引擎盖在前缘、后备箱盖在后缘），两侧都用竖直法线。保留现有铰链及 `joint_driver` 参数。模板的 `ConnectionData` 保留门边这对连接，恢复时按普通连接重建；模板与蓝图按 `STRUCTURE_ONLY` 恢复，不加载锁扣子系统数据，`connected` 保持初始 `false`，由首次对账看到实际已连接后写为 `true`。不得同时留下第二条永久门边连接。
- **开合共用一个交互区**：门上现有拉手的交互区同时承担开、关。点击时动画事件先切换开／关目标，随后 `onInteract` 无论当前方向都请求解扣锁扣；解扣是瞬时的，开门必须解扣，关门时多发的解扣请求无害，因为门合拢需要时间。不新增独立关闭交互区，也不按角度门控关闭。读档后门回到关闭属于可接受的初始表现：模板或存档保留门边连接时锁扣直接扣合，没有保留时在关门过程中按几何判据重新扣合。其他门和舱盖保留现有事件。
- **同 `Part` 夹具**：一个 `RegularPart`、两个 `SubPart`，有永久铰链和满足条件的简单端；验证动态扣合写一条自环边、解扣删除；存档按连接记录恢复双端引用与自环边，连接记录缺失时才凭 `connected` 标记在锁止窗口内恢复唯一候选，歧义时安全清除标记。
- **非根子零件必须有 `internal` 连接点**：构造期唯一会建立约束的是内部配对；只靠非 `internal` 同件连接点的子零件在构造后没有任何关节，入世即成为自由刚体掉落。锁扣的同件对是叠加在 `internal` 铰链上的第二道约束，不承担结构支撑；`checkContent` 与构造期告警各拦一次。
- **配重夹具**：两个 `RegularPart`，同一载具内由近场捕获建立唯一锁扣边。释放成功后观察配重原实例、原 `Part` UUID 与同步分裂结果，不引入额外推力或专用载荷。
