# 动力系统：动力图与支路控制实施计划

> **状态：** 计划中，供审阅；本文列出的实施阶段均未执行。
> **日期：** 2026-10-31
> **审阅版本：** v2；外审 E1—E12 及后续七项句级意见已纳入，落实位置见 §15。
> **核对基线：** Machine-Max `a89501a1` 工作区中的相关源码；本文的源码坐标均为活引用，执行时须复核实际声明。
> **用途：** 指导编码 agent 完成机械动力关系识别、对象来源传递、按支路控制，以及有功率预算约束的简化多输入传动。
> **路径约定：** 本文代码路径相对于 Machine-Max 仓库根；`../Spark-Core/` 指同级仓库。

## 1. 目标、约束与审阅范围

### 1.1 目标行为

1. 车辆／履带控制器能够从执行端反查上游动力源、变速箱和传动装置，也能从动力源查询受影响的执行端。
2. 多个电机独立驱动车轮时，每个电机、反馈和换挡计算归属于实际机械支路；跨部件同名子系统不会混淆。
3. 发动机经主传动提供行驶输入、电机经另一传动提供转向输入时，控制器能分别控制两路，并识别它们在履带驱动处的汇合。
4. 断开连接、离合分离、有效零转速、零功率和设备失效有明确区别；功率与反馈不会滞留在失效支路。
5. 分流和汇合不放大所传递的功率预算。物理端继续使用有限扭矩的速度伺服；实际能量结算的范围见 §8.6。

### 1.3 本稿的实施建议

§3—§11 给出建议落地形态，尤其是：输入数量限制、非法接线处理、更新相位、双流角色配置、反馈近似、功率预算归一化。它们是供审阅的具体方案，并非已实现能力。§13 汇总需要重点审阅的取舍。

### 1.4 范围以外

不在本计划范围：通用机械闭环求解器、真实齿轮约束、通用扭矩矢量分配器、完整牵引力控制算法、再生制动／电池能量收支重写、HUD 制作、整车物理线程迁移。电动机当前禁用的耦合扭矩不得借本计划启用。

## 3. 动力图的归属、结构与唯一事实来源

### 3.1 持有关系

建议创建具体类 `common/mech/energy/MechPowerGraph`（本节路径以 `src/main/java/io/github/sweetzonzi/machine_max/` 为前缀），由 `SubsystemController.mechPowerGraph` 持有。拟建符号不是现有源码引用。

```text
SubsystemController
  allSubsystems
  energyGrid
  mechPowerGraph
    正向：producer → 输出配置槽 → consumer 对象
    反向：consumer → 直接上游 producer 对象集合
    功率节点的前向／反向执行顺序
```

不创建节点包装层、通用图服务接口、全局动力节点注册表、持久化连接 ID。图的两类实际消费者是驾驶控制中的支路查询，以及机械更新中的路径投递与排序。

### 3.2 对象身份与字符串的边界

- producer / consumer 的身份按对象实例判断；底层集合必须保持实例身份语义，不能以后因 `equals` 按名称实现而把节点合并。
- 正向表可以保留输出配置槽字符串，如 `power_outputs` 中的键，用于找到该槽的传动比。它不是消息来源身份。
- 反向表来自同一份已解析的正向表。图作为这两份索引的所有者。
- producer 的 `getMechPowerTargets()` 可以作为图的只读视图入口；不得再让 producer 单独维护、修改一份运行期目标表。
- P2 统一在图／端口的共享解析入口完成寻址：清除接口及四个 producer 实现中的 `rebuildMechPowerTargets()`、各自的可变目标表，以及 Engine／Motor／Gearbox／Transmission 四份 `resolveEnergyTarget`。兼容保留的 getMechPowerTargets 仅允许物理线程调用，委托当前已安装图，返回含内层集合在内的不可变视图；默认 pushMechPower／反馈收集属于其调用方。主线程建图、HUD 和其他跨线程查询不得读取这个运行视图，应使用对应的构建元数据或已发布遥测；接口及实现的 Javadoc 必须写明此线程契约。
- 图构建需要 producer 声明输出配置槽。建议在现有 `IMechPowerProducer` 上提供最小的 `getMechPowerOutputNames()` 集合查询：Engine、Motor、Gearbox 返回各自单目标，Transmission 返回 `power_outputs` 的键。图从配置声明构建，不能依赖尚未生成的运行期目标视图。具体传动比继续由所属子系统解释。
- 图不保存逐步功率、反馈数值或离合布尔值。子系统持有本步数据；图只保存结构和编译出的遍历顺序。
- 图与对象引用均不写 NBT、不发网络包。读档／客户端建体完成后按本地对象重建。

### 3.3 输入数量与重复接线

首版支持一对 producer / consumer 间一条独立动力输入关系。相同名称的不同 producer 对象是合法多输入。

同一个 producer 的两个输出配置槽如果解析到同一个 consumer，可能意味着重复布线，也可能意味着需要两个独立端口。首版应报出两个配置槽与解析终点，并使这组歧义连接失效，不能静默覆盖、重复计功或只取最后一个值。

TrackDrive 是明确的多输入消费者。Gearbox、Transmission、WheelDriver、JointDriver 在首版中保持单输入；若发现多个直接上游，报告配置错误并隔离该消费者的机械输入。若确有同一 producer 的多端口需求，再扩充端口参数；不要预建无人使用的连接对象体系。

### 3.4 解析方向必须与投递方向一致

图构建使用现有输出配置作为唯一源：先查 producer 所属同一 SubPart 的子系统，再查该 SubPart 的连接器；连接器从发送端跨到 `attachedConnector`，在对侧 SubPart 内查它的消费目标。若该目标又是端口，继续按投递语义解析。不能在整个装配体或 allSubsystems 中按名字查找目标；两个 SubPart 可以合法地各有名为 motor 的子系统。

需要区分“发送到端口”与“已经跨到对侧端口、正在交付本地消费者”这两种解析位置，防止把对侧端口再次跨回发送侧。S6 的 `onMechPowerReceived` 与 `deliverToLocalConsumer` 是核对入口。

实现时只保留一套解析逻辑供建图与端口转发使用。已解析的图可直接投递最终消费者；端口对象承担配置／物理连接的桥接职责，不占一个物理更新节点。

解析期间以端口实例和解析位置组成已访问状态，检测任意长度递归，不仅检查互相对接的两个端口。普通断开连接可产生无出边；配置指向不存在或类型不符的本地目标，需要定位诊断。

### 3.5 构建与诊断

1. 捕获本次子系统集合和连接配置，构建临时解析表。
2. 按 §3.4 的 SubPart 作用域解析目标，再检查解析到的对象属于本控制器的 allSubsystems。该集合仅作身份归属校验，不是按名解析表。跨控制器机械连接在首版中诊断为不支持，不自动接管对方。
3. 检查重复终点、消费者输入数量、非有限／零传动比等配置边界。
4. 从合法正向表构建反向表、拓扑序与逆序。
5. 若存在有向功率环，报告环中的设备和输出槽，隔离含环的机械连通分量；其他独立分量继续工作。反馈查询不参与该环检测。
6. 产出完整、不可变的结构结果；只有全部必要索引一致后才能发布。

日志包含部件／子部件／子系统的可定位名称以及输出槽；这些名字仅用于诊断。相同错误按结构版本报告一次，避免每物理步刷屏。无效组件仍执行通用生命周期与独立制动；机械输入使用 EMPTY。

### 3.6 具体容器与并发边界

图是带输出槽的有向邻接表，首版合法运行分量为 DAG；汇合节点可以有多个父节点，因此不限制成树。建议的字段类型为：

```java
Map<IMechPowerProducer, Map<String, IMechPowerConsumer>> outgoing;
Map<IMechPowerConsumer, Set<IMechPowerProducer>> incoming;
List<AbstractSubsystem> forwardOrder; // 现有机械子系统对象
List<AbstractSubsystem> reverseOrder;
```

输出槽字符串只用于配置倍率定位；两张表的对象键用 IdentityHashMap，来源集合用身份集合。构建器独占可变容器，产物冻结每一层，且不得泄漏可变 backing map。身份 Map／Set 用隔离后的容器加不可修改视图，不能用会改变身份去重语义的通用拷贝；字符串槽表和顺序列表可以使用 copyOf。冻结的是结构关系，不是子系统对象的全部状态。

并发容器已经可用：`src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/SubsystemController.java#channels` 使用 ConcurrentHashMap，`src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/SubsystemController.java#allSubsystems` 使用 CopyOnWriteArraySet。它们适合独立条目的注册／查询，但不能让正向表、反向表、拓扑序和驾驶绑定作为整体同时生效。ConcurrentHashMap 的批量操作及迭代也不提供整图事务快照，见 [Java 21 ConcurrentHashMap 文档](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/concurrent/ConcurrentHashMap.html)。给每张表换并发容器无法满足 §6.1 的一致发布契约。

本计划选择普通容器构建不可变结构，经单个 volatile 候选引用发布，物理线程只在步首安装。逐步输入槽、传播资格和控制 claim 由物理线程独占，使用普通身份容器；主线程只读取另行发布的不可变遥测。无需通用并发图依赖、逐边锁或 synchronized。解析完端点后，索引／拓扑排序为 O(V+E)，每步机械图处理为固定次数的 O(V+E) 遍历；控制器的路径查询按 §7.1 单独管理。

## 4. 机械消息接口与输入生命周期

### 4.1 来源直接传对象

目标签名：

```java
void onMechPowerReceived(IMechPowerProducer producer, MechPower power);
default void beginMechPowerStep() {}
default void refreshPathEligibility() {}
default boolean hasFeedbackSpeed(IMechPowerProducer producer) { return false; }
float getFeedbackSpeed(IMechPowerProducer producer);
boolean isPowerPathConnected(IMechPowerProducer producer);
```

无参数 `getFeedbackSpeed()` 可服务单输入设备的默认实现。已检索 Machine-Max 及同级 ARMS-Core、Spark-Core、BallisticsFramework 的源码，`setFeedbackSpeed(float)` 只有接口／实现和端口转发，没有业务调用；P1 删除这一接口方法、实现和无效转发链。

`beginMechPowerStep()` 只清本步功率槽，在任何 producer 输出前统一调用。`refreshPathEligibility()` 逆序计算并缓存传播后的资格，同时按已采样末端值刷新反馈折算；它不推进发动机、不发功率、不驱动关节。`hasFeedbackSpeed` 区分“路径接合但尚无测量”与“有效测量为 0”，`getFeedbackSpeed` 只在资格和样本有效时读取。端口不在机械遍历表中，不得借图钩子再次遍历终端；它仅转发查询和消息。

两个 void 钩子的默认实现为空操作，供无自有机械状态的转发器使用；Gearbox、Transmission、WheelDriver、TrackDrive、JointDriver 都持有输入／资格状态，必须覆盖并完成各自工作，单输入也不能省略清槽。hasFeedbackSpeed 默认 false 表示接口尚未声明有样本，不检查转速大小。实际消费者必须覆盖为采样有效标志（并确认 producer 属于该输入）：采样成功的 0 与有限非零值都返回 true，未采样或无效样本返回 false，禁止以 speed != 0 判断。MechPowerPort 继承两个空钩子，覆盖 hasFeedbackSpeed 并沿统一解析结果转发到终端，未解析到终端则返回 false；不得转发清槽／资格刷新。

推送侧传 `this`。连接器透明转发同一个 producer 对象；Gearbox / Transmission 作为生产者输出自己的结果时，以自身对象标识来源。完整祖先关系由图查询，不随每条 `MechPower` 消息重复携带。

TrackDrive 的多输入缓存按 `IMechPowerProducer` 对象索引。接口适配需覆盖 S4—S11、JointDriver 及其他仓库中的实际调用方；当前测试没有引用这两个接口，不预设已有测试替身迁移工作。后续图测试可按 §12.1 建轻量替身，不增加靠名字查询对象的兼容旁路。

### 4.2 每步输入必须完整且不会陈旧

物理步 Pre-0 对所有消费者统一调用 beginMechPowerStep：单输入置 EMPTY，多输入清空。不能把清槽放到消费者自己的 onPrePhysicsTick 开头，因为此时上游已可能交付本步输入。生产者按本步拓扑序最多向每个输出槽交付一次，消费者在所有上游都执行完后求值一次。

完整交付后，下游缓存只代表本物理步。上游未输出、支路断开、失效或结构切换不会留下上一步扭矩。EMPTY 不参与数值计算；ZERO 是有效零载荷，二者不能互相代替。

本步功率槽与上个已完成物理步的反馈缓存是两份有不同时间含义的数据。清空功率槽时不能清空反馈缓存。TrackDrive 在 Post 利用刚完成的输入分量与实测速率生成按 producer 对象索引的反馈，供下一步 Pre 使用；不得在 Pre 清槽后再从空的 `received` 推导反馈比例。

功率接收本身只写入槽位，不递归触发下游的动力计算；这样汇合节点不会因两路先后到达而执行两次。

### 4.3 输入数据安全

`MechPower` 继续是不可变载荷；传递来源引用不代表跨线程读取该来源的全部可变状态。转速、功率和扭矩计算在物理线程完成；主线程只消费已发布的遥测。

显式 EMPTY 是合法哨兵；其他 NaN、Infinity、无效传动比在输入／配置边界产生定位诊断并使该路无效，不允许进入 Bullet。null 不作为第三种正常消息状态。

### 4.4 动力源的分支契约

Engine／Motor 先询问是否存在本步有传力资格的出边，再单独收集有测量的反馈；不能以 feedbacks.isEmpty() 代替接合判断。

| 路径资格 | 测量 | 动力源行为 |
| --- | --- | --- |
| 无 | 无关 | 运行自身怠速／自由转动／阻尼策略；对无资格路线统一交付 EMPTY。Engine 和 Motor 使用同一消息有效性契约。 |
| 有 | 尚不可用 | 保持本步控制输入，按本机转子模型推进并输出有限预算，跳过尚无依据的反馈耦合；不因缺样本将电门置零。 |
| 有 | 含有效 0 或非零值 | 使用有效反馈；0 按静止负载测量参与控制。 |

collectFeedbackSpeeds 仅收集 isPowerPathConnected 且 hasFeedbackSpeed 的项。无样本时的源自身推进不能产生 Infinity／NaN，也不能借此启用 S15 中被禁用的耦合扭矩。端点按 §5.2 独立采样，避免反馈与输出相互等待。

## 5. 拓扑、传力资格与反馈

### 5.1 状态契约

| 情况 | 结构边 | 本步反馈资格 | 数值意义 |
| --- | --- | --- | --- |
| 车轮静止且接合，已有测量 | 存在 | true | hasFeedbackSpeed=true，有效 ω = 0 |
| 结构已接合，尚未获得测量 | 存在 | true | hasFeedbackSpeed=false；不能伪造 0，也不等同断开 |
| 车辆滑行、源未提供驱动功率 | 存在 | 按机械接合判定 | 可以有非零反馈；P = 0 不意味着断开 |
| 离合分离／换挡动力中断 | 存在 | 对该输入为 false | 不将占位 0 作为有效反馈返回上游 |
| 连接器断开 | 对应路线不成立 | false | 清除对应输入与反馈关联 |
| 末端无有效关节／被驱动对象失效 | 可存在配置关系 | false | 不向该物理端执行驱动 |
| 发动机停机但机械仍接合 | 存在 | 按接合状态判断 | 停机与物理断开不是同一个状态 |

连接资格不能以“本步是否已经收到非空功率”决定，否则源等待反馈、末端等待源输出，会形成启动互等。

### 5.2 中间机构传播

物理步内在控制命令落地后，以逆拓扑顺序更新有效路径资格。末端先检查关节、连接、损伤及离合；中间机构结合本地接合条件与有效下游，得出每个输入的资格。

传播结果存于消费者的物理线程字段，不写不可变图：单输入节点一个缓存布尔值，按输入有独立门控的多输入节点用 producer 身份表。共享同一关节／离合的多输入节点可共享一个门控值，再校验 producer 属于图的合法入边。refreshPathEligibility 每步重新计算；isPowerPathConnected 只读这个传播结果，不返回仅有本地离合条件的值，也不触发递归求值。样本有效性和测量值是另一组字段；资格清零不会把无效测量伪装成有效 0。

首版的单输入 Gearbox / Transmission：没有任何有效下游时，上游资格为 false；有有效下游时，仅聚合有效项。对未建模轴惯量的无负载中间机构，采用“无有效末端反馈”的简化，不伪造一个静止负载。

反馈数值使用上一个完成物理步的采样，在本步 Pre 中按当前传动比、当前有效路径重新折算；这样换挡后不会拿上一挡折算值计算本挡控制。结构刚接通而无历史采样时，从已就绪的物理关节采样；多输入分量的初始化见 §8.5。无法取得总轴采样则该步暂不提供有效反馈，物理 Post 独立采样，不以本步收到功率为采样前提。

本步 Post 先采样末端，再逆序聚合中间机构。不能依靠递归跨任意层读取、或集合遍历顺序“碰巧”完成反馈刷新。

### 5.3 零转速与锁止

有效 ω = 0 仅表示测量值。是否允许转动、是否施加保持扭矩，由离合、制动和伺服控制决定。功率链无反馈代表该路不约束源的转速，但源自身阻尼、怠速策略继续执行。

## 6. 重建、线程与确定性更新

### 6.1 结构变化的发布边界

主线程工作：捕获结构、解析并校验新图、完成信号发现，构建与该图匹配的驾驶绑定元数据。在 SubsystemController 内用一个最小的不可变候选单元封装图、节点列表、绑定元数据及诊断版本，经单个 volatile 引用发布。构建在主线程串行完成，不引入后台重建任务或完成顺序仲裁器。

主线程准备阶段只读取连接和配置元数据。驾驶绑定所需的刚体位置、关节就绪状态与初始速度由物理安装阶段采样。S21 中 TrackController 的 rebuildTrackBindings 及 S23 中 CarController 的 recalculateSteeringCenter 所读 native 状态必须迁入该阶段。握手只收集 drive／channel／connector 等对象关联。物理线程从这些关联构造完整、不可变的 TrackBinding 列表及轮式几何绑定后，与图一起成为本步运行视图；主线程不能清理或修改这些结果。

安装入口就是 SubsystemController.prePhysicsTick 的第一个阶段，早于任何子系统回调：读取一次候选，若它与物理线程记录的 appliedCandidate 不是同一实例，则采样并切换图和匹配绑定，清理失效输入／反馈，准备执行序列。该步固定使用所选运行视图直到 Post 结束；步中发布的候选等下一步处理。“运行视图”指控制器已安装的图、列表和绑定字段，不要求额外定义 InstalledView 包装类。

发布槽不采用“读取后写 null”：这两个操作之间主线程可能发布另一份候选，随后被物理线程的 null 覆盖。使用以下最小协议即可；符号均为拟议字段，不是现有 API：

```java
// 主线程：冻结全部结构和绑定元数据后，只写一次。
pendingCandidate = completedCandidate; // volatile；每次构建一个新实例

// 物理线程：prePhysicsTick 开头；后续相位固定使用已安装的字段。
var candidate = pendingCandidate;
if (candidate != null && candidate != appliedCandidate) {
    installAndSample(candidate); // 仅在物理线程内设置图、顺序和绑定字段
    appliedCandidate = candidate;
}
// 不清空 pendingCandidate；它可与 appliedCandidate 指向同一实例。
```

尚未被采纳的中间候选可以被更新的完整候选覆盖，因为结构结果是快照，不是必须逐项消费的事件。结构版本仅用于诊断和生命周期核对，不是来源 ID。只有候选需要跨线程冻结，不为每条边、每条功率消息再套发布包装。

S19 的执行顺序是 Pre 事件 → 车辆机械 Pre → ALL／PRE 队列；因此本计划不使用 PRE 任务安装图。物理安装时尚未就绪的关节或刚体标为不可用，其支路不施加驱动；每个后续 Pre-0 重试未就绪的绑定采样，完整冻结可用绑定后供该步使用，不必等待下一次结构变化。样本缺失按 §4.4，硬件不可用按 §5.1，二者不能混同。

首次 initAllSubsystems 必须同步完成候选发布，首次进入机械 Pre 便可安装，不引入人为等待一物理步的任务空窗。如果初始化尚未发布候选或失败，控制器显式处于空图状态：各通用生命周期回调一次、消费者输入 EMPTY、自动动力命令不发出、驱动扭矩为零；独立制动仅在物理对象就绪时执行。该状态及首个有效步都纳入 T34，不允许读取半成品目标表。

### 6.2 与通用生命周期的衔接

S2 的“全部预清理，再全部握手”是弹药等其他系统依赖的契约，需要保留。动力图相关顺序应为：

1. 捕获结构并准备图候选；保留全部预清理先于全部握手的次序。通用主线程预清理只操作发现用数据，不清理正在物理使用的发布结果。
2. 完成所有信号握手；驾驶控制器使用图候选建立绑定元数据。
3. 将图候选与绑定元数据作为同一次更新发布。
4. 在机械 Pre-0 安装并清理运行期动力槽；首次初始化同样走这条构建／发布路径，硬件就绪判定见 §6.1。

允许调整 `initAllSubsystems` 和 S2 的内部顺序，但所有子系统的 attach／detach、预清理／握手次数必须保持一次。禁止把整个结构回调搬到物理线程。

### 6.3 每个物理步的建议顺序

| 相位 | 动作 |
| --- | --- |
| Pre-0 | 安装候选、采样绑定／初始物理观测，固定本步节点列表；统一调用消费者 beginMechPowerStep 清槽；清空 claim 集，全部驾驶控制器准备本步输入并提交认领，统一判定冲突。准备和认领不得发控制命令。 |
| Pre-1 | 驾驶控制器以 Pre-0 固定输入执行本步一次通用 Pre 回调，按 claim 判定和支路计算命令，完成油门、离合、挡位和制动请求。 |
| Pre-2 | 逆序调用消费者 refreshPathEligibility：各节点在该钩子内确定本步本地门控／换挡窗口，再结合已刷新下游缓存传播资格和折算反馈；不输出功率。 |
| Pre-3 | 动力源 → 传动 → 执行端，按拓扑序各执行一次机械更新；汇合端收齐输入后求值。 |
| Pre-4 | 非动力子系统（含炮塔等非动力图机械执行器）各执行一次通用 Pre 回调；全部子系统 Pre 完成后执行一次电网 Pre。 |
| Physics | Bullet 执行实际积分与约束求解。 |
| Post | 末端采样 → 中间机构逆序反馈聚合 → 驾驶遥测发布。 |

Pre-1 的换挡评估读取步首观测及候选比值；Pre-2 则应用本步最终挡位和离合状态。实际扭矩曲线求值不能使用不存在的混合轴速，规则见 §7.2。

驾驶等机械控制器只消费本物理步开始前已发布的外部输入／控制信号，并在步首固定；步中发布的外部信号及 Pre-4 产生的上游控制信号留待下一步消费。Pre-1 根据这份固定输入生成的内部动力命令按既定顺序在本步 Pre-2／Pre-3 生效，不属于步中外部输入。

优先重排已有机械子系统及地面控制器的 Pre／Post 调用，不创建通用任务调度框架。通用 onPrePhysicsTick／onPostPhysicsTick 及其 super 每步各一次：驾驶控制器在 Pre-1，机械节点在 Pre-3，其余子系统在 Pre-3 之后、Physics 之前的 Pre-4 各一次；同一对象不能同时出现在两份执行列表。Post 按末端到上游安排机械回调，反馈采样与聚合各一次。

图钩子另计：清槽、准备／认领、逆序资格和前向功率可以各自遍历，不能为了“一次遍历”压进同一个节点回调。它们不重复机械求值。禁止的是先对全部节点运行通用 Pre，再对机械节点重复运行通用 Pre。换挡窗口、离合等本步门控必须在 Pre-2 固定，Pre-3 不能再次推进状态导致资格与执行不一致。

非动力子系统保持其生命周期职责；电网沿用 S3 的位置，在全部子系统 Pre 完成后调用一次，不借本计划重排整套电力结算。S17 的关节轴功率分配须在读取本步机械输入后执行，不能留在 20 Hz 主线程造成额外缓存延迟。

### 6.4 拆分、合并与销毁

结构拆分／合并涉及的所有 `SubsystemController` 都要得到独立的图与节点集合。一个 producer 对象最多由一个当前控制器执行；移交期间不得被两份执行序列重复更新。

destroy 与 S18 的主线程侧只先置 volatile 失效标志、清空 pending 槽，并投递物理终止任务；该侧不得写 appliedCandidate、运行视图、驾驶绑定、claim 或机械缓存。这些物理线程私有字段由终止任务在物理生命周期边界清理，与已经进入的回调串行执行。发布入口与安装入口都检查失效标志；已取到候选的物理线程在采纳前复核，发现失效则不安装。终止任务可以使用物理任务队列，它承担资源释放，不承担 §6.1 的步首图安装。

重载后使用新建对象重建，禁止通过失效对象引用恢复关系。客户端只使用客户端本地对象，不跨端共享图；服务端继续承担权威动力状态。

## 7. 支路查询与驾驶控制

### 7.1 查询能力

首版只提供有调用方的操作：直接入边／出边、某执行端的上游、某源的下游执行端，以及某变速箱输入路径上的源与机构。返回既有对象或只读集合，不为每次查询复制全套节点状态。

连通查询可以按对象去重；传动折算必须保留路径与输出配置槽，不能在汇合点过早去重而丢掉不同路径的倍率。禁止预枚举所有源到所有末端的路径；对控制器实际使用的支路按需编译或遍历，结构不变时缓存对象关联，动态比值每步读取。

信号握手决定控制可达范围；图决定机械影响范围。自动控制对象取两者交集。发现一个机械上可达的动力源，不等于获得对它的控制权。

### 7.2 自动换挡

每台变速箱使用自己的输入路径与输出轴观测评估挡位：

1. 取得本箱输出侧有效反馈，作为候选挡位共同使用的输出轴速度；无负载反馈时使用现有起步／方向规则，不能构造全车平均转速。
2. 对候选挡位 g，以本箱总比值预测输入轴速度，再沿已知的单输入传动路径折算到源。
3. 在该源自己的扭矩曲线上求值，沿同一路径把扭矩折回本箱输出侧；各级比值符号用于方向，扭矩能力使用绝对倍率。
4. 保留手动优先、换挡间隔、相邻挡约束与收益迟滞；纯电／燃油判断按该输入路径进行。
5. 首版不支持“多自由度汇合机构位于变速箱上游”时的自动最优挡位推导。识别该情况并保留手动挡位、给出一次诊断；不能把多个不同轴速平均后冒充本箱输入轴速度。

图可以识别复杂支路，并不意味着控制器必须一次实现所有机构的最优控制。首版已支持的实际结构是每台变速箱具有可唯一折算的源路径、分流位于其下游，以及多个这样的独立支路。

S12 的控制分发与平均转速计算需分开职责。S13 的统计量如有遥测消费方，可按实际需求保留为显示数据；驾驶决策不得依赖全车混合平均值。

### 7.3 独立电机驱动轮胎

```text
电机 A → 减速／变速支路 A → 左前轮
电机 B → 减速／变速支路 B → 右前轮
电机 C → 减速／变速支路 C → 左后轮
电机 D → 减速／变速支路 D → 右后轮
```

默认驾驶可以向四路发送同一纵向需求，但发送与反馈按对象分别处理。通过现有信号入口给其中一路不同电门时，其余支路的输入和换挡评估必须独立。共享电网限额造成的相互影响属于电力供应约束，不属于机械串路。

本阶段不强制实现轮胎打滑控制器。验收重点是逐路命令确实作用到指定轮、图能解释影响范围，而非把四轮全部置于同一个转速闭环。

### 7.4 控制冲突

SubsystemController 持有本物理步的 claim 表：设备对象 → 驾驶控制器身份集合。它是物理线程私有状态，每个 Pre-0 清空。AbstractGroundControllerSubsystem 提供 prepareDriveStep（拟议钩子），只消费／固定本步输入和可控对象，提交即将自动写入的源、变速箱和执行器认领，不发送信号或修改设备。控制器先收齐所有认领，再允许任何 Pre-1 命令执行。

同一设备只有一个有效认领时执行该控制器命令；已有路由能明确排他则按路由判定；多个有效认领冲突时，从首个冲突步起抑制该设备的全部自动写入，并报告参与者身份。禁止使用遍历顺序决定胜者。只抑制冲突设备，不阻塞各控制器的其他独立支路；连续冲突诊断去重。

抑制须同时撤销这些控制器在对应信号频道中持有的自动命令，避免上一步电门残留。按 sender 身份清理／投递约定的中性值，不能清掉其他发送者的手动输入；自动换挡冲突保持当前挡位，不写“零挡”作为中性值。失去激活状态的控制器也要释放自己的自动命令。准备阶段和执行阶段使用同一份步内输入，不能在 Pre-1 再读一份变化后的输入来绕过认领。

## 8. 功率预算与多输入合成

### 8.1 符号与单位

`speed` 单位 rad/s，符号表示该级轴方向；`power` 单位 W，正表示沿该目标方向驱动的预算，负表示制动／反拖预算。载荷不是实际做功计量器。

固定比值 r 的理想变换：`ω_out = ω_in / r`，`P_out = P_in`。r 为负只反转轴方向，不把正驱动预算变成制动预算。反馈用 `ω_in_feedback = r × ω_out_feedback`。

这是针对 S9 当前 Transmission 在负比值下生成异号功率的行为修正，不是仅改说明。P5 必须覆盖两个分配分支，T24／V06 验证负比值下正功率能驱动反向旋转，而非触发 S22 的 engineBrake。

若引入效率 η，正驱动预算最多为 η × 输入正预算，且 0 < η ≤ 1；首版可以采用 η = 1，不要求为了本计划增加效率配置。

### 8.2 汇合：先合成功率与转速，再求扭矩

对 TrackDrive 本步所有有效输入，速度已折算到该轮端：

```text
P = Σ P_i
ω = Σ ω_i
T = P / max(abs(ω), ω_min)
```

本模型是明确的游戏合成规则，不宣称重建真实行星轮反力矩。不得同时使用 `Σ(P_i / abs(ω_i))` 作为合成扭矩，否则两路相同输入会同时增加速度与扭矩能力。

验收算例：两路各 (1000 W, 100 rad/s)，合成为 (2000 W, 200 rad/s)，反推扭矩为 10 N·m；不能输出 20 N·m。反向两路各 (1000 W, -100 rad/s) 时，功率合计同样为正，目标转速为 -200 rad/s。

对混合正负功率，首版按有符号预算相加，然后把正值作为驱动预算、负值作为制动预算。正负抵消不计作电力回收；此规则是净输出近似，不表达内部循环功率。输入方向与功率正负必须分别判断。

`ω_min`、驱动扭矩上限沿用设备参数／现有数值下限并明确单位。对 P = 0、ω = 0，驱动扭矩为 0；保持能力由独立制动预算提供。对 P > 0、ω 约为 0，允许有界零速保持伺服，不允许除零或超硬件扭矩上限。

若目标转速被设备上限钳制，首版保留由合成载荷算出的扭矩预算再做硬件限扭，不因缩小目标速度自动放大扭矩；未使用的预算不算额外消耗。

### 8.3 分流：预算总和受输入约束

Transmission 可以保留开放差速／差速锁的候选分配策略，但最终发出的载荷必须满足预算约束。建议使用以下清晰的归一化流程：

1. 算出各输出候选目标转速与非负扭矩能力权重；负传动比通过速度方向表达，倍率大小用 abs(r)。
2. 以候选 `abs(T_i) × max(abs(ω_target_i), ω_min)` 形成非负分配权重 q_i。
3. 仅对有效出边分配：`P_i = P_in × q_i / Σq`；若候选权重全零，该步输出零预算并保留各路有限候选速度，只有候选速度也为 0 时才使用 ZERO。可用预算允许不完全使用，但不允许超额。
4. 以分配后的 `P_i` 和 `ω_target_i` 生成 `MechPower`，下游据此还原实际扭矩预算；不能再用归一化前的扭矩执行。

该方案保证单一正／负输入的输出预算同号且总量有界；限扭造成的未用预算可以暂不回收重分配。差速器候选算法的牵引特性可能随功率归一化发生变化，需要专门的静止起步、单轮悬空、两侧负载差测试，不能仅测加法恒等式。

S9 的 `LOCK_DRIVE_BIAS` 可以继续作为伺服候选速度的策略，但增加目标速度不能增加输入给定的总预算。P5 在广播型 pushMechPower(MechPower) 入口强制检查：已解析目标数大于 1 时只允许广播 EMPTY；包括 ZERO 在内的有效载荷必须走逐目标分配接口。违规调用在任何交付前给出 producer 定位诊断、不向任何目标交付，并使 SubsystemController 的物理线程诊断计数递增；随后正常返回，不抛异常、不打断本步其余节点。日志按 producer／结构版本去重，每次违规均计数。0 个目标为空操作，1 个目标正常交付。T35 验证此约束，不能仅靠注释禁止预算复制。

生产路径不得依赖异常处理隔离这种违规：`../Spark-Core/src/main/kotlin/cn/solarmoon/spark_core/physics/level/PhysicsLevel.kt#handleException` 会对逃出的物理异常启动重启／停止恢复流程。只有独立测试替身可选择抛出以定位误用；生产入口验收必须验证不抛异常及其他节点继续执行。

### 8.4 前向预算与零速边界

所有执行器保持有限最大力／扭矩，低速反推扭矩不超过上限。ZERO 与 EMPTY 在资格和反馈上的差异按 §5 处理，不能以 `P == 0` 推断机械断开。

Engine、Motor、Gearbox、Transmission 和执行端采用以下一致规则；表中的 P、ω 是该节点已经完成传动／合成后的载荷，不能将末端实测零速度直接当成源的零预算：

| 条件 | 前向消息／执行 |
| --- | --- |
| 该输入路径无资格、没有本步输入或输入为 EMPTY | 该路 EMPTY；执行端无该路驱动预算。反馈采样仍按物理状态独立进行。 |
| 有资格且载荷为 P=0、ω=0 | ZERO；保持接合和有效零测量，驱动扭矩为 0。 |
| 有资格且 P=0、ω 为有限非零值 | 有效 MechPower(0, ω)，保留速度及方向，不折叠为 ZERO 或 EMPTY；驱动扭矩为 0。 |
| 有资格且 P 非零、abs(ω) 接近 0 | 有效有限载荷；按 §8.2 下限和硬件限扭计算，不以低速为由断链。 |
| 非 EMPTY 的非法数值 | 该路无效并定位诊断，禁止进入物理求解。 |

P5 必须处理 Transmission 的近零输入分支和 distributeOpenDiff 的 P=0 分支，按此表输出，而不是 S22 中的 EMPTY。静止接合、有正预算的起步、零预算滑行分别验收；ZERO 是载荷值，hasFeedbackSpeed=true 且反馈为 0 是测量状态，两者不要求同时出现。

转速方向相抵时，目标可以为 0；首版允许净预算下的有界保持行为。其手感和耗能不等同于真实双流机构内的循环功率；不要据此向电网结算虚构的回收或热量。

### 8.5 反馈近似的准确范围

单输入：返回实测末端转速，再由中间传动逐级折算。

多输入：首版采用 S11 的有界比例分摊作为游戏近似，以 producer 对象索引各分量。Post 用本步输入计算分摊结果，结果缓存跨到下一步，生命周期见 §4.2。正常且未限幅的区间内，分量和应等于实测总量；抵消区间采用明确记录的指令分量回退和限幅。限幅／回退时不宣称各路反馈是独立测得的轴转速。

首次接合或所有有效输入分量的绝对值之和接近零时，实测总轴转速仍可能非零。此时建议把总轴实测速率按本步有效上游数量等分作为初始化近似，并限幅；若只有一个输入，直接使用总轴实测值。初始化的“有效上游”取图入边与本步接合资格，不取尚未填充的 received 槽。不能把“缺少分摊权重”当成机械断开，也不能要求源先产生功率才建立反馈资格。该初始化与比例／抵消回退合计为三个互斥数值区间，须测试从静止接合和滑行中接合两种情况。

这一近似用于运行和控制稳定性，不证明机械反力矩、能量守恒或任意多自由度机构的可观测性。双流验收必须包括混合行驶与转向、单侧堵转、输入接近抵消，不能只验证左右轮能反向转。

### 8.6 本计划保证到哪里

必须保证的是消息预算分配：汇合后的净预算来自有效输入，单输入分流的预算总量不超输入。测试要检查每个中间节点以及整条链的端点，避免中间增益相互掩盖。

限扭速度伺服的目标速度与实际速度可能不同，甚至在越速状态发生制动。因此 `P_payload` 不能直接用作实际机械做功、电池扣能或回收量。严格实际能量收支需要实际施加力矩／冲量与位移的观测、惯性储能及耗散结算，属于后续独立任务。

## 9. 双流接线与控制扩展

### 9.1 推荐组合

```text
发动机 → 变速箱 → 主传动 ──┬→ 左 TrackDrive
                           └→ 右 TrackDrive
转向电机 → 转向传动 ───────┬→ 左 TrackDrive
                           └→ 右 TrackDrive
```

主路对左右输出同向速度，转向路对左右输出反向速度。每个传动先分配自身功率预算，每个 TrackDrive 再按 §8.2 汇合。图保留两条独立上游，不把二者压成同一个“发动机列表”。

例：主路总预算 2000 W、每侧速度分量 +100；转向路总预算 400 W、左右分量 +20/-20。等分预算后，左端 (1200 W, 120)，右端 (1200 W, 80)，端点总预算为 2400 W。该算例规定预算与速度合成，不规定两侧最终实际功率相等。

### 9.2 角色由控制接线显式声明

建议在 `TrackControllerSubsystemAttr` 增加可选 `steering_control_outputs`，类型与现有 `control_outputs` 相同，默认空。字段名为本稿建议，落地时需同步 Codec、schema 和示例。

- `control_outputs` 负责通用执行器、行驶源和行驶变速箱发现。
- `steering_control_outputs` 使用专用控制频道发现转向源；目标支持 local 名、连接器与 global，沿用信号解析规则。
- 空映射启用单流模式。非空映射明确声明双流意图；若转向源不可用，令该路命令为零并诊断，不根据一帧设备故障自动切换驾驶模式。
- 同一设备同时被两个角色声明为独立动力源，或同一频道导致来源角色不可区分，须诊断歧义；不能按回调先后分类。
- 图校验行驶／转向源实际到达受控履带，以及转向路径对左右形成所需方向关系。仅有信号握手但无机械路径不算有效绑定。

拟议片段仅展示角色接线，不是完整子系统定义：

```json
{
  "control_outputs": { "car_control": ["global"] },
  "steering_control_outputs": { "track_steering_control": ["global"] }
}
```

转向电机的 `control_inputs` 必须匹配专用频道。输出的机械目标继续由它自己的 `power_output` 决定；控制频道不代替机械连线。

字段从 Codec 到运行需要同时接通以下入口（S20）：

1. getTargetNames 把 steering_control_outputs 纳入 local／connector／global 路由；与既有五张表合并时按频道校验歧义，不能用 putAll 静默覆盖角色。
2. handShake 遍历行驶及转向两类控制频道，完成全部回调后才编译绑定；clearActuatorBindings 和 callback 目标清理覆盖两种角色。
3. onSignalUpdated 先根据回调 controlChannel 确定角色，再按设备类型登记；转向电机不进入行驶 motors，不参与行驶换挡统计。角色表只存发现元数据，运行绑定随 §6.1 的候选发布。
4. builtin 两种语言的 schema 接受该字段，syncSchemas 同步所有副本，checkSchemas 校验；T30／T36 同时验证字段缺省、字段实际存在及真实握手后的命令路由。只验证可省略字段的解码不算配置接入完成。

### 9.3 控制落点

行驶输入只驱动行驶源并参与行驶变速箱换挡。转向输入只驱动转向电机；首版可按有符号转向需求给电门，使用现有横摆反馈修正并限幅，不能把“rad/s 目标”直接塞进只接受归一化电门的入口。

履带轴目标只有一个权威：单流模式保持每侧有限的 TrackControlSignal.targetSpeed；双流模式（steering_control_outputs 非空）对两侧发送 targetSpeed=NaN，表示控制器不限速，TrackMath.singleFlowMotor 使用动力链合成的 sourceSpeed。该 NaN 是控制信号的既定哨兵，不是允许 MechPower 含非法数值。双流不执行单流的每侧目标速度比例钳制；制动、手刹、离合和设备物理限速继续有效。首版不叠加第二套对称车速上限控制，避免目标权威含糊。

若实施需要转向电机目标转速闭环，控制器负责把目标转速与实测转速之差转换为 [-1,1] 电门，并记录增益单位、物理步长与饱和策略；这部分须独立测试，不能假定 `MotorSubsystem` 已提供转速命令接口。

纯转向时，示例载具应通过行驶变速箱离合隔离发动机怠速贡献，避免主路残余速度使原地转向变为前进转向。主路没有可断开机构的结构须明确诊断能力限制。双流控制不要复用单流中“纯转向自动请求前进动力”的规则。

制动、手刹继续到各 TrackDrive；左右反向驱动由负目标速度实现，不能用负功率充当反向驱动。转向电机失效、无玩家输入、接线失效时显式发送零控制，不能保留最后一帧电门。

### 9.4 适配范围

首个双流样例限定发动机／可分离变速箱／主传动，加一个电机／转向传动，驱动左右两条履带。四履带、单源可变比机械双流、严格双自由度反馈重建不是首个样例的完成条件；图与对象来源接口应能表达其接线，不预建专用类型。

## 12. 验收矩阵与运行命令

### 12.1 自动化验收

测试应直接调用生产解析／索引／控制计算，不能复制一份算法后只测试复制品。纯图和预算使用轻量对象替身；连接器解析与安装生命周期至少有真实构造或 GameTest 覆盖。测试类不得放入 Mixin 独占包。

浮点预算比较使用绝对加相对容差，例如 `εP = 1e-3 W + 1e-4 × abs(P_in)`；报告采用的具体容差。节点注册顺序变换后的数值结果允许在相同容差内一致，身份、执行次数、有效性及控制路由则必须完全一致。

| 编号 | 场景与判据 |
| --- | --- |
| T01 | 两个不同 producer 均名为 motor：同一 TrackDrive 收到两项，反馈分别回到正确实例。 |
| T02 | 两级连接器转发：来源对象保持 `==`；Gearbox 输出时来源是 Gearbox 自身。 |
| T03 | 结构重建／无本步输出：上一物理步功率不残留。 |
| T04 | 同一 SubPart 本地目标与跨部件多跳目标：图终点与实际接收对象相同；另一 SubPart 的同名对象不能被装配体级按名查找误选。 |
| T05 | 端口互绕、三端口循环、缺目标、类型错误：有限步终止，输出定位诊断。 |
| T06 | 一源分流、两源汇合：正反向索引一致，遍历不遗漏源或末端。 |
| T07 | 同一 producer 两个槽接到同一 consumer：不覆盖、不重复计功，明确隔离。 |
| T08 | 单输入消费者接两源：诊断，不能由最后到达消息决定输出。 |
| T09 | 功率环与独立合法支路并存：合法分量运行，含环分量不递归。 |
| T10 | 接到其他控制器管理的对象：不跨域运行。 |
| T11 | hasFeedbackSpeed 默认 false；实际消费者采样到 0 后返回 true，connected=true 时收集结果含该项；样本无效或 connected=false 则无该项，只有无资格才走源的空载路径；端口转发有效性，两个图钩子不重复触达终端。 |
| T12 | 发动机→变速箱→传动→失效末端：无反馈资格逐级传播，不伪造零速负载。 |
| T13 | 离合断开、接合、换挡：结构不重建；反馈按当前状态和挡位折算。 |
| T14 | 零功率但末端滑行：机械反馈有效，停止供能不会被误当断开。 |
| T15 | 随机节点注册顺序、多级链、两个输入先后交换：相同输入得到相同本步输出，无随链深增加的隐含步延迟；统一清槽发生在第一次交付前，清槽不破坏反馈；分别计数通用回调、清槽、资格刷新和机械求值。非动力 Pre 位于 Pre-3 与 Physics 之间，步中外部信号留待下一步。冷启动／滑行接合不互等，有资格无样本时源不强制电门为 0。 |
| T16 | 两台变速箱连接不同转速曲线的源：改变 A 支路状态不改变 B 的挡位评估。 |
| T17 | 图可达但不在控制握手范围：不发控制命令。 |
| T18 | 主线程准备图时物理线程连续运行：只观察完整版本，图与驾驶绑定版本一致；构建不读 native 物理态。物理线程取到 A 后主线程发布 B，A 安装后下一步必须安装 B；候选不可变、内层集合不可被调用方改写。 |
| T19 | 拆分／合并：对象只被一个控制器每步执行一次；失效图不继续驱动。 |
| T20 | 初始化失败／销毁／资源重建：已读取但未安装的失效候选不能挂入对象；主线程只置失效标志及清 pending，物理终止任务清 appliedCandidate、运行视图、claim、绑定和缓存；各引用可释放，主线程不改物理私有集合。 |
| T21 | JointDriver 使用本步功率分配；单输入不活跃时没有遗留轴功率。 |
| T22 | 两个驾驶控制器竞争同源／箱／执行器：首个冲突步即抑制，交换遍历顺序结果一致，全部认领先于第一次信号写入；前步自动电门清理，其他发送者的手动输入和无冲突支路保留；冲突解除后正常控制。 |
| T23 | 两路 (1000,100) 合成：预算 2000、速度 200、扭矩 10；反向等价场景方向正确。 |
| T24 | 多输出预算和 ≤ 输入预算，包含差速锁速度偏置、负比值和断开一侧；开放／锁定分配的负比值均只翻转 speed，正驱动 P 保持为正且进入反向驱动分支。 |
| T25 | 同向 n 路、分流再汇合：端点预算无 n² 放大；逐个中间节点同样满足约束。 |
| T26 | 静止接合、P>0 且 ω 近零、正负速度抵消、P 正负混合：无 NaN／Infinity，扭矩有界，匹配净预算规则；Transmission 近零速不会推 EMPTY，末端有真实零反馈。 |
| T27 | Engine／Motor／Gearbox／Transmission 各自覆盖 EMPTY、(0,0)、(0,非零ω)、非法非有限载荷；开放差速 P=0 保留有效速度，静止接合的 ZERO 与无资格 EMPTY 不混同。 |
| T28 | 裸 Bullet 静止起步、两侧负载差、单轮悬空、堵转：记录实际速度与预算，不能仅验证输出字段。 |

## 13. 审阅重点与执行约束

| 审阅项 | 本稿推荐 | 影响 |
| --- | --- | --- |
| R1 来源身份 | producer 对象；同一对象到同一 consumer 的独立多端口暂不支持。 | 接口最小，真实端口需求出现时再扩展。 |

## 14. 完成判据

动力图里程碑完成须同时满足：对象来源全链一致、接线查询与实际投递同源、动态资格不混同零反馈、独立支路控制、每步更新确定、生命周期不残留引用或功率、既有轮式／摩托车／单流回归通过。
