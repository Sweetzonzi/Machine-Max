# 部件精确准星拾取与渲染包围盒设计

**状态**：计划中；本文提出的拾取器、共享视线查询与完整结果发布、主动轮履带剔除范围尚未实现。

**目标**：部件实体保留完整 AABB 和 `isPickable() == true`；原版准星及使用 ProjectileUtil 的投射物只在射线命中部件的有效碰撞形状时选中部件。射线经过部件 AABB 的空白区域时，可以选择后方方块或普通实体。普通部件使用完整刚体 AABB 做渲染剔除，履带主动轮额外合并整条履带的 AABB。

本文相对路径以 Machine-Max 仓库根为基准；`../Spark-Core/`、`../Libbulletjme/` 为同级源码仓库。Minecraft 源码坐标中的 `jar!/路径#符号` 指向开发环境生成的 sources jar 内对应文件。

## 1. 职责与行为契约

| 对象 | 用途 | 本方案的约束 |
| --- | --- | --- |
| 实体 `getBoundingBox()` | 实体空间查询、原版交互距离校验等 | 使用部件刚体的完整世界 AABB，不乘 0.7 |
| 部件拾取几何 | 准星是否真正命中部件 | 使用有效 HitBox 的物理形状，排除轮胎辅助球体 |
| `getBoundingBoxForCulling()` | 视锥剔除 | 普通部件取完整刚体 AABB；履带主动轮合并整条履带 AABB，接受动画外伸造成的边缘剔除 |
| `isPickable()` | 实体是否允许被选中 | 返回 `true`，近战、原版实体右键和中键入口继续可达 |
| Bullet 碰撞体 | 实际物理接触 | 拾取过程只查询，不修改形状、碰撞组、位姿或约束 |

最近目标规则：在 ProjectileUtil 的每候选求交位置，普通实体提供原版 AABB 命中点，部件提供有效形状命中点；原版循环比较距离、选出优胜实体，再由 GameRenderer 与方块比较。方块在前时阻挡部件；部件在前时可以攻击或交互；部件形状之间的空隙允许射线通过。

这里的“精确”指部件碰撞形状，而非模型三角形或贴图透明度。没有建成 HitBox 空隙的模型开口，不承诺可穿透。独立的座椅 InteractBox、连接器触发区不作为原版近战的部件表面。

## 3. 注入位置：ProjectileUtil 的每候选求交

拟新增共通 `ProjectileUtilMixin`，登记到 `src/main/resources/machine_max.mixins.json` 的 `mixins` 数组。共享查询与过滤逻辑位于共通包，由 Eyesight 和 Mixin 共同调用；该层不得引用客户端类。

Minecraft 1.21.1 有三个 `getEntityHitResult` 重载，其中两条执行候选循环，一条负责转调。两条循环共用部件精确求交，按完整签名分别定位注入点：

| 签名 | 用途与接入范围 |
| --- | --- |
| `(Entity, Vec3, Vec3, AABB, Predicate, double)` | GameRenderer 等使用；包装候选的 clip 与 contains，原版负责最大平方距离与乘客规则 |
| `(Level, Entity, Vec3, Vec3, AABB, Predicate)` | 以默认膨胀量 0.3 转调下一条；通过转调自动获得精确部件判定，无需重复注入 |
| `(Level, Entity, Vec3, Vec3, AABB, Predicate, float)` | 箭矢、抛射物等使用；包装候选 clip，并修正最终普通 EntityHitResult 的部件命中位置 |

double 重载的原版循环结构为：

```java
for (Entity candidate : level.getEntities(source, searchBox, predicate)) {
    AABB box = candidate.getBoundingBox().inflate(candidate.getPickRadius());
    Optional<Vec3> point = box.clip(from, to);
    if (box.contains(from)) {
        // AABB 内部起点的距离 0 快捷分支
    } else if (point.isPresent()) {
        // 按 point 的距离与当前最佳候选比较，并处理乘客排除
    }
}
```

double 重载使用两处 `@WrapOperation`，并捕获当前 `candidate`：

1. 包装 `AABB.clip(Vec3, Vec3)`：普通实体调用 `original.call`；MMPartEntity 调用共享查询，返回本部件最近有效形状的真实命中点，未命中返回 `Optional.empty()`。
2. 包装 `AABB.contains(Vec3)`：普通实体调用 `original.call`；MMPartEntity 返回 false，禁用“位于整个部件 AABB 内就强制距离 0”的快捷路径。部件内部起点的几何语义见 §4.4。

候选枚举、原版谓词、距离比较与乘客规则保留在原版循环中。部件 A 未命中时循环会检查后面的部件 B 与普通实体；不需要事后重跑普通实体查询或另写候选合并器。距离完全相等时采用该重载自身的遍历与比较语义；最终部件结果的命中位置见下段约定。

float 重载使用同一个 clip 包装函数；它没有 contains 快捷分支。普通实体继续使用该重载传入的 AABB 膨胀量。部件以有效 HitBox 的真实表面为准，不把 0.3 等 AABB 宽容量加在部件外面；因此擦过部件包围盒的空白区域应当穿过。若某类投射物需要有限半径扫掠，必须显式提供半径和形状扫掠语义，不能把 AABB 膨胀参数当成精确射线的半径。

float 重载原版通过命中点选目标，但返回的是 `new EntityHitResult(entity)`，结果位置是实体位置，并非实际表面。对最终优胜的部件，使用已有构造器 `new EntityHitResult(entity, precisePoint)` 返回真实命中点。两个重载均保留原版方法签名与普通 EntityHitResult 返回类型；HitBox、法线等伤害几何不附着到该返回值，也不在候选循环中改写投射物伤害状态。

共享解析方法返回 §4.0.1 定义的有序 `List<RayHit>`，其中部件、连接器、交互区等使用各自的结果类型。ProjectileUtil 适配层只消费 SubPartRayHit 的部件目标与命中点；Eyesight 和 PartHitHandler 按各自调用需要消费对应类型。§5.1 定义 PartHitHandler 在实际命中时调用该方法的流程。

共享查询结果由 MixinExtras `@Share` 保存在本次调用上下文中：遇到第一个需要查询的部件时执行一次当前射线查询，按 SubPart 索引最近有效命中，其余候选只查表。不能每遍历一个部件就再次向整个物理空间发射同一条射线。该上下文不放在静态可变字段里；重入、客户端和服务端调用各自隔离。

候选局部变量可通过 `@Local` 捕获，局部选择器应以实际目标字节码核对，不能凭反编译变量名猜 ordinal。该能力的参数约定见 [MixinExtras Local 官方说明](https://github.com/LlamaLad7/MixinExtras/wiki/Local)。若局部捕获过于脆弱，可在 `Entity.getBoundingBox` 包装器中从 receiver 取得候选，并经本次 `@Share` 上下文传递。

方块 OUTLINE 查询、实体/方块交互距离过滤，以及 `Minecraft.hitResult` 与 `Minecraft.crosshairPickEntity` 发布继续由 GameRenderer 完成。这里不覆盖整个方法。`@WrapOperation` 的普通实体分支通过 `original.call` 保留包装链，具体约定见 [MixinExtras 官方说明](https://github.com/LlamaLad7/MixinExtras/wiki/WrapOperation)。

## 4. 部件窄相查询

### 4.0 与 Eyesight 共用算法和发布设施

几何判定复用 `src/main/java/io/github/sweetzonzi/machine_max/common/attachment/LivingEntityEyesightAttachment.java#onTick` 中识别 SubPart、跳过 wheel 辅助球体、跳过未激活 HitBox 的规则。Eyesight 对指定碰撞组与观察者自身的排除属于其调用方策略。公共解析核心由 Attachment、原版实体求交适配层和 PartHitHandler 共同使用，不各自维护一套部件过滤规则或子形状索引注册表。

需要区分两种消费方式：

- **共用已发布结果**：物理线程执行 Eyesight 查询并发布一份完整结果，准星直接消费；采用 tick 级射线输入，沿用 Eyesight 的更新时间。这个方案不需要另一轮逐帧物理查询，但转头时的实体确认可能等待下一次 Eyesight 结果。
- **共用查询方法**：准星用本帧起终点，在只读物理快照上调用相同规则；保留本帧转头响应。§4.1 描述这种调用方式。当前帧规则需要的激活值与形状映射从共享发布设施获得。

两个模式的差别是射线输入的时效性，不是是否使用同一套判据。完整发布问题应先在 Eyesight 内解决，§4.2 的数据由该设施提供，不建立第二套独立全局快照系统。

后置否决有明确适用边界：在私有 `GameRenderer.pick` 比较方块前，将无效的最终实体结果置为 `null`，可以回到其已保留的方块结果；在整个 pick 返回后直接设 MISS 则会丢掉方块。仅否决最终优胜实体也不会自动找回被其 AABB 抢先选取机会的其他实体。§3 把否决和命中点替换放在原版候选循环内部，由原版继续比较后续候选，解决这两个问题。

### 4.0.1 公用算法的输入、输出与调用方式

公用核心命名为拟议的 `RayHitResolver.resolve`。它接收已经执行完的物理射线结果，负责按 owner 解析成不同命中类型、进行部件有效性过滤，并准备该类型需要的数据；射线发射由调用方选择实际世界或只读快照。公共 RayHit 只约定距离排序所需的 fraction，不要求所有结果拥有 owner、HitBox、命中点或法线。以下均为接口设计，不是当前源码中已存在的类型：

```java
public static List<RayHit> resolve(
        List<PhysicsRayTestResult> rawHits,
        Vec3 from,
        Vec3 to,
        RayHitReadView view);

public interface RayHit {
    double fraction();
}

public record SubPartRayHit(
        double fraction,
        SubPart subPart,
        HitBox hitBox,
        Vec3 point,
        Vec3 normal) implements RayHit {}

public record ConnectorRayHit(
        double fraction,
        AbstractConnector connector) implements RayHit {}

public record InteractBoxRayHit(
        double fraction,
        InteractBox interactBox,
        boolean enabledAtQuery) implements RayHit {}

public record TerrainRayHit(
        double fraction,
        PhysicsChunkSection section,
        Vec3 point,
        Vec3 normal) implements RayHit {}

public record EntityRayHit(
        double fraction,
        Entity entity,
        Vec3 point) implements RayHit {}

public record OtherRayHit(
        double fraction,
        PhysicsHost owner) implements RayHit {}

public interface RayHitReadView {
    @Nullable PhysicsHost ownerOf(PhysicsCollisionObject object);
    @Nullable SubPartShapeState subPartShape(
            PhysicsCollisionObject object, int childIndex);
    @Nullable InteractBoxShapeState interactBoxShape(
            PhysicsCollisionObject object, int childIndex);
}

public record SubPartShapeState(
        HitBox hitBox,
        boolean active,
        boolean auxiliaryWheelSurface) {}

public record InteractBoxShapeState(
        InteractBox interactBox,
        boolean enabledAtQuery) {}
```

这些类型使用接口加 record 实现，没有共享字段的抽象基类。SubPartRayHit 的 subPart、hitBox、point、normal 由构造入口保证非空；ConnectorRayHit 不具有 HitBox 字段，也不为没有用途的法线分配占位值。InteractBoxRayHit 直接指向从 InteractBoxes 子形状解析出的单个 InteractBox，enabledAtQuery 是本次查询的状态值，交互模式仍由 Eyesight 的策略处理。

`rawHits` 不包含完整射线起终点，只有沿本次射线的命中比例，所以 `from/to` 必须和这份列表来自同一次 rayTest。需要命中位置的类型使用 `point = from + (to - from) * fraction`；需要法线的类型将引擎结果中的世界空间法线复制成不可变 Vec3。其他类型无需为它们增加字段。结果中的领域对象是身份引用，不代表其指向对象的全部状态被冻结。

`view` 是显式的线程读取边界，只读取 owner 和各类型自己的映射/状态，不做射线、不决定最终交互目标。物理线程使用可合法读取本体状态的实现，主线程使用 §4.2 的同代只读元数据实现。SubPart 的映射只返回 SubPartShapeState，InteractBoxes 的映射只返回 InteractBoxShapeState，不能用一份带可空 HitBox 的通用状态承载二者。映射无效返回 null，该条命中不进入输出。

子形状映射来源为 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/SubPart.java#getHitBox` 与 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/interact/InteractBoxes.java#getInteractBox` 所对应的形状索引关系；view 必须校验索引，不能使用这两个现有方法在异常时回退到首个元素的行为。ConnectorRayHit 只表示物理射线直接命中 AbstractConnector；“先命中 SubPart，再从其连接器中挑最近可用者”属于 Eyesight 后续策略，不在解析器中伪造成直接连接器命中。

算法固定为以下步骤：

1. 检查起终点有限；零长度射线返回空列表。逐条检查 fraction 有限且在 `[0, 1]`。
2. 通过 view 取得 owner；没有 owner 时跳过。
3. 按 owner 分派：SubPart 经有效的 SubPartShapeState 过滤激活状态与辅助球体后生成 SubPartRayHit；AbstractConnector 生成 ConnectorRayHit；InteractBoxes 经子形状映射生成 InteractBoxRayHit；PhysicsChunkSection 生成 TerrainRayHit；Entity 生成 EntityRayHit；其他有 owner 的命中生成 OtherRayHit，避免静默丢掉未知目标。
4. 各分支只准备自身类型需要的数据；需要的几何数值非有限时跳过。SubPart 无效形状直接跳过，不能转成 OtherRayHit 绕过过滤。
5. 按 fraction 升序排序，返回不可变列表。输入列表不修改；同一刚体的多个有效子形状均保留，不在这里按刚体去重。

没有有效结果时返回空列表，不返回 null。公共结果接口不提供通用 hitBox() 或 owner()；消费方先按具体结果类型判断，再读取该类型的字段。核心不应用观察者自身排除、Eyesight 的 PROJECTILE 碰撞组排除、实体交互距离、原版 canHitEntity/乘客规则，也不写投射物字段或触发伤害；这些属于调用方策略。碰撞组等底层筛选若依赖真实碰撞对象，应由调用方在合法线程上、进入解析器前完成，不能为此给每种结果强加 native 对象字段。

三个调用方的消费方式为：

| 调用方 | 执行 rayTest 的位置 | 如何消费 resolve 的输出 |
| --- | --- | --- |
| LivingEntityEyesightAttachment | 物理线程真实世界 | 在合法线程完成自身、忽略碰撞组等策略；分别消费 SubPartRayHit、ConnectorRayHit、InteractBoxRayHit、TerrainRayHit、EntityRayHit 与 OtherRayHit，保留各类型的遮挡/选择语义，再整体发布 |
| ProjectileUtilMixin | 当前方法调用中，只读物理快照 | 首次遇到部件候选时查询、解析一次；筛出 SubPartRayHit，以 `putIfAbsent(hit.subPart(), hit)` 建最近命中索引。每个候选只查自己的 SubPart 并返回 point，原版继续做实体间比较 |
| PartHitHandler | 实际命中事件中的只读物理快照 | 沿用该次候选查询的起终点与谓词，解析结果后筛出仍符合谓词的 SubPartRayHit，再取最近者；与事件目标一致才消费其非空 HitBox、point、normal。不能越过仍有效的前方部件，但应跳过原版已明确排除的实体 |

例如输入顺序为“未激活形状 A@0.1、部件 B@0.3、地形@0.5、部件 B 的另一形状@0.7”，输出为 SubPartRayHit(B@0.3)、TerrainRayHit(@0.5)、SubPartRayHit(B@0.7)。Eyesight 可以识别地形类型，Mixin 给 B 建索引时保留 0.3，Handler 的最近部件也是 B@0.3。保留所有有效命中使三者可以共用解析核心，而不把它们的目标选择策略混在一起。

输入列表并不自动提供线程安全：resolve 需要稳定的列表与合法的 view 读取视图。跨线程传递时发布输出及对应射线输入的完整不可变快照；不向主线程公开正在填充的引擎结果列表。列表可以直接按 `RayHit::fraction` 排序；所有结果无需为了集合或排序而拥有一致的其他字段。

### 4.1 查询来源与时间口径

ProjectileUtil 适配层使用方法参数或 source.level() 对应 Level 的 `worldSnapshot.rayTestDp(from, to, reusableResults)`。起终点从 Minecraft `Vec3` 直接转为 `Vec3d`，中途不转成世界坐标 `Vector3f`。Eyesight 则在物理线程向真实世界发射自己的射线，再使用同一个 resolve 核心。

实体求交适配层在客户端准星和双端投射物的主线程调用中消费只读快照，复用结果容器。主线程不得向正在步进的真实物理世界查询，也不得为了对齐画面临时移动快照刚体。结果中的命中比例仍为 float；世界命中点使用原版 double 起终点重建：`from + (to - from) * fraction`。

首期采用“最新完整物理快照”的时间口径。画面的位置插值由 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/DestroyableObject.java#getWorldPositionMatrix` 完成，因此高速平移、快速旋转时，快照表面与当前插值画面可能有一个 tick 量级的偏移。首期不声称逐帧贴合可见模型。若实机验收不能接受该偏移，单列插值拾取工作：使用独立查询对象或单形状只读查询，按同一 `partialTick` 变换射线；禁止修改共享 `WorldSnapshot` 位姿。

射线起点和方向使用被包装调用的参数，遵循原版相机实体眼睛的口径；不改用第三人称相机的后移位置，也不重定向炮镜或武器瞄准系统。

### 4.2 同一代元数据

`src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/interact/HitBox.java#active` 是由同文件 `#updateActive` 在物理线程更新的普通字段，不能在每帧查询中直接读取它并假定与快照一致。共享 Eyesight 发布设施需要提供同一代的只读数据；若准星采用 §4.0 的本帧查询模式，在 `PhysicsSnapshotReadyEvent` 中，于真实物理线程唤醒前发布该模式需要的元数据，包含：

- Level 与快照步号；部件对应的实体身份、SubPart 身份与形状代次。
- 子形状索引到 HitBox 的映射。
- 每个子形状是否可拾取：本代的激活值，以及是否为轮胎辅助球体。

本帧查询模式按 Level 消费共享设施最近一份完整元数据；共用结果模式按观察者消费一份 Eyesight 射线结果。记录中的实体在使用前再次检查存活、Level 与 `entity.subPart` 绑定关系。部件重建、变体切换、实体移除、维度卸载和断线时使相应记录失效。

Eyesight 当前的查询调度与缓存发布需要分开审视。`onTick` 将真实世界射线送入 `PPhase.PRE`，这一调度避免在主线程直接查询真实物理世界；但 `targetBodyCache` 是普通 HashMap，由物理线程清空和写入、由主线程 getter 消费。`sortedTargetBodyCache` 等 CopyOnWriteArraySet 的 `clear` 与 `addAll` 也分为两次发布，不构成跨集合的完整结果替换。`getHitPoint` 又组合共享的 `startPos`、`view` 与传入结果的比例，不能保证它们来自同一条射线。

修正方式是：提交任务时捕获本次不可变射线输入；物理线程在局部容器中完成查询、过滤、排序和命中点计算；最后通过单个 volatile 引用一次发布不可变结果。消费方每次操作只读一次该引用，不跨集合拼接结果。对同一刚体的多个命中保留最近有效值，不能让按升序遍历时后面的 `put` 覆盖较近命中。共享结果中保留世界命中点、目标身份、输入射线与采样序号，使读方无需重新读取真实刚体来恢复命中信息。

索引构造在物理空闲阶段读取形状，不在渲染调用里 `listChildren()` 或调用会读取真实刚体的懒初始化。普通帧不重新解析模型或建立 native 对象。

### 4.3 每条命中的有效性

§4.0.1 定义公共解析器的规则；本节补齐 ProjectileUtil 部件候选的适配条件，任一失败就令该候选返回 Optional.empty：

1. 候选是仍存活、位于当前 Level 且绑定关系吻合的 MMPartEntity；resolve 保留的其他 owner 不在此转换为部件实体。
2. 当前读取视图与形状代次有效，并且索引中有该 SubPart 的命中。
3. 实体通过原版谓词；§3 的原版循环继续处理 root vehicle 与 `canRiderInteract()` 的乘客排除规则。不在共享物理查询中笼统排除整辆载具，以免车内可用部件失去选择入口。
4. 子形状映射在 resolve 的读取视图中解析，禁止使用 `SubPart.getHitBox` 的“索引异常取首个 HitBox”兜底。wheel 的一般判定圆柱保留；辅助球体与圆柱的来源见 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/attr/SubPartAttr.java#getCollisionShape`。
5. 世界命中点有限，并符合该重载的射线和距离条件；原版循环仍执行自己的距离比较。

结果为空、实体刚出生尚无快照、索引代次不匹配时，本次不生成部件命中；不退回整块 AABB 精选。这样缺失精确数据不会使空间中的空白区域成为阻挡。

引擎查询是否覆盖同一 compound 的多个子形状，要由本机 native 回归钉住。源码中 `../Libbulletjme/src/main/native/glue/com_jme3_bullet_CollisionSpace.cpp#JmeRayResultCallback` 返回 1，且 compound 遍历会逐子形状回调，依据是 `../Libbulletjme/src/main/native/bullet3/BulletCollision/CollisionDispatch/btCollisionWorld.cpp#rayTestSingleInternal`。不能仅凭“忽略第一条命中”就假设后面的有效子形状必然已返回；若实际 native 回归不成立，必须补子形状查询后才能接入。

### 4.4 距离、内部起点与原版边界

包装器仅替换部件候选的求交点，不提前按玩家实体交互距离删掉部件。私有 `GameRenderer.pick` 的最后一层过滤保持原版语义：实体在实体交互距离之外、但位于方块之前时，结果可能是 MISS，不自动改选后方方块。

部件不使用 `AABB.contains(eye)` 制造零距离命中，也不把原版 `getPickRadius()` 膨胀量套在部件形状上。眼睛位于大 AABB 内但处于各实际形状之间的空隙时，射线仍应正常选择面前目标。

眼睛确实位于某个实心形状内部时，采用 Bullet 正向射线的内部起点语义；必须对 box、cylinder、capsule、sphere 实测并记录结果，不能用整个部件 AABB 代替形状内外判定。这一情况与“位于驾驶舱空隙”分开验收。

## 5. 近战与原版交互的接续

优胜部件生成 `EntityHitResult(partEntity, preciseWorldHitPoint)`。外层公共 `GameRenderer.pick` 统一写入 `Minecraft.hitResult` 与 `Minecraft.crosshairPickEntity`。不只写其中一个字段。

攻击、命名牌、履带物品和中键继续走原版实体入口；独立的 `LivingEntityEyesightAttachment` 上车/工具选择保持其用途。原版实体右键管线见 [NeoForge 1.21.1 文档](https://docs.neoforged.net/docs/1.21.1/items/interactionpipeline/)。在实体 `interact()` 返回 PASS 不是重新射线选择方块的机制，穿透必须在 pick 阶段决定。

服务端继续接收原版 `ServerboundInteractPacket`，客户端精确命中不直接作为服务端伤害权威，不新增“客户端指定 HitBox”的伤害包。`MMPartEntity.hurt` 的服务端物理射线与 BFDamageContext 管线继续承担伤害定位。

### 5.1 投射物接续与单次分发

统一接入涵盖 Minecraft 源码中的三条入口（均位于 §2 所述 sources jar）：`net/minecraft/world/entity/projectile/AbstractArrow.java#findHitEntity` 转调 Level 重载，`net/minecraft/world/entity/projectile/ThrowableProjectile.java#tick` 与 `net/minecraft/world/entity/projectile/AbstractHurtingProjectile.java#tick` 使用 `ProjectileUtil.getHitResultOnMoveVector`，由其内部进入 float 重载。距离排序、方块截短后的射线段、`canHitEntity` 谓词与箭矢穿透忽略列表由这些原版调用链继续提供。

本文“穿透箭”专指原版弩的 Piercing（穿透）附魔产生的箭矢多实体命中：等级 I–IV，成功命中的实体数上限为等级加一。它不是 Machine-Max 的装甲穿深或 RHA 判定，也不是普通箭、雪球等所有投射物默认具有的能力。官方行为说明见 [Minecraft 1.14 Java 发布说明的 Piercing 小节](https://feedback.minecraft.net/hc/en-us/articles/360027306551-Minecraft-Village-Pillage-1-14-0-Java)。1.21.1 的具体代码依据为同一 sources jar 内 `net/minecraft/world/entity/projectile/AbstractArrow.java#getPierceLevel`、`#onHitEntity` 与 `#canHitEntity`：命中过的实体 ID 加入忽略集合，后续查询通过谓词跳过它们。

`src/main/java/io/github/sweetzonzi/machine_max/common/entity/MMPartEntity.java#hurt` 的投射物分支依赖 `IProjectileMixin` 中的命中点、法线、HitBox 和 SubPart。由 `src/main/java/io/github/sweetzonzi/machine_max/common/entity/PartHitHandler.java#onProjectileHit` 在实际命中时调用与 Eyesight、ProjectileUtil 共用的射线方法，取得这些完整数据，再按现有 IProjectileMixin 通道交给伤害管线。完整数据无需经过 getEntityHitResult 的返回值传递。

具体流程为：从事件取出目标 MMPartEntity；取得本次原版候选查询的输入；用相同起终点调用共享射线方法；在解析结果中应用该次查询的实体谓词，再确认最近有效部件与事件目标一致；将复核得到的命中点、法线、HitBox 与 SubPart 一起写入既有通道。复核不命中或目标不一致时按现有事件机制拒绝本次部件命中，不把伤害转交给另一个目标。不能借用观察者 Eyesight 的射线输入，也不能自行延长射线后忽略原版过滤条件。

为独立复核保留的只是 `RayQueryContext(from, to, predicate, queryId)`，不包含完整伤害几何。ProjectileUtil 的返回类型保持普通 EntityHitResult；返回部件命中时，在投射物侧以返回结果实例的身份关联这份输入上下文，Handler 按事件中的结果实例读取。该关联必须支持同 tick 多次查询，以查询身份而非仅投射物身份或 tick 区分，使用后及 tick 结束时清理，避免串用或长期持有谓词引用。

例如箭矢先成功命中仍存活的 A，原版将 A 加入忽略集合，再沿同一运动段选中 B；Handler 对 B 复核时必须应用该次谓词并跳过 A。未经谓词筛选就取原始列表中的第一块部件会错误否决 B。这个过滤属于调用方目标选择策略，公共 RayHitResolver 继续只解析和过滤物理形状。

这里共用的是几何与过滤算法，不要求三个调用方共享同一个结果对象。实际命中事件允许执行一次独立复核，完整伤害数据来自这次复核；不建立跨查询的完整几何搬运协议。命中通道中的数据应以本次分发为作用域，不能让取消、偏转或下一次查询沿用上次命中的字段。

同文件 `#onProjectileTick` 当前会逐 Projectile 额外发射射线，并调用 `machine_Max$manualProjectileHit`。统一后的原版路径必须以自身的命中分发为唯一触发，不能同时由这条补充路径再次触发。实现时先记录每个投射物 tick 是否进入过统一求交：Pre 只捕获运动段起点并建立本 tick 身份，候选查询标记本 tick 已覆盖，Post 对已覆盖或已移除的投射物不执行补充命中。对完全绕过 ProjectileUtil 的第三方投射物，兼容补充查询使用本 tick 实际运动段，并至少通过相同的部件形状过滤与方块遮挡约束；如其自身已有伤害回调，也必须复用该回调而非再施加一次伤害。

上述覆盖标记必须绑定投射物身份与 tick，不是跨调用的“上一次用了什么”的全局变量。箭矢穿透循环中的每一次查询拥有独立命中结果，以原版忽略列表筛选后续实体；共享射线方法只返回数据，不自行发伤害或消耗投射物。兼容入口的范围由调用链核对与测试确定，不因其类继承 Projectile 就无条件手动调用 onHit。PartHitHandler 的兼容补充查询也调用相同的共享射线方法。

必须验收一个已有边界：`MMPartEntity.hurt` 对生物来源用固定 5 格射线，且可能把伤害交给射线命中的其他 SubPart；原版攻击包只带目标实体，没有本次客户端 HitBox 信息。若精确拾取的测试暴露“选中 A、伤害到 B”或交互距离属性下的漏伤，应在玩家近战分支做针对性修正：使用玩家交互距离与原版服务端容差，校验服务端真实命中与被攻击实体一致，再进入既有伤害管线。不得让不一致的目标静默重定向伤害；也不把该修正扩散到爆炸、投射物和非玩家生物伤害。

## 6. 完整 AABB 与渲染剔除

`MMPartEntity.makeBoundingBox` 返回现有完整刚体盒，去掉 0.7 系数。`blocksBuilding = false` 与原版实体碰撞配置保持各自职责；不通过拾取代码改变物理接触或方块放置占位规则。

`PartEntityRenderer.shouldRender` 从 `getBoundingBoxForCulling()` 取盒，规则为：

```text
普通部件：完整刚体 AABB
履带主动轮：完整刚体 AABB ∪ 所属整条履带 AABB
```

这里的“静态 AABB”指几何范围按部件完整刚体盒确定；世界位置和刚体旋转变化时正常更新世界 AABB。骨骼动画、悬挂模型偏移、出生效果的 1.3 倍缩放，以及渲染插值中间姿态超出该盒而造成的边缘剔除均可接受。本期不建立逐骨骼边界缓存、动画全程包络或旋转扫掠包围球。

主动轮的特殊处理依据是 `src/main/java/io/github/sweetzonzi/machine_max/client/render/renderer/TrackRenderer.java#renderTrack`：只有主动轮实体绘制整条履带。履带 AABB 覆盖完整轮组包络，计入履带厚度、宽度和型号单节几何的静态外伸；随轮组刚体姿态更新，创建、断带、解散、型号资源重载和主动轮变更时刷新或失效。范围计算及缓存限于履带路径，不建立通用 PartRenderBounds 系统。普通成员轮使用自己的完整刚体盒。

该合并只影响主动轮的 getBoundingBoxForCulling，不扩大其 getBoundingBox 或射线交互形状。无需为了履带链节相位逐节重建模型边界；缓存可使用包住整条履带的保守 AABB。

本次先保持远近渲染分派的既有距离规则。`src/main/java/io/github/sweetzonzi/machine_max/client/render/renderer/DistantVehicleRenderer.java#render` 自有远近阈值，不能只修改近处渲染器的距离门而制造两条管线的空档或重复；距离分派的重构单列后续工作。视锥验收在近处实体管线负责的距离内进行，并另测交接边缘。

| 原版投射物与普通实体，其他模组包装同一查询点 | 两条执行求交的重载均接入；普通实体原操作与 `original.call` 包装链继续执行 |
| 箭矢、三叉戟、抛射物高速穿过部件间隙；部件表面命中 | 间隙可穿透；表面只触发一次原版命中，伤害使用的 HitBox、法线与命中点均来自 Handler 的同次复核 |
| 原版穿透附魔箭依次命中两个仍存活的部件 A、B | B 的 Handler 复核沿用其查询谓词，跳过已在原版忽略列表中的 A；两个目标各结算一次 |
| 事件取消、偏转、同 tick 多次查询 | 原版返回结果与其输入上下文逐次对应；没有补充命中重放或上次伤害几何残留 |
| 射线擦过 float 重载膨胀 AABB，但没有碰到部件形状 | 部件不因 AABB 宽容量被误命中；普通实体维持该调用的膨胀规则 |
| 第三方投射物未走 ProjectileUtil，或有自定义命中回调 | 兼容路径按实际运动段和遮挡判定；同一次碰撞只有一条伤害分发 |

自动化分两层：纯逻辑测激活/身份过滤、命中点、边界与元数据失效；裸 Bullet 测 compound 子形状、wheel 与双精度射线。接线测试必须覆盖“空 AABB 后方普通实体”“AABB 内起点但没有形状命中”“实际表面远近与 AABB 远近相反”“一次方法调用有多个部件候选但只执行一次物理射线”，并确认两个执行循环的重载均已接入、委托重载没有重复查询。投射物 GameTest 验证命中次数、伤害次数、遮挡、穿透与取消；客户端 runClient 验证准星注入及视锥、Iris 阴影与多人交互。测试不放 Mixin 独占包；服务端 GameTest 不能代替客户端 pick 接线验收。

所有 Gradle 命令使用 `gradlew --offline`。本次是方案文档，未实施上述阶段，也未以文档审查代替运行验收。
