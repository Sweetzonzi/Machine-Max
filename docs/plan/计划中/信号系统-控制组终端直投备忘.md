# 信号系统-控制组终端直投备忘

> 状态：计划中，未细化。本文只记录一条待细化的设计方向，不是实现计划。

## 1. 背景

座位对武器的可达性由控制组的「频道 → 目标名」声明决定。名字是内容包写的约定名，粒度是"这类设备"，不是"这一台"：同一频道上有两台控制器时（两座炮塔各一门炮），名字解析把它们都收进首跳表，控制组只能一起控制。

内容包作者无法把声明下到实例：零件不知道自己所在的装配体里还有哪些控制器，能写的只有频道名和本零件内的名字。而运行期其实分辨得出来——`AbstractControllableSubsystem#weaponControllersByGroup` 已经按组给出实例列表。缺的是"声明"这一层，不是"识别"这一层。

## 2. 提案

`ControlGroup` 增加一个默认为空的字段（暂名 `terminal_targets`），按频道声明一份终端列表：

```json
"terminal_targets": {
  "crew_gunner_aim": ["<part uuid>/machine_max:main_weapon"]
}
```

- 终端身份 = `(part UUID, 子系统名)`。它直接指向信号终端消费者（子系统），不需要频道名之外的中介。
- [Part 级名字解析](信号系统-Part级名字解析与子系统封装.md) 落地后，身份里不再需要子零件名；该计划之前则要带子零件名，因此本备忘排在其后。
- 空表 = 不改变现有行为。
- 投递走已有的实例重载 `ISignalSender#sendSignalToTarget(channel, ISignalReceiver, value)`，不新增传输机制。

## 3. 语义待定（核心未决）

- **追加还是覆盖**。同一频道同时存在名字声明与终端声明时怎么合并：
  - 追加：保留全部名字目标，再额外发给终端。适合"加一条私线"，表达不了"只要这一台"。
  - 覆盖：该频道一旦声明了终端就只发这些。能实现精细选择，但要把"两种声明的优先级"写成明确规则。
- **越级量**：直投终端取该频道在 `ControlGroup#priorities` 里的值，缺省 0。写进 `terminal_targets` 而没写进 `priorities` 的频道按 0 处理。
- **与发现的一致性**：直投终端必须同时进入发现结果（HUD 候选、按组控制器列表），否则会出现"能控但看不见"。发现与投递继续共用同一份解析结果，这是现成的契约。

## 4. 身份与持久化

- 配置里的身份是 `(part UUID, 子系统名)`。`SubPart#id` 是会话内计数器（`DestroyableObject#ENTITY_COUNTER`），不能用来存档。
- 只对实例有意义：内容包预设写不了 UUID，因此该字段在预设里恒为空，由玩家编辑或存档产生。
- 引用失效时（子系统改名、零件被替换）静默丢弃条目，回落到名字声明，不报错。

## 5. 与完整方案的关系

本备忘是"字段级"的最小路子：给控制组开一个直达终端的口子。完整形态（玩家在界面里勾选、编组、调优先级，以及权限门控与准入钩子）见 [Part 级名字解析与子系统封装](信号系统-Part级名字解析与子系统封装.md) 的附录 A。两者不冲突：字段是数据形态，界面是编辑手段。

## 6. 待细化

- 追加与覆盖的取舍，以及与 `getMerged*Targets` 合并规则的对应关系。
- 是否禁止 `local` / `global` 出现在 `terminal_targets`（按保留地址语义应当禁止）。
- 只对主／副武器通道开放，还是五类目标表都开放。
- 网络与编解码：`ControlGroupSetEditPayload` 已能承载整个 `ControlGroupSet`，只需给 `ControlGroup.CODEC` / `STREAM_CODEC` 加字段，注意协议版本号同步。
- 内容包 schema：建议不暴露该字段，避免作者误以为能在预设里写 UUID。
- 权限：现有编辑校验是"你正坐在这个子系统上"。允许配置到终端等于允许给自己加权限，门控要先定。
