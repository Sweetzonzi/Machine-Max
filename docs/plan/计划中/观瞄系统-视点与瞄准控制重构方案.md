## 2. 已确认的行为约束

### 2.1 三种状态分别持有

1. **实际视点姿态**：决定这一帧画面的位置和朝向。
2. **期望瞄准目标**：玩家希望武器指向哪里，可以领先实际武器。
3. **实际机构姿态**：真实方向机、高低机及炮管的运动结果。

鼠标更新观察意图或武器期望目标；机构追赶武器期望目标。第三人称跟随模式下，乘坐参考姿态的变化也是世界目标的更新来源。渲染只读取已发布状态，渲染调用次数不能改变控制目标。

### 2.2 第三人称分跟随与自由，两种模式都发送世界目标

第三人称是可转的虚拟观察视点。用于武器瞄准时，期望目标与逻辑观察视线一致，两轴都使用世界瞄准点控制，发往 WC 的角增量均为零。武器受转速、力矩和机械限位约束，实际炮管允许滞后于视线。

- **跟随模式**：保存相对乘坐参考的观察角。乘坐刚体旋转时，逻辑视线和世界瞄准点随之更新；鼠标零输入也需要更新。完整姿态跟随包含俯仰、偏航和侧倾。
- **自由模式**：保存世界瞄准点，观察朝向不继承乘坐刚体的旋转。鼠标更新世界目标；零输入时保持该点，观察位置移动带来的有限距离视差按 §4.4 处理。

两种模式的观察位置都随载具移动。自由模式表示“不跟随乘坐姿态”，不等同于暂时只观察、不控制武器的自由观察操作。第三人称的姿态跟随只依赖玩家乘坐刚体及座椅固定挂点，不从装配拓扑推断车体、炮塔或统一基座。位置的环绕中心、偏移和碰撞处理与姿态跟随分别计算，不能把位置中心当成旋转参考体。

内容包逐座椅指定默认值，玩家偏好可以覆盖：一般车辆驾驶座默认跟随，坦克等载具的武器操作座默认自由。同一装配体内不同座椅可以不同；代码不按车种或连接拓扑自动分类。坐在炮塔内时，强制跟随并持续让炮塔追视线可能产生 §4.6 描述的循环；不通过寻找其他刚体自动修正该配置。

“两轴使用世界目标”描述 WC 的输入契约，不表示相机无条件保持世界目标不动。跟随模式会主动更新世界点，自由模式才保持世界点不受乘坐旋转影响。

第三人称不提供炮镜式放大；其精确瞄准能力以观察条件限制。WC 不以一份不可被视角模式覆盖的硬件稳定配置禁止该行为。

### 2.3 固定炮镜跟随实际光轴

固定炮镜的画面取实际光轴位姿，鼠标不直接偏转画面。炮管因输入而转动时，画面随实际炮镜运动。

炮镜模式的分轴稳定设置决定期望目标的保持方式：双稳使用世界瞄准点，无稳轴保持相对机构基座的目标角；单轴稳定在无稳轴目标固定的条件下，利用稳定轴的自由度尽量对准世界点，具体契约见 §4.5。鼠标停止后，机构继续追赶尚未到达的目标。

目标圆圈表示期望目标在当前画面中的投影；光轴分划表示实际炮镜方向。圆圈的收敛由实际机构运动产生。

### 2.4 稳定模式不改变无扰动时的鼠标手感

比较对象是同一个固定炮镜在有稳／无稳模式下的行为。当机构基座位姿不变、初始实际状态与期望目标相同、输入序列相同、限位与执行参数相同时，两种模式应产生相同的目标关节角及追赶过程，允许约定的数值误差。这项要求不表示第三人称和固定炮镜必须使用相同的观察轴。

该等价性用于验证鼠标映射、双稳与双轴无稳的目标累计，不能扩展成单轴模式与真实惯性稳定器的数学等价要求。单轴采用 §4.5 的受限瞄准近似；验收重点是相同输入的基本手感，以及可补偿方向上的颠簸减弱。

炮塔和炮管自身的追赶属于受控运动，不能被当作新的鼠标输入，也不能据此重置期望目标。

### 2.5 可转摄像头拥有自身转轴状态

可转摄像头有独立的 yaw/pitch，可配置行程和两轴稳定。无稳时保持相对挂点的角度；稳定时主动调整局部角度以补偿基座运动。摄像头转动由逻辑姿态和模型骨骼承担，不要求额外 Bullet 刚体。

观察运行状态暂由客户端逐设备持有，摄像头角度同步列为后续 TODO。无稳可转摄像头按正常路径发布瞄准信号，不按稳定配置或挂载位置特殊禁用、暂停或补偿信号。内容包作者负责将其安装在车体等适合的位置，或不连接火控、仅用于观察；循环自追的成因见 §6。

镜头自身的稳定和镜头指挥武器时的瞄准保持方式是两项语义。固定炮镜自身没有独立转轴，其稳定画面来自实际武器运动；可转摄像头可以独立稳定光轴。

### 2.6 普通瞄准统一使用 1000 米世界点

用户已选定：普通鼠标瞄准暂用 1000 米世界点近似方向。本轮包内使用世界点坐标，不引入 Direction／Point 双类型协议，不加入射线命中选择、测距或近距离目标跟踪功能。

常量统一为 `AIM_DISTANCE_METERS = 1000.0`。第三人称和固定炮镜的普通瞄准都遵守这个表示距离。1000 米是生成近似方向用点的距离，不是命中距离、有效射程或弹道归零距离。

用户确认的是这个数据表示。点在何时生成、保持或重建属于 §4.4 的工程实施约定；不能把当前渲染路径每帧改写 aimPoint 的机制视为必须保留的行为。

### 2.7 鼠标轴由观察方式定义

用户明确了固定炮镜的操作含义：水平鼠标控制方向机平转，竖直鼠标控制高低机。车体侧倾时，固定炮镜画面本身随机构倾斜，输入以机构局部轴为准；不能额外把鼠标纠正到世界水平／竖直。俯仰和偏航输入是角增量，不是屏幕像素点的平移量。

第三人称使用自身观察姿态定义的鼠标转向：跟随模式更新乘坐参考中的观察角，自由模式更新世界观察目标，随后交付世界点给 WC。第三人称的水平观察旋转轴与侧倾机构的方向机轴可以不同；两种第三人称模式的完整更新流程见 §4.6。

“按屏幕方向符合直觉”在本方案中指上述两种具体操作规则，不要求屏幕标记做严格的水平／竖直像素平移。禁止把独立稳定摄像头的观察轴规则套到随炮管的固定炮镜上。

## 3. 职责与类型组织

### 3.1 实体视点的三类结构

实体观瞄以是否拥有独立观察转轴划分。这是本轮重构的必做结构，不能只修改 CameraController 的条件分支或网络包来宣称完成：

```text
AbstractViewpointSubsystem
├─ FixedViewpointSubsystem       固定光轴、观察口、随炮管的炮镜
└─ RotatableViewpointSubsystem   独立转轴、车长镜、可转观察摄像头
```

| 类型 | 状态与行为 | 边界 |
| --- | --- | --- |
| AbstractViewpointSubsystem | 设备身份、生命周期、挂载描述、光学配置、发现、HUD 公共契约；提供可采样的观察位姿 | 不假定所有设备都有 yaw/pitch、转动行程或跟踪电机 |
| FixedViewpointSubsystem | 按绑定机构的真实姿态生成观察位姿；位置与朝向来源可分别指定 | 没有独立观察 yaw/pitch；鼠标输入转交瞄准目标逻辑，不直接旋转画面 |
| RotatableViewpointSubsystem | 描述独立转轴、安装参考、行程、转速和观察稳定能力；客户端运行状态保存实际局部角与观察意图 | 挂载参考由设备安装定义，与操作者座位位置无关；不要求额外刚体 |

公共基类沿用 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/BasicSubsystem.java#BasicSubsystem` 的设备生命周期并实现 `src/main/java/io/github/sweetzonzi/machine_max/common/visual/IHudHost.java#IHudHost`；纯观察数学放在独立计算模块。固定式和可转式作为平级运动能力分支，各自通过对应的属性与工厂创建，不用继承可转式来复用固定式所需的光学或 HUD 功能。

固定式的“固定”表示相对绑定机构固定。炮管运动时，绑定炮管的炮镜随真实炮管运动；独立的武器期望目标允许领先这条实际光轴。可转式在无稳时保存相对观察意图，在稳定时保存世界观察意图并解出局部角；每个模式只设一个权威意图，不能让局部角和世界目标各自独立累计。

分划与归零能力可独立组合，设备是否具有分划不决定它是否具有自由转轴。固定炮镜的瞄准稳定配置用于武器目标保持；可转摄像头的观察稳定配置用于自身光轴控制。两类配置必须有明确归属，不能因字段同名而共用一份隐含语义。

### 3.2 属性、发现与现有类型的迁移边界

静态属性与动态属性都需要与运动能力对应。公共属性提供安装与光学配置；固定式属性提供实际光轴绑定与瞄准配置；可转式属性提供独立转轴、行程、转速和观察稳定配置。个人变焦偏好放在视角会话，设备观察状态与个人显示偏好分别持有。

本轮可转设备的实际局部 yaw/pitch、观察目标、稳定求解缓存均保存在客户端运行状态中，按设备稳定身份索引，例如装配体 UUID、Part／SubPart 身份和子系统名的组合。共通子系统及属性类提供配置和设备身份，不引用客户端类，不把这些观察角字段注册成服务器同步属性。动态属性继承关系的分拆只处理该层实际需要的设备数据，不能为了类名对称而制造同步角字段。客户端缓存的生命周期见 §4.7；后续同步 TODO 见 §9。WC 的机构目标与武器实际运动依照 §5 在服务端处理。

现有 SightSubsystem 中的固定炮镜行为进入固定式分支，CameraSubsystem 中的独立转动行为进入可转式分支。当前源码中的 Sight → Camera 继承关系同时存在于子系统、静态属性和动态属性三处，三处都要处理。内容包里的 sight 类型可能用于车长镜，逐设备分类规则见 §10；不能仅凭名称决定运动能力。

发现列表、活动实体视点、切换和 HUD 公共调用都依赖 AbstractViewpointSubsystem；只有转动控制读取可转式能力。需要检查 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/AbstractControllableSubsystem.java#discoveredCameras`、`src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/AbstractControllableSubsystem.java#activeCamera` 及 `src/main/java/io/github/sweetzonzi/machine_max/client/input/CameraController.java#activeCamera` 的类型假定。公共层及固定式不能为满足调用方而提供无效的转轴字段。

### 3.3 第三人称虚拟视点与共用计算

第三人称由客户端的 ThirdPersonViewpoint 持有观察状态与跟随策略，不注册为实体子系统，不创建刚体。它与可转实体摄像头复用无世界／无活体刚体依赖的观察角更新和旋转合成函数；实体设备提供生命周期与转动参数，客户端设备运行状态负责观察角推进。

共用计算接收不可变参考位姿和输入，返回逻辑观察结果。第三人称的位置轨道、距离与相机碰撞在客户端计算，姿态跟随参考只能取乘坐刚体及座椅固定挂点。实体摄像头使用自己的安装参考，两者不能共享一份全局静态角度缓存。

CameraController 的职责是选择活动视点、路由输入、调度逻辑更新、发布／读取位姿快照及应用显示效果。设备观察状态由设备或其会话持有，第三人称状态由 ThirdPersonViewpoint 持有，武器期望状态由瞄准控制持有。渲染不得隐含推进其中任何一个状态。

### 3.4 控制职责及状态归属

| 职责 | 持有的状态与工作 |
| --- | --- |
| 视角会话 | 当前操作者、活动视点、控制组、输入模式和会话序号 |
| 第三人称虚拟视点 | 跟随／自由模式，相对观察角或世界目标，乘坐参考与逻辑观察位姿；不读取武器拓扑 |
| 实体视点 | 自身安装参考与光学配置；固定式采样真实光轴，可转式观察状态由客户端逐设备缓存 |
| 输入映射 | 灵敏度、变焦缩放、鼠标输入到统一瞄准增量的转换 |
| 瞄准目标状态 | 世界目标、无稳轴相对目标角、最近消费的输入序号 |
| 机构几何适配 | 参考基座、关节轴、零位、符号、正解／反解、机械限位 |
| WC | 消费瞄准意图、保持目标、解算并派发机构目标 |
| 执行机构 | 按实际转速、力矩及关节约束追赶目标 |
| 视点渲染 | 采样实际光轴或摄像头局部姿态，合成最终画面 |

视角／观瞄模式选择武器的瞄准保持规则；WC 执行该规则。摄像头自身的转轴稳定由摄像头姿态控制负责。

## 4. 坐标与公共输入更新

### 4.1 武器参考系由各机构定义，第三人称参考由乘坐关系定义

- 装配体不要求存在可统一识别的“车体基座”。武器机构参考由驱动器自身的关节关系定义，不通过车种、部件名或全装配体拓扑猜测。
- 方向机的相对目标以该方向机的支承参考体为准，常见坦克布局中是车体。
- 高低机的相对目标以该高低机的支承参考体为准，常见坦克布局中是炮塔。
- 联动目标的正解／反解使用完整的目标机构关系，包含零位与轴向约定。
- 座椅和 WC 的物理安装位置不决定上述参考系。
- 实际视点挂点与瞄准参考基座是不同概念，固定炮镜随炮管运动的挂点不能充当每帧重新初始化目标的基准。
- 第三人称跟随使用乘坐刚体及座椅固定挂点，不调用武器机构适配器寻找跟随对象。实体可转摄像头使用自身安装挂点。文中的“机构基座／根基座”仅指一组待解算关节的参考，不是装配体级别的统一对象。

### 4.2 固定炮镜的公共输入：俯仰／偏航角增量

输入入口核对 `src/main/java/io/github/sweetzonzi/machine_max/mixin/MouseHandlerMixin.java#beforeTurnPlayer` 和 `src/main/java/io/github/sweetzonzi/machine_max/client/input/CameraController.java#turnCamera`。该入口已经接收 Minecraft 处理的基础灵敏度和反转鼠标结果；不得重复应用这两项。

固定炮镜采用以下语义。角度全部为弧度，朝右的语义 yaw 为正，抬高的语义 pitch 为正；Bullet 关节的实际正负号只在机构适配器中处理一次。

```text
mx = turnCamera 的水平输入             // 正为右
my = turnCamera 的竖直输入             // 正为下，包含用户的反转设置
s = radians(0.15) / max(currentZoom, 0.1)
deltaYaw   =  s * mx
deltaPitch = -s * my
```

这两个增量在有稳／无稳时完全相同。固定炮镜的车体横滚不会改变这两个量的含义；不能根据画面地平线倾斜再混合一次鼠标轴。

角度和角增量均使用现有 `net.minecraft.world.phys.Vec2`，按 Minecraft 的分量顺序约定 `x=pitch、y=yaw`；单位为弧度，正 yaw 向右、正 pitch 抬高。目标角与增量由变量名和参数名区分。期望机构相对目标写作 `new Vec2(pitch, yaw)`。方向机角以其支承参考体为准，高低机角以完整目标机构关系中的支承姿态为准；常见坦克布局分别对应车体和期望炮塔姿态。公共函数只做：

```text
advanceRelativeAim(target, delta, limits):
    target.x = applyPitchLimit(target.x + delta.x)
    target.y = applyYawLimit(target.y + delta.y)
    return target
```

连续回转轴在内部保留连续角或显式绕圈状态；有限行程轴按真实边界处理。例如 179° 加 2°，连续轴可表示为 181°／等价的 −179°，但有限行程轴不允许直接穿越其禁止区域。传入本函数的 delta 已经过 §7.1 的硬编码输入领先上限过滤；该过滤只限制本次可接受增量，不能混入摄像头自身的视野范围字段。

公共函数不读取实际炮管角、不依赖渲染帧、不修改画面。无稳模式直接用它累计相对目标，不必先生成一个世界点再把该点反解成鼠标增量。

若限幅后两轴接受增量均为零，保持目标状态，不能借一次被拒绝的鼠标事件重建世界点。机械行程裁剪后目标角完全未变时同样保持该点；稳定求解可以继续推进执行目标。

### 4.3 两种保持方式如何使用同一增量

符号与 helper 契约：

| 名称 | 精确定义 |
| --- | --- |
| B | 一份机构参考快照：根基座世界位姿、关节零位／轴向／连接关系及限位；不以操作者座位或 WC 的安装位置代替 |
| qHeld | 无稳模式持久保存的期望相对角，包含 yaw/pitch |
| PWorld | 稳定模式持久保存的期望世界点 |
| solveAim(B, P, branch) | 在完整目标机构关系中求瞄准 P 的相对角，branch 用于保持连续角分支；不能从实际炮管角重新起算 |
| buildAimPoint(B, q, 1000) | 按期望机构姿态 q 正解瞄准原点 OGoal 和方向 DGoal，返回 OGoal + 1000DGoal；OGoal 来自期望姿态，不是正在追赶的实际光轴 |

固定炮镜双轴无稳：

```text
收到输入：qHeld = advanceRelativeAim(qHeld, delta, limits)
没有输入：保持 qHeld
每物理步：执行机构追赶 qHeld
HUD 目标：buildAimPoint(B, qHeld, 1000)
```

固定炮镜双轴稳定：

```text
收到输入：
    qBefore = solveAim(B, PWorld, previousBranch)
    qAfter = advanceRelativeAim(qBefore, delta, limits)
    PWorld = buildAimPoint(B, qAfter, 1000)
没有输入：保持 PWorld
每物理步：qCommand = solveAim(currentB, PWorld, previousBranch)
          执行机构追赶 qCommand
```

稳定路径的“解到相对角 → 施加角增量 → 写回世界点”是对“存储的世界瞄准点结合角增量得到新世界点”的明确实现。它不把普通无稳输入绕到世界空间，也不把世界 Y 轴当成侧倾车体的方向机轴。

两个 helper 必须成对验证 `solveAim(B, buildAimPoint(B, q, 1000), q.branch) ≈ q`。观察点／炮口偏置和多枢轴机构需要进入同一模型。不能只给出“用四元数旋转一下”的占位实现，也不能使用当前炮镜位置重建 PWorld 来代替按期望姿态生成目标。

在 B 固定、初始 PWorld 与 qHeld 一致时，两条路径输入后应得到相同相对目标。基座世界位置较大时，先用 double 相减再转换到物理库 float；禁止先把绝对世界点压成 float。

物理求解使用完整目标机构关系。当前方向机尚未转到位时，不得因为分别采样实际从动部件，导致两种模式得到不同的期望高低机角。

第三人称按 §4.6 的跟随／自由规则更新逻辑视线和世界目标，两种模式都交付两轴世界点控制命令，角增量为零。其鼠标转向使用自身观察姿态，不使用固定炮镜的方向机轴，也不向武器相对目标累计观察角。

渲染数学用 JOML、物理适配用 JME，跨边界按仓库规范转换。公共纯逻辑模块不得依赖 Minecraft 客户端类型或读取活体刚体。

### 4.4 1000 米点的生命周期

本节是为执行者明确的工程实施约定，不把 1000 米点扩展成真实目标跟踪：

| 时机 | 处理 |
| --- | --- |
| 首次接管、没有可继承目标 | 从选定观察原点 O 和初始化方向 F 构造 O + 1000F；实际机构角只在这次初始化采样 |
| 第三人称跟随逻辑更新 | 保持／更新相对观察角，与当前乘坐参考旋转合成后生成 O + 1000F；乘坐刚体转动或观察位置移动时，即使鼠标零输入也更新点 |
| 第三人称自由、收到鼠标输入 | 从保存世界点与当前逻辑观察位置求观察方向，按自身观察轴施加角增量，写回 O + 1000F |
| 第三人称自由、没有鼠标输入 | 保留世界点；观察位置随动，逻辑视线指向保存点；乘坐刚体旋转不主动搬动该点 |
| 固定炮镜收到鼠标输入 | 按 §4.2—§4.3 施加角增量；稳定模式写回期望姿态前方的 1000 米世界点，无稳模式累计相对目标角 |
| 固定炮镜双稳、没有鼠标输入 | 保留已保存的世界点；不把目标重新放回实际炮镜前方 |
| 固定炮镜单轴稳定、没有鼠标输入 | 保存世界参考点及无稳轴的相对目标；按 §4.5 重算稳定轴目标，不让实际机构追赶改写参考点 |
| 固定炮镜双轴无稳、没有鼠标输入 | 保持 qHeld；HUD 点由 §4.3 的 buildAimPoint 生成，随机构根基座运动，不读取实际炮管来重置目标 |
| 渲染帧 | 读取快照并投影；目标状态保持只读 |
| 视角切换 | 按 §4.7 继承切出视点的期望目标并转换表示；不能隐式调用“首次接管”来清掉待追赶目标 |

固定炮镜双稳与第三人称自由保持的是有限距离点，因此观察位置平移会有小幅视差。第三人称跟随按当前逻辑视线持续生成远点。两种方式都不应称为严格无穷远方向保持。

目标生成时的距离是 1000 米；固定炮镜双稳与第三人称自由的观察原点随后运动时，不要求保存点到新观察原点的距离恒等于 1000。强行每帧重新拉到 1000 米会改变这两种模式的保持契约。第三人称跟随在每次逻辑更新中生成 1000 米点，是该模式的明确行为。

两种稳定模式的等价性必须使用相同 B、相同初始期望目标和成对的有限点正反解进行测试。不能用单一枢轴、零观察偏置的测试代替炮镜位置与机构中心不同的情形。

### 4.5 单轴稳定：固定无稳目标，在可控自由度内尽量对准世界点

用户已确认本轮采用游戏几何近似，不要求与真实陀螺或惯性扰动补偿在数学上等价。目的为单轴稳定能在自身可控制的方向上减弱颠簸影响；不要求单轴保持完整世界方向，也不要求同时保持独立的世界方位角／仰角。

单轴状态持有世界参考点 PWorld、无稳轴累计的相对目标 qHeld，以及稳定轴最近一次有效解。每次求解固定无稳轴的目标，仅调整启用稳定的那个机械自由度，使光轴方向尽量接近从瞄准原点指向 PWorld 的方向。这里的接近指夹角，执行器的转速与力矩决定实际追赶能力。

| 配置 | 求解时固定的量 | 允许调整的量 |
| --- | --- | --- |
| 有垂稳、无水平稳定 | 累计的方向机相对偏航目标 | 高低机俯仰目标 |
| 有水平稳定、无垂稳 | 累计的高低机相对俯仰目标 | 方向机偏航目标 |

机构几何按 §4.1、§4.3 的快照和完整期望关节关系计算；不得用实际追赶中的角度反复初始化 qHeld。采用纯函数 `solveSingleAxisAim(B, PWorld, qHeld, stableAxis, previousSolution)`，返回组合目标角和有效性；残余夹角可供数值验证使用，不产生界面告警。

实现优先使用机械转动平面内的方向投影或简单的一维角度求解。候选目标角的正解提供瞄准原点 OGoal 和光轴 DGoal，以 DGoal 与 normalize(PWorld − OGoal) 的夹角评价解；观察点／炮口相对枢轴的偏置按同一几何模型处理。只要求稳定、连续、能改善可补偿分量的结果，不引入全局优化器或真实陀螺反馈回路，也不要求为几何近似证明全局最优。不能把完整双轴反解中的一个分量直接截出来，就认定已经满足另一轴固定时的受限瞄准。

稳定轴只能在其机械可达范围内给出执行目标。出现退化投影、多个近似等价解或目标接近轴线时，优先保留连续且接近上一有效解的分支；不能产生 NaN、无输入跳转半圈或偷偷改变无稳轴。基座运动造成世界点暂时不可达时保留该点，执行目标服从机械行程；鼠标累计服从 §7.1 的输入上限，不为不可达或追赶不足绘制提示。

固定炮镜的输入更新使用相同的语义角增量：

```text
收到输入：
    qBefore = solveSingleAxisAim(B, PWorld, qHeld, stableAxis, previousSolution)
    qAfter = advanceRelativeAim(qBefore, delta, limits)
    qHeld[无稳轴] = qAfter[无稳轴]
    PWorld = buildAimPoint(B, qAfter, 1000)
没有输入：
    保持 PWorld 和 qHeld[无稳轴]
每物理步：
    qCommand = solveSingleAxisAim(currentB, PWorld, qHeld, stableAxis, previousSolution)
    执行机构追赶 qCommand
```

因此鼠标操作无稳轴也会更新共同的世界参考方向，稳定轴不会继续追逐输入前的旧方向；实际炮塔／炮管追赶、渲染以及网络重发都不能反向改写这份参考点。客户端构造 PWorld，服务端按包中的新点和一次消费的无稳轴增量更新目标；稳定轴不得再次叠加同一鼠标增量。目标点和有效受限解可以存在误差，HUD 可分别显示期望点与实际光轴。

可转摄像头的单轴观察稳定复用相同的受限求解思想，参考体取自身安装挂点。摄像头的正常瞄准输出取其当前逻辑光轴前方的 1000 米点，包含安装参考运动与镜头自身转动，不含显示抖动；两轴使用世界点控制、角增量为零，具体接线见 §6。单轴纯逻辑和接入可直接实施，验证场景见 §11.9 T18、T19。

### 4.6 第三人称两模式的状态、更新与发送

本节描述第三人称参与武器瞄准时的路径。普通座椅第一人称的工程基线为乘坐参考内的自由观察，以当前逻辑视线生成世界点，两轴角增量为零；该姿态规则依据 `src/main/java/io/github/sweetzonzi/machine_max/client/input/CameraController.java#updateCameraRotSeatMode` 的第一人称分支。其进入／退出也遵守 §4.7，不额外定义一种稳定器模式。暂时只观察、不控制武器的操作与跟随／自由模式分别表示，不能把 `src/main/java/io/github/sweetzonzi/machine_max/client/input/RawInputHandler.java#freeCam` 直接当作自由模式开关。

| 符号 | 定义 |
| --- | --- |
| RSeat | 当前乘坐刚体世界旋转与座椅固定挂点旋转的合成；包含完整姿态，不查询武器控制器或装配体中的其他参考体 |
| qLook / RLook | 玩家相对乘坐参考的观察 yaw/pitch 及其旋转；只由鼠标或明确的会话初始化修改 |
| O | 当前逻辑观察原点，由第三人称位置、环绕距离和碰撞策略产生；不含显示抖动，与方向使用同一逻辑快照 |
| F0 | 观察模型的单位前向，经边界适配映射到引擎的相机前向 |
| PWorld | 自由模式持久保存的世界目标；跟随模式中为本次逻辑更新的输出 |

跟随模式每次逻辑更新：

```text
1. 消费鼠标输入，按自身观察轴更新 qLook，得到 RLook。
2. 读取当前乘坐参考 RSeat。
3. RWorld = RSeat × RLook；FWorld = RWorld × F0。
4. 用同次逻辑观察姿态得到 O，写出 PWorld = O + 1000 × FWorld。
5. 发布观察快照和世界目标；需要发送时，两轴采用世界点控制，角增量均为 0。
```

这里的乘法为旋转合成，不是把世界欧拉角逐项相加。鼠标改变 RLook，乘坐运动改变 RSeat；两者在相机侧各计入一次。不能把乘坐刚体转角再伪造成鼠标增量，也不能在 WC 端额外叠加这次转角。没有鼠标输入时，步骤 2—5 也执行；目标发生有效变化时须进入发送路径，不能仅由鼠标事件触发发包。网络频率受客户端逻辑更新约束，不依赖渲染调用次数。

水平例子忽略观察点与炮塔原点的偏置，约定向右为正：

| 情况 | 乘坐刚体世界偏航 | 相对观察偏航 | 世界观察／瞄准偏航 |
| --- | --- | --- | --- |
| 初始化 | 0° | 20° | 20° |
| 鼠标不动，乘坐刚体右转 10° | 10° | 20° | 30° |
| 鼠标再向右输入 5° | 10° | 25° | 35° |

第二行的世界目标已经包含乘坐旋转，第三行已经同时包含乘坐旋转与鼠标输入。两行发往 WC 的 yawDelta/pitchDelta 都是 0。玩家坐在车体上时，炮塔自身追赶不会修改该乘坐参考，所以不会通过这条逻辑链继续推动世界目标。

自由模式在无鼠标输入时保存 PWorld，按当前 O 指向该点；不把 RSeat 的变化乘到世界观察朝向上。收到鼠标输入时，从保存点与 O 求当前逻辑观察方向，按该视点自身观察轴施加角增量，写回方向前方 1000 米的点，然后发布位姿和世界目标。乘坐参考只服务于位置随动，不参与自由模式的观察旋转输入。世界点保持造成的平移视差见 §4.4。

跟随／自由是观察状态的保持策略，两种模式都选择 WC 的两轴世界点分支。若沿用现有 verticalStabilized/horizontalStabilized 协议字段，两者都传 true/true；该值只表示接收端持续解算世界点，不得被客户端用于把跟随模式强制变为自由模式。WC 的世界点消费契约见 §5。

内容定义以座椅为单位配置模式，玩家覆盖入口沿用 `src/main/java/io/github/sweetzonzi/machine_max/common/attachment/ControlPreference.java#shouldFollowPose` 的优先级。`src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/attr/static_attr/SeatSubsystemStaticAttr.java#ViewAttr` 中的 follow_vehicle 表示乘坐姿态跟随；保留字段兼容时也必须按这个语义解释。一般车辆驾驶座默认跟随，坦克武器操作座默认自由，不创建自动识别车种或寻找武器基座的流程。仅跟随偏航、自动保持地平线水平不是本轮跟随模式的含义。

若座位在受控炮塔上，跟随模式的观察方向会包含炮塔实际转角；叠加非零观察偏角并持续驱动该炮塔时，会产生 §6 的固定偏角自追。此时内容默认值采用自由模式。玩家强制跟随不获得“任意拓扑都能安全连续联动”的保证；执行者不得静默切换参考刚体或推导另一套拓扑补偿算法。

模式切换时按 §4.7 将同一目标转换为相对观察角或世界点，切换本身不产生鼠标增量。目标继承发生一次，后续逻辑更新遵守目标模式的保持规则。

### 4.7 视角切换继承目标与客户端状态生命周期

继承对象是切出视点的期望瞄准目标，不能拿正在追赶的实际炮管方向替代。切换事件先处理已采集的输入，再冻结切出来源的预测目标和几何快照；创建新输入会话时携带这份目标作为初始化值，不能把尚未确认的输入又当作新会话增量重放。迟到的旧会话包无权重置新会话。

从双稳固定炮镜、第三人称自由或已有世界点来源切出时，继承其世界点；从无稳固定炮镜切出时，以当次 B 和持久 qHeld 调用 buildAimPoint 得到继承点；单轴固定炮镜继承保存的 PWorld，并在同一机构、相同配置的切换中保留无稳轴目标。可转摄像头的切出目标取正常瞄准输出点。定义上述结果为 PInherited。

下表是落实目标继承的工程约定，具体区分目标转换与实际画面初始化：

| 切入模式 | 一次性的目标初始化 |
| --- | --- |
| 固定炮镜双稳 | PWorld = PInherited；实际画面直接取真实炮镜位姿，不能旋转画面去对齐目标 |
| 固定炮镜双轴无稳 | 用切入机构的 solveAim 求 qHeld，选择连续且可达的分支；相同机构已具有有效相对目标时直接继承该状态 |
| 固定炮镜单轴 | 保留 PInherited；相同机构及配置继承无稳轴目标，否则由切入机构对该点的反解初始化无稳轴，再按 §4.5 求稳定轴 |
| 第三人称自由 | PWorld = PInherited，逻辑观察朝向指向它 |
| 第三人称跟随／普通座椅第一人称 | 以切入观察原点指向 PInherited，将方向转换到当前乘坐参考，得到 qLook；随后按跟随规则生成 1000 米点 |
| 可转摄像头 | 以切入挂点指向 PInherited，初始化观察意图并解局部角，稳定轴保存世界参考、无稳轴保存相对角；切入时将本地观察姿态对齐该可达方向，后续按自身转速和行程推进 |

对于可转摄像头，切入时的本地姿态对齐是会话初始化，不驱动额外刚体。缓存中的观察角不能覆盖可继承的目标。受行程约束无法对准时采用最近的可达角；下一次正常输出就是实际逻辑光轴，不为此添加暂停输出或提示。切入固定炮镜时，实际画面与继承目标存在差距属于正常追赶。

“继承目标”要求转换过程保持指向意图；使用相对角或重新生成 1000 米点的模式可能改变点的距离，可达范围也可能裁剪方向。不能在有有效继承目标时随意重置成实际炮管前方。固定炮镜的输入领先上限只约束后续新鼠标输入，不裁掉这次继承的目标。

仅在没有有效继承目标时，按设备缓存的有效观察状态初始化；缓存也不存在时，使用当前真实光轴或设备默认角生成首个目标。暂时只观察时可以独立更新观察缓存，但恢复武器控制时继承该控制来源保持的瞄准目标，不把临时观察方向悄悄当作一次目标指示。

客户端按设备身份保存可转观察状态；非活动设备保留缓存，不消费鼠标，下一次进入按本节初始化。设备销毁、离开当前世界、断线时释放相应缓存；仅切换视角不清空其他设备缓存。不同客户端各自持有状态，本轮不保证多名观察者看到相同的镜头角度，也不建立共享镜头控制权协议。

同一操作者切换控制组输出频道也继承自己的当前目标，并释放切出频道；车长／炮手之间因优先级变化而选中另一来源时，各来源按 §5—§6 保持自身目标，不将一人的目标复制给另一人。离座、断线或来源失效时结束会话并释放输出，继承规则不允许失效来源继续占据频道。

## 5. 输入包、目标保持与线程

保留“世界点 + 分轴角增量”的表达能力，世界点使用双精度 x/y/z。输入命令用不可变值表达；网络类只负责编解码及交付，控制数学放在公共纯逻辑模块。

```text
AimInput
  source                 控制来源及活动视点／控制模式身份
  session                本次接管会话
  sequence               会话内输入序号
  aimPointWorld          1000 米近似得到的世界点，三个 double
  yawDelta               固定炮镜本包的语义偏航输入角增量，弧度
  pitchDelta             固定炮镜本包的语义俯仰输入角增量，弧度
  stabilizationMode      WC 各轴使用世界点／累计相对角的控制规则；不是相机的跟随开关
  initialRelativeAim     仅会话建立时可有：固定炮镜无稳轴的初始化绝对相对角，弧度
```

模式可随包携带，也可由已建立的会话解析；服务端应能根据控制来源和活动观瞄确认模式。第三人称跟随和自由都使用两轴世界点分支，角增量均为零；跟随／自由的观察状态由客户端视角会话持有，WC 不据此查询乘坐刚体或重新合成目标。若 source 记录第三人称子模式，它只承担来源识别，不能使同一运动被重复计算。

会话建立命令使用该结构的 sequence=0、零角增量和继承世界点；切入固定炮镜有无稳轴时，同时携带按 §4.7 得到的 initialRelativeAim。该字段是绝对相对目标，不能当作角增量累加，也不能省略后仅凭单轴的世界参考点反推无稳轴。服务端校验来源、切换合法性、角度有限性及机械行程后，仅初始化一次目标。后续输入序号从 1 递增，不含 initialRelativeAim。

切换命令承接客户端已消费到的预测目标，包括切换时尚未确认的输入效果；新会话不能再重放那些增量，服务端也不能用较早的确认状态覆盖切换初态。普通更新不能借由重复发送 sequence=0 重置目标。没有可继承目标时，客户端按 §4.7 生成初始化状态；会话初始化不因鼠标领先上限而裁剪目标，但实际机械行程有效。

现有 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/AbstractControllableSubsystem.java#setViewInputSignal` 会按控制组向多个目标发送同一信号。执行 §11 P0 时必须列出同一控制组的接收 WC、共用关节和用于固定炮镜目标正反解的主机构。语义角增量由每个接收机构按自身轴向适配，不能当作各刚体的世界欧拉角。多个异构机构的输入归属存在歧义时，在 P2 明确路由契约；不要仅为假设的需求扩展成逐关节网络数组。

yawDelta／pitchDelta 来自 §4.2 的公共角增量；灵敏度和变焦缩放只做一次。稳定轴使用 aimPointWorld，无稳轴使用该增量，禁止稳定轴在使用新世界点后再次加同一增量。第三人称两轴增量发送 0。客户端可以合并多个输入采样，但跨周、触及限位后反向输入等有顺序影响的情况必须与逐条消费结果一致。

第三人称跟随的目标更新可以只由乘坐运动引起。无鼠标、乘坐参考旋转时也要计算并发送变化后的世界点；不存在另外一份“载具旋转角增量”字段。WC 在下一份命令到达前保持最近收到的世界目标，不在服务端猜测客户端相机应如何随动。

服务端主线程接收输入，按会话与序号交付不可变命令。物理线程消费命令，持有机构目标状态：

```text
接管初始化：建立目标状态
新命令：
  稳定轴更新世界目标
  无稳轴目标 += 本命令角增量（仅消费一次）
每个物理步：
  解算稳定轴目标
  读取无稳轴持久目标
  派发关节目标，执行机构追赶
```

每份有效增量都通过已有 PhysicsLevel 的 `submitImmediateTask(PPhase.PRE, ...)` 逐项交付，不能只用 latest 快照覆盖中间的增量。该机制由 `../Spark-Core/src/main/kotlin/cn/solarmoon/spark_core/util/TaskSubmitOffice.kt#submitImmediateTask` 与 `#processTasks` 提供；观瞄模块不另建命令队列、来源仲裁器或频道优先级选择器。重复序号不重复消费，过期会话不影响当前控制。物理步可以反复读取保持目标，不能反复累计同一命令。

多来源竞争遵循 §6 的既有信号优先级。输入序号、预测确认和目标状态按控制来源／会话隔离；低优先级来源可以维护自己的目标，但不能把增量累加到高优先级来源当前驱动的目标上。切回时采用当时有效来源的目标，不集中重放此前被覆盖的输入来驱动机构，也不从高优先级的实际追赶姿态重置另一个来源。这里的增量“一次性消费”是网络与物理线程的去重要求，与一次性目标指示功能无关。

客户端预测武器期望目标，服务端发布机构目标状态和已消费序号，客户端据此校正并重放当前会话未确认输入。HUD 使用预测／校正后的武器期望目标；固定炮镜实际光轴使用真实机构的插值快照。这条确认链服务于 WC 的角增量消费，不同步可转摄像头的观察 yaw/pitch，也不让服务端重建或驱动客户端镜头。

主线程／物理线程交接必须包含完整不可变命令，不能分别用多个 volatile 发布点、模式和角增量，让消费者拼到不同输入序号的数据。世界坐标先做双精度差值，再按物理库需要转换，避免先把绝对世界点降成 float。

客户端帧率变化时，未触及限位的相同累计鼠标角位移必须产生相同累计相对目标。如果参考姿态或限位在多次采样间改变，保留有意义的输入顺序；不能把“先触顶、后反向”的轨迹简单相加为零输入。

## 6. 可转摄像头联动与控制组优先级

可转摄像头的客户端运行状态分别持有实际局部角度和期望姿态，并受自身转速与行程约束。本轮观察角无需服务端持有或同步；双端共通类型及缓存边界见 §3.2、§4.7。

所有可转摄像头按同一流程输出：先更新自身观察姿态，取当前逻辑光轴的原点 OCamera 和前向 FCamera，生成 OCamera + 1000 × FCamera；经控制组的视角输出接线交付 WC，两轴均选择世界点分支、角增量为零。这里的逻辑光轴是镜头自身转速／行程执行后的观察方向，尚未追到的摄像头理想观察方向不能直接冒充可见方向。显示抖动不进入输出；没有火控接线时信号不会驱动武器。

镜头双稳、单轴、无稳只影响自身观察姿态的保持和更新，不改变上述输出路径。无稳镜头也正常发布瞄准信号，代码不依据稳定配置或挂载拓扑自动拒绝、暂停、切换参考体或抵消安装体的转动。

无稳摄像头相对炮塔保持一个非零偏角，同时要求炮塔持续瞄准该摄像头，会形成自追：设车体角为 h、炮塔相对角为 t、镜头相对炮塔角为 c，镜头世界角为 h+t+c；炮塔相对目标为 t+c，误差始终为 c。

本轮支持观察与持续瞄准输出，不实现一次性目标指示、目标移交包或车长专用的超控仲裁器。车长超控通过控制组切换输出频道，复用已有优先级：

| 状态 | 车长输出 | WC／执行机构采用的来源 |
| --- | --- | --- |
| 常态备用 | 低于炮手的备用瞄准频道，或仅观察、不输出瞄准 | 有效炮手信号优先；炮手无有效信号时可采用备用来源 |
| 临时超控 | 切换到高于炮手的瞄准频道，持续发送车长目标 | 有效高优先级车长信号覆盖炮手 |
| 结束超控 | 释放高优先级输出，切回低优先级备用控制组 | 恢复当前最高优先级有效来源；不把车长目标锁存成一次指示 |

示意顺序为 `车长超控 > 炮手 > 车长备用`，具体频道名由内容包声明，不是内置身份或网络包里的优先级数值。不同观瞄各自维护观察与目标状态；优先级决定当前哪个来源驱动武器，不要求车长与炮手共享一份可互相覆盖的输入累计量。

现有接线与检查入口：

- `src/main/java/io/github/sweetzonzi/machine_max/common/mech/control/ControlGroup.java#viewTargets` 指定各组的视角输出频道和接收者。
- `src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/WeaponControllerSubsystem.java#readInputSignals` 按 aimInputs 的声明顺序选择有效瞄准频道。
- `src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/TurretDriverSubsystem.java#getTargetAngle` 按 controlInputs 的声明顺序选择有效机构目标；`src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/TurretDriverSubsystem.java#setTargetAngle` 接收 null 表示释放该频道。
- `src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/AbstractControllableSubsystem.java#clearInputSignals` 发送空信号以释放当前控制组的输出。切换控制组、离座、断线及设备失效时需确认高优先级信号和对应机构目标不会残留；仅停止发包不等于释放已保存信号。

优先级通过不同频道及接收方声明顺序表达。同一频道内的发送者由 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/signal/SignalChannel.java#SignalChannel` 保存，不能把其 Map 遍历顺序当作车长／炮手优先级。P0 应核对实际内容包的竞争层级：同一 WC 的输入优先级，或多个 WC 的执行机构优先级；按对应层级验证有效来源选择和释放，不构造第二套抢占系统。

信号优先级解决来源竞争，固定偏角自追由安装与用途约定避免：无稳摄像头应安装在车体等不会被其火控输出带动的参考体上，或只作观察、不给武器配置接线。稳定车长镜可以安装于炮塔并输出持续目标。内容作者需要核对参考体是否会被这份输出带动；本轮不实现拓扑检测或运行时防自追功能。多人客户端的镜头缓存互相独立，只有武器控制信号通过现有优先级竞争；共享镜头角度同步属于 §9 的后续 TODO。

## 7. 视点挂载、限位与 HUD

固定炮镜的位置来源和朝向来源需要明确。可以直接挂在炮管上，也可以位置取炮塔挂点、朝向绑定实际炮管。两种方式均不需要额外刚体。

内容包迁移必须逐设备核对光轴来源。例：`src/main/resources/spark_modules/Machine-Max_2S38/machine_max/parts/2s38_turret.json` 的 `subsystem.machine_max.gunner_sight` 与 `subsystem.machine_max.commander_sight` 都定义在炮塔 SubPart 内；当前挂点变换规则见 §1。仅改变 Java 继承关系不能使炮塔挂点自动随炮管俯仰。

### 7.1 机械范围与输入累计上限

四类范围分别定义：

1. 光学 FOV：单幅画面的可见角度。
2. 摄像头转轴行程：镜头相对挂点可转范围。
3. 武器机械行程：真实关节可达范围。
4. 输入领先范围：固定炮镜允许鼠标推动期望关节角领先实际关节角的幅度，以硬编码常量限制新输入。

本轮不做输入上限的配置 UI 或内容包调参。工程初值取每轴 `MAX_INPUT_LEAD_RAD = radians(30)`，常量集中定义；30°是实施初值，可在记录游戏内验收结果后统一调整，不是用户指定的精确数值。限制的是尚未被机构追上的角输入，不是从进入视角起累计转过的总角度；机构追上后可继续完整回转。

对每个输入轴，先从持久目标求本次输入前的期望相对角 qDesired，并采样同一快照中的实际相对角 qActual。两者使用相同轴向及连续角分支。令 e = qDesired − qActual、L 为上限，只过滤这次鼠标增量：

```text
lower = min(0, -L - e)
upper = max(0,  L - e)
acceptedDelta = clamp(rawDelta, lower, upper)
qAfter = advanceRelativeAim(qDesired, acceptedDelta, mechanicalLimits)
```

例如实际 0°、期望 28°、右移 5°，只接受 2°；目标到 30°后继续右移不累计，左移立即生效；机构追到 10°后，右移又有 10°余量。若切换或基座扰动使既存目标领先 40°，零输入保持该目标，右移被拒绝、左移按输入量逐步减小领先，不把目标突然拉回 30°。该函数的零输入输出必须为零，实际角只决定还能接受多少新输入，不能充当累计起点。连续回转轴的差值必须选连续且相邻的分支，不能在 ±180°处误判为一整圈领先。

双稳、单轴、无稳使用相同过滤规则；§4 的 delta 均指接受后的增量。客户端过滤一次，稳定轴由该增量生成世界点、无稳轴发送该增量；服务端不能基于迟到的另一份实际角再次过滤同一输入。服务端执行目标服从真实机械行程，并按 §5 校验输入及去重。测试等价性时采用相同的实际角快照与限幅参数。

有限行程的相对目标在行程边界截断，反向输入可立即离开边界。基座运动或目标继承造成世界目标不可达时，世界点可以保留，执行目标限制在可达行程；不额外积累有限关节之外的鼠标角债务。第三人称和可转摄像头观察不能按炮塔追赶误差限幅；它们遵守自身观察角范围，可转设备的本地转动也可复用同一上限规则约束镜头自身尚未追上的输入。

### 7.2 目标投影与显示边界

HUD 分别读取期望目标和实际光轴，使用同一帧的相机变换投影。固定炮镜分划与实际光轴一致，目标圆圈随真实追赶靠近分划。目标在画面外、相机后方或无法投影时，本轮跳过圆圈绘制，不设计额外方向箭头。机械限位、目标不可达、镜头或武器追赶不足均不提供告警或专门提示；这些限制不影响真实执行约束。镜头抖动属于显示效果，不能回流到瞄准输入。

## 8. 实施顺序与验收

### 8.1 实施顺序

1. P0 核对机构接线、实体视点和座椅第三人称配置；P1 建立 §3 的公共／固定／可转类型与属性契约、虚拟视点边界，再实现机构目标和观察状态的纯逻辑。验证固定炮镜双稳／双轴无稳的输入一致性、单轴受限瞄准效果，以及第三人称两模式的不同保持规则。
2. P2—P3 接入服务端持久目标、输入一次性消费、预测确认和协议，按既有频道优先级选择有效目标并验证超控释放。WC 不推断第三人称的旋转参考；单轴按已确认的 §4.5 实施。
3. P4 基于公共视点接入固定炮镜真实光轴、第三人称跟随／自由和目标 HUD。客户端调度与每种视点的状态持有者分离。

5. P6 完成类型注册、codec、schema、内容包设备分类与座椅模式默认值，执行客户端和服务端验收。类型关系和属性分拆是完成条件的一部分。

协议变更需要同步维护 `src/main/java/io/github/sweetzonzi/machine_max/network/MMPayloadRegistry.java#register` 中受影响的协议组。内容包 schema 维护 Builtin 权威副本，并通过仓库的 `syncSchemas`／`checkSchemas` 流程同步和校验。

## 10. 迁移说明

§1 给出了当前代码基线。实施时需要以本方案的明确状态替代这些机制：客户端固定角速度的虚拟追赶、渲染阶段改写控制目标、WC 每步以实际角加偏移构造无稳目标，以及全局视角缓存承担设备姿态。

`CameraSubsystem` 与 `SightSubsystem` 的现有类型标识、codec 和内容包定义需要迁移策略。建议尽量保留内容 id，通过显式设备行为配置完成分类；车长镜不能因类型名含 sight 就被自动归为固定光轴。具体兼容字段与迁移版本在实现清单中确定。

继承关系的迁移同时覆盖 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/SightSubsystem.java#SightSubsystem`、`src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/attr/static_attr/SightSubsystemStaticAttr.java#SightSubsystemStaticAttr` 和 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/attr/dynamic_attr/SightSubsystemAttr.java#SightSubsystemAttr`。已有 sight 配置中的武器瞄准稳定与 camera 配置中的观察稳定需要逐项确定语义；不能把固定式缺失的观察行程补成一套无效状态来维持继承。

第三人称沿用逐座椅配置和玩家覆盖的来源。保留 follow_vehicle 字段时解释为乘坐姿态跟随；若调整字段名称或使用枚举，codec 必须显式读取兼容值。内容迁移清单逐座椅记录乘坐 SubPart、用途和默认模式，不给整个载具设置一个掩盖座位差异的自动分类结果。

无稳可转摄像头逐设备记录安装参考与火控接线。会被自身瞄准输出带动的炮塔安装方式不适合作持续火控来源；内容作者可选择车体等参考体，或不给该摄像头连接火控。该审核是内容迁移工作，运行代码不增加无稳设备的禁止输出规则。

| T18 | 分别只有垂稳／只有水平稳定，初态对准目标、零输入，在可达范围内施加稳定轴能补偿的小幅基座摆动；覆盖基座侧倾与非零初始目标角 | 无稳轴目标不变，稳定轴目标朝减小指向误差的方向变化；实际执行能力足够时，相比无稳基线的相关摆动减弱。再操作无稳轴鼠标，世界参考方向随该输入更新，不能继续追输入前的旧点 |
| T19 | 单轴目标偏离机构可达平面、接近转轴方向或限位；重复同一快照，改变渲染帧率，并让实际机构滞后 | 求解有限、分支连续、不无故翻转，无法补偿的误差允许保留；无稳轴与参考点不因实际追赶或渲染次数变化。结果不要求与真实惯性稳定器数学等价 |
| T20 | 三个已初始化的世界目标来源按“车长超控 > 炮手 > 备用”接线，先炮手生效，再启用车长超控，最后切回备用并释放高频道 | 当前有效来源依次为炮手、车长超控、炮手；炮手无有效信号时采用备用。无一次指示锁存，无高频道残留，各来源输入不混合 |
| T21 | 超控期间离座／断线／设备失效，或切换后收到旧高频道会话的迟到包 | 高频道及其驱动目标被释放；迟到包不能重新占据高优先级来源，其他有效来源可接续 |
| T22 | 炮手和车长使用相同数值的 sequence，但来源不同；低优先级期间持续更新各自输入，并覆盖无稳角增量场景 | 去重按来源／会话隔离，各源更新自己的目标且每份增量只消费一次；有效机构目标只来自获选来源，恢复低优先级时不把被覆盖输入成批叠加到高优先级目标上 |
| T23 | 保存一个与实际炮管不同的目标，依次切换第三人称自由／跟随、固定炮镜各稳定配置、可转镜头；另设无可继承目标与观察行程不可达情况 | 有有效目标时各模式继承指向意图，固定炮镜不旋转画面；相对表示按切入参考换算。可转镜头切入对齐可达方向，缓存不覆盖继承目标；无目标才用缓存或默认角。受行程限制的误差不产生提示 |
| T24 | 实际角 0°、目标 28°、输入 +5°，继续正向，再反向；随后实际角追到 10°；另设继承目标领先 40°但零输入 | 30°初值下首次只接受 +2°，继续正向为 0，反向立即生效；实际追赶释放输入余量，能够连续整周回转。40°既存目标零输入不变，正向不扩张、反向按量缩小；双稳／单轴／无稳均只过滤一次 |
| T25 | 无稳镜头装在车体上并接火控，改变局部观察角；随后断开火控接线；另用无稳镜头偏炮塔 20°且连续控制该炮塔的配置作对照 | 正常接线按实际逻辑光轴发世界点，无火控接线时只作观察、不驱动武器；不当炮塔接线可复现 §6 的自追且不会触发引擎特殊拦截。第一方内容不得用此不当配置承担持续火控 |

测试中“度”仅为可读说明，实现边界转换为弧度。至少加入非零初始朝向、不同变焦、正负双向输入、多个世界位置和合法轴向符号配置。
