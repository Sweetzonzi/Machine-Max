## 2. 已确认的行为约束

### 2.1 三种状态分别持有

1. **实际视点姿态**：决定这一帧画面的位置和朝向。
2. **期望瞄准目标**：玩家希望武器指向哪里，可以领先实际武器。
3. **实际机构姿态**：真实方向机、高低机及炮管的运动结果。

鼠标更新观察意图或武器期望目标；机构追赶武器期望目标。第三人称跟随模式下，乘坐参考姿态的变化也是世界目标的更新来源。渲染只读取已发布状态，渲染调用次数不能改变控制目标。

### 2.2 第三人称分跟随与自由，两种模式都发送世界目标

第三人称是可转的虚拟观察视点。用于武器瞄准时，期望目标与逻辑观察视线一致，两轴都使用世界瞄准点控制，发往 WC 的 relativeAim 为零。武器受转速、力矩和机械限位约束，实际炮管允许滞后于视线。

- **跟随模式**：保存相对乘坐参考的观察角。乘坐刚体旋转时，逻辑视线和世界瞄准点随之更新；鼠标零输入也需要更新。完整姿态跟随包含俯仰、偏航和侧倾。
- **自由模式**：保存世界瞄准点，观察朝向不继承乘坐刚体的旋转。鼠标更新世界目标；零输入时保持该点，观察位置移动带来的有限距离视差按 §4.4 处理。

两种模式的观察位置都随载具移动。自由模式表示“不跟随乘坐姿态”，不等同于暂时只观察、不控制武器的自由观察操作。第三人称的姿态跟随只依赖玩家乘坐刚体及座椅固定挂点，不从装配拓扑推断车体、炮塔或统一基座。位置的环绕中心、偏移和碰撞处理与姿态跟随分别计算，不能把位置中心当成旋转参考体。

内容包逐座椅指定默认值，玩家偏好可以覆盖：一般车辆驾驶座默认跟随，坦克等载具的武器操作座默认自由。同一装配体内不同座椅可以不同；代码不按车种或连接拓扑自动分类。坐在炮塔内时，强制跟随并持续让炮塔追视线可能产生 §4.6 描述的循环；不通过寻找其他刚体自动修正该配置。

“两轴使用世界目标”描述 WC 的输入契约，不表示相机无条件保持世界目标不动。跟随模式会主动更新世界点，自由模式才保持世界点不受乘坐旋转影响。

第三人称不提供炮镜式放大；其精确瞄准能力以观察条件限制。WC 不以一份不可被视角模式覆盖的硬件稳定配置禁止该行为。

### 2.3 固定炮镜跟随实际光轴

固定炮镜的画面取实际光轴位姿，鼠标不直接偏转画面。炮管因输入而转动时，画面随实际炮镜运动。

炮镜模式的分轴稳定设置决定期望目标的保持方式：双稳使用世界瞄准点，无稳轴保持相对机构基座的目标角；单轴稳定在无稳轴目标固定的条件下，利用稳定轴的自由度尽量对准世界点，具体契约见 §4.5。鼠标停止后，机构继续追赶尚未到达的目标。

目标圆圈表示期望目标在当前画面中的投影；光轴分划表示实际炮镜方向。圆圈的收敛由实际机构运动产生。

### 2.4 稳定模式不改变无扰动时的鼠标手感

比较对象是同一个固定炮镜在有稳／无稳模式下的输入方向与基础灵敏度。在稳定轴未触及光学领先上限时，相同输入得到相同的角增量。各执行器使用自己的参考和机械边界，不要求炮镜输入生成整套机构的同一期望姿态。

该一致性用于验证鼠标映射和目标累计；单轴采用 §4.5 的分轴控制，不要求与真实惯性稳定器数学等价。验收重点是输入方向、基础灵敏度及可补偿方向上的颠簸减弱。

炮塔和炮管自身的追赶属于受控运动，不能被当作新的鼠标输入，也不能据此重置期望目标。

### 2.5 可转摄像头拥有自身转轴状态

可转摄像头有独立的 yaw/pitch，可配置行程和两轴稳定。无稳时保持相对挂点的角度；稳定轴以世界目标为观察意图，按本次挂点的可视范围和可达转角约束实际视野。双稳镜头与第三人称自由观察共用世界目标输入和朝向合成；局部角用于描述行程及角速度边界。摄像头转动由逻辑姿态和模型骨骼承担，不要求额外 Bullet 刚体。

观察运行状态暂由客户端逐设备持有，摄像头角度同步列为后续 TODO。无稳可转摄像头按正常路径发布瞄准信号，不按稳定配置或挂载位置特殊禁用、暂停或补偿信号。内容包作者负责将其安装在车体等适合的位置，或不连接火控、仅用于观察；循环自追的成因见 §6。

镜头自身的稳定和镜头指挥武器时的瞄准保持方式是两项语义。固定炮镜自身没有独立转轴，其稳定画面来自实际武器运动；可转摄像头可以独立稳定光轴。

### 2.6 普通瞄准统一使用 1000 米世界点

用户已选定：普通鼠标瞄准暂用 1000 米世界点近似方向。本轮包内使用世界点坐标，不引入 Direction／Point 双类型协议，不加入射线命中选择、测距或近距离目标跟踪功能。

常量统一为 `AIM_DISTANCE_METERS = 1000.0`。第三人称和固定炮镜的普通瞄准都遵守这个表示距离。1000 米是生成近似方向用点的距离，不是命中距离、有效射程或弹道归零距离。

用户确认的是这个数据表示。点在何时生成、保持或重建属于 §4.4 的工程实施约定；不能把当前渲染路径每帧改写 aimPoint 的机制视为必须保留的行为。

### 2.7 鼠标轴由观察方式定义

用户明确了固定炮镜的操作含义：水平鼠标控制方向机平转，竖直鼠标控制高低机。车体侧倾时，固定炮镜画面本身随机构倾斜，输入以机构局部轴为准；不能额外把鼠标纠正到世界水平／竖直。俯仰和偏航输入是角增量，不是屏幕像素点的平移量。

第三人称使用自身观察姿态定义的鼠标转向：跟随模式更新乘坐参考中的观察角，自由模式更新世界观察目标，随后交付世界点给 WC。第三人称的水平观察旋转轴与侧倾机构的方向机轴可以不同；两种第三人称模式的完整更新流程见 §4.6。

“按屏幕方向符合直觉”在本方案中指上述两种具体操作规则，不要求屏幕标记做严格的水平／竖直像素平移。禁止把独立稳定摄像头的观察轴规则套到随炮管的固定炮镜上。

## 3. 职责与类型组织

### 3.1 实体视点的三类结构

实体观瞄以是否拥有独立观察转轴划分。这是本轮重构的必做结构，不能只修改 CameraController 的条件分支或网络包来宣称完成：

```text
AbstractViewpointSubsystem
├─ FixedViewpointSubsystem       固定光轴、观察口、随炮管的炮镜
└─ RotatableViewpointSubsystem   独立转轴、车长镜、可转观察摄像头
```

| 类型 | 状态与行为 | 边界 |
| --- | --- | --- |
| AbstractViewpointSubsystem | 设备身份、生命周期、挂载描述、光学配置、发现、HUD 公共契约；提供可采样的观察位姿 | 不假定所有设备都有 yaw/pitch、转动行程或跟踪电机 |
| FixedViewpointSubsystem | 按所属 SubPart 与 locator 的完整真实姿态生成观察位姿 | 没有独立观察 yaw/pitch；鼠标输入转交瞄准目标逻辑，不直接旋转画面 |
| RotatableViewpointSubsystem | 描述独立转轴、安装参考、行程、转速和观察稳定能力；客户端运行状态保存实际局部角与观察意图 | 挂载参考由设备安装定义，与操作者座位位置无关；不要求额外刚体 |

公共基类沿用 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/BasicSubsystem.java#BasicSubsystem` 的设备生命周期并实现 `src/main/java/io/github/sweetzonzi/machine_max/common/visual/IHudHost.java#IHudHost`；纯观察数学放在独立计算模块。固定式和可转式作为平级运动能力分支，各自通过对应的属性与工厂创建，不用继承可转式来复用固定式所需的光学或 HUD 功能。

固定式的“固定”表示相对绑定机构固定。炮管运动时，绑定炮管的炮镜随真实炮管运动；独立的武器期望目标允许领先这条实际光轴。可转式在无稳时保存相对观察意图，在稳定时保存世界观察意图并解出局部角；每个模式只设一个权威意图，不能让局部角和世界目标各自独立累计。

分划与归零能力可独立组合，设备是否具有分划不决定它是否具有自由转轴。固定炮镜的瞄准稳定配置用于武器目标保持；可转摄像头的观察稳定配置用于自身光轴控制。两类配置必须有明确归属，不能因字段同名而共用一份隐含语义。

### 3.2 属性、发现与现有类型的迁移边界

静态属性与动态属性都需要与运动能力对应。公共属性提供安装与光学配置；固定式属性提供实际光轴绑定与瞄准配置；可转式属性提供独立转轴、行程、转速和观察稳定配置。个人变焦偏好放在视角会话，设备观察状态与个人显示偏好分别持有。

本轮可转设备的实际局部 yaw/pitch、观察目标、稳定求解缓存均保存在客户端运行状态中，按设备稳定身份索引，例如装配体 UUID、Part／SubPart 身份和子系统名的组合。共通子系统及属性类提供配置和设备身份，不引用客户端类，不把这些观察角字段注册成服务器同步属性。动态属性继承关系的分拆只处理该层实际需要的设备数据，不能为了类名对称而制造同步角字段。客户端缓存的生命周期见 §4.7；后续同步 TODO 见 §9。WC 的机构目标与武器实际运动依照 §5 在服务端处理。

SightSubsystem 表示固定式分支，CameraSubsystem 表示可转式分支；子系统、静态属性和动态属性三处均使用公共视点基类。内容包里的 sight 类型可能用于车长镜，逐设备分类规则见 §10；不能仅凭名称决定运动能力。

发现列表、活动实体视点、切换和 HUD 公共调用都依赖 AbstractViewpointSubsystem；只有转动控制读取可转式能力。需要检查 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/AbstractControllableSubsystem.java#discoveredCameras`、`src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/AbstractControllableSubsystem.java#activeCamera` 及 `src/main/java/io/github/sweetzonzi/machine_max/client/input/CameraController.java#activeCamera` 的类型假定。公共层及固定式不能为满足调用方而提供无效的转轴字段。

### 3.3 第三人称虚拟视点与共用计算

第三人称由客户端的 ThirdPersonViewpoint 持有观察状态与跟随策略，不注册为实体子系统，不创建刚体。它与可转实体摄像头复用无世界／无活体刚体依赖的观察角更新和旋转合成函数；CameraSubsystem 保存观察区间起点的 Vec2 实际局部角、无稳相对目标、稳定世界点和区间时长。逻辑 tick 提交区间终点，刻内采样用本次挂点与世界目标求方向，并以转速乘刻内时间限制可达转角。采样只读，稳定轴的视野不由两份缓存局部角插值产生。

共用计算接收不可变参考位姿和输入，返回逻辑观察结果。第三人称的位置轨道、距离与相机碰撞在客户端计算，姿态跟随参考只能取乘坐刚体及座椅固定挂点。实体摄像头使用自己的安装参考，两者不能共享一份全局静态角度缓存。

CameraController 的职责是选择活动视点、路由输入、调度逻辑更新、发布／读取位姿快照及应用显示效果。设备观察状态由 CameraSubsystem 字段持有，第三人称状态由 ThirdPersonViewpoint 持有，武器期望状态由瞄准控制持有。渲染不得隐含推进其中任何一个状态。

### 3.4 控制职责及状态归属

| 职责 | 持有的状态与工作 |
| --- | --- |
| 视角路由 | 当前操作者、活动视点、控制组和输入模式 |
| 第三人称虚拟视点 | 跟随／自由模式，相对观察角或世界目标，乘坐参考与逻辑观察位姿；不读取武器拓扑 |
| 实体视点 | 自身安装参考与光学配置；固定式采样真实光轴，可转式观察角保存在每个 CameraSubsystem 实例内 |
| 输入映射 | 灵敏度、变焦缩放、鼠标输入到统一瞄准增量的转换 |
| 瞄准目标状态 | 世界目标、无稳轴绝对相对角和当前机构执行角 |
| 机构几何适配 | 参考基座、关节轴、零位、符号、正解／反解、机械限位 |
| WC | 消费瞄准意图、保持目标、解算并派发机构目标 |
| 执行机构 | 按实际转速、力矩及关节约束追赶目标 |
| 视点渲染 | 采样实际光轴或摄像头局部姿态，合成最终画面 |
| HUD | 投影期望目标圆圈和实际光轴分划；不提供机械限位或追赶不足告警 |

视角／观瞄模式选择武器的瞄准保持规则；WC 执行该规则。摄像头自身的转轴稳定由摄像头姿态控制负责。

## 4. 坐标与公共输入更新

### 4.1 炮镜输入与执行器几何的职责边界

固定炮镜通过所属 SubPart 与 locator 提供完整实际位姿、光学和保持模式。`src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/SightSubsystem.java#onPostPhysicsTick` 在物理线程取得主 WC 的机构采样，发布几何及同一步的实际角；主线程和 HUD 只读取快照。实际画面始终取公共视点的真实挂点。

WC 沿 control_outputs 握手发现全部驱动器。稳定轴由各驱动器的 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/TurretDriverSubsystem.java#computeAimAngles` 对世界点求角；无稳轴由同一方法的 Vec2 重载转换操作者的绝对相对角。机械参考、原生符号、行程与转速属于执行器。座椅、WC 或炮镜的安装位置不替执行器定义参考。

座椅经 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/AbstractControllableSubsystem.java#getActiveMainWeaponController` 从当前控制组已发现的控制器中，按主武器开火频道选出有效主 WC。`src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/WeaponControllerSubsystem.java#sampleAimGeometry` 从 control_outputs 握手结果选择高低机及支承同一炮塔的方向机，优先直接驱动炮镜宿主的机构；间接挂载采用首套有效机构。座椅可以安装在炮塔、车体或其他部件上，其朝向不参与机构角推算。多执行器的实际控制分发覆盖全部握手机构，不受这项观察参考选择影响。

### 4.2 固定炮镜的公共输入：俯仰／偏航角增量

输入入口为 `src/main/java/io/github/sweetzonzi/machine_max/mixin/MouseHandlerMixin.java#beforeTurnPlayer` 和 `src/main/java/io/github/sweetzonzi/machine_max/client/input/CameraController.java#turnCamera`。上游已处理 Minecraft 基础灵敏度及反转鼠标；此处只转换单位并按倍率缩放：

```text
s = radians(0.15) / max(currentZoom, 0.1)
deltaPitch = -s * 鼠标向下量
deltaYaw   =  s * 鼠标向右量
```

角度和增量统一使用 Vec2，x=pitch、y=yaw，单位为弧度；正 pitch 抬高、正 yaw 向右。水平和垂直输入各处理一个分量，不通过机构轴向推断鼠标语义，也不因画面地平线倾斜混合输入分量。

切入固定炮镜或切换主 WC 时，相对目标从该 WC 的实际方向机／高低机角初始化，随后累计接受的鼠标输入。无稳轴将目标相对实际角的累计偏差限制在 ±60°，连续偏航在当前目标附近解释 native 角度分支并保留累计圈数。机械行程由关节约束处理，客户端不读回机械边界。采样未就绪时显示真实挂点，等待采样后再发送无稳目标。

### 4.3 世界点与累计角

`src/main/java/io/github/sweetzonzi/machine_max/common/mech/control/aim/AimTargetState.java#AimTargetState` 由客户端主线程持有，仅保存保持模式、有限世界点和操作者累计角。它不保存机构执行解或 native 引用。

稳定轴在实际光轴参考中更新保存的世界点，按 §7.1 的 30°光学领先量过滤新输入。无稳轴从机构实际角初始化，累计目标相对实际角的偏差按 ±60°过滤；两者使用同一基础灵敏度。全无稳模式在逻辑更新时，以当前机构基座与累计目标正解光轴，生成该光轴前方 1000 米的世界点，使输入、瞄准圈和机构目标具有相同参考。

```text
收到输入：
    offset = 保存世界点在当前光轴参考内的俯仰／偏航
    accepted = 分轴处理本次输入；稳定轴限光学领先，无稳轴限累计机构偏差
    relativeAim += accepted
    worldPoint = 当前观察原点 + rotate(当前光轴, offset + accepted) × 1000
没有输入：
    保留 relativeAim
    含稳定轴：保留稳定世界参考
    全无稳：按当前机构几何正解 relativeAim，更新 worldPoint
每物理步：
    稳定轴：各驱动器分别根据 worldPoint 求绝对目标
    无稳轴：各驱动器直接使用 relativeAim 的对应分量
```

全无稳世界点来自所选机构的炮镜光轴正解；混合模式的世界点供稳定轴求角。无稳电机目标直接取累计角，WC 不用该世界点重新反解无稳轴。瞄准圈按屏幕轴合成：稳定轴投影保持世界点，无稳轴投影累计机构目标，并以本次实际角填充其稳定分量。无稳投影先取得目标相对采样实际光轴的偏差，再以本帧显示光轴为参考，消除采样与渲染插值的时差。机构追赶后，无稳轴圆圈回到实际光轴中心。

### 4.4 1000 米点的生命周期

| 时机 | 处理 |
| --- | --- |
| 首次接管且没有继承点 | 稳定轴从真实光轴生成首点；无稳相对目标从主 WC 的实际机构角初始化 |
| 固定炮镜收到接受的鼠标输入 | 按 §4.3 在光轴参考内更新指向并生成 1000 米点 |
| 固定炮镜逻辑更新 | 全无稳世界点随当前机构基座正解；稳定参考点及累计目标保持；渲染只读 |
| 固定炮镜切换 | 稳定轴继承世界点，无稳轴从所选主 WC 实际角初始化；画面使用新挂点 |
| 第三人称跟随 | 按当前乘坐参考和相对观察角生成 1000 米点 |
| 第三人称自由零输入 | 保留有限世界点，观察位置运动允许视差 |
| 可转摄像头输出 | 以实际逻辑光轴生成 1000 米点，与自身尚未追到的期望角区分 |

稳定模式保持有限世界点；观察原点随后移动时，不要求它与新原点仍恰好相距 1000 米。显示抖动和渲染采样不能修改该点。

### 4.5 单轴稳定由 WC 分轴分发

| 配置 | 稳定轴 | 无稳轴 |
| --- | --- | --- |
| 仅垂稳 | 各高低机根据世界点求俯仰 | 各方向机接收操作者累计偏航 |
| 仅水平稳定 | 各方向机根据世界点求偏航 | 各高低机接收操作者累计俯仰 |

WC 不把稳定轴的求角结果再次叠加鼠标量，也不把一个执行器的目标复制给其他机构。操作者操作任一轴时更新共同世界参考方向；零输入时保持参考点和累计角。真实负载、侧倾及受阻时的追赶表现按 §8.2 验收。

可转摄像头的单轴观察稳定属于本机观察控制，可以使用自身挂点与观察行程做局部求解；该设备向武器输出时统一使用当前逻辑光轴的世界点，relativeAim 为零。该路径不要求固定炮镜了解武器驱动几何。

### 4.6 第三人称两模式的状态、更新与发送

本节描述第三人称参与武器瞄准时的路径。普通座椅第一人称的工程基线为乘坐参考内的自由观察，以当前逻辑视线生成世界点，两轴relativeAim 为零；该姿态规则依据 `src/main/java/io/github/sweetzonzi/machine_max/client/input/CameraController.java#updateCameraPos` 的第一人称分支。其进入／退出也遵守 §4.7，不额外定义一种稳定器模式。暂时只观察、不控制武器的操作与跟随／自由模式分别表示，不能把 `src/main/java/io/github/sweetzonzi/machine_max/client/input/RawInputHandler.java#freeCam` 直接当作自由模式开关。

| 符号 | 定义 |
| --- | --- |
| RSeat | 当前乘坐刚体世界旋转与座椅固定挂点旋转的合成；包含完整姿态，不查询武器控制器或装配体中的其他参考体 |
| qLook / RLook | 玩家相对乘坐参考的观察 yaw/pitch 及其旋转；只由鼠标或明确的观察初始化修改 |
| O | 当前逻辑观察原点，由第三人称位置、环绕距离和碰撞策略产生；不含显示抖动，与方向使用同一逻辑快照 |
| F0 | 观察模型的单位前向，经边界适配映射到引擎的相机前向 |
| PWorld | 自由模式持久保存的世界目标；跟随模式中为本次逻辑更新的输出 |

跟随模式每次逻辑更新：

```text
1. 消费鼠标输入，按自身观察轴更新 qLook，得到 RLook。
2. 读取当前乘坐参考 RSeat。
3. RWorld = RSeat × RLook；FWorld = RWorld × F0。
4. 用同次逻辑观察姿态得到 O，写出 PWorld = O + 1000 × FWorld。
5. 发布观察快照和世界目标；需要发送时，两轴采用世界点控制，relativeAim 为零。
```

这里的乘法为旋转合成，不是把世界欧拉角逐项相加。鼠标改变 RLook，乘坐运动改变 RSeat；两者在相机侧各计入一次。不能把乘坐刚体转角再伪造成鼠标增量，也不能在 WC 端额外叠加这次转角。没有鼠标输入时，步骤 2—5 也执行；目标发生有效变化时须进入发送路径，不能仅由鼠标事件触发发包。网络频率受客户端逻辑更新约束，不依赖渲染调用次数。

水平例子忽略观察点与炮塔原点的偏置，约定向右为正：

| 情况 | 乘坐刚体世界偏航 | 相对观察偏航 | 世界观察／瞄准偏航 |
| --- | --- | --- | --- |
| 初始化 | 0° | 20° | 20° |
| 鼠标不动，乘坐刚体右转 10° | 10° | 20° | 30° |
| 鼠标再向右输入 5° | 10° | 25° | 35° |

第二行的世界目标已经包含乘坐旋转，第三行已经同时包含乘坐旋转与鼠标输入。两行发往 WC 的 yawDelta/pitchDelta 都是 0。玩家坐在车体上时，炮塔自身追赶不会修改该乘坐参考，所以不会通过这条逻辑链继续推动世界目标。

自由模式在无鼠标输入时保存 PWorld，按当前 O 指向该点；不把 RSeat 的变化乘到世界观察朝向上。收到鼠标输入时，从保存点与 O 求当前逻辑观察方向，按该视点自身观察轴施加角增量，写回方向前方 1000 米的点，然后发布位姿和世界目标。乘坐参考只服务于位置随动，不参与自由模式的观察旋转输入。世界点保持造成的平移视差见 §4.4。

跟随／自由是观察状态的保持策略，两种模式都选择 WC 的两轴世界点分支。若沿用现有 verticalStabilized/horizontalStabilized 协议字段，两者都传 true/true；该值只表示接收端持续解算世界点，不得被客户端用于把跟随模式强制变为自由模式。WC 的世界点消费契约见 §5。

内容定义以座椅为单位配置模式，玩家覆盖入口沿用 `src/main/java/io/github/sweetzonzi/machine_max/common/attachment/ControlPreference.java#shouldFollowPose` 的优先级。`src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/attr/static_attr/SeatSubsystemStaticAttr.java#ViewAttr` 中的 follow_vehicle 表示乘坐姿态跟随；保留字段兼容时也必须按这个语义解释。一般车辆驾驶座默认跟随，坦克武器操作座默认自由，不创建自动识别车种或寻找武器基座的流程。仅跟随偏航、自动保持地平线水平不是本轮跟随模式的含义。

若座位在受控炮塔上，跟随模式的观察方向会包含炮塔实际转角；叠加非零观察偏角并持续驱动该炮塔时，会产生 §6 的固定偏角自追。此时内容默认值采用自由模式。玩家强制跟随不获得“任意拓扑都能安全连续联动”的保证；执行者不得静默切换参考刚体或推导另一套拓扑补偿算法。

模式切换时按 §4.7 将同一目标转换为相对观察角或世界点，切换本身不产生鼠标增量。目标继承发生一次，后续逻辑更新遵守目标模式的保持规则。

### 4.7 视角切换继承目标与客户端状态生命周期

观察切换按切出来源的世界点初始化新观察，固定炮镜的稳定轴继承该点。固定炮镜无稳轴以主 WC 实际机构角建立一次性初值，后续输入累计在此基础上。下一次上报携带完整目标；网络和物理线程都按值覆盖，不重放鼠标增量。

从固定炮镜或第三人称自由切出时，继承其当前世界点；第三人称跟随使用当前逻辑输出点，可转摄像头取正常瞄准输出点。定义上述结果为 PInherited。主 WC 或固定炮镜切换后，无稳输入等待相应机构采样就绪。

下表是落实目标继承的工程约定，具体区分目标转换与实际画面初始化：

| 切入模式 | 一次性的目标初始化 |
| --- | --- |
| 固定炮镜双稳 | PWorld = PInherited；实际画面直接取真实炮镜位姿，不能旋转画面去对齐目标 |
| 固定炮镜双轴无稳 | 从主 WC 方向机／高低机实际角初始化累计目标，并由机构正解世界点 |
| 固定炮镜单轴 | 稳定轴保留 PInherited；无稳轴从主 WC 实际角初始化，随后直接采用累计值 |
| 第三人称自由 | PWorld = PInherited，逻辑观察朝向指向它 |
| 第三人称跟随／普通座椅第一人称 | 以切入观察原点指向 PInherited，将方向转换到当前乘坐参考，得到 qLook；随后按跟随规则生成 1000 米点 |
| 可转摄像头 | 以切入挂点指向 PInherited，初始化观察意图并解局部角，稳定轴保存世界参考、无稳轴保存相对角；切入时将本地观察姿态对齐该可达方向，后续按自身转速和行程推进 |

对于可转摄像头，切入时的本地姿态对齐是观察状态初始化，不驱动额外刚体。缓存中的观察角不能覆盖可继承的目标。受行程约束无法对准时采用最近的可达角；下一次正常输出就是实际逻辑光轴，不为此添加暂停输出或提示。切入固定炮镜时，实际画面与继承目标存在差距属于正常追赶。

世界点继承保持稳定轴及观察视点的指向意图；使用相对角或重新生成 1000 米点的模式可能改变点的距离，可达范围也可能裁剪方向。固定炮镜无稳轴采用表中规定的实际机构角初值。输入领先上限只约束后续鼠标输入，不裁剪稳定轴继承的世界点。

仅在没有有效继承目标时，按设备缓存的有效观察状态初始化；缓存也不存在时，使用当前真实光轴或设备默认角生成首个目标。暂时只观察时可以独立更新观察缓存，但恢复武器控制时继承该控制来源保持的瞄准目标，不把临时观察方向悄悄当作一次目标指示。

CameraSubsystem 实例直接保存可转观察状态；非活动设备不消费鼠标，已有目标按逻辑 tick 推进追赶与稳定，下一次进入按本节初始化。设备销毁、离开当前世界、断线后，观察状态随设备实例释放；仅切换视角不清空其他设备实例的字段。不同客户端各自持有状态，本轮不保证多名观察者看到相同的镜头角度，也不建立共享镜头控制权协议。

同一操作者切换控制组输出频道也继承自己的当前目标，并释放切出频道；车长／炮手之间因优先级变化而选中另一来源时，各来源按 §5—§6 保持自身目标，不将一人的目标复制给另一人。离座、断线或来源失效时释放输出，继承规则不允许失效来源继续占据频道。

## 5. 输入包、目标保持与线程

客户端按采样顺序累计鼠标输入，网络只传完整瞄准目标。`src/main/java/io/github/sweetzonzi/machine_max/network/payload/ViewInputPayload.java#ViewInputPayload` 是唯一的观瞄目标载荷，字段如下：

```text
subPartId/subSystemName   操作者所在座椅
viewPartId/viewName       活动设备；-1/seat 表示座椅虚拟视点
controlGroup             当前控制组索引
aimPoint                有限世界目标点，三个 double
relativeAim             无稳轴的绝对相对目标角，Vec2，弧度，x=pitch、y=yaw
```

服务端校验座椅乘客、控制关系、控制组、设备发现与装配体归属、设备有效性及数值有限性。固定炮镜的保持模式由服务端设备配置解析；第三人称和可转摄像头均使用世界点模式，relativeAim 为零。跟随／自由属于客户端的观察规则，WC 不查询乘坐刚体或重复合成观察目标。

固定炮镜每次上报世界点及无稳轴绝对角。稳定轴从世界点解算，无稳轴直接采用 relativeAim 对应分量并执行机械限位；不能把 relativeAim 当增量再次累计。多个鼠标采样依次经过灵敏度、稳定轴 30°光学领先或无稳轴 60°累计偏差过滤。每 tick 发送完整结果，保留触及输入边界后反向的逐采样顺序。

`src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/AbstractControllableSubsystem.java#setViewInputSignal` 按当前控制组向目标发送同一份不可变 ViewInputSignal。WC 按 control_outputs 的既有握手发现执行器，可同时控制任意数量的方向机和高低机；稳定轴由每个执行器使用自己的参考、枢轴对世界点求角，无稳轴采用对应分量的绝对相对角目标。主 WC 额外提供输入初始化与瞄准圈所需的物理几何采样，没有内容包主方向机、高低机或炮镜绑定字段，也没有逐关节网络数组。

主线程和物理线程的职责如下：

```text
客户端：逐采样更新期望目标，每 tick 上报完整目标
服务端主线程：校验来源，按控制组派发不可变目标值
服务端信号频道：按发送者保存完整不可变目标
每个物理步：
  按现有 aim_inputs 顺序选择当前有效来源
  遍历 control_outputs 握手发现的全部执行器
  各执行器的稳定轴独立对世界点求角，无稳轴直接使用绝对角目标
  派发每个关节的目标，执行机构按自身行程与转速追赶
```

服务端主线程通过现有 ConcurrentHashMap 信号频道发布完整不可变 ViewInputSignal，物理线程直接读取当前值；`src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/WeaponControllerSubsystem.java#selectAimInput` 按 aim_inputs 取有效来源。每份值包含世界点、无稳轴绝对角与模式，不需要专用任务投递、网络会话序号、去重表或确认重放。重复上报同一值、一个目标运行多个物理步，都不会再次累计角度。

多来源竞争遵循 §6 的信号优先级。信号频道按发送者保存各自的完整目标，低优先级来源可以持续更新自己的值；切回时直接采用当前有效来源的目标。切换控制组、离座和设备失效通过空信号释放；服务端拒绝当前控制关系或控制组不匹配的载荷。WC 不把低优先级输入累计到高优先级目标，不保存第二套来源目标缓存。

HUD 使用客户端当前期望目标；实际炮镜光轴使用服务器机构的插值快照。服务器负责实际机构和开火判据，执行自身的机械行程限制；没有额外的目标确认校正。真实网络延迟下的目标圆圈与实际机构误差列入 §8.2 的客户端验收。可转摄像头观察角同步属于 §9 的后续 TODO。

世界坐标先做双精度差值，再按物理库需要转换。跨线程以完整不可变值交付模式、世界点和相对角，不能用多个独立 volatile 字段拼接不同次输入。客户端帧率变化时，未触及限位的相同累计鼠标角位移必须得到相同相对目标。

## 6. 可转摄像头联动与控制组优先级

CameraSubsystem 的客户端实例持有观察区间起点的实际局部角、无稳相对目标、稳定世界参考点及区间时长，并受自身转速与行程约束。稳定轴在行程和补偿转速允许时直接对准世界点，超限时视野按可达方向拉偏；双稳镜头的世界朝向合成与第三人称自由观察一致。本轮观察角无需服务端持有或同步；双端共通类型及缓存边界见 §3.2、§4.7。

所有可转摄像头按同一流程输出：先更新自身观察姿态，取当前逻辑光轴的原点 OCamera 和前向 FCamera，生成 OCamera + 1000 × FCamera；经控制组的视角输出接线交付 WC，两轴均选择世界点分支、relativeAim 为零。这里的逻辑光轴是镜头自身转速／行程执行后的观察方向，尚未追到的摄像头理想观察方向不能直接冒充可见方向。显示抖动不进入输出；没有火控接线时信号不会驱动武器。

镜头双稳、单轴、无稳只影响自身观察姿态的保持和更新，不改变上述输出路径。无稳镜头也正常发布瞄准信号，代码不依据稳定配置或挂载拓扑自动拒绝、暂停、切换参考体或抵消安装体的转动。

无稳摄像头相对炮塔保持一个非零偏角，同时要求炮塔持续瞄准该摄像头，会形成自追：设车体角为 h、炮塔相对角为 t、镜头相对炮塔角为 c，镜头世界角为 h+t+c；炮塔相对目标为 t+c，误差始终为 c。

本轮支持观察与持续瞄准输出，不实现一次性目标指示、目标移交包或车长专用的超控仲裁器。车长超控通过控制组切换输出频道，复用已有优先级：

| 状态 | 车长输出 | WC／执行机构采用的来源 |
| --- | --- | --- |
| 常态备用 | 低于炮手的备用瞄准频道，或仅观察、不输出瞄准 | 有效炮手信号优先；炮手无有效信号时可采用备用来源 |
| 临时超控 | 切换到高于炮手的瞄准频道，持续发送车长目标 | 有效高优先级车长信号覆盖炮手 |
| 结束超控 | 释放高优先级输出，切回低优先级备用控制组 | 恢复当前最高优先级有效来源；不把车长目标锁存成一次指示 |

示意顺序为 `车长超控 > 炮手 > 车长备用`，具体频道名由内容包声明，不是内置身份或网络包里的优先级数值。不同观瞄各自维护观察与目标状态；优先级决定当前哪个来源驱动武器，不要求车长与炮手共享一份可互相覆盖的输入累计量。

现有接线与检查入口：

- `src/main/java/io/github/sweetzonzi/machine_max/common/mech/control/ControlGroup.java#viewTargets` 指定各组的视角输出频道和接收者。
- `src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/WeaponControllerSubsystem.java#selectAimInput` 按 aimInputs 的声明顺序选择有效瞄准频道。
- `src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/TurretDriverSubsystem.java#getTargetAngle` 按 controlInputs 的声明顺序选择有效机构目标；`src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/TurretDriverSubsystem.java#setTargetAngle` 接收 null 表示释放该频道。
- `src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/AbstractControllableSubsystem.java#clearInputSignals` 发送空信号以释放当前控制组的输出。切换控制组、离座、断线及设备失效时需确认高优先级信号和对应机构目标不会残留；仅停止发包不等于释放已保存信号。

优先级通过不同频道及接收方声明顺序表达。同一频道内的发送者由 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/signal/SignalChannel.java#SignalChannel` 保存，不能把其 Map 遍历顺序当作车长／炮手优先级。P0 应核对实际内容包的竞争层级：同一 WC 的输入优先级，或多个 WC 的执行机构优先级；按对应层级验证有效来源选择和释放，不构造第二套抢占系统。

信号优先级解决来源竞争，固定偏角自追由安装与用途约定避免：无稳摄像头应安装在车体等不会被其火控输出带动的参考体上，或只作观察、不给武器配置接线。稳定车长镜可以安装于炮塔并输出持续目标。内容作者需要核对参考体是否会被这份输出带动；本轮不实现拓扑检测或运行时防自追功能。多人客户端的镜头缓存互相独立，只有武器控制信号通过现有优先级竞争；共享镜头角度同步属于 §9 的后续 TODO。

## 7. 视点挂载、限位与 HUD

固定炮镜挂载到实际光轴所在的 SubPart，locator 同时确定位置与旋转。子系统配置节点和模型 locator 的骨骼归属必须一致；直接使用现有挂载关系，无需额外刚体或位置／朝向绑定字段。

内容包迁移必须逐设备核对光轴来源。例：`src/main/resources/spark_modules/Machine-Max_2S38/machine_max/parts/2s38_turret.json` 的 gunner_sight 位于炮管 SubPart，commander_sight 位于炮塔 SubPart；挂点变换使用各自宿主。仅改变 Java 继承关系不能使炮塔挂点自动随炮管俯仰。

### 7.1 机械范围与输入累计上限

四类范围分别定义：

1. 光学 FOV：单幅画面的可见角度。
2. 摄像头转轴行程：镜头相对挂点可转范围。
3. 武器机械行程：真实关节可达范围。
4. 输入领先范围：稳定轴的世界点方向相对当前光轴的可接受新输入范围，不是关节转过的总角度。

稳定轴的工程初值为每轴 `MAX_INPUT_LEAD_RAD = radians(30)`，无内容包配置或 UI。以保存世界点在当前光轴参考中的偏角为 e、L 为上限，只限制本次鼠标增量：

```text
lower = min(0, -L - e)
upper = max(0,  L - e)
acceptedDelta = clamp(rawDelta, lower, upper)
```

例如稳定偏角 28°、向外输入 5°，只接受 2°；到 30°后向外输入被拒绝，反向输入立即生效。既存目标领先 40°时，零输入保持该目标，向外输入被拒绝，反向输入逐步减小领先。机构追赶改变实际光轴，因此会释放输入余量。

无稳轴采用相同的增量过滤公式，e 为累计目标减去实际机构角，L 为 60°。偏航实际角先换算到累计目标附近的等价分支，因此限制的是未追上的偏差，炮塔仍可连续转过多圈。客户端不裁剪机械行程，机械止挡处允许积累最多 60°余量；反向输入需要退掉越界目标后机构才能离开止挡。服务端覆盖完整目标，不重复过滤或累计同一份输入。

第三人称与可转摄像头按自己的观察行程更新，不按武器追赶误差限幅。可转镜头的观察数学可以读取本机期望角和实际角，与固定炮镜的机械执行职责区分。

### 7.2 目标投影与显示边界

HUD 分别读取期望目标和实际光轴，使用同一帧的相机变换投影。固定炮镜分划与实际光轴一致，目标圆圈随真实追赶靠近分划。目标在画面外、相机后方或无法投影时，本轮跳过圆圈绘制，不设计额外方向箭头。机械限位、目标不可达、镜头或武器追赶不足均不提供告警或专门提示；这些限制不影响真实执行约束。镜头抖动属于显示效果，不能回流到瞄准输入。

| 视角切换 | 按 §4.7 继承目标；固定炮镜画面显示真实光轴，相对角模式转换目标表示，不以实际追赶状态清零目标 |
| 输入限幅与 HUD | 稳定轴按 30°光学领先、无稳轴按 60°累计机构偏差过滤新输入；圈的对应轴分别投影世界保持目标与累计机构目标；机械行程由执行器处理，无限位或追赶不足告警 |
| 网络延迟、视角／控制组切换 | 完整目标覆盖不产生重复累计；服务端拒绝不匹配的来源与控制组，目标圆圈与机构误差按动态场景验收 |

## 10. 迁移说明

§1 的历史快照记录了迁移基线。当前实现以设备实际光轴显示固定炮镜，输入目标由客户端预测与服务端物理状态分别持有；渲染只读目标。设备与座椅迁移清单见实施记录 §4。

内容 id 保持稳定；camera 表示可转设备，sight 表示固定设备。2S38、K17 的车长镜定义和安装项均使用 camera。固定式解析时忽略观察行程字段，每个执行器按自己的关节机械边界执行，炮镜输入参考从实际光轴的关节关系采样；具体默认值及协议组版本见实施记录 §3—§4。

继承关系的迁移同时覆盖 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/SightSubsystem.java#SightSubsystem`、`src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/attr/static_attr/SightSubsystemStaticAttr.java#SightSubsystemStaticAttr` 和 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/attr/dynamic_attr/SightSubsystemAttr.java#SightSubsystemAttr`。已有 sight 配置中的武器瞄准稳定与 camera 配置中的观察稳定需要逐项确定语义；不能把固定式缺失的观察行程补成一套无效状态来维持继承。

第三人称沿用逐座椅配置和玩家覆盖的来源。保留 follow_vehicle 字段时解释为乘坐姿态跟随；若调整字段名称或使用枚举，codec 必须显式读取兼容值。内容迁移清单逐座椅记录乘坐 SubPart、用途和默认模式，不给整个载具设置一个掩盖座位差异的自动分类结果。

### 11.9 必须写清预期结果的测试表

上述数值容差用于输入累计、有限点正反解和状态一致性；单轴受限近似按 T18、T19 的可控效果与连续性验收，不要求达到真实稳定器或全局最优解的数值精度。优先级测试使用显式初始化的来源目标，视点／控制组切换时的目标继承按 §4.7。稳定轴连续输入测试要推进实际光轴或比较过滤后的输入；无稳轴累计值由执行器独立限位。
