# Machine-Max 渲染 — 屏幕空间光照物理化设计

> **状态**：提案，未实现（2026-10-17）。当前落地的是"发光叠加"：通用光照链把每条光源的 `color × intensity × (1 − d/R)²` 逐像素求和、截到 1，再与画面做 screen 混合（`shaders/program/screen_space_light.fsh`）。本文给出物理模型、在只有颜色与深度的链里可达的近似、标定方法、分阶段改动与验收判据；实施后由本文的算子替换该混合。
>
> **本文自包含**：符号、公式、参数默认值与判据都在文内给出，不要求先读其他文档。引用现有代码只为定位，理解本文不需要先记住那些实现。

**术语**：E = 辐照度（照到表面上的光，单位面积功率）；L = 辐亮度（表面/空气沿视线发出的光，相机看到的量）；ρ = 反照率（表面反射比例，0–1）；I = 光源光强（本文用归一化单位，见 §4.1）；R = 剔除半径；`w` = 有限支撑窗函数。

## 1. 现状与问题

### 1.1 现行算子

```glsl
att    = (1 − d/R)²;                       // d = 表面点到光心的距离
light += color × (att × intensity);        // 逐光源求和
light  = min(light, 1);                    // 硬截断
out    = src + light × (1 − src);          // screen 混合，sRGB 显示空间
```

一条光源贡献的是**与表面无关的常数 RGB**：不知道表面反照率、不知道法线、不做 `1/d²`、不在线性空间、没有色调映射。

### 1.2 三个可量化的缺陷

| 缺陷 | 数学原因 | 观感 |
| --- | --- | --- |
| 衰减形状是"平板" | `(1 − d/R)²` 在 `d = R/2` 时恒为 0.25，与大半径配对时整片区域亮度几乎不随距离变化 | 大范围均匀发亮，没有"光池"的层次 |
| 合成算子压低对比 | `out = src + L(1 − src)`：暗像素吃满 L、亮像素几乎不变，加一次就把动态范围向 1 压缩 | 纹理细节被抹平，像刷了一层漆 |
| 硬截断成纯白 | `min(L,1)` 之后超出部分直接变纯白；`intensity` 越大只是白斑越大 | "更亮"表现为"更白、更大的一片白" |

补充一点色彩上的问题：`light` 是近白颜色时，R/G/B 被等量抬高；screen 混合又压缩通道差，于是**色相一起被洗掉**——红墙也会发白。物理上，白光照明提高的是亮度，色相由反照率保持不变。

### 1.3 信号弹的计算实例（`flare_illum`：R = 40 m，intensity = 1.8，color ≈ (1.00, 0.93, 0.80)）

信号弹悬在 20 m 高时，正下方地面 `d ≈ 20`，`att = (1 − 0.5)² = 0.25`，于是

```text
L ≈ 0.45 × (1.00, 0.93, 0.80) = (0.45, 0.42, 0.36)
```

- 影响球落在地面上是一个半径 `√(40² − 20²) ≈ 34.6 m` 的圆盘，中心 0.45、边缘 0——**大面积近似均匀**。
- 夜间地面 `src ≈ 0.04 ~ 0.12`，叠加后 `out ≈ 0.47 ~ 0.50`：纹理对比从 0.08 压到 0.03。
- 近白光色 + screen 混合：地面上任何颜色都被推向同一种淡黄灰。

这就是"被涂白"：它不是亮度高，而是**对比与色相同时丢失**。

### 1.4 枪口火光的对照（120 mm：R = 20 m，intensity = 2）

| d (m) | `att` | `L` | 结果 |
| --- | --- | --- | --- |
| 2 | 0.81 | 1.62 | 截断 → 纯白 |
| 5 | 0.56 | 1.13 | 截断 → 纯白 |
| 10 | 0.25 | 0.50 | 半亮 |
| 20 | 0 | 0 | 无 |

炮口周围是"纯白圆心 + 一圈过渡到 0.5 的盘"，不是"离得越近越刺眼、向外平滑衰减的光池"。

## 2. 物理模型

点光源在表面点 P 处产生的辐照度：

```text
E(P) = I · max(cos θ, 0) / d²        θ = 表面法线与入射方向夹角
```

漫反射（Lambert）表面的出射辐亮度：

```text
L = (ρ / π) · E
```

相机看到的最终值是曝光与色调曲线的结果：`display = tonemap(exposure · L)`。空气里看到的光晕是**散射**，沿视线积分：

```text
L_air = ∫ σs · p(θ) · I / d² ds
```

这四项里，我们手上只有 depth（→ 表面点 P 与距离 d）。缺：

| 量 | 现状 | 影响 |
| --- | --- | --- |
| 法线 | 可从深度重建（设计里叫 S4，当前未做） | 缺 `cos θ`，地面与竖直墙面吃到的光一样多 |
| 反照率 ρ | 最终颜色里与已有光照乘在一起，无法分离 | 无法"让白墙亮、黑墙暗"，这是根本限制 |
| 曝光 | 画面已经被原版渲染器曝光并编码 | 新增光只能以"增量"形式叠加，不能重新曝光整帧 |

因此**在这条链里做不到物理正确的表面光照**；能做的是采用"物理形状 + 合理近似"的算子，让结果在观感上符合物理直觉。

## 3. 可达近似

### 3.1 在线性空间里做

`src` 是 sRGB 编码的显示值。与光照相加必须在线性辐射度上进行：

```glsl
vec3 C = pow(src.rgb, vec3(2.2));     // 近似 sRGB → linear，或精确分段函数
...                                    // 增量在此空间计算
fragColor = vec4(pow(C_out, vec3(1.0 / 2.2)), 1.0);
```

未受光的像素 `E = 0` 时变换是恒等的（解码再编码只差浮点精度），因此**没有光源的地方逐位不变**。

**光源颜色同样要解码**：内容包里的颜色是 sRGB 的 `[0,255]`，直接当线性系数用会让暖色偏冷（线性 `(1, 0.85, 0.60)` 与 sRGB `(1, 0.93, 0.80)` 不是同一个颜色）。换算在来源提交时完成一次，着色器只接收线性 RGB。

### 3.2 衰减：`1/d²` + 有限支撑窗

```text
w(d) = (1 − (d/R)⁴)²        d < R 时为 1→0，d ≥ R 时为 0
E(d) = I / max(d², d_min²) · w(d)
```

- `1/d²` 给出物理的近距离陡增与远距离长尾；`R` 只承担**剔除**与**窗**，不参与亮度（修掉 §1.2 的耦合）。
- `(1 − (d/R)⁴)²` 在 `d = R` 处严格归零且一阶导为零，包围剔除不会在边界留硬边。
- `d_min`（初值 0.75 m）截住 `d → 0` 的奇点，避免光源贴在表面上时出现无穷大。

### 3.3 合成算子：乘性 + 受反照率限制的加性

三条候选各自的失败方式：

| 算子 | 问题 |
| --- | --- |
| 纯加性 `src + E` | 抬得动夜间暗面，但平等地加在所有通道上，压平细节、去饱和，且会削顶 |
| 纯乘性 `src × (1 + kE)` | 保色相、保纹理，但抬不动近黑的地面（0.03 × 2 仍是 0.06） |
| 现行 screen | 介于两者之间：压对比、去饱和，并且 `min(L,1)` 后直接变纯白 |

采用两项之和，各自负责一件事：

```text
Elum = dot(E_rgb, vec3(0.2126, 0.7152, 0.0722));      // 辐照度的亮度分量
m    = kMul · Elum / (1 + Elum);                      // 乘性项的软肩
a    = kAdd · ρ̄ · (1 − exp(−E_rgb));                  // 加性项，逐通道，带光色
C'   = C · (1 + m) + chroma(C) · a;                   // 线性空间
```

- **乘性项** `C·(1+m)`：把新增辐照度折算成"现有亮度的相对提升"，因此纹理细节、色相都保留；它对近黑表面几乎无作用，这符合"反照率低的表面确实反光少"。
- **加性项** `chroma(C)·a`：解决夜间暗面"乘性抬不动"的问题。它被 `ρ̄`（平均反射率，初值 0.25）限制，不会把表面刷成白色；`chroma(C)` 取像素自身的色度，使红墙加的是暗红、土地加的是土黄，不会统一发白。
- `chroma(C) = (C + ε) / max(C.r, C.g, C.b, ε)`，`ε ≈ 0.01`：纯黑像素也取到中性色，而不是"任何光都照不亮"。
- **色调映射只作用于增量**：`Elum/(1+Elum)` 与 `1 − exp(−E)` 在 `E → ∞` 时有界，所以高强度表现为"接近饱和"而不是硬截断；未受光像素的 `m`、`a` 都是 0，逐位不变。整帧色调映射需要 HDR 目标，当前链是 LDR，不做。
- `E` 逐光源钳到 `[0, E_MAX]`（初值 1024），兜住旧内容里的异常值，避免 `inf`。

### 3.4 本期不做、但要记住的两项

- **`cos θ`（法线项）**：需要从深度重建法线（S4）。在它落地前，地面与竖直墙面等量受光，这是已知偏差，不在本设计里假装解决。
- **光晕 / 散射**：信号弹"看起来亮"的主体应该是空气散射与镜头的 bloom，而不是把 35 m 地面刷亮。本设计只处理表面光照；光晕是独立的加法通道或后处理 pass，列为后续阶段。

## 4. 参数与标定

### 4.1 `intensity` 的语义

`I` 定义为**光源在 1 m 处的辐照度**（归一化单位，不是坎德拉）：`I = 1` 表示在 1 m 处 `E = 1`。之所以不引入真实单位，是因为这条链没有曝光量，绝对单位不可校准；取 1 m 处归一化可以保证内容数值与观感一一对应。

**内容包的 `intensity` 保持"相对亮度"的语义与数值**——仓库内与外部内容包都不需要改数。来源在提交时把它换算成 `I`：

```text
I = intensity × R² / 16
```

`R²/16` 来自 §4.2 的换算关系（旧衰减在 `R/2` 处是 0.25，除以 `(R/2)²`）。这样换算的结果是：**亮度随 R² 增长**，而枪口火光与曳光的 R 按口径线性折算，于是新强度天然按口径²增长（装药量 ∝ 炮口截面积），不需要新增字段或内容规则。

`radius` 的语义是**剔除半径 / 窗宽**，但它通过上面的换算同时承载"这个光源有多大能量"：显式把 `R` 调大的内容，会同时得到更远的光池与更高的总光通量。这是为兼容既有内容数值而保留的耦合，写在这里以免被当成物理定律。

### 4.2 换算表与推导

旧光源在 `d₀` 处的辐照度是 `i_old · (1 − d₀/R_old)²`。取 `d₀ = R/2`（旧衰减的中点，也是观感上"半亮"的位置）对齐：

```text
i_old · (1 − d₀/R)² = I / d₀²
I = i_old · (1/2)² · (R/2)² = i_old · R² / 16
```

按当前内容值换算（R 取现行折算值与显式值，内容数值不变）：

| 光源 | R (m) | `intensity`（内容值，不变） | 换算出的 I | 校验：E 在 d = 2 m（含窗） |
| --- | --- | --- | --- | --- |
| 曳光 7.62 mm | 3.1 | 1 | 0.60 | 0.10 |
| 曳光 20 mm | 5.0 | 1 | 1.56 | 0.37 |
| 曳光 50 mm | 9.5 | 1 | 5.64 | 1.41 |
| 爆炸火光（缺省） | 8 | 1 | 4.0 | 1.00 |
| 枪口火光 20 mm | 5.0 | 2 | 3.13 | 0.74 |
| 枪口火光 50 mm | 9.5 | 2 | 11.3 | 2.82 |
| 枪口火光 120 mm | 20 | 2 | 50 | 12.5 |
| 枪口火光 155 mm | 25.3 | 2 | 80 | 20.0 |
| 信号弹 | 40 | 1.8 | 180 | 45.0 |

表里的 `I` 只是**换算起点**：新算子在中近距离本来就会比旧算子更亮、更集中，最终数值要按 §4.4 的流程重新标定；标定的对象是 `kMul` / `kAdd` / `ρ̄` 与各来源自己的常量，而不是这些内容值。

### 4.3 全局常量（初值，待标定）

| 常量 | 初值 | 作用 |
| --- | --- | --- |
| `kMul` | 0.5 | 乘性项的强度；保纹理、保色相的主体 |
| `kAdd` | 1.0 | 加性项的强度；决定夜间暗面能被抬多亮 |
| `ρ̄` | 0.25 | 平均反照率代理；上限约束，防止涂白 |
| `d_min` | 0.75 m | `1/d²` 的奇点截断 |
| `E_MAX` | 1024 | 单光源辐照度上限，兜异常内容 |
| `ε` | 0.01 | `chroma` 的黑像素下限 |

### 4.4 标定流程

固定场景与相机，只改一个量，记录三个距离的观感与像素统计：

1. **夜景地面**（无其它光源）：信号弹停在 20 m 高。
2. **车体侧面**：发射器连射 3 发，取炮口正对的装甲板。
3. **爆炸**：`explosion_test` 在 6 m 外起爆。

每个场景记录：被照区域的**白像素占比**（R/G/B 任一 ≥ 0.98）、**亮度标准差**（纹理是否还在）、**色相偏移**（与无光帧比较）。判据见 §7。

## 5. 分阶段实施

| 阶段 | 内容 | 预计文件 | 观感变化 |
| --- | --- | --- | --- |

- **不改分层**：来源 → 光源表 → 效果三层、容量 16、数组契约（`LightView[64]` / `LightColor[64]` / `LightTol[16]` / `LightOcclusion[16]`）都不变；只改片元算子与来源提交时的换算。

- **字段范围不变**：`muzzle_flash.intensity` 的 `[0,8]` 与爆炸 `light.intensity` 的 `[0,8]` 都保持；换算后的 `I` 最大约为 320（`8 × 25.3²/16`），由着色器的 `E_MAX` 兜底。
- **文档联动**：`docs/plan/进行中/渲染-屏幕空间光照通用化设计.md` 的 §2.2、§8.2 描述现行算子（"先求和 → 截到 1 → 一次 screen 混合"），实施后按新算子重写；`docs/plan/计划中/武器系统-投射物曳光光照设计.md` §8.2 的"LDR 帧用 screen 混合而非加法"同样以本文 §3.3 的算子为准。

## 7. 验收

沿用本项目惯例：**主视图实机目视**，不建立像素级自动断言。每个场景同时记录上文的像素统计作为参考：

| 场景 | 判据 | 失败指向 |
| --- | --- | --- |
| 信号弹悬停 | 地面出现半径约 10–20 m 的**光池**：中心亮、向外连续变暗；光照区内纹理与色相仍可辨；白像素占比不超过 5% | 衰减或 `kAdd`/`ρ̄` 过大 |
| 枪口单发 | 炮口附近有明亮核心，5 m 外是可见的柔和亮区；车体不被整块刷白 | `kMul` 过大或 `E_MAX` 未生效 |
| 连射 | 持续光而非频闪；亮度不随射速线性增长到全白 | 重叠条目 + 加性项 |
| 曳光 | 弹道线经过处有细亮带，地面光斑不沿整条弹道连成一片 | 曳光 `I` 偏大或 `d_min` 偏大 |
| 爆炸 | 爆心亮、向外衰减；不与波前折射互相干扰 | 同爆炸火光参数 |
| 回归 | 天空档、未受光区域逐位不变；关闭总开关时画面与无该效果一致 | 线性化/编码的恒等性 |

数值参考（非硬门槛）：被照区域的亮度标准差应不低于无光帧的 60%；白像素占比 ≤ 5%（信号弹场景）。

## 8. 风险与未决

| 类别 | 内容 | 处理 |
| --- | --- | --- |
| 根本限制 | 没有反照率，无法真正区分"黑墙被照亮"与"白墙在阴影里" | 用像素色度 + 平均反射率代理；不声称物理正确 |
| 根本限制 | 画面已被曝光，新增光只能做增量 | 色调映射只作用于增量；整帧 HDR 需要独立 HDR 通路，不在本设计内 |
| 内容迁移 | 旧内容包的 `intensity` 数值语义变化 | 仓库内按 §4.2 更新；外部包偏亮/偏暗但不会崩坏；在内容包文档里注明 |
| 观感回归 | 曳光、爆炸、枪口火光的观感全部改变 | 分阶段落地，每阶段单独目视；标定表随阶段更新 |
| 性能 | 每光源增加约 10 条 ALU（`1/d²`、窗、软肩、色度） | 与每像素的深度采样和循环次数相比可忽略；不改采样数 |
| 光影兼容 | 只改颜色运算，不涉及深度快照与目标格式 | 原版/ Iris 都适用；仍按原有验收矩阵覆盖两种会话 |
| 未决 | `cos θ` 是否提前用深度重建法线（S4） | 当前留到 P5；若先做，地面与墙面的差异会更明显，需重新标定 |

## 附录 A · 公式与取值推导

**窗函数选择**：`(1 − (d/R)⁴)²` 在 `d = R` 处值与一阶导同时为 0，且中心附近接近 1，能把 `1/d²` 的长尾平滑截断；`(1 − d/R)²` 的中心平坦正是"平板"感的来源，不用于衰减。

**换算式的推导**：令新旧辐照度在 `d₀ = R/2` 相等：

```text
i_old · (1 − d₀/R)² = I / d₀²
I = i_old · (1/2)² · (R/2)² = i_old · R² / 16
```

**乘性项软肩**：`m = kMul · Elum/(1 + Elum)` 在 `Elum → 0` 时近似线性（不改变暗处的响应斜率），在 `Elum → ∞` 时有界于 `kMul`，因此永远不会把 `C` 乘到无穷。

**加性项**：`a = kAdd · ρ̄ · (1 − exp(−E))`，逐通道；`E` 很小时近似 `kAdd·ρ̄·E`（与物理的"新增辐照度 × 反照率"同阶），`E` 很大时有界于 `kAdd·ρ̄`。
