# Machine-Max 渲染 — 屏幕空间光照物理化设计

> **状态**：提案，未实现（2026-10-17）。当前落地的是"发光叠加"：通用光照链把每条光源的 `color × intensity × (1 − d/R)²` 逐像素求和、截到 1，再与画面做 screen 混合（`shaders/program/screen_space_light.fsh`）。本文给出物理模型、在只有颜色与深度的链里可达的近似、标定方法、分阶段改动与验收判据；实施后由本文的算子替换该混合。
>
> **本文自包含**：符号、公式、参数默认值与判据都在文内给出，不要求先读其他文档。引用现有代码只为定位，理解本文不需要先记住那些实现。

**术语**：E = 辐照度（照到表面上的光，单位面积功率）；L = 辐亮度（表面/空气沿视线发出的光，相机看到的量）；ρ = 反照率（表面反射比例，0–1）；I = 光源光强（本文用归一化单位，见 §4.1）；R = 剔除半径；`w` = 有限支撑窗函数。

## 1. 现状与问题

### 1.1 现行算子

```glsl
att    = (1 − d/R)²;                       // d = 表面点到光心的距离
light += color × (att × intensity);        // 逐光源求和
light  = min(light, 1);                    // 硬截断
out    = src + light × (1 − src);          // screen 混合，sRGB 显示空间
```

一条光源贡献的是**与表面无关的常数 RGB**：不知道表面反照率、不知道法线、不做 `1/d²`、不在线性空间、没有色调映射。

### 1.2 三个可量化的缺陷

| 缺陷 | 数学原因 | 观感 |
| --- | --- | --- |
| 衰减形状是"平板" | `(1 − d/R)²` 在 `d = R/2` 时恒为 0.25，与大半径配对时整片区域亮度几乎不随距离变化 | 大范围均匀发亮，没有"光池"的层次 |
| 合成算子压低对比 | `out = src + L(1 − src)`：暗像素吃满 L、亮像素几乎不变，加一次就把动态范围向 1 压缩 | 纹理细节被抹平，像刷了一层漆 |
| 硬截断成纯白 | `min(L,1)` 之后超出部分直接变纯白；`intensity` 越大只是白斑越大 | "更亮"表现为"更白、更大的一片白" |

补充一点色彩上的问题：`light` 是近白颜色时，R/G/B 被等量抬高；screen 混合又压缩通道差，于是**色相一起被洗掉**——红墙也会发白。物理上，白光照明提高的是亮度，色相由反照率保持不变。

### 1.3 信号弹的计算实例（`flare_illum`：R = 40 m，intensity = 1.8，color ≈ (1.00, 0.93, 0.80)）

信号弹悬在 20 m 高时，正下方地面 `d ≈ 20`，`att = (1 − 0.5)² = 0.25`，于是

```text
L ≈ 0.45 × (1.00, 0.93, 0.80) = (0.45, 0.42, 0.36)
```

- 影响球落在地面上是一个半径 `√(40² − 20²) ≈ 34.6 m` 的圆盘，中心 0.45、边缘 0——**大面积近似均匀**。
- 夜间地面 `src ≈ 0.04 ~ 0.12`，叠加后 `out ≈ 0.47 ~ 0.50`：纹理对比从 0.08 压到 0.03。
- 近白光色 + screen 混合：地面上任何颜色都被推向同一种淡黄灰。

这就是"被涂白"：它不是亮度高，而是**对比与色相同时丢失**。

### 1.4 枪口火光的对照（120 mm：R = 20 m，intensity = 2）

| d (m) | `att` | `L` | 结果 |
| --- | --- | --- | --- |
| 2 | 0.81 | 1.62 | 截断 → 纯白 |
| 5 | 0.56 | 1.13 | 截断 → 纯白 |
| 10 | 0.25 | 0.50 | 半亮 |
| 20 | 0 | 0 | 无 |

炮口周围是"纯白圆心 + 一圈过渡到 0.5 的盘"，不是"离得越近越刺眼、向外平滑衰减的光池"。

## 2. 物理模型

点光源在表面点 P 处产生的辐照度：

```text
E(P) = I · max(cos θ, 0) / d²        θ = 表面法线与入射方向夹角
```

漫反射（Lambert）表面的出射辐亮度：

```text
L = (ρ / π) · E
```

相机看到的最终值是曝光与色调曲线的结果：`display = tonemap(exposure · L)`。空气里看到的光晕是**散射**，沿视线积分：

```text
L_air = ∫ σs · p(θ) · I / d² ds
```

这四项里，我们手上只有 depth（→ 表面点 P 与距离 d）。缺：

| 量 | 现状 | 影响 |
| --- | --- | --- |
| 法线 | 可从深度重建（设计里叫 S4，当前未做） | 缺 `cos θ`，地面与竖直墙面吃到的光一样多 |
| 反照率 ρ | 最终颜色里与已有光照乘在一起，无法分离 | 无法"让白墙亮、黑墙暗"，这是根本限制 |
| 曝光 | 画面已经被原版渲染器曝光并编码 | 新增光只能以"增量"形式叠加，不能重新曝光整帧 |

因此**在这条链里做不到物理正确的表面光照**；能做的是采用"物理形状 + 合理近似"的算子，让结果在观感上符合物理直觉。

## 3. 可达近似

### 3.1 在线性空间里做

`src` 是 sRGB 编码的显示值。与光照相加必须在线性辐射度上进行：

```glsl
vec3 C = pow(src.rgb, vec3(2.2));     // 近似 sRGB → linear，或精确分段函数
...                                    // 增量在此空间计算
fragColor = vec4(pow(C_out, vec3(1.0 / 2.2)), 1.0);
```

未受光的像素 `E = 0` 时变换是恒等的（解码再编码只差浮点精度），因此**没有光源的地方逐位不变**。

**光源颜色同样要解码**：内容包里的颜色是 sRGB 的 `[0,255]`，直接当线性系数用会让暖色偏冷（线性 `(1, 0.85, 0.60)` 与 sRGB `(1, 0.93, 0.80)` 不是同一个颜色）。换算在来源提交时完成一次，着色器只接收线性 RGB。

### 3.2 衰减：`1/d²` + 有限支撑窗

```text
w(d) = (1 − (d/R)⁴)²        d < R 时为 1→0，d ≥ R 时为 0
E_i  = c_i · I_i(t) · w(d_i) / max(d_i², d_min,i²) · V_i · B_i · N_i
```

其中 `c_i` 是线性光色、`I_i(t)` 含内容强度与时间包络、`V_i` 是遮挡、`B_i` 是锥角响应（球光为 1）、`N_i = max(N·L_i, 0)` 是朝向响应。逐项乘进同一条 E，最后求和得到 §3.3 的 `e`。

- `1/d²` 给出物理的近距离陡增与远距离长尾；`R` 只承担**剔除**与**窗**，不参与亮度（修掉 §1.2 的耦合）。
- `(1 − (d/R)⁴)²` 在 `d = R` 处严格归零且一阶导为零，包围剔除不会在边界留硬边。
- `d_min`（0.5–0.75 m，逐来源，见 §4.3）截住 `d → 0` 的奇点，避免光源贴在表面上时出现无穷大。

### 3.3 合成：先累加，再一次有界映射

所有光源先在线性空间逐通道求和（**求和后再合成一次**，因此结果与遍历顺序无关），再用同一条曲线映射到显示值：

```text
q     = C + β(1 − C)
C_out = (C + e ⊙ q) / (1 + e ⊙ q) = 1 − (1 − C) / (1 + e ⊙ q)
```

`e` 是求和后的光照响应（逐通道、非负），`C` 是解码后的线性显示 RGB（`[0,1]`），`β` 是暗部补偿常数（初值 0.03），乘除均逐通道。

**推导**：设虚拟亮度 `H = C/(1−C)`，令 `H' = H + e(H+β)`，再取 `C_out = H'/(1+H')`，代入化简即得上式。`H` 只是构造增亮曲线的中间量，不代表恢复出了真实 HDR 或反照率。

**性质**（`0 ≤ C ≤ 1`、`e ≥ 0`）：

| 性质 | 内容 |
| --- | --- |
| 零光恒等 | `e = 0 ⇒ C_out = C`；未受光像素直接旁路，画面逐位不变 |
| 输出有界 | 恒在 `[0,1]`；分母 `1 + e·q ≥ 1`，不会除零，也不需要编码前硬截断 |
| 灰阶单调 | `∂C_out/∂C = (1+e) / [1 + e(β + (1−β)C)]² > 0`（固定 `e`、逐通道） |
| 光色隔离 | `e` 逐通道，某通道 `e = 0` 时该通道不动；纯蓝光不会抬红通道 |
| 端点行为 | `C = 0` 时 `C_out = eβ/(1+eβ)`（黑面被照成随光色的暗色）；`C = 1` 时恒为 1 |
| 强光饱和 | `e → ∞` 时 `C_out → 1`，渐进饱和，没有硬截断 |

着色器合成部分：

```glsl
vec3 q = C + beta * (vec3(1.0) - C);
vec3 outLinear = vec3(1.0) - (vec3(1.0) - C) / (vec3(1.0) + e * q);
```

**为什么不用另外三种写法**：

| 算子 | 问题 |
| --- | --- |
| 纯加性 `C + e` | 抬得动夜间暗面，但平等加在所有通道上，压平细节、去饱和，且会削顶 |
| 纯乘性 `C × (1 + k·e)` | 保色相、保纹理，但抬不动近黑的地面（0.03 × 2 仍是 0.06）；且乘性系数若取自亮度就是中性增亮，彩色光会点亮其它通道 |
| 现行 screen | 压对比、去饱和，`min(L,1)` 之后直接变纯白 |

**`β` 的代价**：`q` 逐通道，暗通道的 `β(1−C)` 占比更大，所以暗部的饱和色会轻微去饱和。`β = 0.03` 时 `(0.1, 0, 0)` 在白光 `e = 1` 下变为 `(0.201, 0.029, 0.029)`，比例仍约 7:1；`β` 越大，黑色材质越容易被抬灰，因此保持小值。

`E` 逐光源钳到 `[0, E_MAX]`（初值 1024），兜住异常内容，避免 `inf`。

### 3.4 本期不做、但要记住的两项

- **`cos θ`（法线项）**：需要从深度重建法线（S4）。在它落地前，地面与竖直墙面等量受光，这是已知偏差，不在本设计里假装解决。
- **光晕 / 散射**：信号弹"看起来亮"的主体应该是空气散射与镜头的 bloom，而不是把 35 m 地面刷亮。本设计只处理表面光照；光晕是独立的加法通道或后处理 pass，列为后续阶段。

## 4. 参数与标定

### 4.1 `intensity` 的语义

`I` 是**光源在 1 m 处的辐照度**（归一化单位，不是坎德拉）：`I = 1` 表示在 1 m 处 `E = 1`。不引入真实单位，是因为这条链没有曝光量，绝对单位不可校准；取 1 m 处归一化可以让内容数值与观感一一对应。

三个量各管一件事，互不派生：

| 量 | 管什么 | 不管什么 |
| --- | --- | --- |
| `radius` | 剔除范围与窗宽（`1/d²` 的长尾截在哪里） | 亮度 |
| `intensity` | 照明水平（参考距离上把参考灰板抬多高） | 范围 |
| `duration_ticks` / 时间包络 | 随时间的衰减 | 峰值 |

`I` 逐弹种写显式值，**不从半径或口径自动派生**：同样口径的枪与炮、不同的装药与炮口装置，本来就可以不一样。

来源提交时先把内容强度乘上类别倍率与时间包络得到 `I_i(t)`，再乘进 `E_i`；`g`（光照响应倍率）并进已有的总倍率与类别倍率，不新增 uniform。

### 4.2 从目标灰度反解 `I`

标定不是凭感觉调数字，而是指定"在参考距离上把参考灰板从多亮抬到多亮"，再反解。由 §3.3 的曲线解出所需响应：

```text
e_target = (y − c) / ((1 − y) [c + β(1 − c)])
```

再用衰减式反推光源强度（`Y_light` 是线性光色的亮度，`g` 在标定时取 1）：

```text
I = e_target · max(d_ref², d_min²) / (w(d_ref) · Y_light)
```

`c` 是参考灰板在无光帧的线性显示值，`y` 是希望达到的值，`d_ref` 取 `R/2`（窗函数在这个位置约 0.88，光照分布最具代表性）。反推式假设 `V = B = N = 1`——无遮挡、球光、灰板正对光源；实测场景里按实际遮挡与朝向修正。

**算例**：120 mm 枪口火光，`R = 20`、`d_ref = 10 m`、灰板 `c = 0.10 → y = 0.30`、`β = 0.03`：

```text
e_target = (0.30 − 0.10) / (0.70 × (0.10 + 0.03 × 0.90)) = 2.25
I        = 2.25 × 100 / (0.879 × 0.645) ≈ 397
```

按同一组锚点对仓库现有光源算首轮值（灰板与光色取各自缺省，`β = 0.03`）：

| 光源 | R (m) | `d_ref` (m) | 灰板 `c → y` | `e_target` | 初值 `I` |
| --- | --- | --- | --- | --- | --- |
| 曳光 7.62 mm | 3.1 | 1.55 | 0.06 → 0.12 | 0.77 | 2.1 |
| 曳光 20 mm | 5.0 | 2.5 | 0.06 → 0.12 | 0.77 | 5.5 |
| 曳光 50 mm | 9.5 | 4.75 | 0.06 → 0.12 | 0.77 | 19.8 |
| 爆炸火光（缺省） | 8 | 4 | 0.10 → 0.45 | 5.01 | 165 |
| 枪口火光 20 mm | 5.0 | 2.5 | 0.10 → 0.30 | 2.25 | 24.8 |
| 枪口火光 50 mm | 9.5 | 4.75 | 0.10 → 0.30 | 2.25 | 89.5 |
| 枪口火光 120 mm | 20 | 10 | 0.10 → 0.30 | 2.25 | 397 |
| 枪口火光 155 mm | 25.3 | 12.65 | 0.10 → 0.30 | 2.25 | 635 |
| 信号弹 | 40 | 20 | 0.04 → 0.20 | 2.91 | 1519 |

表里是**首轮标定起点**，不是最终值；锚点本身也要按 §4.4 的实机观感调整。仓库内 13 个弹种的 `tracer_light_intensity` 与 `muzzle_flash.intensity`、爆炸参数的 `light.intensity` 按这张表（或按各弹种单独指定的锚点）写入显式值。

### 4.3 全局常量（初值）

| 常量 | 初值 | 作用 |
| --- | --- | --- |
| `β` | 0.03 | 暗部补偿；越大越容易把黑色材质抬灰 |
| `d_min` | 0.5–0.75 m（逐来源） | `1/d²` 的奇点截断；枪口/曳光取小、爆炸取大 |
| `E_MAX` | 1024 | 单光源辐照度上限，兜异常内容 |
| `g` | 1 | 光照响应倍率；并进已有的总倍率与类别倍率 |

### 4.4 标定流程

固定场景与相机，每次只改一个量：

1. **灰阶序**：同一盏灯照在一片从 0.02 到 0.90 的灰阶上，5 个台阶必须保持顺序，且两端都不跳过相邻台阶（检验 `β` 是否过大）。
2. **夜景地面**：信号弹停在 20 m 高，调整 `I` 使光池中心亮度符合预期，同时记录被照区域的白像素占比与亮度标准差。
3. **车体侧面**：发射器单发，取炮口正对的装甲板，检查是否出现整块刷白。
4. **光色隔离**：把某盏灯临时改成纯蓝 `[0, 0, 255]`，画面里除蓝通道外不应有变化（检验逐通道性）。

每个场景记录：被照区域**白像素占比**（任一通道 ≥ 0.98）、**亮度标准差**（纹理是否还在）、**色相偏移**（与无光帧比较）。判据见 §7。

## 5. 分阶段实施

| 阶段 | 内容 | 预计文件 | 观感变化 |
| --- | --- | --- | --- |
| A | 线性空间（含光色解码）+ 有界合成曲线 + 未受光旁路；衰减保持现状 | `screen_space_light.fsh` | 硬削顶消失；同样亮度下不会一片纯白；彩色光不会点亮其它通道 |
| B | 衰减换 `1/d²` + 窗 + 逐来源 `d_min` | `screen_space_light.fsh` | 大范围"平板"变成有中心的光池；信号弹与枪口焰显著改善 |
| C | 逐弹种写入显式 `I`（按 §4.2 锚点），`β` 与 `d_min` 定稿 | 13 个弹种 JSON + 爆炸参数 + `MuzzleFlash` / `ExplosionLightParams` 的缺省值 | 亮度层次与"近距离刺眼、远距离柔和"的关系正确 |
| D | 光晕/散射（独立通道或 bloom）与 S4 法线 | 新增 pass 或着色器分支 | "亮"由空气散射与高光承担，表面光可以更克制 |

A 与 B 可以合并为一次改动；C 是纯标定；D 属于新能力。

## 6. 与现有实现和内容的关系

- **不改分层**：来源 → 光源表 → 效果三层、容量 16、数组契约（`LightView[64]` / `LightColor[64]` / `LightTol[16]` / `LightOcclusion[16]`）都不变；只改片元算子、提交到 uniform 的数值口径与内容数值。
- **不改同步**：不涉及网络字段，registrar 版本不动。
- **内容数值需要重写**：`tracer_light_intensity`、爆炸参数 `light.intensity`、弹种 `muzzle_flash.intensity` 的语义从"倍率"变成"1 m 处辐照度"，数值按 §4.2 的首轮表（或各弹种锚点）写入。仓库内 13 个弹种 + 爆炸缺省 + 两个代码缺省常量都要改；外部内容包沿用旧数值会明显偏暗，需要按 §4.2 重标，这一点要写进内容包文档。
- **字段范围要放宽**：`muzzle_flash.intensity` 与爆炸 `light.intensity` 当前的 `[0,8]` 容不下新量级（155 mm 枪口 635、信号弹 1519），需要放宽到 `[0, 4096]`；曳光强度本就无范围限制。代码缺省值同步更新（`MuzzleFlash.DEFAULT.intensity` 取 50 mm 档约 90，`ExplosionLightParams.DEFAULT.intensity` 取 165）。
- **文档联动**：`docs/plan/进行中/渲染-屏幕空间光照通用化设计.md` 的 §2.2、§8.2 描述现行算子（"先求和 → 截到 1 → 一次 screen 混合"），实施后按新算子重写；`docs/plan/计划中/武器系统-投射物曳光光照设计.md` §8.2 的"LDR 帧用 screen 混合而非加法"同样以本文 §3.3 的算子为准。

## 7. 验收

沿用本项目惯例：**主视图实机目视**，不建立像素级自动断言。每个场景同时记录上文的像素统计作为参考：

| 场景 | 判据 | 失败指向 |
| --- | --- | --- |
| 灰阶序 | 同一盏灯照在一片 5 级灰阶（0.02 / 0.10 / 0.30 / 0.60 / 0.90）上：顺序不反转，相邻台阶不互相跳过 | `β` 过大或该处 `e` 过大 |
| 光色隔离 | 把某盏灯临时改成纯蓝 `[0,0,255]`：画面除蓝通道外逐像素不变 | 合成曲线不是逐通道（回到了中性乘性/加法） |
| 信号弹悬停 | 地面出现半径约 10–20 m 的**光池**：中心亮、向外连续变暗；光照区内纹理与色相仍可辨；白像素占比不超过 5% | 衰减、`I` 或 `β` 不当 |
| 枪口单发 | 炮口附近有明亮核心，5 m 外是可见的柔和亮区；车体不被整块刷白 | `I` 过大或 `d_min` 过小 |
| 连射 | 持续光而非频闪；亮度不随射速线性增长到全白 | 重叠条目 × `I` 过大 |
| 曳光 | 弹道线经过处有细亮带，地面光斑不沿整条弹道连成一片 | 曳光 `I` 偏大或 `d_min` 偏大 |
| 爆炸 | 爆心亮、向外衰减；不与波前折射互相干扰 | 同爆炸火光参数 |
| 回归 | 天空档、未受光区域逐位不变；关闭总开关时画面与无该效果一致；同一画面重复渲染两次结果逐位相同 | 线性化/编码的恒等性与旁路 |

数值参考（非硬门槛）：被照区域的亮度标准差应不低于无光帧的 60%；白像素占比 ≤ 5%（信号弹场景）。

## 8. 风险与未决

| 类别 | 内容 | 处理 |
| --- | --- | --- |
| 根本限制 | 没有反照率，无法真正区分"黑墙被照亮"与"白墙在阴影里" | 曲线只能按像素现值整体抬高；`β` 是替代手段，不声称物理正确 |
| 根本限制 | 画面已被曝光，新增光只能做增量 | 曲线作用在显示值上、输出有界；整帧 HDR 需要独立 HDR 通路，不在本设计内 |
| 已知近似 | `β > 0` 时暗部饱和色会轻微去饱和（`(0.1,0,0)` 在白光 `e=1` 下变 `(0.201,0.029,0.029)`） | `β` 取 0.03；实机若黑色材质发灰，先降 `β`，不要动 `I` |
| 内容迁移 | 13 个弹种、爆炸缺省与两处代码缺省的 `intensity` 都要重写为绝对量 | 按 §4.2 首轮表写入，再按 §4.4 实机重标；外部内容包需同步重标 |
| 观感回归 | 曳光、爆炸、枪口火光的观感全部改变 | 分阶段落地，每阶段单独目视；标定表随阶段更新 |
| 性能 | 每光源约 8 条 ALU（`1/d²`、窗、颜色乘），每像素 3 次除法（逐通道） | 与每像素的深度采样和循环次数相比可忽略；不改采样数 |
| 光影兼容 | 只改颜色运算，不涉及深度快照与目标格式 | 原版/ Iris 都适用；仍按原有验收矩阵覆盖两种会话 |
| 未决 | `cos θ` 是否提前用深度重建法线（S4） | 当前留到 P5；若先做，地面与墙面的差异会更明显，需重新标定 |

## 附录 A · 公式与取值推导

**窗函数选择**：`(1 − (d/R)⁴)²` 在 `d = R` 处值与一阶导同时为 0，且中心附近接近 1，能把 `1/d²` 的长尾平滑截断；`(1 − d/R)²` 的中心平坦正是"平板"感的来源，不用于衰减。

**合成曲线的推导**：设虚拟亮度 `H = C/(1−C)`，令 `H' = H + e(H+β)`，取 `C_out = H'/(1+H')`。代入：

```text
H' = C(1+e)/(1−C) + eβ
C_out = [C(1+e) + eβ(1−C)] / [1−C + C(1+e) + eβ(1−C)]
      = [C(1+e) + eβ(1−C)] / [1 + eC + eβ(1−C)]
```

令 `q = C + β(1−C)`，分子分母同除 1 后即 `(C + eq)/(1 + eq)`。`H` 只是构造这条曲线的中间量，不代表真实 HDR 或反照率。

**单调性**：令 `q = β + (1−β)C`，则

```text
C_out = (C + eq)/(1 + eq)
dC_out/dC = (1 + e) / (1 + eq)²  > 0
```

**端点**：`C = 0` 时 `q = β`，`C_out = eβ/(1+eβ)`；`C = 1` 时 `q = 1`，`C_out = 1`。`e → ∞` 时对任何 `C > 0` 都有 `C_out → 1`。

**反解**：令 `C_out = y`、`C = c`：

```text
y(1 + eq) = c + eq  ⇒  y − c = eq(1 − y)  ⇒  e_target = (y − c) / ((1 − y)[c + β(1 − c)])
```
