# 武器系统 — 客户端模拟同步与状态持久化计划

**状态**：计划中，尚未实施；源码调查已经完成，报告的表现缺陷未在本次文档工作中复现或修复。

**核对日期**：2026-11-13。

**目标**：客户端正常模拟装填、取弹、扣弹和射击表现，服务端负责真实库存、来源选择与投射物生成。同步回调缓存权威新值，客户端在主线程 `postTick` 统一校准。运行关系由服务端重建后下发；子系统仅保存自身需要延续的实际状态。

C1—C3 表明，膛室可能在服务端同 tick 经历“空 → 入膛 → 发射后空”，下发只有最终空值。客户端如果仅凭同步膛室进入射击循环，就无法完整表现这次过程。本文采用本地供弹与射击模拟，并在 tick 末校准；实际触发条件按 §7 核对，不把代码分析写成实机复现。

## 2. 客户端模拟与 postTick 校准

1. 同步回调只缓存本次收到的武器运行字段，不在模拟中途覆盖膛室、Belt 或交付进度。每个缓存项区分“未收到更新”和“收到空值”；同一字段多次到达时保留最新值，未到达字段不参与本次覆盖。
2. 客户端业务 tick 按当前运行状态正常推进装填、取弹、补膛、Belt 消费与回充，并从本地射击循环生成枪声、弹壳、尾焰、火光和动画。客户端修改的是自己的状态副本，不向服务端回写库存，不生成真实投射物，不执行真实能源扣费或世界伤害。
3. 本轮武器模拟结束后，在客户端主线程 `postTick` 一次应用待处理字段；这里不是物理线程的 `postPhysicsTick`。发射器先采用专门处理入口，供弹库存与交付进度中被本地模拟消费的字段也按同一边界校准，不要求重写其他子系统的全部同步机制。
4. 校准只覆盖状态，不触发射击、装填标记或完成音效；库存覆盖本身不无条件重置射速累积、连射状态和声音实例。权威停用、摧毁或实际操作终止按其语义收尾。
5. 应用后清除本次待处理标记。没有新值时继续模拟，不把上一份缓存反复覆盖回去。Belt 的消费与回充使用独立可变实例，不能原地修改同步基线。

本轮接受网络延迟内的短暂模拟差异，以实际到达的权威新值持续校准。不建立输入历史、状态回滚、预测重推、永久射击日志或逐发确认协议；不为一次射击的声音、粒子、火光分别发送表现包。`chamberedType` 可以正常同步，它不承担逐发事件编码，也不需要按“正在开火”暂停同步。

当前通路的 `packDirty()` 只发送变化项。实施时逐项检查本地修改的状态是否确实有权威更新可校准；校准遗漏不能靠假定“下个 tick 一定有完整快照”掩盖。先沿用现有同步通路，确实需要的字段在该通路补齐，不另建并行预测框架。

## 3. 供弹选择与运行期引用

装弹机、弹药架和当前作业的来源由服务端决定并下发。客户端可以模拟选定作业的计时与弹药消费，但不重新选择最快来源、抢占机构或认领人员。共用机构的请求是否已获受理也跟随服务端，不能仅靠两端自行遍历请求获得相同结果。

拆分库存与机构后，同步本次作业实际使用的来源和机构引用即可，不下发完整发现图。一台机构可服务多个消费者时，来源归属跟随各自作业，不能用机构上唯一的全局来源字段代替。

运行期子系统引用统一使用“宿主 SubPart ID ＋ 子系统名”，与 C5 的普通子系统更新寻址形状一致。供给指认无需 Part UUID 或 SubPart 名，不引入额外的子系统整数注册表。双方使用服务端创建数据中的宿主 ID；不能各自分配后假定一致。

对象定位后检查它是否仍属于当前合法发现关系、是否已失效。指认目标尚未就绪时暂存等待，不自行改选，也不沿旧来源继续取弹；已在膛内或已装 Belt 中的弹药依其自身状态使用。运行期 ID 和对象引用都不进入子系统关系存档。

## 4. 需要下发的数据与带宽边界

| 所有者 | 下行数据 | 客户端用途 |
| --- | --- | --- |
| Launcher | 膛内弹、已装 Belt 的内容与余量／回充状态、当前供给者；分段接入后有当前作业、流程与阶段进度 | 本地供弹、射击、装填音效与 HUD，tick 末校准 |
| 库存提供者／机构 | 实际数量、自身再生状态、当前已受理交付及必要计时／停摆状态 | 模拟既定交付与显示进度，不重新仲裁来源和机构竞争 |
| 武器控制器 | 选中的交付规格及既有开火控制状态 | 保持弹药选择一致；核对多管轮射和瞄准门控的双端差异 |

固定的 label、pattern、length、容器 ID 与回充配置在安装、更换和完整补推时发送；平稳过程尽量只同步余量、进度和变化状态，不把 3000 发弹链展开。推进装填所需的实际时长由服务端发布，不为显示重新计算人物能力。具体字段拆分随现有序列化器调整，不把“每 tick 检查同步”扩展为无差别全量广播。

首次进入和对象恢复时，保持“创建对象 → 全量补推”的顺序。完整初值建立本地模拟基线，不播放历史枪声或历史装填标记。多人旁观同样跟随权威来源，不依赖自己是否持有该武器的输入。

同步字段或引用编码改变时，读取 `network/MMPayloadRegistry.java#register` 的实际版本后递增相关协议组，不预写固定的新版本号。

## 5. 子系统持久化与恢复

| 子系统 | 保存自身数据 | 不保存的运行关系 |
| --- | --- | --- |
| Launcher | 独立膛内弹、完整紧凑 Belt（含 label、实际弹序、余量与回充运行态）、需要延续的剩余射击冷却 | 当前供给者、装弹机／弹药架路径、历史退回来源、发现表和网络引用 |
| 弹药架／再生来源 | 实际物品或数字库存、自身逐发或批量再生进度与剩余延迟 | 消费者认领、交付预留、机构关系和客户端显示缓存 |
| 武器控制器 | 玩家选中的弹药规格；恢复后对合法来源重新匹配 | 聚合资源池、已选来源引用及派生路由 |
| 装弹机构／当前装填 | 首轮不保存未完成装填作业，读档后重新发起 | 人员认领、机构占用、作业路径、阶段进度与音效播放记录 |

结构、接线配置和连接拓扑由现有载具／部件层恢复，不在上述子系统存档里重复保存。服务端恢复实际库存与玩家选择后，握手发现、选择来源、建立运行关系，再向客户端同步。没有关系存档时也不能为 Launcher 播种满额 Belt。

剩余冷却、延迟和再生进度表达游戏内尚未完成的量，不绑定客户端出生后的 tick。卸下或未加载的 Belt 暂停回充，不计算现实时间恢复。客户端预测状态、待应用缓存、声音实例和已播标记不存档；服务端使用自己的实际状态保存。

首轮恢复不承诺从人工／机械段中途续装。未来确实需要跨存档续装或分装弹检查点时，再明确所需作业信息和恢复政策，不为当前范围保存历史路径。

## 6. 退回与丢弃

已装 Belt 不要求退回原提供者。退回时可尝试当前合法且接受该份内容的提供者；本轮不实现跨多个接收方拆分回收。无人接收或整份拒收时允许直接丢弃，正常卸弹／换装不因此受阻，也不要求生成掉落物。

接收方接口保持全收／全拒：成功时按类型回收完整实例或增加数字数量；拒收时不改库存、不修改传入 Belt。调用方在拒收后执行丢弃并清理自身对应内容，不能把丢弃报告为提供者成功接收。数量核对将这笔计为明确的丢弃损耗。

新交付不合法或交付失败时，不应提交新装填；这与“有效新交付已取得、旧 Belt 回收失败后丢弃”分别处理。战术换弹保留膛内弹，换掉的是已装 Belt。子系统无需 `loadedBeltSource` 这类历史来源追踪，也无需为重启后原路退回持久化引用。
