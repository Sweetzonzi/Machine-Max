## 1. 目标与非目标

目标：

1. 15 处部件从"焊死在车上、只能打掉"变成"点一下开、再点一下关、关到位重新扣上"。
2. 生成、蓝图放置与读档三条路径都让部件处于扣合状态，且不播捕获声。
3. 新增内容只有三份型号定义（一份锁扣、一份平动驱动、一份重载旋转驱动）、每处部件两段动画片段与一台控制器；不新增子系统类型、不新增语言键、不改 Java。

非目标：

- 不改 `CouplerSubsystem`、`JointDriverSubsystem` 的运行逻辑、判据公式与默认值。
- 不重做外观：只在车体模型里加 0 立方体的铰链骨骼，在可开合件模型里加一个只含一根方块的交互骨骼。
- 不动语言表：六个交互区名与十二个子系统名全部复用现有条目，其中包括桑塔纳车门交互区那条"进入前排左侧座位"的措辞。
- 不为纯物理行为新增自动化验收，判定按 §8 的人工验收项；内容与 schema 的离线校验按 §8 的阶段门跑。

四辆车共同的缺口：

- 车体侧没有任何 `joint_driver` 或 `coupler` 实例，可开合件也没有可用的驱动与锁扣。
- 车体锁扣连接点是 Simple 的 `fixed_up`，与件侧 Simple 的 `fixed_down` 配对后被 `adjustJoint` 把三根转动轴锁到 0，形成第二条刚性焊缝——门被铰链与锁扣双重焊死，唯一"打开"方式是打掉锁扣（默认 `integrity 15`），之后门自由摆动且无法再扣上。
- 车体模型里没有一根可以单独转动的铰链骨骼。Kluo、Wine Fox、Van 的车体与可开合件共用同一个 geo 文件，件是同一模型里的一段骨骼子树（`start_bone` 取 `LeftFrontDoor`、`Hood`、`Trunk`、`BackDoor` 等）。车体侧的铰链与锁扣 locator 挂在车体子树的骨骼上：Kluo、Wine Fox 是 `HullConnector`（枢轴 `0,0,0` / `0,7,0`，同一根骨骼下挂着整车全部连接点），Van 是 `Hull`（车体自身的渲染根骨骼，43 个方块）；件侧的 locator 挂在件根骨骼上，这些根骨骼的枢轴有的正好在铰链轴上（Kluo 两扇门与引擎盖、Van 前门与后备箱盖），有的不在（Wine Fox 全部、Van 两台滑门）。宿主骨骼带着整段子树，直接旋转它会把车体或整片件一起甩动，所以模型侧要补一根专用骨骼。
- 没有开合片段与状态机；Kluo、Wine Fox、Senna 的件上也没有交互区。Van 的四个车门交互区已存在（前门 `fast`、滑门 `accurate`），但目标表里没有 `global`，状态机即使写出来也收不到点击；后备箱盖没有交互区。

## 4. 共用资产

### 4.1 锁扣型号 `machine_max:door_latch`

放 Builtin：`machine_max/subsystems/coupler/door_latch.json`，参数取桑塔纳现有型号的一组起始值——`capture_distance` 0.04、`lock_distance` 0.015、`max_capture_force` 0、`lock_angle_tolerance` 3.0、`max_lock_speed` 0.25、`rearm_distance_multiplier` 2.0、`basic_durability` 20，`on_attach` 与 `on_detach` 都是 `minecraft:block.tripwire.attach`。

桑塔纳六处安装块的 `definition` 写 `machine_max:door_latch`，型号只有这一份（型号不进存档，改名不影响既有存档与蓝图）。

某个件需要不同窗口时再单独加一份型号——最可能的候选是 Van 的滑动门（§7.1）。

### 4.2 平动驱动型号 `machine_max:translation_joint_driver`

放 Builtin：`machine_max/subsystems/joint_driver/translation_joint_driver.json`，`type` 仍是 `machine_max:joint_driver`，`axes` 取 `X` 与 `Z`。`max_force` 是牛顿、`max_speed` 是 m/s，与旋转型号的 250 N·m / 180 °/s 同构。滑动门先向外让开 0.1 m 再沿车身滑 1 m，两条平动轴在同一段片段里一起给目标，一台驱动覆盖两个方向。

### 4.3 名字与语言键全复用

| 类别 | 取值 | 出处 |
| --- | --- | --- |
| 子系统名 | `subsystem.machine_max.{left_front_door,right_front_door,left_back_door,right_back_door,hood,trunk_door}_{driver,coupler}` 共 12 个 | Civilian 语言表已有中英文 |
| 交互区名 | `interact.machine_max.{left_front_door,right_front_door,left_back_door,right_back_door,hood,trunk_door}` 共 6 个 | Builtin 语言表已有 |

| 动画片段 | `left_front_door_open` / `_close` 等，每个动画集内各一份 | 桑塔纳现状 |

名字键只要求在本 Part 内唯一，不同车复用同一批名字不冲突。位置词按"这扇门在车的哪一侧"取：Kluo、Wine Fox、Senna 的两扇门是前门，用 `left_front_door` / `right_front_door`；Van 的四个门按前后左右各自对应。

### 4.4 交互区体积与模式

件上加一根只含方块的 `interact_<位置>` 骨骼，JSON 里一条 `interact_boxes` 指向它，体积就是骨骼里那些方块的位置与姿态。模式用 `accurate`，与桑塔纳一致：`accurate` 按射线判定，且要求交互区比件自己的命中框更靠外、射线先碰到交互区，所以交互骨骼挂在件现有命中框骨骼下面——`parent` 取命中框骨骼、`pivot` 抄它、方块照抄命中框的方块并把每块的 `origin` 三轴各减 1、`size` 三轴各加 2，交互区因此是命中框向外裹一圈的壳。`fast` 按玩家碰撞箱判定，贴身站着按交互键就触发；车门板与舱盖上用 `fast` 会与上车的座位交互区抢同一次按键，所以这批件只用 `accurate`。Van 已有的四个车门交互区保持原模式，只补 `global`。

同一件的交互区身份是"这块件被拆掉时提示该消失"，所以交互区长在可开合件上，不长在车体上。

### 4.5 重载旋转驱动型号 `machine_max:rotation_joint_driver_heavy`

放 Builtin：`machine_max/subsystems/joint_driver/rotation_joint_driver_heavy.json`，`type` 仍是 `machine_max:joint_driver`，三个旋转轴 `max_force` 1500 N·m、`max_speed` 180 °/s。它服务两处弹簧在闭位力矩超过通用型号 250 N·m 的件：Senna GTR 的两扇车门（闭位 1200 N·m）与 Van 的后备箱盖（开位自重静力矩约 220 N·m）。取值依据见 §12.5，通用型号的取值不变。

## 5. 单件改造清单

对每一处可开合件按下表七步施工，`<W>` 是位置词，`<铰链>`／`<锁扣>` 是该车车体侧对应连接点名。

| 步 | 动作 |
| --- | --- |
| 1 | **车体铰链连接点补两张表**：`signal_targets` 写 `{"interact": ["subsystem.machine_max.<W>_coupler"]}`，`signal_translations` 写 `{"interact_<W>": "interact"}`，完整写法见[桑塔纳车体左前门铰链](../../../src/main/resources/spark_modules/Machine-Max_Civilian/machine_max/parts/santana/santana_hull.json#L226-L236)。表要落在**对侧**：交互区朝件侧连接点发信号，过边到达车体侧连接点时才读车体侧的表。Van 的四个门铰链把 `interact_<W>` 转给 `connector.machine_max.chassis_connection`，而整车只有一个该连接点、它没有后续表，这条转发到不了任何终端，四个门铰链因此写本表；座位有自己的交互区，不依赖这条链。Senna 的两张表落在**锁扣**连接点上而不是铰链上，见 §6.2。 |
| 2 | **车体锁扣连接点换型号**：`fixed_up` → `machine_max:fixed_rigid`（Advanced，六轴全锁），`overwrite` 补 `direction`＝件侧锁扣法线的反向、`integrity` 3.5、`impact_reduction` 0.5、`impact_absorption` 0.6，以及 `required_tags`（车门写 `machine_max:door` + `machine_max:direction/<左或右>` + `machine_max:series/<车>`，引擎盖写 `machine_max:hood`，后备箱盖写 `machine_max:trunk`）。件侧锁扣的型号是 `fixed_down`（法线 `yn`），车体侧因此一律写 `yp`。 |
| 3 | **车体装两台子系统**，都装在连接点所在的子零件上（这四辆车的车体各只有一个 `sub_part.machine_max.main`）：`subsystem.machine_max.<W>_driver`（`type` `machine_max:joint_driver`，`definition` `machine_max:rotation_joint_driver`，`connector` 指铰链）；`subsystem.machine_max.<W>_coupler`（`type` `machine_max:coupler`，`definition` `machine_max:door_latch`，`connector` 指锁扣）。样例见[桑塔纳车体左前门两台子系统](../../../src/main/resources/spark_modules/Machine-Max_Civilian/machine_max/parts/santana/santana_hull.json#L530-L539)。滑动门的 `driver` 改引用 `machine_max:translation_joint_driver`；Senna 的车门与 Van 的后备箱盖的 `driver` 改引用 `machine_max:rotation_joint_driver_heavy`（§4.5）；Senna 的两类子系统分装前后车身（§6.2）。 |
| 4 | **件侧锁扣补弱化参数**：在件侧 `connector.machine_max.lock` 的 `overwrite` 里写同一组 3.5 / 0.5 / 0.6 与 `required_tags: ["machine_max:hull", "machine_max:series/<车>"]`。件侧 `definition` 保持 `fixed_down`，不换型号。两侧都弱化，打门板与打车体都能让锁扣先于铰链脱开。 |
| 5 | **车体模型加铰链骨骼**：0 立方体，`parent` 取当前挂着该铰链 locator 的那根骨骼（Kluo、Wine Fox 是 `HullConnector`，Van 是 `Hull`，Senna 前车身是 `Connectors`），`pivot` 取该铰链 locator 的坐标；把铰链 locator 的声明整条挪到新骨骼下，位置数值不变；locator 自带的朝向按下面的规则决定落在哪根骨骼上。locator 有两种写法，都要按原样搬：数组 `[x,y,z]` 只给位置，对象 `{"offset": [...], "rotation": [...]}` 给位置加朝向（Kluo、Wine Fox 的后备箱盖是对象写法）。这个格式里 locator 的 `offset` 与骨骼枢轴都是模型空间绝对坐标，骨骼旋转绕枢轴施加，两者相等时转动中心正好落在 locator 上。锁扣 locator 留在原骨骼，锁扣不参与动画。命名沿用桑塔纳：`<位置>Hinge`（`LeftFrontDoorHinge`、`HoodHinge`…）。<br>**locator 带非零朝向时，先看那组朝向是不是绕铰链轴。**位姿管线在一根骨骼内部把动画欧拉角逐分量加到该骨骼的静止欧拉角上、再按 ZYX 合成（`BonePose` 的 `getLocalRotation().add(bone.rotation)` 与 `rotateZYX`），跨骨骼才是矩阵相乘；locator 的朝向相当于把这个旋转共轭一次。朝向与铰链轴同轴时（Kluo、Wine Fox 的后备箱盖 locator 是 `[15, 0, 0]`，铰链是 `xr`）共轭不改变旋转，片段照写单轴即可。朝向把铰链轴转到与任何坐标轴都不重合时（Senna 的两扇车门，朝向约 39°/−41°/−15°），一根自身带倾斜的骨骼拿不到"绕铰链轴的单轴旋转"，只能写三轴欧拉角去凑。这种件用两根骨骼：父骨骼 `<位置>HingeTilt` 承担倾斜角、`pivot` 取铰链点，被动画的子骨骼 `<位置>Hinge` 在父坐标系里静止旋转为零、`pivot` 与父骨骼相同，locator 挂在子骨骼下且只写位置。整条链的静止朝向与把倾斜写在 locator 上时相同，片段只需写绕自身 Z 轴的角度，采样出的目标正好落在限位上。理由与实测见 §12.9，作者口径见 [5.2 模型与动画](../../wiki/5-内容包制作教程/5.2-模型与动画.md)。 |
| 6 | **件模型加交互骨骼**，并在件 JSON 里加交互区：<br>`"interact.machine_max.<W>": {"bone": "interact_<W>", "interact_mode": "accurate", "condition": "local.has_connector('connector.machine_max.axis')", "signal_targets": {"interact_<W>": ["connector.machine_max.axis", "global"]}}`。<br>骨骼按 §4.4 挂在命中框骨骼下并外扩一圈；`condition` 让被拆下的件不亮提示（铰链没有对端即不可交互，门开着时铰链仍然接着、所以不影响关合）。<br>`global` 是必需项：状态机在车体上，靠装配体广播才收得到。只有连接点目标时交互区照样会亮、点了动画不动——Van 的四个框正是缺这一项。Senna 的第一个目标写 `connector.machine_max.lock`（§6.2）。 |
| 7 | **车体动画集加两段片段与一台状态机**：片段写进该车现有的动画集目录（`animations/part/<动画集名>/`），只写新加的那根铰链骨骼——旋转件给绕铰链轴的目标角，滑门给平移目标；状态机写进 `controllers/part/<模型文件基名>/<同名>.animation_controllers.json`。**控制器目录按模型 id 取，不按动画集 id**（`AnimStateModule` 用 `ModelController` 的模型索引做键）：Kluo 的模型是 `kluo.geo`、动画集却是 `kluo`，所以控制器目录是 `kluo.geo`；Van 是 `van.geo`、Wine Fox 是 `wine_fox.geo`、Senna 前车身是 `senna_gtr_front_hull.geo`。转换事件 `event.interact_<W>`，两状态互切。`loop` 按 §7.2 判据取。 |

## 6. 逐车差异

### 6.1 Kluo（4 件）与 Wine Fox（4 件）

两车同构，可以同一批做完，差别只有模型文件与 `series` 标签。

- 位置词：左门 `left_front_door`、右门 `right_front_door`、`hood`、`trunk_door`。
- 铰链限位已在连接点定义里（Kluo 左门 `yr -80..0`、右门 `yr 0..80`、引擎盖 `xr 0..80`、后备箱盖 `xr -80..0`），不动。
- 盖板铰链的弹簧刚度是 2.3（引擎盖）／1.4（后备箱盖）N·m/度，`adjustJoint` 按 ×180/π 换算成 Bullet 的 131.8／80.2 N·m/rad，平衡位在开限位（±80°）。开位的弹簧托力为零，自重绕铰链约 150 N·m 会把盖板带向关闭位，所以开片段必须 `loop: true` 持续给目标角；关片段单次（走完松手，闭位由锁扣承力）。闭位的弹簧力矩是 184／112 N·m，低于驱动器的 250 N·m 与锁扣已承住的 172 N·m 量级（取值依据见 §12.4）。
- 车门绕竖直轴开合，没有重力回正力矩，铰链只有 1.74 的阻尼、没有弹簧：开、关片段都单次，与桑塔纳一致。
- 件上的 `LeftDoorHitBox`、`HoodHitBox`、`TrunkHitBox` 是命中框；交互骨骼挂在它们下面照抄并外扩一圈（§4.4），不直接把命中框当交互区。
- 车体上的 `interact.machine_max.trunk` 挂在 `HullInteract` 下的 `TrunkInteract` 骨骼上，目标是后备箱储物子系统，不是后备箱盖的开合——名字与新的 `trunk_door` 不冲突，保持不动。两扇门与引擎盖上没有现成交互区，四处都新加。

### 6.2 Senna GTR（2 件）

唯一跨件接线的一辆车。

- `front` 变体持有两台铰链与动画集，`back` 变体持有两个锁扣。两台 `driver` 跟前车身（铰链所在），两台 `coupler` 跟后车身（锁扣所在）。
- 前车身的两台铰链是倾斜轴：朝向约 39°/−41°/−15°（右门镜像，39°/41°/15°）写成父骨骼 `LeftDoorHingeTilt` / `RightDoorHingeTilt` 的静止旋转，被动画的 `LeftFrontDoorHinge` / `RightFrontDoorHinge` 在父坐标系里静止旋转为零，铰链 locator `hull_left_door_axis` / `hull_right_door_axis` 挂在后者下面且只写位置。写法见 §5 第 5 步，取值来源见 §12.9。
- 转动自由度是 `zr` 而不是 `yr`，且两个轴都带弹簧、平衡位就在开位（左 `zr -80..0`、平衡 −80；右 `0..80`、平衡 80，刚度 15、阻尼 3.5031）——解扣后门会自己弹到开位。因此开片段单次（走完松手，弹簧托住），关片段循环（驱动器持续压到关闭位，直到锁扣扣上），与其余四辆车的车门相反（§7.2）。闭位弹簧力矩是 15 × 80 = 1200 N·m，通用型号的 250 N·m 压不过去，驱动引用 §4.5 的重载型号。
- 开片段是绕铰链轴的单轴旋转：左门 `[0, 0, -80]`、右门 `[0, 0, 80]`，与两侧 `zr` 的开位限位同号（左 `-80..0`、右 `0..80`）。两段的 X、Y 恒为 0，位姿管线对 X、Y 的取反不改变位姿；采样出的目标正好等于开位限位（§12.9）。
- 点击三跳：① 门件交互区的 `signal_targets` 把 `interact_left_front_door` 指向门侧 `connector.machine_max.lock`；② 该连接点与后车身的 `connector.machine_max.left_door_lock` 已配对，信号过边到达对侧；③ 后车身连接点的 `signal_targets` 写 `{"interact": ["subsystem.machine_max.left_front_door_coupler"]}`、`signal_translations` 写 `{"interact_left_front_door": "interact"}`，锁扣解扣。同一次点击的 `global` 由前车身的状态机接住，动画照常切换。
- 两侧 `required_tags` 要互相认：门侧锁扣要求 `machine_max:hull` + `machine_max:series/senna_gtr`（后车身有），后车身锁扣要求 `machine_max:door` + `machine_max:direction/left|right` + `machine_max:series/senna_gtr`（门有）。
- 模板里这两对锁扣的连接记录两侧槽位是反的（`simplePointConnectorName` 写后车身、`advConnectorName` 写门侧）。`VehicleCore#attachConnector` 按 `instanceof` 重排角色，功能不受影响，不改；要改的话 `posRotS` 与 `posRotA` 必须跟两个名字一起换位，只换名字会把姿态贴到错误的连接点上。

### 6.3 Van（5 件）

- 前门两台：旋转驱动，同 §6.1。
- 滑动门两台：平动驱动（§4.2）。铰链连接点已有 `x`（-0.1 到 0，弹簧平衡在 -0.1）与 `z`（0 到 1，弹簧平衡在 1）的限位与刚度 1000 N/m 的弹簧，驱动只写马达目标，限位与弹簧留给连接点。`x` 让门先外让、`z` 是滑行；两者的零点与正方向、以及"平衡位到底算关还是算开"必须在 P0 实测，它决定关片段要不要 `loop`（§7.2）。
- 后备箱盖一台：旋转驱动，`trunk_door_axis` 的 `xr -80..0`，开位在关节坐标系里是 −80°（开片段写模型 +80°，采样器取反后落到 −80°），弹簧平衡位 −80°、刚度 1.4、阻尼 0.22（§12.4）；33 kg 的盖板开位自重静力矩约 220 N·m，通用型号的 250 N·m 余量不足，驱动引用 §4.5 的重载型号。
- 四个车门交互区已存在，前门与滑门都用 `accurate`（贴身的 `fast` 会与上车的座位抢同一次按键），只需在 `signal_targets` 的目标数组里补 `"global"`；频道名（`interact_left_front_door`、`interact_left_back_door` 等）已与状态机事件同名，不用改。后备箱盖没有交互区，按 §5 第 6 步新加一根交互骨骼与一条 `interact.machine_max.trunk_door`。
- 门件变体里另有 `rearview_mirror` 子系统与后视镜命中框，不受本计划影响。

## 7. 标定项

### 7.1 滑动门的锁止窗口

锁扣的锁止判据要求端点相对速率不超过 `max_lock_speed`（起手值 0.25 m/s）。滑动门的接近速度由平动驱动的 `axes.Z.max_speed` 决定（§12.3 取 0.8 m/s），伺服在目标位附近按剩余位移自行减速，末段速度通常已经降下来。扣不上时按下列顺序调，**先调驱动再调锁扣**：

1. 把 `axes.Z.max_speed` 往下压（0.5 → 0.3），每次进游戏确认关合末段能扣上；X 轴的 0.12 m/s 不受影响。
2. 仍不扣，再给滑动门单独一份型号（`door_latch_slide`），把 `max_lock_speed` 提到 0.5。
3. 不要靠放大 `lock_distance` 换取扣合：窗口放大意味着门在离关闭位几厘米处就被焊住，缝是看得见的。

### 7.2 片段的 `loop` 判据

判据是"片段走完松手之后，这个件靠什么停在目标位"：

- 目标位由铰链限位、自重与锁扣承担 → 写 `loop: false`，走完即松手。车门（绕竖直轴、无重力回正，停在限位或由锁扣扣住）属于这一档；盖板的关闭位也属于这一档（关闭位由锁扣扣住，弹簧与自重都推不动它）。
- 目标位没有静力托住 → 写 `loop: true`，由驱动器持续给目标角或目标位移。盖板的开位属于这一档（弹簧平衡位在开限位时力矩为零，自重把盖板带向关闭位）、滑动门的开位也属于这一档（驱动器按 `max_speed` 控速）。

按 §3 与 §6 的读数：车门开、关都单次，唯一的例外是 Senna GTR——它的两台铰链带 `zr` 弹簧且平衡位就在开位（§6.2），所以开片段单次（走完松手，弹簧把门托在开位）、关片段循环（弹簧在闭位有 1200 N·m 力矩，驱动器要持续压到关闭位，直到锁扣扣上）；盖板（Kluo、Wine Fox 的引擎盖与后备箱盖、Van 的后备箱盖，与桑塔纳两块同构）开片段循环、关片段单次；Van 的滑动门开、关都循环——弹簧平衡位在开位，开方向要驱动器按 `max_speed` 控速、关方向要驱动器持续顶住弹簧。

### 7.3 其余不标定

弱化冲击参数取桑塔纳同一组 3.5 / 0.5 / 0.6（小口径几发即脱锁，铰链仍按 15 / 2.0 / 0.30 结算，在门板耐久耗尽之前不脱），方法见 [5.14 连接点标定](../../wiki/5-内容包制作教程/5.14-连接点标定.md)。`separation_impulse` 沿用默认 8 N·s；滑门与盖板的观感在 §8 的 K4 里一并看，需要时逐件写 `0` 或调大。

## 10. 风险

| 风险 | 应对 |
| --- | --- |
| Senna 的三跳任一环漏配，交互区静默不激活（提示不亮、射线选不中、无日志） | 现场顺序排查：先看 F3+B 下交互框在不在（第 1 跳），再看点了动画动不动（`global` 这一跳），最后看锁扣解不解（第 3 跳）。漏的是中间那一跳时表现为"动画动了、门没松"。 |

| 旧存档里的锁扣连接记录 | 连接记录只存连接点名，不存定义；车体侧锁扣是 Advanced、件侧是 Simple，这些记录按 Advanced↔Simple 恢复，锁扣自动接管，不需要迁移。 |
| 生成时门被焊接的姿态与新锁扣 locator 不重合 | 四辆车模板里已有的锁扣对是精确重合的（同款车 byte 一致），恢复走已保存的位姿、不做几何校验，所以打错 locator 会表现为"歪着焊住"而不是"扣不上"；每车 K1 目视一遍门缝即可发现。 |

## 12. 首轮游戏内验收：问题定位与修正方案

首轮进游戏确认了四个现象：Van 左右前门向车内开、Van 滑动门太慢、Kluo／Wine Fox／Van 的引擎盖与后备箱盖合不上、Senna GTR 的两扇车门合不上。前两项是符号约定与速度配置（§12.2、§12.3）；后两项是同一个物理量：**铰链弹簧在闭位的力矩超过 `rotation_joint_driver` 的 250 N·m**（§12.1）。四条修正按 §12.4、§12.5 的取值施工，验收项见 §12.7。

### 12.1 力的读数

`AbstractConnector#adjustJoint` 把 JSON 刚度（单位 N·m/度）乘 180/π 写成 Bullet 关节弹簧的 N·m/rad（[AbstractConnector.java#L331-L348](../../../src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/connector/AbstractConnector.java#L331-L348)），`JointDriverSubsystem#applyServoTarget` 把型号的 `max_force` 写成同一根轴的马达上限（[JointDriverSubsystem.java#L101-L114](../../../src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/JointDriverSubsystem.java#L101-L114)）。两者作用在同一轴上，驱动能把件压到哪由两者之差决定。下表是首轮验收时读到的值，现行取值见 §12.4 与 §12.8：

| 铰链 | JSON 刚度（N·m/度） | 换算后（N·m/rad） | 平衡位 | 闭位偏离平衡位 | 闭位弹簧力矩 | 250 N·m 驱动的可达范围 |
| --- | --- | --- | --- | --- | --- | --- |
| Kluo／Wine Fox 引擎盖 | 17.363193 | 994.8 | +45° | 45° | **781 N·m** | 平衡位 ±14.4°：开只到 59.4°、关只到 30.6° |

四组件的可动区间因此被压在平衡位附近一条 ±(250/刚度) 的窄带里，离锁扣的 4 cm 捕获窗口差一截，锁扣永远捕获不到，表现为"合不上"。桑塔纳两块盖板的闭位弹簧力矩在 250 N·m 以内，这是它通过验收的原因。

修复有两条路：降弹簧或升驱动。盖板的关片段是单次片段，走完松手、闭位由锁扣承力；把驱动升到 800 N·m 以上虽能压到底，松手后锁扣要独自承住 781 N·m，超过桑塔纳锁扣已验收的 172 N·m 量级。所以盖板降弹簧（§12.4），Senna 车门相反（§12.5）。

### 12.2 Van 左右前门的开合方向

### 12.3 Van 滑动门的速度

`translation_joint_driver` 的 `axes.<轴>.max_speed` 是该轴的目标速度（`MotorParam.TargetVelocity`，平动单位 m/s）。滑动门关节的 X 是外让的 0.1 m（模型 x 1.6），Z 是沿车身的 1.0 m（模型 z 16），两轴现在都取 0.25 m/s，1 m 行程 4 s。

| 文件 | 字段 | 施工前 | 落地值 |
| --- | --- | --- | --- |
| `subsystems/joint_driver/translation_joint_driver.json` | `axes.X.max_speed` | 0.25 | 0.12 |
| 同上 | `axes.Z.max_speed` | 0.25 | 0.80 |

两轴并发：X 的 0.1 m 用 0.83 s 让完，Z 的 1 m 用 1.25 s 滑完，一次开合由 4 s 降到 1.25 s，门的动作是先外让再长距离滑行。`max_force` 保持 1600 N（连接点弹簧 1000 N/m，关门要从平衡位压回 0）。

### 12.5 Senna 车门与 Van 后备箱盖：重载驱动型号

Senna 的两台车门铰链是倾斜的 `zr` 轴，弹簧同时充当自重回正：平衡位就在开位，门松手后靠 859 N·m/rad 的刚度把开位偏差压在几度以内。若把刚度降到 250 N·m 能关上的水平（≤3 N·m/度），开着的门会大幅下垂，而它的开片段是单次片段、走完就松手（§7.2），没有别的力托住门；要托住就得把开片段改成循环，等于换一套开合模型并重新验收摆动观感。因此 Senna 车门保留弹簧、升驱动：

- 重载型号取 §4.5 的定义：三个旋转轴 `max_force` 1500 N·m、`max_speed` 180 °/s。
- 数值依据：闭位弹簧 15 × 80 = 1200 N·m；阻尼 3.5031 N·m·s/度 ≈ 200.7 N·m·s/rad，180 °/s 时约 630 N·m。1500 在闭位留 300 N·m 净力矩，门能压到底并让锁扣捕获；关合过猛时向下调，下限是 1200（闭位弹簧力矩本身）。
- `parts/senna_gtr/senna_gtr_hull.json` 的两台车门驱动改引用这份型号。
- Van 后备箱盖同样改引用：33 kg 的盖板按力臂约 0.7 m 估，开位自重静力矩约 220 N·m，250 N·m 的驱动余量不足。它的关片段单次、闭位弹簧力矩 112 N·m（§12.4），重载驱动关到位后松手由锁扣承力，不受影响。

### 12.8 第二轮验收：三处修正

第二轮进游戏又确认了三处：Van 后备箱盖开向反了、Van 前门交互区是贴身触发、Senna 车门点开后约 1 秒才动。前两处是取值与交互模式写错，第三处是倾斜轴的朝向挂错了骨骼，复算与落地见 §12.9。

| 现象 | 原因 | 修正 |
| --- | --- | --- |
| Van 后备箱盖朝车内开 | 关节坐标系里的开位是 −80°，此前限位与弹簧平衡位都填成 +80，驱动器与弹簧一起把盖板往车内推 | `connectors/van/van_back_door_axis_hull.json` 的 `xr` 限位改 `-80..0`、平衡位改 −80；`animations/part/van/van.animation.json` 的 `trunk_door_open` 旋转改 `[80, 0, 0]`（§12.4） |
| Van 前门交互区是 `fast` | 早期 Van 的车门交互区按贴身触发写的，与上车的座位抢同一次按键 | `parts/van/van_door.json` 的两扇前门改 `"interact_mode": "accurate"`；交互体积本来就包住门板命中框，射线先碰到交互区（§4.4） |
| Senna 车门点开后约 1 秒才弹开 | 倾斜轴的朝向写在铰链 locator 上、被动画的骨骼自身静止旋转为零：位姿管线在一根骨骼内部把动画欧拉角按分量加到静止欧拉角上（`OBoneAnimation#getPresentAnimValue` 的 `mul(-1f, -1f, 1f)` 与 `BonePose` 的 `getLocalRotation().add(bone.rotation)`），一根带倾斜的骨骼拿不到"绕铰链轴的单轴旋转"，只能用三轴欧拉角去凑。凑出来的骨骼旋转确实是绕铰链轴的 80°，但方向落在关节坐标系的 +80°，而开位是 −80°；目标被限位钳到 0，驱动器把门按在关闭位，直到单次开片段走完松手、弹簧才把门顶开 | 倾斜角改挂父骨骼 `LeftDoorHingeTilt` / `RightDoorHingeTilt`，被动画的子骨骼在父坐标系里静止旋转为零、只绕自身 Z 轴转（`models/part/senna_gtr/senna_gtr_front_hull.geo.json`）；两段开片段写成 `[0, 0, -80]` 与 `[0, 0, 80]`（`animations/part/senna_gtr/senna_gtr.animation.json`），采样目标正好落在两侧的开位限位（§12.9） |

由此得到一条作者口径：**倾斜轴的朝向挂在铰链骨骼的父骨骼上，被动画的骨骼在父坐标系里静止旋转为零**，片段只写绕该骨骼自身 Z 轴的角度。用三轴欧拉角去凑倾斜轴上的旋转，形状与符号都不受片段本身约束（引擎把动画欧拉角按分量加到静止欧拉角、再按 ZYX 合成，只有跨骨骼才是矩阵相乘），凑出来的值必须靠复算才能确认。

### 12.9 第三轮验收：Senna 车门的倾斜轴改挂父骨骼

第三轮进游戏时，Senna 车门表现为"点开后约 1 秒才弹开"；反馈指出倾斜应当由骨骼组承担、locator 相对组归零。复算证实这个方向对，且需要**两根**骨骼：只把倾斜挪到被动画的那根骨骼上，拿不到绕铰链轴的单轴旋转（`[0, 0, -80]` 的片段只采样出 −30.25°）。

复算脚本按 `JointDriverSubsystem#getPhysicsSpaceLocatorMatrix` 与 `JointTargetSampler` 的算法实现：骨骼内部静止欧拉角与动画欧拉角逐分量相加后按 `rotateZYX` 合成，跨骨骼矩阵相乘，动画欧拉角的 X、Y 先取反，位姿差换算到关节坐标系后按 XYZ 分解、ZR 轴取反。左门三种写法的结果：

| 倾斜挂在哪 | 开片段 | 采样出的关节目标 | 与开位限位 −80° 的关系 |
| --- | --- | --- | --- |
| 铰链 locator 上 | `[62.760834, 9.096452, 57.483538]`（X、Y 被引擎取反后是绕铰链轴的 +80°） | +80° | 反向，钳到 0，门被按住 |
| 被动画的同一根骨骼上 | `[0, 0, -80]` | −30.25° | 只开到约三成 |
| 父骨骼上、动画骨骼静止为零 | `[0, 0, -80]` | −80° | 正好等于限位 |

同一套算法跑 Van 左前门作校准（locator 只有位置、片段 `[0, -80, 0]`）：采样目标 +80°，与 `yr` 的限位映射一致——JSON 的 `-80..0` 在 `adjustJoint` 里交换取反后是关节的 `0..80`，所以开位在关节坐标系里是 +80°，算法的符号与关节约定对得上。

落地两处：`models/part/senna_gtr/senna_gtr_front_hull.geo.json` 新增 `LeftDoorHingeTilt` / `RightDoorHingeTilt` 两根父骨骼（静止旋转取 `[39.3953, -41.3265, -15.0263]`，右门镜像为 `[39.3953, 41.3265, 15.0263]`，枢轴取铰链点），`LeftFrontDoorHinge` / `RightFrontDoorHinge` 改为它们的子骨骼、静止旋转为零，铰链 locator 只留位置；`animations/part/senna_gtr/senna_gtr.animation.json` 的 `left_front_door_open` / `right_front_door_open` 写成 `[0, 0, -80]` / `[0, 0, 80]`，注释写明约定。

整条链的静止位姿与倾斜留在 locator 上时相同（同一组角度、同一个枢轴），所以连接点帧、门侧帧与关节限位都不动；改动只影响"动画旋转如何进到 locator 的位姿里"。验收项见 §12.7 的 K11 与五辆车 K1–K7 复跑；写进作者文档的部分见 [5.2 模型与动画](../../wiki/5-内容包制作教程/5.2-模型与动画.md) 的「倾斜轴铰链：朝向写在父骨骼上」。

### 12.10 第四轮验收：快速上座区按车门状态门控

第四轮验收指出：Senna、Kluo 这类车的快速上座区在车门关着时照样一步坐进车里。`fast` 交互区是玩家包围盒与体积接触即触发，它不认识门板——玩家站在门外会同时落在门边拉手区与舱内快速上座区里，按键有机会先命中后者。

这是内容侧少了一道门控，`fast` 本身仍适合上座。落地方式按锁扣与交互区在不在同一个 `Part` 分两种：

| 车 | 快速上座区 | 锁扣 | `condition` |
| --- | --- | --- | --- |
| Kluo / Wine Fox | 车体零件 | 车体零件（同一 `Part`） | `!local.has_connector('connector.machine_max.<侧>_door_lock')` |
| Senna GTR | 底盘零件 | 车尾车体零件（跨 `Part`） | `global.get('senna_<侧>_door_latched') == 0` |

为此给锁扣子系统加了 `state_outputs`（安装属性里的「频道 → 目标」表，每 tick 发 `1` 扣合、`0` 未扣合）。Senna 的两把锁扣各声明一个频道（`senna_left_door_latched`／`senna_right_door_latched`）写进 `["global"]`，底盘上的快速上座区按名读装配体信号存储。Kluo 与 Wine Fox 的锁扣与交互区同在一个 `Part`，连接点名够用，不发布状态。

三点取舍：

- **只读锁扣一个位。** 锁扣只在装上件且关到位时才有对端，所以这一个位覆盖「没装门 / 开着 / 关着扣好」。锁扣被打脱、门板还虚掩着的那一档读不出区别，按"门没挡着"处理。
- **只门控快速上座区。** 门边拉手区保持恒可交互，否则门打不开；舱内 `accurate` 入座区不必门控，`accurate` 的射线碰到门板命中框就停，从车外选不中它。
- **发数字不发布尔。** `global.get` 与 `local.get` 只认 `Number`，布尔会静默读成 0，门控条件 `== 0` 于是恒成立，锁扣等于没接。

离线校验：`checkContent`、`checkSchemas`（coupler 动态属性 schema 的双语源加了 `state_outputs`，副本由 `syncSchemas` 生成）；`CouplerGameTest` 新增 `stateOutputsPublishLatchBit`，用 Senna 车尾车体与左前门夹具钉住「扣合发 1、解扣发 0」。作者口径写进 [5.3 零件定义](../../wiki/5-内容包制作教程/5.3-零件定义.md) 的「用 condition 让快速上座区随车门状态出现」与 [5.14 连接点标定](../../wiki/5-内容包制作教程/5.14-连接点标定.md) 的「扣合状态对外发布（state_outputs）」。
