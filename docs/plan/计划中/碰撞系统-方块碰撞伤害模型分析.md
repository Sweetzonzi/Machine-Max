# 碰撞系统 — 撞碎与压溃实现计划

**状态：待实现。** 本文规定实现边界、数据流和验收条件；列为“起步公式”的数值口径需要通过标定验收，不代表已经验证的游戏参数。

**目标：** 普通零件通过撞击破坏方块；专用子系统通过持续接触载荷执行压溃、推土一类作业。支持没有 Machine-Max 专属数据的第三方方块。

**路径约定：** `src/` 相对于 Machine-Max 仓库根；`../Spark-Core`、`../BallisticsFramework`、`../Libbulletjme` 是同级源码仓库。正文的文件名简写由 §2 的源码表定位。拟创建的类型与接口会明确标注，不能当作已存在 API 使用。

## 0. 实现必须遵守的决定

1. 普通撞击与子系统压溃是两条处理路径。普通刚体没有持续压溃能力。
2. 方块破坏可以在 `Processed` 或 `Post` 发生；针对部件的碰撞伤害计算、投递统一在物理子步的 `Post` 发起。
3. `Processed` 的单点预测足以破坏目标时，立即标记方块失效，并同步禁用相关接触。这类障碍的阻力按游戏近似忽略，不施加人工反冲。
4. 单点预测不足时，接触由引擎正常求解；`Post` 根据本步实际冲量聚合判破坏。已经发生的减速保留。
5. “弱方块”是单次接触比较的结果，不要求维护“即时破坏材质”标签或新方块属性。现有耐久计算中的原版标签修正可以使用。
6. 速度门控在 `Processed` 完成。一次方块碰撞组通过门控后，`Post` 聚合该组本步的全部有效接触冲量；不逐点反算求解前速度。
7. **每个服务端 `PhysicsLevel` 每物理子步至多遍历一轮全部 manifold。** 遍历由 Level 级管理器负责，禁止在每个 SubPart 或每个载具内重复枚举。
8. **逐接触点定位方块、按块聚合。** 一个 manifold 可以覆盖多个方块；一个方块也可以被多个 manifold、多个零件同时命中。
9. 实现使用现有 JNI 查询接口。减少的是各零件重复遍历产生的 JNI，不以“一次批量 JNI”为本期要求。
10. 不缓存跨阶段的裸接触点 ID；不缓存刚体位姿、线速度、角速度快照；不启用 Started/Ended 注册表来维持本流程。
11. 普通撞击以冲量作为起步伤害口径。不得把包含关节传力的接触冲量用 `J² / (2 × 零件自身质量)` 随意换成耗散能量。
12. 方块耐久、背撑加成、材料防护和现有伤害投递基础可以使用；不要求内容作者提供接触面积、三种材料强度或真实土体仿真数据。

## 1. 要解决的问题与代码现状

### 1.1 游戏表现

- 数十吨车体以很低高度直接落地时，容易破坏泥土乃至石头；需要能明确标定的低落差容忍区间。
- 轮子等轻小接触零件承受车体传力；只看零件自身质量会漏算，只给它分配一份整车质量又可能高估。
- 树叶等相对于本次撞击很弱的障碍，应在本步求解前失效，避免先产生完整刚性阻挡。
- 普通撞车应保留真实的速度损失。推土铲等工具则需要以较低速度、持续载荷完成作业。
- 第三方方块通常只有硬度与爆炸抗性；不能要求兼容模组为每种方块提供完整力学材料表。

### 1.2 当前实现的事实基线

`CollisionHandler.java#applyBlockDamage` 使用的有效表达式是：

```text
u = abs(contactVel · normal)
E = 0.5 × equivalentMass × u² × (1 - restitution)
E_block = E × partArmor / (partArmor + blockArmor)
break iff blockDamageFactor × E_block > 250 × blockDurabilityWithSupport
```

源码中“把接触冲量除以质量后加到速度”的项是注释，不参与上述计算。`CollisionHandler.java#onContactProcessed` 的注释称回调在求解后，但原生实际时序是求解前，见 §2.2。实现者必须以有效代码和原生时序为准。

`MassUtil.java#getEquivalentMass` 的当前表达式为本体质量、相连零件质量的 0.3 倍、装配体其余质量的 0.05 倍之和。它没有描述关节允许的方向、弹簧行程、其他接触分担和偏心转动。

当前风险集中在以下位置：

| 问题 | 影响 | 本计划的处理位置 |
| --- | --- | --- |
| 每接触点用估算质量构造一份能量 | 多个点可能各自领取过多惯性参与量 | §5 单点预测的范围；§6 实际冲量聚合 |
| 用绝对法向速度 | 分离速度也可能触发撞击 | §3.1 有符号接近速度 |
| 方块、部件伤害在接触回调中直接结算 | 混用历史冲量与本步输入，难以去重 | §7 Level 级 Post |
| 伤害数值写进 `penetration` | 护甲穿透、未击穿开关和随机跳弹影响碰撞掉血 | §8 显式碰撞上下文 |
| 碎块后 `applyImpulse`，伤害接收端还有击退回退 | 可能在引擎响应之外再次改变速度 | §8.2 显式零额外冲量 |
| 用小于 1 HP 的条件丢掉逐点伤害 | 接触拆分、物理频率会改变结果 | §8.1 先聚合再走材料修正 |

`CollisionHandler.java#handleCreateTerrainCollision` 当前处理 Create 接触材料和子系统钩子，没有与原版地形等价的方块删除通路；§10 对它定义适配边界。

### 2.2 回调时序与接触点生命周期

单个物理子步依次执行：

```text
Pre → 速度预测 → 碰撞检测〔Conceived / Processed〕
    → 关节与接触约束求解 → 积分 → Post
```

- `Processed` 读取的 `appliedImpulse` 是历史缓存，新点可能为零；不能用它作本次即时破坏依据。
- `Post` 查询本轮求解后仍存在的点，读取的是本步写回值。当前 Spark 已启用 WarmStart；须保持其开启，接口对关闭 WarmStart 的取值没有本计划所需保证。
- `setDistance1(id, 500)` 只写距离；它用于使当前约束失效，不等于立即从 manifold 中删除点。下一次刷新会重算几何距离。
- 刷新循环逆序处理点；删除低槽位的点时，末尾仍存活的点会搬到空槽。它可能已经发过本步 Processed 回调，所以同一步内裸 `pointId` 也不是稳定身份。
- `getAppliedImpulse(pointId)` 直接把 ID 转成原生指针；它不是能返回“对象已删除”的安全查询。
- 每个 manifold 至多四点，点与方块不是一一对应关系。Started/Ended 表达空/非空接触变化，不能解决逐点搬移；本流程不依赖它们。

以上结论分别由 §2.1 的原生相位、点刷新、冲量写回和 JNI 坐标支撑。保持当前 `Processed`/`Conceived` 接线即可，禁止为本期引入稳定点 token、原生求解后回调或批量 JNI。

## 3. 基本口径与分组键

### 3.1 方向、单位与门控

对地形接触统一令 `n` 为“从地形指向零件”的单位法线，`v_rel` 为零件表面速度减去对方表面速度：

```text
u = max(0, -dot(v_rel, n))       // m/s；只认接近
J = max(0, appliedImpulse)       // N·s；本步法向冲量
dt = 实际物理子步长度             // s，不是游戏 tick 时长
```

速度必须包含 `ω × r`，计算可沿用 `CollisionHandler.java#onContactProcessed` 中 `MMMath.relPointWorldVel` 的调用形态。运动学 Create 对方也需要其表面运动；不能以“非动态刚体”等同于“速度为零”。

普通 Post 撞击门控为 `u >= impactMinSpeed`，且 `impactMinSpeed > approachEpsilon >= 0`。候选资格只在当前子步内有效；同一组本步任一点通过，即收集该组本步所有有效接触的冲量，不要求这些点分别再次通过门控。下一子步重新决定资格，禁止把一次高速接触永久扩展成静载损伤。

即时破坏先于普通 Post 速度门控尝试，只要求 `u > approachEpsilon` 并满足 §5 的预测门槛。这样低速通过很弱的障碍不受普通损伤速度门槛限制；重车轻落地也必须检查即时分支，不能仅靠 Post 门控宣称安全。

### 3.2 拟使用的数据键

所有键都处于一个 Level 级管理器内，Level 身份由管理器隔离。对象 ID 使用本步有效的刚体 native ID；只把它作为 Java 索引值，不延迟解引用原生点。

| 拟使用的键 | 字段 | 含义 |
| --- | --- | --- |
| `TargetBlockKey` | 地形对象身份、方块坐标及坐标域 | 原版地形用世界 BlockPos；Create 用装置身份和本地 BlockPos |
| `TerrainImpactKey` | 零件刚体 ID、HitBox 索引、TargetBlockKey | 普通撞击的速度资格与材料贡献组 |
| `PartPairKey` | 排序后的两刚体 ID、各自 HitBox 索引 | 零件间撞击，双方回调只登记一个组 |
| `EntityImpactKey` | 零件刚体 ID、HitBox 索引、实体 UUID/代理身份 | 零件与生物碰撞的组 |
| `PartDamageKey` | SubPart 身份、HitBox 索引、伤害来源类别 | 部件 Post 伤害投递组 |
| `CrushWorkKey` | 子系统/工具身份、作业面、TargetBlockKey | 专用作业任务，允许跨子步保存进度 |

`manifoldId` 和 `pointId` 都不出现在跨阶段候选键中。一次 Post 中同一个当前接触点仅枚举一次，零件—零件接触只分发一次物理记录，再分别计算双方受伤。

方块聚合可以接收不同零件、不同车辆的贡献；部件受伤只使用该部件实际承受的贡献，不能把方块总冲量给每个零件重复使用。

### 3.3 目标定位必须由两阶段共用

拟建立一个纯解析适配层，把“碰撞双方＋双方子形状索引＋接触位置/法线”转成上述键和目标数据。Processed 与 Post 使用同一实现。

- 先识别哪一侧是 SubPart，统一法线方向，再选取相应的 HitBox 索引。`normalWorldOnB` 指向 A；零件在 B 时须取反。
- 原版地形以地形侧接触位置定位方块。现有 `PhysicsChunkSection.kt#getBlockPosFromContactPoint` 只做偏移与 floor，不提供稳健的表面归属判断；解析层须覆盖整数边界、负坐标、薄形状和 section 边界，必要时沿 `-n` 向方块内部偏移一个几何小量并验证快照。
- Create 使用 `CreateCollisionResolver.java#resolve` 的子形状映射。`../Spark-Core/src/main/kotlin/cn/solarmoon/spark_core/compat/create/CreateContraptionPhysicsHost.kt#getContactBlockPosByChildShapeId` 返回装置本地坐标，不能与原版世界 BlockPos 混用。
- 一个 manifold 中各点分别解析目标，不能读取第一个点后给整组套同一个方块。
- 无法解析或快照不存在时不破坏方块、不创造伤害；保留正常物理响应，诊断计数加一。物理线程禁止为解析目标同步加载区块。

## 4. 方块抗性：使用现有耐久与背撑

### 4.1 耐久基线

第一版使用 `DamageUtil.java#getMaxBlockDurability`。其现行默认表达式为：

```text
普通：100 × (0.01 + H)
泥土/雪/沙、羊毛/羊毛地毯：200 × (0.01 + H)
树叶：10 × (0.01 + H)
黏性方块：1000
随后乘 (0.25 + 0.75 × 碰撞形状包围盒体积)
```

标签分支按该方法源码顺序匹配。这些是游戏耐久映射，不是材料压缩强度。第三方方块没有匹配标签时自动走普通分支，无需配置新字段。硬度小于零在调用此公式前按不可破坏处理；空碰撞形状、NaN、无穷值必须有守卫。

部件/方块的相对抗性可使用部件现有 RHA 与 `ArmorUtil.java#getBlockArmor`。后者当前由爆炸抗性与硬度共同计算：`100 × log10(R + 1) × log10(1.001 + H)`。本期不改投射物的 RHA 与材料定义。

### 4.2 背撑

沿受力进入方块的方向查询紧邻后方一个位置，使用物理快照与逻辑移除状态：

```text
D_star = D_target + 0.5 × D_back
```

无有效实体支撑时 `D_back = 0`。不能仅以“不是空气”或“快照对象非 null”判支撑；液体、空形状、已逻辑移除的方块不提供此加成。不可破坏的背撑不能把负硬度代进耐久函数；此时明确取 `D_back = D_target`，保证前方普通方块不因背后一块基岩变成无限耐久。

同块不同面可能有不同背撑。聚合期间保存各贡献的 `D_star`，按传入的有效方块冲量加权求平均；总有效贡献为零时不判碎。单点即时判定直接用该点的值。所有贡献必须使用同一纯函数计算背撑，不能由最后枚举到的点覆盖门槛。

### 4.3 冲量阈值与材料分配的起步公式

沿用耐久数值不等于沿用能量换算系数。普通撞击的起步门槛为：

```text
J_break = C_J × D_star            // C_J 单位 N·s / 耐久点
```

不得把原式中的 `250` 直接当作已经标定的 `C_J`。

起步分配函数取 `A_p = max(0, partRha)`、`A_b = max(0, blockArmor)`：和大于数值 epsilon 时 `w_block = A_p / (A_p + A_b)`，否则取 0.5；`w_part = 1 - w_block`。所有输入先判有限性。

```text
方块贡献 I_block = max(0, blockDamageFactor) × w_block × J
部件贡献 I_part  = w_part × J
```

这是一条共享的游戏伤害分配曲线，不宣称双方吸能按此精确分配。防护较高的一方承受较小的碰撞损伤；`blockDamageFactor` 只调破障贡献，不放大对自身的伤害。履带表面材料必须经 `SubPart.java#contactMaterial` 取值，部件防护经其现有履带装甲选路取值。

同块聚合先把各点的 `I_block` 相加，再与 `C_J × 加权D_star` 比较；不得先将总冲量套到某一个命中箱的材料上。未达到门槛的普通撞击不保存跨子步“方块掉血”进度。

## 5. Processed：单点即时撞碎与候选登记

### 5.1 分支顺序

1. 服务端权威检查、目标解析、接触有效性检查。
2. 已逻辑移除的目标：禁用当前接触并结束。
3. 摩擦、恢复系数、轮胎滑移、攀爬辅助等求解前物理处理；已经被辅助路径禁用的接触不登记撞击资格。
4. 调用子系统接触钩子。专用作业面可以登记 §9 的压溃任务并认领方块处理权。
5. 默认撞击路径：允许破坏时做单点即时预测。
6. 接触保留且通过普通撞击速度门控时登记 TerrainImpactKey；目标不可破坏或地形破坏开关关闭时，也可登记部件伤害资格。
7. 记录碰撞表现数据；此阶段不调用针对部件的 `BFDamageApi.hurt`。

现有攀爬辅助分支会在子系统钩子之前返回，见 `CollisionHandler.java#handleTerrainCollision`。工具工作面应显式避开攀爬辅助吞掉作业接触，或把工作面声明接线放在该返回分支之前；不能假设所有接触必然到达当前钩子。

### 5.2 单点预测

对静态地形，使用接触刚体的方向有效质量：

```text
1 / m_n = 1 / m + (r × n)^T × inverseInertiaWorld × (r × n)
J_hat = (1 + e) × m_n × u
```

`r` 从该刚体质心指向接触点；`e` 使用本次接触的合成恢复系数，并限制在本期支持的 [0,1] 范围。该式是“孤立接触若阻挡本体所需作用量”的预测，不能解释成求解器已经施加的冲量。

**第一实现阶段只使用接触刚体本体及其转动惯量。** 不调用 `MassUtil.java#getEquivalentMass`；不按整车质量或接地点个数分摊。后续可支持全六自由度刚性锁定的刚体簇，但必须连同总质心、合成惯量和接触杠杆计算；悬挂、铰链、弹簧和临时触底不直接并成刚性簇。

把 `J_hat` 代入 §4.3 的同一分配函数，单点贡献达到 `J_break` 即破坏。Processed 使用预测输入，Post 使用实际输入；两者共用耐久、背撑、材料分配和比较函数，不维护两份方块强度公式。

预测有意不计柔性连接传来的后续作用；该部分由正常约束求解及 Post 体现。单点预测也不保证多个同时接触的能量预算守恒。§13 的连续多块与大车底落地案例必须覆盖即时分支；若可忽略阻力的范围过宽，应标定预测增益/余量或提出独立预算扩展，不能偷偷恢复质量加权或人工速度修正。

### 5.3 即时破坏的原子语义

拟提取共享 `disableContact` 帮助方法，统一设置禁用距离哨兵 500，并清零法向、两个切向缓存冲量。实现时将本模组的无效点、已移除块、即时破坏分支统一接入它；Post 排除距离达到该哨兵的点，避免读取到没有参与本步求解的历史缓存。现有攀爬辅助的 5000 距离也属于禁用范围。

首次确认即时破坏时执行：

- 物理线程立刻调用目标适配器的逻辑移除，使后续该块接触查询失效。
- 禁用当前点；同一块后续回调也必须禁用自己的点。不得只处理触发破坏的一个点。
- 若已有该块的本步普通候选，将其标记为 `PRE_BROKEN` 并排除后续 Post 撞击统计。
- 主线程按目标键去重执行实际方块删除和掉落；任务需核对目标身份/预期 BlockState，防止延迟任务删除已经被替换的目标。

默认该分支对部件的碰撞伤害为零：约束被禁用，不能以预测的“假如未碎会受到的冲量”伤害自身。附加割伤/磨损不是本期默认行为。禁止调用 `applyImpulse` 或恢复/改写速度。

## 6. Post：一次枚举，逐点按块聚合

### 6.1 管理器与生命周期

拟创建 Level 级 `CollisionSettlementManager`，由 ObjectManager 持有；它不属于 VehicleCore 或 SubPart。一个管理器保存本子步的候选、刚体引用索引、结果累计器和只读接触结果。

- `beginStep` 放在 `ObjectManager.java#onPrePhysicsTick` 的物理业务之前；清空本步集合，保存实际 dt/子步序号。当前 `PhysicsLevel.kt#stepPhysics` 每次以 `1 / tps` 做固定单步，事件没有 dt 参数时据此取值；不要硬编码 0.01 或用游戏 tick 的 0.05。
- Processed 把对象引用、键和必要的目标/材料数据登记进去；不保存运动快照、裸点 ID。
- `collectAndSettle` 放在 `ObjectManager.java#onPostPhysicsTick` 开头，先于载具/子系统的 Post 业务；子系统应能消费本步已收集的作业反馈。
- 当前 Spark 在 Level Post 事件前还会发出逐刚体 PhysicsTick.Post，见 `PhysicsLevel.kt#physicsTick`。MM 必须保证这些更早的回调不删除本期候选物理体或更换碰撞形状；若接入时发现此类路径，需调整采集钩子到它们之前，不能依赖过期 native 对象。
- Level 卸载、物理世界重建时释放管理器及跨步作业任务；异常路径也清空本步集合，避免候选遗留到下一子步。

### 6.2 JNI 查询预算

本步有撞击或压溃候选时只调用一次 `PhysicsSpace.java#listManifoldIds`；没有候选可以直接结束，枚举次数为零。该方法内部包含逐 manifold JNI，本期接受这种实现。

逐 manifold 读取双方 ID 一次，先用本步候选对象索引筛选；每个刚体的 Java 引用/owner 分类在本轮缓存，避免每点重复调用 `PhysicsCollisionObject.findInstance`。相关 manifold 再调用一次 `countPoints`，按索引取点，复用临时数学对象。

复杂度目标为 `O(M + P_relevant)`，不是“零件数 × 全空间 M”；M 为本空间 manifold 数。优化不能依靠遗漏其他车辆、公共装配体或某些 HitBox 的接触。

### 6.3 单点处理与聚合

对每个当前点：

1. 统一 A/B 身份，解析两侧 HitBox 与目标；应用有效接触检查，过滤本模组禁用哨兵、PRE_BROKEN 目标和无效快照。
2. 读取本步法向冲量，只有有限、正值才贡献普通撞击；保持 WarmStart 条件，不能混入禁用点的旧缓存。
3. 地形点先逐点解析 TargetBlockKey，再查 TerrainImpactKey 资格。相同 manifold 中其他方块不能被这个资格放行。
4. 将本点材料加权的方块贡献和对应背撑条件加入该块累计器；同时把本零件承担的贡献加入 PartDamageKey。
5. 零件—零件点读取一次，按 PartPairKey 资格分别计算双方贡献；交换 A/B 不得重复生成第二份物理作用量。
6. 作业面接触即使没有普通速度资格，也向 §9 的作业载荷累计器贡献；同一个物理点只读取一次，分发给需要它的累计器。

不能把法向标量冲量按世界方向相加后用矢量模长判破坏；从两侧挤压同一块时，不应因方向相反而抵消。用于伤害的标量贡献、用于表现的方向/位置数据分别保存。

**整个枚举阶段只读物理世界。** 枚举完成后先固定所有部件贡献，再决定碎块/作业结果，最后投递部件伤害。Post 碎块不能把已经发生的部件撞击一并抹掉。

### 6.4 总体伪代码

```java
beginStep(dt) {
    clearStepData();
    this.dt = dt;
}

processed(contact) {
    // 目标、物理预处理、子系统钩子按 §5.1 排序。
    if (targetAlreadyRemoved(contact)) { disableContact(contact); return; }
    if (!toolOwnsBlock(contact) && canBreakTarget(contact)
            && instantPredictionPasses(contact)) {
        markPreBrokenAndScheduleRemoval(contact.target());
        disableContact(contact);
        return;
    }
    if (contact.closingSpeed() >= impactMinSpeed) registerImpactGroup(contact);
    if (toolOwnsBlock(contact)) registerCrushGroup(contact);
}

post() {
    if (hasCandidates()) {
        for (long manifold : world.listManifoldIds()) { // 全 Level 仅此一轮
            var pair = resolveRelevantBodiesOnce(manifold);
            if (pair == null) continue;
            int count = PersistentManifolds.countPoints(manifold);
            for (int i = 0; i < count; i++) {
                long point = PersistentManifolds.getPointId(manifold, i);
                collectCurrentPoint(pair, point);       // 只在此调用栈读取裸点
            }
        }
    }
    freezeCollectedContributions();
    decidePostBlockBreaks();
    advanceExclusiveCrushTasks(dt);
    deliverPartCollisionDamage();
    clearStepData();
}
```

伪代码中的管理器方法和数据类型是拟实现接口。它展示职责与顺序，不替代 §5 的有效性、权限与工具认领检查。

## 7. 普通撞击的结果语义

| 结果 | 方块状态 | 部件伤害 | 速度处理 |
| --- | --- | --- | --- |
| Processed 单点预测通过 | 求解前逻辑移除 | 默认零 | 禁用接触，不加人工冲量 |
| Post 聚合通过 | 本步求解后逻辑移除 | 按本步真实贡献计算 | 保留引擎造成的减速 |
| 聚合不足 | 正常存在 | 按本步真实贡献计算 | 正常引擎响应 |
| 低速、无普通资格 | 正常存在或被即时分支破坏 | 无普通撞击伤害 | 正常响应或已禁用 |
| 不可破坏/破坏开关关闭 | 正常存在 | 仍允许部件撞击伤害 | 正常引擎响应 |

Post 碎块的掉落率可保留“超额越大，完整掉落越少”的单调曲线，以本次总有效贡献除以门槛计算，且每块最多一次掉落决策。不按某个随机接触点的值决定。

## 8. 部件伤害投递与去重

### 8.1 所有部件碰撞伤害在 Post 发起

范围包括零件—原版地形、零件—Create 地形、零件—零件，以及零件—生物路径中对零件的一侧。Processed 保持材料设定、子系统通知与表现采样，不发起这些部件伤害。

起步伤害为 `baseDamage = C_D × ΣI_part`，先按 PartDamageKey 聚合，再调一次材料伤害修正；第一版取线性响应，防止接触点拆分改变总伤害。只丢弃有限的数值噪声，禁止逐点用“修正后 > 1 HP”作门槛。材料配置中的固定减伤依然是显式玩法参数；标定时必须检查它在不同物理频率下的效果。

这不要求绕过 `BFDamageApi`。拟在 `MMDamageExtensions` 增加 `COLLISION_IMPACT` 布尔标记，默认 false，并规定：

1. 上下文带有效 `HIT_BOX`、`baseDamage`、代表性命中位置/法线和标记；`penetration = 0`。
2. `SubPart.java#resolvePenetration` 对此标记直接返回 BLOCKED，跳过弹道跳弹随机数和穿深判定。
3. `SubPart.java#calculateFinalDamage` 对此标记走碰撞伤害分支：对已完成相对防护分配的 baseDamage，调用现有 `modifyArmorDamage` 完成材料修改；碰撞分支忽略 `unpen_power` 与穿深比例。弹丸上下文没有此标记，执行弹丸规则。
4. 履带装甲选路、伤害事件、子系统拦截、装配体记账与主线程耐久落地使用既有管线；必须有覆盖测试。`SubPart.java#isArmorPenetrated` 的碰撞上下文应报告未穿透，使音效/效果不把它当弹孔。

以上是本计划选定的碰撞上下文契约，不准把 HP、Bullet 数值穿透深度或冲量伪装成毫米穿深来使伤害“通过”。扩展 key 注册位置为 `src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/data/MMDamageExtensions.java#HIT_BOX` 所在类；协议入口为 `../BallisticsFramework/src/main/java/io/github/sweetzonzi/ballistics_framework/api/BFDamageApi.java#hurt`。

### 8.2 物理作用与伤害呈现分离

所有上述碰撞上下文必须显式写 `BFDamageExtensions.IMPULSE = 0`；该字段表示伤害接收端需要额外施加的冲量，不是遥测字段。实际接触 J 放在诊断记录或独立碰撞元数据里。

`SubPart.java#hurt` 对缺少显式 IMPULSE 的某些伤害会生成回退击退，地形路径当前使用 flyIntoWall，不能只依靠 PART_COLLISION 类型排除回退。显式零值必须在履带与普通零件路径都保持，避免第二次施力。

物理线程的 Post 负责计算与调用协议；耐久扣减仍按 `SubPart.java#settleAccumulatedDamage` 在主线程落地。为避免合并不同来源产生错误修正，PartDamageKey 包含伤害来源类别；地形与生物保留其合适来源，零件间使用现有 PART_COLLISION。

### 8.3 生物碰撞边界

当前 `CollisionHandler.java#processEntityCollision` 自算冲量、改变生物代理速度、排入实体击退，同时给零件减速。生物代理可能是运动学体，它不等同于可自由响应的动态刚体。

本期要求对零件的伤害迁入统一 Post，优先使用当前接触实际冲量。生物伤害与原版击退桥接另行保留明确职责，不能因“没有人工地形反冲”而盲删生物桥接，也不能让代理响应、实体桥接与人工零件反冲重复作用于同一侧。实施这一阶段须验证代理类型与实际冲量；若某种代理没有可用接触求解结果，写明受限路径并在 Post 使用显式兼容估计，不能继续在 Processed 直接伤害零件。

## 9. 专用子系统压溃/推土

### 9.1 定义与接口边界

压溃是工具作业模型：接触载荷达到门槛，作业进度随时间增长，达到完成值后破坏目标。不要求材料面积、土体主应力、真实压入量；不以 Bullet 穿透深度冒充材料应变。

普通车体、轮胎、履带停车均没有该进度。工具必须通过已有 `AbstractSubsystem.java#onCollideWithBlock` 钩子，向本步管理器登记作业面、目标和工具参数。现有 void 钩子及脚本调用约定保持；拟提供管理器方法 `claimCrushContact` 进行认领。

认领具有以下语义：

- 仅在工具启用、指定 HitBox 是工作面、朝向符合工具参数且具有有效载荷能力时登记。
- 被工具认领的方块碰撞组由压溃路径决定块破坏，该组的默认即时/聚合撞碎判定停用；碰撞物理约束保持。
- 高速撞击仍可按真实冲量伤害工具本身；工具的额外磨损若需要，也必须在 Post 按单独规则生成，不能重复投递普通碰撞损伤。
- 工具作业登记不需要通过普通撞击速度门控，因此低速推土、静止顶压可以工作。

### 9.2 载荷与进度的起步公式

复用同一轮 Post 枚举，将认领组的法向冲量汇总：

```text
F_measured = ΣJ / dt
F_smooth += (F_measured - F_smooth) × (1 - exp(-dt / tau_tool))
F_required = C_F × D_star / toolEfficiency
progress += dt / toolTime × max(0, F_smooth / F_required - 1)
```

dt 来自物理子步。`toolEfficiency`、`toolTime`、`tau_tool` 为正有限工具参数；无平滑需求可显式选择直接测量值。进度限制在 [0,1]，完成仅触发一次。这里的进度是抽象作业量，不能称为测得的真实塑性功。

工具额定最大作业载荷应限制可用 F，不能通过一个伪造的“整车推力”给每个目标都灌满额定值；同一接触点分给哪个任务，只能累计一次。发动机、液压或能量条件由子系统报告；通用碰撞管理器不猜测动力来源。

### 9.3 作业状态

跨步只保存 CrushWorkKey、目标预期状态、进度、载荷包络和最后接触时间。目标更换/被移除、工具禁用、作业面不符或超过明确的脱离宽限时间时终止任务。多个工具争同一块时，第一版按稳定工具身份选一个作业任务负责块进度；其他接触保留物理响应，不能复制同一份载荷或完成奖励。

该路径在 Post 完成时使用与撞碎相同的逻辑移除、主线程删除与去重动作。它会保留本步阻力：推力不足时停住，作业完成后恢复前进。第一版可以只实现松动/删除与掉落；土方搬运、堆积和回填是后续工具能力，不作为本期完整土体仿真的隐含要求。

## 10. 权威、兼容与物理行为保持

- 服务端生成破坏和伤害；客户端仅保留接触物理/表现所需逻辑，不能独立删块或投递伤害。
- 破坏总开关与实际世界的保护/取消结果必须覆盖即时、Post 撞碎和压溃三种入口。不能让工具通过钩子绕过总开关。
- 原版地形在物理快照中先逻辑失效，主线程后落地。若实际删除被保护规则拒绝或目标发生变化，必须恢复/重建对应地形快照，不能留下幽灵通道。该补偿动作进入验收，不以任务已排队等同于成功删除。
- Create 可提供目标本地坐标、状态和接触载荷；当前没有可直接复用的安全块移除适配。第一版对其计算部件伤害，块破坏能力标记为不支持；需要实现并验证装置更新适配后，才能开启即时删除/压溃。禁止用本地 BlockPos 删除世界中的同坐标方块。
- 未知地形 owner 保持碰撞，不强转 PhysicsChunkSection。第三方方块数据回退到现有硬度/爆炸抗性公式。
- 摩擦、轮胎滑移、履带材料、恢复系数、攀爬辅助与碰撞效果均有独立职责。搬走伤害代码时须保留这些求解前写入，不把整个碰撞处理器简单推迟到 Post。
- 对已经由引擎响应的地形/零件接触，Processed 和 Post 都不施加补偿冲量、不退回积分、不写恢复速度。生物代理桥接按 §8.3 单独验证。

| `util/mechanic/DamageUtil.java` | 以现有耐久为基线，完善空形状/非法值守卫；不借机重做全方块材料表 |

表中 `common/`、`util/` 路径均位于 `src/main/java/io/github/sweetzonzi/machine_max/`。类拆分允许按仓库风格调整，职责、生命周期和查询预算是硬约束。主线程只消费结果；数学使用 JME，不能混入客户端类或 JOML。

## 13. 标定、测试与验收

### 13.1 系数不得藏在实现分支内

集中定义并记录 `approachEpsilon`、`impactMinSpeed`、`C_J`、`C_D`、非法值 epsilon、工具 `C_F/toolTime/toolEfficiency/tau_tool`。普通撞击响应第一版为线性；需要非线性时先说明接触拆分、时间分辨率和聚合顺序。

`impactMinSpeed` 可以用 2 m/s 作为待测起点，不是已确认的最终值。`C_J/C_D` 必须依据参考车型、泥土/石头/树叶门槛与部件可接受损伤反解，不能仅因为继承了耐久数值就把 250 保留为冲量系数。

在 0、0.1、0.5、1、2、5、10、20 m/s 的法向速度阶梯上，覆盖轻零件、轻车、中型车和数十吨车体。轻落地样例至少记录 0.05/0.1/0.2 m 三档；50 t、0.1 m 自由落地的接近速度约 1.4 m/s，只是量级参照，不能把它的一份整车动能当成每块实际耗散。

即时分支与 Post 门槛要在同一响应表中展示。若存在“轮子撞树叶不够、车体轻落地却挖坑”的冲突，应报告冲突样例并调整明确的预测/标定参数，不能通过抬高轮胎抗弹 RHA 隐藏问题。

### 13.2 纯逻辑与伪查询测试

| 用例 | 必须断言 |
| --- | --- |
| 法向方向与分离 | A/B 交换结果等价；分离不打开普通撞击资格；含角速度的接近可通过 |
| 材料函数 | 两侧抗性均为零、负值、NaN、无穷守卫；较高防护的一侧受伤不增加 |
| 同 manifold 的两块 | 只给块 A 开门，不放行块 B；门槛和删除事件分别处理 |
| 同块多个 manifold | 各点贡献准确相加；不按 manifold 单独判碎 |
| 多零件/多车辆 | 方块只删一次；各部件只收到自己的贡献；不同坐标域不合并 |
| 门控与作用量 | 同组一次通过后收集本步其他有效点；下一子步资格清空；普通静载无持续掉血 |
| 接触失效 | Processed 已禁用、后续已移除、槽位搬移后的点不串身份；Post 不解引用缓存点 ID |
| 查询预算 | 候选为空枚举零轮；有多个零件仍至多一轮；countPoints 每相关 manifold 一次，点不重复采集 |
| 删块阶段 | PRE_BROKEN 无普通自伤；POST_BROKEN 保留本次自伤；不开破坏也允许部件伤害 |
| 协议路径 | IMPULSE 显式为零；碰撞不掷跳弹随机数、不依赖虚构穿深；材料只修正一次；弹丸用例不变 |
| 履带与事件 | 履带承接、子系统取消/修改伤害、装配体记账与普通部件选路完整 |
| 压溃 | 无速度资格仍可作业；载荷不足不涨；相同力在不同 dt 下完成时间近似；脱离/禁用/替换清理 |

物理步与查询接口应通过测试用适配器注入，从而测试枚举次数、点搬移与双端去重，不用为这些逻辑启动 Minecraft。

### 13.3 裸 Bullet / 游戏内验收

- 真 PhysicsSpace 中对照自由零件、刚性连接、悬挂连接与悬挂触底：实际冲量反映传力，不能用自算加权质量冒充。
- 车辆以低速/正常行驶速度穿树叶：首个触碰子步禁用接触，不出现刚性墙式减速；连续多块不重复掉落或自伤。
- 参考重车的低落差在泥土、石头上符合预先确定的安全目标；必须记录是否由即时分支破坏以及接触块数。
- 撞同一硬障碍时，更重的同构载具通常有更大破坏贡献；偏心碰撞与转动响应有合理区别。
- 只靠多个接触累计才碎的障碍，本次确实减速；禁止在 Post 把速度补回。
- 工具低速顶土：受力不足时停住不涨进度，受力足够时完成作业；普通车体同样顶住不启动作业。
- 模组未知方块、不可破坏块、关闭破坏、保护规则拒绝、Create 装置、维度卸载都不产生幽灵通道或跨域删块。
- 增加载具和 SubPart 数后，计数证明 Level 每子步至多一轮枚举；记录相关 manifold/点数、JNI 查询计数和采集耗时。未测量前不声称具体毫秒收益。

普通撞击使用每步冲量而不是 `J/dt`，压溃使用载荷与 dt；比较 50/100/200 Hz 时须分别检查单次撞击总伤害和工具完成时间。固定减伤、接触离散与多子步持续撞击造成的差异需记录，不用“公式量纲正确”替代实测。

实现阶段运行仓库包装器：`.\gradlew --offline test`，需要真实世界/客户端时按仓库环境执行相应离线 run。本文档编辑本身不要求启动游戏。测试类放在业务测试包，不放 Mixin 独占包。
