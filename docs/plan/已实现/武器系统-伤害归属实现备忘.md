# 武器系统-伤害归属实现备忘

> **状态**：已实现。本文自包含——只读本文即可理解归属链、字段职责、殉爆继承规则与未做项，不要求先读其他文档。

**范围**：投射物动能伤害、命中起爆、弹药殉爆这三类伤害的归属（causing entity）。不做同载具过滤，不做载具侧的击杀记功，不改客户端表现。

---

## 一、归属链

一个"谁打的"从座位一路传到伤害源，链条上每一环只做一件事：

```text
SeatSubsystem.passenger                    ← 唯一的人员来源（客户端恒为 null）
  ↓ 读开火信号时按发送者解析
WeaponControllerSubsystem.operator         ← volatile，主线程写、物理线程读
  ↓ FireCommand.shooter（与开火权同一份记录）
LauncherSubsystem.fireSingle → BallisticProjectileType.fire
  ↓
BallisticProjectile.owner                  ← final 引用，服务端发射时写入
  ├─ MMProjectileEntity.setOwner(owner)    ← 代理实体拿原版 Projectile 的 owner
  └─ BFDamageContext.source
       = DamageSource(type, direct = 代理实体, causing = owner)
       ├─ 实体受伤：击杀记功、仇恨、死亡消息
       ├─ SubPartDamageEvent.ctx：零件与子系统读到同一份归属
       └─ 关键模块被打爆 → 殉爆继承（§三）

命中起爆：
ProjectileManager#enqueueWarheadDetonation(projectile, hitPoint)
  → PendingDetonation(hitPoint, warheads, owner, projectile)
  → EffectContext(directEntity = 代理实体, ownerEntity = owner, sourceObject = 弹丸)
  → ExplosionWorldEffect#apply → ExplosionManager#detonate(..., attacker = ownerEntity)
```

归属只有一个来源（`SeatSubsystem.passenger`）与一个出口（`DamageSource` 的 causing entity）；中间的每一跳都是搬运，没有第二套判定。

## 二、字段与职责

| 位置 | 字段 | 写点 | 读点 | 线程 |
| --- | --- | --- | --- | --- |
| `WeaponControllerSubsystem` | `operator` | `readInputSignals()`、`updateRegularInputs()`（松开即清空） | `fireSalvo()` / `fireRipple()` | 主线程写、物理线程读，`volatile` |
| `LauncherSubsystem.FireCommand` | `shooter` | 武器控制器构造指令时 | `fireSingle()` | 物理线程 |
| `BallisticProjectile` | `owner` | 构造器（`BallisticProjectileType#create`） | `buildHurtContext()`、`settleAccumulatedDamage()` | `final` |
| `BallisticProjectile` | `proxyEntity` | `ProjectileManager#createProjectileEntity` | `getProxyEntity()` | `volatile`，读取时判 `isRemoved()` |
| `ProjectileManager.PendingDetonation` | `owner`、`source` | 物理线程命中路径 | 主线程 `flushNormalDetonations()` | 队列即边界 |
| `ProjectileManager.PendingCookoff` | `attacker` | `BallisticProjectile#settleAccumulatedDamage`（主线程） | 主线程 `flushCookoffDetonations()` | 同上 |
| `ExplosionManager#detonate` | `attacker` 形参 | 三个起爆调用方 | 构造 `DamageSource` | 主线程 |

三条口径：

1. **归属随开火权下发。** `FireCommand` 是"允许这一发存在"的那份记录，射手挂在它上面，不另建一条并行的归属通道。指令被释放（`EmptySignal`）时没有主人，本发无归属。
2. **`operator` 与载具控制器同一条读法。** 发送者是 `SeatSubsystem` 时取 `passenger`，因此"谁在开车"与"谁在开火"不会分家。脚本子系统、命令、AI 直发没有可指认的操控实体，一律无归属。
3. **客户端不参与。** `SeatSubsystem.passenger` 只有服务端有值；经 spawn 包重建的弹丸 `owner` 恒为 `null`。归属不进任何网络包。

## 三、殉爆继承

**规则：殉爆的归属是导致殉爆那一击的归属，不是"炸自己所以无主"。** 敌人瞄准弹药架或炮闩的弱点打穿并摧毁它时，那一次伤害事件的 causing entity 成为随后殉爆爆炸的 causing entity——打弱点与打装甲因此在战果上可区分。

判据只有一个方法，`AbstractSubsystem#getCookoffDamageEvent()`，起爆定位、穿透豁免与归属三者同源，不会各走一路：

| 子系统 | 事件来源 | 含义 |
| --- | --- | --- |
| `LauncherSubsystem` | 炮闩模块（`breech`）的 `lastHitEvent` | 打坏炮闩的那一击 |
| `RegenLoaderSubsystem` | 弹仓模块（`magazine`）的 `lastHitEvent` | 打坏弹仓的那一击 |
| `AmmoLoaderSubsystem` | 子系统级 `lastDamageEvent` | 打坏装弹机的那一击 |

归属取 `event.getCtx().source().getEntity()`（`AbstractSubsystem#getLastDamageAttacker()`）。子系统早已记录每次有效受击的完整 `BFDamageContext`，起因实体因此不需要另外存一份。

飞行中被击毁的弹药走另一条：`BallisticProjectile#settleAccumulatedDamage()` 把**打爆这发弹的那一击**的 causing entity 交给 `enqueueWarheadCookoff`，所以殉爆属于攻击者，不属于被打掉那发弹的发射者。

归属沿伤害链自然传递：殉爆爆炸本身带着归属，它再打爆另一辆车的弹药架时，那一环读到的就是同一个起因实体。

无归属的三种情形：读档后没有有效受击记录、指令或调试物品直接起爆、发射时没有座位（无人载具、`/mm debug autofire`）。

## 四、死亡消息

`damage_type` 的 JSON 保持 `"death_message_type": "default"`，文案由 `mixin/DamageSourceMixin` 在 `DamageSource#getLocalizedDeathMessage` 头部接管：本次伤害属于本项目三类（`machine_max:projectile` / `blast` / `cookoff`）且**带有 causing entity** 时，返回 `death.attack.machine_max.<id>.player`（受害者、起因实体）；其余情形一律交回原版。

三条取舍：

1. **不新增伤害类型。** 原版把爆炸分成 `minecraft:explosion` 与 `minecraft:player_explosion`，判据是 direct 与 causing 是否都非空——它要两套措辞：没人可写时「炸死」、有人可写时「被 X 炸死」。箭只有 `minecraft:arrow` 一个类型，因为它的 direct entity 恒非空，一个 2 参键就够。我们的口径是「总能写出施加者」，一个类型同样够；分型会让材料 `damage_modifiers` 的 `damage_type` 条件与 `HitBox` 的殉爆冲击倍率同时失配，代价大于收益。
2. **不为文案造实体。** 项目里没有「只为死亡消息而存在」的实体；爆炸保持无载体，无归属时维持基础文案。
3. **不接管原版的两条兜底。** 无归属时继续走原版的「无实体」分支（有击杀记功用 `.player`，否则用基础键），因此基础键仍按 1 参使用，不会漏出字面的 `%2$s`；`.item`（凶手手持改名物品）那一支也不再可达，无需补键。

命中的唯一位置就够：`CombatTracker#getDeathMessage()` 对 `DeathMessageType.DEFAULT` 直接返回本方法的结果，玩家死亡屏、聊天广播与生物死亡因此走同一分支。语言键取自 `MMLanguageRegistry`，不在注入里拼字符串。
