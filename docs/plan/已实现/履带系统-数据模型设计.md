## 1. 范围与原则

### 1.1 本文解决

- `TrackAttr` 的字段集合、单位、默认值与校验。
- `FittingVisual` 的字段：模型、模型贴图与可选的物品图标。
- `link_bones`：型号模型按最小重复单元组织时，逐节骨骼名与参考点。
- 履带如何复用 `MaterialAttr` 的装甲与物理属性。
- 履带接触的摩擦口径：前向/侧向摩擦，不使用轮胎滑移曲线。
- 履带如何接管方块伤害、湿滑适应与装甲结算。
- 履带音效的数据边界：命中音可配，滚动/滑移音保持硬编码。
- 型号模型在近处/远处的渲染分工与回退。

### 1.2 本文不解决

- `fittings/` 目录、模块 id、注册表与 `type` 分派；这些由模块文档定义。
- 履带物理算法（GearJoint、张力、包络求解）；这些由物理实现文档定义。
- 物品经济的消耗规则：用料按节数记录，物品是否消耗、按什么粒度消耗不在本文范围。
- 装甲板、装饰物、`Fitting` 运行时对象、两点放置。
- LOD 与合批；远处渲染直接使用程序化履带。

### 1.3 设计原则

1. **材料是装甲与接触物理的唯一来源。** 履带存活期间，成员轮面的摩擦、滚动/自旋摩擦、弹性、湿滑适应、方块伤害因子读履带材料；履带未断带时，装甲 RHA、线性减伤、伤害乘数也读履带材料。装甲与方块伤害的耐久衰减比例同时取自履带耐久。成员轮上不属于轮面的 HitBox 仍读自身材料。
2. **厚度只有一个，单位写在字段名里。** `thickness_mm` 同时是几何厚度与装甲厚度；几何侧由 `thicknessMeters()` 换算为米。毫米与米不会出现在同一个无单位字段上。
3. **不给履带套轮胎模型。** 履带只保留前向/侧向各向异性摩擦；`slip_curve` 是轮胎摩擦椭圆的近似，履带不读取。
4. **音效保持硬编码。** 命中音提供两个可配字段；滚动音与滑移音由 `CollisionEffectManager` 固定选择，不进入履带数据。
5. **视觉是模型加贴图。** 履带型号必须指定模型与贴图；程序化扁长方体只作为模型缺失或远处渲染的回退。
6. **近处模型，远处程序化。** 不做距离 LOD；由渲染入口选择模式。
7. **型号不持有静态默认实例。** 默认型号由内容包 fixture `machine_max:default` 提供，`TrackAttr` 没有静态 `DEFAULT` 常量，避免在材料注册表就绪前解析材质。

## 2. 数据模型总览

```text
FittingType
├── visual: FittingVisual          // 基类公共字段，见 §4.1
└── TrackType
    ├── linkBones: List<String>    // 逐节骨骼名，见 §4.2；空列表表示整模型一节
    └── attr: TrackAttr
        ├── durabilityPerLink
        ├── lengthPerLink
        ├── thicknessMm
        ├── material               // 材料 id，装甲 + 接触物理
        ├── overwrite              // 可选，复用 HitBoxAttr.OverwriteAttr
        ├── sounds                 // 仅 hit_un_pen / hit_pen
        └── tension
```

- `FittingType` 与 `TrackType` 的类关系由模块文档定义；本文只定义字段与材料口径。
- `TrackAttr` 在构造时解析材料并缓存 `MaterialAttr`，避免每次接触都查表与合并。
- `TrackAttr` 是 class，不是 record；缓存 `resolved` 需要实例字段。

## 3. `TrackAttr`

### 3.1 字段

| 字段 | 类型 | 单位 | 默认 | 校验 | 用途 |
| -- | -- | -- | -- | -- | -- |
| `durabilityPerLink` | float | 点 | 20 | 有限且 > 0 | 每节耐久；整条带最大耐久 = `durabilityPerLink × N` |
| `lengthPerLink` | float | 米 | 0.2 | 有限且 > 0 | 节长；用于节数 `N` 与相位 |
| `thicknessMm` | float | 毫米 | 50 | 有限且 > 0；装配时另校验小于最小成员轮半径 | 节厚；同时用于装甲 RHA 与几何/渲染 |
| `material` | ResourceLocation | — | 无（必填） | 存在于 `MMDynamicRes.MATERIALS` | 装甲与接触物理来源 |
| `overwrite` | Optional&lt;HitBoxAttr.OverwriteAttr&gt; | — | 空 | 可选 | 按 physics / armor 覆写材料 |
| `sounds` | MaterialAttr.MaterialSoundAttr | — | `hard_metal` 固定范围事件 | 可选 | 仅 `hit_un_pen` / `hit_pen` |
| `tension` | Tension | — | 全部字段可省，见 3.3 | 见 3.3 | 相邻轮弹簧-阻尼参数 |

`thicknessMm` 与几何的换算：

```text
thicknessMeters() = thicknessMm × 0.001
```

- `TrackEnvelope2D`、`TrackRenderer`、轮面半径约定都使用 `thicknessMeters()`。
- `SubPart` 的履带装甲路径直接使用 `thicknessMm` 的毫米值。
- `maxDurability(N) = durabilityPerLink × max(1, N)`，由 `TrackLink.refreshEnvelope` 在节数推导后调用。
- 节数 `N` 属于具体一环履带，不是型号属性：型号只声明节长，`N` 由该环的包络周长推出。载具数据（模板 / 蓝图的 `track_links[]`）里带 `link_count` 时直接采用该值，因此同一型号套在不同轮系上各自有自己的节数。
- 装配与载入时校验 `thicknessMeters() < min(成员轮 getMaxWheelRadius())`；不满足时 `VehicleCore.createTrack` / `TrackLink.assemble` 拒绝闭合并给出成员名与两侧数值。包络求解器只接受已通过该校验的厚度，避免运行期以 `IllegalArgumentException` 静默丢失包络。

### 3.2 `TrackAttr` 形状

```java
public final class TrackAttr {
    private final float durabilityPerLink;
    private final float lengthPerLink;
    private final float thicknessMm;
    private final ResourceLocation materialId;
    private final Optional<HitBoxAttr.OverwriteAttr> overwrite;
    private final MaterialAttr.MaterialSoundAttr sounds;
    private final Tension tension;
    private final MaterialAttr resolved;      // 构造时由 materialId + overwrite 解析

    public float durabilityPerLink() { return durabilityPerLink; }
    public float lengthPerLink() { return lengthPerLink; }
    public float thicknessMm() { return thicknessMm; }
    public float thicknessMeters() { return thicknessMm * 0.001f; }
    public ResourceLocation materialId() { return materialId; }
    public MaterialAttr material() { return resolved; }
    public MaterialAttr.ArmorAttr armor() { return resolved.armor(); }
    public MaterialAttr.PhysicsAttr physics() { return resolved.physics(); }
    public MaterialAttr.MaterialSoundAttr sounds() { return sounds; }
    public Tension tension() { return tension; }

    public float maxDurability(int linkCount) { return durabilityPerLink * Math.max(1, linkCount); }

    public static final MaterialAttr.MaterialSoundAttr TRACK_DEFAULT_SOUNDS = ...;
    public static final MapCodec<TrackAttr> MAP_CODEC = ...;
}
```

字段平铺在型号 JSON 顶层，`MAP_CODEC` 不写 `"type"`，也不把字段包进 `"attr"`：

```java
public static final MapCodec<TrackAttr> MAP_CODEC = RecordCodecBuilder.mapCodec(instance -> instance.group(
        Codec.FLOAT.optionalFieldOf("durability_per_link", 20f).forGetter(TrackAttr::durabilityPerLink),
        Codec.FLOAT.optionalFieldOf("length_per_link", 0.2f).forGetter(TrackAttr::lengthPerLink),
        Codec.FLOAT.optionalFieldOf("thickness_mm", 50f).forGetter(TrackAttr::thicknessMm),
        ResourceLocation.CODEC.fieldOf("material").forGetter(TrackAttr::materialId),
        HitBoxAttr.OverwriteAttr.CODEC.optionalFieldOf("overwrite").forGetter(TrackAttr::overwrite),
        MaterialAttr.MaterialSoundAttr.CODEC.optionalFieldOf("sounds", TRACK_DEFAULT_SOUNDS)
                .forGetter(TrackAttr::sounds),
        Tension.CODEC.optionalFieldOf("tension", Tension.DEFAULT).forGetter(TrackAttr::tension)
).apply(instance, TrackAttr::new));
```

- `material` 无默认值。缺字段或 id 不在材料表中时，Codec 构造失败，`FittingModule` 记为内容包错误，该型号不进入注册表。
- `resolved = HitBoxAttr.resolve(materialId, overwrite.orElse(null))`；`resolve` 在 id 缺失时返回 `null`，由 `TrackAttr` 构造器抛出带 id 的 `IllegalArgumentException`。
- `HitBoxAttr` 需要提供公共静态 `resolve(ResourceLocation, OverwriteAttr)`，把现有 `getEffectiveMaterial` 的合并逻辑抽出来；`HitBoxAttr` 与 `TrackAttr` 共用。`HitBoxAttr` 自身在该方法返回 `null` 时回退 `MaterialAttr.DEFAULT` 并打 warn，保持碰撞箱的容错行为。
- `FittingModule` 注册在 `MaterialModule` 之后，型号解析时 `MMDynamicRes.MATERIALS` 已就绪。
- `TRACK_DEFAULT_SOUNDS` 是两个 `part.collision.terrain.hard_metal` 固定范围事件（64 格）。
- 接地摩擦由 `MaterialAttr.PhysicsAttr` 提供，命中音由 `MaterialAttr.MaterialSoundAttr` 提供；`TrackAttr` 不嵌套 `Friction` / `Sounds` 记录。
- `MAP_CODEC` 的 `Tension` 字段是嵌套对象，其余字段与 `"visual"` 同级。

### 3.3 `Tension`

沿用物理文档 §4.4 的字段集合：

| 字段 | 单位 | 默认 |
| -- | -- | -- |
| `enabled` | bool | true |
| `stiffness` | N/m | 12000 |
| `damping` | N·s/m | 900 |
| `preload` | 米 | 0 |
| `slack` | 米 | 0.015 |
| `max_force` | N | 800 |

`rest` 不声明，装配 / 载入时按相邻轮心距采样。`Tension.DEFAULT` 取上表六个默认值。`stiffness`、`damping`、`max_force` 要求有限且 ≥ 0；`preload`、`slack` 要求有限且 ≥ 0。

```java
public record Tension(boolean enabled, float stiffness, float damping,
                      float preload, float slack, float maxForce) {
    public static final Tension DEFAULT = new Tension(true, 12000f, 900f, 0f, 0.015f, 800f);

    public static final MapCodec<Tension> MAP_CODEC = RecordCodecBuilder.mapCodec(instance -> instance.group(
            Codec.BOOL.optionalFieldOf("enabled", true).forGetter(Tension::enabled),
            Codec.FLOAT.optionalFieldOf("stiffness", 12000f).forGetter(Tension::stiffness),
            Codec.FLOAT.optionalFieldOf("damping", 900f).forGetter(Tension::damping),
            Codec.FLOAT.optionalFieldOf("preload", 0f).forGetter(Tension::preload),
            Codec.FLOAT.optionalFieldOf("slack", 0.015f).forGetter(Tension::slack),
            Codec.FLOAT.optionalFieldOf("max_force", 800f).forGetter(Tension::maxForce)
    ).apply(instance, Tension::new));

    public static final Codec<Tension> CODEC = MAP_CODEC.codec();
}
```

`Tension` 是嵌套对象；`MAP_CODEC` 用于需要扁平组合的调用点，`CODEC` 用于 `optionalFieldOf`。`TrackAttr.MAP_CODEC` 用 `Tension.CODEC.optionalFieldOf(...)` 读取它。

## 4. 型号级字段

`TrackType` 在基类字段 `visual` 之外还声明逐节骨骼名 `link_bones`；两者平铺在型号 JSON 顶层（`visual` 是对象，`link_bones` 是字符串数组）。

### 4.1 `FittingVisual`

```java
public record FittingVisual(ResourceLocation model, ResourceLocation texture, ResourceLocation icon) {
    public static final ResourceLocation NO_ICON =
            ResourceLocation.fromNamespaceAndPath(MachineMax.MOD_ID, "empty");

    public static final Codec<FittingVisual> CODEC = RecordCodecBuilder.create(instance -> instance.group(
            ResourceLocation.CODEC.fieldOf("model").forGetter(FittingVisual::model),
            ResourceLocation.CODEC.fieldOf("texture").forGetter(FittingVisual::texture),
            ResourceLocation.CODEC.optionalFieldOf("icon", NO_ICON).forGetter(FittingVisual::icon)
    ).apply(instance, FittingVisual::new));

    public boolean hasIcon() {
        return !NO_ICON.equals(icon);
    }
}
```

- `model`：履带节的模型，按 `ModelIndex("fitting", model)` 加载，与零件模型同一套 `OModel`；`model` 是内容包 `models/fitting/` 下的模型 id，保留 `.geo` 后缀（文件 `track_link.geo.json` 对应 id `machine_max:track_link.geo`）。`link_bones` 为空时它是单节模型，非空时它是最小重复单元（§4.2）。
- `texture`：该模型的贴图全路径。
- `icon`：物品栏 2D 图标贴图，可选；省略时取哨兵 `NO_ICON`（`machine_max:empty`），`hasIcon()` 为 `false`。图标只影响物品与创造栏的绘制，不影响世界里履带节的渲染。
- `model` 与 `texture` 必填；`TrackType` 不接受只有贴图、没有模型的型号。
- 渲染宽度与颜色不进入型号数据：程序化回退使用 `TrackRenderer` 的 `LINK_WIDTH` / `LINK_COLOR` / 纯白贴图。
- `FittingVisual` 只由本节定义；模块文档引用本节，不重复声明字段。
- 未来 `prop` 也使用“模型 + 贴图 + 可选图标”；需要纯程序化几何的类型另设 `kind`，不要放宽 `FittingVisual`。

### 4.2 `link_bones`

```java
Codec.STRING.listOf().optionalFieldOf("link_bones", List.of()).forGetter(TrackType::linkBones)

public List<String> linkBones()      // 按节序排列；空列表表示整模型一节
public int linkPeriod()              // K = max(1, linkBones.size())
```

- **模型是这条带的最小重复单元。** 一个模型里按节序摆 K 节、每节一个骨骼，`link_bones` 的第 k 个名字就是第 k 个槽位的骨骼；环上第 i 节取槽位 `i % K`。每节的 Z 跨度必须等于 `lengthPerLink`（逐节摆放不拉伸几何）。
- **空列表表示整模型一节（K = 1）。** 此时整个模型的全部骨骼一起画，参考点是模型原点；五个第一方型号都用这种写法。
- **参考点是骨骼 pivot。** `link_bones` 非空时，渲染器把该骨骼 pivot 在模型里的位置（经父链静态变换，取 `BonePose#getSpaceBonePivot`）当作这一节的参考点，绘制时先平移到采样点。因此 pivot 必须与该节**外表面中点**重合；空列表不读 pivot，所以“空列表”与“把唯一骨骼写进列表”两种写法不等价——后者会按 pivot 整体平移。
- **校验分三层。** 空名字与重名在解码期由 `TrackType` 构造拒绝（`IllegalArgumentException`，该型号不注册）；名字是否在模型骨骼表、每个槽位是否有 cube 或 `poly_mesh`、K 是否超过 8，由 `FittingAssetTest` 在内容进游戏前核对；运行期漏网的失败（模型里找不到该名字、槽位没有几何）记一条告警并按型号回退程序化履带。
- **与节数无关。** `link_bones` 描述模型怎么分节，`link_count`（`TrackLinkData` 的持久化字段）描述这一环装多少节；两者唯一的约束是 `link_count % K == 0`（闭环首尾相接），由推导端取整、加载端只检查，见物理实现文档 §8.4 / §8.6。

## 5. 材料语义

### 5.1 装甲

```text
rhaCoeff(ratio) = decay_rha + (rha − decay_rha) × ratio^decay_power
RHA = thickness(mm) × rhaCoeff(ratio)
dmgResist(ratio) = decay_dmg_resist + (dmg_resist − decay_dmg_resist) × ratio^decay_power
dmgMult(ratio) = decay_dmg_mult + (dmg_mult − decay_dmg_mult) × ratio^decay_power
ratio = 当前耐久 / 最大耐久
```

- `rha`、`decay_rha` 是**系数**，与 `HitBoxAttr.thickness × rhaCoeff` 语义一致； `RHA` 的毫米数由 `thicknessMm` 提供。
- 履带的三个衰减量都使用履带自身耐久比例；成员轮走 `HitBox.getRHA` 时使用 SubPart 耐久比例。
- 默认标定：

| 参数 | 值 |
| -- | -- |
| `material` | `machine_max:track_steel` |
| `thickness_mm` | 50 mm |
| `rha` | 0.6（冲压/穿孔履带板的结构系数） |
| `decay_rha` | 0.3 |
| `decay_power` | 1.5 |
| `unpen_power` | 0.6 |
| `dmg_resist` | 1.0 |
| `dmg_mult` | 0.95 |
| `decay_dmg_resist` | 0.0 |
| `decay_dmg_mult` | 1.0 |

| 耐久 | RHA | 线性减伤 | 伤害乘数 |
| -- | -- | -- | -- |
| 100% | 30.0 mm | 1.0 | 0.95 |
| 50% | 20.3 mm | ≈ 0.354 | ≈ 0.982 |
| 0% | 15.0 mm | 0.0 | 1.0 |

以上是首版标定，实机后按手感调整；`decay_rha` / `decay_power` 不属于兼容性字段。

### 5.2 物理

履带接触读取 `material.physics()` 的以下字段：

| 字段 | 用途 |
| -- | -- |
| `friction` | 摩擦向量 `[横向, 纵向, 纵向]`；`x` = 侧向，`y` = `z` = 纵向（后两值必须相同） |
| `rolling_friction` | 滚动摩擦 |
| `spinning_friction` | 自旋摩擦 |
| `restitution` | 弹性 |
| `slip_adaptation` | 湿滑适应；参与 `wetFactor` |
| `block_damage_factor` | 方块破坏能量系数 |

`slip_curve` 不参与履带：它是轮胎椭圆摩擦模型的近似。`material` 仍保留 `slip_curve` 字段供轮胎/碰撞箱使用；履带路径忽略它。

### 5.3 覆写

- `overwrite` 复用 `HitBoxAttr.OverwriteAttr`。
- 对履带生效的组：`physics`、`armor`。
- 对履带不生效的组：`sounds`；履带命中音由 `TrackAttr.sounds` 定义。
- `overwrite` 的合并由 `HitBoxAttr.resolve` 完成，履带与碰撞箱使用同一套规则。
- schema 必须列出 `overwrite`，并注明 `overwrite.sounds` 对履带不生效。

### 5.4 缺席材料

| 场景 | 处理 |
| -- | -- |
| 材料 id 在 `MMDynamicRes.MATERIALS` 中不存在 | `FittingModule` 记内容包错误，该型号不注册；`HitBoxAttr.resolve` 同时返回 `null`，`TrackAttr` 构造失败 |
| 客户端缺少材料 | 与上一条同一路径：该型号不注册，引用它的履带按模块文档 §8 的缺型号规则处理 |
| 服务端缺少材料 | 该型号不注册；载入的履带按缺型号规则丢弃，物理不进入默认材料 |

材料是型号的硬依赖：不存在“缺材料仍以默认材质运行”的回退。默认材质 `MaterialAttr.DEFAULT` 只服务碰撞箱的容错路径。

### 5.5 履带材料文件

`machine_max:track_steel` 定义在 builtin 内容包：

```text
src/main/resources/spark_modules/Machine-Max_Builtin/machine_max/materials/track_steel.json
```

内容见 §9.2。该文件属于首个数据驱动版本的交付物；`fittings/default.json` 依赖它，两者在同一个内容包内发布。

## 6. 接触与伤害口径

### 6.1 统一入口

`SubPart` 提供四个入口，`CollisionHandler` 与 BF 管线只通过它们读取履带材质：

```java
boolean isTrackContact(int hitBoxIndex) {
    TrackLink track = this.trackLink;
    return track != null && !track.isDisposed()
            && isWheel(hitBoxIndex) && isWheelSurface(hitBoxIndex);
}

MaterialAttr contactMaterial(int hitBoxIndex, HitBox hitBox) {
    if (isTrackContact(hitBoxIndex)) return trackLink.attr().material();
    return hitBox.attr.getEffectiveMaterial();
}

MaterialAttr armorMaterial(HitBox hitBox) {
    TrackLink track = this.trackLink;
    if (hasLiveTrack(track)) return track.attr().material();
    return hitBox.attr.getEffectiveMaterial();
}

float getRHA(@Nullable HitBox hitBox) {
    TrackLink track = this.trackLink;
    if (hasLiveTrack(track)) {
        return ArmorUtil.rha(track.attr().armor(), track.attr().thicknessMm(),
                track.durabilityRatio());
    }
    return hitBox == null ? 0f : hitBox.getRHA(this);
}
```

- `isTrackContact` 是履带接触的唯一判据，`setupFriction` 与 `setupContactFriction` 共用；轮面判定同时包含 `isWheel` 与 `isWheelSurface`。
- `contactMaterial` 只对轮面接触返回履带材料；成员轮上的车体、悬挂等非轮面 HitBox 使用自身材料。
- `armorMaterial` 对成员 SubPart 的所有命中返回履带材料；履带包住轮组，命中轮毂也先由履带装甲层吸收。
- `hasLiveTrack(track)` 的定义是 `track != null && !track.isDisposed() && !track.isBroken()`。

### 6.2 装甲与接触路径的接线

| 读取点 | 口径 |
| -- | -- |
| `SubPart.getRHA(BFDamageContext)` | `getRHA(findHitBox(ctx))`；角度效应读 `armorMaterial(hitBox).armor().angleEffect()` |
| `SubPart.calculateFinalDamage` | 击穿与未击穿分支都按 `modifyArmorDamage` 的口径：`damageModifiers` → `ArmorUtil.resist` → `ArmorUtil.mult`，比例取履带耐久 |
| `CollisionHandler.applyBlockDamage` 的护甲项 | `subPart.getRHA(hitBox)` |
| `CollisionHandler.applyBlockDamage` 的伤害修正 | `subPart.modifyArmorDamage(hitBox, source, partDamage)` |
| `CollisionHandler.setupFriction` | `isTrackContact(hitBoxIndex)` 时用 `track.attr().physics()` 的 `friction` / `rolling_friction` / `spinning_friction` / `restitution`；其他接触读 HitBox 材质 |
| `CollisionHandler.setupContactFriction` 的湿滑 | `subPart.contactMaterial(hitBoxIndex, hitBox).physics().slipAdaptation()` |
| 方块伤害因子三处（预判、摧毁阈值、掉落率） | `subPart.contactMaterial(hitBoxIndex, hitBox).physics().blockDamageFactor()` |

`SubPart.modifyArmorDamage(HitBox hitBox, DamageSource source, float amount)` 与 `HitBox.modifyDamage` 同构，材料与耐久比例取自 `armorMaterial` 与履带/轮子各自的耐久：

```java
float modifyArmorDamage(HitBox hitBox, DamageSource source, float amount) {
    MaterialAttr.ArmorAttr armor = armorMaterial(hitBox).armor();
    float ratio = hasLiveTrack(trackLink)
            ? trackLink.durabilityRatio()
            : getDurability() / getMaxDurability();
    float dmg = armor.damageModifiers().apply(source, amount);
    dmg = Math.max(0f, dmg - ArmorUtil.resist(armor, ratio));
    return dmg * ArmorUtil.mult(armor, ratio);
}
```

`ArmorUtil` 提供四个静态函数，`HitBox` 与 `SubPart` 共用同一套公式：

```java
static float rhaCoeff(MaterialAttr.ArmorAttr armor, float ratio);
static float rha(MaterialAttr.ArmorAttr armor, float thicknessMm, float ratio);
static float resist(MaterialAttr.ArmorAttr armor, float ratio);
static float mult(MaterialAttr.ArmorAttr armor, float ratio);
```

`HitBox.getRHA`、`getEffectiveDmgResist`、`getEffectiveDmgMult` 委托这四个函数；成员轮的装甲数值与当前公式逐位一致。

### 6.3 不走轮胎滑移曲线

`CollisionHandler.setupContactFriction` 对履带接触走简单合成摩擦，不调用 `applyWheelFriction`：

```java
boolean isTrackContact = subPart.isTrackContact(hitBoxIndex);

if (isTrackContact) {
    // 前向/侧向摩擦由 body 的 anisotropicFriction 提供；
    // 这里只写合成摩擦标量，不设 LATERAL_FRICTION 方向。
    ManifoldPoints.setCombinedFriction(manifoldPointId,
            Math.max(0.001f, subPart.body.getFriction() * blockFriction * wetFactor));
    ManifoldPoints.setFlags(manifoldPointId,
            ManifoldPoints.getFlags(manifoldPointId) & ~ContactPointFlag.LATERAL_FRICTION);
} else if (subPart.isWheel(hitBoxIndex) && subPart.isWheelSurface(hitBoxIndex)) {
    applyWheelFriction(hitBox, slipAngle, slipRatio, slipVel,
            manifoldPointId, blockFriction, wetFactor); // 轮胎
} else {
    // 非轮 / 非轮面
}
```

- `applyFriction` 在履带成员轮面设置 `body.setAnisotropicFriction(physics.friction(), AfMode.basic)`；前向/侧向摩擦由该向量承担。
- `wetFactor` 的 `slipAdaptation` 与 `block_damage_factor` 三处读取都走 `contactMaterial`。
- `applyBlockDamage` 的护甲项与伤害修正走 §6.2 的口径。

### 6.4 断带

| 属性 | 断带后 |
| -- | -- |
| 装甲 RHA / 线性减伤 / 伤害乘数 | 回退到成员轮 `HitBox` 材质与 SubPart 耐久比例 |
| 命中音 | 回退到成员轮 `HitBox` 材质音效 |
| 前向/侧向摩擦、滚动/自旋、弹性、湿滑适应、方块伤害因子 | 仍读履带材料（`!isDisposed()`） |
| 滚动音 | 仍为履带硬编码滚动音 |

断带只解除装甲层与传动耦合，不改变履带仍挂在轮组上的接触属性。

## 7. 音效

### 7.1 数据字段

`TrackAttr.sounds` 是 `MaterialAttr.MaterialSoundAttr`，只包含：

| 字段 | 默认 |
| -- | -- |
| `hit_un_pen` | `part.collision.terrain.hard_metal` |
| `hit_pen` | `part.collision.terrain.hard_metal` |

- `MaterialSoundAttr.CODEC` 使用 `SoundEvent.DIRECT_CODEC`，每个字段只接受 `{ "sound_id": ..., "range": ... }` 对象；裸字符串不是合法输入。
- 省略 `sounds` 字段时取 `TrackAttr.TRACK_DEFAULT_SOUNDS`（两个 `hard_metal` 事件）。
- 写 `"sounds": {}` 时，`MaterialSoundAttr.CODEC` 的两个 `optionalFieldOf` 落到 `MaterialSoundAttr.DEFAULT`（`hit_box.hit.*`），不是 `hard_metal`。型号 JSON 示例显式写出两个事件，避免这个歧义。
- `MaterialSoundAttr.DEFAULT` 服务碰撞箱；履带使用自己的缺省值。

### 7.2 播放路径

| 音效 | 来源 | 代码 |
| -- | -- | -- |
| 命中（未击穿 / 击穿） | `TrackAttr.sounds` | `SubPart.hurt` 在履带存活时读 `track.attr().sounds().onHitPen()` / `onHitUnPen()`；断带后读 `HitBox` 材质 |
| 持续滚动 | 硬编码 | `CollisionEffectManager.getFrictionSound` 对履带成员固定返回 `TIRE_METAL` |
| 额外滑移 | 硬编码 | `updateSlipSound` 固定 `TIRE_EXTRA_SLIP` |

- `material.sounds` 与 `overwrite.sounds` 对履带不生效，文档与 schema 注明。
- 滚动音不提供数据字段；内容包不能为某个履带型号单独指定滚动音。
- 滑移音不按地面材质细分，也不提供数据字段。

## 8. 视觉与渲染

### 8.1 模型

- `visual.model` 是**逐节**模型，不是整条带：`link_bones` 为空时它是一节，非空时它是最小重复单元（里面按节序摆 K 节）；渲染器在每个节的帧下画该节对应的槽位。
- 模型与零件模型使用同一套载具坐标系，美术可以直接在车体工程里建这一节：

| 轴 | 含义 |
| -- | -- |
| +X | 轮轴 / 宽度方向 |
| +Y | 由节外表面指向轮组（内法线，履带齿朝 +Y） |
| +Z | 切线 / 前进方向 |

- 原点在节**外表面**的中点；渲染器把原点放在节外表面上，模型向 +Y 方向长出厚度。沿 Z 的长度不超过节距 `lengthPerLink`，沿 X 的宽度由模型决定。
- `link_bones` 非空时，每一节以自己骨骼的 pivot 为参考点（§4.2）：第 k 个槽位的 pivot 与那一节的外表面中点重合，渲染器把参考点对到采样点，模型原点因此不必在节上。父链的 rotation 一并计入参考点，但父链带静态 rotation 会让节相对采样帧再转一次，属于内容错误。
- 模型沿 Y 的几何可以比 `thicknessMeters()` 更厚：履带板连同履带齿的总高通常超过 `thickness_mm`，多出的部分伸向轮组，被负重轮挡住。装甲与包络仍只认 `thicknessMm`。
- 渲染器把模型 +X 对齐轮轴、+Y 对齐内法线、+Z 对齐切线，因此在同一条带的上下行程上履带齿始终朝向轮组。
- 贴图路径由 `visual.texture` 明确给出；不使用 `ModelIndex` 的默认贴图推导。

### 8.2 渲染分工

```java
public enum TrackRenderMode { MODEL, PROCEDURAL }

public static void renderTrack(SubPart subPart, PoseStack poseStack,
                               MultiBufferSource bufferSource,
                               float partialTick, int packedLight,
                               TrackRenderMode mode)
```

| 调用方 | 模式 | 行为 |
| -- | -- | -- |
| `PartEntityRenderer` | `MODEL` | 模型可用则按槽位逐节渲染型号模型；不可用则回退程序化 |
| `DistantVehicleRenderer` | `PROCEDURAL` | 始终画程序化扁长方体，不加载内容包模型 |

- 不做距离 LOD；近处/远处由渲染入口选择。
- 模型路径：`ModelIndex("fitting", visual.model())`；借用主动轮所属 `Part` 作为 `IAnimatable` 创建静态 `ModelPose`；按 `link_bones` 切槽（§4.2），每节用 `ModelRenderHelperKt.render` 画该槽的骨骼。
- `visual.model` / `visual.texture` / `visual.icon` 的命名空间是内容包里**命名空间目录**的名字，不是内容包名：文件位于 `spark_modules/<包>/<命名空间>/...` 时，ResourceLocation 写 `<命名空间>:...`。sdkfz 包的两个履带因此写 `machine_max:2s38_track.geo` / `machine_max:textures/part/2s38/2s38.png`，与同包零件的写法一致。
- 图标：`visual.icon` 存在时物品栏与创造栏画 2D 图标；缺省时画 3D 型号模型——K > 1 时看到的是整个最小重复单元（K 节）。图标只影响物品，不影响世界里履带节的渲染。
- 缓存：`ModelPose`、`RenderType`、槽位表（骨骼 + 参考点）按型号 id 缓存，不每帧新建；客户端接收内容包重载完成（`PackAllFinishedEvent`，`fromServer` 为真）时清空，因为 `OModel.ORIGINS` 与型号表都被重建了。
- `RenderType` 按 `visual.texture()` 缓存 `RenderType.entityCutout(texture)`；不透明贴图也可用 `entitySolid`。
- 模型缺失（`OModel.EMPTY`）或 `link_bones` 与模型不符：日志一次并按型号记住，回退程序化，不崩。
- 程序化回退：`LINK_WIDTH`、`LINK_LENGTH_RATIO`、`LINK_COLOR`、纯白贴图，沿用 `TrackRenderer` 现有常量。

### 8.3 性能

- 每槽一次 draw call：单骨骼、少量 cube 的节，逐节绘制成本与逐节扁长方体同一量级。
- 多骨骼单元需要合批或 LOD；不做，远处已由 `PROCEDURAL` 分流。
- 模型纹理缓存避免每节重复创建 `RenderType`；剔除盒不读模型几何，与 K 无关。

### 9.3 型号到物品

`machine_max:track` 的 `FITTING_TYPE` 由配方产物直接写入。`machine_max:fabricating` 与标准合成配方都用 `ItemStack.CODEC` 解析 `result`，支持 `components`：

```json

  "ingredients": [ { "item": "minecraft:iron_ingot", "count": 4 } ],
  "result": {
    "id": "machine_max:track",
    "count": 1,
```

- 一个型号一条配方；型号 id 只出现在 `components`，物品 id 固定为 `machine_max:track`。
- 标准 `minecraft:crafting_shaped` 的 `result` 同样使用 `ItemStack.CODEC`，内容包可以按自己的制造路线选择配方类型。

| 断带 | 装甲与命中音回退 HitBox 材质；摩擦/滚动音用履带材料 |
| 音效 | 命中音由 `TrackAttr.sounds` 决定；滚动固定 `TIRE_METAL`；滑移固定 `TIRE_EXTRA_SLIP` |
| 渲染 | 近处按槽位逐节显示型号模型；远处显示程序化履带；模型或 `link_bones` 不可用时近处回退程序化 |
| 物品图标 | `visual.icon` 存在时物品栏与创造栏画 2D 图标；省略时画 3D 型号模型（K > 1 时为整个重复单元）；图标缺失不影响世界内渲染 |
| 周期节 | 空 `link_bones` 时整模型一节、五个第一方型号外观不变；非空时第 i 节取槽位 `i % K`，节序沿整圈循环，左右两侧绕向相反时循环方向随之反向（允许的反装结果） |
| 模型轴向 | 模型 +X 对齐轮轴、+Y 对齐内法线、+Z 对齐切线，放置矩阵行列式为 +1；原点落在节外表面，上下行程的履带齿都朝向轮组 |
| 同步 | `TrackLinkData.track_type` 往返保留；旧存档回落默认型号 |
| 节数 | `TrackLinkData.link_count` 在 JSON 与线格式往返保留，蓝图归一化不清零；模板 / 蓝图自带该值时加载端直接采用，旧数据缺该字段时为 `0`，加载端按当前包络推导一次；超过 `MAX_LINK_COUNT` 的 JSON 值在解码期拒绝；与型号的周期 K 不整除时保留原值并记一条按型号去重的告警 |
| 成员下限 | 成员少于 2 时 `removeMember` / `refreshMembers` / `onMemberDestroyed` / `fromData` 都解散；`createTrack` / `assemble` 返回 `null` |
| 耐久上限 | `TrackAttr.maxDurability(N)` = `durabilityPerLink × max(1, N)`；N 取持久化的 `link_count`（模板 / 蓝图可预置），只有旧数据才按 `lengthPerLink()` 推导 |
