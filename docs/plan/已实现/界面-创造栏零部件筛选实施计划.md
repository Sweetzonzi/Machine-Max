## 1. 交付目标与范围

零部件与零部件制造蓝图两张创造页提供三个组合条件：series 下拉选择系列、category 侧栏选择用途、搜索框匹配文字。三条件取交集。没有研究配方的零部件同样参与目录。

目标页由 `src/main/kotlin/io/github/sweetzonzi/machine_max/common/registry/MMCreativeTabs.kt#MACHINE_MAX_PART_TAB` 与 `#MACHINE_MAX_FABRICATING_BLUEPRINT_TAB` 确定。装备、整车蓝图、预装配体、配件及其他模组创造页均运行各自的界面逻辑。

本期不做内容包来源分组、研究组派生、收藏、最近使用、参数比较、连接点兼容性推荐、AUI 页面、型号级公共 tags 字段或新网络协议。研究配方的 groups 保持其科研组织职责。搜索结果表示文本匹配，不表示能装到当前连接点。

产品行为已确定。工程细节包括注入描述符核对、按钮图标和像素微调，由实施者在本文默认布局与第 10 节验收约束内完成；这些细节不是待确认的产品需求。若目标版本源码与第 2 节不同，先核对接线坐标并记录差异。

## 3. 标签与文本契约

### 3.1 系列

- 识别标签路径 `series/` 下的非空名称，例如 `machine_max:series/k17`、`my_pack:series/example`。
- 成员判定使用完整 ResourceLocation，保留命名空间；两个包的同名后缀是两个不同系列。
- 以型号全部变体的标签并集确定系列，允许一个型号出现在多个系列中。
- 选项来自当前页完整候选的有效型号，而非当前搜索结果。选择类别或输入文字时选项位置保持稳定。
- 固定第一项“全部系列”，后面按完整标签 ID 排序。没有系列的型号在“全部系列”下可见，本期不设独立“未归族”选项。

### 3.2 类别

共用类别词表固定为 `machine_max:category/structural`、`mobility`、`weapon`、`decoration`、`misc`，依次显示结构、机动、武器、装饰、杂项。侧栏顺序为“全部”加这五类，再加“未分类”。

一个型号可以匹配多个类别。没有命中任何上述类别的型号归入“未分类”，包括仅有未知 category 标签的型号。未知标签参与文字搜索，不动态扩张侧栏。所有按钮保持固定顺序；没有成员的具体类别禁用，避免点击进入空页。“全部”保持可用。

### 3.3 文字搜索与翻译

- 去掉首尾空白，以 Locale.ROOT 转小写，按连续空白分词；每个词必须在至少一个搜索字段中出现，字段之间可不同。
- 字段包括：物品显示名、型号完整 ID、标签完整 ID、标签译名；包含系列译名。每个字段独立匹配，不靠拼接边界产生误命中。
- 普通输入按子串匹配；本期不承诺拼音、模糊纠错、引号、正则或 @ 特殊语法。保留 # 标签搜索，具体行为见本节末尾。series 弹层自己的搜索只匹配系列 ID 和译名，不修改主搜索条件。
- 标签语言键约定为 namespace + 点 + path 中斜杠转点；例如 `machine_max:series/k17` 对应 `machine_max.series.k17`。无翻译时显示完整原始标签 ID。
- 标签语言键由 `TextUtil#getTagLanguageKey` 生成：`ResourceLocation.toLanguageKey` 保留路径里的斜杠，而内容包语言表按点分隔，因此该助手把斜杠转成点。`getTranslatedOrRawTag` 在键查不到时返回完整原始标签 ID，`collectSearchTexts` 用同一转换并把完整 ID 与译名都放进搜索字段。物品名称的语言键规则保持不变。
- 本期标签并集用于目录发现，左右等词命中意味着型号某个变体带该标签。界面不声称自动选定了这个变体。

主搜索和弹层搜索最大长度统一设为 256，覆盖原版 init 的 setMaxLength(50)，避免长 ID 与多词被静默截断。超限由 EditBox 的长度约束处理。

以 # 开头时，仅搜索标签字段：部件自定义标签的完整 ID/译名，以及候选 ItemStack#getTags 返回的原版物品标签 ID；后续关键词按空白分词并取交集，series/category 条件同时生效。只有 # 时匹配至少有一条上述标签的候选。普通模式也保留标签字段。visibleTags 在每次刷新时清空，# 模式按查询词重新填入命中的原版 TagKey<Item>，供原版标签提示使用；自定义部件标签由 appendPartTags 展示，不能伪装成注册的物品标签。不得把接管 refreshSearchResults 实现成静默丢弃 # 功能。

翻译助手修改会直接改变现有 tooltip：已定义翻译的 category/direction 等显示译名，没有翻译的标签显示完整原始 ID。测试与 U13 须验证这个消费方；不能只验新侧栏。

## 4. 界面行为和布局

### 4.1 顶部与侧栏

两张目标页调用 withSearchBar() 和 hideTitle()。withSearchBar() 在使用默认背景时会选择搜索版背景纹理；该纹理与槽位的对齐属于 U01 验收。原生网格、槽位和快捷栏位置保持不变。以 getGuiLeft/getGuiTop 对应的 GUI 坐标定位，不使用窗口物理像素。

默认布局：series 按钮位于 (leftPos+8, topPos+4) 的约 70 × 12 区域；右侧保留原生搜索框。系列名称超宽截断，tooltip 展示全名。类别侧栏位于面板外侧 [leftPos-28, leftPos)，不占容器内部 x=9 开始的格子区域；使用固定高度视窗与上下箭头，鼠标位于视窗时滚动类别。优先用原版按钮底图或简单 GuiGraphics 绘制。

本期支持 GUI 逻辑宽度至少 251，常规验收基准为 320：195 宽容器居中时，宽度 251 对应 leftPos=28，面板外侧可以完整容纳 28 宽侧栏。容器采用原版居中位置，不交付面板平移、类别折叠按钮或类别弹层。低于 251 的逻辑宽度属于本期支持范围之外，不保证外侧栏完整可用，也不要求实施者建立适配分支；SeriesPickerWidget 仅承担第 4.2 节的系列弹层。

不能把 320 当作引擎保证的最小逻辑宽度：目标版本归档内 `com/mojang/blaze3d/platform/Window.java#calculateScale` 在常规缩放循环后还有 forceUnicode 的偶数缩放调整；`#setGuiScale` 根据最终缩放计算实际逻辑宽度。支持下限是本功能的验收边界，不是对其他窗口/缩放组合不可达的断言。系列弹层在支持范围内钳制到窗口边界。

类别按钮的图标取该类别当前候选中的一个堆，因此显示的是内容物本身；该类别没有成员时回退到固定的原版物品。图标只在候选集合变化时重选，输入查询词不会让它跳动。按钮须有翻译名称、选中态、悬停提示和旁白文本；悬停提示给出类别译名，五个共用类别再加一行完整标签 ID，供内容包作者对照 `variants[].tags`。

### 4.2 series 弹层

- 按钮展开同屏弹层，顶部一个 EditBox，下面固定最大高度的滚动列表。默认显示六行；按屏幕可用空间缩短列表并钳制边界。
- 允许覆盖格子；绘制处于物品、拿起的物品堆和槽位提示之上，弹层覆盖范围内不显示背后物品 tooltip。
- 点击一项：应用系列、关闭弹层、联合刷新。点击外部：关闭并消费本次按下及对应释放，防止同次操作拿取背后物品或切换 tab。
- Esc 先关闭弹层；弹层关闭时 Esc 交给原版关闭界面。方向键移动选择、Enter 应用，滚轮滚动列表。长名称提供完整 tooltip。
- 弹层打开期间，字符、粘贴、退格、数字键和导航键只进入弹层；避免原版快捷栏数字键和主搜索框同时响应。
- 主搜索有焦点时数字键优先作为文本输入，避免悬停物品导致数字变成快捷栏操作。目标页允许主搜索失焦：点击格子后数字键交给原版快捷栏操作，点击搜索框恢复输入焦点。主搜索失焦时字符不自动写入；弹层关闭后恢复展开前的主搜索焦点。须接管目标页原版 keyPressed 中数字键优先于 EditBox 的顺序。

### 4.3 状态与反馈

条件为单选系列、单选类别与主搜索字符串。两张目标页共用这三个条件；离开目标页隐藏控件并关闭弹层。一次世界连接期间记忆条件，退出世界清空。弹层内的临时搜索每次展开清空。

类别选中态和 series 按钮直接展示条件。提供小型“清除全部”入口，将系列与类别设为全部、主搜索置空。主搜索框右键清空仅清文字。控件布局不足时可把重置入口放在侧栏，不覆盖物品槽位。

非零结果的数量在系列按钮 tooltip 中报告“匹配数 / 本页总数”；零结果在空网格中显示短提示“无匹配结果”，并保持条件与重置入口可用。不同目标页的蓝图数量可以较少，因为它只包含有制造配方的型号。

## 6. 屏幕接线步骤

### 6.1 初始化和切页

1. init 入口解除上轮控件实例引用，保存当前条件。原版负责其控件列表重建。
2. init 尾部建立 Browser 和控件，通过 addRenderableWidget 挂载，按当前 tab 设置可见性，恢复主搜索字符串并执行一次刷新。
3. selectTab 入口保存目标页的主搜索字符串；尾部设置控件显隐，关闭弹层，进入目标页时恢复条件并刷新。原版 selectTab 会清空搜索框，并强制 setCanLoseFocus(false)/setFocused(true)；目标页 TAIL 必须设 setCanLoseFocus(true)，恢复本期焦点状态，同时 setMaxLength(256)。非目标页保留原版设置。
4. refreshSearchResults 入口仅在目标页且 Browser 已初始化时接管；首次 init 中 Browser 尚未建立的调用交给原版，第 2 步负责最终展示。
5. 使用明确的初始化/恢复保护，避免 setValue 与刷新互相触发形成递归；不要每帧重复 setValue。
6. mouseClicked HEAD：先处理弹层/侧栏；点击主搜索框设置其焦点，点击格子或普通空白解除焦点。必要时同步 Screen#setFocused，避免两套焦点记录分歧。
7. keyPressed HEAD：弹层打开时先走弹层，无论主搜索是否有焦点；弹层处理并消费输入后直接返回，不向主搜索或原版分发。弹层关闭时，目标页主搜索有焦点才先将编辑键交给该 EditBox，消费非 Esc 的普通键，字符由 charTyped 处理；这样数字进入 ignoreTextInput/checkHotbarKeyPressed 分支前已被接管。Esc 交给关闭弹层/原版关闭路径。主搜索失焦时走原版快捷栏操作，不因手动输入钩子误吞数字快捷键。
8. charTyped HEAD：弹层优先；否则仅主搜索有焦点时转交 EditBox，文字变化触发刷新，消费处理过的字符；失焦时返回 false。处理按键时保持 ignoreTextInput 与对应 charTyped 的顺序一致，避免数字按键被原版标记后字符丢失。keyReleased 清理相关临时输入标记。

### 6.2 统一过滤和写回

完整候选始终取当前 tab.getDisplayItems()。BuildCreativeModeTabContentsEvent 只生成完整目录，不按界面条件删项。每次过滤从完整候选开始，判断 series、category、每个查询词，写入 menu.items。

写回顺序：clear menu.items → addAll 结果 → 重建第 3.3 节 visibleTags → scrollOffs = 0 → menu.scrollTo(0)。只有条件改变时回顶；普通 containerTick 不反复回顶。

resize 必须规避零分母：ItemPickerMenu#calculateRowCount 为 ceil(N/9)-5，N=37—45 时为 0，getScrollForRowIndex(0) 得到 0/0。仅在目标页的 resize 内包裹调用 getScrollForRowIndex：重建后 N≤45 直接返回 0，否则调用原版再检查 Float.isFinite 并钳制到 [0,1]。resize HEAD 对已有非有限 scrollOffs 先归零，TAIL 再保证 scrollOffs 有限并调用 scrollTo。保留原版 init/控件重建顺序，不全局改 ItemPickerMenu。验收 0、1、36、37、44、45、46、54、55 个候选。

直接保留候选 ItemStack 的组件和顺序，不重新手工生成制造蓝图，不按 Item 去重。当前部件页使用 PART_TYPES.forEach，底层发布快照为 Map.copyOf，不能视为有序；制造蓝图分支也须检查。实施时在 MMCreativeTabs#putPartsIntoCreativeTab 的这两条分支显式按完整型号 ID sortedBy 后输出，作为排序交付项。外部事件插入的条目保留事件最终顺序。未知 PART_TYPE 或外部无型号条目视为未分类，可在全部条件下按自身名称搜索，不能因索引缺项消失。

主搜索输入、类别点击、系列选择、重置全部都触发同一个 refreshSearchResults 入口。原版搜索树仅服务其他页；目标页结果计算由 Browser 完成。开箱式过滤 O(N × 查询词数)，只在输入或数据变化时执行；本期不引入全文检索库、后台任务或倒排索引。

### 6.3 输入与绘制

在界面 mouseClicked/mouseReleased/mouseScrolled/mouseDragged/keyPressed/charTyped 的入口检查 Browser 是否处理事件，处理后直接返回 true。弹层打开时优先路由弹层，再考虑侧栏，最后才进入原版。记录被消费的按下对应的释放，避免释放事件触发原版 tab 切换。点击侧栏即使位于容器外也必须消费。

正常目标页的侧栏与系列按钮由控件系统绘制。弹层最后绘制；针对 render 内调用 renderTooltip 的位置抑制弹层覆盖下的槽位 tooltip，避免在 AbstractContainerScreen 全局加注入。注入描述符以本地归档源码核对，可使用已有 MixinExtras 能力包裹调用；不要因单个绘制点扩展全局 UI 事件系统。

render 的视觉层级和鼠标命中层级必须一致。仅提高 z 值不足以阻止点击；仅添加 GuiEventListener 也不足以覆盖创造页直接处理滚轮和字符的行为。

格子行为直接交给原版 slotClicked。ItemPickerMenu#canTakeItemForPickAll/#canDragTo 已禁止创造候选格上的双击合并和拖拽分摊，无需加同义注入。右键不是一概禁用：slotClicked 对鼠标携带堆有 shrink(1) 等明确处理，保留并验收。自定义右键清空只命中搜索框区域。

## 7. 内容、配方与语言生命周期

### 7.1 完整目录缓存

CreativeModeTabsMixin 在 tryRebuildTabContents HEAD 内直接执行检测，不依赖已建立的 Screen 或 containerTick：用 @Unique 静态字段保存最后处理的 PartDefinitions.regular(true) 引用，以及配方目录脏标记；仅 `isReady(true) && (快照引用变化 || 配方标记为真)` 时，将 @Shadow 的非 final CACHED_PARAMETERS 置 null，记录本次快照并消费配方标记。原版继续执行重建，屏幕随后重建所有带搜索栏 tab 的搜索树。检测与失效发生于同一入口。

该 HEAD 同时覆盖开屏后的 containerTick 检查和闭屏更新：CreativeModeInventoryScreen 构造函数直接调用其 tryRebuildTabContents，最终进入此静态入口，构造时就会识别闭屏期间发布的新快照。禁止把快照比较仅放在 Browser/containerTick。

目录检测不比较长期保持同一引用的 MMDynamicRes.PART_TYPES 视图，应读取 PartDefinitions 提供的发布快照。isReady=false 时不置 null、不更新最后处理的快照、不消费配方脏标记，Browser 保留最近完整目录和系列选择，不拿未就绪的类型表重新筛空。理由：PartDefinitions.begin 发布暂空表，若据此强制重建，屏幕 tryRefreshInvalidatedTabs 会把完整候选为空的当前页切到默认建筑页。

屏幕侧注入契约：在 CreativeModeInventoryScreenMixin 中，对 `tryRefreshInvalidatedTabs` 做 `@Inject(at = @At("HEAD"), cancellable = true)`；当 selectedTab 是本期两个目标页之一且 `!PartDefinitions.isReady(true)` 时调用 `ci.cancel()` 并返回，跳过该次方法内的重建、collection.isEmpty() 检查和 selectTab(defaultTab)。非目标页或 isReady=true 时直接放行。该钩子同时挡住装载空窗里的权限/注册表参数变化路径，配方脏标记与最后完整快照保持待处理状态；就绪后的下一次 containerTick 自然重入，恢复原版检查和第 7.1 节静态入口的快照检测。无需额外的重试任务或计时器。

首次在装载空窗中打开创造栏、且此前没有完整目标页目录时，接受原版 init 以 hasAnyItems 筛掉两个空目标页并落到默认页；这不属于“已打开目标页的选择保持”契约。就绪后目录恢复，两个有内容的目标页可重新选择，但不自动把玩家从当前页切回零件页。目标版本可见翻页列表是在 init 中构建的，因此目录恢复导致页集合变化时，在本次目录重建结束后的安全屏幕 tick 执行一次界面重初始化，恢复玩家当前可见的 tab，不能仅更新 menu.items；此检查对当前处于默认页的创造界面也生效。以目录发布轮次记录一次待重建标记，避免 init/刷新递归和每 tick 重建。若本次就绪目录本身为空，目标页保持隐藏。

硬失败边界：若装载未执行 onFinish 且 isReady 长期为假，本期接受目标页保持最近完整展示、该页上的原版权限/注册表参数刷新持续延后这一退化，不设置超时放行、不增加轮询恢复任务。切到非目标页后原版检查直接放行，重连按退出清理契约重置缓存。该选择仅规定此筛选功能的行为，不承诺修复内容包装载失败。

isReady=true 的最终空快照允许重建；完整页本身已无条目时接受原版返回默认页。选项被过滤到零条不会修改 tab.getDisplayItems()，因此不触发默认页跳转。部件与配方的重建顺序遵循第 2 节入口，不在 Browser 重建制造配方。

两项标记职责明确：配方事件标记目录待重建，Browser 在最终 displayItems 集合变化后重建自己的缓存。闭着创造栏发生的更新也必须影响下次打开时的目录。无需每 tick 扫描全部标签。

### 7.2 打开中的界面与语言

目标页 containerTick 在 isReady=true 时检查最终目录/语言是否变化：变化后重建搜索缓存和系列选项，重新过滤；已选系列在最终非空候选中不存在时设为全部。普通绘制帧只绘制。未就绪时采用第 7.1 节最近完整目录。

语言缓存可比较 `net/minecraft/locale/Language.java#getInstance` 返回对象身份，或用客户端资源重载监听置脏，下次主线程读取名称后重建。不要在异步资源 prepare 阶段修改界面。退出世界清空条件、候选与文本缓存；Browser 的静态状态不持有旧 Screen、Level 或玩家引用。

共通类不得引用本项目 client 包或 Minecraft 客户端类。部件快照由客户端观察，配方通知放在现有客户端 handler；无需为本功能给 Spark-Core 加事件。两个 Mixin 均只列入 client 配置。

### 10.1 自动化

生产过滤分两层：`CreativePartBrowser` 的实例入口读当前页候选与型号级缓存、写回菜单，不读 Level、玩家或屏幕之外的全局表，也不修改候选堆；纯判定（系列标签识别与并集、类别词表命中、分词、跨字段匹配、字段组合）是不依赖 GUI 初始化的静态方法，供 JUnit 直接调用。实际拆分见 §12.4。

### 12.3 Mixin 最终注入点

`CreativeModeInventoryScreenMixin`（全部为 `@Inject`）：

| 目标 | 位置 | 作用 |
| --- | --- | --- |
| `init()V` | HEAD / TAIL | 解除上轮控件引用并保存搜索串；建立 Browser、把控件加入 `renderables`/`children`/`narratables`、同步当前页 |
| `selectTab` | HEAD / TAIL | 离开目标页前保存搜索串；切页后同步显隐、关闭弹层、恢复条件与焦点 |
| `refreshSearchResults` | HEAD（cancellable） | 目标页改用 Browser 过滤，写回 `items`、`visibleTags`，回顶 |
| `mouseClicked` / `mouseReleased` / `mouseScrolled` / `mouseDragged` / `keyPressed` / `charTyped` | HEAD（cancellable） | 交给 Browser，必要时消费 |
| `tryRefreshInvalidatedTabs` | HEAD（cancellable） | 目标页且部件未就绪时跳过本次刷新 |
| `containerTick` | TAIL | 目录轮次变化时重建一次界面，否则做引用比较 |
| `resize` | HEAD / TAIL | `scrollOffs` 归零与钳制 |
| `refreshCurrentTabContents` | TAIL | 目录刷新路径同样可能得到非有限 `scrollOffs`，钳制后回写 |
| `render` | `renderTooltip` 调用之前（cancellable） | 绘制弹层/零结果提示；弹层覆盖鼠标时取消槽位提示 |

`CreativeModeTabsMixin`：`tryRebuildTabContents` HEAD —— 发布快照引用变化或配方脏标记为真时，把 `CACHED_PARAMETERS` 置空并推进目录重建轮次。

### 12.4 与本文原设计的偏差清单

- **类别侧栏不设滚动视窗与上下箭头**：侧栏固定七项（全部、五类、未分类），在 136 高的面板里以 18 像素行距完整显示，没有需要滚动的状态；按 `AGENTS.md#设计节制` 的“没有消费方的分支不写”，只保留固定列表。
- **生产过滤入口不是单个“接收候选与型号表的确定性方法”**：实际拆成两层——`CreativePartBrowser` 的实例入口读当前页候选与型号级缓存并写回菜单，纯判定拆成 `isSeriesTag`、`seriesTags`、`knownCategory`、`matchesCategory`、`tokenize`、`matchesAllWords`、`searchFields` 等静态方法供 JUnit 直接调用。物品堆与组件仍只在实例路径上出现，自动化用例因此不需要伪造注册环境。
- **滚动有限性覆盖 `refreshCurrentTabContents`**：原设计的除法风险写在 `resize`，但目录刷新重建内容时也会走到 `ItemPickerMenu#getScrollForRowIndex`，候选数为 37—45 时行数为零。该注入点同样在 TAIL 钳制并回写，不改 `ItemPickerMenu`。
- **主搜索失焦时还原编辑键造成的改动**：`EditBox#keyPressed` 不检查自身焦点，失焦时也会处理退格、方向键与粘贴。`CreativePartBrowser#keyPressed` 在失焦分支调用后立即还原文本，只让不改变文本的按键（含数字快捷键）继续走原版路径。
- **控件挂载不走 `addRenderableWidget`**：该方法声明在 `Screen`，`@Shadow` 在目标类里解析不到超类成员（客户端实测报 `Unresolved method addRenderableWidget in target class`）；整体放宽访问又被 NFRT 判为与 `CreateWorldScreen` 的同名覆写冲突。最终按该方法的语义逐项加入三个列表：`renderables` 本就 public，`children` 与 `narratables` 由访问转换器放宽为 public。
