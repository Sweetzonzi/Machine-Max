# 观瞄系统：第三人称瞄准点与相机焦点实施计划

**状态**：未偏置焦点、相机局部坐标偏置解析、方向分离与跨视点目标连续性交接已于 2026-11-23 落地；`test` 通过（572 项，0 失败）。G1—G10 客户端实机验收待完成。

初稿日期：2026-11-22；修订日期：2026-11-23。

本文处理第三人称座椅视角的相机观察方向、武器控制方向、世界目标点与相机焦点，并规定它们在第一人称、固定炮镜和可转摄像头之间切换时的交接语义。第三人称参考姿态平滑、镜头惯性与碰撞震动分别由独立计划处理。源码路径以 Machine-Max 仓库根为基准。

## 1. 目标与范围

高大载具的车体可能占据第三人称画面中心。普通第三人称下，相机观察方向是屏幕中心的光轴；武器控制方向则从相机观察方向向上偏转座椅配置的俯仰偏置。HUD 目标环投影武器控制目标点，因此保持水平居中并按偏置出现在屏幕中心上方。相机不得为了把目标环压回屏幕中心而转向武器目标点。

交付范围：

- 为第三人称座椅定义可配置的中性俯仰偏置，首轮标定值采用 15°，允许内容将其设为 0° 或在 0°—20° 范围内调整。
- 普通第三人称观察所生成的有限世界目标点同时作为武器控制目标与 HUD 目标环位置；相机观察方向与该目标方向分离。
- 跨视点切换保持期望武器目标方向；只转换目标点与目标视点焦点的表示，不瞬间改写炮塔、炮镜等机构的实际角度。
- 将逻辑瞄准锚点与相机后置轨道分开计算；武器目标方向由未偏置的相机观察方向向上偏转得到，不要求穿过载具中心或座椅枢轴。
- 保留地形遮挡裁剪、第三人称前／后视角、座椅跟随／自由配置、临时自由观察、当前 HUD 目标环语义和武器实际炮管方向显示。

不在范围内：

- 鼠标输入平滑、第三人称参考姿态跟随滤波或任何新的转速限制。
- 镜头惯性、落地／碰撞震动、投射物震屏以及旋转／位移叠加架构。
- HUD 目标环以共同世界目标点的屏幕投影表达；武器控制目标使用该有限世界点，不使用屏幕坐标偏移或实体射线命中点。
- 网络协议沿用既有世界目标字段；武器机构转速与行程不属于本计划范围。

## 2. 当前实现与问题基线

### 2.1 目标点与观察状态

客户端 `CameraController#tick` 在主线程 tick 推进座椅观察。视点只保存未偏置相机焦点 `F`；主线程从 `F` 的相机姿态解析武器目标 `P`，存入 `expectedPoint` 并经既有输入包上报，供服务器武器控制器追赶。第三人称在目标解析时应用座椅俯仰偏置；新会话默认焦点距离为 `AimMath.AIM_DISTANCE_METERS = 1000` 米。

第三人称目标环由 `SightHud` 把世界点投影到当前渲染相机。正常观察时，目标环表达武器期望目标；各发射管的轴向另绘制小环。因此目标环与炮管方向可以因机构滞后而分离，不能把两者合并成一个准星。

### 2.2 相机位置与遮挡原因

`CameraController#seatAimAnchor` 按 `focusOnCenter` 选择载具中心或座椅挂点，作为逻辑瞄准锚点 `A`；`#seatPivot` 在其上应用 `third_person_offset` 得到相机轨道锚点 `B`。`#seatOrigin(B, V)` 沿相机方向和配置距离生成轨道位置，并以枢轴到候选位置的方块射线裁剪。

已落地的相机轨道修复使第三人称显示旋转不再 `lookAt(P)`；C 键松开时，回正后的显示旋转同时提供相机朝向和轨道方向，相机位置围绕同一 `B` 连续移动。本次重构把视点唯一保存值改为未偏置焦点；逻辑目标和 HUD 目标均在输出边界从焦点重新解析。`CalculateDetachedCameraDistanceEvent` 仍把原版附加距离设为 0，因为载具视点的完整配置距离已经写入自定义轨道位置；这不表示相机与轨道锚点重合。

### 2.3 需保持的逻辑边界

1. 第三人称视点持久状态与逻辑采样保存未偏置相机焦点 `F`；`expectedPoint` 是解析出的武器目标 `P`。渲染帧不能改变它或发送额外控制输入。跨模式切换以 `P` 交接，在目标视点边界转换为其所需表示；不得把带偏置的 `P` 直接冒充第三人称 `F`。
2. `renderedSeatAimPoint` 是本帧从渲染焦点重新解析、供 HUD 投影的武器目标采样；它可以按刻内插值重建，但不得成为持久逻辑状态。
3. `renderPose` 表示显示相机位姿；地形裁剪只改显示位置，不能改变 `expectedPoint`。相机显示旋转不得通过看向 `expectedPoint` 来消除目标环的垂直偏移。
4. 当前第三人称目标使用有限的 1000 米世界点近似武器控制方向，服务端协议接收一个世界点。本计划继续使用此表示，并将相机观察方向作为独立的显示状态处理。

## 3. 行为契约

1. 普通第三人称座椅的中性相机观察方向沿座椅参考前向；武器控制方向则在相机局部坐标中绕局部右轴向上偏转配置值，首轮为 15°。鼠标俯仰／偏航仍使用原输入增量与灵敏度，不加入鼠标加速度或响应延迟。
2. 正常跟随观察保存未偏置焦点 `F`。从 `F` 的相机方向和焦点距离解析出的世界点 `P` 用于武器期望目标与目标环投影，不回写为焦点。偏置为正时，目标环应位于相机画面的水平中心线上方；偏置为 0° 时回到相机光轴附近。不得为实现该位置而移动 HUD 贴图或改变武器目标点。
3. 逻辑点 `P` 不依赖相机实际位置、地形裁剪结果、显示抖动或渲染帧调用次数。
4. 相机观察方向与武器控制方向是两条方向：正常第三人称沿未加偏置的焦点 `F` 显示，武器目标 `P` 在目标解析阶段按偏置生成。切出第三人称时交接 `P`；切入第一人称时将 `P` 作为零偏置焦点，切入第三人称时按新座椅参考和锚点反算 `F`，使再次解析所得目标仍为 `P`。
5. 目标环直接投影本帧武器目标点。目标点与相机位置来自不同锚点时可能产生有限距离视差；水平偏移须测量并限制在验收容差内，不能通过改写逻辑目标点或使用被裁剪相机位置来消除。
6. 座椅安装参考的 yaw、pitch、roll 组合语义保持不变；俯仰偏置在相机局部坐标中应用，绕相机局部右轴旋转局部前向，因此也随相机姿态及其滚转正确转动。
7. `min_pitch` / `max_pitch` 是相对于座椅参考的有效武器瞄准俯仰硬限位。偏置后的有效瞄准角不得越界；因此输入相对中性点的可用上、下行程可以不对称。
8. 座椅、设备视点及第一／第三人称切换保持当前期望目标方向。进入第三人称时按目标点反算未偏置焦点，进入第一人称或摄像头时以目标建立视点。可转摄像头切出时继承其尚未追到的期望观察方向；固定炮镜继承瞄准状态的期望目标，而非真实光轴当前角。
9. 临时自由观察仍只改变相机画面。它开始时继承当前显示方向，武器控制目标保持不变，目标环按该点投影且允许离开常规偏置位置；退出时恢复原控制目标，相机朝向与轨道位置一起平滑回到正常观察状态。
10. 固定炮镜画面始终读取真实挂点光轴；目标处于机构转动途中时，继承的目标继续由执行器按原转速追赶，不得把实际角瞬时改成目标角。可转摄像头保留原有的入场对齐行为；切出时交接其期望观察目标，而不是限速后尚未追到的实际观察角。

## 4. 几何定义

### 4.1 逻辑瞄准点

定义：

- `A`：第三人称逻辑焦点锚点。由 `focusOnCenter` 在载具中心与座椅挂点加眼高之间选择；不叠加相机偏移。
- `R`：本 tick 或本渲染帧对应的座椅跟随参考旋转，包含当前代码支持的乘坐刚体完整姿态。
- `u = (pitch, yaw)`：相对座椅参考的未偏置相机观察角，单位为弧度。`ThirdPersonViewpoint` 持有该状态及对应焦点；鼠标增量不经过新的平滑。
- `b`：座椅型号配置的第三人称俯仰偏置，单位在 JSON 中为度，内部转换为弧度。
- `Q`：未偏置相机姿态，由 `R` 与 `u` 构造；`Q` 的局部前向定义相机光轴，局部右轴定义偏置旋转轴。
- `V = Q·(0,0,-1)`：未偏置相机观察方向，它定义常规第三人称屏幕中心光轴及相机轨道方向。
- `D = Q·Rx(b)·(0,0,-1)`：武器控制方向；`Rx(b)` 表示在相机局部坐标绕局部右轴应用偏置。正偏置使局部前向向上，不依赖座椅参考的局部轴。
- `L`：第三人称新会话默认采用 `AimMath.AIM_DISTANCE_METERS = 1000` 米；第三人称继承既有目标时取新锚点 `A` 到继承点的距离，以免切换视点时重投目标距离。第一人称仍使用原有 1000 米距离。
- `F = A + L·V`：持久的未偏置相机焦点；它是视点唯一保存的世界焦点。
- `P = A + L·D`：从同一锚点和焦点距离临时解析出的有限世界武器控制目标，也是 HUD 目标环投影点；它不写回视点状态。

`u.pitch` 表示未偏置相机观察俯仰，并限制在 `[min_pitch - b, max_pitch - b]`，以保证偏置后的有效瞄准俯仰不越过原硬限位。偏置本身通过相机姿态 `Q` 的局部 X 轴旋转应用，而不是把 `b` 加入座椅参考下的俯仰角。`V` 与相机姿态沿用现有 `ViewMath.lookRotation` / `AimPose.forward` 坐标约定；目标解析使用相同相机局部轴，不手写另一套欧拉角符号映射。第三人称会话的 `L` 在建立时确定：无继承焦点为 1000 米，有继承焦点则按新锚点到焦点的距离取值，后续观察仍使用该距离；第一人称及炮镜保持各自原有距离行为，偏置为零。

主线程逻辑采样使用本 tick 的未偏置焦点 `F_logic`，从其相机姿态按当前偏置解析 `P_logic`，写入 `expectedPoint` 并沿既有链路发送。渲染阶段从刻内采样的焦点 `F_render` 独立解析 `P_render`，供 `renderedSeatAimPoint` 投影 HUD。偏置只参与目标解析，不参与焦点保存；渲染采样只读观察状态。后续若把固定距离解析替换为命中射线，只需替换 `F` 到 `P` 的解析步骤。

### 4.2 相机后置轨道与焦点

相机使用未偏置的观察方向 `V` 计算后置轨道，并在相机轨道锚点应用 `third_person_offset`。武器目标方向 `D` 与相机观察方向不同；相机不得再朝 `P` 转动来抵消偏置产生的屏幕垂直位移。

1. 按现有 `focusOnCenter` 规则求瞄准锚点 `A`；相机轨道锚点 `B = A + R·third_person_offset`，偏移沿座椅参考旋转变换到世界空间。
2. 跟随模式使用未偏置观察方向 `V`；自由模式从逻辑锚点指向保存的世界焦点 `F`。第三人称后视沿 `-V` 放置相机；前视按现有距离符号放置到相反一侧。
3. 按现有速度距离修正及座椅距离配置求轨道长度 `d`，得到理想相机位置 `C_ideal = B - d·V`。地形裁剪只把 `C_ideal` 沿 `B → C_ideal` 轨道缩短为 `C_render`。
4. 相机显示旋转保持未偏置观察方向 `V_render`，并保留 `R` 的滚转参考；不得以 `P_render` 调用 `lookAt`。`F_render` 就是本帧采样的未偏置相机焦点，不另造辅助焦点，也不以地形裁剪后的相机位置重算它。
5. 将 `(C_render, Q_view_render)` 一起写入本帧 `renderPose`。位置事件只应用该位姿，不重新采样物理或座椅状态。自由观察退出回正期间，先对自由观察方向与正常 `V_render` 求同一份平滑显示方向，再用该方向同时计算相机旋转和围绕 `B` 的轨道位置；方块裁剪继续作用于该帧候选轨道。

在理想无偏移且无裁剪的几何中，`P` 相对相机光轴向上偏转 `b`；透视投影的垂直像素偏移符号为负（GUI 坐标向下为正），大小随垂直 FOV 与目标深度按透视关系变化。座椅／载具锚点与相机轨道不重合时会有有限距离视差，尤其 `third_person_offset` 带横向分量时；须量化该误差并通过显示几何控制在验收容差内，不能通过把相机转向 `P` 消除。

目标点由逻辑锚点 `A` 生成；相机轨道由 `B` 生成。`third_person_offset` 保留相机偏移职责，只影响 `B` 和相机位置，不移动 `P`。相机中心光轴 `V` 与偏置后的武器射线 `D` 分离；目标环应自然投影到该光轴上方，而不是被相机旋转重新居中。武器从其自身机构位置指向同一 `P`，不要求炮口射线与相机光轴重合。

### 4.3 偏置、输入和初始化

`ThirdPersonViewpoint` 的跟随模式状态表示未偏置相机角 `u`，同时保存与该方向一致的焦点。偏置在目标解析阶段对相机姿态的局部右轴应用，不改变相机角或焦点。这样鼠标灵敏度和输入增量不变，也避免把 15° 当成额外鼠标输入累计。

切入普通第三人称时：

- 有可继承焦点：直接以该未偏置世界点初始化视点，并由当前相机锚点反解相机观察角；不得从 `expectedPoint` 反解后再扣除偏置。
- 无可继承焦点：相机观察角初始化为零，先沿相机光轴建立焦点；之后从该焦点解析出的武器目标再应用 `b`。
- 在座椅跟随与自由模式间切换时，继承同一未偏置焦点；偏置只用于解析目标，不重复写入焦点。
- 进入临时自由观察时，以当前显示相机方向建立临时自由焦点，不对捕获到的显示方向再加偏置；正常座椅焦点与武器控制目标均保持不变。

座椅型号的 `follow_vehicle=false` 表示未偏置相机焦点在零输入时保持世界位置不动。相机姿态由当前逻辑锚点指向该焦点；每次目标解析都从这份未偏置焦点重新应用一次相机局部偏置，不把解析结果写回，因此不会逐 tick 累积抬高。临时 `freeCam` 使用独立焦点，武器控制目标保持原值。

## 5. 配置与内容兼容

在 `SeatSubsystemStaticAttr.ViewAttr` 增加静态属性 `thirdPersonPitchBias`，JSON 键名 `third_person_pitch_bias`：

- 类型：有限浮点数，单位为度。
- 初始默认值：15.0°，作为第一轮游戏内标定值；内容可显式写 0.0°关闭。
- 建议合法范围：0.0°—20.0°。构造校验与中英文 schema 使用同一范围。
- 属性只影响普通第三人称座椅的武器控制方向及目标环垂直位置，不抬高相机光轴，也不影响固定炮镜、可转摄像头、第一人称相机或临时自由观察。
- 该字段是型号级视图属性，不进入座椅动态属性，也不增加任何网络载荷字段。

需要审查 `src/main/resources/spark_modules/Machine-Max_Builtin/machine_max/docs/zh_cn/schemas/subsystem/static/view_attr.schema.json` 与 `src/main/resources/spark_modules/Machine-Max_Builtin/machine_max/docs/en_us/schemas/subsystem/static/view_attr.schema.json`。schema 只手改 Builtin 的中英文版本，再运行 `syncSchemas` 生成其它内容包副本。所有 `src/main/resources/spark_modules/*/machine_max/subsystems/seat/` 第一方座椅定义需在同一批次审查：承担武器瞄准的座椅使用 15°起始值；纯乘客或不应抬高的观察座椅显式使用 0°；其他载具按画面和武器用途选择 0°—20°。字段省略时由 codec 默认值解析，schema 默认值与 Java codec 默认值必须相同。

若载具配置了 `min_pitch` / `max_pitch`，按有效瞄准角硬限位，不自动扩大行程。迁移时检查中性 15°是否落在配置范围内；不在范围内时按限制裁剪并在内容检查中报告，不能静默产生越界方向。

## 6. 实施阶段

### P0：基线采集与内容审查

1. 列出第一方包中所有使用座椅第三人称观察的载具，记录 `focus_on_center`、`third_person_offset`、距离倍率、俯仰范围、座位用途和主武器关系。
2. 建立至少一台高车体、一台低车体、一台乘客座位和一台可切前／后视角的复现场景。
3. 对照 `CameraController#updateSeat`、`#seatPivot`、`#seatOrigin`、`#updateCameraRot`、`#updateCameraPos` 与 `SightHud#renderTargetRing`，核对主线程焦点、目标解析、相机光轴与显示相机位置的来源。
4. 记录目标环的屏幕 X/Y 投影、未偏置焦点和解析目标的世界坐标、相机位置与光轴方向、武器控制方向；记录不同偏置下目标环相对屏幕中心的垂直位移，以及高车体遮挡和 C 键回正期间逐帧的相机位置。

### P1：数学契约与配置

1. 在 `SeatSubsystemStaticAttr.ViewAttr` 添加 `thirdPersonPitchBias`，同步两个 codec 默认构造点、取值校验和 `view_attr.schema.json` 中英文版本。
2. 明确 `ThirdPersonViewpoint` 中的操作者角与有效瞄准角边界；角度均为弧度，配置边界在 codec 处验证。
3. 在纯逻辑层验证未偏置相机焦点及相机姿态；在客户端目标解析边界验证“焦点方向 → 相机局部右轴偏置 → `P`”，继续使用 JOML 相机旋转与前向向量生成方向。
4. 在 `ThirdPersonViewpointTest`、`ViewMathTest` 增加相机方向与武器方向分离、偏置、非零参考 yaw／roll、正反输入、硬限位、目标继承和重复渲染只读判据。
5. 增加纯相机几何测试：相机光轴保持 `V`，目标方向为 `D`；零锚点视差时目标投影水平居中且垂直在上，偏置为零时回到光轴附近。不同相机／瞄准锚点及滚转下量化水平视差。

### P2：相机轨道与焦点分离

1. 将逻辑瞄准锚点与显示轨道锚点的求值职责从 `seatOrigin(pivot, forward)` 的单一路径中拆开。新函数只在存在明确消费方时建立，避免建立未使用的通用相机框架。
2. `expectedPoint` 由未偏置焦点对应的相机姿态、焦点距离及相机局部偏置解析；不得使用 `seatOrigin` 的地形裁剪结果作为目标解析起点，也不得把解析结果写回焦点。
3. 相机位置从应用 `third_person_offset` 的相机轨道锚点 `B` 沿未偏置相机方向 `V` 计算，再复用现有八角方块遮挡轨道裁剪。
4. 相机显示旋转由未偏置相机方向 `V_render` 构造，保留乘坐参考滚转；武器目标点 `P_render` 不参与相机 `lookAt`。
5. 自由观察退出时，旋转与轨道方向使用同一份平滑回正状态；相机位置沿相同轨道锚点连续变化，并继续经过方块遮挡裁剪。
6. `ComputeCameraAngles` 与 `ComputeCameraPosEvent` 共享同一个 `renderPose` 样本；显示位置裁剪不能重写目标点或 `aimDirection`。
7. `focusOnCenter` 和 `third_person_offset` 的现有内容语义保持稳定。若实机证明某些座椅的相机轨道仍进入自车模型，只通过明确的座椅相机锚点／偏移内容调整处理，不改变武器目标点来修正画面。

### P3：目标、HUD 与视角生命周期

1. 正常第三人称的主线程 `expectedPoint` 与同 tick 的 `P_logic` 一致，并继续走既有世界目标网络链路。
2. 普通跟随视角的 `renderedSeatAimPoint` 使用本帧只读重建的 `P_render`。目标环投影该点并按偏置出现在相机水平中心线上方；相机显示旋转保持未偏置观察方向，不朝向该点。
3. 临时自由观察继续把 `expectedPoint` 作为武器控制目标；自由观察只改变相机方向与轨道，目标环始终投影控制目标点，不把控制目标与自由观察方向合并。
4. 第三人称偏置不应用于第一人称、固定炮镜或可转摄像头；这些视点从交接目标建立自身观察状态。
5. 进出座椅、同载具换座、设备视点切换、第一／第三人称切换均保持期望武器目标方向。切入第三人称时按新锚点、参考姿态和偏置反算焦点；切出第三人称时交接解析后的目标点。
6. 固定炮镜画面始终来自真实挂点。切换时只建立期望目标，不覆盖实际机构角；在途转向保持目标并按原执行器转速继续。
7. 可转摄像头切出时继承其目标观察方向，而非尚未追到的实际角。切入摄像头保留既有的目标对齐初始化；目标超出行程时使用设备自身限位结果。
8. 临时自由观察仍只改变相机画面；松开 C 后相机位置与旋转同步平滑回轨道，武器目标点保持不变。

### P4：内容落地和运行验收

1. 审查并显式标注第一方座椅的 `third_person_pitch_bias`；同一批次更新 Builtin 中英文 schema 和 codec 默认值。
2. 运行 `.\gradlew --offline syncSchemas`，生成各内容包的 schema 副本。
3. 运行 `.\gradlew --offline test`、`.\gradlew --offline checkSchemas` 与 `.\gradlew --offline checkContent`，记录实际任务结果。
4. 由用户在 `runClient` 按 G1—G10 进行客户端人工验收，对照高车体／低车体、不同座椅锚点与偏置值，并覆盖视点切换与持续旋转载具。
5. 若默认 15°对低车体或非武器乘员位造成不合适的上仰，按座椅用途调整内容值；不得通过降低鼠标灵敏度或添加输入平滑掩盖偏置问题。

## 9. 风险与限制

- 15°会改变第三人称中性武器控制目标与目标环的垂直位置，但不应改变相机光轴。偏置按座椅配置并允许归零，首轮游戏内标定需覆盖武器用途和乘员用途。
- 切入第三人称时必须在新座椅参考坐标中反算焦点；若俯仰限位使该焦点不可达，目标会受既有限位约束，不得通过瞬间旋转武器机构绕过行程。
- 固定炮镜实际光轴与继承目标可以短暂不一致，这是机构正在转动的直接表现；切换逻辑保留目标，不伪造光轴或改写实际机构角。
- 可转摄像头的期望方向与限速后的实际方向可以不同；切出时交接期望方向，可能使下一视点直接对齐该方向，这是保持操作者目标意图的结果。
- 方块视线裁剪不会检测载具自身渲染模型。相机光轴与轨道的无遮挡必须由座椅配置和游戏内验收共同保证；不能只以单元测试证明。
- 使用有限 1000 米世界点时，逻辑锚点、相机原点和炮口并非同一点，目标环会有小量水平／垂直视差。须记录不同 FOV、`third_person_offset` 与裁剪比例下的容差；不得为了显示对准而改写服务端武器目标。
- 偏置是角度而非固定像素值。目标环的垂直像素位移随 FOV、屏幕尺寸、目标深度和锚点视差变化；验收应以相机局部投影角度为主，并给 GUI 像素测量留出容差。
- 极端俯仰会使相机轨道趋近竖直。轨道方向应从保存的操作者 yaw／pitch 角构造，不从接近垂直的方向向量反解 yaw；允许范围边界必须保持确定且连续。
- 第三人称偏置不自动保证所有模型、所有座位都无遮挡。若特定内容形态仍挡住目标或相机光轴，应调座椅相机锚点或轨道配置，而不是改变目标点或扩大偏置至 20°以上。
