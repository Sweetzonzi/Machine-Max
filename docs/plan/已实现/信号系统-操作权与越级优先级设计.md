# 信号系统-操作权与越级优先级设计

> **状态**：已实现（P1—P4、P6 已交付，P5、P7 为首期之外的可选项）。适用：Minecraft NeoForge 1.21.1 的 `common/mech/signal/` 信号层、座位与武器控制器的输入读取，以及内容包的 `control_groups/` 预设。
>
> 本文定义两件事：**武器站由哪个乘员岗位操作**（归属），以及**多路输入争同一台设备时谁生效**（越级优先级）。归属由频道名承担（§4），争用由三键排序承担（§3）。§1.1 记录促成这次改造的三类缺口，§6 记录各阶段的交付内容，附录 A 是本次替换的施工清单。源码坐标以 Machine-Max 仓库根为基准。

## 1. 问题与目标

### 1.1 三类缺口

**武器站的归属写在预设里，装配时无人校验。** 遥控武器站是独立零件 `m1a2_sep:m153_crows`，可以被装到任何车上；驱动它的控制器有两处来源——M1A2 炮塔上的 `subsystem.m1a2_sep.rws_controller`，以及加装件 `m1a2_sep:m153_crows_terminal` 自带的那一份，两者用同一份型号 `m1a2_sep:rws_controller`（`src/main/resources/spark_modules/Machine-Max_M1A2_SEP/m1a2_sep/subsystems/rws_controller.json#aim_inputs`）。它认哪几条频道是固定的（`crew_commander_aim`、`crew_any_aim`），而座位发不发这些频道由该车自己的预设决定：M1A2 的车长预设发通用那条，所以默认能用；只发 `crew_commander_aim` 的座位走岗位那条；两者都不发的座位装配后武器站既不能瞄准也不能开火，HUD 里也不出现——整条链路没有一处报错。

**车长接管的实现依赖"名次频道 + 按名寻址"，作用域只有同一个 SubPart。** 车长切到超控组时，向 `subsystem.m1a2_sep.main_weapon` 发 `aim_input_p1` / `fire_input_p1`（`.../m1a2_sep/control_groups/m1a2_commander.json#groups`），炮长发 `aim_input_p2`；主炮控制器列表里 `_p1` 排在 `_p2` 前，于是车长压过炮长。名字寻址只在发送者所在 SubPart 的子系统表里解析（`src/main/java/io/github/sweetzonzi/machine_max/common/mech/signal/ISignalSender.java#getReceiversFromNames`），因此这套接管只在车长座与目标控制器处于同一 SubPart 时成立；跨零件、跨子部件时目标解析落空，只在日志留一条错误。

**频道名把"名次"写进了字符串。** 每个接收者的默认输入列表是 `p0`—`p3` 四档加裸名（`src/main/java/io/github/sweetzonzi/machine_max/common/mech/subsystem/attr/static_attr/WeaponControllerSubsystemStaticAttr.java#WeaponControllerSubsystemStaticAttr`、`.../TrackControllerSubsystemStaticAttr.java#TrackControllerSubsystemStaticAttr`），内容包的实际发送方只用到其中两档：`default_driver` 与 `default_commander` 的超控组发 `_p1`，`default_gunner` 发 `_p2`。名次与"谁在操作"混在同一个字符串里，于是**换一档就得改每个接收者的列表**，而列表顺序同时也是读取优先级——两件事共用一个数字位。

### 1.3 目标

1. 频道名只回答"谁在操作、操作哪台设备"。名次只由接收者列表顺序与越级量表达。
2. 同一台设备被两个岗位同时操作时，裁决规则确定、可复现、可在运行期临时提升某一路输入的生效顺序。
3. 默认状态下与当前行为逐位等价：没人使用新能力时，读取结果与"列表里第一个有效信号"完全一致。
4. 不引入需要持久化的新运行期状态，不引入跨座位的定向抑制。

### 1.4 非目标

- 角色频道自动发现并绑定设备（见 §4.5）。
- 跨 SubPart 的名字寻址（属 Part 级名字解析，见 [`信号系统-Part级名字解析与子系统封装`](信号系统-Part级名字解析与子系统封装.md)）。
- 控制组自定义编辑的持久化与入口（见 `docs/plan/进行中/AUI载具控制面板实现计划.md`）。
- 客户端预测与 HUD 上的"控制权"显示。

## 3. 越级优先级

### 3.1 三键排序

读取一个类目的输入时，候选是"接收者声明的该组频道"里的全部有效信号。排序键依次为：

1. **越级量降序**——大于 0 的信号排在任何 0 号信号之前；越级量之间大的在前。
2. **档位降序**——频道在输入列表里的位置越靠前，档位越高。
3. **发送者稳定身份升序**——用 `ISignalSender#compareSenders`（部件 UUID → SubPart 名 → 寻址名），与总线订阅者排序 `#compareBusSubscribers` 共用同一把尺子，保证同键时的结果与哈希顺序无关。

取排序后的第一项。候选集是这批频道的全部有效信号，因此读取要扫完这批频道。

### 3.2 车道不是步数

越级量与档位**不相加**。相加需要三样本文都不接受的东西：

- **一个全局步长常量**。一旦相乘，就得约定"一步是多少"；
- **跨接收者可比**。同一个信号发给 3 条频道的控制器与 5 条频道的控制器，"前进 1 步"的含义不同；
- **两个所有者混算**。档位属于接收者，越级量属于发送者；相加等于让两个来源互相补偿。

按车道排序时，"越级量为 1"在任何一个接收者处的含义都相同：排到所有未越级的输入之前。

### 3.3 Signal 携带越级量

`Signal` 增加一个不可变字段与一个复制出口：

```java
public abstract class Signal<T> {
    public final T value;
    public final int priority;                       // 越级量：0 = 不越级
    public Signal(T value) { this(value, 0); }       // 保留单参构造，现有子类无需改动
    public Signal(T value, int priority) { ... }
    public abstract Signal<T> withPriority(int priority);
}
```

- 各具体信号类实现 `withPriority`，返回类型写成自身类型（协变返回），出口处不必转型；越级量相同则返回 `this`，否则构造同类型副本；
- 会真的构造副本的只有座位出口投递的三个类：`ViewInputSignal`、`MoveInputSignal`、`RegularInputSignal`；`RotationSignal`、`MotorControlSignal`、`WheelControlSignal`、`InteractSignal` 是执行器与交互线，直接返回 `this`；`EmptySignal` 同样返回自身（空信号不参与排序）；
- `SignalChannel` 结构不变，仍是 `ConcurrentHashMap<ISignalSender, Object>`；
- 值类型保持 `Object`：`ControlBinding` 与 GUI 动作投递的是裸 `1.0f`，开火判定按语义接受布尔与非零数值（`isFireSignal`）。读取处的规则统一为"值是 `Signal` 就取它的越级量，否则视作 0"。

越级量只由发送方在自己出口处写入：视图信号由网络包或相机侧构造，座位按频道逐个 `withPriority` 复制后再投递；移动与常规信号由座位自己构造，构造时带上该频道的数。

### 3.4 越级量来自控制组

`ControlGroup` 增加一张按**频道名**取值的稀疏表：

```json
"priorities": { "crew_commander_aim_coax762": 1 }
```

- 键是频道名，值是这条频道的越级量；不在表里的频道为 0，整块可以不写。
- 按频道给而不是按类目给，是因为同一个控制组会同时发出几条性质不同的频道：车长超控并列机枪时 `crew_commander_aim_coax762` 要抬到 1，而同一次输出里的 `crew_any_aim`（给武器站与加装件的广播）不能跟着抬。按类目抬档会把整片频道一起抬，正好抬到不该抬的那条上。
- 值是 ≥ 0 的整数，解码期校验；键必须是这个座位真的会发出的频道，这一条由 `checkContent` 做文件内检查（§7.1 T9），因为解码时看不到基础组。
- 越级量随组生效：切出该组时 `clearInputSignals` 把这一路的槽位写成空信号，读取处自然按未越级处理。

合并：基础组与当前活动子组**按频道键覆盖**——子组声明了这条频道就按子组的值，没声明就继承基础组。与目标表的合并口径相同（`ControlGroupSet#getMergedViewTargets` 一类方法按频道键 `putAll`）。

这条规则让超控组对基础组已有的频道只写数字即可；只在超控时才出现的频道仍要在组内写目标表：

```json
{
    "name": "controlGroup.m1a2_sep.commander_override",
    "priorities": {
        "crew_commander_aim": 1,
        "crew_commander_fire": 1
    },
    "view_targets": { "crew_commander_aim": ["global"] },
    "main_weapon_targets": { "crew_commander_fire": ["global"] }
}
```

`crew_commander_aim` 与 `crew_commander_fire` 都只在备用组与超控组里出现——基础组发的是通用频道的 `crew_any_aim` 与副武器类目的 `crew_commander_secondary_fire`——所以两条都要在组内声明，区别只剩数字：备用组不写（炮长在位就让位），超控组各写一个 1（压过炮长）。判据是：能压过去的写法是给基础组已有的那条加数字；只在某个子组里才存在的频道要在该组内声明目标表。

出口按频道逐个取数，不能一次算好共用；投递也按频道逐个进行，接收者取该频道在合并表里声明的那些目标名：

```java
for (Map.Entry<String, List<String>> entry : controlGroupSet.getMergedViewTargets().entrySet()) {
    ViewInputSignal signal = input.withPriority(controlGroupSet.priorityOf(entry.getKey()));
    for (String targetName : entry.getValue()) {
        sendSignalToTarget(entry.getKey(), targetName, signal);
    }
}
```

首跳表按 base 与全部子组的并集建立，因此只出现在一个组里的频道同样能解析到接收者；基础组与子组把同一频道指向不同接收者时，活动组决定这条频道这一次发给谁。切组时 `clearInputSignals` 按并集把可能发过的频道全部置空，上一组的接收者不会留着旧值。

`priorityOf(channel)` 先查活动子组、再查基础组、都没有就是 0。同一 tick 里同一座位发出的几条频道因此可以带不同的越级量；`withPriority` 在数字相同时返回原实例，不抬档的地方不产生副本。

**裸值不携带越级量。** `ControlBinding` 与 GUI 动作投递的是裸 `1.0f` / `0.0f`（§3.3），没有位置放数字，读取处按 D7 视作 0。需要越级的输入走 `setViewInputSignal` 这类类目出口，不要指望按键绑定。

把越级量放在控制组而不是座位型号，是因为座位型号是共享成品件：M1A2 的车长、炮长、装填手用的是同一个 `machine_max:default_3rd_seat`，MTLB 车长也用同一个型号，任何写在型号上的等级对这三个岗位都相同，无法区分。

**档位表达默认归属，越级量表达临时抢占。** 接收者的候选集是它列表里全部频道的有效信号，"谁平时说了算"由列表顺序给出（默认操作者在前，§4.4）；越级量把某条频道的一次输出插到整个候选集的最前，因此它跨频道生效——车长超控并列机枪时 `crew_commander_aim_coax762` 带 1，就压过了列表里排在它前面的 `crew_gunner_aim_coax762`。M1A2 车长的超控组与 T-90A 车长的超控组就是它的出厂用例。

### 3.5 车道不能与档位交错

越级量大于 0 的信号压过所有未越级信号，无法表达"高于某一档但低于另一档"。这是刻意的边界：允许交错后，作者必须同时推理对方列表长度与自己的数字，等于把档位与越级量重新混算。需要更细的次序时，正确做法是加一条档位（新频道），而不是调数字。

### 3.6 默认等价

决定 D1—D3 在全部越级量为 0 时退化为"按档位降序取第一个有效信号"，与当前的两处读取点一致。这条是回归契约：P2 与 P4 落地后，现有全部用例的读数必须逐位不变，可用 `ViewpointGameTest` 的瞄准用例直接对拍。

### 3.7 可选优化：两段式读取

读取点不能以"遇到第一个有效信号"作为停止条件：列表里排在后面的频道可能带着更大的越级量——车长的 `crew_commander_aim_coax762` 排在炮长那条之后，超控时带 1。两段式读取可以保住快路径：

1. 先看这批频道里有没有越级信号（每频道一次整数读，不遍历槽位）；
2. 没有 → 按档位顺序扫描，命中即停；
3. 有 → 全扫并按三键排序。

第 1 步需要一个按频道缓存的"最大越级量"，维护点是 `SignalChannel` 的写入、移除与清空，以及 `SignalPort` 直接写接收者频道的那一处。这条优化不列入 P1—P7：每条频道只有一到两个发送者，全扫每 tick 只有几十次查表，先以代码直白为准；缓存作为后续可选项，前提是保留 §3.6 的对拍。

## 4. 操作权归属：岗位频道、设备频道与接线

### 4.1 命名文法

**频道名一律用下划线分隔。** 点号属于寻址名——`subsystem.<命名空间>.<名字>`、`weapon.<类别>.<型号>`、`interact.<命名空间>.<名字>`——它不是频道的分隔符；`global` 与 `local` 是保留地址，同样不属于频道。

```
crew_<role>_<category>                岗位频道
crew_<role>_<category>_<device>       设备频道
crew_<role>_reload                    能力发现频道（§4.7）
```

| 段 | 取值 | 说明 |
|---|---|---|
| `role` | `driver` / `commander` / `gunner` / `loader` / `any` | 岗位词；`any` 表示"任何乘员"，只在岗位频道里出现，是接收者列表里最低的一档 |
| `category` | `aim` / `fire` / `secondary_fire` / `move` / `regular` | 与控制组的输出类目一一对应（`view_targets` 对 `aim`、`main_weapon_targets` 对 `fire`、`secondary_weapon_targets` 对 `secondary_fire`） |
| `device` | `main_gun` / `coax762` / `csamm` / `rws` / `citv` / `aa` / `port_mg` / `aft_mg` / `atgm` | 设备词，由内容按设备种类取名 |

三段与四段的区别是"目标定不定"：三段是岗位频道，接收者由装配决定；四段点名一台已知设备（§4.2）。四段都是普通字符串，没有注册表、没有校验、没有语法树。引擎只把它们当频道名比较；词表存在的意义是让预设与控制器两侧写到同一批字符串上。`role` 与 `category` 也不参与任何计算：读取点按自己的字段（`aim_inputs` / `fire_inputs` / `control_inputs`）取用，不解析名字。

为什么是下划线而不是点号：

- **语料一致**：内容包现有的频道名全部是下划线（约一百个），点号族只有装填发现频道一处，已并入本文法。换成点号要重写全部频道、接收者列表、schema 默认值与 wiki，功能上没有一分收益。
- **与寻址名分家**：点号在本仓库表示"会被解析的名字"——`subsystem.<命名空间>.<名字>`、`interact.<命名空间>.<名字>`、`weapon.<类别>.<型号>`；`HitBox#label` 还按最后一个点截段显示。频道从不解析（`getReceiversFromNames` 只做整串 `Map` 查找）。让频道不含点号，读到一个带点的字符串就能断定它是地址而不是频道。
- **嵌进表达式更安全**：MoLang 以 `local.get('<频道名>')` / `global.get('<频道名>')` 取频道值，AUI 文档与 Blockbench 插件也会把频道名写进 JSON 与模板；点号在这些场合是属性访问分隔符，下划线不与任何表达式语法相撞。

### 4.2 三种定位手段

| 手段 | 目标怎么定 | 服务对象 |
|---|---|---|
| 岗位频道 `crew_<role>_<cat>` | 频道名相同即命中，装配体内每台声明它的设备都收 | 岗位的主武器、玩家加装的武器、整车唯一的行驶与常规链 |
| 设备频道 `crew_<role>_<cat>_<device>` | 点名一台已知设备 | 同一岗位的第二台及以后设备 |
| 连接点接线 `signal_targets` | 在连接点上把某条频道点名到某个接收者（`src/main/resources/spark_modules/Machine-Max_Civilian/machine_max/parts/van/van_chassis.json#signal_targets`） | 同型多台要分开，或一次性把某条线接到某台设备 |

判据是**作者在装配时知不知道这台设备**：

- **不知道**——玩家经连接点加装的武器。它只能靠岗位频道，因为装到哪台车、旁边坐着谁都是运行期才知道的。`m153_crows_terminal` 零件上的控制器因此靠瞄准的 `crew_any_aim`、`crew_commander_aim` 与副武器开火的 `crew_any_secondary_fire` 工作。
- **知道**——本车自带的武器。岗位的主武器用岗位频道：它是这个岗位唯一的那台，而且通用预设（`default_gunner`）只可能发得出岗位频道。同一岗位的额外设备（并列机枪、C-SAMM、CITV、舱盖机枪、尾部机枪、高射机枪、反坦克导弹）用设备频道，一台一条。
- **知道但要分开同型两台**——连接点接线把频道点名到其中一台，或者作者另起一个设备词。

所以座位同时发两类：岗位频道给主武器与加装件，设备频道给本岗位的额外设备。同一台额外设备允许两个座位各有一条设备频道（`crew_commander_aim_coax762` 与 `crew_gunner_aim_coax762`），默认操作者的那条排在接收者列表前面。

M1A2 三种手段都用上：主炮走岗位频道（`crew_gunner_aim` / `crew_commander_aim`），并列机枪、C-SAMM、CITV 走设备频道，武器站走通用频道（`crew_any_aim` / `crew_any_secondary_fire`），车长的默认组只发通用频道那条；主炮的岗位频道只在备用组与超控组里发。MTLB 的车长同时有 PKT 与可加装的武器站，因此它需要一份自己的车长预设（§4.3）。

每行的先后是刻意选的：**默认操作者排第一，接管方第二**。炮长在位就由炮长控制主炮；车长要压过，靠超控组的越级量，不靠档位。主炮没有第三档兜底——`crew_any_aim` 不在它的列表里，因此任何座位都不能凭通用频道把炮塔带走。

写进 `fire_inputs` 同时获得两件事：广播可按频道筛到它（`getAcceptedChannels`），座位发现也能解析到它（`resolveWeaponControllersForGroup`）。反过来说，一台控制器能不能开火由宿主的预设决定：MTLB 的 PKT 机枪塔（`src/main/resources/spark_modules/Machine-Max_MTLB/machine_max/parts/pkt_turret.json`）用 `machine_max:main_weapon_controller`，它在基础组能不能开火取决于宿主预设是否发出主武器类目——`machine_max:mtlb_commander` 声明了 `crew_commander_fire`（§4.3），换成只发副武器类目的预设时那台机枪塔就只剩瞄准。

### 4.5 广播边界与默认归属

岗位频道是广播：装配体内每台声明它的设备都会收到。由此有两条规则。

**一、默认归属写在接收者列表里。** 车长与炮长都能操作主炮时，列表是 `crew_gunner_aim` → `crew_commander_aim` → `crew_any_aim`：炮长在座位上就由炮长控制；炮长不在而车长切进了超控组，炮长的槽位是空信号被过滤掉，车长那条生效。车长官大，列表里却排在后面——档位表达的是"平时谁说了算"。

**二、临时抢占靠越级量。** 车长切进超控组时，`crew_commander_aim` 带 1 发出，压过列表里排在它前面的炮长那条（§3.4）；切出超控组，这条频道上没有信号，炮长立刻恢复。超控因此不需要第三条频道。

岗位频道是广播，会带动同一岗位上所有接受它的设备。要把车长的默认操作只落在武器站上，就让默认组走通用频道、把主炮的岗位频道留到备用与超控：主炮不接 `crew_any_aim`，车长的默认组只发它，于是默认状态下车长看着哪里，转的只是武器站；切进备用或超控组，主炮才跟着走。

开火这一侧靠类目分开，不靠频道分开：所有机枪（武器站、并列机枪、舱盖机枪、尾部机枪）都走副武器类目，主炮走主武器类目（`crew_<岗位>_fire`，只在车长的备用火控组与超控组里发出）。因此车长按副武器键打的是一排机枪，按主武器键才是主炮，两个按键之间没有耦合。

频道名无法表达"这台设备不接受该岗位"，引擎也没有按车型改写接收者列表的机制；同型多台要分开，只能靠连接点接线或运行期自定义控制组（§1.4）。

### 4.6 不受本文约束的频道

`interact`、`weapon_control`、`aim_drive_*`、`car_control`、`diff_lock_control` 等是子系统之间、连接点与控制器之间的内部线，不承载乘员意图，命名与读取方式保持原样。

### 4.7 装填能力发现频道

装填需求方与座位之间还有一条同族频道：座位在 `loader_discovery_inputs` 里声明自己能被哪些需求方发现（`src/main/resources/spark_modules/Machine-Max_M1A2_SEP/m1a2_sep/parts/m1a2_turret.json` 的 `crew_loader_reload`、`crew_gunner_reload`、`crew_commander_reload`），装弹机与发射器在 `loader_discovery_targets` 里写同一批名字。它是发现用的键，不是信号频道，但同在 `crew_` 前缀下，因此沿用同一条下划线文法与角色词表。

## 5. 已评估并放弃的做法

| 做法 | 结论 | 理由 |
|---|---|---|
| 保留 `_p0`—`_p3` 名次频道 | 不做 | 名次与岗位挤在同一个字符串里，换一档要改每个接收者的列表；列表顺序已经能表达先后，越级量能表达临时插队（§4.1、§3.4） |
| 保留裸名 `aim_input` 等 | 不做 | 与 `crew_any_aim` 表达同一件事，词表里留两套写法等于两套规则（D9） |
| 频道名用点号分层（`crew.commander.aim`） | 不做 | 点号在本仓库是寻址名（`subsystem.<命名空间>.<名字>`）的分隔符，与频道混用后两类字符串只能靠上下文分辨；频道一律下划线（§4.1） |
| 频道别名与兼容读取 | 不做 | 新旧两名同时可用会让"漏改"表现为静默失效；仓库内发送方与接收方同批改齐，没有外部兼容负担（D16） |
| 一条频道承载所有站位、常态归属也靠越级量 | 不做 | 默认归属会从接收者列表挪进每个预设的数字里，读接收者看不出谁平时说了算，改机型就得改数字。每站位一条频道 + 默认操作者在前，让"平时谁说了算"与"此刻谁在抢"分开表达（D14、D19） |
| 座位抑制（给座位发抑制频道、目标席自行静音） | 不做 | 需要跨座位定向寻址，而名字寻址只在同一 SubPart 内解析；还要一套"谁释放、何时释放"的状态与同步。越级优先级用"同一批频道 + 更高的车道"达到同样效果，且不留状态 |
| 座位转发（发起席发频道、目标席用它自己的控制组重发） | 不做 | 结果依赖目标席当前的控制组，等于把对方的 UI 状态变成我的输入语义；同时改变开火归属（发送者变成目标席），还要防转发环路 |
| 构建期报错：禁止两个座位声明同一频道 | 不做 | 玩家可以自由装配两个座位，静态检查管不到运行期；同一频道多发送者在三键排序下已有确定语义（§3.1 第二、三键） |
| 座位型号上的权威等级（`authority`） | 不做 | 座位型号是共享成品件，车长与炮长拿到的是同一个数字（§3.4 末）；把等级挪到安装或预设上，就与"选哪条频道、排第几档"重复表达同一件事，制造两个真值源 |
| 全局频道优先级表 | 不做 | 同一对频道在不同接收者处可能需要相反次序（战机前后座：飞行以飞行员为先、武器以武器操作员为先）；优先级必须留在接收者本地 |
| 越级量相加式（"前进 N 步"） | 不做 | 需要全局步长、跨接收者不可比、两个所有者混算（§3.2） |

## 8. 风险与未决

1. **跨 SubPart 名字寻址**由 Part 级名字解析覆盖：`getReceiversFromNames` 的输入表由发送者所属整个 Part 聚合，跨子零件的具名目标可达，名字在 Part 内唯一由解码期校验保证（见 [`信号系统-Part级名字解析与子系统封装`](信号系统-Part级名字解析与子系统封装.md)）。本文的设计不依赖按名寻址：岗位频道与设备频道都用 `global` 广播，越级用"写同一批频道"，因此跨零件接管可行；按名寻址仍适用于不关心线路走向的直连场合。
2. **其它读取点**（驾驶、引擎、变速箱、履带驱动的"第一个有效信号"循环）不接入 P2—P4，越级量对它们无效。P1 落地后这些频道是岗位名，先后仍只由列表顺序给出。这是有意为之的增量边界，写进 AGENTS.md 以免误用。
3. **广播耦合**（§4.5）：岗位频道会同时命中装配体内所有声明它的设备。出厂配置避开了这个组合，玩家自由加装时可能遇到。
4. **设备频道数量随组合增长**：每台按角色拆分的设备最多需要"角色数 × 2"条频道。当前只拆了 6 台（并列机枪、C-SAMM、武器站、CITV、舱盖机枪、高射机枪），且只有一车一用的控制器才需要拆。
5. **`SignalPort` 直接写接收者频道**（转发时 `put`），值对象自带越级量，因此转发后仍保留；若 §3.7 的缓存落地，这一处必须同步维护。
6. **协议**：控制组经 `ControlGroupSetEditPayload` 传输，`ControlGroup.STREAM_CODEC` 是手写编解码，加字段要两端同批合入并核对协议号；`control_group_set` 不参与 NBT 载入，重登后以预设为准。
7. **schema 同步**：驾驶控制器的 `control_inputs` 默认列表与 `sub_part_attr`、`signal_targets` 的示例跟着改了；改 builtin 后跑 `./gradlew syncSchemas` 生成其余包副本与技能快照（本次已跑，副本与清单在同一提交里）。
8. **未接入的读者造成的不一致**：同一个座位对武器可越级、对驾驶不可越级，需要在文档中明确，不写成"统一生效"。
9. **`SignalPort` 没有优先级字段**：它的字段是名称、所属连接点、目标表、转译表与输入频道表，转发按目标表迭代顺序进行；跨连接点的"谁先"由越级量随信号转发保留，不由端口排序。`common/mech/signal/AGENTS.md` 已按这一点改写。
