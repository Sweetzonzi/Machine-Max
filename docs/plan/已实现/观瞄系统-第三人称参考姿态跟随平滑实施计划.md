# 观瞄系统：第三人称参考姿态跟随平滑实施计划

**状态**：代码、自动化验证与客户端验收均已完成。逻辑焦点和武器目标即时更新，第三人称显示相机朝向独立追赶焦点，因此目标环会按实际相机矩阵产生偏移。`FOLLOW_SECONDS = 0.05` 秒为客户端调教确认值。

日期：2026-11-22。

本文为独立实施计划，限定第三人称座椅观察中逻辑焦点与实际相机朝向的解耦跟随。源码路径以 Machine-Max 仓库根为基准。

## 1. 目标与范围

第三人称下，未偏置焦点 `F` 与武器目标 `P` 按当前观察输入和座椅参考即时更新；实际相机朝向则以无超调的一阶指数响应追赶指向 `F` 的期望朝向。焦点不经过位置阻尼，因而目标环会因相机朝向滞后而暂时偏离屏幕中心；俯仰偏置还会叠加其固有投影偏移。

本计划的对象是期望观察朝向 `Q_focus` 到实际显示朝向 `Q_view` 的一阶响应。逻辑焦点 `F` 与武器目标 `P` 保持在即时逻辑链上；显示相机独立追赶 `Q_focus`，不改写 `F`／`P`。相机位置沿 `Q_view` 的轨道几何生成，HUD 圆环按 `P` 相对实际相机的真实投影绘制。相机不转向带偏置目标 `P`。

范围之外：

- 鼠标 delta 的平滑、加速度曲线、输入滤波和第三人称最大角速度限制。
- 可转摄像机子系统自己的轴行程、目标角速度限制及稳定轴控制。
- 第一人称、固定炮镜和武器机构的实际角度控制。
- 相机位置惯性、碰撞／落地冲击、投射物抖屏与震动偏移合成。
- 网络协议、座椅 JSON、服务端武器执行器和客户端选项界面。

## 2. 当前实现基线

### 2.1 修订前的参考姿态低通

`client/input/CameraController.java` 原先定义 `FOLLOW_SECONDS = 0.12` 秒，并把 `RotationDamper` 用于座椅参考姿态。该结果同时进入逻辑焦点生成和相机显示朝向，因此焦点与相机一起滞后；相机仍直接朝向当前焦点，二者之间没有可见的追赶误差。`follow_vehicle=false` 时焦点保持世界坐标，`ViewMath.lookAt` 每帧直接重算看向焦点的朝向，也不会得到相机朝向滞后。

`RotationDamper.advance` 的单步系数为：

```text
alpha = 1 - exp(-clamp(dt, 0, 0.25) / tau)
Q_follow = slerp(Q_follow_previous, Q_mount, alpha)
```

该数学形式保留为通用工具，但阻尼目标改为期望观察朝向，输出为显示朝向 `Q_view`。`tau` 是固定目标下角度残差衰减到 `1/e` 的时间，不是每 tick 固定混合比例，也不是角速度上限。

### 2.2 主线程与渲染采样

普通座椅观察的 tick 路径先用当前挂点与操作者相对角更新 `F`／`P`，再以期望观察朝向推进显示朝向阻尼器。鼠标事件直接更新逻辑观察角和目标，不经过输入滤波；显示相机因追赶逻辑目标而产生延迟。

渲染阶段以 `partialTick` 插值显示朝向阻尼器最近两次推进结果，不推进其状态。普通第三人称的本帧焦点样本用于解析 HUD 目标 `P`，显示相机则使用独立的 `Q_view`；渲染不得将相机追赶结果写回 `F`、`P` 或控制上报用的 `expectedPoint`。因此目标环偏离中心线反映真实的相机朝向滞后与目标偏置，而非逻辑目标被平滑。

### 2.3 相邻但独立的平滑

- `ThirdPersonViewpoint.sampleDisplayRotation` 只处理临时自由观察退出后的 0.2 秒显示回正；自由观察期间绕过正常焦点追赶，回正结束后重置显示朝向阻尼状态，避免两层平滑叠加。
- `CameraSubsystem` 使用设备自身的角度、限位和可达转速路径；其机械角速度语义不是第三人称相机跟随参数。
- `CameraShakeController` 的投射物冲击通过独立弹簧生成显示旋转／位移偏移，在相机观察位姿求出之后合成。`vehicleChaseDamper` 有定义但当前生产代码未找到调用点；本计划不把它当成正在运行的第三人称旋转跟随。
- `src/test/java/io/github/sweetzonzi/machine_max/util/RotationDamperTest.java` 已覆盖固定目标下的指数衰减、等时长分步一致性、长间隔裁剪、刻内插值、只读采样与 reset。后续测试在这组判据上补边界，而非复制第二套阻尼器。

## 3. 行为契约

1. 第三人称逻辑焦点 `F` 与武器目标 `P` 按当前挂点／输入即时更新；实际相机朝向使用独立的一阶旋转低通追赶 `F`，不反向改写逻辑目标。
2. 鼠标角增量直接进入相对观察角并即时更新期望焦点；相机显示朝向对该期望方向的可见响应由相机跟随时间常数决定，不再宣称屏幕视角即时跟手。
3. 显示朝向阻尼使用主线程 tick 推进，渲染读取最近两个 tick 的插值样本。重复渲染采样不得增加阻尼推进次数，也不得改写 `F`／`P`。
4. HUD 目标环按 `P` 对实际相机位姿投影。相机追赶期间目标环相对画面中心偏移是预期行为；俯仰偏置的垂直偏移继续独立保留。
5. 相机朝向采用单调一阶响应，不出现超过当前期望朝向的超调、振铃或回弹；它不限制持续转动的最大角速度。
6. 当前 `FOLLOW_SECONDS` 为 0.05 秒，最终取值由同一客户端场景的画面与控制验收确定；首轮比较 0.05、0.08、0.12、0.16 秒，以及无低通基线。
7. 首轮不提供内容包字段、网络字段或玩家设置项。第三人称跟随时常量统一使用，不按座位或载具重定义。
8. 进入／重建第三人称座椅观察时，以当前显示／期望朝向建立阻尼状态；不同世界、离座和相机来源切换不能继承过期滞后。第一人称与设备视点不读取该阻尼。

## 4. 方案取舍

### 4.1 保留一阶指数旋转低通

`RotationDamper` 与本需求匹配：期望观察朝向作为输入，显示朝向渐近靠近目标；响应由时间常数决定，对固定目标的时间步长划分不敏感；没有振铃，状态只需前后两份四元数。

代价是存在相位滞后。`F`／`P` 仍即时更新，而画面相机追赶 `F`，所以目标环会暂时离开画面中心；这是目标效果，不是逻辑目标或 HUD 投影错误。鼠标输入本身不做预处理滤波，但其改变焦点后的屏幕朝向同样由显示相机追赶。

### 4.2 不把二阶弹簧用于正常跟随

二阶响应需要额外速度状态，可能超调或振铃，连续旋转、重新进入座位、暂停恢复时也需处理速度状态重置。冲击弹簧适合表达瞬时碰撞输入；正常的第三人称基座跟随没有冲量输入，也没有要求越过目标后回摆的表现目标。若日后希望摄影机出现电影化超调，应作为镜头动态／震动设计单独评估，不混入本跟随低通。

### 4.3 不平滑鼠标 delta

对鼠标样本做独立指数或二阶滤波，会令逻辑目标依赖采样时长与输入历史。本计划保留直接角增量和即时 `F`／`P`，只平滑显示朝向；因此操作者控制目标仍即时改变，但屏幕中心会短暂落后。

## 5. 时序、状态与视角边界

| 路径 | 逻辑焦点／目标来源 | 实际相机朝向来源 |
| --- | --- | --- |
| 第三人称座椅观察 | 当前挂点与相对观察角即时生成 `F`／`P` | `RotationDamper.sample(partialTick)` 平滑追赶指向 `F` 的期望姿态；相机轨道沿实际显示朝向生成，HUD 环按实际相机投影而偏移 |
| 第三人称临时自由观察 | 自由观察状态独立保存世界焦点 | 自由观察期间不受焦点追赶滤波影响；座椅逻辑目标不被临时方向改写 |
| 自由观察退出回正 | 正常座椅观察的即时逻辑焦点 | 保留单独的 0.2 秒显示回正；回正结束后从期望姿态重置正常跟随状态，不叠加两层滤波 |
| 第一人称座椅 | 当前挂点与相对观察角 | 直接使用当前逻辑观察姿态，不经过第三人称显示阻尼 |
| 可转摄像机设备 | 设备实际可达姿态采样 | 保留设备行程与转速限制；不读取第三人称显示阻尼 |
| 固定炮镜 | 实际光轴／机构姿态 | 不更改真实光轴与武器期望目标的职责 |
| 相机冲击显示 | `CameraShakeController` 输出 | 仍在最终显示合成层工作，不回写逻辑焦点、武器目标或显示阻尼 |

离座、换载具、世界切换与失效视点释放时不得复用过期显示残差。换座或从设备视点回到座椅时，先保存继承的武器目标 `P`，按新座椅参考与偏置把 `P` 反算为未偏置焦点 `F`，再以新视点的期望朝向重置显示阻尼；之后才开始追赶。第一人称不应用第三人称偏置，固定炮镜和可转摄像机也不读取该阻尼。

## 6. 实施阶段

### P0：基线与时序确认

1. 核对 `CameraController.tick`、座椅逻辑更新、显示朝向推进与 `updateCameraRot` 的真实调用顺序，确认逻辑目标与渲染采样各自只读／写入边界。
2. 逐项确认 `FOLLOW_SECONDS`、最大单步时间、显示朝向 reset 触发点、第一人称 bypass、相机设备路径和临时观察回正路径。
3. 建立固定场景：静止底盘鼠标操作、底盘匀速偏航、快速反向偏航、侧倾与俯仰组合、座位切换。
4. 记录当前 0.05 秒参数下的焦点角度、实际相机朝向误差、鼠标角增量和屏幕目标环偏移。可用临时调试读数，不建立通用遥测子系统。

### P1：数学与输入隔离判据

1. 保持 `RotationDamper` 单一实现，复核指数公式、四元数单位化与最短弧插值约定。
2. 扩展 `RotationDamperTest` 覆盖角度跨越 ±180°、四元数双覆盖 `q`／`-q`、非零 yaw／pitch／roll 组合、零时间步与单调时钟异常值。
3. 在 `ThirdPersonViewpointTest` 或现有纯逻辑测试中验证挂点转动／输入角增量立即改变逻辑焦点／期望朝向；相机显示阻尼不能回写或拖慢逻辑目标。
4. 覆盖 `sample(partialTick)` 重复读取不推进 `previous/current`，以及显示样本与逻辑 `expectedPoint` 相互独立。
5. 验证目标已转向新焦点而相机仍处于追赶过程时，目标方向相对显示相机产生非零投影偏移。

### P2：控制器边界复核

1. 第三人称逻辑焦点和武器目标从当前挂点／观察输入生成；独立的 `Q_view` 从期望焦点方向推进，不得让 `Q_view` 反向参与 `F`／`P` 计算。
2. 相机显示位姿与轨道位置共同使用 `Q_view`；HUD 目标环按本帧相机矩阵真实投影，允许因追赶误差离开屏幕中心。
3. 修改 `CameraController` 的推进顺序与模式边界，并用纯逻辑测试锁定隔离契约。
4. 不抽取新的泛化滤波框架，不改 `SpringDamper`、`CameraShakeController` 或可转摄像机机械限速。

### P3：生命周期与模式隔离

1. 验证进入座位、同车换座、换车、第一／第三人称切换、进入／退出设备视点与离开世界的显示阻尼 reset 时机。
2. 验证自由观察期间绕过正常显示阻尼；退出回正使用独立 0.2 秒过渡，结束时无双重平滑或跳变。
3. 验证第一人称、固定炮镜与可转摄像机没有第三人称焦点朝向阻尼造成的延迟。
4. 验证底盘转动与投射物冲击同时发生时，冲击只改变最终显示偏移，不污染 `expectedPoint` 或显示阻尼状态。

### P4：客户端手感标定

1. 使用同一载具、相同路径和输入，在 `tau = 0.05 / 0.08 / 0.12 / 0.16` 秒下比较，并用原始挂点姿态作为零平滑对照。
2. 覆盖低速连续转向、急转急停、反向修正、侧倾、自由观察及大车体目标居中；判断滞后是否足够轻、鼠标是否仍即时。
3. 由用户在 `runClient` 完成画面与控制验收。记录客户端版本、场景、帧率范围、参数值和每个判据结果。
4. 首轮结束固定一个 `FOLLOW_SECONDS` 值；只有用户明确需要个性化平滑设置时，另立客户端设置方案。

## 7. 自动化判据

自动化覆盖纯数学与可重复的状态契约；视角路由是否符合玩家实际观感、镜头震动组合和不同座位的体验由 §8 的客户端人工验收确认，不要求把完整 Minecraft 渲染流程改造成自动测试。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A1 | 固定目标，经过 `dt = tau` | 相对目标姿态的角残差为初始残差的 `e^-1`，允许浮点容差 |
| A2 | 同一固定目标与总经过时间，单步和多步推进 | 最终姿态一致；结果只取决于经过时间 |
| A3 | 目标横跨 ±180° 或使用 `q` 与 `-q` 表示同一姿态 | 沿最短四元数弧连续逼近，不绕远路翻转 |
| A4 | yaw、pitch、roll 同时非零并连续改变 | 姿态有限且归一；滤波结果不引入欧拉角分轴错误 |
| A5 | `partialTick` 为 0、0.5、1，并重复采样 | 样本位于两次推进姿态之间，采样前后阻尼内部状态相同 |
| A6 | 零 elapsed、超过 0.25 秒的推进间隔、显式 reset | 零步不改变姿态；大间隔遵守上限；reset 后前后样本均等于目标 |
| A7 | 相同座椅参考下应用鼠标俯仰／偏航增量 | 逻辑相对角与 `F`／`P` 即时更新；显示相机样本可滞后但不改写逻辑目标 |
| A8 | 对显示阻尼重复渲染采样并读取同一逻辑 tick 目标 | 渲染次数不推进滤波；`F`／`P`／`expectedPoint` 不被显示朝向改写 |
| A9 | 焦点从旧方向切到新方向，阻尼器只推进一个短时间步 | `F` 已在新方向；显示朝向仍位于追赶途中；将 `F` 投影到显示相机时得到非零角偏移 |

| G3 | 急转后急停与反向转向 | 相机朝向单调追赶期望焦点，不自行回摆；`F`／`P` 立即反向更新 |

## 10. 风险与限制

- 一阶低通消除不了显示朝向滞后；载具角速度与操作者快速转向都会使目标环短暂偏离中心。验收须覆盖急转急停与反向输入。
- `F`／`P` 即时更新而相机显示朝向滞后，因此相机中心不再等于逻辑目标。服务器仍按上报的 `P` 控制武器，不能将显示偏移误认为武器目标被阻尼。
- 当前滤波只作用于显示朝向；第三人称轨道位置按同一个显示朝向绕相机枢轴重算，因此相机绕枢轴随之移动，但不另行平滑焦点位置或引入相机平移惯性。
- 焦点与目标环投影必须分别使用即时逻辑目标和实际显示相机矩阵；俯仰偏置与朝向追赶误差是两类可叠加的偏移，不能把渲染相机姿态反馈至 `F`／`P`。
- 一阶滤波与设备最大转速限制语义不同。不得用调低 `tau`、增加角度步长上限或借用设备限速来代替对实际参考响应的判断。
- Minecraft 暂停、卡顿和 tick 时间突变会影响单次滤波步长；0.25 秒裁剪需保留并在恢复场景验证。
- `CameraShakeController` 中的载具位置追赶接口当前没有生产调用点。本计划不借它实现旋转跟随；若后续接通位置惯性，应单独检查与本计划的相机焦点几何是否一致。
