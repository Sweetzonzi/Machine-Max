    5.4 连接点定义¶

    连接点是零件之间进行物理连接、信号传递和机械能传输的核心机制。每个连接点由两部分属性共同决定其行为：静态属性（通过 connectors/ 模块预先定义并可被多个零件复用）和动态属性（直接在零件 JSON 的子零件 connectors 字段中内联配置）。本章面向 UGC 作者，逐字段解释两部分的完整结构。

    如果说命中箱和材料决定的是“这一块会不会被打穿、会掉多少耐久”，那么连接点决定的就是“它还能不能继续挂在原来的位置上”。这一点和第四章中的 4.4 伤害系统 是直接对应的：部件受击后，系统并不会只扣本体耐久，还会把一部分冲击按距离分配给附近连接点。连接点随后再用自己的 integrity、impact_reduction、impact_multiplier 和 impact_absorption 去决定这次冲击是被吃掉、被削弱，还是直接把零件打到脱落。

    若把某次命中产生的总冲击记为 $I$，分配到第 $i$ 个连接点的原始冲击记为 $I_i$，则在第四章中已经近似写成

    $$ I_i = I \cdot \eta_i $$

    其中 $\eta_i$ 来自按距离归一化后的权重。进入连接点自身结算后，还会再经过

    $$ I_i' = \max(0, I_i - R)\cdot M $$

    其中 $R$ 对应 impact_reduction，$M$ 对应 impact_multiplier。若修正后的冲击超过连接点当前剩余结构完整性 $C_i$，则可以近似理解为

    $$ I_i' \ge C_i \quad \Rightarrow \quad \text{断开} $$

    因此，连接点定义并不是一组只影响“装配能不能拼上”的静态元数据，而是在实战、碰撞和部件断裂中持续参与结算的结构参数。

    在阅读本章之前，建议先完成：

    • 5.3 零件定义中关于子零件结构、Locator、标签等内容的理解；
    • 模型文件中连接点 Locator 的放置（确保模型中有对应的定位器，参照 5.2 模型与动画 中的命名规范）。
    • 4.4 伤害系统 中关于连接点冲击、结构完整性和断开机制的部分。

    静态属性（connectors/ 模块）¶

    静态属性定义连接点的物理参数和匹配规则，存放在内容包的 connectors/ 模块目录下。多个零件可以通过 definition 字段引用同一个静态定义，避免重复配置。

    从职责上看，静态属性更像“这种连接接口本身是什么东西”。例如它更像是一种厚重铰链、轻型挂耳、柔性的橡胶安装座，还是一组只负责信号与动力转接的内部结构。只要这种“接口物理性格”在多个零件上都成立，就值得单独抽成静态定义复用。

    文件位置¶

    连接点静态定义 JSON 放在内容包对应的命名空间目录下：

    spark_modules/
└── my_pack/
    └── my_mod/
        └── connectors/
            ├── simple_connector.json
            └── advanced_hinge.json

    每个文件名（不含扩展名）即为该连接点定义的内部 ID。模组加载时，以 命名空间:文件名 的格式注册（如 my_mod:simple_connector），后续在零件 JSON 中通过 definition 字段以此格式引用。

    connectors/ 目录下的 JSON 文件可以任意嵌套子文件夹来组织（如 connectors/advanced/hinges/door_hinge.json），但注册名仅取文件名（不含扩展名和路径），即 my_mod:door_hinge。嵌套路径仅用于作者自行分类，不影响注册结果。

    如果一个连接点定义会被门铰链、炮塔座圈、轮组安装座、挂载支架等多处复用，建议尽早按用途分目录整理。虽然注册名不包含路径，但良好的目录结构仍然会显著降低后续维护成本。

    顶层字段¶

    字段 类型 必需 默认值 说明
    $schema 字符串 否 — JSON Schema 引用路径，供编辑器提供智能提示和校验。建议保留
    type 字符串 是 — 连接点类型。可选值："Simple"（简单连接点）、"Advanced"（高级连接点，支持关节属性）。大小写不敏感
    direction 字符串 否 "yp" 连接点的法线方向，指向被连接零件一侧。可选值：xp、xn、yp、yn、zp、zn
    integrity 浮点数 否 20.0 连接点结构完整度。连接点可承受不超过此数值的冲击力而不脱落（冲击力来自伤害或关节应力）
    impact_absorption 浮点数 否 0.2 冲击转化率（0\~1）。当连接点受到冲击但未断开时，冲击按此比例转化为结构完整度的损耗。例如 0.2 表示 20% 的冲击转为损耗
    impact_reduction 浮点数 否 2.0 冲击减免值。在判定是否击落前，先将冲击力减去此值。可将冲击削减至 0 以完全避免对结构完整度的影响
    impact_multiplier 浮点数 否 1.5 冲击倍率。在减免之后、判定击落之前，将冲击力乘以此值。大于 1 使连接点更容易断开，小于 1 使连接点更坚固。内部连接点恒定不可破坏，不受此值影响
    collide_between_parts 布尔值 否 false 是否允许通过此连接点连接的两个零件之间产生物理碰撞。通常设为 false 以避免穿透问题。仅在关闭了全局零件碰撞选项时需要考虑设置
    required_tags 资源路径数组 否 [] 必需标签列表。对侧零件必须全部拥有这些标签才能连接。留空则不检查
    acceptable_tags 资源路径数组 否 [] 可接受标签列表。对侧零件必须至少拥有其中一个才能连接。留空则不检查
    forbidden_tags 资源路径数组 否 [] 禁止标签列表。对侧零件不得包含其中任何一个才能连接。留空则不检查
    joint_attrs 对象 否 {} 关节属性。仅在 type 为 "Advanced" 时生效。详见下文

    标签匹配是三层优先级过滤：required_tags（全部满足）→ acceptable_tags（至少一个满足）→ forbidden_tags（全部不满足）。三层必须同时通过才算匹配成功。三层均留空时任意零件均可连接。

    从第四章的角度看，这些字段其实可以分成三组：

    • 结构强度：integrity、impact_absorption、impact_reduction、impact_multiplier
    • 装配匹配：required_tags、acceptable_tags、forbidden_tags
    • 物理行为：type、direction、collide_between_parts、joint_attrs

    其中最值得内容包作者单独理解的是第一组，因为它们直接决定“被打以后会不会散架”。如果把连接点看成一条结构生命线，那么：

    • integrity 决定这条生命线的基础长度；
    • impact_reduction 决定每次冲击先被抵消多少；
    • impact_multiplier 决定剩下的冲击会被放大还是缩小；
    • impact_absorption 决定没有被当场打断时，保留下来的冲击会以多高比例继续磨损完整性。

    这组参数并不会改变命中箱本体的装甲与耐久，它们只决定“东西会不会从车上掉下来”。

    结构完整性相关字段¶

    integrity¶

    integrity 是连接点的基础结构完整性，也就是满状态下可用的连接点“血量”。它不是部件本体耐久的替代品，而是一条与部件耐久并行的独立结构线。在第四章的近似写法里，如果修正后的冲击 $I_i'$ 满足

    $$ I_i' \ge C_i $$

    那么连接点就会直接断开。这里的 $C_i$ 就是连接点当前剩余结构完整性，而它的初始满值正是 integrity。

    因此：

    • 高 integrity 适合主承力结构、大型外挂支架、重要轮组安装座；
    • 低 integrity 适合轻量化外装、易抛挂架、薄弱附件接口；
    • 它不应该拿来替代部件耐久。若某零件本体很厚实、但挂架很脆，那么本体耐久和连接点完整性就应当明显分开设计。

    impact_reduction¶

    impact_reduction 是连接点的固定冲击减免值。每次分配到该连接点的原始冲击，会先减去这一常数，再进入下一步倍率结算：

    $$ I_i' = \max(0, I_i - R)\cdot M $$

    其中 $R$ 就是 impact_reduction。它非常适合用来表达“轻微震动根本无所谓，但真正大冲击还是会出事”的连接件。

    对调校来说：

    • 提高它，会显著过滤掉高频小冲击；
    • 降低它，则会让连接点对每一次命中都更敏感；
    • 若一个零件总是被零碎碰撞慢慢震掉，优先检查这里，而不是只盯着 integrity。

    impact_multiplier¶

    impact_multiplier 是冲击倍率，用于放大或缩小减免后的剩余冲击。它是最直接的“脆弱性旋钮”：

    • 大于 1：连接点更容易被同样的冲击打断
    • 小于 1：连接点更耐冲击
    • 等于 0：理论上会把剩余冲击压到 0，但通常更适合用在特殊设计场景，而不是常规结构件

    这个字段的典型用途并不是替代 integrity，而是表达某种连接方式本身就特别怕冲击集中。例如柔性挂耳、薄焊点、脆性卡扣，即使满值完整性不低，也可以因为 impact_multiplier 偏高而表现得更容易突然断开。

    需要注意的是，internal = true 的内部连接点恒定不可破坏，不走这条结构断裂逻辑，因此这组冲击字段对内部连接点没有实际意义。

    impact_absorption¶

    impact_absorption 最适合被理解为“没被当场打断时，冲击有多少会继续转化为结构疲劳”。也就是说，它主要描述的是连接点在扛住一次冲击之后，会留下多少后续损耗。

    在设计意图上，它更接近下面这种关系：

    $$ \Delta C \approx -\alpha I_i' $$

    其中 $\alpha$ 对应 impact_absorption。虽然当前实现里连接点完整性在主线程处理时还有额外的状态相关修正，但从内容包作者角度，把它理解成“未断开时的结构耗损比例”是最稳妥也最接近调校直觉的。

    因此：

    • 高 impact_absorption：适合一次次扛住，但会越扛越脆的连接件；
    • 低 impact_absorption：适合能把小到中等冲击长期吃掉、不容易被磨损的连接件。

    如果你希望某连接件“平时不容易掉，但连吃几次重击后会迅速危险起来”，通常就应提高 impact_absorption，而不是只压低 integrity。

    示例：简单连接点¶

    {
  "$schema": "../docs/zh_cn/schemas/part/subpart/connector/connector_static_attr.schema.json",
  "type": "Simple",
  "direction": "xn",
  "integrity": 30.0,
  "impact_absorption": 0.15,
  "impact_reduction": 3.0,
  "impact_multiplier": 0.8,
  "required_tags": [],
  "acceptable_tags": [],
  "forbidden_tags": []
}

    示例：带标签匹配和关节属性的高级连接点¶

    {
  "$schema": "../docs/zh_cn/schemas/part/subpart/connector/connector_static_attr.schema.json",
  "type": "Advanced",
  "direction": "yp",
  "integrity": 50.0,
  "impact_absorption": 0.1,
  "impact_reduction": 5.0,
  "impact_multiplier": 1.0,
  "required_tags": ["machine_max:door"],
  "acceptable_tags": [],
  "forbidden_tags": ["machine_max:explosive"],
  "joint_attrs": {
    "yr": {
      "lower_limit": 0.0,
      "upper_limit": 90.0,
      "stiffness": 4000,
      "damping": 20
    },
    "y": {
      "lower_limit": 1.0,
      "upper_limit": -1.0
    }
  }
}

    关节属性（JointAttr）¶

    joint_attrs 仅在 type 为 "Advanced" 时生效。它是一个以自由度为键的对象，每个键对应一个关节驱动轴：

    从实现角度看，Simple 和 Advanced 的主要区别并不在“能不能连接”，而在连接后是否会把 joint_attrs 注册成真正的可调关节。Simple 更适合刚性固定、普通外挂或不需要精细自由度管理的结构；Advanced 则适合车门、炮塔、转向节、悬臂、活动挂架等需要明确限位、回正、刚度和阻尼的部件。

    键 含义 单位
    x X 轴平动 米 （m）
    y Y 轴平动 米 （m）
    z Z 轴平动 米 （m）
    xr 绕 X 轴旋转 度 （°）
    yr 绕 Y 轴旋转 度 （°）
    zr 绕 Z 轴旋转 度 （°）

    每个轴对应的值对象包含以下字段（均非必需）：

    字段 类型 默认值 说明
    lower_limit 浮点数 — 关节位置下限。平动轴单位为 m，旋转轴单位为度。下限高于上限时该轴自由活动；下限等于上限时该轴固定；下限低于上限时该轴被限制在区间内
    upper_limit 浮点数 — 关节位置上限。规则同上
    equilibrium 浮点数 — 平衡位置。关节在无外力作用时趋向恢复到的目标位置
    stiffness 浮点数 — 刚度系数（N/m 或 N·m/rad）。数值越大关节抵抗变形的力越强，表现为"更硬"
    damping 浮点数 — 阻尼系数（N/(m/s) 或 N·m/(rad/s)）。数值越大关节运动时的能量耗散越快，表现为"更粘滞"

    关节限位规则¶

    通过 lower_limit 和 upper_limit 的数值关系，可以灵活控制关节的自由度：

    关系 行为 典型用途
    下限 ＜ 上限 关节在区间内活动 车门铰链（0° \~ 90°）
    下限 ＝ 上限 关节固定在指定位置 焊接死点
    下限 ＞ 上限 关节自由活动，无限制 车轮旋转轴
    两值均不填 关节不受此字段约束，不注册对应约束 仅需刚度和阻尼的场景

    这里需要补充一点实现层面的理解：MachineMax 最终使用的是六自由度关节，因此 joint_attrs 并不是“动画值”，而是真正参与物理求解的关节参数。它们会直接影响相连部件在外力、重力、碰撞和驱动输入下的姿态变化。

    刚度与阻尼的实际意义¶

    若把某个受约束自由度上的偏离量记为 $x-x_{\text{eq}}$，速度记为 $\dot{x}$，则关节回复力可以近似理解为

    $$ F \approx -k(x-x_{\text{eq}}) - c\dot{x} $$

    其中 $k$ 对应 stiffness，$c$ 对应 damping。对旋转自由度来说，可以把它理解为完全同构的回复力矩关系。

    这意味着：

    • stiffness 越高，越像“硬弹簧”或刚性铰链
    • damping 越高，越像“带油阻尼器”的回正
    • 两者都很低时，关节会显得松软、晃动和拖沓

    对于车门、舱盖、炮塔座圈之类有明确平衡位置的结构，通常应把 equilibrium、stiffness 和 damping 一起看；只调其中一项，结果往往会很怪。

    关节属性示例¶

    "joint_attrs": {
  "yr": {
    "lower_limit": -45.0,
    "upper_limit": 45.0,
    "equilibrium": 0.0,
    "stiffness": 5000,
    "damping": 30
  },
  "x": {
    "lower_limit": 1.0,
    "upper_limit": -1.0
  }
}

    此例中，绕 Y 轴的旋转被限制在 ±45° 范围内并趋向回归 0°；X 轴平动自由（下限高于上限）。

    动态属性（零件 JSON 内联）¶

    动态属性在每个零件 JSON 的子零件 connectors 字段中内联配置，确定连接点在模型上的落点、引用哪个静态定义、以及信号与能量的传输目标。动态属性面向每个具体的连接点实例。

    如果说静态属性回答的是“这种接口一般是什么性格”，那么动态属性回答的就是“这一个接口具体装在模型哪里、朝向哪边、和本零件内哪些功能模块相连”。因此，动态属性更多承担装配实例化与局部布线的职责。

    在零件 JSON 中的位置¶

    连接点定义位于子零件的 connectors 字段下，是一个以连接点名为键的键值对集合：

    "sub_parts": {
  "main_body": {
    ...
    "connectors": {
      "connector.my_mod.left_front_wheel": {
        "locator": "LeftFrontWheel",
        "definition": "my_mod:simple_connector",
        ...
      },
      "connector.my_mod.rear_hitch": {
        "locator": "RearHitch",
        "definition": "my_mod:advanced_hinge",
        ...
      }
    }
  }
}

    每个连接点实例的键为该连接点的唯一名称（推荐格式：connector.命名空间.描述性名称），值为其动态属性对象。

    动态属性字段¶

    字段 类型 必需 默认值 说明
    locator 字符串 是 — 模型中的 Locator 名称。系统会搜索名称匹配的 Locator，以其世界位置和旋转姿态作为该连接点的位置和朝向
    definition 资源路径 是 — 引用 connectors/ 模块中定义的连接点静态属性，格式为 namespace:file_name。例如 "my_mod:simple_connector"
    overwrite 对象 否 — 属性覆写。可按需覆写 definition 指向的静态属性中的任意字段。覆写后的值合并基础值后生效（覆写优先）。详见下文
    power_target 字符串 否 "" 机械能输出目标。从对侧连接点传入的机械能将转发至本零件内的指定子系统。填写子系统名称（如 "engine"）。留空则不传输机械能
    signal_translations 对象 否 {} 信号频道转译规则。键为对侧传入信号频道名，值为本零件内使用的目标频道名。例如 {"steering": "wheel_control"} 表示将对侧的 steering 信号转译为 wheel_control 信号再转发
    signal_targets 对象 否 {} 信号传输目标。键为信号频道名，值为目标列表。例如 {"move_control": ["car_controller", "engine"]}。目标可以是子系统名、连接点名、"subpart" 或 "vehicle"
    internal 布尔值 否 false 是否为零件内部连接点。设为 true 时仅在同一零件的不同子零件之间自动连接，不参与对外的拼装交互。内部连接点恒定不可破坏，不受冲击相关参数影响

    属性覆写（overwrite）¶

    overwrite 字段允许在不修改静态定义的前提下，针对特定连接点实例微调某些属性。这在以下场景中特别有用：

    • 同一个静态定义被多处引用，但某处需要更大的结构完整度；
    • 某连接点的对侧零件具有特殊标签要求；
    • 只需要为特定实例添加关节限位。

    这一机制和 5.6 材料定义 中命中箱材料的 overwrite 思路非常接近：静态定义提供可复用基线，动态实例只覆写真正与当前装配位置有关的差异。对连接点来说，最常见的覆写不是换整套定义，而是：

    • 某一侧轮组挂点比另一侧更强；
    • 同一种铰链，但左门和右门限位不同；
    • 同一类连接件中，只有最外层那一个更容易被震掉。

    overwrite 对象中的字段均为可选，结构如下 —————— 只填写需要覆写的字段即可：

    字段 类型 说明
    type 字符串 连接点类型覆写
    direction 字符串 法线方向覆写
    integrity 浮点数 结构完整度覆写
    impact_absorption 浮点数 冲击转化率覆写
    impact_reduction 浮点数 冲击减免值覆写
    impact_multiplier 浮点数 冲击倍率覆写
    collide_between_parts 布尔值 零件碰撞覆写
    required_tags 资源路径数组 必需标签覆写
    acceptable_tags 资源路径数组 可接受标签覆写
    forbidden_tags 资源路径数组 禁止标签覆写
    joint_attrs 对象 关节属性覆写（结构与静态定义中的 joint_attrs 相同）
    power_target 字符串 机械能目标覆写（覆写顶层 power_target 字段）

    覆写后的最终属性按"覆写值优先，缺失值回退到静态定义"的规则合并。未在 overwrite 中出现的字段保持静态定义中的原值。

    "overwrite": {
  "integrity": 80.0,
  "impact_multiplier": 0.5,
  "joint_attrs": {
    "yr": {
      "lower_limit": 0.0,
      "upper_limit": 120.0
    }
  }
}

    信号转译（signal_translations）¶

    信号转译用于在不同内容包间的信号频道命名不一致时建立映射。例如，零件 A 发送 "steer" 信号，但零件 B 的转向子系统接收的是 "steering" 信号。在零件 B 的连接点上设置 "steer": "steering" 的转译即可桥接此差异。

    "signal_translations": {
  "steer": "steering",
  "accel": "throttle"
}

    此例中，从对侧连接点接收到的 steer 信号在本零件内被当作 steering 信号处理，accel 则被当作 throttle。

    信号传输目标（signal_targets）¶

    信号传输目标定义了此连接点接收到的信号应向本零件内的哪些模块转发。键为信号频道名，值为目标列表。目标支持以下类型：

    目标写法 含义
    "subsystem_name" 零件内的指定子系统
    "connector.连接点全名" 本零件内的其他连接点
    "subpart" 本零件自身
    "vehicle" 当前载具 
    "signal_targets": {
  "move_control": ["car_controller"],
  "steering": ["left_steer_knuckle", "right_steer_knuckle"],
  "door_control": ["left_door", "right_door"]
}

    机械能传输（power_target）¶

    power_target 字段使连接点可以作为机械能（转速/转矩）的传输通道。对侧连接点传入的机械能将转发到本零件内该字段指定的子系统。

    "power_target": "engine"

    此配置使对侧传来的机械能注入到本零件名为 engine 的子系统。留空（默认）则不传输机械能。

    需要注意的是，连接点断开时，这条机械能传输链也会一起被切断。这一点和第四章中提到的“连接点断开不只是几何脱离，还会切断动力链与信号链”完全一致。因此，对轮边减速器、挂载机具、拖车牵引、炮塔供能这类结构来说，连接点既是装配接口，也是动力系统的一部分。

    内部连接点（internal）¶

    当连接点仅用于同一零件内的子零件之间自动连接、不参与与其他零件的外对拼装时，将 internal 设为 true：

    "internal": true

    内部连接点的特点：

    • 不参与玩家拼装时的对侧匹配流程；
    • 恒定不可破坏，不受 integrity、impact_absorption、impact_reduction、impact_multiplier 等冲击相关参数的影响；
    • 典型场景为底盘子零件与悬架子零件之间的内部固定连接。

    这意味着 internal 不只是“玩家看不见”，而是明确告诉系统：这是一条零件内部的结构关系，不应被当作可被战斗、碰撞和装配操作打断的外挂接口。凡是你希望在第四章那套“打散架”逻辑里完全排除掉的内部骨架连接，都应优先考虑这里。

    完整示例¶

    以下是一个连接点动态属性的完整配置示例，同时展示了覆写、信号转译、信号目标和机械能传输的综合用法：

    "connectors": {
  "connector.my_mod.left_front_wheel": {
    "locator": "LeftFrontWheel",
    "definition": "my_mod:wheel_mount",
    "overwrite": {
      "integrity": 100.0,
      "impact_multiplier": 0.3
    },
    "power_target": "",
    "signal_translations": {
      "steer": "steering",
      "accel": "throttle"
    },
    "signal_targets": {
      "move_control": ["car_controller", "engine"],
      "steering": ["left_steer_knuckle", "right_steer_knuckle"]
    },
    "internal": false
  }
}

    标签匹配机制¶

    连接点的标签匹配用于控制哪些零件可以相互连接。在配对两个连接点时，系统基于被连接侧（对侧）零件变体的 tags（详见 5.3 零件定义 > 变体属性字段）与本侧连接点静态属性中的三层标签进行匹配：

    1. required_tags（必需标签）：对侧零件必须全部拥有。任缺一个则匹配失败。
    2. acceptable_tags（可接受标签）：对侧零件必须至少拥有其中一个。列表为空则跳过此项检查。
    3. forbidden_tags（禁止标签）：对侧零件不得包含其中任何一个。包含任意一个则匹配失败。

    三层检查同时通过时，两个连接点匹配成功。三层均留空时，任意零件均可连接。

    "required_tags": ["machine_max:wheel"],
"acceptable_tags": ["machine_max:steerable", "machine_max:driven"],
"forbidden_tags": ["machine_max:explosive"]

    此例中，对侧零件必须同时包含 machine_max:wheel 标签、至少包含 machine_max:steerable 或 machine_max:driven 之一、且不得包含 machine_max:explosive，方可与本连接点对接。

    当服务端配置 ignoreAssemblyTagRequirements 为 true 时，标签匹配检查被全局跳过，所有零件均可无视标签连接。此设置仅影响拼装操作。

    调校建议¶

    如果你是在做常规轮式载具，连接点调校最好分三层看。第一层是“能不能拼上”，由 required_tags、acceptable_tags 和 forbidden_tags 控制；第二层是“拼上以后是什么关节”，由 type、direction 和 joint_attrs 控制；第三层是“挨打或碰撞后会不会掉”，由 integrity、impact_reduction、impact_multiplier 和 impact_absorption 控制。把这三层拆开调，通常比把所有问题都堆在某一个字段上更容易收敛。

    如果你希望某个附件“平时很稳，但一旦被重击就该飞出去”，可以提高 impact_reduction 来过滤小冲击，同时适当降低 integrity 或提高 impact_multiplier；如果你希望某个挂载件“不会被一发直接震掉，但多挨几下会越来越危险”，就应适当提高 impact_absorption。反过来，如果某个大部件总是先被震掉，而本体看起来并没有明显损伤，优先检查连接点冲击参数，而不是只去改部件材料或耐久。

    最后需要强调的是，连接点定义并不是孤立于第四章之外的“装配元数据”。它和命中箱材料、部件耐久、碰撞效果、子系统信号与动力传输共同构成了完整的载具结构逻辑。内容包作者一旦开始做门、轮组、炮塔、外挂支架、拖挂接口或可脱落模块，就应把连接点视为和命中箱同等重要的核心配置对象。
