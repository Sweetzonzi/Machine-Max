# A.3 常见问题

本章收集了 MachineMax 玩家和内容包作者经常遇到的问题与解答。如果你在阅读 Wiki 其他章节后仍有疑问，可以优先在这里查找。如果问题仍然没有解决，欢迎通过 GitHub Issues 或其他社区渠道反馈。

***

## 一般问题

### MachineMax 可以在什么版本上玩？

MachineMax 目前支持 Minecraft **1.21.1**，需要 **NeoForge** 21.1.219 及以上版本，以及 **Java 21** 或更高版本。模组不提供 Fabric、Quilt 或旧版 Forge 的支持。详细安装步骤请参考 [1.2 安装与配置](../1-快速上手/1.2-安装与配置.md)。

### MachineMax 需要哪些前置模组？

- **SparkCore**（≥ 1.0.1021）：提供基于 Bullet Physics 的物理引擎和基岩版模型动画渲染支持，是 MachineMax 的底层框架。
- **Kotlin for Forge**（≥ 5.10.0）：MachineMax 和 SparkCore 均使用 Kotlin 编写，需要此模组提供运行时支持。

以上前置模组需与 MachineMax 一同放入 `mods` 文件夹。

### MachineMax 和机械动力（Create）兼容吗？

MachineMax 的载具可以与机械动力的**动态结构**产生物理碰撞交互。此外，MachineMax 兼容 **AcclerateRendering** 加速渲染模组——当同屏载具数量较多时，建议安装此模组以提升帧率表现。更详细的兼容性说明请参考 [A.2 Create 兼容性](A.2-Create兼容性.md)。

### 以后会兼容航空学（Aeronautics）吗？

**短期内没有明确计划，但未来有精力时存在“可能尝试”的空间。**

对玩家来说，可以先把当前结论理解为：**现在不要把航空学兼容当作已规划的近期功能**。原因并不只是“还没做”，而是两边底层依赖的物理方案本身差异很大。

目前，航空学相关玩法建立在 **Sable** 提供的物理能力之上；而 Sable 本质上是一个面向 Java 模组环境封装的物理基础库，底层使用的是 **Rapier**，也就是一个基于 Rust 的物理引擎。现阶段 Sable 已经实现的 JNI 桥接，主要覆盖的是航空学自身所需的那部分功能。

这带来的问题是：这些功能对航空学来说已经够用，但对 MachineMax 来说还不够。MachineMax 目前依赖的一些高级能力，例如：

- 更细粒度的**接触点级碰撞处理**
- 更灵活的**6 自由度自定义关节**
- 面向复杂载具结构的更多底层物理约束能力

这些恰恰都是 MachineMax 比较依赖、而 Sable 目前尚不足以完整提供的部分。换句话说，即使未来想做兼容，也不是简单写一层适配就能完成，而更接近于“是否要重新整理底层物理框架”这一等级的工作。

从目前情况看，如果将来确实投入这方面的精力，更现实的方向可能不是直接给现有架构补一个临时兼容层，而是**尝试调整 SparkCore，自底向上评估是否迁移到基于 Sable 的物理方案**。不过这仍然只是一个**可能的长期探索方向**，并不代表已经进入开发排期。

因此，现阶段更稳妥的结论是：

- **不会承诺近期兼容航空学**
- **技术上并非完全没有可能**
- **真正的困难在于底层物理能力是否足够，而不是单纯缺少对接代码**

如果后续 Sable 提供了更完整的高级特性支持，或者 MachineMax 在物理层架构上进行了更大规模的调整，那么相关兼容性才会更有现实推进空间。

### 服务器可以安装 MachineMax 吗？

可以。MachineMax 支持在专用服务器上运行，物理引擎在每个世界独立运行于各自的物理线程中。服务器管理员需特别注意服务端配置中的方块破坏开关——在偏建造向服务器上建议关闭 `should_destroy_blocks` 以避免载具误伤建筑。更多配置说明请参考 [A.1 模组配置](A.1-模组配置.md)。

## 驾驶与操作

### 为什么我的车开起来很颠簸？

MachineMax 的驾驶基于实时物理模拟，而非绑定固定速度。颠簸的原因可能有以下几种：

- **地形不平**：Minecraft 方块地形天然存在锯齿边缘。模组自带的地形平滑系统（LocalHeightField）会在行驶时根据周围地形动态生成平滑的高度场，但极端崎岖的地形（如天然山地、深谷）仍可能产生颠簸——这是物理模拟的正常表现。
- **悬挂配置**：如果你的内容包自定义了载具，检查悬挂的弹簧刚度和阻尼参数。过硬的悬挂会导致高频颠簸，过软则可能在某些地形下失稳。
- **车速过快**：高速行驶放大了地形的微小起伏。可以尝试降低速度或使用更大尺寸的轮胎。

详细机制请参考 [4.6 地形平滑](../4-物理与战斗机制/4.6-地形平滑.md)。

### 车开起来总觉得太灵敏/太迟钝，怎么办？

客户端配置提供了多种操控调节项：

| 现象        | 建议调整项                                         |
| --------- | --------------------------------------------- |
| 油门响应过快/过慢 | `ground_vehicle.full_power_time`（增大更平顺，减小更灵敏） |
| 转向过于灵敏    | `ground_vehicle.full_steering_time`（增大数值）     |
| 转向过于迟钝    | `ground_vehicle.full_steering_time`（减小数值）     |
| 高速转向易失控   | 开启 `ground_vehicle.speed_turning_limit`       |
| 不习惯手动换挡   | 开启 `ground_vehicle.auto_switch_gear`          |
| 起步溜车      | 开启 `ground_vehicle.auto_handbrake`            |

如果你使用手柄或追求休闲驾驶体验，还可以开启 `drift_assist`（漂移辅助）和 `pose_preference`（镜头跟随车体）。所有配置项详见 [A.1 模组配置](A.1-模组配置.md)。

### 怎么才能拆掉拼错的零件？

手持**撬棍**（CrowbarItem），对准需要拆卸的零件右键即可安全拆下。如果你只想断开两个零件之间的连接而不拆下整个零件，可以潜行状态下对准连接点右键。撬棍有 1000 点耐久，大量拆装时注意及时更换。

### 载具上的窗户显示异常怎么办？

如果玻璃或半透明零件出现渲染顺序错误、模型遮挡异常等问题，可以尝试在客户端配置中开启 `render_force_translucent_parts`（强制半透明渲染）。该选项默认关闭，因为开启后可能在部分环境下带来性能波动。更多信息请参考 [A.1 模组配置](A.1-模组配置.md)。

## 生存模式与制造

### 生存模式怎么获取载具？

生存模式中，你需要在**研究台**中完成对应的研发项目来解锁载具的制造配方。获得制造蓝图物品后，将其放置到世界中，再用**焊枪**消耗背包中的材料逐步完成组装。完全组装后即可正常驾驶。详细流程请参考 [1.4 生存模式起步](../1-快速上手/1.4-生存模式起步.md)。

### 制造蓝图和装配体有什么区别？

| 对比项   | 制造蓝图（FabricatingBlueprintItem） | 装配体（AssemblyItem）            |
| ----- | ------------------------------ | ---------------------------- |
| 获取方式  | 研究台研发解锁后获得                     | 创造模式物品栏直接拿取；生存模式通过末影树脂封装已有载具 |
| 放置后状态 | 组装进度为 0，需要焊枪投入材料逐步组装           | 完全组装状态，放置即用                  |
| 主要用途  | 生存模式逐步制造载具                     | 保存、携带和快速部署完整载具               |

### 焊枪怎么用？组装进度为什么不动？

手持焊枪对准需要组装的零件**长按右键**，焊枪会自动消耗背包中对应材料来提升组装进度。组装速度取决于焊枪的效率和材料是否充足。需要注意：

- 焊枪只会消耗与该零件配方匹配的材料——如果背包中没有对应材料，组装不会推进。
- 个别零件的组装需要多种材料，缺一不可。
- 焊枪同时也会修复该零件上已受损的子零件、子系统和连接点。
- 潜行状态下使用焊枪会逆向拆解，返还材料。

焊枪有 6000 点耐久，长时间作业时备一把替换焊枪是稳妥的做法。

### 怎么把做好的载具带走？

手持**末影GK树脂**（EnderGkResinItem），对准载具上的任意零件右键，即可将整辆载具封装为一个装配体物品，载具会从世界中移除。之后你可以在需要时手持装配体右键地面重新放置出来。另外，你也可以使用空白蓝图为载具制作蓝图备份。

## 物理与性能

### 多辆载具同时在场会很卡吗？

MachineMax 的物理引擎独立于 Minecraft 主游戏循环运行在专用线程中，每个世界拥有独立的物理线程，能够利用多核 CPU 并行计算。在一台拥有多核处理器的设备上，多辆载具同时在场通常不会导致严重的帧率下降。如果你确实遇到了性能问题，可以尝试：

- 安装 **AcclerateRendering** 模组以获得更好的渲染管线加速。
- 适当减少同屏载具数量。
- 检查是否有其他模组与物理线程产生冲突。

### 我的载具碰坏了方块，怎么关掉这个功能？

在服务端配置中将 `should_destroy_blocks` 设为 `false` 即可关闭载具碰撞破坏方块的行为。这项配置在服务器端控制，单人存档中也同样生效。偏建造向的服务器通常建议关闭此项以保护建筑。

### 车被撞坏以后零件消失得很快，能延长吗？

可以。在服务端配置中调整以下三项：

- `subpart_destroy_ticks_per_durability`：每点耐久上限对应的倒计时刻数，增大可延长残骸保留时间。
- `subpart_destroy_min_ticks`：最短保留时间，增大可保证即使很脆的零件也能多留一会。
- `subpart_destroy_advance_ticks_per_damage`：持续受击时倒计时推进速度，减小可让残骸在继续挨打时没那么快消失。

详细说明请参考 [A.1 模组配置](A.1-模组配置.md)。

## 未来计划

### 模组目前处于什么阶段？

MachineMax 目前处于**早期开发阶段**（可以理解为 Alpha 阶段），当前主要覆盖**轮式民用载具**的拼装、驾驶和物理模拟。模组的核心架构——包括数据驱动的内容包系统、基于 Bullet Physics 的实时物理引擎、模块化的子系统机制、装甲与伤害系统——已经建立完善，但载具种类和功能维度仍在持续扩充中。

### 武器系统什么时候来？

武器系统已在开发计划中，但**尚未有明确的实装版本和时间表**。实际上，模组的伤害系统（命中判定、装甲穿深、连接点断裂、部件损毁等）已经在底层做了充分的设计准备——第 4.3 和 4.4 节中描述的装甲穿深机制和伤害分发链路，本质上是武器系统的前置框架。当武器系统实装时，玩家赋予载具的火力将与现有的防御和结构完整性计算无缝衔接，形成完整的攻防闭环。

在武器系统到来之前，你可以通过配置内容包中的装甲、材料和伤害参数来调整载具在面对原版伤害源（爆炸、碰撞、生物攻击等）时的表现。

### 有没有打算做履带载具？坦克什么时候能玩？

**履带载具（坦克、装甲车等）** 是明确列入计划的方向之一。这涉及到推进系统的重大扩展——当前的载具移动基于轮式物理（Bullet 的 raycast vehicle），而履带需要完全不同的驱动和地面交互模型。开发团队需要解决履带分段刚体运动、地面附着力分布、履带橡胶/金属材质与多种地形的摩擦建模等一系列工程问题，因此履带系统的开发周期会比轮式载具更长。

当履带系统实装时，现有的零件拼装框架、子系统体系和伤害系统都可以直接复用到履带载具上。换言之，你现在学到的所有载具构建知识，在未来都能无缝迁移到履带载具的组装。

### 有没有打算做飞行器？直升机和固定翼飞机呢？

**有**。飞行器是 MachineMax 长远计划中的重要方向，包括**固定翼飞机**和**旋翼飞行器（直升机）**。客户端配置中已经预留了 `plane` 相关选项（`full_pitch_time`、`full_yaw_time`、`full_roll_time` 等），这表明飞行控制体系已进入结构设计阶段。

固定翼飞行器需要处理升力面（机翼）的空气动力学、襟翼/副翼/方向舵的力矩控制、失速边界等物理模型，而旋翼飞行器则需要旋翼转速-升力映射、扭矩平衡（尾桨/共轴反转）、自转降落等机制。两者都依赖第 4.2 节描述的流体动力学与气动框架进行扩展。和武器、履带载具一样，气动系统在底层已在逐步建设中，具体的飞行载具实装时间需等待后续版本更新。

### 会不会做水面舰艇？

水面舰艇也在计划范围内。客户端配置中已经预留了 `ship` 组（船只的 `full_steering_time` 等），说明船载具的操作框架已有初步规划。水面舰艇的核心技术挑战在于浮力与流体动力学——载具需要根据排水体积计算浮力，水面与船体的相对位置需要实时解算，同时还要处理兴波阻力、水流影响等。类似的物理挑战同样适用于潜艇等水下航行器。

### 人形机甲或多足步行载具会不会有？

模组初始愿景中提到了**人形或多足机甲**作为可能的方向之一。不过这类载具在技术难度上是最高的——多足步行的步态规划、足端地面接触的独立物理交互、重心实时调整等都是工程上的硬挑战。因此，机甲/步行载具属于**远期愿景**，在轮式、履带、飞行器和水面载具之后才会开始实质推进。

### 未来会不会支持更多 Minecraft 版本？

当前的开发重点是完善 1.21.1 版本下的核心功能。是否会适配未来的 Minecraft 版本（如 1.22 及以上）取决于 NeoForge 平台自身的版本跟进节奏以及开发团队的资源分配。一旦核心系统稳定，可以考虑向后适配。但**大概率不会再回到 Forge 1.20.x 或更早版本**，因为模组深度依赖 NeoForge 1.21+ 提供的 API 特性。

## 内容包制作

### 我不会编程，能做内容包吗？

**可以**。MachineMax 完全基于**数据驱动**——所有零件、子系统、材料、配方和载具结构都通过 JSON 配置文件定义，你不需要编写任何 Java 或 Kotlin 代码。如果你会编辑文本文件和理解 JSON 格式，就能制作内容包。建议从阅读 [5.1 内容包总览](../5-内容包制作教程/5.1-内容包总览.md) 开始，然后参考官方内容包的文件结构学习具体的写法。

### 我把内容包放进 spark\_modules 了，为什么游戏里没变化？

请按以下顺序排查：

1. **目录结构是否正确**：确认内容包根目录下有 `meta.json`，模块文件位于 `命名空间/模块名/` 路径下。
2. **meta.json 的 id 是否唯一**：如果同一个 id 被多个包使用，会产生冲突。
3. **是否声明了硬依赖**：如果你的包依赖 `machine_max:base` 但没有正确声明为 `hard` 依赖，可能会因为加载顺序问题导致注册失败。
4. **是否执行了重载**：修改内容包文件后，可以在游戏中执行 `/spark package reload` 命令重载内容包，无需重启游戏。
5. **是否有 JSON 语法错误**：使用 JSON 校验工具检查你的配置文件是否有括号不匹配、缺少逗号等语法问题。

### 零件模型用什么格式？可以用 Blockbench 做吗？

MachineMax 使用基岩版几何模型格式（`minecraft:geometry`），这是一种 JSON 格式的模型描述，完全可以在 **Blockbench** 中制作和导出。选择 "Bedrock Model" 项目类型即可。骨骼动画同样采用基岩版格式，动画控制器则使用基岩版的动画状态机格式。详细说明请参考 [5.2 模型与动画](../5-内容包制作教程/5.2-模型与动画.md)。

### 我能把我的内容包分享给别人吗？

可以。将你的内容包文件夹打包为 `.zip` 文件（保持内部目录结构不变），放在 `spark_modules/` 下即可被模组加载。分享时只需将 .zip 文件发给其他人，放入相同位置并启动游戏即可。你还可以在 `meta.json` 中标注作者信息和版本号，方便他人了解包的来源和兼容性。

## 故障排查

### 游戏启动时崩溃，报错与 SparkCore 或物理线程有关

常见原因：

- **Java 版本不匹配**：MachineMax 需要 Java 21 或更高。如果你的启动器使用了 Java 17 或更老版本，请切换为 Java 21+。
- **前置模组版本不匹配**：确认 SparkCore 版本 ≥ 1.0.1021，Kotlin for Forge 版本 ≥ 5.10.0。
- **模组冲突**：某些修改物理或渲染管线的模组可能与本模组的物理线程产生冲突。尝试在仅加载必要模组的环境下启动，定位冲突源。

### 载具放置后不动或移动异常

- 检查载具是否处于**组装未完成**状态。用焊枪对准零件查看组装进度——如果进度不到 100%，载具功能会受到限制甚至完全无法工作。
- 检查发动机、变速箱、车轮等子系统是否完整挂载。如果传动链中某环节缺失（例如没有变速箱就试图连接发动机和车轮），载具无法获得驱动力。
- 检查载具的发动机是否有燃料/能量。燃油发动机需要燃料罐，电动机需要电池供电。

### 连接的零件突然断了

零件之间的连接由连接点维持。连接点在受到冲击（碰撞、爆炸等）时会逐步损失结构完整性，冲量超过剩余完整性时就会直接断开。如果你发现零件频繁意外脱落，检查：

- 是否经历了碰撞或攻击等伤害事件。
- 在内容包中，连接点的 `impact_reduction` 和 `impact_multiplier` 是否设置得过脆弱。
- 基础结构的承载零件是否耐久不足——如果承载零件本体的耐久已被打空，其上连接点也会加速失效。

### 渲染问题：零件不显示、闪烁或颜色错误

- 确保模型 JSON 格式正确，贴图路径匹配。
- 尝试调整客户端配置中的 `render_force_translucent_parts` 开关。
- 如果使用了着色器模组（如 Iris/Oculus），某些着色器可能与 MachineMax 的自定义渲染管线不兼容，尝试关闭着色器排查。
- 确认显卡驱动为最新版本。
